# 가상 학교 연간 시험 환경

운영 사이트와 별도 Supabase·Vercel 프로젝트로 만든 사용자 승인 시험 환경이다. 이 브랜치를 운영 main에 병합할 필요는 없다. 복제 Vercel의 Production 브랜치는 `feat/accelerated-school-sandbox`로 지정한다. 가속 시계는 시험 플래그와 시험 DB 주소가 동시에 일치할 때만 작동한다.

복제 주소는 https://daedong-year-sandbox.vercel.app 이다. 22개 계정의 비밀번호와 전달 자료는 Git에서 제외한 `private-sandbox/연간시험_전달자료/`에만 보관한다. 공개 가입과 Google 로그인은 꺼져 있으며 전용 이메일 계정으로 로그인한다.

## 자료와 계정

- 원본: 다운로드 폴더의 `2026학년도 2학기(08.13.)교사별시수표_컴시간용2학기(담임 창체 포함) (1).xls`.
- SHA-256: `927bcae7b5d3d478fc78e087b5da757a6dc040039d9b114b7c3541b2f5d506a9`.
- 중복 과목 행을 합치면 교사 22명이다. 공통 담임 창체 행을 별도 교사로 세지 않는다.
- T09: 관리자 겸 교사 1명. T01: 시간표 담당 겸 교사 1명. 나머지 20명: 일반 교사.
- 9학급, 학급당 주 32시간, 주간 288개 수업. 두 학기 314개 교과 수업을 편성했다.
- 학생 수가 자료에 없어 학급당 가명 학생 30명, 총 270명을 사용한다. 실제 학생 자료는 없다.
- 담임 배정, 시간표 담당, 일과 시간은 합성 값이다. 2027-03-01부터 2028-02-29까지 두 학기에 같은 2학기 시수를 적용한 연간 시나리오이며 실제 1학기 편성표가 아니다.
- 주중 전체를 수업일로 준비했다. 공휴일·방학·시험·행사에 의한 휴업/특별일과는 Claude가 운영 시나리오로 반영한다.
- 원본의 실제 교사 이름은 공개 저장소·복제 DB에 넣지 않았다. 비밀번호와 서버 비밀값도 Git에 포함하지 않는다.

## 시간과 권한

상단 노란 시험 표시에서 T09만 시계를 시작·일시정지·앞으로 이동할 수 있다. 실제 진행 시간 3,600초에 윤년을 포함한 학년도 366일이 지난다. 일시정지한 시간은 1시간에서 차감하지 않는다. 이전 날짜로 되감기는 없다.

업무 날짜, 수업의 과거/미래, 교환 만료, 수합 마감을 가속한다. 로그인 토큰, 임시 계정의 30일 만료, 파일 업로드·검사 임대, 서명 URL, 요청 복구, 미리보기 15분, 감사 시각, 실제 AI 예산 월은 실제 시계를 쓴다. 화면 전체의 `Date`를 덮어쓰지 않는다. 두 시계의 차이를 실제 장애로 오판하지 않는다.

계정의 학교 소속·수업 담당·수강 관계·관리 권한은 원래 서버 함수가 검사한다. 전체 기능을 열되 일반 교사에게 관리자 역할을 주지 않는다. T01의 `year.manage`는 기존 시간표 담당 계약이 요구하는 권한이며 별도의 superadmin이 아니다. 승인 신청자가 자신을 승인하지 못하는 규칙은 유지한다.

## AI 비용

복제 DB의 모든 AI 요청 시작을 한 행 잠금으로 직렬화한다. 요청별 최대 예약액의 두 배(최소 $0.04)를 누적 선차감하고, 총 $9를 넘는 요청은 공급자 호출 전에 거절한다. 실패·응답 유실·월 변경·키 변경으로 누적 한도를 돌려주지 않는다. 전체 22명·모든 기능·모든 월을 합친 상한이다. 일반 AI 설정의 월 $100 표시는 기존 정책이며 시험 상단의 더 낮은 누적 $9 제한이 추가 적용된다.

전용 Claude 워크스페이스/키만 사용한다. 운영 키는 복사하지 않는다. Haiku의 짧은 질문 위주로 시험하며 Sonnet은 소수의 명시 검토에만 사용한다. 기존 자동 정밀 검토 금지는 유지한다. 이 한도는 **사이트가 호출하는 API**에 적용한다. Claude가 브라우저를 조작하는 데 사용하는 별도 구독/에이전트 비용과 Vercel 호스팅 비용은 포함하지 않는다.

전용 공급자 워크스페이스도 월 $9로 제한했다. 공급자 월 한도가 다음 달에 다시 생겨도 위 DB 누적 상한은 초기화하지 않는다. 시험 키는 30일 만료이며 원래 서버의 암호화 저장 경로로 연결했다. 키를 Claude에게 전달할 필요는 없다.

## 재현 순서

전용 연결 파일은 Git 밖에 보관한다. `environment.mjs`가 프로젝트 ID·DB 사용자·TLS CA·시험 표식을 검사하며 운영 프로젝트는 거절한다.

1. 빈 전용 Supabase 프로젝트를 만들고 공식 CA를 넣은 비공개 `provisioning.json`을 준비한다.
2. `node scripts/school-sandbox/install.mjs <비공개파일> foundation`.
3. `node scripts/school-sandbox/accounts.mjs <비공개파일>` — Auth 임시 계정과 R0 첫 학교.
4. `node scripts/school-sandbox/install.mjs <비공개파일> modules` — 확정 원문 해시를 대조한 증분 63개 전체.
5. `node scripts/school-sandbox/overrides.mjs <비공개파일>` — 복제에서만 시계/시험 명단 차이 적용. SB-01 → SB-02 → SB-03을 순서대로 적용하고 원문/적용 해시를 보관한다.
6. `node scripts/school-sandbox/seed.mjs <비공개파일>` — 가명 학교 자료.
7. `node scripts/school-sandbox/activate.mjs <비공개파일> local-build` — 기본 모듈. 파일/AI 서버 활성화와 구분한다.
8. `TIMETABLE_PYTHON`에 OR-Tools 9.15.6755 인터프리터를 지정하고 `timetables.mjs <비공개파일>` 실행. 원래 준비/확정/공개 RPC와 앱 parser로 검증한다.
9. `verify.mjs`, `verify-concurrency.mjs` — AI 키 등록·첫 유료 실행 전에만 수행한다. 실제 Auth/PostgREST, 역할, 시계, 누적 한도와 동시 접수를 확인한다.
10. 별도 Vercel 배포 뒤 `connect-servers.mjs <비공개파일>` — 파일 모듈·개인 기억·전용 AI 키를 원래 서버 API로 연결한다. AI 키 생성과 외부 설정은 사용자 승인 범위에서만 진행한다.
11. `verify-live-files.mjs`, `verify-calendar.mjs`, `verify-connected.mjs` — 각각 같은 비공개 파일을 인자로 넣는다. 실제 메시지·HWPX, 연간 전체 날짜, AI 연결·누적 한도를 확인한다. `verify-connected`의 비용 경계 시험은 롤백하며 실제 차감액을 되돌리지 않는다.
12. `package-handoff.mjs <비공개파일>` — 계정표·전달문·시험 HWPX를 Git 제외 폴더에 만든다. API·DB·암호화 키는 전달 폴더에 넣지 않는다.

## 보존과 종료

시험 완료 후 결과·스크린샷·접수 번호를 먼저 내보낸다. 계정은 실제 30일이 지나면 시험 명단 검사에서 막힌다. 중간 종료는 시계 일시정지와 `sandbox_private.ai_limit.enabled=false`로 신규 유료 실행을 막고, 전용 API 키를 비활성화한다. 프로젝트 삭제는 사용자가 따로 결정한다. 운영 DB와 main은 건드리지 않는다.

시험 진단 로그는 복제 플래그와 DB 주소가 모두 맞을 때 오류 종류·파일명·함수명·줄 번호만 남긴다. 예외 메시지·질문·키·지역 변수는 남기지 않으며 일반 배포에서는 동작하지 않는다.


## 연간 시험 피드백: SB-03 (2026-10-29)

- Claude 전달본 SB-03은 사용자가 이미 시험 DB에 적용했다. Codex도 읽기 전용 함수 조회에서 `WHERE singleton` 반영을 확인했다. 현재 시험에는 재실행할 필요가 없다.
- SB-01·SB-02 원문은 그대로 보존했다. 다음 **새 복제 설치**에서 누락되지 않도록 overrides.mjs에 SB-03 순서를 추가했다. 진행 중인 시험에 전체 설치기·seed·초기 검증을 다시 실행하지 않는다.
- 저장소 SB-03은 전달본의 변경 내용(WHERE 한 곳 추가)은 같고, 안전장치는 강화했다. 정확한 public 함수 시그니처, 줄바꿈을 LF로 정규화한 원문 지문(`9260cd8a170b0c55705977173c7062d7`)을 검사한다. 다른 스키마의 동명 함수를 수정하지 않고, 이미 WHERE가 있어도 다른 변경이 섞이면 중단한다.
- 원래 함수의 권한·소유자·멱등성·시계 규칙·예산은 바꾸지 않는다. 이미 보강된 함수는 재생성하지 않는다. 적용 파일이 시계 상태나 이력을 초기화하는 쓰기는 없다.
- sandbox SQL의 WHERE 없는 UPDATE는 SB-01의 예산과 시계 두 곳이었다. 각각 SB-02·SB-03으로 보강한다. DELETE 문은 없다.
- 검증: `node tests/test_school_sandbox_clock_sql.mjs` — 로컬 PGlite에서 최초 설치/재실행, 날짜 진행/시작/멈춤/동일 번호 복구, 원문 변조·다른 프로젝트 거부, 상태·권한 보존을 확인한다. PGlite에는 Supabase safeupdate 확장이 없으므로 확장 자체의 실행 시험으로 주장하지 않는다. 실제 시험 환경 성공은 Claude 보고와 읽기 전용 반영 확인을 별도로 근거로 삼는다.
- 후속 브랜치 `npm test`: **5,236/5,236 통과**(SB-03 전용 9건 포함). 첫 전체 실행의 `test_timetable_cpsat.mjs` 실패는 단독 29건 및 전체 재실행에서 재현되지 않았다. 최초 로그만으로 원인을 특정하지 못했으며 검사 기준과 계산기 코드는 변경하지 않았다.
