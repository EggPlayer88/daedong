화면 연결은 기존처럼 **화면 연결됨**, 실제 접수 결과가 있는 단계는 **처리 내역 확인**이다. 후속 접수는 같은 원본의 이력에 추가한다. 접수된 단계에서 다음 업무로 이동해도 아직 처리하지 않은 단계만 입력으로 준비한다. 기존 최종 확인 버튼과 대상·원본 비교를 생략하지 않는다.

## 계약과 복구

- T3는 종류를 임의 추정하지 않는 별도 `intervention` 결과를 사용한다. 대강·보강·취소·재개 모두 검증된 approve/applied만 기록한다. 요청 닫기가 이미 반영된 접수증을 반환할 때만 기록하고, 닫힘만으로 승인 이력을 만들지 않는다.
- 인계 서비스가 이미 검증하던 판과 접수 시각을 반환값에 보존했다. 서버 계약은 바꾸지 않았다. 구형 공식 담당 전용 접수증은 새 인계 단계로 추정하지 않는다.
- 문서는 접수증의 문서 ID·판·action·접수 시각을 기록한다. 문서 후속 조회가 실패해도 성공한 저장을 실패로 돌려 다시 쓰지 않는다.
- AI가 만든 문서 초안의 출처는 탭 복구 메타에만 보관한다. 서버 명령에 추가하지 않는다. 새 문서·작성 닫기·AI 반영 되돌리기·최신 원본 채택에서는 출처를 제거하거나 원래 출처로 복원한다. 별도 AI 초안의 첫 저장을 기존 문서함 이동 단계에 붙이지 않는다.
- 생성 Artifact에는 서버 접수 시각이 없다. 확인한 클라이언트 시각은 `observedAt`으로 분리하고 `recordedAt`을 만들어 내지 않는다. 양식/답변 ID와 판, 파일 ID·해시·크기를 검증하고 본문·저장소 경로를 업무 이력에 복제하지 않는다.
- 같은 요청 번호 재확인은 기존 mutate/recover 경로를 사용한다. 결과 이력은 같은 key를 한 번만 기록한다. 결과 표시 콜백이 실패해도 저장을 재실행하지 않는다.
- 현재 계획 객체·단계 원문·학교/계정/소속·기준일·작업 패널과 첫 원본을 고정한다. 다른 원본, 같은 문구의 새 계획, 연결 교체 뒤 늦은 응답은 이전 단계에 붙지 않는다.
- 이력은 기존 탭 메모리다. 브라우저 종료 이후 영속 복구나 장치 간 동기화는 추가하지 않았다.
- 이미 기록한 단계를 닫고 나중에 같은 업무를 다시 열어도 과거 단계의 이력을 자동 연결하지 않는다. 최초 원본을 유지한 같은 열린 패널의 후속 작업만 지원한다. 실제 접수 결과는 기존 업무 화면에서 계속 조회할 수 있다.

## 판단과 남은 작업

- **독립 결과 종류:** T2와 T3의 명령 계약이 달라 결과 종류를 분리했다. T3의 실제 승인 이후만 기록하며 어떤 운영 종류였는지는 없는 정보로 추정하지 않는다.
- **실제 단계 표시:** 관리자 확인·받는 사람 수락·문서 저장·파일 생성을 분리해 아직 끝나지 않은 절차가 완료로 보이지 않게 했다.
- **보조 연결:** 기존 검증된 결과를 선택적 콜백으로 전달한다. 새 실행기·SQL·권한을 추가하지 않는다. 콜백과 이력 연결을 제거해도 원래 화면의 실행·복구는 남는다.
- **범위 수치 유지:** 기존 업무의 결과 연결을 보강한 것이므로 내부 경로 **55/61개**, 대표 직접 회귀 근거 **27/61개** 집계를 유지한다. 자연어만으로 전체 90% 완료하거나 실제 운영 성공을 확인한 수치가 아니다.
- **다음 범위:** 협업·일정·수업/학생 기록 등 다른 기존 화면의 결과 연결, 평가계획서 내부 작업·관리자/개인 설정·외부 계산기 단계는 남아 있다. 마지막 세 종류의 기존 기능 자체가 없다는 뜻은 아니다.

추가 SQL·환경변수·API 키·비용 정책 설정은 없다. 쌓인 PR 순서대로 검토 후 사용자가 병합·배포한다.
