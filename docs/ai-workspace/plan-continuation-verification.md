## 교사가 사용하는 흐름

1. ‘시간표 보여줘 그리고 교사 명부 보여줘’처럼 기존 복합 요청을 보관한다.
2. ‘다음 업무’ 또는 ‘2번 단계’로 한 요청을 입력칸에 준비한다. 선택만으로 조회·변경·유료 호출을 실행하지 않는다.
3. 기존 버튼으로 요청하고 대상·원본·최종 확인을 거친다.
4. 대화로 돌아오면 원문과 선택 상태가 남는다. 화면을 연 것은 ‘화면 연결됨’으로만 표시한다.
5. 개인 할 일 변경·개인 일정 등록은 검증된 접수증 뒤에 ‘서버 처리 확인’을 표시한다. 다음 단계는 다시 사용자가 요청한다.

‘업무 목록 보여줘’, ‘원문 다시 검토’, ‘업무 목록 닫아줘’도 지원한다. 목록이 없거나 번호가 범위 밖이면 안내하고 입력을 유지한다. 아직 처리하지 않은 계획만 전체 원문을 실행 입력으로 복원한다. 처리 확인된 단계를 재선택하거나 전체 원문을 복원해 같은 저장을 새 요청 번호로 반복하는 경로는 차단한다. 원문 열람과 명시적인 목록 닫기는 유지한다.

## 판단해서 정한 것

- **좁은 제어 명령:** 명확한 목록 조작만 로컬로 분류한다. 일반 질문·인용·부정문을 실행하지 않고 새 유료 분류기를 넣지 않는다. 누락 정보를 받는 중에는 제어 문장을 제목이나 교사 검색어로 채우지 않는다.
- **결과와 연결 분리:** 검색 목록·검토 카드·화면 열기는 서버 처리 완료가 아니다. 검증된 개인 업무 접수 뒤에만 결과 요약을 저장한다. 메시지·수합·시간표 승인 등의 완료를 임의로 추정하지 않는다.
- **원문과 실제 요청 분리:** 일정의 추가 답변은 요청 원문에 누적하되 최초 선택 원문은 `calendarDialogue.planPrompt`로 고정한다. 사용자 수정으로 다른 요청이 되면 기존 단계를 처리한 것으로 표시하지 않는다. 원키·명령·응답 검증은 기존 실행기를 따른다.
- **중복 방지:** 처리 확인된 단계를 다시 선택하거나 완료 상태를 지우는 전체 원문 복원을 차단한다. 목록 닫기와 원문 보기만으로 실제 업무를 되돌리거나 삭제하지 않는다.
- **보조 표시 실패 격리:** 후속 화면 갱신 예외가 서버에서 확인한 저장을 미확정으로 되돌리지 않는다. 접수 결과는 유지하고 원본 확인 안내를 표시한다.
- **보존 범위:** 계획과 결과 요약은 기존 탭 메모리에 보관한다. 브라우저 종료 후 영속 복원이나 여러 장치 간 동기화는 추가하지 않았다. 되돌릴 때는 제어 명령·계획 표시·접수 연결을 제거하면 기존 단일 업무와 메뉴가 남는다.
