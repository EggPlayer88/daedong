# AI 업무 처리 이력 연결 — 8차 검증 기록

2026-11-12. PR #124 `029b5614968ea0d772448423df7debd34aac3d4e`에서 시작했다. DB·RPC·인증·권한·메뉴 공개 범위·AI 모델/비용·HWPX 생성 엔진은 변경하지 않는다. 운영 계정이나 기존 시간표·시험 자료를 수정하지 않는다.

## 결과와 표시

| 기존 패널의 검증된 접수 | AI 업무 목록에 남기는 표시 |
|---|---|
| 메시지 start / reply | 메시지 전송 / 답장 전송 · 접수한 대화 수 |
| 수합 create / update | 수합 초안 저장 / 변경 저장 · 아직 미공개 |
| 수합 publish | 수합 공개 |
| 제출 save_draft / submit | 제출 초안 저장 · 최종 제출 전 / 최종 제출 접수 |
| 수합 review / withdraw / open_correction | 제출 검토 결과 저장 / 제출 철회 / 정정 기간 저장 |
| T2 approve이며 applied인 접수 | 시간표 교환·이동 승인 · 실제 반영 수업 수 |

단계에 **처리 내역 확인**과 가장 최근 결과를 표시한다. 같은 원본의 이전 접수는 접힌 이력으로 남긴다. 화면을 열거나 읽기만 하면 **화면 연결됨**이다. T3 대강 승인·시간표 공개·실시 기록·공식 인계·문서 생성은 이번 처리 이력에 추가하지 않았다. 원래 기능과 기존 결과 화면은 유지한다.

메시지 개별 전송은 모든 대화·메시지 번호를 보존한다. 수합 양식 업로드를 위해 먼저 만든 임시 초안은 결과로 기록하지 않고 마지막 초안 저장만 전달한다. 명령 거절·결과 미상·취소·읽음만으로 전송/제출/승인을 기록하지 않는다.

## 출처·복구·동시성

- 보관한 계획 객체, 단계 원문, 학교/계정/소속 범위, 기준일과 현재 작업 패널 번호를 고정한다. 같은 문구의 새 계획이나 새 패널에 옛 응답을 붙이지 않는다.
- 새 메시지·수합은 처음 전달한 `composeId`가 같은 작성의 start 또는 create/update만 최초 접수로 받는다. 출처 번호는 편집기와 원키 복구의 탭 메모리에만 보관하고 기존 서버 명령에 보내지 않는다.
- 초안 취소 뒤 새 수동 작성·답장·기존 제출에는 옛 출처가 없다. 처음 확인된 원본 번호를 고정한 뒤에는 같은 대화·수합·교환 요청의 후속 결과만 추가한다.
- 결과 미상은 기존 원래 요청으로 재확인한다. 같은 key는 이력을 한 번만 남긴다. 새 이력 기록이 실패해도 실제 저장을 실패로 바꾸거나 다시 전송하지 않는다.
- 접수된 단계의 재선택/전체 원문 실행 입력 복원은 차단한다. 다음 업무는 아직 접수 이력이 없는 단계의 입력만 준비한다. 공개·최종 제출 같은 후속 과정은 이미 열린 같은 작업 패널에서 기존 확인을 거친다.
- 이력은 기존 탭 메모리다. 브라우저 종료 후 복구나 여러 장치 동기화를 추가하지 않는다. 메시지 본문·학생 자료·수신자 명부를 이력에 복제하지 않는다.

## 발견한 문제와 이전 CI

코드 검토에서 AI 초안 취소 뒤 새 수동 작업의 결과가 같은 종류라는 이유로 옛 단계에 붙을 수 있음을 발견했다. 작성 출처를 고정하고 취소·새 작성에서는 제거하도록 고쳤으며 원키 복구·초안 취소 후 다른 전송/수합 저장 회귀를 추가했다.

새 연결 시험의 초기 fixture가 수신자 목록에 본인까지 반환해 실제 파서가 거절했다. 합성 응답을 기존 계약대로 본인 제외로 고쳤다. AI 안에서 자동 적용된 초안에 별도 적용 버튼이 있다고 기대한 시험도 현재 동작에 맞췄다. 제품의 수신자 검증을 완화하지 않았다.

## 판단해서 정한 것

- **기존 검증 뒤의 선택적 알림:** 각 업무가 이미 검증한 접수 결과만 콜백으로 전달한다. 실행기를 새로 만들거나 RPC 계약을 바꾸지 않기 위해서다. 콜백 예외는 업무 접수와 분리한다.
- **완료 대신 실제 행위 표시:** 초안·공개·최종 제출은 별개이므로 `recorded` 이력으로 보관한다. 수합 한 번 저장을 전체 수합 완료로 보이게 하지 않는다.
- **출처 고정:** 화면 종류만 같다고 원래 업무의 결과로 인정하지 않는다. 최초 작성 출처 또는 선택한 원본, 그 뒤 동일 원본이라는 두 단계를 둔다.
- **좁은 승인 연결:** 이번에는 T2의 검증된 approve/applied만 기록한다. T3 대강과 공식 인계는 승인 계약이 달라 무리하게 공통 완료로 묶지 않는다.
- **되돌리기:** 결과 콜백·계획 이력 표시를 제거하면 기존 패널의 실행·복구와 일반 메뉴가 남는다. DB 롤백이나 새 활성화 SQL은 필요하지 않다.
