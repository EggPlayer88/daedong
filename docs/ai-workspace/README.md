2026-11-12. 기준 main `ee4fd9db`에서 시작했다. 운영 DB와 기존 시험·실제 학교 자료는 변경하지 않는다.

## 목표와 완료 기준

사용자가 메뉴 이름을 익히기보다 하고 싶은 일을 말하고, 필요한 선택과 확인을 대화 안에서 마치도록 한다. 일반 대화의 넓은 관점과 업무별 전문 지침을 함께 사용한다. 핵심 화면과 수동 조작은 같은 업무 함수를 이용하며 유지한다.

“90% 이상”은 버튼 수가 아니라 교사가 수행하는 업무 흐름으로 측정한다. 이동이나 초안 열기만 된 업무를 완료로 세지 않는다. 대상 선택 → 필요한 정보 보완 → 실행 전 확인 → 서버 접수증 → 결과 열기까지 가능해야 완료다. 향후 업무 목록과 중요도를 고정해 측정하며 현재 전체 90% 달성을 주장하지 않는다.

처음 4회와 1~2회 보완을 예상했다. 이후 사용자의 계속 구축 지시에 따라 실제 수업·기간 업무·대화 이어가기와 처리 이력을 보완했으며 현재는 8차다. 작업 회수를 완료율로 계산하지 않는다. 새 SQL·권한·공개 범위·비용 정책 변경이 필요하면 구현 명세와 영향부터 따로 제시한다.

## 8차: 메시지·수합·시간표의 실제 처리 이력 연결

PR #124 위에서 기존 업무 패널이 받은 접수 결과를 보관한 AI 업무 목록에 연결했다. 메시지 전송·답장, 수합 초안 저장·공개·제출 초안·최종 제출·검토·철회·정정 기간, T2 교환·이동 승인 후 반영을 구분한다. 화면을 열기만 한 경우는 계속 **화면 연결됨**, 검증된 업무 접수는 **처리 내역 확인**이다. 초안 저장을 전체 업무 완료나 공개로 표시하지 않는다.

첫 접수는 해당 AI 초안의 작성 출처 또는 사용자가 선택한 원본에만 연결한다. 초안을 취소한 뒤 새로 작성하거나 다른 원본을 처리한 결과는 옛 단계에 붙지 않는다. 이후에는 처음 접수한 같은 대화·수합·교환 요청의 이력만 추가한다. 같은 요청 번호의 재확인은 이력을 중복 생성하지 않는다. 이미 기록된 단계는 새 번호로 다시 실행하지 않고, 현재 작업 패널에서 기존 공개·최종 제출 등 후속 절차를 계속한다.

연결 셸·계획·업무 패널의 원문/날짜/학교 범위와 요청 번호는 유지한다. 보조 표시가 실패해도 실제 전송·저장·승인 결과를 미확정으로 되돌리지 않는다. T3 대강 승인, 공식 인계, 문서 생성과 다른 업무의 결과 요약은 이번 연결 범위에 포함하지 않는다. 해당 기능은 기존 패널에서 계속 사용한다.

[8차 검증 기록](workflow-results-verification.md): 전체 단위 **5,602건**, 중복 제외 브라우저 **15파일·260건**, TypeScript·운영 빌드 통과. 기존 61개 업무의 경로를 보강하므로 **55/61개 내부 경로**, **27/61개 직접 대표 시나리오 근거** 집계를 유지한다. 자연어만으로 전체 업무의 90%를 완료했다는 수치가 아니다.

## 7차: 다음 업무를 대화로 이어가기와 처리 결과 보존

화면 연결은 **화면 연결됨**, 검증된 개인 할 일 변경·일정 등록 접수증은 **서버 처리 확인**으로 구분한다. 일정 누락 답변을 보완해도 최초 단계 원문을 유지한다. 응답이 끊기면 완료로 표시하지 않고 원키로 복구한 뒤 표시한다. 처리 확인된 단계의 재선택과 전체 원문 재실행 입력 복원을 막아 새 번호의 중복 등록을 예방한다. 원문 보기와 목록 닫기는 가능하며 업무 자료는 변경하지 않는다.

[7차 검증 기록](plan-continuation-verification.md)에 실제 실행과 판단을 적었다. 관련 브라우저 **11파일·134건**, TypeScript·운영 빌드 통과. 이번에는 같은 61개 업무의 연결 범위를 늘리지 않고 연속 처리와 결과 보존을 보완했으므로 기존 **55/61개 내부 경로** 집계를 유지한다. 모든 업무의 완료를 접수증으로 추적하거나 자연어만으로 90% 완료한다는 뜻은 아니다.

## 4차: 복합 요청과 남은 업무 연결·통합 점검

3차 PR #120 위에 쌓았다. 여러 일을 한 번에 부탁하면 최대 4개 단계로 나누고 원문을 보관한다. 단계 선택은 입력칸만 준비한다. 각 요청은 다시 확인해 실행하며, 다음 단계를 자동 시작하거나 선택한 단계를 완료로 표시하지 않는다. 번호 목록이나 `그리고`·`이어서`로 구분한 완전한 명령을 지원하고, 메시지 본문·인용 속 명령을 별도 업무로 승격하지 않는다. 지원하지 않는 단계가 섞이면 일부만 실행하지 않는다.

| 연결 | 동작과 확인 |
|---|---|
| 복합 요청 | 원문 → 단계 목록 → 단계 선택 → 기존 요청 검토·실행. 새 입력을 덮어쓰지 않음 |
| 협업 | AI 안에서 요청·받은 요청·연결 할 일·완료 확인을 기존 화면으로 처리 |
| 학교 자료 | 정확한 원문 판·인용 위치 조회, HWPX 가져오기·초안·별도 게시 확인 |
| 전체 일정 | 공유·대상 지정·여러 날짜 일정, 원본 변경 비교, 일괄 가져오기·확정 |
| 복구와 작은 화면 | 결과 미확정은 원래 요청만 재확인. 320px·높이 축소·두 배 글씨의 입력·복귀 점검 |

기준 날짜가 바뀌면 보관한 계획을 다시 검토한다. 선택해 둔 `내일` 같은 입력도 새 날짜로 자동 재해석해 실행하지 않는다. 계정·학교·소속 경계는 기존 연결과 탭 메모리 규칙을 유지한다. 브라우저 종료 후 영속 복구를 추가하지 않았다.

[업무 연결 범위](coverage.md)를 61개 업무로 정리했다. 4차 시점 **51/61개(83.6%)**는 AI 작업 공간 안에서 이용하는 경로가 있다. 이는 8개 기본 화면·확인 카드와 43개 기존 업무 패널의 합이며, **자연어만으로 90% 완료한다는 뜻이 아니다**. 나머지는 일반 메뉴·외부 계산기·아직 연결하지 않은 기존 기능이다. 전체 사이트 구축률이나 운영 성공률과 구분한다.

이번 변경은 DB·권한·AI 모델/예산·파일 엔진을 바꾸지 않는다. [4차 검증 기록](completion-verification.md)과 [통합 검토 요청](review-request.md)을 함께 본다.

학생 기록은 유효 관찰과 교사가 확인한 평가 근거만 기존 AI 문맥으로 전달한다. 선택된 원본의 판·hash·epoch·구간을 유지하며 상담 자료를 새로 AI에 연결하지 않는다. AI 결과를 기록으로 자동 확정하지 않는다.

### 판단해서 정한 것

- `specialist-workflows.ts`에 전문 작업의 명칭·별칭·목표·단계를 모았다. 새 서버 계약을 만들어 기존 검증과 갈라지지 않도록 했다. 되돌릴 때는 `ConnectedWorkspace`의 전문 패널 진입과 해당 분류기를 제거하면 일반 메뉴가 남는다.
- 전문 편집기의 미저장 입력·미확정 요청이 새 업무 목표보다 우선한다. 동적 수업·학기별 초안 슬롯도 검사한다. 작성 중에는 기존 잠금이 적용되며, 먼저 저장/취소 후 대화로 돌아간다. 탭 메모리 보존이며 브라우저 종료 후 영속 복원을 약속하지 않는다.
- 학교 관리 재연결 때 최초 메뉴 대신 실제 미확정 요청/보관 입력이 있는 탭을 먼저 연다. `SchoolAdministration`의 시작 탭 선택만 바꿨고 명령·권한 검증은 그대로다.
- 이전 알림·준비 링크의 이동 정보를 새로운 전문 요청에 재사용하지 않는다. 같은 대화로 돌아오기만 할 때는 편집기를 유지한다. 2차 메시지·문서의 접어 둔 초안으로 답변을 돌려보내는 기존 경로는 유지한다.
- CSV 가져오기는 담당 수업을 직접 선택한 뒤 기존 입력기만 한 번 연다. 취소·권한 거절·조회 실패 이후 자동 재시작하지 않는다. 파일 전송·자료 반영은 별도 확인이다.

실제 운영 DB·계정·시간표·학생 자료와 AI 비용은 이번 자동 시험에서 변경하지 않았다. [3차 검증 기록](specialists-verification.md)을 참조한다.

## 2차: 메시지·수합·문서 완료 연결

1차 PR #118의 일반/전문 대화·개인 업무 기반 위에 구현한다. #118과 후속 PR은 순서대로 병합하며 운영 DB 적용은 추가로 필요하지 않다.

대화에서 작성한 메시지·수합 초안, 검색해 선택한 메시지·수합·문서, 해당 메뉴를 열라는 요청은 AI 안의 작업 패널로 이어진다. 필요한 사람은 사용자가 후보에서 선택한다. 메시지·수합의 최종 쓰기는 AI 답변을 실행하는 방식이 아니라 현재 업무 화면과 같은 검토·확인 버튼을 통해 실행한다.

| 흐름 | 2차 연결 |
|---|---|
| 메시지 | 본문·수신자 보완 → 최신 대상 확인 → HWPX 첨부 → 발송 미리보기 → 명시 전송 → 접수 결과/대화 |
| 수합 만들기 | 제목·기한·제출 대상 → 양식 선택과 검사 → 초안 저장 → 별도 공개 확인 |
| 수합 제출 | 기존 수합 선택 → 내 제출 파일 작성 → 검사·초안 저장 → 파일/판/대상 확인 → 별도 최종 제출 |
| 내 문서 | 문서 찾기/내용 초안 → 편집·확인 → 기존 문서 저장 |
| 질문형 HWPX | 양식 선택 → 질문 답변 → 저장 → 기존 생성기로 HWPX 생성 → 내려받기·파일 확인 → 명시 수합 첨부 → 별도 최종 제출 |

문서 작업에서 AI 도움을 요청하면 작성 중인 문서를 보관한 채 대화로 돌아가고, 결과를 같은 양식과 답변 판에 비교한다. 파일은 첨부 선택만으로 전송하거나 AI에 보내지 않는다. 문서의 생성물 번호를 제출 파일 번호로 대신 쓰지 않으며 기존 예약·업로드·검사를 재사용한다.

### 판단해서 정한 것

- 기존 `MessagingWorkspace`, `CollectionServerPanel`, `DocumentsWorkspace`에 `presentation='assistant'` 표시 방식을 추가했다. 전송·생성·권한·복구 컨트롤러를 복제하지 않기 위해서다. 일반 페이지 표시가 기본이며, 표시 변경을 되돌리려면 연결 셸에서 기존 페이지 이동을 사용하면 된다.
- AI 작업과 일반 메뉴의 같은 편집기는 동시에 마운트하지 않는다. 같은 소속의 초안/미확정 요청 저장소에 두 화면이 쓰는 문제를 방지한다. `ConnectedWorkspace`와 `assistant/delivery-workspace.tsx`가 단일 작업 선택과 전환을 관리한다.
- 대화 안의 최종 수합 제출에도 파일·단위·판·기한을 별도로 확인한다. 확인 후 최신 자료가 달라지면 다시 검토해야 한다. 변경 위치는 `CollectionEditorView`의 대화 표시 분기다.
- 문서 생성물 전달은 내려받기와 현재 요청이 끝난 뒤 전환한다. 결과 미확정 상태를 새 수합 요청으로 바꾸지 않는다. 전달받은 파일을 사용하지 않을 때 저장된 문서 원본을 삭제하지 않는다.
- 이번 단계에서도 복합 요청을 자동으로 여러 번 전송하지 않는다. 대화의 업무 패널에서 한 건씩 결과를 확인하고 다음 작업으로 이어간다. 기능 전체의 대화 완료율은 4차에 측정한다.

DB·RPC·RLS·인증·공개 범위·AI 모델/예산·파일 생성 엔진 변경은 없다. 실제 운영 전송이나 유료 AI 호출 없이 합성 계정과 서버로 검증한다. [2차 검증 기록](delivery-verification.md)을 참조한다.

## 1차 기반 구현

### 일반 대화와 전문 대화

분야는 일반 대화, 일정·할 일, 메시지·협업, 문서·수합, 시간표, 수업·기록, 학교 관리의 7가지다. 모든 분야가 목표·대안·영향·확인하지 못한 점을 함께 살피며, 단순한 질문에는 짧게 답한다. 학생/교사/담당자의 다른 관점을 제안하되 학교의 확정 사실처럼 꾸미지 않는다.

자동 선택은 고정 학생 문맥, 명시 요청 종류, 선택한 자료를 먼저 따른다. 그 외에는 질문에 명확히 드러난 분야 단서를 보조적으로 사용한다. 복수 분야의 단서가 동점이면 일반 대화로 남는다. 교사가 직접 일반 대화나 특정 분야를 고를 수 있으며 질문을 작성하는 중에도 분야를 바꿀 수 있다.

분야 선택과 자료 범위는 별개다. 분야를 바꿔도 학교/개인 모드·근거·학생 선택·권한·실행 대상은 바뀌지 않는다. 학교 규정/현재 현황/학생의 실제 기록은 허용된 근거로만 설명하고, 일반 지식·아이디어·추론은 그 성격을 구분한다. 이 변경은 검색 도구나 실제 데이터 접근을 새로 제공하지 않는다.

분야 지침과 표시 문구의 원본은 `apps/main/api/workhub-ai/_assets/conversation-profiles.json`이다. 기존 exact RPC 계약을 바꾸지 않도록 요청 문자열 끝의 정형 표식으로 분야를 전달한다. 표식은 구두점과 한 자리 번호로만 구성해 기존 SQL의 첫 줄 제목과 2글자 이상 검색 낱말에 영향을 주지 않는다. 원요청은 그대로 접수·보관하고 화면에서만 표시용 표식을 벗긴다. 복구와 Sonnet 재검토는 원요청을 재구성하지 않는다. 일반 대화는 기본적으로 기존 원문 그대로다. 사용자가 표식과 같은 문장으로 끝내면 한 겹 더해 원문을 보존한다. 입력 한도 표시는 표식을 포함한 서버의 기존 한도와 동일하게 계산한다. 이전에 저장한 질문이 우연히 동일한 표식으로 끝났던 경우 표시 시 한 겹이 제거될 수 있으나 저장 원문은 변하지 않는다.

### 화면

- 질문 입력과 현재 대화가 중심이며, 현재 자료 범위는 한 줄로 표시한다.
- 자료 범위 변경·요청 설정·예산·기억·과거 대화는 필요할 때 펼친다.
- 분야에 맞는 예시는 입력만 채운다. 예시 선택으로 AI 호출이나 저장을 실행하지 않는다.
- 필요한 권한/결과 미확정/실패 안내, 근거 인용, 학생 근거 확인, 유료 정밀 검토 확인은 유지한다.
- 기존 프리텐다드·토스페이스 및 밝은/어두운 화면의 공통 스타일을 사용한다.

### 대화 안에서 개인 업무 완료

| 업무 | 구현 상태 | 확정 시점 |
|---|---|---|
| 메뉴 이동·허용 자료 찾기 | 기존 기능 유지 | 사용자 지시로 즉시 이동/조회, 유료 호출 없음 |
| 새 개인 할 일 | 기존 제안·검토·확정 유지 | 확인한 할 일 추가 |
| 기존 할 일의 메모·기한 수정/완료 | 이번에 대화 안으로 연결 | 동명 후보 선택 → 최신 원본 비교 → 확인한 변경 저장/완료 |
| 개인 일정 등록 | 이번에 대화 안으로 연결 | 누락 날짜·시각 보완 → 나만 보기 검토 → 확인한 일정 등록 |
| 메시지·수합 초안 | 기존 기능 유지 | 대화에서 대상/기한을 보완하고 기존 작성 화면에서 최종 확인 |
| 공유·복수 날짜 등 복잡한 일정 | 1차에서는 일반 화면, 4차에서 AI 안의 기존 편집기로 연결 | 기존 일정 화면의 검토·저장 |

실행기·검토 카드·React 복구 훅·연결 어댑터를 분리했다. 대화의 개인 업무도 기존 TaskAdapter/CalendarAdapter를 이용한다. AI 답변이나 학교 자료 안의 문장을 실행 명령으로 해석하지 않는다.

첫 저장 전에 학교/계정/소속/기준일과 최신 할 일 원본을 다시 확인한다. 원본 판·내용이 바뀌면 새 판에 임의 적용하지 않는다. 원키/원문은 전송 전에 탭 메모리에 보관한다. 통신 유실·잘못된 접수증·전송 후 계정 변경은 결과 미확정으로 남겨 원래 요청으로만 재확인한다. 같은 요청의 재확인은 이미 바뀐 원본을 다시 고르지 않는다. 다른 편집기나 미확정 요청이 있으면 새로운 변경을 막는다. 새로고침·브라우저 종료 이후의 영속 복구를 추가한 것은 아니다.

## 보존 경계와 후속

DB/RPC/RLS, 로그인·권한·공개 범위, 학교별 키·월 예산, Haiku/Sonnet 배정, 출력 토큰 한도, 정밀 검토의 명시 확인, HWPX 생성 엔진은 그대로다. 분야별 지침이 추가되어 요청별 입력 토큰은 달라질 수 있으며 기존 토큰 계수·비용 예약·정산을 그대로 적용한다. 이번 개인 업무 명령은 별도 유료 호출을 추가하지 않는다.

6차까지 개인 업무·메시지·수합·문서·시간표·수업·기록·학교 관리·협업·학교 자료·전체 일정·오늘 수업/업무·급식·알림을 연결했다. 상대에게 전송하거나 공개·제출하는 순간에는 대상과 내용을 확인한다. 평가계획서는 기존 화면 새 탭 연결까지만 제공한다. 남은 연결은 평가계획서의 내부 편집·생성·제출, 관리자/개인 설정, 외부 로컬 계산이다. 자연어 안내와 직접 통합 회귀 근거도 더 넓혀야 한다. 일반 교사에게 AI 메뉴를 추가 공개하는 작업과 실제 교사 연결은 별도다. 전체 업무의 자연어 완료 90%는 아직 측정하거나 확정하지 않았다.

이번 변경은 추가 SQL 없이 앱/서버 배포로 적용한다. 자동 시험과 실제 운영 검증의 구분은 [검증 기록](verification.md)에 남긴다.
