# Claude 검토 요청 — 대화 중심 업무 1~10차

기존 업무를 AI 대화 안에서 조회·검토·확정하는 연결을 검토해 주세요. PR #118 → #119 → #120 → #121 → #122 → #123 → #124 → #125 → #126 → 10차 후속 PR 순서로 쌓였으며, 최신 후속 PR의 기준 커밋과 CI를 먼저 확인해 주세요. 병합·운영 DB 적용·기능 활성화·일반 교사 공개를 요청하는 문서가 아닙니다.

## 구현 범위

- 일반 대화와 업무별 전문 지침, 간결한 입력 화면, 개인 할 일 변경·완료와 개인 일정 검토·등록.
- 메시지·수합·문서·질문형 HWPX의 기존 편집기·확인·접수 결과를 AI 안에 연결.
- 시간표·수업/학생·기록·학교 관리·인계의 기존 대상 선택과 승인 흐름 연결.
- 협업·학교 자료·공유/여러 날짜/일괄 일정 연결. 명시 복합 요청 최대 4단계, 원문 보존과 한 단계씩 실행.

- 오늘 업무·급식·알림 원본의 AI 내부 조회. 제목·상태 변경과 완료/취소한 할 일 다시 시작은 대상 선택·원본 비교·확인 후 저장.
- 오늘 요약의 실제 날짜별 수업·현재 시각·취소 상태와 정확한 시간표 상세 연결. 평가계획서 작성/제출은 기간 업무 표시 설정 안에서 기존 화면을 명시적으로 새 탭에 연결.
- 보관한 업무의 다음/번호 선택·목록·원문 대화 제어. 화면 연결과 개인 업무 접수 확인을 구분하고 처리 확인된 단계를 재실행 입력으로 만들지 않음.
- 메시지 전송·답장, 수합 저장/공개/제출 등의 단계별 접수와 T2 교환·이동 승인·반영 이력을 원래 AI 업무에 연결. 처음 초안의 출처와 같은 원본을 고정하고 초안 취소·별개 새 작성의 결과를 오귀속하지 않음.
- T3 대강·보강·취소·재개 승인과 공식 인계 단계별 접수, 문서함 저장·내용 확인·보관, 질문형 HWPX 생성 결과를 연결. 파일 생성이나 문서 저장을 최종 제출로 표시하지 않음.

- 협업 요청/응답/완료 확인, 일정 단일/일괄 저장, 수업/명부/관찰/평가/활동 자료 처리 결과를 같은 AI 단계로 연결. 상담 본문과 처리 사실은 제외.

## 중점 확인

1. **말과 실행의 구분:** 일반 조언·자료 인용·메시지 본문이 실행 명령이 되지 않는지. 복합 요청 일부만 실행하거나 다음 단계를 자동 시작하지 않는지. 선택 표시를 완료로 오해하게 하지 않는지.
2. **선택·확정:** 교사/학생/수업/학기/자료를 기존 권한 안에서 직접 고르는지. 공개·발송·제출·승인은 기존 최종 확인을 유지하는지.
3. **입력·복구:** 같은 편집기 중복 마운트, 입력 덮어쓰기, 날짜 변경 후 상대 날짜 재해석, 결과 미상일 때 새 요청 번호 발급이 없는지.
4. **원문 근거:** 학교 자료 ID·판·인용 위치와 학생 기록의 revision/hash/epoch가 이어지는지. 상담 자료를 AI 문맥으로 추가하지 않았는지.
5. **교차 흐름:** 메시지/문서/학교 자료에서 AI 조언 후 돌아오기, 수합 제출, 일정에서 수업 열기, 협업과 할 일, 원래 일반 메뉴가 계속 동작하는지.
6. **접근성:** 320px·확대 글씨·키보드 초점·처리 중 잠금/복귀. 실제 휴대폰 IME는 별도 미검증으로 남겨 주세요.
7. **비용·권한:** 기존 Haiku/Sonnet, 명시 정밀 검토, 예산/정산, 인증/RLS/메뉴 공개와 HWPX 엔진에 변경이 없는지. 무료 명령이 유료 요청으로 우회하지 않는지.

8. **일상 업무:** 조회 실패와 정상 0건을 구분하는지, 급식 날짜와 현재 권한 기준일을 혼동하지 않는지. 알림 원본 열기로 자동 읽음·완료가 되지 않는지. 제목·재개·상태 변경에서 다른 필드와 원키 복구를 보존하는지.
9. **오늘 수업:** 기본 배치와 실제 날짜별 수업을 혼동하지 않는지. 교환·취소·조회 실패·늦은 응답, 선택한 수업의 ID/날짜/시각과 전체 시간표 진입을 확인해 주세요.
10. **기간 업무:** 숨김·설정 조회 중·오류·권한 변경에서 새 평가계획서 링크가 남지 않는지. 자동 팝업·유료 호출·생성·제출 없이 사용자 클릭으로만 새 탭을 여는지. 현재 대화 입력을 유지하고 원래 문서 엔진과 비용 계약을 바꾸지 않는지 확인해 주세요. 기간 업무 숨김은 메뉴 표시 설정이며 이미 열린 기존 화면의 권한을 새로 철회하는 계약은 아닙니다.
11. **연속 업무와 결과:** 다음 단계는 입력만 준비하는지, 목록 명령이 누락 일정/수신자 답변으로 섞이지 않는지, 실제 개인 업무 접수증 뒤에만 서버 처리 확인을 표시하는지 확인해 주세요. 기준일 변경·원키 복구·최초 단계와 다른 수정 입력·처리된 단계 재선택·전체 원문 복원 차단을 함께 검토해 주세요. 화면을 연 것만으로 메시지 전송·수합 제출·승인을 완료했다고 표시하면 안 됩니다.
12. **업무 패널의 접수 이력:** 전달한 초안 취소 후 다른 메시지 전송/답장·새 수합·기존 제출이 옛 계획에 붙지 않는지 확인해 주세요. 새 초안 출처는 복구 메모리에서만 보관하고 서버 명령에는 넣지 않습니다. 수합 양식 업로드 도중 중간 생성은 완료로 기록하지 않으며, 마지막 초안 저장·공개·최종 제출을 구분합니다. 같은 요청 번호 복구, 같은 원본의 후속 작업, 다른 원본·계획·날짜·학교·작업 패널의 늦은 응답, 콜백 예외로 재전송이 생기지 않는지도 확인해 주세요. T2와 T3는 각각 approve/applied만 기록합니다.
13. **승인·인계·생성물:** 공식 인계의 관리자 확인과 받는 사람 수락, 신청 취소와 반려를 실제 action/state로 구분하는지 확인해 주세요. 구형 공식 담당 접수증을 새 인계 접수로 추정하지 않습니다. 문서 ID/판과 별도 AI 초안 출처, 새 문서와 기존 문서의 구분, 생성 Artifact의 양식/답변 ID·판·해시·크기를 확인해 주세요. 생성물은 서버 접수 시각이 없어 `observedAt`을 별도 사용하며 파일 확인·최종 제출은 기존 절차로 남습니다. 이미 기록한 단계를 닫고 다시 연 경우 자동으로 이력을 재연결하지 않습니다.

14. **협업·일정·학생 기록:** 완료 확인 요청을 협업 완료로 표시하지 않는지, 평가 초안과 확인 저장을 구분하는지 확인해 주세요. 일정 저장은 원래 ID·다음 판·정규화한 입력을 대조하고 일괄은 prepareId와 전체 접수 행을 검증합니다. 수업 안의 별도 학생 기록·다른 전문 작업을 같은 단계에 붙이지 않으며 상담 저장/철회 사실도 전달하지 않습니다. 활동 원문 정정 A→B→C는 직전 import ID만 잇고 A로 되돌아가거나 A에서 갈라지는 결과를 붙이지 않습니다. 결과 콜백 예외·늦은 응답·후속 조회 실패가 중복 저장을 만들지 않는지 확인해 주세요.
15. **#126 검사 보완:** SQL 원문과 SQL_REF를 유지하고 임시 시험 사본만 해시 검증 뒤 보정합니다. 인계 응답의 version·recordedAt을 실제 SQL 응답과 정확히 대조하고, 해시/비교식/임시 경로가 다르면 중단하는지 확인해 주세요.
