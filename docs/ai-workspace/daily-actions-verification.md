# AI 일상 업무 연결 — 5차 검증과 판단 기록

2026-11-11. PR #121 위에서 오늘 업무·급식·알림과 개인 할 일의 제목·상태 변경을 연결했다. 운영 DB, 실제 계정 자료, 인증·권한·공개 범위, AI 모델·예산·파일 생성 엔진은 변경하지 않았다.

## 구현과 확인 경계

| 요청 예시 | 결과 | 확정 경계 |
|---|---|---|
| 오늘 업무 요약해줘 | 확인할 일·내 할 일·관련 일정·급식의 원본 조회 | 조회만 수행. 읽음·완료·저장 자동 실행 없음 |
| 내일 급식 알려줘 | 학교 기준일에서 계산한 날짜의 급식 | 기존 나이스 조회·갱신 정책 유지 |
| 업무 알림 보여줘 | 기존 알림 목록과 지원하는 업무 원본을 AI 안에서 열기 | 읽음 버튼과 원본 열기는 별도 |
| 할 일 제출 자료 확인 제목을 자료 점검으로 바꿔줘 | 후보 선택 → 원본 제목·새 제목 비교 | 확인한 변경 저장 |
| 할 일 자료 점검 상태를 대기로 바꿔줘 | 기존 5개 상태 중 하나를 비교 | 확인한 상태 변경 |
| 할 일 자료 점검 다시 시작해줘 | 완료·취소한 내 업무를 할 일 상태로 복귀 | 확인한 할 일 다시 시작 |

일반 질문·인용·부정문은 조회나 변경 지시로 승격하지 않는다. 동명 업무를 자동 선택하지 않으며 제목 120자·메모 2,000자 제한을 그대로 사용한다. 새 변경은 최신 원본 판을 확인하고, 미확정 결과는 원래 명령·요청 번호로만 복구한다. 제목·기한·메모 등 다른 필드를 임의 수정하지 않는다.

## 점검 중 보완

- AI 메시지 작성 화면이 목록을 숨기는 기존 규칙 때문에 알림·오늘 업무의 전체 대화 목록까지 가려졌다. `initialTab`과 명시적인 `showThreadList`로 구분하고 조회·필터·새로고침·원본 이동을 회귀로 고정했다. 일반 메시지 화면과 초안 복구 우선순위는 유지한다.
- 날짜·학교 소속 변경 중 늦은 응답을 폐기하고, 조회 실패를 정상 0건으로 표시하지 않는다. 과거 자료 판과 현재 원본 조회를 혼동하지 않는다.
- PR #120 CI의 학교 관리·수업 시험은 안내 문구가 부모 잠금 해제보다 먼저 렌더되는 경합이었다. 기대값은 낮추지 않고 실제 사용 가능한 복귀 상태를 기다리도록 수정했다. 원키·원문·적용 1회 검증을 보존했다.

## 판단해서 정한 것

1. **무료 결정 규칙:** 명시적 날짜/상태/제목과 조회 경로만 기존 로컬 분류기로 처리한다. 새 유료 분류·추가 호출·모델 전환을 넣지 않는다. 모호하면 질문으로 돌리고 업무를 추측해 저장하지 않는다.
2. **조회와 실행 분리:** 오늘 요약·알림은 원본 조회다. 알림을 열었다는 이유로 읽음 처리하거나 업무를 완료하지 않는다. 기존 상태 변경·읽음 버튼과 권한을 사용한다.
3. **원래 편집기 재사용:** AI의 할 일 목록과 알림 원본은 기존 TaskPanel·MessagingWorkspace 등으로 이어진다. 별도 복제 저장 경로나 API 계약을 만들지 않았다.
4. **범위 수치:** 61개 목록 중 내부 이용 경로는 **54개(88.5%)**다. H01은 업무 요약의 부분 연결이며 실제 날짜별 수업 시각까지 종합하지 않아 일반 화면 연결로 남겼다. 자연어만으로 90% 완료하거나 운영 성공률을 뜻하지 않는다.
5. **되돌릴 지점:** 이 앱 변경을 되돌리면 기존 일반 메뉴에서 같은 업무를 계속 이용한다. SQL·자료 변환·외부 설정이 없으므로 데이터 되돌리기는 필요하지 않다.
