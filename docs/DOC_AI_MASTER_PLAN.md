> 2026-08-17. 두 트랙(웹앱 doc-ai / 일괄 변환 파이프라인)을 이 문서로 통합.
> 이전 대화방의 「인수인계_평가계획서_AI_초안생성.md」 는 이 문서로 대체·흡수됨.
> 최종 목표: **교사가 편리하게 양질의 평가계획서를 AI 도움으로 작성한다**
> (정량 목표: 교사 수정 5% 이하 초안. 첫 학기 5~15% → 반복 학기 5%)

## 0. 현재 보유 자산 (실전 검증 상태)

| 자산 | 상태 |
|---|---|
| daedong-school.vercel.app /doc-ai (챗 → hwpx) | 배포·가동. 첫 실전 산출물 검증 완료 |
| template.hwpx (토큰 130개) + manifest 계약 + generate v2 | 무결성 검증 통과. 조건부 문장·블록 삭제 작동 확인 |
| 성취기준 DB (542개, 2022 13교과 + 한문 2015) | 실측 검증. 교과별 3천~3.3만 자 — 프롬프트 캐싱으로 전체 주입 가능 |
| 학교 상수 (2026-2 학사일정·시수 공식·시험 일정) | 적용됨 |
| 첫 산출물 피드백 5건 + DB 통합 지시 | CC 반영 진행 중 (개선 2차 블록) |

핵심 통찰 (이전 대화방, 유효): **이것은 생성이 아니라 변환 문제다.** 같은 교사가
같은 교과서로 가르치므로 진도·성취기준·관행은 작년 문서에 이미 검증돼 있다.
환각이 개입할 자리는 추출 정확도뿐이다.

## 1. 통합 아키텍처

```
[사전 구축 1회]                          [교사 사용 상시]
참고 파일 5종 ──파서──> 36블록          교과·학년 선택
        │                  │                  │
        │            prefill JSON ──────> 챗: "작년 기준 초안 잡음.
        │           (교과·학년별)              달라진 것만 알려주세요"
        │                  │                  │ 수행평가만 유지/변경/신규 3분기
   성취기준 DB ──검증기──> 매칭 리포트         │
   (1·2학년 2022 재선정,                 확인 카드 → generate → hwpx(초안)
    3학년 2015 유지)
```

- 참고 파일 원본 파싱은 **사전 구축에서만**. 웹앱 런타임은 prefill JSON 만 읽는다.
- 런타임 참고 파일 업로드 기능은 보조로 유지 (prefill 없는 교과·개인 자료용).
- 출력은 전 경로가 **단일 엔진**(template.hwpx + generate v2) 경유. 이중 구현 금지.

## 2. 참고 파일 역할 분담 (이전 대화방 정리, 유효)

| 출처 | 가져올 것 |
|---|---|
| 2025학년도 2학기 (1·2·3학년) | 학기 진도, 단원 배열, 시수 패턴, 수행평가 구성·유형, 성취수준 진술 |
| 2026학년도 1학기 (1·2·3학년) | 반영비율 관행, 서술 톤, 학교 공통 문장 (2학년분은 이전 대화방에 수령됨 → 이 방으로 재업로드 필요) |

⚠ **교육과정 분기 (절대 규칙)**: 2026학년도 기준 1·2학년 = 2022 개정, 3학년 = 2015 개정.
2025-2 파일은 전부 2015 개정이므로 **1·2학년 prefill 의 성취기준 코드는 복사 금지** —
단원·내용은 유지하되 코드는 DB(2022)에서 재선정하고 매칭 리포트로 검토받는다.
3학년은 작년 코드 그대로 사용 가능.

## 3. prefill JSON 명세 (교과·학년별 1파일)

manifest v2 의 필드 구조를 그대로 따르되 출처 표시를 더한다:
`{ source: {y2025s2: 파일명, y2026s1: 파일명}, monthly_plan[...], eval_purpose[...],
exam: {count, ratio, mc/essay 관행}, perf_areas[...], perf_plans[...](작년 전문),
achievement_levels{...}, min_achievement_plan, _match_report: [성취기준 교체 내역] }`

배치: `api/doc-ai/_assets/prefill/{subject}_{grade}.json`

### 3-1. 정규화 규칙 (작년 원본 → prefill)

작년 문서에 있던 값을 **그대로 계승할지, 고쳐서 계승할지** 를 사례마다 적어 둔다.
파서가 매번 판단하면 해마다 답이 달라진다.

| 사례 | 원본 | 판정 | prefill 에 넣는 값 |
|---|---|---|---|
| 도덕 수행 만점 | 30점 | **원본 오기** — 각 평가는 각각 100점 만점이 학교 관행 (실측) | 100점 만점으로 정규화. 반영비율 30% 는 그대로 |
| 역사 지필 배점 | 선택형 50 + 서·논술형 50 | **실제 관행** — 합 100 이라 배점 규약에 맞는다 | 그대로 계승 (파서 정상 판정) |

원칙: **합이 100인 조합은 관행으로 보고 계승**, 만점 규약(각 평가 100점)을 어기는
값만 정규화한다. 정규화한 항목은 `_match_report` 에 "원본 → 보정" 으로 남겨
교사가 되짚을 수 있게 한다.

### 3-1-1. 정기시험 3분류 전환 (2026학년도부터 · 전 교과 공통)

정기시험 평가방법이 **선택형(객관식) / 단답형·완성형(주관식) / 서·논술형(주관식)**
3분류로 바뀌었다. 작년 문서는 2분류(선택+서논)라 **prefill 로 그대로 옮길 수 없다.**

- 작년 "선택형 N점" 안에 올해의 단답형·완성형이 섞여 있다
- **파서·AI 가 나누지 않는다.** prefill 에는 작년 값을 `mc` 에 그대로 두고
  `_needs_split: true` 를 붙여, 대화에서 교사에게 나눠 받는다
- 서·논술형 30% 산입은 `essay` 만이다 — 단답형·완성형은 주관식이지만 **제외**

### 3-2. 횟수 세트 전환 (작년 조합이 올해 세트 밖일 때)

올해 세트는 시험 0회→수행 3개 / 1회→2개 / 2회→1~2개 다
(`school-constants.perf_count_rule`). 작년 조합이 세트 밖이면 prefill 에 그대로
넣되 **전환 안내를 붙인다** — 어느 영역을 합치거나 뺄지는 교사가 정한다.

- 알려진 사례: **2025-2 3학년 영어** = 시험 1회 × 수행 3개 → 올해 수행 2개

## 4. 실행 단계

### Phase A — 사전 구축 (참고 파일 도착 즉시, Claude Web 세션)
- [ ] A1. 파서 제작: 원본 평가계획서 hwpx → 교과 블록 분해 → 필드 추출
      (표 변종 대응: 교과별 열 수 상이·병합 불규칙·쪽 분할. **여기가 첫 관문** —
      깨지면 뒤가 무의미하므로 36블록 전수로 검증)
- [ ] A2. prefill 36개 생성 + 검증기 (성취기준 DB 대조, 비율 합, 배점 정합)
- [ ] A3. 매칭 리포트 산출 → 계란님 검토 (특히 1·2학년 2022 코드 재선정 결과)
- [ ] A4. 파서·prefill 을 repo 에 배치 (내년 재사용 자산)

### Phase B — 웹앱 prefill 모드 (Claude Code)
- [ ] B1. 교과·학년 선택 시 prefill 로드 → 시스템 프롬프트에 주입
- [ ] B2. 프롬프트: prefill 있으면 "요약 제시 → 차이만 질문" 모드.
      시수/누계는 올해 학사일정으로 항상 재계산. 수행평가는 항목별 3분기
- [ ] B3. prefill 없는 교과는 현행 백지 모드 (DB 주입 유지)

### Phase C — 시범 → 전 교과
- [ ] C1. 수학(계란님 본인 교과)으로 E2E: 수정량 실측 (5~15% 기대)
- [ ] C2. 교사 2~3명 시범 → 프롬프트 다듬기 → 전체 안내
- [ ] C3. (선택) prefill 기반 36블록 일괄 초안 생성해 배포하는 방식과 병용 검토

## 7. 백로그 (규정 검증기 후속 — Phase 2+)

규정 룰셋(V01~V18) 통합 시 **의도적으로 미룬** 항목. 잊지 않기 위해 여기 고정한다.

| 항목 | 상태 | 재개 조건 |
| --- | --- | --- |
| **V09 심의 표식** | **비활성** (2026-08-18) | 되살릴 계획 없음. 시험·수행 횟수는 교과 교사 재량이고 최종 검토는 관리자 단계에서 한다 — 문서작성 단계에서 "심의 대상입니다" 라고 되묻는 것은 교사가 이미 아는 사실을 매번 확인시키는 소음이었다. 규칙 정의·조문은 `regulation-2026.json` 에 `severity: "DISABLED"` 로 남아 있어, 필요해지면 자산 한 줄로 되살릴 수 있다 (심의 안건 자동 집계도 그때 함께) |
| **기본점수 (R6, 제19조 ⑧ — 40% 초과 금지)** | 보류 | 확정 양식 안에 기본점수 기입 칸이 있는지 실측 후. 수집 항목이 없으므로 `regulation-2026.json` 의 V11 은 `severity: "SKIP"` 으로 비활성 |

| **`EXAM_RATIO_SENT` 3분류 문장** | 대기 | 새 마스터 manifest 도착 시. 현행 계약 문장은 "선택형 N점, 서술형 M점" 2분류다. 계약 섹션이라 이쪽에서 고치지 않는다 |
| **유형 B·C 자격 목록 실측 보강** | 백로그 | `eligibility.type_b_subjects` / `type_c_subjects` 는 규정 조문 기준. 학교 실제 편제와 대조 필요 |
