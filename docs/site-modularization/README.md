# 운영 사이트 모듈화와 통합 화면

기준: main 49b389d179aac86cd628244879df3afabd77cd71. 작업 브랜치 feat/site-modular-shell.
2026-10-31 사용자 승인 범위: 추천 모듈화, 하나의 사이트 화면, 관리자에 의한 기간 업무 메뉴 표시. 가상 학교 전용 사이트는 대상에서 제외했다.

## 사용자에게 달라지는 점

- 기존 상단의 '기존 업무 메뉴'와 '신축 업무실' 구분을 없애고 같은 사이드 메뉴·모바일 더보기·화면 설정을 사용한다.
- 업무실 이용 권한이 있는 계정의 홈은 현재 학교 업무 홈이다. 그 외 계정도 같은 틀에서 기존 허용 업무와 내 계정을 이용한다.
- 관리자 더보기 → 기간 업무 관리에서 평가계획서 작성·제출 메뉴를 함께 표시하거나 숨긴다.
- SP1 초기값은 숨김이다. 표시 설정은 현재 평가계획서 서비스 전체 기준이다. 기존 회원의 학교 연결을 이번에 만들거나 추정하지 않는다.
- 표시를 끄더라도 저장 자료·현재 작성 입력·기존 주소의 접근 권한은 바뀌지 않는다. 이 스위치는 제출 마감이나 권한 차단 기능이 아니다.
- 다른 문서 업무와 그 AI 기능은 이번에 새로 만들지 않는다.

## 모듈 경계

| 영역 | 역할 |
|---|---|
| apps/main/src/site | 사이트 전체 표시 설정, 공통 메뉴 연결, 기존 화면의 공통 틀 |
| apps/workhub/src/app/site-navigation.tsx | 사이트 표시 문맥. 권한을 제공하지 않는 연결 지점 |
| 각 기능의 기존 Workspace/Panel | 기존 import 경로·props·재마운트 키를 유지하는 진입점 |
| 각 기능의 use* 컨트롤러 | 해당 기능의 상태·이벤트·저장·원번호 복구 |
| 각 기능의 *View와 단계별 Section/Step | 표시와 사용자 입력 연결 |
| 각 기능의 *model | 기존 타입·상수·순수 도움 함수 |
| services/service-values.ts | 순수 검증기·오류. React·RPC를 import하지 않음 |
| services/recovery-scope.ts | 기존 계정·학교·소속의 복구 범위 계산 |
| services/scoped-rpc.ts | 기존 인증 전후 재검증·RPC·시간초과·응답 세대. 본문 유지 |

핵심 화면 5개를 분리했다: 수합, 질문형 문서, 시간표 편성, 메신저, AI 비서.
질문형 문서는 매핑·답변·파일·게시, 시간표는 기준·조건·계산·확정의 8개 표시 영역으로 추가 분리했다.

코드가 삭제된 수치가 아니다. 동일한 상태·명령 코드를 컨트롤러로 이동했고 표시를 분리한 것이다.
다섯 컨트롤러의 명령 본문을 기존 코드와 TypeScript AST 추출·동일 조건 esbuild 정규화로 대조해 모두 같음을 확인했다.
컨트롤러에는 여전히 복합 상태가 있다. 다음 기능 점검에서 실제 수정이 필요한 단위만 더 나누고, 미확정 저장 상태를 여러 훅으로 무리하게 분산하지 않는다.

## 이후 개발 규칙

1. 계약·순수 검증 → 서비스 → 컨트롤러 → 표시 화면 방향으로 의존한다.
2. 순수 서비스에서 React 화면의 pending-requests를 import하지 않는다. recovery-scope를 사용한다.
3. 기존 공개 진입점·re-export는 호환성을 유지한다. 타입은 export type으로 내보낸다.
4. 저장 명령과 결과 미확정 복구의 소유자는 컨트롤러 하나다. 표시 화면은 새 요청 번호를 만들지 않는다.
5. 기능의 단계별 화면을 고칠 때 관련 Section/Step과 해당 브라우저 회귀를 함께 확인한다.
6. site-navigation은 허용 목록을 표현한다. 실제 라우트는 modules.js, 업무실은 기존 서버 접근 판정이 계속 결정한다.
7. 기존 문서 CSS와 업무 화면의 기본 CSS는 @scope와 Shadow DOM 경계로 분리한다. 새 공통 스타일이 숨김 파일 입력이나 radio를 덮지 않는 회귀가 있다.

## 판단해서 정한 것

- 평가계획서 서비스는 학교 연결 전의 기존 회원도 이용하므로 첫 표시 정책은 사이트 전체 1개다. 학교별 분리는 회원 연결 설계 때 별도 계약으로 확장한다.
- 관리자 화면에서 숨기는 동작이 현재 작업을 취소하지 않도록 라우트·API 권한은 유지한다. 직접 주소 차단이 필요하면 별도 요구사항으로 다룬다.
- 승인·비용·파일 생성·기존 SQL의 내부를 재작성하지 않았다. 코드 위치 변경과 필요한 표시 저장소만 추가했다.
- RPC 값 검증과 화면 복구 범위가 UI를 역참조하던 의존성과 시간표 연습 패널 사이 순환 참조를 해소했다. 운영 앱의 연습 기능은 유지했고 가상 학교 전용 사이트는 수정하지 않았다.
- 공통 메뉴는 처음부터 필요한 가벼운 틀만 불러오고 기존 기능 페이지 지연 로딩을 유지한다. 성능 개선 수치를 약속하는 작업은 아니다.
