# 나이스 학교 자료 연결 — 2026-11-08

사용자 결정: 급식은 자동 갱신, 학사일정은 변경 비교 후 선택 반영. 최초 범위는 **2026학년도 학사일정 + 현재 2학기 시간표**. 대동여자중학교 한 곳을 우선 지원한다.

## 구현과 사용 위치

| 위치 | 하는 일 | 실제 자료 반영 |
|---|---|---|
| 홈 → 오늘의 급식 | 날짜별 메뉴, 영양·원산지, 마지막 확인 시각 | 서버 일 1회 예약 갱신 + 홈 접속 시 24시간 넘은 캐시 갱신 |
| 학교 관리 → 나이스 학교 자료 → 학사일정 비교 | 신규·변경·누락·보류 비교, 기존 일정 연결, 최대 50건 선택 반영 | 관리자가 선택·공개 범위 확인 후 기존 일정 저장 함수를 호출 |
| 같은 화면 → 학급 시간표 | 조회 날짜·학급 선택, 주간 그리드, 공개 원본 CSV | 공개 원본 조회만. 운영 확정본은 바꾸지 않음 |

기존 메뉴·승인·학교 소속·일정 관리 권한을 그대로 사용한다. 화면 공개 범위, 인증 로직, AI 모델·요금·호출, 파일 생성은 변경하지 않는다. 나이스 키와 서비스 키는 서버에만 둔다. 새 SQL 설치·학교 연결 등록·환경변수 등록·운영 배포는 아직 하지 않았다.

## 실제 조회한 자료

나이스에서 확인한 학교는 강원특별자치도교육청 K10 / 학교 코드 7892043 / 대동여자중학교다. 공공 자료만 [reference-2026](reference-2026)에 담았다. API 키·회원·학생 개인정보는 없다.

| 자료 | 조회 기간 | 원본 응답 | 동일 항목 중복 제거 후 |
|---|---|---:|---:|
| 학사일정 | 2026-03-01 ~ 2027-02-28 | 185 | 184 |
| 현재 2학기 학급 시간표 | 2026-11-02 ~ 2026-11-15 | 751 | 612 |
| 학급 | 2026학년도 | 9 | 9 |
| 급식 | 2026-11-01 ~ 2026-12-31 | 20 | 20 |

시간표는 **2학기 전체를 가져온 것이 아니라 현재 주와 다음 주**다. 미래 자료는 학교가 나이스에 공개한 범위만 조회된다. 급식도 요청 기간 전체의 식단이 존재한다는 의미는 아니다. 같은 페이지의 동일 자연 식별값·동일 내용만 중복을 합친다. 같은 식별값에 다른 내용이 있거나 페이지 사이 중복·건수 변경이 있으면 마지막 정상 원본을 유지한다.

## 학사일정 반영 과정

1. 서버가 2026학년도 원본 전체를 끝까지 조회한다. 실패·잘린 응답·건수 불일치는 기존 성공 자료를 대체하지 않는다.
2. 일정 담당자가 학사일정 비교를 연다. 신규/변경/원본 누락과 사이트 현재 일정을 함께 본다.
3. 신규 일정은 종일·학교 전체 일정으로 제안한다. 원본 대상 학년은 설명에 남긴다. 교사 대상·수업·학급을 이름으로 추정하지 않는다.
4. 날짜나 제목이 바뀌어 새 원본이 된 경우, 기존 일정을 직접 선택해 연결한다. 이전 원본이 누락 상태라면 그 연결을 이어받을 수 있다. 자동 유사도 매칭은 없다.
5. 이미 연결된 일정은 마지막 반영 원본·지금 원본·사이트 현재 값을 비교한다. 사이트에서 고친 시간·장소·공개 범위·관련 대상은 유지한다. 제목·설명·날짜를 양쪽에서 다르게 고쳤다면 명시적으로 충돌을 확인해야 한다.
6. 선택과 공개 범위를 확인한 뒤 반영한다. 전체 묶음은 한 트랜잭션이며 일부 실패 시 전부 반영하지 않는다.
7. 원본 누락은 **삭제·수업 취소로 자동 처리하지 않는다**. 이번 변경 보류 또는 별도 일정·시간표 운영 화면에서 판단한다.
8. 결과 미상이면 같은 내용·같은 요청 번호로 확인한다. ‘이 요청 닫기’는 이미 반영된 접수증을 확인하거나, 늦게 도착할 원 요청도 반영되지 않도록 닫은 뒤 잠금을 푼다.

나이스 학사일정을 일정에 올리는 것과 휴업·특별 일과를 운영 시간표에 적용하는 것은 별도다. 방학·공휴일 원본을 읽었다는 이유만으로 기존 수업을 취소하거나 보강을 만들지 않는다.

## 시간표의 연결 범위와 남은 정보

현재 공개 학급 시간표는 1학년 1반~3학년 3반의 날짜·교시·과목을 조회할 수 있다. **담당 교사 ID, 교시 시작·종료 시각, 사이트 수업 ID는 나이스 응답에 없다.** 따라서 교환·대강·승인용 확정 시간표로 자동 덮어쓰지 않는다.

운영 시간표 반영에는 기존 학교 자료의 학기·학급·수업↔학급·담당 교사 연결, 교시별 시각을 확인해야 한다. 교과 이름이 같다는 이유만으로 교사를 추정 배정하지 않는다. 초기 공개 시간표는 그 대조용 자료이며 등록이 끝난 운영 시간표라고 표시하지 않는다.

## 판단해서 정한 것

| 판단 | 이유 | 변경 위치 |
|---|---|---|
| 급식은 하루 1회, 홈에서는 오래된 캐시만 갱신 | 호출을 줄이면서 마지막 정상 식단을 유지 | vercel.json, NeisMeals, _service.py |
| 동일 범위 갱신 30분 간격, 실행 임대 2분 | 중복 클릭·동시 탭·예약 실행 경쟁 방지 | N1 신규 SQL, limits.json |
| 일정 반영 최대 50건 | 비교·권한 확인·원자성 유지 | N1 신규 SQL, NeisCalendar |
| 긴 원문은 자르지 않고 보류 안내 | 기존 일정 100자 제목·2,000자 설명 한도 보존 | 기존 normalizeDraft 재사용 |
| 나이스 원본을 운영 시간표와 분리 | 담당 교사·시각이 없는 자료로 잘못 확정하지 않음 | NeisTimetable |
| 연결 해제 시 원본·기존 일정 보존 | 비파괴 중지와 기존 접수증 복구 | N1-80, close/apply |

N1은 전용 표 4개와 공개 함수 6개를 추가한다. 기존 SQL 원문·일정 저장 함수·RLS·권한은 덮어쓰지 않는다. 설치·서버 연결 순서는 [적용 안내](../../database/workhub-neis/n1/README.md), 자동 검증은 [verification.md](verification.md)에 있다.
