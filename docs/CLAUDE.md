## 작업 원칙 — 반드시 지킬 것

### 1. 제안 → 승인 → 실행 흐름

사용자(계란, 중학교 교무행정 담당) 는 비개발자입니다. 직접 코드를 쓰지 않고 클로드와 협업하는 방식으로 진행합니다. 그래서:

- 큰 작업 시작 전에 **결정 사항 정리 + 추천안** 제시
- 사용자가 답변하면 **그 답에 따라 진행**
- 작업 끝나면 **검증 시나리오** 제시

작은 작업은 알아서 진행해도 OK. 새 기능 추가, UI 변경, 데이터 모델 변경 같은 큰 작업은 반드시 사전 의견 수렴.

### 2. 한국어 + 공손한 어조

- 사용자 응답은 한국어
- 코드 주석도 한국어 (변수명/함수명은 영어)
- 너무 자주 사과하지 말 것 (요청 시: "너무 자주 사과하지 마")
- 추측보다는 "데이터 확인 필요" 라고 명시

### 3. 결정 사항은 절대 잊지 말 것

`DECISIONS.md` 의 모든 결정은 누적되며 후속 작업에 영향을 줍니다. 예:

- "같은 학급 안 swap 우선, 다른 학급은 경고" → 어떤 변동 추천이든 이 원칙 따름
- "합반 케이스 없음" → 동시간 교사 중복은 강제 차단
- "직권 변경은 즉시 적용 + 사후 통보" → 별도 승인 단계 없음

새 작업 시작 전에 관련 결정 사항 다시 한 번 확인.

### 4. 시뮬레이션 페르소나 시스템 이해

Phase 4 (인증 통합) 가 아직 안 되어서 임시로 페르소나 셀렉터가 있습니다:
- 일반 교사 페르소나: `t2`, `t7`, `t20`, `t12`, `t4`, `t14` (시드 시간표에 등장하는 교사)
- 관리자 페르소나: `'admin'` (시뮬레이션 전용)

`teachers` 테이블에는 실제 사용자 행이 있지만 시뮬레이션은 별개. 003 마이그레이션으로 UUID → TEXT 로 완화해서 't2' 같은 문자열 ID 를 그대로 씁니다.

Phase 6 에서 인증 통합 시 페르소나 셀렉터 제거 + UUID 복원 예정.

### 5. 외부 API 키 / 환경변수

- **ANTHROPIC_API_KEY** — Vercel 환경변수에 설정됨. "Needs Attention" 라벨은 Sensitive 권장 알림 (정보성). 무시 가능.
- **VITE_SUPABASE_URL, VITE_SUPABASE_ANON_KEY** — 클라이언트용
- **SUPABASE_SERVICE_ROLE_KEY** — API 라우트 (서버) 용
- **VITE_GOOGLE_CLIENT_ID** — Google 로그인 (이전 채팅 작업)

`.env.local` 은 절대 commit 하지 말 것.

### 6. API 라우트 (Vercel ESM)

`api/` 폴더의 파일은 Vercel serverless function 으로 동작. **ESM 환경이라 import 시 확장자 필수**:

```javascript
// ❌ 안 됨
import { foo } from './_helper';

// ✅ 됨
import { foo } from './_helper.js';
```

이거 한 번 놓쳐서 빌드는 통과했는데 런타임에 ERR_MODULE_NOT_FOUND 났던 적 있음.

### 7. 빌드 검증

작업 후 PowerShell/터미널에서:
```bash
npm run build
```
실행해서 문법 오류 미리 잡고 push.

push 후 Vercel 대시보드에서 deployment Ready 확인.

### 8. 시뮬레이션 페르소나 동기화

시뮬레이션의 페르소나가 시드 시간표에 등장하는 교사여야 본인 셀이 보입니다. 만약 시드 데이터를 바꾸면 페르소나 셀렉터도 같이 업데이트.

현재 시드 등장 교사: `t2`(국어T2), `t7`(수학T1), `t20`(영어T2), `t12`(과학T2), `t4`(사회), `t14`(체육T2)

### 9. timetableData 의 export 이름

자주 헷갈리는 부분:
- `SBJ` (과목) — `SUBJ` 가 아닙니다
- `TCH` (교사)
- `CLS` (학급)
- `gS`, `gT`, `gC` — id 로 조회 함수
- `CLR` — 색상 팔레트
- `DAYS` — 요일 배열

### 10. 시간표 데이터 형식

활성 시간표는 `timetables.data` JSONB 컬럼에 저장:

```json
{
  "c1": {
    "월-1": { "sid": "s1", "tid": "t2" },
    "월-2": { "sid": "s5", "tid": "t7" },
    "월-3": { "sid": "s3", "tid": "t20" },
    "목-7": { "type": "special", "name": "창체", "tid": null }
  },
  "c2": { ... }
}
```

- key 형식: `${day}-${period}` (예: `'월-3'`)
- 일반 슬롯: `{ sid, tid }`
- 특별활동(창체): `{ type: 'special', name, tid: 담임 }`
- 자습 변경 결과: `{ type: 'self_study', sid, supervisor_tid }` (timetableEngine 에서 동적 생성)

## 자주 하는 작업

### 새 페이지 추가하기

1. `src/pages/NewPage.jsx` 생성
2. `src/App.jsx` 에 import 추가
3. `adminMenus` 또는 `commonMenus` 에 메뉴 항목 추가
4. `renderPage()` 의 switch 문에 case 추가

### 새 API 엔드포인트 추가하기

1. `api/your-endpoint.js` 생성
2. 다른 엔드포인트 (admin-chat.js 등) 의 CORS 헤더 + handler 패턴 따라 작성
3. 외부 모듈 import 시 `.js` 확장자 잊지 말 것
4. 로컬에서 `npm run build` 로 검증

### Supabase 마이그레이션

1. `migrations/00X_xxx.sql` 파일 생성
2. Supabase SQL Editor 에서 직접 실행
3. 코드 push 는 마이그레이션 실행 후

### 디버깅

- **로컬**: `npm run dev` 로 띄우고 브라우저 콘솔 확인
- **배포 후 에러**: Vercel Dashboard → Logs 에서 함수 실행 로그 확인
- **브라우저 캐시**: 변경사항 안 보이면 `Ctrl+Shift+R` 강제 새로고침

(중요: 사용자와 작업하는 패턴 참고용)

- **결정 우선** — 큰 작업은 결정 사항 정리해서 추천안 제시 후 답 듣기

- **검증 시나리오 제시** — 작업 끝나고 어떻게 확인할지 안내
- **AI 기능 신중** — AI 영역은 시범운영 후 재설계, 지금은 더 추가 안 함
