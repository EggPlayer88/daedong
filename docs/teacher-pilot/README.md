# 실제 교사 연결 전 10명 한정 AI 업무 시험

2026-11-12. 기준은 main `ab6ea8355f2fa0a5e2b9d08538fa852d272103b2`다. 사용자가 가입 전 명부 교사 10명에 시험 계정을 임시 대응시키고, 기존 관리자와 업무를 시험한 뒤 실제 가입 계정으로 전환하도록 승인했다. 기존 실제 계정·확정 기본표·학교 자료·AI 비용 정책은 보존한다.

## 준비할 세 가지

| 단계 | 구현 경계 | 운영 완료의 증거 |
| --- | --- | --- |
| 계정 준비 | 관리 SDK로 정확히 10개 Auth 계정, 서로 다른 무작위 암호, 관리자 메타데이터, 충돌/응답 유실 복구 | 비공개 `registration.json`의 10개 Auth ID와 실제 회원 목록 일치 |
| 학교·담당 연결 | TP1 관리 SQL로 승인·학교 소속·기간 있는 명부 연결·교과/담임 배정 | 학교/명부/계정 1:1, 기존 12개 연결과 기본표 본문 보존 |
| AI 시험 허용 | 활성 TP1과 기존 OP1 업무 범위를 함께 확인한 10명만 기존 AI 업무 화면 사용 | 배포 기준과 SQL 판 일치, 명단 밖·만료·철회 계정 차단 |

Auth 계정 생성만으로 학교 연결·AI 활성화가 완료되지는 않는다. 앱 병합·배포는 사용자가 한다. TP1 설치·계정 등록·활성화는 각각 실행 결과를 기록한다.

## 계정과 기간

- 실제 이름과 이메일로 로그인 계정을 대신 만들지 않는다. 표시 이름은 `[시험] 이름`, 이메일은 `teacher-pilot-<batchId>-t01@example.com` 형식이다.
- 실명 교사/학교/명부 ID는 Git에 넣지 않고 로컬 비공개 실행 설정에서 받는다. 저장소 예시는 합성 자료다.
- 기존 임영진 관리자 계정은 그대로 둔다. 시험 계정의 전역 역할은 일반 교사이며 슈퍼관리자·학교 관리자 역할을 추가하지 않는다.
- 기존 OP1의 최대 7일 범위 안에서 시험 기간을 정한다. 연장이 필요하면 새로 승인하고 현재 판을 재확인한다.
- 실제 기본표의 적용 시작일과 시험 연결 기간이 겹쳐야 담당 수업·담임이 나타난다. 기본표 조회와 T2 날짜별 운영은 별도이므로 연결 성공을 교환·대강까지 활성화됐다는 의미로 해석하지 않는다.
- 시험 종료 뒤 실제 교사는 자기 계정으로 가입한다. 시험 계정의 비밀번호·작성자 ID·과거 기록 소유권을 실제 교사에게 넘기지 않는다.

## AI와 기존 교사 권한

TP1이 허용하는 화면은 AI 대화와 기존 OP1의 할 일·일정·메시지·수합·협업·수업·시간표·인계 범위다. 실제 쓰기는 기존 업무 API의 권한·대상·판·요청 번호 검증을 사용한다. 학교 관리, API 키 관리, 비용 운영 관리와 기존에 허용하지 않은 문서 제작·개인 기억을 추가 공개하지 않는다.

Haiku/Sonnet 배정, 정밀 검토 확인, 학교별 월 100달러 예산, 토큰 한도, 예약·정산과 HWPX 생성기를 변경하지 않는다. 시험에서 실제 AI를 호출하면 기존 학교 예산으로 과금된다. 자동 검증은 합성 응답과 격리 DB로 실행하며 유료 호출하지 않는다.

**이 시험은 별도 복제 학교나 데이터 격리 환경이 아니다.** 시험 교사는 배정된 학교·수업 권한을 사용한다. 메시지·수합·공유 일정의 서버 대상이 시험 10명과 관리자만으로 강제 제한되는 기능은 이번 범위에 포함하지 않는다. Claude 실사용 시험에서는 대상을 관리자·시험 계정으로 직접 확인하고, 전체 학교/전체 교사를 대상으로 전송·공개하지 않는다.

## 시험 진행과 기록

1. 관리자와 시험 계정 1개에서 로그인·소속·교과·담임·AI 접근을 먼저 확인한다. 나머지 계정은 같은 대조표로 확인한다.
2. 할 일 → 일정 → 메시지 → 수합 순으로 AI 요청, 누락 정보 보완, 원본 확인, 명시 실행, 결과 목록까지 확인한다.
3. 새 시험 자료에는 `[AI 검토시험 날짜]` 표시를 붙이고, **학교·소속·원본 ID·요청 번호·파일 경로**를 별도 시험 기록에 남긴다. 표시 문구만으로 삭제 대상을 판단하지 않는다.
4. 관리자 작성 자료는 실제 자료와 같은 작성자이므로, 이번 시험에서 생성한 ID를 반드시 따로 기록한다.
5. 실제 교사에게 전송·알림·공개하거나 실제 학생 기록을 수정하지 않는다. 수업 기록 시험에는 가상 학생과 시험 기록만 사용한다.
6. 오류·결과 미상은 원래 요청으로 재확인한다. 계정 전환 전 작성 중 내용과 미확정 요청을 정리한다.

## 종료와 자료 정리

종료 명령과 정리 후보 조회는 [TP1 SQL](../../database/workhub-teacher-pilot/) 및 [계정 도구 실행안내](../../scripts/teacher-pilot/README.md)를 따른다.

- 먼저 진행 중 전송·제출·AI 요청을 확인하고, 원래 요청 번호의 접수 상태와 비용 예약을 정리한다.
- 시험 허용과 임시 담당 연결을 종료한다. 기존 실제 교사의 연결·배정·기본표는 바꾸지 않는다.
- 사이트 업무 접근 차단과 Auth 로그인 자체 차단은 구분한다. 세션이 남아 있어도 업무 API의 만료/정지 검사가 쓰기를 거절해야 한다.
- 읽기 전용 정리 목록과 별도 기록한 관리자 자료 ID를 대조한다. 실제 자료나 다른 교사 기록과 연결된 항목은 일괄 삭제에서 제외한다.
- 삭제 가능한 초안·파일은 별도 확정 목록으로 준비한다. 감사·접수·승인·AI 비용 이력은 보존하며, 보호 트리거를 끄거나 계정 참조를 강제로 지우지 않는다.
- 실제 교사로 연결할 때 종료된 시험 계정의 대화·관찰·상담·제출 기록 소유자를 바꾸지 않는다.

## 판단해서 정한 것

1. 시험 계정을 실제 교사와 구분해 실수로 실제 로그인 계정을 수정하는 일을 막는다.
2. 기존 기간·권한 검증을 재사용하고 TP1 10명 명단을 추가 확인한다. 일반 교사 전체 메뉴 공개나 비용 정책 변경을 피한다.
3. 정리는 삭제 대상의 미리보기부터 준비한다. 되돌릴 수 없는 삭제와 감사 원장 손상을 시험 종료와 한 동작으로 묶지 않는다.
4. 별도 학교로 데이터를 복제하지 않아 기존 학교의 후보가 보일 수 있음을 명시한다. 대상 제한 운영 수칙을 서버 격리로 표현하지 않는다.

자동 검증과 실제 계정·DB 적용 결과는 최종 검증 기록에서 별도로 보고한다.
