# 일정 연속 가져오기 수정 검증

2026-10-25. 운영 연결 시험 중 발견한 기능 오류를 수정한다.

## 재현과 수정

일정 일괄 저장을 마친 다음 `다른 원본 가져오기`를 누르면 제목과 입력은 비워지지만,
이전 접수증·열 연결·비교 결과가 남아 입력 칸이 계속 잠겼다.
초안 변경 함수가 기존 객체에 새 객체를 병합하는데 초기값에서 선택 필드를 생략한 것이 원인이었다.

초기값에서 `table`, `mapping`, `preview`, `receipt`를 명시적으로 비워 새 입력을 받는다.
이전 서버 접수 기록은 건드리지 않는다. 후속 가져오기는 새로운 비교와 새로운 요청 번호로 저장한다.

## 자동 검증

- 새 회귀를 수정 전 코드에 실행해 입력 칸이 잠긴 상태에서 실패하는 것을 확인했다.
- 수정 후 협업·일정 일괄 브라우저 시험 15건 통과. 정상 저장과 응답 복구 각각에서 초기화 → 재진입 → 두 번째 원본 저장을 확인한다.
- 협업 인계 브라우저 시험 15건, 학교 인계 브라우저 시험 51건 통과. 합성 서버 응답을 쓰는 총 81건이다.
- `npm run check:workhub`, `npm run build` 통과.
- Ubuntu · Node 22.22.2 · Python 3.12의 격리 복제본에서 `npm test` **5,158건 전체 통과**. P7 실행본 준비 회귀 4건을 포함하며 시험·제품 코드를 우회하거나 성공 기준을 낮추지 않았다.
- Windows 전체 실행은 시간표 계산·작업자 2개 파일이 Python 프로세스 종료/대기 시간 초과로 실패했다. 같은 소스의 Ubuntu 시험에서는 CP-SAT 29건과 작업자 55건을 포함해 전부 통과했다. Windows 실행 문제의 정확한 원인은 아직 확정하지 않았으며, 이번 일정 화면 수정으로 해결됐다고 표시하지 않는다.

## 운영 시험과의 경계

운영에서는 관리자 전용 시험 일정 2건 저장과 잘못된 날짜 1건 제외를 확인했다.
동일 원본 재비교는 중복 2건으로 새 저장이 막혔고, 한 행의 설명만 수정한 비교에서는 변경 1건·중복 1건으로 나뉘었다.
변경 1건을 저장한 뒤 기존 두 일정이 각각 v2·v1로 유지되는 것도 확인했다.
연속 가져오기 결함의 수정본은 아직 운영에 배포되지 않았다.
두 계정 간 협업·인계의 실제 왕복 성공을 이 회귀 결과만으로 주장하지 않는다.
권한·메뉴 공개 범위·실제 교사 연결은 이 코드 변경에 포함하지 않는다.

## P7-05 실행본 준비 도구

사용자가 별도로 승인한 P7-05를 적용할 때 운영의 기존 `collections_guard` 본문이 CRLF여서 사전 MD5 검사가 멈췄다.
운영 원문 MD5는 `835e7055c3ae358acdc94f780a887a9e`, CRLF만 LF로 바꾼 MD5는 승인 원본의 `192396592ea201a158dcadb4b92d7b33`과 같았다.
다른 두 트리거와 두 제약도 승인 원본과 같은 것을 먼저 조회했다.

`scripts/prepare-workhub-p7-05.mjs`는 확정 SQL을 변경하지 않고 실행 사본을 만든다.
원본 전체 SHA-256을 확인한 후 이 함수의 사전 비교 한 곳만 CRLF → LF로 정규화하고 승인자·근거를 채운다.
공백 제거·일반적인 본문 치환·지문 검사 생략은 하지 않는다. SQL 자동 실행 기능도 없다.
기존 출력 파일을 덮어쓰지 않으며 원본 차이와 승인 누락은 거부한다.

회귀 4건으로 원본 변조 거부, LF/CRLF 동등성, 실제 관찰 지문 재현, 승인 입력 검사를 확인했다.
승인된 실행 사본의 운영 적용 결과는 **4행 모두 ok**, 뒤이은 INT-09는 **18행 중 16행 ok·2행 info, FAIL 0**이었다.
이 PR을 병합할 때 P7-05를 다시 실행하지 않는다. 다른 환경에서는 별도 적용 승인과 사전·사후 점검이 필요하다.
이후 본인 대상 `[연결시험] 질문형 HWPX 제출`의 접수 마감 → 재개를 실제 서버에서 확인했다.
기한은 2026-10-30으로 유지했고 기존 제출 v1·접수 시각·파일명·완료 1건이 그대로 남았다.

## 두 계정 실제 시험의 남은 조건

현재 일반 교사 시험 계정은 MP1의 메신저만 사용할 수 있다.
P2의 `p2_member_reachable`과 이를 이용하는 P7은 여전히 superadmin만 협업·인계 수신 대상으로 인정한다.
운영 화면에서 협업 대상 목록이 비어 있고 업무 인계 준비가 비활성인 것을 확인했다.
별도 시험 권한을 설계·승인하기 전에는 두 계정 간 협업 요청·수락·완료·인계 성공으로 기록하지 않는다.
학년도 전환은 합성 날짜로 서버 미리보기의 변경 대상 12건을 확인하고 취소했다. 새 학년도는 만들지 않았다.
