## 임시 자료의 출처

`backup/v1_timetables_data.csv`의 “2026학년도 1학기 (시드)”다. 과거 마이그레이션에 시뮬레이션·개발용 가상 자료라고 명시돼 있다.

- 교과·요일·교시 279칸은 보존했다.
- 원본 교사 6명의 동시 수업 충돌 90건은 18개 가상 역할로 분리해 제거했다.
- 수업 시각과 2026-03-02~08-15 연습 구간은 임시값이다. 공식 학사 자료로 쓰지 않는다.
- 실제 회원 이름·UID를 추정하지 않는다. P9 서버에서 확인한 소속 또는 관리자가 확인한 CSV에서 명시적으로 선택한다.
- 가상 Auth 사용자·회원·업무실 소속은 만들지 않는다.

지문·변환 규칙: [원본 설명](../timetable/pilot-source.md).

## 화면 사용

1. 시간표 → **9학급 운영 연습**.
2. 날짜·학급·수업을 선택하고 교환·이동·대강·휴강·보강을 요청한다.
3. “지금 연습할 역할”을 바꿔 영향받는 교사의 수락을 진행한다.
4. 담당자 A 또는 승인 담당자 B가 최종 승인하거나 사유와 함께 반려한다.
5. 변경 시간표·내 알림·변경 이력을 확인한다.
6. **실제 자료로 교체**에서 명단·시간표를 비교한다.

역할 선택은 실제 로그인·권한·교사 동의를 대체하지 않는다. 연습 접수증은 운영 서버로 보내지 않는다.

독립 미리보기도 실제 React 컴포넌트다:

```sh
node scripts/export-workhub-school-pilot.mjs "/원하는/폴더/시간표운영_미리보기.html"
```

로컬 HTTP 서버에서 열면 저장·복원까지 동작한다. 실제 회원 조회는 하지 않는다.

## 실제 자료로 교체하는 범위

**교사:** 안정된 역할 ID에 실제 `membership.id`를 연결한다. 동명이인은 ID로 구별하고, 같은 실제 교사를 여러 역할에 연결하면 동시간 충돌을 검사한다. 계획은 열린 연습 화면 안에서 유지한다. 외부 화면 이동·새로고침 전 CSV로 보관한다. 가상 운영 백업에는 실제 이름·ID를 넣지 않는다. 계획만으로 P8 담당 변경을 실행하지 않는다.

**시간표:** 현재 9학급·279칸·기존 역할·교실 범위에서 교과·담당·배치를 변경하고 적용일 이후만 교체한다. 과거 운영 기록을 덮어쓰지 않는다. 미래의 승인·실시·보강·휴업과 겹치면 적용일 조정을 요구한다.

교사 연결 변경 시 이전 시간표 미리보기를 폐기한다. 반영 직전 현재 연결 기준의 충돌과 다음 연결판을 재검사한다. 교사 연결 확인과 시간표 반영 확인도 별도다.

**학급 수·교시 수·자원 구성이 다른 임의의 시간표로 자동 확장하는 기능은 아니다.** 이 경우 기존 T1 준비 화면에서 새 기준판을 만들고 정식 공개 흐름을 사용한다.

## 상태와 남은 연결

| 대상 | 현재 상태 |
|---|---|
| #72·#74 | 두 최신 커밋을 작업 브랜치에 포함. main 병합 안 함 |
| P9 SQL | 신규 증분·점검·시험 작성. 운영 실행 안 함 |
| 기존 SQL·로그인·회원·비용·공개 | 변경 없음 |
| 실제 가입 교사 연결 | 학교별 UID 허용 목록·P9 승인 후 가능 |
| 가상 운영 | DB 설치와 관계없이 연습 화면에서 가능 |
| 실제 T2 교환·일과·실시 | 기존 구현·설치 유지. 실제 자료·활성화 별도 |
| 실제 T2 대강·보강 | 이번 로컬 엔진을 정식 SQL에 연결하는 증분이 남음 |
| AI | 새 유료 호출 없음. 교환 추천은 결정적 검사 |
| 일반 교사 공개 | 확대하지 않음 |

다음 순서:

1. Claude가 앱·로컬 엔진과 P9 SQL을 검토한다.
2. 사용자가 [P9 실행 안내](../../../database/workhub-school-data/p9/README.md)에 따라 신규 SQL을 직접 적용하고 학교별 허용 UID를 확인한다.
3. 실제 회원을 업무실 소속으로 연결한다. 실제 수업 담당은 기존 P8의 기간·미리보기·확정 절차로 배정한다.
4. T2 시범 명단·알림·두 번째 실제 승인 담당자를 준비한다. 가상 담당자 두 명은 활성화 조건에 포함하지 않는다.
5. 정식 운영의 대강·휴강·보강 저장은 검증한 명령을 T2 증분 SQL·어댑터로 연결한다.
6. 실제 시간표는 T1 새 기준판과 T2 공개 절차로 교체하며 과거 기록·원요청 번호는 보존한다.

실사용 후 피드백과 사용자 결정이 필요한 비용·API 키·일반 공개는 이번 구축 상태와 별도다.
