원래 적용한 SQL 파일·로그인·기존 회원·비서 모델/비용·신규 메뉴의 `superadmin` 공개 범위는 유지한다. P10/T3의 기존 함수 보강은 새 SQL 파일이 원문을 확인한 뒤 수행한다.

## 실제로 사용하는 순서

1. 검토가 끝난 뒤 사용자가 새 SQL을 단계별 적용한다. 이미 설치한 R0/R1/P1~P8/T1/T2는 재실행하지 않는다.
2. P9의 명시적 학교별 허용 UID로 기존 가입 교사를 연결한다. 가상 Auth 회원을 만들지 않는다.
3. 학교 관리의 **학교 준비 진행 안내**를 펼쳐 조회된 현황과 다음 입력을 확인한다. 학교·수업 자료를 입력하고 잘못 입력한 내용은 **수업·학생 정정**에서 영향과 전후 값을 비교한다.
4. **실제 시간표 가져오기**에서 선택한 학기의 공식 수업·교사·학급·공간 ID와 참고 이름을 담은 엑셀 양식을 받는다. 요일과 시각을 채워 업로드한 뒤 수업·교사·학급 배치표를 비교하고 저장한다.
5. 저장된 새 기준판·초안을 **공개 검토**에서 확인한다. 가져오기 완료만으로 공개하지 않는다.
6. 실제 시범 명단·독립 승인 담당자를 확인해 T2/T3를 별도로 켠다.
7. 교사는 변경 요청을 작성하고 관련 교사는 동의한다. 독립 승인 담당자가 최신 조건을 다시 확인해 반영한다.

학교 준비 안내는 단계마다 실제 조회에서 확인한 수치를 보여 준다. 조회 실패나 미설치를 자료 없음으로 바꾸지 않으며, 필요한 모든 교사가 등록됐거나 시간표가 공개됐다고 추정하지 않는다. 학생 수는 고유 학생 수가 아닌 수업별 수강 등록 합계다. 대상 학기가 조회 중 바뀌거나 원본 지문이 다르면 다시 확인하도록 안내한다.

엑셀 양식의 학교·학기·원본 지문이 달라지면 기존 입력을 유지하고 새 양식을 요청한다. 참고 이름을 수정해도 교사·학급 연결은 바뀌지 않는다. 배치 비교는 검색과 40행씩 페이지 이동을 지원한다. 파일을 여는 것만으로 서버에 저장하거나 시간표를 공개하지 않는다.

홈에서 보강을 열면 해당 취소 수업을 선택한다. 다른 입력이 남아 있으면 확인 없이 덮어쓰지 않는다. 운영 요청은 내 동의·승인 필요, 종류, 진행 상태로 좁혀 볼 수 있으며, 선택한 요청은 필터 밖이어도 원본을 유지한다. Claude 제안도 수동 입력을 바꾸기 전 확인을 거친다.

### 실제 자료 전환과 일과 처리 연결

수강 명부는 현재 수업에서 내려받은 XLSX 양식 또는 UTF-8 CSV를 읽는다. 학교내학생번호로 현재 수업 명부만 비교한다. 같은 이름으로 합치지 않고, 이름·학년·반·번호·수강 기간이 다른 기존 학생은 정정 필요로 표시한다. 파일에서 빠진 학생과 기존 기록은 유지한다. 다른 수업의 학생번호 중복은 기존 서버가 최종 검사하므로 ‘새 연결 후보’를 학교 전체의 신규 학생으로 표시하지 않는다.

파일 오류나 읽는 도중 원본 변경이 생겨도 이전 파일 입력을 보관한다. 현재 명부가 바뀌면 명시적으로 다시 비교하고 확인해야 저장할 수 있다. 결과를 모르는 요청은 새 명부로 바꿔 보내지 않고 기존 명령·번호로 복구한다.

홈의 학생 후속 카드는 정확한 수업을 연다. 근거 확인은 사용자 동작으로 10명씩 시작하고, 관찰의 이전 페이지까지 확인한다. 조회 실패·중단·한도 초과를 ‘재검토 없음’으로 바꾸지 않는다. 학생당 첫 재검토 관찰의 위치만 목록에 보관하며, 해당 학생을 선택하면 현재 권한으로 그 페이지를 다시 읽는다. 상담은 이 흐름에서 조회하지 않는다. 작성 중 입력이나 결과 미상 요청이 있으면 기존 내용을 유지하고 이동을 미룬다.

공유 시간표의 선택 수업에서 운영 변경과 실시 기록을 시작할 수 있다. 기간을 옮길 때 입력과 요청 번호는 보존하고, 이전 변경 미리보기는 다시 확인한다. 학사 변경을 가로막는 기존 요청도 원본을 확인한 뒤 보관한 입력으로 돌아갈 수 있다.

운영 출력은 같은 조회 기간의 적용 완료 이력과 현재 수업 ID·판·내용이 일치할 때만 변경 종류와 보강 원수업을 표시한다. 이력을 조회하지 못하면 기존 시간표 출력은 유지하되 원인을 추정하지 않는다. 개인 사유는 인쇄·XLSX에 넣지 않는다.

새 SQL 설치 순서는 [통합 안내](../../../database/workhub-school-data/integration/README.md)를 따른다. 활성화·실제 서비스 연결 확인은 설치와 별도다.

## 입력과 요청의 보존

- 작성 중 입력은 학교·계정별 현재 탭 메모리에 보관한다. 브라우저 종료 뒤 복원을 보장하지 않는다.
- 응답 유실 시 원래 요청 번호와 명령을 유지한다. 새 번호를 자동 발급하지 않는다.
- 명시적 닫기를 보냈다면 응답이 끊겨도 닫기 결과만 다시 확인한다.
- 서버는 접수증이 있으면 원접수증을 반환하고, 미처리 번호를 닫으면 늦게 도착한 원요청을 막는다.
- 소속·권한 확인은 유지한다. 특히 T4 복구·닫기도 기존 학교 관리 권한을 요구한다. 관리 권한을 잃은 경우 임의로 다른 계정에서 재실행하지 않는다.
- 미리보기의 원본·판·지문·기한이 바뀌면 다시 비교한다. 입력은 유지한다.
- 운영 변경, 가져오기, 학교 정정은 실패 시 같은 트랜잭션 안의 변경을 함께 취소한다.

## 자료와 이력의 경계

P10은 물리 삭제 대신 상태와 전후 원장을 남긴다. 수업 복원은 보관한 수업에 한하며, 취소한 수업의 취소를 되돌리는 기능은 포함하지 않는다. 학생 입력 취소는 같은 학생 ID로 복원할 수 있다. 이미 기록·공개 시간표와 연결된 수업을 단순 정정으로 과거까지 바꾸지 않는다. 실제 담당 기간 변경은 기존 관계 변경 흐름을 사용하며, 새 전체기간 담당 정정은 아직 시작하지 않은 수업에 한정한다.

T3는 휴강 원수업과 보강 수업을 연결하고 중복 보강을 거부한다. 휴업 취소도 원래 휴업 기록과 현재 수업판을 확인한다. 교환·대강·휴강·보강 등의 반영 수업은 재공개로 덮어쓰지 않는다.

T4는 선택한 학기의 전체 수업을 공식 ID로 명시적으로 연결한다. 동명이인·비슷한 수업 이름을 추정해 연결하지 않는다. 기존 고정·불가 조건을 조용히 없애는 가져오기도 거부한다. 실제 자료 가져오기는 기존 T1 제한을 따르며 무제한 대용량 업로드가 아니다.

## 9학급 연습 자료

`backup/v1_timetables_data.csv`의 “2026학년도 1학기 (시드)”는 과거 개발용 가상 자료다.

- 1-1~3-3의 9학급, 주간 279칸, 날짜별 수업 6,696건이다.
- 원본 교사 6명의 동시 배치 충돌 90건은 가상 역할 18개로 나눴다.
- 수업 시각과 2026-03-02~08-15 연습 구간은 공식 학교 일정이 아니다.
- 실제 교사 이름·UID를 추정하지 않는다. 연습 역할의 동의·승인·접수증을 운영 서버로 복사하지 않는다.
- **9학급 연습 배치로 시작** CSV에는 실제 수업·교사·학급·공간 ID를 비워 둔다. 공식 자료에서 확인해 채워야 한다.

연습 자료 자체는 학교·계정별 브라우저에 압축 보관하며 JSON 백업·복원을 지원한다. 상세 출처는 [원본 설명](../timetable/pilot-source.md)에 있다.

## 현재 작업과 후속 단계

| 구분 | 이 PR의 의미 |
|---|---|
| 앱·증분 SQL 구축 | 검토 가능한 파일과 자동 시험을 준비 |
| 운영 DB | P9/P10/T3/T4 적용하지 않음 |
| 실제 교사 연결·시범 명단 | 사용자 확인 후 학교별 승인 필요 |
| 실제 시간표 | 가져오기 경로 구축. 공식 자료를 넣었다는 뜻은 아님 |
| Claude | 기존 비서 연결 사용. 실제 유료 호출 시험 안 함 |
| 배포·기능 켜기 | 사용자 결정. 앱과 SQL 설치 상태를 따로 확인 |
| 일반 교사 공개 | 기존 제한 유지 |

사용자 요청에 따라 검토는 후속 작업을 모은 뒤 진행한다. 현재는 **앱 구축과 자동 검증**을 이어 간다. 이후 순서는 **종합 검토 → 사용자 SQL 적용 → 앱 배포와 연결 확인 → 관리자 시범 활성화**다. SQL을 먼저 설치하고 앱을 병합하며, 이전 앱이 영향받는 기존 함수 보강 단계는 실행 직전에 다시 설명한다.

검증 결과와 실제 서비스에서 확인하지 않은 범위는 [verification.md](verification.md)에 따로 기록한다.
