기존 CI 실패는 실행 요일에 따라 충돌하는 수업을 고르는 시험 자료의 문제였다. T2 시험은 실제 미리보기에서 차단 사유가 없는 후보를 고르고, 교환에 고정된 날짜를 휴업·특별일과 자료와 분리했다. 과거 요청 시험은 조회 범위보다 충분히 앞선 날짜를 사용한다. T3 재공개는 주말 때문에 수업이 없는 5일 구간 대신 7일을 검사하고 합성 대조 수업을 분리했다. 실패를 제외하거나 기대값을 낮추지 않았다. **기존 T2 SQL과 T3 SQL 원문은 변경하지 않았다.** 보호 검사 예외도 기존 `t2/test/run_t2.py` 한 파일에만 둔다.

학교 준비 요약은 기존 읽기 어댑터·RPC를 사용한다. 위 학교 준비·홈 연결의 브라우저 시험은 운영 DB가 아닌 합성 응답으로 실행한다. 이번 작업에서 새 SQL 설치나 모듈 활성화를 수행하지 않았다.

이번 브라우저 검사는 합계 **12개 파일 133건**이다. 마지막 연결 점검에서 미수정 예시 편성이 공식 준비 링크를 가리던 경로와 Shadow DOM에 안내 CSS가 적용되지 않는 경로도 수정했다. 수정한 연습·조건·AI 입력·미확정 요청을 자동으로 버리지 않는지 함께 확인했다.

## 실제 SQL과 확인한 경계

- 모든 SQL 시험은 PostgreSQL 17.6 로컬 임시 클러스터에 합성 회원·학교를 만든다. 운영 접속 문자열은 받지 않는다.
- 기존 회원 내용을 해시로 비교하고 새 정책이 설치만으로 켜지지 않는 것을 확인한다.
- T3의 관련 교사 동의·독립 승인, 교환·공개·재공개 보존, 중복 보강, 닫기 장벽, 다른 학교·타인 요청 거부를 확인한다.
- 기존 T2 교환 제출·승인도 관련 회원·소속·정책을 잠근 뒤 현재 자격을 확인한다. 정책이나 영향 교사를 동시에 회수하는 세 경로가 잠금 해제 후 거부되는 것을 확인했다.
- T4는 선택한 학기 전체 수업의 교사·학급·공간·시수·충돌과 원본 지문을 검사한다. 기준판 저장 뒤 초안 저장이 실패하면 둘 다 남지 않는다.
- 닫기와 원요청이 경합하면 원접수증 또는 종료 장벽 중 하나로 끝난다. 닫힌 뒤 늦은 원요청은 적용되지 않는다.
- P10은 원장을 거치지 않는 기존 쓰기를 막고, 취소 학생·취소 또는 보관 수업에 새 자료가 쌓이지 않게 한다.
- INT-04는 전체 정의를 다시 생성해 저장된 점검문과 비교한다. 새 요청 원장 보호를 끄거나 익명 실행 권한을 추가하면 실패하고, 복구하면 통과한다.
- 가입·로그인 인증은 그대로다. 선택적 RPC가 아직 없는 경우만 준비 안 됨으로 분류한다. 권한 실패나 통신 실패를 성공·빈 목록으로 바꾸지 않는다.

입력은 계정·학교별 현재 탭 메모리에 보존한다. 브라우저 종료 후 복구를 보장하지 않는다. 결과 미상 요청은 원번호·원문·닫는 단계를 유지한다. T4 복구·닫기에도 기존 관리 권한 검사는 남아 있다.
