전체 브라우저 첫 실행에서 계산기 두 파일은 OR-Tools 없는 기본 Python을 참조해 시작 전에 실패했다. 의존성이 설치된 시험용 Python을 지정한 재실행에서 두 파일 모두 통과했다. 그 최초 실패를 성공으로 바꾸거나 기대값을 낮추지 않았다. 이후 요청 종료 단계 보존을 보완한 교사 연결 화면은 별도 9건을 다시 통과했다.

## 실패를 보존하는 경로

- 연결 요청·닫기 응답 유실: 원키·원문·닫는 단계 보존. 닫기 시작 후에는 연결을 재전송하지 않는다.
- 닫기와 원요청 경합: 원접수증 또는 종료 장벽 한 가지로 끝난다.
- 교사 연결·기준판 변경: 이전 시간표 미리보기 폐기, 실제 연결 충돌 사전 검사.
- 저장 중 입력: 비활성으로 고정해 성공 후 새 입력이 지워지지 않는다.
- 입력 중 알림 이동: 안내 후 이동을 막고 작성 중 내용을 유지한다.
- 손상·다른 범위 백업: 현재 자료를 유지하며 거부한다.
- 두 탭 저장: 원문 비교와 Web Locks로 오래된 자료의 덮어쓰기를 차단한다.
- 압축 보관: 전체 학기 원문 약 4.18MB를 약 0.21MB로 줄였다. 압축 입력 8MB와 실제 해제 출력 24MB를 각각 제한한다.

P9 전체 점검은 13행 FAIL 0이다. 원장 보호 트리거를 일부러 끄면 FAIL이 발생하고 되켜면 통과한다. 기존 회원 지문·Auth 계정 수·역할 수 보존, 다른 학교·타인 접근 거부, 미리보기 만료·원자성·동시성도 확인했다.

## 아직 이 결과가 증명하지 않는 것

- 운영 Supabase에 P9가 적용됐다는 사실
- 실제 교사 명단·재직 기간의 정확성
- 실제 PostgREST·Storage 왕복과 T2 활성화
- 가상 역할의 동의가 실제 교사 동의라는 주장
- 정식 T2 SQL에 대강·보강 저장까지 연결됐다는 주장
- 실제 교사 PC·휴대폰에서의 실사용 점검
