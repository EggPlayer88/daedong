# Claude 검토 요청 — PR #76 학교 자료·시간표 운영 통합

이 문서는 후속 종합 검토용으로 보관합니다. 2026-10-21 사용자 요청에 따라 지금은 구축과 자동 검증을 계속하며, 외부 검토를 요청하지 않습니다.

검토를 시작할 때 [PR #76](https://github.com/EggPlayer88/daedong/pull/76)의 최신 head를 기준으로 확인해 주세요. 기존 #72·#74에 P9 교사 연결, P10 학교 자료 정정, T3 실제 시간표 운영, T4 정식 시간표 가져오기와 앱 연결을 함께 담았습니다. 사용자 역할 전환에 따라 Codex가 새 증분 SQL까지 작성했습니다.

운영 SQL 실행·main 병합·정책 활성화·일반 교사 공개·유료 Claude 호출은 하지 않았습니다. 기존 적용 SQL 파일·Auth/public.users·비서 모델/비용·메뉴 제한은 유지했습니다.

## 중점 확인

### 전체 사이트 추가 연결

- 홈의 종류별 전체 건수와 최대 8개 대표 항목이 혼동되지 않는지, 종류끼리 합산하지 않고 전체 목록·복귀가 입력 잠금을 따르는지.
- 수합 20개 단위 페이지·상태 검색이 실제 처리 대상이나 검토 의견을 바꾸지 않는지. 최신 제출과 이전 완료본, 미충족 보완을 구분하는지.
- 발송 접수증의 수신 소속 ID와 threadId만으로 대화를 여는지. 동명 교사·결과 미상·현재 초안·계정 전환을 보존하는지.
- 학생 명부 정정 왕복에서 공식 학생번호와 학생·학적·수강 ID를 확인하고, 최신 명부 재조회 전에는 기존 비교로 저장하지 않는지.
- 질문형 AI 답변이 실제 요청과 원래 양식 문맥에만 연결되는지. 다른 답변·양식판·저장 답변판을 거부하고 질문 선택과 확인 뒤에만 입력에 반영하는지. 자동 저장·생성·첨부·제출이 없는지.

아래는 기존 #76 서버·시간표 검토 범위다. 이번 추가분은 기존 계약을 활용하며 SQL 변경이 없다.

1. **P9:** 기존 가입 UID를 명시적으로 연결하는지, 재직 기간과 학교 범위·권한·중복 연결·원자성이 맞는지. 담당 후보 자격이 일반 교사 입장 권한까지 넓히지 않는지.
2. **P10:** 전후 원장 없는 원행 변경을 막는지. 수업 취소/보관·학생 등록 취소 뒤 P5/P8/T1/T2의 새 쓰기가 우회하지 않는지. 미래 전체기간 담당 정정과 실제 기간별 관계 변경을 구분하고 과거 담당·평가·관찰을 보존하는지.
3. **T3 동의·승인:** 대강의 원교사/새교사, 휴강/보강의 관련 교사 모두 동의해야 하는지. 요청자·영향 교사와 다른 계정의 관리자가 승인하는지. 시범 명단·현재 소속·변경일 재직 기간·자원·실시 기록을 반영 직전 다시 확인하는지.
4. **T3 기존 운영 보호:** 보강 중복, 휴업 취소의 최신 판/원기록, 다른 요청과 충돌, 재공개에서 휴강·대강·보강·휴업 취소 보존. 시범 정책 행이 없는 학교와 등록한 학교의 기존 T2 교환 차이도 확인해 주세요.
5. **T4:** 공식 ID·전체 수업·시수·조건·배치를 확인하고 기준판과 초안을 한 트랜잭션으로 저장하는지. 두 번째 저장 실패가 첫 저장까지 되돌리는지. 자동 공개하지 않고 기존 공개 검토로 정확한 초안 ID/판을 넘기는지.
6. **복구·닫기:** 최초 명령/원번호 보존, 같은 번호 다른 내용 거부, 적용/닫기 경합, 늦은 원명령 차단, 닫기 응답 유실 뒤 commit으로 돌아가지 않기. T4의 현재 관리 권한 확인은 유지했습니다.
7. **화면·AI:** 홈/알림이 정확한 요청을 여는지, 미설치 RPC와 실제 조회 실패를 구분하는지. Claude는 기존 4,000자 입력·기존 비용/호출 규칙 안에서 제안만 하고, 교사가 반영해야 입력이 채워지는지. 오래된 기준판에 생성된 제안은 막는지.
8. **설치·점검:** P9 → P10 → T3 → T4 단계와 INT-04 생성 결과가 맞는지. 설치만으로 기존 보호 함수에 적용되는 보강과 별도 활성화를 문서가 구분하는지. 부분 설치·트리거 해제·익명 권한 부여를 점검이 놓치지 않는지.
9. **학교 준비 안내:** 같은 대상 학기의 기존 조회만 집계하는지. 조회 실패·원본 변경을 완료로 표시하지 않고, 수강 등록 합계를 고유 학생 수로 안내하지 않는지. 입력 중에는 화면 이동을 막는지.
10. **엑셀과 배치 비교:** 공식 ID와 참고 이름이 분리되고 학교·학기·원본 지문을 확인하는지. 손상·구형 양식에서 기존 입력이 유지되는지. 배치 검색·페이지 이동이 저장할 전체 명령을 바꾸지 않는지.
11. **보강·요청 화면:** 홈에서 정확한 취소 수업의 보강을 여는지. 기존 입력과 결과 미상 요청을 보존하는지. 요청 필터가 선택한 원본을 숨겨 처리 대상이 바뀌지 않는지. AI 제안 적용 전 수동 입력 변경을 다시 확인하는지.
12. **학생 명부 전환:** XLSX 학교·수업 문맥, 공식 학생번호와 현재 명부의 정확 대조, 기존 학적·기간 덮어쓰기 차단, 누락 학생 보존, 파일 실패·원본 변경 후 명시 재비교, 결과 미상 시 원래 명령과 번호 복구를 확인해 주세요. 학교 전체 중복을 화면에서 확인했다고 표현하지 않습니다.
13. **학생 후속 업무:** 홈의 수업 ID를 그대로 사용하는지, 관찰만 사용자 동작으로 조회하는지, 일부 실패를 0건으로 바꾸지 않는지, 이전 페이지의 재검토 관찰을 열고 편집 중 조회 위치와 입력을 유지하는지 확인해 주세요. 상담 조회와 자동 쓰기는 없습니다.
14. **운영 동선과 출력:** 수업 상세의 운영 작업, 공통 기간 변경 시 입력·원키 보존과 미리보기 무효화, 학사 변경과 원요청 왕복을 확인해 주세요. T3 이력 조회 실패 또는 수업판 불일치에서 이전 출력 근거를 재사용하지 않고, 개인 사유가 인쇄/XLSX에 들어가지 않는지 확인해 주세요.

기존 T2 SQL은 그대로이며 `t2/test/run_t2.py`의 날짜별 시험 자료 선택만 보완했습니다. T3 시험도 재공개 범위와 날짜를 분리했습니다. 수요일·목요일에 제품의 실제 충돌 검사로 유효한 자료를 고르며, 기대값을 느슨하게 하거나 실패를 제외하지 않습니다.
