# Claude 검토 요청 — 학교 자료 연결·9학급 운영

이번 PR은 #72 시간표 운영과 #74 화면 개편에 P9 교사 연결 및 확정 시간표를 가정한 운영 연습을 더했습니다. 기존 적용 SQL·로그인·회원·AI 비용·공개 범위는 유지했습니다. 운영 SQL 실행과 main 병합은 하지 않았습니다.

중점 검토:

1. **P9 연결:** 학교별 UID 허용 목록, 현재 재직 기간, 판·원문·미리보기 일치, 관리 권한, 전체 원자성. Auth/public.users와 기존 역할 보존.
2. **결과 미상·종료:** 원번호 복구, 이미 반영된 접수증 또는 취소 장벽을 확인한 뒤에만 잠금 해제. 만료·비활성·응답 단절·동시 실행 포함.
3. **담당 후보:** P5/P8 네 곳만 자격 판정 변경. 일반 교사 입장·메신저 수신·메뉴 권한까지 확장되지 않는지.
4. **가상 운영:** 자원 충돌, 모든 영향 교사의 동의, 별도 승인·사유 반려, 원수업 보존·보강 연결, 멱등·종료 장벽·판 검사.
5. **자료 교체:** 실제 회원 명시 선택, 동일 교사의 다중 역할 충돌, 과거 기록 보존, 교사 연결 변경 시 미리보기 폐기, 반영 직전 재검사, 여러 기준판 복원, 확인 체크 분리.
6. **저장·입력:** 계정 범위, 실패 시 기존 상태 보존, 다른 탭 CAS, 압축·해제 크기 제한, 손상 백업 거부, 저장 중 입력·알림 이동 잠금.

범위:

- 원본은 공식 시간표가 아닌 개발 시드입니다. 9학급 279칸을 보존하고 가상 역할 18개로 충돌을 제거했습니다.
- 운영 연습은 실제 React·로컬 저장소입니다. 실제 교사의 동의나 운영 Supabase 자료가 아닙니다.
- 신규 P9는 격리 PG17·실제 SQL 응답으로 시험했습니다. 운영 적용 결과로 표시하지 않습니다.
- 로컬 대강·휴강·보강을 정식 T2 SQL에 연결하는 일은 남아 있습니다.
- 교사 연결 계획은 CSV로 보관하며, 실제 담당 변경은 P8의 별도 확인이 필요합니다.
