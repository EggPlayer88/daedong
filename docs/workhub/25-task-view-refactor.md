# 내 업무 입력 양식·카드 분리

2026-10-13 · 기준 main `78e2392`

내 업무의 입력 양식과 카드 표시가 저장·조회·복구 처리와 한 파일에 섞여 있었다. 이후 UI를 고칠 때 저장 상태까지 함께 건드리지 않도록 표시 부분을 두 컴포넌트로 분리했다. 교사가 보는 문구·디자인·버튼 동작은 유지한다.

## 구성과 책임

| 파일 | 책임 |
|---|---|
| `TaskPanel.tsx` | 입력·목록 상태, 학교/계정 범위, 저장 요청과 버전, 충돌·초안 복구, 이동 잠금, 초점 이동 |
| `TaskEditor.tsx` | 부모가 전달한 값·잠금·오류 연결로 입력 양식 표시, 필드 변경·저장·취소 의도 전달 |
| `TaskCard.tsx` | 업무 카드·홈 축약 표시, 상태 변경·수정 의도 전달 |
| `presentation.ts` | 기존 상태 라벨을 한곳에서 제공. 기존 정렬·요약 계산 유지 |

새 컴포넌트에는 상태나 effect, 서버 호출이 없다. TaskPanelScope의 상태·조회·저장·복구 처리 본문은 기준 커밋과 문자 단위로 동일하다. 부모가 만든 ID, 제목 input ref, 카드 ID와 접근성 속성, 수정 버튼의 실제 DOM 참조를 그대로 연결한다.

## 판단해서 정한 것

- **표시만 먼저 분리:** 큰 파일을 한 번에 hook/store로 바꾸면 조회 응답 무효화와 저장 복구의 결합이 끊길 위험이 있다. 상태 로직은 이번 범위에서 이동하지 않았다.
- **기존 잠금 차이 유지:** 카드 상태 변경은 기존 locked, 수정 버튼은 locked 또는 편집 중 여부를 그대로 따른다. 제목·메모 수정의 오류 해제와 기한 수정의 동작도 유지한다.
- **기존 ID 사용:** 자식에서 새 ID를 만들지 않아 필드 설명·카드 원본 이동·초점 계약을 유지한다.
- **상태 라벨 공용화:** 입력 화면·필터·카드·알림이 같은 라벨을 사용한다.
- **PR #25와 독립:** #25가 미병합인 상태에서 main에 있던 동일한 업무 코드를 정리했다. #25를 포함하거나 변경하지 않는다. 같은 main 대상 PR로 각각 검토·병합할 수 있다.

되돌릴 때는 이 PR의 구현 커밋을 되돌리면 된다. DB 작업이나 자료 이전이 없어 상태를 복원하는 별도 SQL은 필요하지 않다.

## 검증

- `npm test`: **1,223건** 통과(Python·계약·SSR 포함).
- `npm run check:workhub`, `npm run build`, `npm run build:workhub`: 타입 검사·두 앱 빌드 통과.
- 고정 Chromium 전체 **28/28 시험 파일** 통과. 등록/수정/취소, 상태 변경, 충돌·미확정 저장, 동료 명부 변경 후 복구, 원본 이동, 페이지, 키보드·모바일을 기존 실제 컴포넌트 시험으로 검증했다.
- 분리 전 실제 JSX와 현재 컴포넌트의 SSR HTML이 **1,024조합(양식 64·카드 960)**에서 정규화 없이 완전히 일치했다. 기준 Git 원문으로 비교하는 한시적 도구를 사용했으며 npm 시험 수에 합산하지 않는다. 이벤트·초점·비동기 복구는 위 브라우저 시험이 별도로 검증한다.
- 모바일·데스크톱 충돌 상태에서 입력 양식과 카드 화면을 육안 확인했다.
- 별도의 영구 테스트를 추가하거나 기존 테스트를 수정하지 않았다. 기존 인수 동작을 그대로 검증한다.

#25의 별도 시험(SSR 4건·브라우저 1파일)은 이 브랜치에 포함되지 않아 #25의 1,227건/29파일과 집계 기준이 다르다. 이 PR이 테스트를 삭제한 것은 아니다.

저장소 루트에서 기존 의존성과 Chromium을 준비한 뒤 실행한다.

```bash
npm test
npm run build
npm run build:workhub
PLAYWRIGHT_CHANNEL=chromium npm run test:workhub:browser
```

PowerShell에서는 브라우저 실행 전에 `$env:PLAYWRIGHT_CHANNEL = 'chromium'`으로 지정한다. 주요 시험은 `workhub-tasks`, `workhub-accessibility`, `workhub-task-navigation`, `workhub-task-paging`, `workhub-draft-recovery`다.

## 남은 작업

이것은 화면 코드 분리의 첫 단계다. TaskPanel의 상태 책임은 여전히 많다. 필요하면 복구·충돌 안내와 필터 계산을 별도 단계로 정리하되, 저장 처리와 응답 무효화의 결합을 검증하면서 진행한다. 다음 기능 작업은 기존 회원 관리를 유지한 학교 소속·초기 설정 UI 구체화다.

#23·#24는 main에 병합돼 있고 #25와 이번 PR은 별도 검토 대상이다. 기존 로그인·회원, 공개 범위, 인증·권한 판정, DB·SQL, AI 호출·비용, 시간표는 변경하지 않는다. **DB 구축과 시간표는 보류**한다. 합성 전송 기반 검증이며 실제 운영 서버 연결·교사 시범 공개 완료를 뜻하지 않는다.
