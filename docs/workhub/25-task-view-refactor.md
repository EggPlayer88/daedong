# 내 업무 표시 분리와 연결 오류 후속 보완

2026-10-14 · PR #26 · 기준 main `ebdc064`(#25 병합)

내 업무의 입력 양식과 카드 표시가 저장·조회·복구 처리와 한 파일에 섞여 있었다. 이후 UI를 고칠 때 저장 상태까지 함께 건드리지 않도록 표시 부분을 두 컴포넌트로 분리했다. 내 업무의 문구·디자인·버튼 동작은 유지한다. 연결 오류 화면에는 Claude S1·S2의 문구·이동 경로 보완을 함께 반영했다.

## 구성과 책임

| 파일 | 책임 |
|---|---|
| `TaskPanel.tsx` | 입력·목록 상태, 학교/계정 범위, 저장 요청과 버전, 충돌·초안 복구, 이동 잠금, 초점 이동 |
| `TaskEditor.tsx` | 부모가 전달한 값·잠금·오류 연결로 입력 양식 표시, 필드 변경·저장·취소 의도 전달 |
| `TaskCard.tsx` | 업무 카드·홈 축약 표시, 상태 변경·수정 의도 전달 |
| `presentation.ts` | 기존 상태 라벨을 한곳에서 제공. 기존 정렬·요약 계산 유지 |

새 컴포넌트에는 상태나 effect, 서버 호출이 없다. TaskPanelScope의 상태·조회·저장·복구 처리 본문은 기준 커밋과 문자 단위로 동일하다. 부모가 만든 ID, 제목 input ref, 카드 ID와 접근성 속성, 수정 버튼의 실제 DOM 참조를 그대로 연결한다.

## 연결 오류 후속 보완

- **S1:** 입력 폐기 완료와 신축 화면 로딩 실패 안내의 “상단의”를 제거했다. 화면 크기·메뉴 위치와 관계없이 “기존 업무 메뉴”로 안내한다.
- **S2:** WorkhubPage가 기존 MODULES의 dashboard 경로를 읽고 React Router useHref로 기준 경로(basename)를 반영한다. 완성된 주소를 ConnectedWorkspace → ConnectionRecoveryActions의 legacyHomeHref로 전달한다. 연결 화면의 href 고정값을 제거했으며 신축 앱이 기존 앱의 메뉴 설정을 직접 가져오지 않는다.
- 새 탭 링크의 target/rel, 현재 탭 입력 보호, 미확정 요청의 폐기 차단은 유지한다. 실제 배포 경로나 인증 판정은 변경하지 않는다.

## 판단해서 정한 것

- **표시만 먼저 분리:** 큰 파일을 한 번에 hook/store로 바꾸면 조회 응답 무효화와 저장 복구의 결합이 끊길 위험이 있다. 상태 로직은 이번 범위에서 이동하지 않았다.
- **기존 잠금 차이 유지:** 카드 상태 변경은 기존 locked, 수정 버튼은 locked 또는 편집 중 여부를 그대로 따른다. 제목·메모 수정의 오류 해제와 기한 수정의 동작도 유지한다.
- **기존 ID 사용:** 자식에서 새 ID를 만들지 않아 필드 설명·카드 원본 이동·초점 계약을 유지한다.
- **상태 라벨 공용화:** 입력 화면·필터·카드·알림이 같은 라벨을 사용한다.
- **검토를 통과한 기준 사용:** #25를 사용자 승인으로 merge commit 병합한 뒤 main을 #26에 merge했다. #25와 #26의 변경을 함께 검증하며, #26은 Claude 재검토 후 별도로 병합한다.

되돌릴 때는 이 PR의 표시 분리 또는 문구·경로 보완 커밋을 변경 목적에 맞게 되돌린다. main 동기화 merge를 함께 되돌리지 않는다. DB 작업이나 자료 이전이 없어 상태를 복원하는 별도 SQL은 필요하지 않다.

## 검증

- `npm test`: Python을 포함한 전체 회귀 **1,227건** 통과.
- `npm run check:workhub`, `npm run build`, `npm run build:workhub`: 타입 검사·두 앱 빌드 통과.
- 고정 Chromium 전체 브라우저 **29/29파일 통과**. 등록/수정/취소, 상태 변경, 충돌·미확정 저장, 동료 명부 변경 후 복구, 원본 이동, 페이지, 키보드·모바일을 기존 실제 컴포넌트 시험으로 검증했다.
- 표시 분리 시 확인한 기존 기록: 분리 전 실제 JSX와 현재 컴포넌트의 SSR HTML이 **1,024조합(양식 64·카드 960)**에서 정규화 없이 완전히 일치했다. 기준 Git 원문으로 비교하는 한시적 도구를 사용했으며 npm 시험 수에 합산하지 않는다. 이벤트·초점·비동기 복구는 위 브라우저 시험이 별도로 검증한다.
- 모바일·데스크톱 충돌 상태에서 입력 양식과 카드 화면을 육안 확인했다.
- 연결 오류 브라우저 **12건**을 통과했다. 기존 9개 시나리오의 문구·새 탭 목적지 검증을 보완하고, 실제 WorkhubPage에서 기본 경로 `/`, basename `/school`, 메뉴 경로 변경과 basename의 결합 `/school/legacy-home`이 새 탭까지 이어지는 3개 시나리오를 추가했다. 현재 탭 주소·보관 입력·중복 저장 방지도 확인했다.

#25 병합 후 전체 시험을 포함한 기준으로 다시 검증했다. 이전 #26의 1,223건/28파일은 #25 병합 전 기준의 기록이다.

## 남은 작업

이것은 화면 코드 분리의 첫 단계다. TaskPanel의 상태 책임은 여전히 많다. 필요하면 복구·충돌 안내와 필터 계산을 별도 단계로 정리하되, 저장 처리와 응답 무효화의 결합을 검증하면서 진행한다. 다음 기능 작업은 기존 회원 관리를 유지한 학교 소속·초기 설정 UI 구체화다.

#23·#24·#25는 main에 병합돼 있고 이번 #26은 재검토 대상이다. 기존 로그인·회원, 공개 범위, 인증·권한 판정, DB·SQL, AI 호출·비용, 시간표는 변경하지 않는다. **DB 구축과 시간표는 보류**한다. 합성 전송 기반 검증이며 실제 운영 서버 연결·교사 시범 공개 완료를 뜻하지 않는다.
