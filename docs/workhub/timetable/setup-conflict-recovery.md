# 공간·수업 연결 일괄 입력의 충돌 복구

PR #70 · U-2 보완 · 2026-10-19

## 교사에게 보이는 흐름

1. 일괄 저장이 CONFLICT로 끝나면 이전 판으로 같은 요청을 반복하는 버튼 대신 **최신 자료로 남은 항목 다시 비교**를 제공한다.
2. 서버에서 최신 준비 자료를 읽는다. 완료 항목은 그대로 두고 남은 항목의 처음 값·현재 서버 값·보관한 입력을 표시한다.
3. 항목마다 **내 입력으로 저장 준비** 또는 **현재 서버 값 유지**를 직접 고른다. 선택 기본값은 없고, 전체 남은 항목이 선택되어야 확인할 수 있다. 20개씩 표시해도 다른 쪽의 선택을 유지한다.
4. **선택한 비교 결과 적용**은 브라우저의 승인 묶음만 갱신한다. 저장은 하지 않는다.
5. 별도 저장 확인 후 이어 저장한다. 그 사이 자료가 다시 바뀌면 또 충돌시키며 자동으로 덮어쓰지 않는다.

## 요청 번호와 완료 결과

- 저장 완료 항목: 명령·요청 번호·접수증을 그대로 보존하며 재전송하지 않는다.
- 거절이 확정된 CONFLICT 항목: 최신 판을 넣은 새 명령과 새 요청 번호를 만들고, 이전 명령·번호를 `replacedRequests`에 보존한다.
- 한 번도 보내지 않은 대기 항목: 다시 승인한 값과 최신 판으로 준비하되 기존 미전송 요청 번호를 유지한다.
- 현재 서버 값 유지를 고른 항목: `skipped`로 기록하고 쓰기를 보내지 않는다. 원래 입력과 번호는 결과 목록에 남는다.
- 저장 결과 미상/저장 중: 재계획을 거부하고 기존 명령·번호로 복구한다.
- 원장 없음(`not_found`): 늦은 최초 저장 가능성을 남겨 두므로 재계획을 거부한다. 기존 규칙대로 같은 번호 재전송만 허용한다.

현재 자료를 채택한 시점의 원본과 완료 위치를 checkpoint로 보관한다. 이 시점 이전의 성공 접수증을 최신 원본에 다시 적용해 외부 변경을 덮지 않는다. 이후 성공 항목만 다음 저장 비교에 반영한다. 학교·회원·소속/역할 범위가 다르거나 대상 학기·학기 기간이 달라지면 재승인하지 않는다.

## 입력 잠금

기존 `onLockChange`는 파일 읽기·쓰기·결과 미상뿐 아니라 가져온 미완료 입력과 일괄 저장 중단 상태도 포함한다. 대상 학기 전환 시 이 잠금을 포함해야 한다. 완료 결과만 남은 상태는 잠그지 않는다. 재검토 중 권한/범위가 바뀌면 늦은 조회를 채택하지 않는다.

## 검증과 경계

- 단위 시험: 실제 판 충돌, 완료 접수증 보존, 최신 값 유지, 전부 유지, 사라진 대상, 선택 누락·비교 변조, 키 재사용, 결과 미상과 원장 없음, 학교·소속·학기 변경, 재검토 후 재변경, 재승인 뒤 응답 유실을 검증한다.
- 브라우저 시험: 실제 React·XLSX·전송 어댑터를 사용해 충돌→비교→선택→저장 경로, 완료 보존, 권한 변경, 원키 복구와 320px/200% 확대를 검증한다.
- RPC 응답은 합성이다. 실제 Supabase 적용·서버 왕복과 운영 활성화는 별도다.
- SQL·인증·비용·공개 범위는 바꾸지 않는다.

## 판단해서 정한 것

전체 원자 저장으로 바꾸지 않고 기존 순차 접수 계약을 유지한다. 서버가 확정적으로 거절한 CONFLICT에서만 새 요청을 만들며, 결과를 모르는 요청을 새 명령으로 치환하지 않는다. 선택하지 않은 행을 자동 제외하지 않고 모든 행의 명시 선택을 요구해 다른 사람의 변경을 조용히 덮어쓰지 않도록 했다.
