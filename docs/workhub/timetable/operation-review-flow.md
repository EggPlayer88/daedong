# 시간표 확정·변경 검토 흐름 보완

2026-10-19 · 앱 통합 후속 작업. SQL·권한·공개 범위·비용 계약 변경 없음.

## 담당자가 보는 변화

1. 편성 화면에서 저장한 초안의 ID·판을 운영 화면으로 전달한다. 최신 저장 목록과 정확히 일치할 때만 확정 입력에 선택한다. 기간 확인·미리보기·확정은 담당자가 각각 수행한다.
2. 확정·교환·학사 변경에서 같은 변경 전후 목록을 사용한다. 현재 목록의 새 편성·취소·시각 변경·그 밖의 변경, 표시 교사 수와 수업 시작일을 보여 준다. 교사·학급·수업·공간·학교 현지 날짜·식별 번호로 검색한다.
3. 내 수업과 교환 상대를 검색한다. 검색 밖으로 밀린 현재 선택도 보존한다. 동명 수업·교사는 ID로 구별하고 학급을 함께 표시한다. 최신 조건에서 교환 후보가 사라지면 이전 선택과 사유를 남기고 재확인을 안내한다.
4. 학사 변경의 학급을 검색하고 동명 학급을 ID로 구별한다. 선택한 학급은 검색 밖에도 표시한다. 연결이 사라진 선택은 미리보기를 보내기 전에 안내한다.
5. 학사 변경에 막힌 기존 교환의 요청 번호·판·상태와 조회 가능한 사유를 보여 준다. 임의 철회·승인·덮어쓰기를 하지 않는다.

## 입력·요청 보존

- 보관 중인 확정·교환·학사 변경 입력과 결과 미상 요청은 초안 이동보다 우선한다. 초기 이동 의도는 한 번 소비하고 상위 화면에도 소비를 알린다. 이후 일반 재진입에서 옛 저장 초안을 다시 선택하지 않는다.
- 원래 요청 복구는 기존 명령·키와 계약을 그대로 사용한다. 검색은 표시만 바꾸며 미리보기·확정 대상이나 RPC 내용을 바꾸지 않는다.
- 오래된 초안 판을 최신 판으로 추정하지 않는다. 현재 권한이 없으면 초안 이름을 표시하지 않는다.
- 분할 변경 목록의 검색·요약 범위는 현재 상세 쪽이다. 모든 쪽을 검색했다거나 영향 교사를 모두 센 것으로 안내하지 않는다. 기존 전체 명세 검증과 최종 확인은 그대로 유지한다.
- 표시 집계는 같은 이름을 ID 없이 학급 수로 합산하지 않는다. 교사 수는 표시된 교사 ID를 기준으로 하며 동의 대상 수와 구별한다.

## 판단해서 정한 것

- 일반 운영 전후 비교에 검색과 요약을 추가했다. 긴 학기 변경 목록에서 특정 교사를 찾기 쉽도록 하기 위함이다. 원래 변경 배열은 읽기만 하므로 원자 승인·해시에 영향이 없다.
- 검색창은 접어 두고 20건씩 표시한다. 작은 교환은 기존 비교가 바로 보이며 검색으로 승인 범위를 줄일 수 없다.
- 학사 변경에서 기존 교환을 직접 취소하는 버튼은 추가하지 않았다. 해당 요청의 동의·승인 절차와 원래 요청 번호를 존중한다.
- 3자 교환·대강·새 권한·백그라운드 자동 승인은 추가하지 않았다. 현재 계약의 이동·두 수업 교환·학사 변경 범위만 연결한다.

## 검증

- 순수 변경 요약·검색 회귀 12건, 기존 운영 SSR 8건 통과.
- 신규 변경 검토·확정 연결 브라우저 9건.
- 관련 기존 브라우저: 교환 23건, 확정·공유 16건, 학사 변경 14건, 교환 목록 8건, 학기 전체 확정 16건, 원래 요청 복구 7건.
- 320px 가로 넘침, 키보드 검색 초기화, 목록 축소 후 검색 해제, 저장 판 불일치, 기존 입력 정리 뒤 새 초안 연결, 결과 미상 우선 보존을 포함한다.
- 실제 React·기존 전송 어댑터와 합성 RPC 응답으로 시험한다. 신규 단독 초안 연결 fixture는 UI 동작 검증이며 실제 Supabase 왕복을 입증하지 않는다.
- 실제 T1/T2 설치·활성화, 운영 서버 응답, 실제 학교 편성·교환 데이터의 적용 결과는 Claude 검토와 사용자 승인 후 별도 확인한다.
