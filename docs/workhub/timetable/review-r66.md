2026-10-19. Claude가 보고한 R-1~R-8과 화면·계약 보완을 같은 PR에 반영한다. 기존 `feat/workhub-timetable-usability`에서 진행하며 SQL·인증·비용·메뉴 공개 범위는 유지한다. T1 준비 입력 화면은 Claude의 `timetable.setup.v1` 계약을 받은 뒤 연결한다.

## 수정과 판단 기준

| 검토 항목 | 구현 기준 | 검증할 실패 경로 |
|---|---|---|
| R-1 미완성 접수 파일 | 용량 검사에서 빈/미완성 ready·status를 대기 한 건으로 센다. 읽힌 식별자가 다른 경우와 권한·크기 오류는 그대로 거부한다. 새 파일 쓰기 실패 시 자신이 만든 빈 파일만 제거한다. | 다른 번호의 빈 ready 때문에 새 접수가 막히지 않음. 생성·쓰기·닫기 실패 후 원번호 재접수. 기존 파일·교체된 파일 보존. |
| R-2 실패 안내 | 작업 실패 코드와 다음 조치를 함께 보여 준다. 모르는 코드는 임의 의미를 부여하지 않는다. | STORE_FULL·QUEUE_FULL·INVALID_REQUEST와 알 수 없는 코드 표시. |
| R-3 보관 여유 | 브라우저와 CLI 접수 모두 원본·스냅샷, 결과 최대 크기 두 배, 메타데이터 네 배의 여유를 확인한다. 실행 직전 Python 검사도 유지한다. | 원본만 들어갈 수 있는 폴더에서 새 접수 거부. 기존 원번호 조회·복구 유지. |
| R-4 대기 순서 | 정상 대기 작업을 접수 시각·번호 순으로 처리한다. 한도를 넘겨 외부에서 만든 초과분만 QUEUE_FULL로 끝낸다. | 가장 오래된 정상 작업은 계산되고 초과분만 실패. |

| R-7 미접수 폴더 | 1시간 이상 지난 request-only·불완전 ready를 미리보기 후 보존 격리한다. 실행 흔적이 있거나 최근에 바뀐 폴더는 대상에서 제외한다. | 미리보기 후 변경·실행 흔적·정상 ready는 격리하지 않음. 격리 원본은 용량에 계속 포함. |

미접수 폴더는 삭제 대신 `.cleanup-orphans/<요청 번호>`로 옮긴다. 브라우저 연결과 접수를 중단한 뒤 cleanup 미리보기→명시 실행을 사용한다. 후보의 내용·파일 시각·식별 정보를 다시 확인하며, 정리 도중 바뀌면 중단하고 보존한다. 격리된 파일은 작업 수에서는 빠지지만 디스크 용량에는 포함한다. 실제 사용자 파일을 이번 개발 중 정리하거나 삭제하지 않았다. 상세 명령과 손상 기록 처리 절차는 [로컬 계산기 안내](engine-jobs.md)를 따른다.

## 화면·T2 계약

- 출력에서 수업 판이 올랐다는 이유만으로 임시 변경을 단정하지 않는다. 일치하는 변경 이력이 없으면 **판 갱신 · 재확정·변경 여부 미확인**으로 표시한다.
- AI 카드와 일괄 선호 미리보기의 동명 수업에는 안정된 `[id]`를 붙인다. 표시 이름을 바꿔도 실제 선택 ID와 반영 내용은 유지한다.
- 수업·이동 대상의 시작/끝 시각은 **정수 초 `.000Z`**만 받는다. 조회·접수·기한 같은 메타데이터 시각의 밀리초는 유지한다.
- 확정 명세의 `pageSize`는 **200 고정**이다. 마지막 쪽의 실제 행 수가 200보다 적은 것은 정상이다. 전체 한도는 기존 100,000행·500쪽을 유지한다.
- 정상 요청이 전체 한도를 넘으면 SQL은 성공 데이터 대신 기존 오류 봉투의 `INVALID_INPUT`을 반환해야 한다. 패널은 입력을 보존하고 적용 기간을 나누어 다시 확인하도록 안내한다. 위조된 응답·다른 학교·잘못된 pageSize·과도한 성공 데이터는 계속 `INVALID_RESPONSE`다.
- 구 `workhub_timetable_operations_school_day_preview`는 대체된 계약이다. T2는 `workhub_timetable_school_day_preview`를 구현한다. 구 DTO를 새 함수에 그대로 연결하지 않는다.

## 2026-10-19 교환 브라우저 시험의 재조회 경합 보완
