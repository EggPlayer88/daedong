# 현재 탭의 편성 후보 보관·비교

## 교사가 사용하는 흐름

1. 생성·수동 조정·불러오기를 마친 완성 배치에서 **현재 배치를 후보로 보관**한다.
2. 조건을 바꾸거나 다시 계산한다. 보관 후보는 자동으로 덮어쓰지 않는다.
3. 기본적으로 접혀 있는 **다시 계산 전에 후보 보관·비교**를 열어 후보를 고른다.
4. 현재 배치 또는 다른 보관 후보와 비교한다. 변경 수업은 교사·학급 ID와 검색으로 좁힌다.
5. 기초 자료와 조건이 같은 후보만 명시 확인 후 현재 작업으로 채택한다. 서버 초안 저장·확정·공개는 기존 별도 절차를 따른다.

## 원본과 검증

- 각 후보는 `basis` 전체(기초판 ID·판·원본 지문·자원·수업·교시·하드·소프트 조건)와 배치, 사용자 이름, 후보 UUID, **보관 시각**을 깊은 복사한다.
- 보관 시각은 계산 시작·완료 시각이 아니다. 생성 방식이나 엔진의 최적성 표시는 추정하지 않는다.
- 보관·복원·비교·채택에서 기존 독립 `validatePlacements` 검사를 사용한다. 미배정·충돌·미지원 조건 배치는 새 후보로 보관할 수 없다.
- 학교·학기·회원·소속·권한 범위는 기존 탭 메모리 범위를 따른다. 다른 학교·학기의 후보를 한 보관함에 넣을 수 없다.
- 기초판의 전체 내용과 모든 조건을 canonical JSON으로 비교한다. 키 순서만 무시하고 배열 순서·표시 이름·판·지문도 보존한다. 확실하지 않은 동등성을 추정하여 옛 후보를 채택하지 않는다.
- 현재 작업 배치·조건·선택 후보·비교 기준이 바뀌면 기존 채택 확인은 즉시 무효다. 부모 편집기의 작업 고정·권한 보호가 채택을 거절하면 성공 안내를 하지 않는다.

## 비교의 의미

- 같은 기준·조건일 때만 선호 벌점과 교사 하루 최대 차시를 나란히 표시한다. 전체 최적이나 실제 교사 만족도의 보장은 아니다.
- 기준이나 조건이 다르면 점수 비교를 막고, 수업 ID에 따른 실제 시각·배정 차이만 표시한다.
- 과거 이름·담당자·시각은 당시 기준판으로 읽는다. 동명이인은 `[ID]`로 구별하며 변경 전후 담당자 양쪽으로 검색한다.
- 이동·배정 변경은 중복 집계될 수 있다. 추가·제거는 안정 수업 ID로 구분한다.
- 변경 목록은 전체에서 검색·필터한 다음 20개씩 표시한다. 현재 쪽만 집계하지 않는다.

## 판단해서 정한 것

- **후보 6개 / JSON UTF-8 직렬화 합계 8MiB**: 브라우저·로컬 계산·담당자 수정안 등 몇 가지 대안을 한 번에 비교하면서 큰 학교의 원본 복사본이 탭에 무한히 쌓이지 않게 한 로컬 편의 한도다. 학교 규모나 SQL 계약의 한도가 아니다. 실제 JS 힙 사용량의 절대 상한으로 보장하지 않는다.
- **한도 초과 시 자동 삭제 없음**: 교사가 필요한 후보를 명시적으로 정리하거나 서버 초안에 저장한다. 가장 오래된 후보도 동의 없이 버리지 않는다.
- **후보 자동 채택·자동 서버 저장 없음**: 현재 탭에서의 비교를 서버 초안·학기 확정과 구분하고 현재 작업 고정을 지킨다.
- **별도 영속 저장 없음**: `useEditDraft`로 같은 탭의 화면 재진입만 복원한다. 새로고침·브라우저 종료 이후에는 사라질 수 있음을 화면에 안내한다.
- **기본 접힘**: 편성 화면의 핵심 배치 작업을 가리지 않도록 필요할 때만 보관·비교를 펼친다.
- 한도를 바꾸려면 `apps/workhub/src/timetable/_assets/candidate-library-policy.json`을 수정한다. 서버/SQL 구조와 관계없다.

## 검증 경계

- `tests/test_workhub_timetable_candidate_library.mjs`: 원본·변조·한도·점수 비교·ID 변화·SSR·손상 메모리 검증.
- `tests/browser/workhub-timetable-candidate-library.mjs`: 실제 React에서 명시 보관·비교·채택·부모 거부·재진입·조건 변경·동명이인·55건 페이지·모바일 경로.
- 이 기능은 RPC를 추가하지 않는다. 실제 Supabase 저장·T1/T2 활성화 성공을 뜻하지 않는다.
