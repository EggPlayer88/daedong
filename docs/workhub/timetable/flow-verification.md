## 재현 명령

```text
npm test
npm run check:workhub
npm run build
npm run build:workhub
npm run check:workhub:timetable
node tests/browser/run.mjs timetable
```

`tests/browser/run.mjs`는 이름에 timetable이 들어간 33개 파일을 순서대로 실행한다. 새 파일 4개는 전체 CI 브라우저 목록에도 등록했다. 변경된 작업 브랜치도 기존 시간표 보호 검사를 실행한다.

## 검증 경계

- 브라우저의 React, 화면 상태, RPC 어댑터·파서, 기존 XLSX 처리는 실제 코드다. DB/RPC·Storage·Claude 응답은 합성이다.
- 새 통합 흐름의 계산은 실제 JS 알고리즘이다. 해당 fixture의 Worker 전달은 합성이고, 기존 `workhub-timetable-worker`가 실제 Worker 경로를 별도 검증한다.
- CP-SAT/로컬 계산기는 고정 버전 Python/OR-Tools 왕복을 기존 회귀로 검증한다. 실제 학교 최대 규모의 최적화 성능을 보장하지 않는다.
- 사용자 PC의 실제 파일·인쇄와 운영 Supabase/PostgREST/T1/T2/Claude 호출, 로그인된 운영 화면은 이번 검증에 포함하지 않았다.
- DB SQL 실행·외부 설정·교사 공개·PR 병합은 하지 않았다. GitHub CI 및 Vercel Preview는 PR에서 별도로 상태를 확인한다.

## 검증 중 발견·수정

1. 저장→확정 이동 의도가 부모에 남아 일반 재진입에서 다시 옛 초안을 선택하는 경로를 1회 소비로 고치고 통합 회귀에 추가했다.
2. 부모의 작업 고정 검사에서 후보 채택을 거절해도 계산기 UI가 성공 안내하고 응답을 지울 수 있어 반환 결과를 확인하도록 고쳤다.
3. 최초 npm/browser 병렬 실행에서 CP-SAT의 feasible 기대와 두 순차 작업 대기 시험이 실패했다. 두 작업의 허용 실행 합계보다 시험의 고정 15초 대기가 짧았고 반복 Python CLI 폴링도 부하를 만들었다. 시험 대기만 요청 시간한도+작업자 여유 합계+기동여유로 계산하고 상태 JSON을 읽도록 보강했다. 작업자 실패/종료는 로그와 함께 즉시 실패하고 성공은 CLI로 다시 확인한다. 운영 엔진과 시간한도는 바꾸지 않았다. 최종 npm test는 무거운 브라우저 시험 종료 후 단독 실행한다.

4. 빌드를 병행한 두 번째 전체 회귀에서 기존 메신저 첨부 시험 1파일이 실패했다. 단독 27건은 통과했으며 메신저 코드는 변경하지 않았다. 빌드와 브라우저 작업을 종료한 최종 연속 `npm test`에서 4,106건 모두 통과했다. 짧은 시간 제한에 의존하는 기존 시험의 환경 민감성은 실제 기능 결함과 구분해 기록한다.
