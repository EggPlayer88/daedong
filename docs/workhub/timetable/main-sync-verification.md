최초 전체 `npm test`에서는 `test_timetable_jobs.mjs`의 두 요청 순차 처리 사례가 `ENGINE_START_FAILED`로 실패했다. 단독 재실행에서 해당 사례는 통과했지만, 실제 작업자를 중단하는 다른 사례가 상태 변경 대기 초과로 실패했다. 두 실행의 원본 로그를 보존했다.

계산기·작업자·관련 시험은 main과 같은 코드다. 이 사실만으로 환경 문제라고 단정하지 않는다. 기존 오류 코드가 여러 `OSError`를 함께 나타내므로 원래 실패 원인은 최초 로그만으로 확정할 수 없다. 별도 진단은 동일 시험의 예외 위치와 상태만 기록하며 기대값이나 제품 코드를 바꾸지 않는다.

별도 진단 전체 55건, 최초 실패 두 사례를 각각 3회 반복한 6건이 통과했다. 이후 진단 코드를 넣지 않은 원본 `npm test` 전체를 단독 실행해 4,370건이 모두 통과했다. 이 숫자에 진단·반복 검사를 더하지 않는다. 최초 두 실패의 원인은 미확정이며 재실행 성공을 근거로 실패 이력을 삭제하거나 환경 문제로 확정하지 않는다.

로그는 바탕화면 `GPT작업/2026-10-20_시간표요청닫기/`에 보존한다. 최초 `main-sync-npm-test.log`, 단독 재시험 `main-sync-jobs-recheck.log`, 최종 `main-sync-npm-final.log`, 브라우저 `main-sync-browser/summary.json`, 진단 `jobs-diagnostics/`를 함께 확인한다. CI·Vercel은 푸시한 최신 head의 체크로 따로 판단한다.
