# 시간표 준비 — 공간·연결·시수 엑셀과 입력 점검

기준일: 2026-10-19. PR #68 `463445df97fe7e485c17f1a8e2636a9efa16abb0` 후속 앱 브랜치 `feat/workhub-timetable-setup-batch`.
T1 계약은 PR #67 `ad10792378dd124efe3af6bef57c5cffcd6dff2a`의 `timetable.setup.v1`을 유지한다. SQL 파일과 공개 RPC의 이름·인자·응답은 변경하지 않았다.

## 교사가 사용하는 순서

1. **시간표 → 학교 편성 자료 준비 → 공간·수업 연결 관리**를 연다.
2. 위쪽의 **엑셀로 공간·수업 연결 한 번에 준비**에서 현재 양식을 내려받는다.
3. 엑셀의 공간 시트에서 이름·동시 수업 수를, 수업연결 시트에서 학급·별도 수강집단·공간 연결을 편집한다. 공식학급·공식수업 시트와 ID를 참고한다. 같은 이름만 보고 연결하지 않는다.
4. 다시 가져오면 변경 전후를 보여 준다. 저장할 행만 선택한다. 검색·쪽 이동은 선택을 지우지 않는다.
5. 확인 체크 후 선택한 항목을 한 건씩 저장한다. 완료·대기·결과 확인 필요를 나누어 표시한다. 중간에 멈추면 이미 저장한 것은 유지된다.
6. 저장 뒤 시수·일과 화면에서 바뀐 공식 자료를 확인한다. 기존 시수·교시·활동 ID를 보존하고 **입력 보존하고 현재 자료 채택**을 선택한다. 일괄 입력 자체가 기준판 생성이나 시간표 공개는 아니다.
7. **먼저 확인할 준비 항목**에서 누락·충돌을 확인하고 해당 수업·공간 편집으로 바로 이동한다. 공식 교사 배정 문제는 학교 관리로 이동한다. 준비 점검표와 일괄 저장 결과를 파일로 내려받을 수 있다.

동시 수업 수는 학생 좌석 수가 아니다. 빈칸은 null로 유지하고 1로 추정하지 않는다. 여러 공간을 연결하면 함께 점유한다. 별도 수강집단과 공식 학급은 동시에 지정하지 않는다.

## 이번 일괄 입력의 범위

| 항목 | 처리 |
|---|---|
| 기존 공간 이름·동시 수업 수 | 수정 가능. 종류·ID·기준판은 고정 |
| 수업의 공식 학급·별도 수강집단·공간 | 명시 ID로 수정 가능. 원래 배열·문자열을 복구 명령에서 보존 |
| 공간 추가·삭제 | 기존 개별 화면에서 처리. 엑셀 행 삭제를 DB 삭제로 해석하지 않음 |
| 교사 배정·학생 관계·공식 학급·수업 | 참고만 가능. 학교/수업 관리에서 변경 |
| 주당 시수 | 추가한 시수 전용 XLSX로 미정 시수만 편집. 로컬 초안 반영 후 기존 준비 저장 사용 |
| 일과·활동·계산 조건 | 기존 준비·조건 화면에서 처리. 시수 파일이 자동 변경하지 않음 |
| 원본이 바뀐 파일 | 변경 비교 승인을 해제하고 새 양식과 다시 비교. 임의 병합하지 않음 |

XLSX는 기존 `xlsx.ts`의 크기·ZIP·수식·외부 참조 검사와 한도를 사용한다. 내려받기/파싱은 브라우저 내부에서 수행한다. 수식이 있는 입력은 거부한다. 시트·헤더·필수 행과 ID가 바뀌면 어느 시트·행·열인지 안내한다. 기존의 삭제된 연결은 그대로 보관하되, 실제 수정 명령에서는 현재 존재하는 대상만 받는다.

숨은 원본대조 시트는 학교·학기·기준일·공식 원본이 같은지 비교하는 자료이며 인증 장치가 아니다. 서버의 권한·판·요청 번호 검사를 대신하지 않는다. 파일에는 교사명과 학급·수업 정보가 포함될 수 있다.

## #69에 함께 추가한 시수 준비 흐름

공간·수업 연결 파일과 시수 파일은 목적이 다르므로 따로 둔다. 공간 파일은 T1 setup RPC로 항목별 저장하고, 시수 파일은 **현재 준비 초안만** 변경한다.

1. **엑셀로 주당 시수 한 번에 준비 → 준비 시수 엑셀 내려받기**를 누른다. 현재 화면에서 편집 중인 제목·시간대·활동도 비교 기준에 포함한다.
2. `주당시수` 시트의 `입력시수(G열)`만 편집한다. 공식 시수가 미정인 수업만 바꿀 수 있다. 0은 미완성 입력이며 빈칸·소수·수식·음수는 거절한다. 수업 이름이나 학급 이름으로 추측 연결하지 않는다.
3. 다시 가져와 **현재 시수 / 가져온 시수 / 기존 활동 합계**를 확인한다. 검색·쪽 이동 중에도 선택은 유지된다. 선택한 수업만 명시 확인 후 초안에 반영한다.
4. 반영은 수업 활동·연속수업·교시·허용 시간대·제목을 바꾸지 않는다. 시수와 활동 합계가 달라졌으면 화면에서 조정한다. 서버 저장은 기존 **준비 초안 서버에 저장**으로 별도로 수행한다.
5. **시수·활동 입력 점검**에서 시수·활동·시간대·교사/학생 연결의 누락을 분류해 본다. **입력으로 이동**은 정확한 수업 ID의 편집 영역을 열고 키보드 초점을 옮긴다.
6. **교사·학급별 배정 시수 보기**는 전체 준비 목록을 합산한다. 미정 시수는 별도로 표시한다. 합계만으로 시간 충돌이나 과부하를 판정하지 않는다.

`preparation-hours-workbook.ts`는 학교·학기·공식 자료와 현재 초안 **전체**를 대조한다. 원본 행 삭제·추가·중복, 공식 배정·시수 수정, 타학교 파일, 변경/변조된 미리보기를 거절한다. 파일 행 순서는 바뀌어도 실제 초안 배열 순서는 보존한다. 선택을 반영할 때도 현재 자료로 다시 계산해 검증한다.

`TimetablePreparationHoursPanel.tsx`는 읽는 중과 미반영 변경이 남은 동안 다른 시수·일과·setup 편집을 잠근다. 외부 잠금과 자기 잠금을 분리해 반영 자체가 막히지 않게 했다. 파일 오류·준비 조회 장애·같은 범위의 화면 재진입에서 기존 미리보기와 선택을 보관하며, 확인 체크는 다시 받는다. 권한/계정/원본이 읽는 도중 바뀌면 늦은 결과는 반영하지 않는다. 보관 파일은 내려받거나 명시 확인 후 정리할 수 있다.

저장된 초안만 보고 있던 상태에서 다른 담당자가 서버 초안을 바꾸면 새 초안은 읽을 수 있지만 옛 엑셀은 반영하지 않는다. 미저장 초안이 있으면 그 입력과 판 충돌 안내도 유지한다. 파일을 초안에 반영한 뒤 저장 응답이 끊겼을 때는 기존 `timetable.preparation.v1`의 원래 명령·요청 번호 복구를 그대로 사용한다.

입력 점검의 **기본 입력 채움**은 수업별 필수 입력 현황이다. 계산 성공률이나 전체 사이트 완성률이 아니다. 실제 편성 가능성은 기존 `compilePreparation`, 편성 엔진, 서버 검사에서 별도로 판단한다.

## 저장·복구의 보장 범위

- `setup-workbook.ts`: 파일을 저장 명령으로 바꾸기 전에 전후 비교·고정 원본을 검사한다. 공간 이름 변경을 선택 해제해도 수업 연결 비교가 거짓 이름을 보여 주지 않도록 원본 이름·ID를 명시한다.
- `setup-batch.ts`: 선택한 원본·명령·순서·요청 번호를 고정한다. 각 쓰기 직전에 기존 setup 조회를 실행하고 관련 항목·학기·기준일·진단을 다시 대조한다. 이 묶음은 전체 원자 트랜잭션이 아니다.
- 앞서 성공한 공간 수정은 다음 수업 연결의 비교 기준에 반영한다. 자신이 저장한 연결로 두 수업이 같은 공식 학급에 묶인 경우 해당 학생 겹침 진단 해소만 인정한다. 새 진단 또는 설명할 수 없는 진단 변화는 중지·재확인한다.
- 최초 오류에서 다음 쓰기를 멈춘다. 완료된 접수증은 유지하고 재개 시 다시 보내지 않는다. 중지 버튼은 현재 요청 결과를 확인한 뒤 다음 항목을 멈춘다.
- 쓰기 전 현재 탭의 기억장소에 원래 명령과 요청 번호를 보관한다. 응답 유실·잘못된 접수증은 성공으로 추정하지 않는다. 기존 키와 명령으로 `p_recover_only=true`만 호출한다.
- 복구 성공 후에도 나머지 항목은 자동 저장하지 않고 다시 확인받는다. 원장 NOT_FOUND 뒤 재개도 원래 키를 쓴다. 늦은 최초 요청으로 충돌할 수 있으면 결과 미상으로 돌아간다.
- 계정·학교·소속 범위 변경이나 화면 종료 중 늦은 응답을 새 화면에 반영하지 않는다. 조회 대기 중 화면을 떠나면 쓰기를 시작하지 않는다.
- 조회 장애 뒤에도 입력을 버리지 않고 **준비 입력 자료 다시 확인**으로 재연결할 수 있다. 결과 미상 요청은 최신 목록 조회가 실패해도 복구할 수 있다.
- 개별 공간·수업 편집, 시수·일과 편집, 일괄 입력은 서로 잠금을 공유한다. 보관 작업이 있으면 실제 시간표 메뉴 재진입 시 해당 영역을 연다.
- 보관은 현재 탭 메모리다. 새로고침·브라우저 종료 뒤의 영속 복원을 보장하지 않는다. 편집 파일·결과 파일을 내려받아 보관할 수 있다.

## 점검표

공식 서버 진단의 심각도는 유지한다. 학생 집단 연결 수와 실제 사용하는 공간의 정원 입력 수를 별도로 표시한다. 이것을 전체 시간표 완성률로 표시하지 않는다. 편성 제외 수업이나 사용하지 않는 빈 공간을 완료율의 분모로 섞지 않는다. 삭제된 참조는 누락시키지 않는다.

수업 연결·공간 정원·공식 자료로 분류하고 20건씩 표시한다. 이름이 같은 대상은 ID로 구별한다. 점검 바로가기는 정확한 편집 영역에 키보드 초점을 옮긴다. 공식 담당 변경·학기 중 종료 등의 진단을 임의 연결 수정으로 해결했다고 표시하지 않는다.

## 자동 검증

최종 실행 결과는 PR 설명과 이 절에 함께 기록한다. React/전송 어댑터/파일 codec은 제품 코드이며 RPC·저장 원장은 합성이다.

- 신규 단위·회귀: 공간/연결 엑셀 77, 순차 저장 45, 준비 점검 17, 시수 엑셀 92, 시수/활동 점검·React SSR 27건.
- 브라우저: **7개 파일 91개 시나리오 전부 통과**. setup 27 + setup-batch 13 + preparation 8 + preparation-editing 10 + connected 10 + preparation-hours 14 + preparation-hours-connected 9.
- XLSX 내려받기→재가져오기, 107개 수업 검색·선택, 잘못된 파일, 부분 성공, 같은 요청 복구, NOT_FOUND 재개, 조회 장애 재연결, 탭 재진입, 시수·일과 보존, 320px·200% 글자 확대 포함.
- `npm test`: **4,034건 전부 통과**, Python 생략 없음. 직전 3,915건에 시수 보강 119건을 추가했다. #69 누적 신규 단위 회귀는 258건이다.
- `npm run check:workhub`, 운영 앱/업무실 빌드, 시간표 보호 검사, 변경 파일 `git diff --check`: 통과.
- 전체 회귀 중 기존 HWPX HTTP 크기 시험의 Windows 연결 경쟁을 발견했다. 100회 중 15회 `WinError 10053`을 재현했다. 시험만 길이 헤더로 본문 전 413 거절과 실제 검사 함수 미호출을 확인하도록 바꿨다. 수정 후 같은 100회 모두 통과했다. 서버 코드·한도·인증 로직은 변경하지 않았다.
- 실제 Supabase/PostgREST/Storage/Claude 호출, Microsoft Excel의 실제 파일 편집, 실제 학교 규모 운영 성능은 이번 시험 범위에 포함하지 않는다.

## 남은 일과 판단해서 정한 것

1. Claude의 앱 검토와 T1/T2 SQL 진행을 기다린다. 이번 변경을 위한 추가 SQL은 요청하지 않는다.
2. 기존 R1S 및 P1~P8, T1 설치·승인·활성화 순서는 Claude 실행안내와 사용자의 별도 적용 절차를 따른다. 이 브랜치는 실행하지 않는다.
3. 앱 배포와 T1 연결 후 실제 계정으로 내려받기·수정·저장·조회·준비 원본 채택을 확인한다. 실사용 시험은 사용자 요청대로 모아서 한다.
4. T2 확정·교환·일정 왕복, 실제 Claude 도움 연결 및 비용 결정, 실제 학교 자료의 계산 품질 검증이 남아 있다.
5. 한꺼번에 실패를 되돌리는 새 SQL 대신 기존 항목별 접수 계약을 재사용했다. 부분 성공을 숨기지 않고 결과를 내보내는 방식이다. 일괄 추가·삭제나 공식 배정 자동 추정은 넣지 않았다.

되돌릴 때는 이 후속 PR의 앱·시험·문서를 되돌린다. DB 변경은 없다. 인증·비용·superadmin 공개 범위·Claude SQL 브랜치도 변경하지 않았다.
