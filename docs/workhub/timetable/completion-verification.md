## 구현 중 찾아 고친 문제

1. 초기 준비의 추가 전 교시 이름/시각이 연결 복구 후 사라지는 문제.
2. 기준판 확정 결과 복구 시 원래 교사/시간/수업 원본 비교가 부족한 문제.
3. 공식 원본이 바뀌었을 때 서버에 저장한 옛 초안을 자동 초기화하는 문제.
4. 긴 XLSX 원본 대조 문자열을 UTF-16 중간에서 잘라 이모지를 손상하는 문제.
5. 잘못된 새 파일을 선택해도 이전 파일의 가져오기 확인이 남는 문제.
6. AI 요청의 긴 식별자로 기존 4,000자 한도를 넘는 문제. 검증 가능한 별칭으로 축약하고 한도를 유지했다.
7. 비동기 지문 검사 사이 기준판이 바뀌었는데 이전 AI 제안이 남을 수 있는 문제.
8. 시간표의 고정 밝은 색상이 차콜 스킨에서 읽기 어려운 문제.
9. 최초 Vercel 미리보기에서 `fflate`를 찾지 못한 문제. 배포 앱의 업무실 패키지 의존성을 명시하고 잠금 파일을 갱신했다. 깨끗한 배포 앱 단독 설치에서 수정 전 누락을 재현하고 수정 후 실제 빌드를 확인했다. 같은 설치 범위를 CI에도 추가했다.

## 실제 환경에서 남은 확인

- 시간표 RPC SQL은 아직 작성·설치하지 않았다. PostgreSQL에서 시간표 신규 계약을 시험했다고 주장하지 않는다.
- 기존 1~8단계 SQL 기준과 원문은 #64 상태 그대로다. 이번 로컬 작업에서 SQL 전체 회귀를 다시 실행하지 않았다. 현재 SQL 대조의 앱 import 진입점 13개를 실제 번들해 조사했으며 신규 `packages/timetable` 의존이 없어 기존 SQL 사본 실행 범위를 바꿀 필요는 없었다.
- 실제 Supabase 권한·잠금·동시 요청·교환 원장·날짜별 게시와 알림, PostgREST 왕복.
- 실제 Claude 연결·비용 설정·제공자 실패. 모의 답변만으로 추천 품질을 확정하지 않는다.
- 교사 PC의 Microsoft Excel 편집·다시 저장, 인쇄. 자동 시험은 XLSX 바이트와 표준 공유 문자열을 읽고 쓰는 경로다.
- 계산 서버 배포/취소/진행 조회, 큰 학기 manifest와 학사 변경의 실제 SQL·잠금·원장·운영 반영. 두 흐름의 앱 실행·복구는 위 후속 검증에서 확인했다.

새 RPC가 없으면 준비 중으로 표시한다. 합성 학교나 연습 자료를 실제 학교 자료처럼 저장하거나 보여 주지 않는다. 코드 검토, SQL 적용, 관리자 활성화, 교사 공개는 별도 단계다.
