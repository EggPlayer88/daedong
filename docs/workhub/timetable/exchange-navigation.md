# 교환 요청 정확한 연결과 진행 안내

2026-10-19 · Codex · DB 적용 없는 앱 보완

## 교사가 보는 흐름

새 요청에서는 후보를 비교하고 변경 전후를 확인한 뒤 본인 동의와 요청을 보낸다. 요청별로 접수, 관련 교사 동의, 담당자 승인, 시간표 반영을 구분해서 보여 준다. 동의한 사람 수와 응답 대기 수를 별도 표시하며, 동의 완료를 실제 수업 변경으로 설명하지 않는다. 추천 후보가 없으면 조회 기간·공식 허용 시간 확인과 직접 상대 선택을 안내한다.

## 알림에서 정확한 요청 열기

`TimetableExchangePanel`은 다음 표시 전용 props를 받는다.

```ts
requestSelection?: { requestId: string; token: number }
onRequestSelectionConsumed?: () => void
```

- 서버에서 현재 권한으로 조회한 목록의 **동일한 ID**만 연다. 이름, 순번, 비슷한 ID로 대체하지 않는다.
- 검색·필터·첫 20건 밖의 요청도 따로 표시하고, 상세를 펼친 뒤 해당 카드에 키보드 초점을 옮긴다.
- 요청을 읽는 행위는 동의·승인 명령을 보내지 않는다. 새 요청 초안, 기존 응답 확인 체크, 원래 명령을 그대로 둔다. 다른 응답 확인 중 알림 요청을 열면 두 요청을 별도로 표시한다.
- 로딩·저장·결과 미상 잠금 중에는 알림 소비를 미룬다. 최신 목록과 잠금 상태를 확인한 뒤 처리한다.
- 해당 ID가 현재 조회 기간·권한에 없으면 그 사실과 조회 기간/학교 확인 방법만 안내한다. 자동 기간 추정, 다른 요청 선택, 새 RPC 생성은 하지 않는다.
- 같은 토큰을 다시 전달해도 재처리하지 않는다. 같은 요청을 다시 누르면 새 토큰을 전달한다.
- 배경 재조회 때문에 사용자의 입력 초점을 계속 빼앗지 않는다. 사라진 요청의 카드·동의 확인은 숨기고 새 요청 초안은 보존한다.
- 표시 닫기는 화면상 고정만 해제한다. 서버 요청을 취소하거나 읽음·동의 상태를 바꾸지 않는다.

## 기한과 실제 상태의 경계

응답 권한이 없는 대기 요청도 타이머로 응답 기한 경과를 알린다. 서버가 아직 `awaiting_consent` 또는 `awaiting_approval`을 반환했더라도 화면은 기한 지남을 표시하고 새 응답을 막는다. 이 표시는 서버 요청을 `expired`로 직접 쓰지 않는다. 최종 상태는 최신 서버 조회로 확인한다. 이미 적용된 요청은 응답 기한이 지나도 반영 완료 이력으로 표시한다.

## 검증

- `tests/test_workhub_timetable_exchange_navigation.mjs`: 8건. 정확한 ID, ID 검색, 단계·동의 집계, 만료/종료 상태 불변.
- `tests/browser/workhub-timetable-exchange-navigation.mjs`: 11건. 실제 React 패널, 합성 서버/명령 응답. 검색·20건 밖 ID, 누락 ID, 기존 확인과 초안 보존, 로딩·잠금, 중복 토큰, 요청 소실, 만료, 빈 추천, 320px·큰 글씨·200% CSS 확대·키보드.
- 기존 `workhub-timetable-exchanges.mjs`와 `workhub-timetable-exchange-inbox.mjs`는 실제 앱 어댑터+합성 RPC로 교환·승인·원키 복구를 재검증한다.
- 새 브라우저 시험 최초 실행에서 완료 요청이 첫 페이지에 있다고 가정한 검사 1건을 수정했다. 완료 필터로 실제 요청이 나타난 뒤 검사하며 제품 동작을 느슨하게 바꾸지 않았다.

추가 연결 회귀:

- `tests/test_workhub_timetable_notification_source.mjs`: 6건. `NotificationSource.module='timetable'`의 원본 ID 형식, 필드, 학교·소속, 기존 출처 호환을 실제 메시지 parser로 검증한다.
- `tests/browser/workhub-timetable-notification.mjs`: 3건. 실제 ConnectedWorkspace·MessagingWorkspace·메시지 어댑터·TimetableWorkspace·운영 어댑터·교환 패널을 연결한다. 알림 ID와 교환 요청 ID를 다르게 두고 첫 20건 밖의 정확한 요청을 연다. 없는 요청은 대체하지 않으며, 메시지 복귀와 접힌 메시지 초안 보존·320px 키보드 이동을 확인한다. 읽음·동의·승인 쓰기 호출은 0이다. SQL 응답은 합성이다.
- 연결 셸의 초점 검사는 실제 ShadowRoot의 activeElement를 대상으로 한다. 문서 전체 activeElement를 사용한 최초 시험 가정은 정정했다.

T2 SQL의 알림 출처는 `{module:'timetable', id:<교환 요청 ID>}`로 보내야 한다. 알림 자체 ID, 수업 ID, 기준판 ID는 이 연결의 원본으로 쓰지 않는다. 날짜는 알림 출처에 없으므로 현재 조회 기간에서 원본을 찾지 못하면 기간 확인을 안내하고 임의로 날짜를 추정하지 않는다.

운영 Supabase 왕복, T2 SQL의 권한·동의·승인 원자성, 실제 알림 생성/전달은 이 화면 시험으로 증명하지 않는다. SQL/활성화는 Claude 작업과 사용자 승인 후 별도로 확인한다.
