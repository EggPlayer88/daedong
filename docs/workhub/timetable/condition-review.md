# AI 조건 검토와 부분 배치 계산 보완

PR #65의 Claude 검토에 따른 앱 보완이다. SQL·인증·비용·모델·메뉴 공개 범위는 바꾸지 않는다.

## 조건의 미리보기와 실제 반영

- AI 선호 제안과 일괄 조건은 `condition-policy.ts`의 동일 규칙을 쓴다. 같은 수업·시간의 기존 벌점과 제안 벌점 중 큰 값을 사용한다. 예를 들어 기존 8, AI 제안 3이면 8을 유지한다. 강도를 낮추려면 담당자가 조건 편집에서 직접 수정해야 한다.
- AI 카드에는 제안값과 `기존 → 반영` 값을 함께 표시한다. 같은 응답에 같은 수업·시간의 제안이 여러 개 있어도 뒤의 작은 값으로 앞의 큰 값을 낮추지 않는다.
- AI 카드가 보여 주는 반영 결과와 실제 적용은 `previewTimetableAiProposal`을 공통으로 쓴다. 실제 적용 시에는 원래 컨텍스트 지문을 최신 기초판·조건·배치와 다시 대조하고 사람의 확인 여부를 검사한다.
- 고정·불가를 추가한 결과는 `reviewTimetablePreflight`로 미리 검사한다. 고정 수업 중첩, 배치 가능한 시간 없음, 시수 수용량 부족처럼 확실한 충돌을 반영 전에 보여 준다. 기초판의 필수조건을 지우거나 선호로 낮추지 않는다.
- 담당자는 충돌 안내를 포함한 명시 확인 후 작업 초안에 조건을 반영할 수 있다. 충돌이 남으면 계산·저장의 기존 검사가 막는다. 사전 검사가 조용하다고 해 존재나 최적성까지 보증하지 않는다.
- 기존 고정과 다른 시간으로 다시 고정하려는 응답처럼 조건 자체의 검증이 실패하면 적용 버튼을 열지 않는다.

## 동명 대상

AI 대상 목록과 일괄 조건 목록에서 이름이 같은 교사·학급·공간은 `이름 [안정 ID]`로 구분한다. 일괄 조건은 ID로도 검색할 수 있으며, 불가 조건 미리보기에도 같은 식별자를 표시한다. 선택·전송은 계속 원래 ID를 쓰고 이름으로 합치지 않는다.

## 부분 배치에서 최적화

현재 배치가 일부이거나 필수조건 검사를 통과하지 못했을 때:

1. 검증된 이전 완성판이 있으면 기존 `previous` 계약으로 비교한다.
2. 이전 완성판도 없으면 변경 최소화 비교를 사용할 수 없고 이미 놓은 수업도 옮겨질 수 있다는 경고를 보여 준다. 작업 고정은 유지한다.
3. `기존 배치와 변경 비교 없이 계산하는 것을 확인했습니다`를 선택하기 전에는 파일 계산 요청과 PC 계산 요청을 만들지 않는다.
4. 기초판·조건·배치·범위·시간 한도·후보 수가 바뀌면 확인을 취소한다. 기존 요청·응답 미상 작업의 원래 번호 복구 경로는 바꾸지 않는다.

비교 기준이 없는 후보를 `처음 편성`으로 단정하지 않고 `기존 배치와 변경 비교 없음`으로 표시한다. 기존 `timetable.solve.v1`의 입력·응답 구조는 바꾸지 않았다.

## 회귀

- `tests/test_workhub_timetable_contracts.mjs`: 선호 유지·강화, 같은 응답 안의 중복 제안, 고정/불가 충돌 사전 안내와 원본 보존.
- `tests/test_workhub_timetable_condition_batch.mjs`: 기존 일괄 선호 및 필수조건 회귀.
- `tests/browser/workhub-timetable-assistant.mjs`: 실제 전후값, 동명 대상, 반영 전 충돌 표시, 명시 확인, 원키 복구와 늦은 응답.
- `tests/browser/workhub-timetable-condition-batch.mjs`: 동명 ID 선택/검색/미리보기와 기존 입력 보존.
- `tests/browser/workhub-timetable-engine-panel.mjs`: 부분 배치의 계산 보류·확인 초기화, 이전 완성판 비교 보존, 실제 Python 계산 파일 왕복.

AI 브라우저 응답은 합성이다. 실제 Claude 호출·Supabase 연결·학교 규모 편성 성능은 이 검사로 완료했다고 판단하지 않는다.
