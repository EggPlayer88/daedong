## 담당자가 사용하는 순서

1. 시간표의 **내 수업·편성 → 학교 편성 자료 준비 → 공간·수업 연결 관리**를 연다.
2. 학교 관리에서 가져온 공식 교사·학급·수업 목록과 학기를 확인한다. 이름을 보고 자동 짝짓지 않는다.
3. 교실·특별실 또는 공유 장비를 등록한다. **동시 수업 수는 학생 좌석 수가 아니라 동시에 진행 가능한 수업의 수**다. 모르면 비워 두어 초안으로 저장한다. 1로 추정하지 않는다.
4. 수업마다 공식 학급을 직접 선택하거나, 그 수업의 별도 수강집단으로 지정한다. 여러 공간을 선택하면 모두 함께 점유한다. 후보 공간 중 하나를 골라 쓰는 의미가 아니다.
5. 변경 전후를 확인하고 체크한 뒤 저장한다. 사용 중 공간은 바로 지우지 못한다. 다른 학기에서 사용하는 공간도 서버가 삭제를 거절한다.
6. 공간·연결 저장으로 공식 자료가 바뀌면, 기존 시수·일과·활동을 보관한다. 바뀐 교사·학급·공간과 제한 사항을 확인하고 **입력 보존하고 현재 자료 채택**을 누른다. 이후 준비 초안을 저장하거나 기준판을 다시 검사한다.
7. 기준판 생성은 학기 시간표의 공개와 별도다. 완성한 기준판으로 조건 정리·계산·조정을 진행한다.

## 연결한 서버 계약

공통 응답은 `contract: timetable.setup.v1`, `schoolId`, `memberId`, `data/error`의 기존 scoped RPC 형식이다.

| 함수 | 입력 | 결과 |
|---|---|---|
| `workhub_timetable_setup_get` | `p_member_id` | 학기/기준일, 공식 자료 판·지문, spaces/classes/courses/findings |
| `workhub_timetable_setup_execute` | `p_member_id`, `p_command`, `p_request_key`, `p_recover_only` | 원래 요청 번호·명령 종류·대상 ID·새 판·자료 지문 |

명령은 `space_save`, `space_remove`, `course_link` 세 가지다. 새 항목의 기대 판은 null, 기존 항목은 읽은 판을 보낸다. `sourceFingerprint`는 접수증에서 null일 수 있다. 저장 후 준비 원본을 다시 조회하며, 접수증만으로 완성 기준판을 추정하지 않는다.

한도는 `setup-policy.json`에 모았다. 공간 이름 100 Unicode code point, 동시 수업 수 null 또는 1~1,000, 한 수업의 학급 20개/공간 10개까지다. 학급과 별도 수강집단은 동시에 선택하지 않는다. 빈 연결은 미완성 입력으로 보존한다. 계약 검증기는 원문 공백·배열 순서를 변경하지 않아 복구 요청 해시가 달라지지 않는다. 화면은 최초 명령을 만들 때만 공간 이름 앞뒤 공백을 정리한다.

`findings.blocksConfirm=false`인 담당 교사/학급 누락도 실제 편성 검사에서는 준비 완료가 아니다. 공간 정원 누락, 남은 학기 중 교사 퇴직·배정 변경, 수강 중첩, 삭제된 참조 등은 서버 진단을 표시하고 기준판 생성 검사에 반영한다. 삭제된 학급·공간 참조는 숨기거나 자동 제거하지 않는다.

## 입력 보존과 충돌 처리

- 공간·연결 편집과 시수·일과 편집은 동시에 변경하지 않는다. 작성 중인 시수·일과를 먼저 저장하거나 정리한다.
- 모든 저장은 명시 미리보기와 확인 후 전송한다. 결과 미상은 입력과 원래 요청 번호·명령을 현재 탭 메모리에 유지한다.
- 재연결한 화면도 같은 요청을 `p_recover_only=true`로 조회한다. 최신 목록 조회가 실패해도 원래 접수증 복구를 시도할 수 있다. 접수증이 없다는 NOT_FOUND가 확정되기 전 새 명령을 만들지 않는다.
- 판 충돌은 원래 값/최신 값/내 입력을 비교한다. 기존 입력을 최신 판에 이어 편집할지 담당자가 선택하고 다시 확인한다.
- 준비 원본 갱신 시 일과/주당 시수/수업 활동 ID/시간대 순서를 자동 초기화하지 않는다. 같은 학교·학기, 같은 수업 목록, 유효한 시수, 같은 서버 초안 ID/판일 때만 명시 채택한다.
- 공식 수업 추가·삭제, 확정 시수 변경, 다른 학기, 다른 담당자의 초안 변경이면 그대로 채택하지 않는다. 보관한 입력을 보여 주고 재시작 또는 별도 확인이 필요하다고 알린다.
- 배경 조회 실패에는 이전 목록을 숨기고 입력을 보관한다. 다른 학교·계정·역할 범위에는 이전 초안을 노출하지 않는다. 브라우저 종료 후 영속 복원을 약속하지 않는다.

## 화면 구성과 검증

공간과 수업 목록은 각각 20개씩 나눈다. 수업·교사·ID 검색, 연결 필요 필터, 학급·공간 찾기를 제공한다. 동명이거나 같은 이름의 학급/공간도 식별값으로 구분한다. 검색·쪽 이동 중 편집 입력을 유지한다. 접근 가능한 레이블, 키보드 입력, 320px와 200% 확대를 브라우저 시험에 포함한다.

자동 검증 수치와 실행 결과는 이 문서의 아래 결과 절에 기록한다. 브라우저 시험은 실제 React와 실제 전송 어댑터, 합성 RPC를 사용한다. SQL 응답 대조는 이전 격리 PostgreSQL 17.6 시험에서 저장한 출력이다. 실제 Supabase/PostgREST 왕복이나 운영 활성화 성공으로 평가하지 않는다.
