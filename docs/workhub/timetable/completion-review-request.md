기존 #64 통합 작업과 구분하여 시간표 PR #65를 검토해 주세요. 브랜치는 `feat/workhub-timetable-completion`이며 #64 최종 `a7a6c86`을 merge commit `18247a1`로 가져왔고 #54·#56 이력과 후속 구현을 포함합니다. #3·#5·#44는 포함하지 않았습니다. 상속한 SQL 기준은 `5c05c2d`이며 SQL 원본이나 Claude SQL 브랜치를 별도로 수정하지 않았습니다.

먼저 `docs/workhub/timetable/completion.md`, `completion-finalization.md`, `completion-verification.md`를 읽어 주세요. 미완성·운영 미검증 범위를 별도로 적었습니다. 사용자는 2026-10-18에 Claude 검토를 기다리지 않고 구축을 진행하도록 요청했습니다. 이 문서는 후속 검토/SQL 작성 시의 인계 자료이며 이번 앱 구축을 멈추는 승인 요청이 아닙니다.

이번 편성 사용성 추가분은 `editor-usability.md`에 정리했습니다. 같은 PR #65에 포함했으며 추가 SQL 계약은 없습니다. 특히 `preparation-editing`의 명시 대체·기존 ID/허용 목록 보존, `preflight`의 확정 충돌과 미판정 구분, `adjustments`의 미배정/전체검증 분리·고정 보호·두 수업 원자 반영, `candidate-review`의 이전 판·실제 시각 비교를 검토해 주세요.

## 우선 검토

1. `preparation*`: 공식 교사/수강집단/시수와 시간표 준비 초안 구분, 미완성 저장과 기준판 확정 구분, 오래된 원본·권한 회수, 같은 번호 복구의 원본 비교.
2. `packages/timetable`: 실제 시각/연속 블록/공동교사/학생 중첩/자원 수용, 지원하지 않는 조건, 독립 검증, 이전 기준판 유지, 부분 고정, 최소 변경/최적성 설명의 정확한 범위.
3. `TimetableEnginePanel`/`LocalTimetableEngine`: requestId/hash/기준판이 다른 결과 거절, 변경 후 늦은 결과, 후보 비교·명시 채택. CP-SAT는 수동 CLI 파일 왕복과 담당자 PC의 작업 폴더 자동 왕복을 지원합니다. 공용 계산 서버를 배포한 것은 아닙니다.
4. `assistant-bridge`/패널: 기존 P6 계약·비용을 유지하는지, 별칭이 범위 밖 ID로 바뀌지 않는지, 기준 변경/결과 미상/원키 복구, 확인 전 자동 조건 변경이나 전송이 없는지.
5. XLSX: 미완성 배치 보존, 공식 자료 변경 거절, 조건 삭제 비교, 긴 원본/이모지/공유 문자열, 파일 손상·과도한 압축·수식·외부 연결.
6. 공유/교환: 안정된 학급 ID, 원본 회차 선택, 입력 중 다른 수업 선택, 추천 선택만으로 전송하지 않음, 전체 당사자 동의·담당자 승인·원키 복구.
7. 학기 전체 확정: manifest/page 전체 건수·해시·기간·쪽 간 중복의 전수 검증, 진행 중 취소·늦은 응답, 고정 참조 명령, 단일 접수증과 원키 조회 전용 복구. 조회 일부를 전체 완료로 표시하지 않는지 확인해 주세요.
8. 홈·일정: 날짜/계정 변경 시 옛 수업 숨김, 취소/실시 유지, 일반 일정 중복 생성 없음, 원본 수업 연결, 조회 실패가 기존 일정·업무를 막지 않는지.
9. 행사·휴업·특별일과: 대상 학급 전체와 실제 시각 전후 비교, 공동 수업의 일부만 취소하지 않음, 과거 수업 보존, 교환 동의·승인을 조용히 없애지 않음, 보강 필요 차시/분, 명시 확인 전 무전송.
10. 공통 운영 작업창: 학기 확정·학사 변경·기존 교환 간 단일 쓰기 잠금, 재진입/목록 실패에도 원키 복구, 미실행 확인은 입력 유지, 다른 초안 보존. 응답 미상은 신규 요청으로 자동 재실행하지 않습니다.

## SQL 요청

기존 SQL 1~8단계 완료 작업을 우선 마무리하고, 시간표는 별도 증분으로 작성해 주세요. 최종 SQL 작성과 실제 적용 역할은 그대로입니다.

- 편성 기본: `sql-handoff.md`와 현재 `server.ts`의 exact `timetable.v1` 계약.
- 학교 초기 편성: `preparation-api.md`, `preparation.ts`, `preparation-server.ts`의 `timetable.preparation.v1` 계약. 공식 원본은 승인된 P1/P5/P8 자료를 참조하고 기존 배정 행을 시간표 저장으로 수정하지 않습니다.
- 확정·교환: `operations-api.md`의 기존 `timetable-operations.v1` 계약.
- 참조·추천·학기 전체 목록: `operations-next-api.md`의 `timetable-operations.next.v1` 계약. 그 문서 4절의 구 `workhub_timetable_operations_school_day_preview`는 대체됐으며 T2 SQL 설치 대상이 아닙니다.
- 모든 신규 쓰기는 현재 학교/소속/담당 권한·판·기간·원본 지문을 서버에서 다시 검사하고 단일 트랜잭션/요청 원장/권한 있는 복구 경로를 구현해 주세요. 앱이 검사했으니 안전하다고 가정하지 않습니다.
- 전체 학기 실행은 `publication-execution-api.md`의 `timetable-publication.v1`, 학사 변경 미리보기·실행은 `school-day-execution-api.md`의 `timetable-school-day.v1`을 사용합니다. T2는 `workhub_timetable_school_day_preview`만 만들며 구 초안과 alias로 연결하지 않습니다. next.v1의 참조·추천·전체 목록 조회와 v1 소규모 확정 계약은 유지합니다. 새 계약의 command/receipt/원키 복구 응답을 먼저 앱 parser에 대조해 주세요.
- 추천은 후보 생성·검증과 설명을 구분합니다. Claude 설명을 충돌 검증 근거로 쓰지 않습니다. 실수업 변경과 승인·알림은 명시 승인 경로만 사용합니다.

먼저 실제 응답 JSON을 현재 앱 parser와 대조해 주세요. 코드 병합 가능, 비활성 SQL 설치 가능, 관리자 활성화 가능, 일반 교사 공개 가능을 각각 판정해 주세요. 운영 적용/자동 병합/일반 교사 공개를 이번 검토의 완료 처리로 실행하지 않습니다.

## 응답 형식

- 필수 결함: 재현 조건·파일/함수·자료 영향·권장 수정.
- 계약 누락: 필드·판·권한·원자성·복구의 차이.
- 사용성: 시범 전 필수와 이후 개선 구분.
- 검증: 합성/로컬 계산/실제 Supabase·Claude를 구분하고 실행하지 않은 항목을 표시.
