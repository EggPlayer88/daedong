# 9학급 시간표 운영 연습 자료와 교체 경계

이 자료는 대동여중의 **과거 1학기 시드 기반 운영 연습표**다. 실제 학교에서 확정해 사용한 시간표로 표시하지 않는다. 원본 백업과 확정 SQL은 수정하지 않았다.

- 원본: `backup/v1_timetables_data.csv` 첫 행, 이름 `2026학년도 1학기 (시드)`.
- 백업 SHA256: `d7014ef433c38dd0bdf2ad661a3c89f3fd49a17b7943c1c96f58d3507d34ec34`.
- 생성 근거: `origin/v1-final:migrations/002_seed_data.sql`. 원문에 가상 시간표·시뮬레이션/개발용이라고 명시돼 있으며 백업 JSON과 생성식을 대조해 완전히 일치함을 확인했다.
- 학급·과목 매핑 근거: 2학기 번호 변경 전 `b2d05ce:src/lib/timetableData.js`. 같은 `s14`도 당시 영어이고 최신 2학기 자산에서는 진로이므로 최신 자산과 혼용하지 않는다.
- 9학급: 1학년 1반부터 3학년 3반. 월·화·수·금 6교시, 목 7교시. 일반 수업 270개와 창체 9개, 총 279개다.

- 목7 창체는 서로 다른 가상 교사 9명을 임시 배정했다. 원본에 담임이 없으므로 실제 담임을 알아낸 것처럼 표시하지 않는다.
- 교실 9개, 교실당 동시 수업 수 1, 종소리, 표시 기간은 `pilot-data.json`에 모았다. 모두 연습 설정이다. 실제 공간 정원·공식 학기·학교 종소리가 아니다.
- 연습 날짜는 과거 시드의 2026-03-02~2026-08-15를 쓰고 첫 화면은 2026-03-09다. 오늘 날짜와 혼동하지 않도록 연습 기준일을 표시한다.

현재 로컬 조사 파일은 가입 회원 18명(관리자 1, 교사 17)이라는 집계만 포함한다. 구 2학기 정적 교사 22명은 현재 가입 명단과 일치한다고 확정할 근거가 없어 시드에 넣지 않았다. 실명·메일·auth UUID는 이 자산에 포함하지 않는다.

## 가상 교사와 가입 교사 연결 계획

`roster.ts`는 이름을 추측해서 맞추지 않는다. 서버가 조회한 후보 또는 관리자가 제공한 `id,schoolId,label,active` CSV에서 **후보 ID를 명시 선택**한다. 동명이인도 ID로 구별하며 정지된 교사, 다른 학교 후보, 알 수 없는 후보를 거부한다.

학교에 연결한 화면에서는 운영 연습 엔진의 `pilot-daedong` 기준과 실제 학교의 연결 계획 기준을 분리한다. 연결 계획용 fixture만 현재 로그인 학교 ID로 명시 복제하고 그 지문을 새로 계산한다. 실제 후보의 학교 ID를 가상 학교 ID로 덮어쓰지 않는다. 로그인 학교가 바뀌면 이전 학교의 후보·연결 계획을 폐기한다.

실제 후보 ID와 이름이 들어간 명단·연결 계획은 현재 탭 메모리에만 둔다. 운영 연습 엔진 저장본이나 저장소의 고정 자산에 섞지 않는다. CSV 연결은 관리자 제공 자료라는 출처이며, 이 CSV 자체가 실제 서버의 소속 승인 증명은 아니다.

교사 교체 절차:

1. 기존 기준 지문·명단 판·담당 판으로 미리보기.
2. 적용일, 교사별 전후 담당, 영향을 받는 주간 수업 수 확인.
3. 동일 실교사에 가상 역할 여러 개를 연결할 때 모든 시간표를 다시 검사. 시간 중복이 있으면 거부.
4. 기준·명단·판이 바뀌지 않았을 때만 새 담당 판 추가.
5. 적용일 전 판과 원래 요청 내용을 그대로 보존. 이전 날짜로 소급하지 않는다.
6. 같은 요청 번호의 완료 재조회는 원래 결과를 유지한다. 새 연결 계획은 새 요청 번호를 사용한다.

같은 미래 적용일의 교정도 이전 판을 덮어쓰지 않고 새 판으로 쌓는다. 시간표 기준판을 교체할 때는 `rebasePilotRoster`가 기존 담당을 새 배치에서도 검사하고, 교사 연결과 과거 원문은 보존한 채 새 기준 지문에 대한 판을 추가한다.

이 결과는 **서버에 교사 배정을 적용한 결과가 아니라 검증한 연결 계획**이다. auth 계정을 만들거나 교사를 대신해 동의·승인하지 않는다.

명단 CSV 내보내기는 적용일·역할·표시 이름·연결 상태만 포함하며 회원 ID, 이메일, 연락처는 제외한다. 이 파일은 공유용이며 다시 가져오는 회원 후보 CSV와 다르다. 수식 시작 문자를 문자로 처리한다.

## 실제 시간표로 교체할 준비

`timetable-replacement.ts`는 `lessonId,weekday,period,classId,subject,teacherRoleId,roomId` CSV를 제공한다. 요일은 월=1~금=5다. 현재 역할·교실·학급과 교시를 기준으로 파일을 읽으며 없는 자원을 추정해서 만들지 않는다.

- 같은 수업 ID로 여러 학급 행을 넣으면 합반으로 읽되 교사·요일·교시·과목·교실이 모두 같아야 한다.
- 9학급의 기존 279개 학급별 교시를 모두 채워야 한다. 빈칸을 휴강으로 추정하지 않는다. 다른 일과를 쓰려면 그 일과부터 명시 설정해야 한다.
- 실제 가입 교사 연결 계획이 있으면 역할 중복뿐 아니라 연결된 같은 실교사의 시간 중복도 다시 검사한다.
- 과목·교사·교실 변경을 칸별로 보여 주고, 원본 CSV 지문·이전 기준판 지문·적용일·미리보기 지문을 묶는다.
- 수업 ID만 바꾸는 입력은 기존 이력을 끊을 수 있어 별도로 거부한다.
- 운영 엔진은 미리보기 검증 후 적용일 이후의 새 기준판을 만든다. 과거 수업·기존 요청·이미 실시한 수업을 덮어쓰지 않는 처리는 운영 엔진에서 담당한다.

## 자동 검증 범위

- 백업 해시·279개 원본 과목 배치·충돌 제거·복제본 격리.
- 교사 연결의 학교·상태·명단 지문·판·적용일·재시도와 과거 판 보존.
- CSV의 누락·중복·미매핑·동시간 충돌, 조작된 미리보기, 잘못된 기간.
- 실제 React 화면에서 가상 교사 역할 전환·교환 동의·별도 담당자 승인·대강·휴강/보강·실시 기록·휴업·알림, CSV 연결 계획과 시간표 교체를 검사한다.
- 브라우저 저장과 보관 파일 복원은 현재 계정 범위의 해시와 검사값을 확인하며, 실교사 연결 계획은 포함하지 않는다. 손상된 파일은 현재 자료를 바꾸지 않고 거부한다.
- 320px 화면과 200% 글자 크기에서 화면 전체가 가로로 넘치지 않는지 확인한다. 교사 PC·모바일 기기의 실제 브라우저 확대와 인쇄 결과 확인을 대신하지는 않는다.
- 실제 Supabase 가입 명단 조회, 실제 운영 DB 배정과 배포 이후 사용 검증을 이 시험의 통과로 주장하지 않는다.
