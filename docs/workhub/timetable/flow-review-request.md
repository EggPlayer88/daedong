# Claude 검토 요청 — PR #70 시간표 흐름·대상 학기·U-1·U-2 통합

PR [#70](https://github.com/EggPlayer88/daedong/pull/70), 브랜치 `feat/workhub-timetable-flow-completion`의 최신 head를 검토해 주세요. 이전 5개 앱 묶음에 #71 대상 학기 선택과 U-1·U-2를 함께 추가했습니다. 별도 앱 PR로 나누지 않았습니다.

기준은 main #69 `aa7f195c6fd44ed8aed10e19af0bee5a00d8aadb`입니다. #71은 `339f063275688a55f5f2334b221948cf1f6f5159`의 `timetable.target.v1` 계약을 읽어 앱에 연결했습니다. Claude 브랜치·SQL 원문·인증·비용·superadmin 공개 범위는 수정하지 않았고, SQL 실행·모듈 활성화·병합도 하지 않았습니다.

## 이번 추가 3개 묶음

1. **대상 학기 선택**: 학교 공통 준비 대상, 자동 선택으로 복귀, 기준판 없는 다음 학기 준비, 변경 전 명시 확인. 편집·엑셀·조건·미전송 AI 질문·계산·결과 미상 중 전환을 막습니다. 외부 담당자가 학기를 바꾸면 자료를 다시 읽고 입력·기존 요청을 보존합니다. 준비 학기 선택으로 현재 공개 시간표와 날짜별 운영 조회 기간을 바꾸지 않습니다.
2. **U-1 준비 엑셀**: 기준일만 지난 파일은 실제 자료·학교·학기·판·지문·숨은 원본대조가 모두 같을 때 다시 비교할 수 있습니다. 현재 기준으로 재검사·재승인하며, 실제 자료 변경이나 미래/학기 밖/변조 파일은 계속 막습니다.
3. **U-2 일괄 저장 충돌**: 최신 자료 → 처음/현재/내 입력 비교 → 항목별 명시 선택 → 별도 저장 확인으로 연결합니다. 완료 항목과 접수증은 재전송하지 않고, 확정 거절된 명령만 새 번호를 받습니다. 미전송 항목과 결과 미상/원장 없음의 기존 요청 번호는 보존합니다.

이전 5개 묶음도 같은 후보에 들어 있습니다: 조건 입력·검토, 생성 동선·Claude 도움, 후보 보관·비교, 접수증 기반 저장→확정 연결, 공개·교환·학사 변경의 요약·검색.

## 중점 재검토

- #71 get/set의 exact 필드, 학교/소속 봉투, `termId:null`, `expectedVersion`, 목록 밖 선택과 원키 복구가 SQL과 맞는지. 과거 접수증의 effectiveTermId만 믿지 않고 현재 선택을 다시 읽는지.
- 대상 선택의 결과 미상과 원장 없음(`NOT_FOUND`)을 확정 미접수로 단정하지 않는지. 원래 명령/번호 복구와 명시 재전송에서 늦은 최초 요청과 겹쳐도 새 번호를 만들지 않는지.
- 학기 선택 도중 다른 작업 입력이 사라지거나 다른 학기의 공간·시수·조건으로 섞이지 않는지. 학교 공통 변경·뒤로 복귀·같은 학기로 돌아온 새 판까지 확인해 주세요.
- 새 저장 전 조회는 앱의 사전 검사일 뿐입니다. 그 직후 학기가 바뀌는 최종 동시성은 T1의 학교 잠금·학기/원본 제약으로 거절되는지 SQL 측에서도 확인해 주세요. 원래 접수된 요청은 현재 대상 학기를 요구하지 않고 복구해야 합니다.
- 구 T1처럼 target RPC가 없을 때 기존 준비 조회·저장이 유지되는지. 공통 연결에서 함수 부재가 QUERY_FAILED로 정규화될 수 있으므로 앱이 오류 원인을 과도하게 단정하지 않는지. 한 번 대상을 확인한 이후 연결이 실패하면 새로운 쓰기는 막고 원키 복구는 유지하는지.
- U-1에서 날짜만 예외 처리하고 배정·수강·공간 정원·연결·기준판·지문 등의 실제 변경은 거절하는지. 자정 전에 승인한 미리보기가 자동 승계되지 않는지.
- U-2에서 완료 항목·접수증 보존, 확정 충돌만 키 교체, 원장 없음/결과 미상 재계획 금지, 최신 자료가 다시 바뀌면 재충돌, 학기/소속 변경 차단이 맞는지.
- 320px·200% 확대·키보드 동선, 조건/AI 입력/계산/확정/공개/교환의 기존 회귀를 확인해 주세요.
