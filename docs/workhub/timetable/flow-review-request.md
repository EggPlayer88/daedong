## 중점 검토

- 조건 필터/쪽 이동 뒤 삭제가 원본 행을 정확히 가리키는지. 학교 필수 조건 보호, 강한 선호 보존, 미리보기 sourceKey/조건 재검증이 유지되는지.
- AI 바로가기가 기존 질문·답변·작업 단계·결과 미상 요청을 바꾸거나 유료 요청을 자동 실행하지 않는지.
- 후보의 학교·학기·기초판·지문·조건·배치가 독립 검증되는지. 바뀐 조건·부분 배치·손상 후보·한도 초과가 차단되는지. 채택 시 부모의 작업 고정 검사 실패를 성공으로 표시하지 않는지.
- 계산/저장 중 응답 유실과 늦은 응답에서 입력·기존 요청 번호를 보존하는지. 다른 입력을 이전 저장 접수증과 연결하지 않는지.
- 확정 연결의 ID·판이 최신 서버 목록과 정확히 맞는지. 기존 확정/교환/학사 변경 입력과 pending이 우선인지. 연결 의도는 한 번 소비하고 일반 재진입에서 옛 초안을 재선택하지 않는지.
- 운영 목록 검색이 표시만 줄이고 원본 전체 검증·동의·승인 명령을 줄이지 않는지. 전체 명세와 현재 페이지의 검색 범위를 구분하는지.
- 320px·글자 확대·키보드, 기존 내 시간표/일정 연결과 승인/원키 복구에서 회귀가 없는지.

## SQL/T1/T2와의 관계

이번에 새로운 RPC·SQL 필드·권한을 요구하지 않습니다. T1 준비 계약은 #68·#69와 동일합니다. T2는 기존 공개·교환·학사 변경 계약을 기준으로 계속 작성해 주세요. 앱 화면의 로컬 편의 한도를 SQL 학교 규모 한도로 옮기지 말아 주세요.
