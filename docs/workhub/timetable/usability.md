# 시간표 사용성·사이트 연결 보완

2026-10-18. 기준은 PR #65 `f16c70ea696d0b7bb3e5fef6fdc844f2447d1ab3`다. Claude가 검토·SQL 작성에 사용하는 이 기준을 바꾸지 않고 `feat/workhub-timetable-usability`에 후속 변경을 한 묶음으로 쌓았다. SQL·RPC 응답 계약·계산 알고리즘·인증·비용·공개 범위는 변경하지 않는다.

## 교사가 보는 변화

| 작업 | 보완한 동작 |
|---|---|
| 교사·학급 시간표 찾기 | 이름 검색으로 선택 목록을 줄인다. 동명 대상은 식별 번호로 구분하며 검색 결과에서 벗어난 선택도 유지한다. 내 시간표로 한 번에 돌아간다. |
| 확정 수업 확인 | 불러온 기간을 표시하고, 조회 밖 날짜·찾지 못한 교사나 수업을 공강·취소로 단정하지 않는다. 키보드로 상세를 열고 Esc로 닫은 뒤 원래 수업에 초점을 돌린다. |
| 편성 준비 | 기초판·반영 조건·배치 검사·서버 저장을 구분해 보여 준다. 이전 단계로 이동하고 제목에 초점을 두며 미추가 조건과 초안을 유지한다. 단일조건 대상 검색 및 추가 전 확인을 지원한다. |
| 교환 요청 처리 | 내 동의 / 내 승인 / 내가 보낸 요청을 건수와 필터로 구분한다. 교사·수업·학급·사유를 검색하고 현재 내가 응답할 요청을 먼저 보여 준다. 완료·응답 대기 요청의 긴 상세는 접는다. |
| 응답 확인 | 검색·필터·목록 표시 개수를 바꿔도 확인 중인 요청은 별도로 유지한다. 만료된 요청은 응답할 건수에서 빼되 실제 상태는 서버 응답을 유지한다. |
| 홈·일정 연결 | 수업을 열었던 홈·학교 일정으로 돌아간다. 일정보기·선택 날짜·검색·관련 필터는 현재 탭의 같은 소속에서 유지한다. 작성 또는 결과 확인 중에는 돌아가기도 기존 이동 잠금을 따른다. |
| 사용 안내 | 교사용 조회·교환과 담당자용 편성을 각각 세 단계로 설명하고 기존 시간표 메뉴로 연결한다. 도움말만 읽어서는 서버 조회·AI 호출·쓰기를 하지 않는다. |

## 유지한 기준과 판단

- 검색과 목록 건수는 **현재 서버가 반환한 조회 범위**에 한정한다. 학교 전체 명부·모든 기간을 이미 검색했다고 안내하지 않는다.
- 대상 이름으로 식별자를 새로 만들거나 같은 이름을 합치지 않는다. 학급 정보의 기준판·조회 기간 검사는 기존 그대로다.
- 수업 시각에 초가 있으면 보드와 상세에 보존한다. 행 정렬은 표시 문자열 대신 초까지 포함한 실제 시각을 사용한다. 같은 수업을 다시 누른 뒤 배경 재조회가 검색 초점을 빼앗지 않는다.
- 수업 상세·필터를 보는 것만으로 새 교환 요청을 만들지 않는다. 요청·동의·승인은 기존 미리보기와 명시 확인을 거친다.
- 일정보기 상태는 현재 탭 메모리이며 미저장 입력으로 세지 않는다. 브라우저 종료 후 복원하지 않고, 학교·계정·권한 범위 변경 때 기존 메모리 격리를 따른다. 다른 메뉴를 거쳐 시간표에 다시 들어오면 이전 수업 연결 의도를 재사용하지 않는다.
- 기존 요청 번호, 판·지문 검사, 응답 미상 복구와 저장/이동 잠금은 유지한다. 검색을 바꿨다는 이유로 확인 중인 응답을 초기화하지 않는다.
- 교환 진행 안내는 서버 상태·현재 actions·기한에 근거한다. 최종 시간표 반영과 단순 동의를 구분한다.
- 신규 SQL, DB 적용, 서버 환경 설정, AI 비용 설정, 일반 교사 공개, main 병합은 하지 않았다. 되돌릴 때는 이 후속 PR의 화면·helper·시험·도움말 변경만 되돌리며 PR #65 계약과 SQL에는 손댈 필요가 없다.

## 남은 연결과 Claude 검토

1. PR #65의 준비·기초판·편성 저장·학기 확정·날짜별 변경·추천·교환 SQL을 Claude가 완성하고 실제 응답을 현재 앱 parser와 대조한다. 이 후속 보완 때문에 바뀌는 RPC 계약은 없다.
2. 현재 판·기한·당사자 동의·담당자 권한·중복 요청·자원 경합·원자 반영·알림을 SQL 통합 시험으로 확인한다.
3. DB 적용은 사용자와 Claude가 진행한다. 이후 배포 환경에서 Supabase 왕복, 실제 학교 자료와 달력 연동, 교사 PC의 Excel·인쇄 및 여러 계정의 동의/승인 흐름을 모아서 확인한다.
4. Claude의 시간표 조건 상담·피드백·운영 도움 실제 연결은 기존 비용·설정 승인 범위 안에서 별도로 검증한다. 화면의 추천이나 이번 도움말을 실제 AI 연결 완료로 평가하지 않는다.
5. 실제 학교 규모의 편성 품질·성능, 현재 지원 범위 밖인 대강·보강·다자 교환은 별도 남은 범위다. 이번 화면 보완을 전국 학교 모든 유형의 완성으로 환산하지 않는다.

Claude는 후속 diff에서 검색이 선택 식별자를 바꾸지 않는지, 응답 확인·원키 복구가 목록 필터와 독립인지, 홈·일정 왕복의 입력 잠금과 학교 격리, 조회/연습/검사/저장/반영 문구가 실제 상태와 같은지를 중점 확인하면 된다. 코드 병합과 SQL 설치·기능 활성화 판단은 각각 기록한다.
