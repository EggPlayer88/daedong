# 시간표 운영 앱 마무리 묶음

2026-10-19 · 기준 앱: #70 `f6fd1c2` · SQL 실행 없음

## 범위와 완료 기준

검토된 #70을 그대로 기준으로 후속 PR 하나에 운영 흐름을 모았다. 준비·조건·계산·조정은 기존 구현을 유지하고, 확정 이후 공유·요청·동의·승인·복구·실시 기록과 알림 연결을 보완한다. 이 문서의 완료는 앱 구현과 자동 검증의 완료다. 실제 T2 SQL, Supabase/Storage 왕복, 운영 배포 및 모듈 활성화 완료를 뜻하지 않는다.

- SQL·인증·메뉴 공개·비용 구조·외부 설정은 변경하지 않는다.
- 자동 병합·일반 교사 공개·자동 운영 작업을 추가하지 않는다.
- 기존 login/가입 자료, R0/R1/P1~P8/T1 SQL 원문과 확정 HWPX 엔진을 보존한다.

## 이번 구현

1. **확정과 학사 변경**: 적용 기간, 선택 초안 판, 표시한 일부와 전체 검증 상태를 구분한다. 검토 만료를 화면에 반영하고 동일 입력으로 재검토한다. 현재 조회 밖 날짜는 전송 전에 안내한다. 연결이 사라진 학급만 선택에서 빼고 날짜·사유·나머지 입력은 보존한다.
2. **교환과 승인**: 요청 접수→교사 동의→담당 승인→시간표 반영의 현재 단계를 표시한다. 남은 동의 수, 기한 경과, 후보 없음의 다음 행동을 보여준다. 합의와 승인을 실제 반영으로 표시하지 않는다.
3. **알림 연결**: `source:{module:'timetable',id:<exchange request id>}`를 읽고 정확한 요청만 연다. 필터·첫 20건 밖 요청도 별도 표시한다. 현재 조회에 없으면 없는 이유를 추측하거나 다른 요청을 대신 열지 않는다. 원래 메시지 메뉴로 돌아갈 수 있다. SQL 알림 생성은 별도다.
4. **결과 미상 복구**: 확정·교환·동의·승인·학사 변경의 원키/원문을 보존한다. NOT_FOUND를 미실행 확정으로 취급하지 않는다. 접수증을 다시 조회하거나 명시 확인 후 동일 번호/내용으로만 재전송한다. 재전송 허가는 1회 소비되고 새 조회 없이 반복 재전송하지 못한다. 새 번호·내용·학교/소속으로 바꾸지 못한다.
5. **실시 기록**: 공유 시간표에서 선택한 수업의 실시 완료/미실시/확인 필요와 정정 이력을 관리한다. 예정 수업과 실제 확인 기록은 별도다. 미래 수업을 완료로 추정하지 않으며, 수업 시각·담당 교사·학생 접근 권한을 자동 변경하지 않는다. 변경 판 충돌, 원키 복구, 조회 실패, 다중 페이지 정정 이력, 입력 잠금을 처리한다. 새 RPC는 Claude SQL 구현 대상이며 없으면 해당 패널만 준비 중이다.
6. **준비 화면 후속**: 학기 선택 NOT_FOUND도 최신 목록 재조회로 이어지고 내 선택은 보존한다. 통신 실패를 설치 누락으로 단정하지 않는다. 오류 화면 브라우저 검증은 알림 요소 존재 대신 실제 오류 상태 전이를 기다린다.

## 판단해서 정한 것

- **NOT_FOUND 후 요청을 버리지 않음**: 최초 요청이 아직 서버에 도착하지 않은 경우를 보존하기 위해서다. 늦은 요청을 차단하는 SQL 취소 장벽이 없는 한 안전한 포기 버튼을 만들 수 없다. 해당 판단은 운영 workspace와 세 execution server, SQL 복구 계약에서 함께 변경해야 한다.
- **대강·보강을 기존 교환으로 위장하지 않음**: 실제 담당·추가 시수·기록 접근 변경은 현재 이동/교환 계약과 다르다. 미실시와 확인 필요를 기록하는 앱까지 구현했고 자동 대강 배정 및 보강 시간표 생성은 별도 계약/정책 검토 후 진행한다.
- **실시 확인은 원수업과 분리**: 실시 완료 버튼 하나로 학사 시간표나 학생 권한까지 바꾸지 않는다. 새 기록 기능의 권한은 서버의 allowedOutcomes로 받는다. 서버 구현에서 기존 권한만으로 정할 수 없는 대리 기록 정책은 사용자 결정으로 남긴다.
- **검토된 #70 보존**: 후속 PR을 #70 브랜치 위에 쌓는다. #70이 먼저 main에 병합되면 후속 PR base를 main으로 바꾸고 차이를 다시 확인한다. rebase·force push·Claude 브랜치 수정은 하지 않는다.

## 진척도 해석

퍼센트는 전체 요구사항 대비 범위 기반의 추정치다. 테스트 건수를 기능 완성률로 환산하지 않는다. 실사용 후 피드백/향후 기능 추가는 분모에 넣지 않지만, 아직 없는 SQL·실제 서버 연결·필수 정책/비용 구현은 남은 구축으로 센다.

- 시간표 앱의 현재 확정된 준비→생성→검토→확정·교환 흐름: 약 95% (실제 SQL 대조에서 필요한 보정은 남음).
- 대강·보강, 실시 기록 서버, Claude 실연결까지 포함한 전체 시간표 구축: 약 85% (80~88% 범위).
- 사이트 전체 순수 구축: 약 83% (80~85% 범위). 직전 약 80%에서 시간표 운영 앱을 보강한 만큼만 증가시킨 추정이다.
- 운영 모듈 활성화율이나 일반 교사 공개율은 위 수치와 다르며 이번 작업에서 높이지 않았다.
