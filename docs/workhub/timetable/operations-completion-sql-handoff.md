# Claude 전달 — 시간표 운영 앱 묶음 후속 계약

2026-10-19. SQL은 이 PR에서 쓰거나 적용하지 않았다. T1/T1-07 원문, 인증, 비용, superadmin 공개 범위는 유지한다.

## 반드시 함께 검토할 세 가지

### 1. 같은 요청 복구/재전송

기존 RPC 인자 형태는 유지한다.

- `workhub_timetable_operations_execute(p_command,p_request_key,p_recover_only)`
- `workhub_timetable_publication_execute(p_command,p_request_key,p_recover_only)`
- `workhub_timetable_school_day_execute(p_command,p_request_key,p_recover_only)`

앱 `recover`는 true로 접수증을 조회한다. NOT_FOUND여도 요청 번호와 입력을 버리지 않는다. 그 조회를 한 원래 학교·소속·번호·내용에 한해서 사용자가 확인 후 `resend`로 false를 보낼 수 있다. 새로운 UUID를 만들지 않는다. 새 미리보기를 요구하거나 만료된 원키를 새 명령으로 바꾸지 않는다.

**서버 필수 조건**:

1. 학교/계정/소속과 request key의 동일 잠금 안에서 기존 접수증을 먼저 읽는다. hash 불일치는 IDEMPOTENCY_CONFLICT. 동일 실행은 원래 접수증 그대로 반환한다.
2. 기존 접수증이 있으면 현재 preview 만료·모듈 중지·목록 변경 때문에 새 명령처럼 거절하지 않는다. 조회 가능한 현재 신원/학교 보안 검사는 기존 계약대로 유지한다.
3. 원장이 없고 `p_recover_only=true`이면 쓰지 않고 NOT_FOUND. 이는 늦게 도착할 최초 요청이 없다는 보증이 아니다.
4. 원장이 없고 false이면 현재 권한·수업 판·참가 동의·미리보기 만료·시간 충돌을 모두 다시 검사한다. 만료된 미접수 명령을 새로 실행하면 안 된다.
5. 원래 요청과 재전송이 경합해도 1회만 실행한다. 기록/알림/시간표 반영을 한 트랜잭션에 묶는다. 원래 recordedAt·version·변경 ID 목록이 복구 때 바뀌면 안 된다.
6. NOT_FOUND 이후 재전송 오류도 앱은 원키를 유지한다. 미접수 명령을 안전하게 영구 포기하는 기능이 필요하면 원키 잠금 하의 취소 tombstone 및 접수증 계약을 먼저 제안한다. 앱에서 임의로 키를 지우지 않는다.

회귀: 최초 응답 유실→recover NOT_FOUND→최초 요청 늦은 반영→동일키 resend, 만료 후 기존 접수증 반환, 미접수 만료 명령 거부, 모듈 중지, 다른 소속, 같은 키 다른 명령, 거절 뒤 늦은 원요청 등.

### 2. 시간표 요청 알림

메시지 API의 notification source에 `{module:'timetable',id:'<교환/변경 요청 ID>'}`를 추가 수용한다. id는 수업 ID나 확정본 ID가 아니다. 화면은 해당 ID를 현재 운영 조회에서 정확히 찾아 연다. 조회 범위 밖/권한 변경으로 없으면 안내하고 다른 요청으로 대체하지 않는다.

SQL의 실제 알림 생성은 기존 승인 범위에 따라 T2에서 작성한다. 원요청의 교사 동의→담당 승인→실제 반영 상태 변화와 알림을 원자적으로 기록하고 중복하지 않는다. source만으로 수신 권한을 부여하지 않는다. 현재 UI는 조회 기간 밖 요청을 서버 단건 조회하지 않는다. 필요하면 후속 exact 단건 조회 계약을 제안한다.

### 3. 실시 기록

`execution-records-api.md`가 정확한 앱 계약이다. 예정 시간표와 별도이며 자동 완료/자동 대강/자동 보강/학생 권한 승격은 없다. 아직 SQL 미구현이다. 기존 담당 관계와 승인 권한으로 실제 기록 가능 여부를 계산하여 allowedOutcomes로 반환한다. 관리자 대리 입력 등 신규 권한이 필요한 경우 임의 적용하지 말고 정책 결정으로 남긴다.
