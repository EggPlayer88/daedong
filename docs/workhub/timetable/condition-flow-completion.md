# 시간표 조건 입력·검토 동선 보완

## 담당자가 보는 변화

- 기존 **여러 대상·요일에 조건 한 번에 추가**에서 `요일과 시각 직접 입력` 또는 `실제 시간표에서 여러 시간 선택`을 선택한다.
- 실제 시간 선택에서는 월 1교시·수 2교시처럼 서로 다른 시각을 한 번에 고른다. 교사·학급·공간 선택은 기존 대상 목록을 사용한다.
- 전체 요일 선택도 모든 쪽에 적용된다. 시간 목록은 요일별 20개씩 표시하고 이름·시각·차시·ID를 함께 제공한다.
- 필수 불가 또는 피하고 싶은 선호를 미리 보고, 영향·충돌 안내를 확인한 뒤 초안에 반영한다.
- 등록한 조건은 관련 교사·학급·수업 이름과 ID로 검색하고, 학교 기준자료/이번 초안 출처로 좁혀 볼 수 있다. 각 조건 목록은 20개씩 표시한다.
- 계산 전에 드러난 충돌을 선택하면 함께 확인할 고정·불가 조건만 모아 보여 준다. 학교 조건을 지우거나 충돌을 자동 완화하지 않는다. 관련 조건이 없다면 기초자료의 시수·허용 시간을 확인하도록 안내한다.

## 같은 계약 안에서 처리

새 RPC·SQL·조건 종류는 추가하지 않았다. 실제 시간 선택은 로컬 `ConditionSlotBatchAction`으로 받고 기존 `unavailable`/`preferences`로 변환한다. 작업 초안 저장·복구 계약은 그대로다.

- 같은 실제 시각의 시간대 ID를 여러 개 골라도 불가 조건을 중복 생성하지 않는다.
- 선호는 실제로 겹치는 허용 수업 시간에 한 번 적용한다. 공동 수업 중복 가산과 기존보다 약한 선호로 교체를 막는다.
- 학교의 고정·불가 조건은 원본 그대로 유지한다.
- 전체 기준판·현재 조건을 미리보기의 기준으로 묶고 반영 직전에 재계산한다. 조건·일과가 바뀌거나 미리보기가 변조되면 거부한다.
- 직접 시각 입력과 시간대 선택은 전환 중 보존하되, 반영은 현재 방식만 사용한다.
- 미반영 시간 선택은 기존 ConditionBatchState와 탭 메모리·편집 잠금을 사용한다. 브라우저 종료 이후 보관을 약속하지 않는다.
- 검색·쪽 이동 후 삭제는 화면 순번이 아니라 원래 조건 종류/배열 번호로 처리한다.
- 충돌 목록은 확실한 필요조건 위반의 관련 조건을 보여 주며, 한 행 삭제로 해결된다고 단정하지 않는다. 선호를 필수조건 충돌의 원인으로 표시하지 않는다.

## Claude 바로가기

`TimetableAssistantPanel`에 선택적 `openRequest: { stage: 'setup' | 'adjust', token: number }`를 추가했다. 부모 화면에서 조건 정리 또는 현재 배치 피드백을 열 때 사용한다.

- 패널을 펼치고 질문 입력에 초점을 옮길 뿐, readiness/ask를 자동 호출하지 않는다.
- 빈 입력이고 잠금이 없을 때만 단계를 바꾼다. 결과 피드백은 배치 검사를 통과한 때에만 선택한다.
- 질문·대상·미반영 제안·참고 답변·원키 요청이 있으면 이전 입력과 단계를 유지한다.
- 결과 미상 복구는 원래 요청 번호·명령으로만 진행한다.
- 같은 token으로 다시 렌더해도 요청을 반복 처리하지 않는다.
- SQL·인증·모델·비용·메뉴 공개 범위는 변경하지 않는다.

## 검증

- 조건 일괄 domain 21건, 조건 검토 domain/SSR 9건, 기초자료 기존 회귀 18건.
- 조건 일괄 기존 브라우저 9건, 시간대 선택·조건 검토 새 브라우저 8건.
- Claude 기존 13건과 바로가기 5건을 합쳐 브라우저 18건.
- 브라우저는 실제 React·도메인 코드와 합성 자료를 사용한다. 실제 Supabase·Claude 호출을 시험한 것이 아니다.

## 남은 연결 확인

전체 PR에서 타입·빌드·회귀 및 부모 화면 바로가기 연결을 함께 검증한다. T1 설치와 준비 화면 배포 후 실제 학교의 기준판을 읽어 조건 저장·원키 복구를 확인해야 한다. 조건 제안 AI는 기존 Claude 비서 준비·비용 승인 뒤 실제 왕복을 별도로 확인한다.
