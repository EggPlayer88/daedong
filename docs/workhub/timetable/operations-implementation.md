# 시간표 확정·공유·교환 화면 구축

기준: PR #54 `cb6775c` / 후속 브랜치 `feat/workhub-timetable-operations`.
SQL 적용 없이 앱의 운영 흐름과 전송 계약을 구축한다. 현재 Claude가 작업하는 PR #49~#55 및 7단계 SQL은 수정하지 않는다.

## 사용 순서

### 담당자: 시간표 확정

1. 기존 편성 화면에서 유효한 후보를 새 초안으로 저장한다.
2. **확정·공유·교환**으로 이동해 저장된 초안과 적용 기간을 선택한다.
3. 서버에 공개 영향 미리보기를 요청한다. 이 단계에는 실제 공개가 없다.
4. 날짜별 전후 수업, 관련 교사·학급·교실과 보존 조건을 확인한다. 해결하지 못한 충돌이나 기존 변경이 있으면 확정하지 않는다.
5. 확인한 내용으로만 확정 요청을 보낸다. 초안·기간·권한·기초 자료가 바뀌면 이전 확인을 재사용하지 않는다.
6. 성공 접수증을 받은 뒤 공개 목록과 날짜별 수업을 새로 읽는다. 응답을 잃으면 같은 요청의 결과만 조회한다.

적용 종료일은 사용자에게 포함 날짜로 설명하고, 서버 `until`은 다음 날의 배타적 경계다. 실제 날짜별 수업은 학교 시간대로 표시한다. 화면에서 종료일을 두 번 더하거나 UTC 날짜를 학교 날짜로 오인하지 않도록 시험한다.

### 교사: 공유된 시간표 확인

학교 계정과 현재 열람 권한으로 서버가 제공한 확정판과 날짜별 수업을 확인한다. 주간 후보와 공개된 시간표를 같은 목록에 섞지 않는다. 현재 화면은 열람 가능한 응답 안에서 교사·날짜로 좁혀 본다. 학급·교실 이름은 수업별로 표시한다. 이 화면의 공개는 학교 내부 공유이며, 익명 공개 URL이나 메신저 자동 전송을 뜻하지 않는다.

### 교사와 담당자: 수업 변경

1. 현재 자신이 요청할 수 있는 날짜별 수업을 고른다.
2. **다른 시간으로 이동** 또는 **두 수업 교환**을 선택한다. 이동은 서버가 허용한 시간만 선택한다.
3. 서버 미리보기에서 수업 전후와 관련 교사를 확인한다.
4. 명시적으로 확인한 변경안에 요청자 자신의 동의를 기록하고 다른 참여 교사에게 동의를 요청한다. 요청자만 관련된 이동은 담당자 승인 대기로 넘어간다. 읽음은 동의가 아니며 이 시점에 수업이 바뀌지 않는다.
5. 참여 교사가 동일한 변경안에 동의하거나 거절한다.
6. 모든 동의가 모이면 담당자가 검토한다. 요청 당사자인 담당자는 대리 승인자가 필요하다.
7. 승인과 반영을 하나의 서버 명령으로 처리하고, 성공 결과를 확인한 다음에 반영 완료로 표시한다.

요청 철회와 반려도 정확한 요청판·변경안 지문을 기준으로 처리한다. 이미 반영한 요청을 삭제해 원복하지 않는다. 원복은 이후 별도 변경 요청이다.

## 현재 구현과 서버 책임

| 경계 | 앱이 수행하는 일 | 서버 SQL이 보장할 일 |
|---|---|---|
| 화면/권한 | 현재 응답의 허용 행동만 표시, 이전 학교 자료 숨김 | 현재 JWT·소속·담당·본인 관계 재확인 |
| 미리보기 | 정확한 입력과 응답의 전후·참여자·기간 검사 | 최신 원본·점유·학사일정을 읽고 전체 영향 계산 |
| 확정 | 입력 변경·만료·차단 사유가 있으면 확인 불가 | 기초판·대상 수업·자원 잠금 뒤 재검증 |
| 교환 | 요청/동의/승인/반영 상태를 구분 | 당사자 전원 동의와 계정 단위 자기승인 차단 |
| 저장 | 같은 명령·요청 번호 보존, 결과 미상 복구 | 멱등 원장, 원자 커밋, 결과 조회 전용 처리 |
| 공유 | 공개 원장 응답 조회·검색 | 현재 권한별 결과 제한, 전후 수업·기록 보존 |
| 알림 | 화면에 확인된 반영 상태 표시 | 이력·알림 원장 동시 기록, 실제 전달 별도 처리 |

현재 앱 계약의 세부 필드·함수는 [운영 API 인계](operations-api.md)를 따른다. 기존 `timetable.v1`의 편성 조회/초안 저장은 유지하고, 별도 `timetable-operations.v1` 계약을 추가한다.

## 실패와 복구

- 새 조회 실패: 이전 공개 자료와 교환안을 숨기고 재조회 제공. 연결 실패를 ‘수업 없음’으로 바꾸지 않는다.
- 입력 변경: 이전 미리보기와 확인 체크를 무효로 한다.
- 늦은 미리보기: 더 최근의 조회·입력·범위와 맞지 않으면 버린다.
- 전송 결과 미상: 원래 명령과 요청 번호를 현재 탭 메모리에 유지한다. 새 번호로 자동 재전송하지 않는다.
- 결과 조회 실패: 현재 권한 오류가 원래 저장 실패를 증명하지 않으므로 요청 번호를 지우지 않는다.
- 원장 없음: 서버가 같은 키 잠금 아래 진행 중인 명령도 없음을 확인한 `NOT_FOUND`만 미접수로 정리한다.
- 학교·계정·승인 범위 변경: 이전 화면을 숨기고 새 범위로 전환한다. 다른 학교에서 원래 요청을 복구하지 않는다.
- 미전송 입력: 재조회 뒤 복구하거나 두 단계 확인으로 정리할 수 있다. 결과 미상인 요청에는 입력 폐기 버튼을 제공하지 않는다.

입력 보관은 현재 탭 메모리다. 브라우저 종료 후 복구나 서버 초안 자동 저장을 약속하지 않는다.

## 이번에 확장하지 않는 기능

대강·취소·보강·장기 변경 자동 처리, 다자 교환 작성 화면, 실제 Claude 호출은 후속이다. 기존 순수 도메인에 다자 교환 검사가 있어도 현재 두 수업 교환 화면이 다자 교환 작성까지 제공하는 것은 아니다. DB의 전체 충돌 검사·두 연결 경합·알림 전송·실제 Supabase 시험은 별도 증거가 필요하다.

기존 학교 전체 기초판 입력, 복합 선호 최적화, 후보 자동 비교도 이번 화면 작업만으로 완료되지 않는다.

## 판단해서 정한 것

- 미리보기와 최종 명령을 나눴다. 사람에게 보인 전후 영향이 바뀌면 다시 확인받기 위해서다. 계약을 바꾸려면 operations-contracts/server와 UI·회귀를 함께 바꾼다.
- 공개와 교환의 미확정 요청을 부모 화면에서 함께 관리한다. 처리 결과를 모르는 동안 다른 쓰기를 섞지 않기 위해서다. `timetableOperations` 복구 슬롯과 Workspace의 실행 경로가 관리 지점이다.
- 공유는 현재 학교 계정 안의 조회로 제한했다. 교사의 이름·수업 정보가 들어 있는 익명 공개 링크를 만들지 않기 위해서다. 공개 정책 확대는 별도 사용자 결정이 필요하다.
- 최초 작성 화면은 이동/두 수업 교환에 집중했다. 대강·보강의 추가 시수·담당 변경·보상 원장은 같은 작업으로 간주하지 않는다.

## 검증

최종 자동 시험과 화면 확인 결과는 작업 완료 시 [운영 화면 검증 기록](operations-verification.md)에 기록한다. 합성 서버 성공을 실제 운영 DB 연결 성공으로 보고하지 않는다.
