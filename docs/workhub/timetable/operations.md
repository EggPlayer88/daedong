# 시간표 운영 설계 — 편성부터 실제 수업 변경까지

> 2026-10-16 · 구현 재개 요구사항. SQL 실행 안내가 아니다. 사용자가 시간표 보류를 해제하여 앱·계산 로직 구축을 시작한다. 이미 검토 중인 전체 시범 PR #48과 SQL 1~7단계는 그대로 유지한다. 이 문서의 미래 운영 요구가 현재 서비스에서 동작한다는 뜻은 아니다. 구현·검증된 범위는 같은 폴더 README와 테스트 결과를 확인한다.

현재 구현은 주간 편성 기반에 확정·공유 및 이동/두 수업 교환의 작성·동의·승인 화면과 서버 전송 계약을 추가한 상태다. [운영 화면 구현](operations-implementation.md)과 [현재 API 계약](operations-api.md)을 참조한다. 아래의 실제 서버 잠금·원자 저장·실시·보강은 완성 운영 요구이며 SQL 적용은 하지 않았다. 충돌/미완성 초안의 서버 저장도 후속 요구다. 실제 공급자 호출과 날짜별 변경 DB가 연결됐다고 표시하지 않는다.

## 1. 교사에게 보이는 하나의 흐름

**내 시간표 → 바꿀 수업 선택 → 가능한 변경안 비교 → 관련 교사 확인 → 담당자 승인 → 모두에게 같은 결과 표시**가 교사의 기본 흐름이다. 담당자에게만 **기본자료 → 조건 → 생성 → 조정 → 확정**을 추가한다. 새 메뉴가 관리자용 설정 표로 시작하지 않도록 교사 조회와 편성 작업대를 구분한다.

| 화면 | 먼저 보여 줄 것 | 대표 행동 |
|---|---|---|
| 내 시간표 | 오늘 날짜, 내 다음 수업, 변경된 수업 | 수업 상세, 주간 보기, 변경 요청 |
| 학교 시간표 | 교사·학급·교실 선택, 확정판 갱신시각 | 필요한 시간표 검색, 인쇄 |
| 편성 작업대 | 현재 단계, 미해결 문제, 다음 행동 1개 | 조건 설정, 후보 생성, 후보 비교 |
| 변경 요청함 | 내가 응답할 일, 담당자가 승인할 일 | 전후 비교, 수락·거절, 반영 결과 확인 |

모바일은 하루 수업 목록이 기본이며 주간 표는 별도 보기로 제공한다. 화면에 교사 전체 시간표를 한꺼번에 펼치지 않는다. 색은 변경·주의를 보조하며 텍스트와 아이콘을 함께 쓴다. 드래그만으로 수행하는 동작을 만들지 않고 수업 선택 → 목적지 선택 버튼·키보드 경로를 제공한다. 실패 안내에는 문제가 있는 수업과 해결할 입력 위치를 연결한다.

AI는 같은 업무에 들어가는 편리한 입구다. AI가 없어도 모든 필수 업무를 양식·버튼으로 마칠 수 있어야 한다.

## 2. 역할과 공식 자료의 경계

| 역할 | 책임 | 경계 |
|---|---|---|
| 학교 관리자 | 학기·학급·교사·교과·시수·공식 수업 배정·일과·공간 확정 | 시간표 편의를 위해 승인된 시수를 몰래 변경하지 않음 |
| 시간표 담당자 | 확정 기준자료에 조건 추가, 생성·조정, 적용 기간 확인, 변경 최종 승인 | 개인 선호 편집으로 공식 불가시간을 완화하지 않음 |
| 일반 교사 | 확정표 조회, 본인 수업의 변경 요청, 참여 제안에 응답 | 타인 수업을 단독 변경하지 않음 |
| 지정 대리 승인자 | 담당자가 요청 당사자인 건 승인 | 위임된 학교·기간·범위 밖에는 권한 없음 |
| Claude | 누락 질문, 조건 초안, 변경안 설명 | 충돌·시수·권한·동의·최종 적용을 스스로 확정하지 않음 |

현재 앱 신규 모듈의 superadmin 제한을 유지한다. 역할 설계가 일반 교사 공개 승인이나 회원 역할 승격을 뜻하지 않는다.

학교 관리의 `SchoolAdminSnapshot`에는 현재 학기·학급·교과·소속·공식 담당이 있다. 수업 모듈의 `Course`에는 승인된 수업 관계가 있다. **주당 시수, 실제 교시 시각, 특별실, 수강 중첩 정보는 이 자료만으로 얻을 수 없다.** 빠진 값을 교사 수·과목명으로 추정하지 않는다. 기본자료 준비 화면에서 누락 항목과 관리할 위치를 안내한다.

행정학급과 실제 수업집단은 다르다. 교과 담당 배정과 특정 수업의 승인 담당 관계도 다르다. 시간표용 별도 교사 명부를 만들어 기존 소속과 이중 관리하지 않는다.

## 3. 네 종류의 자료를 분리한다

1. **기준자료판**: 학교·학기·교시·시수·담당·수강·공간을 검토한 불변 입력판.
2. **주간 후보**: 월요일 몇 교시에 어떤 수업을 놓을지 계산한 아직 공개되지 않은 안.
3. **확정 주간표**: 적용 기간을 갖는 승인된 반복표.
4. **날짜별 수업**: 휴업일·특별 일과·교환·대강을 적용한 특정 날짜의 실제 예정 수업.

예를 들어 ‘매주 화요일 3교시 수학’과 ‘10월 20일 수학을 10월 21일 2교시로 옮김’은 다른 자료다. 일회 변경이 다음 주 표를 바꾸지 않는다. 매주 바꾸는 변경은 새 주간표를 해당 적용일부터 확정한다.

엔진의 단위 번호는 편성 실행 내부 ID다. 날짜별 수업의 영구 ID로 쓰지 않는다. 교사·학생 기록은 안정된 `lesson_instance_id`와 당시 판에 연결한다. 수업을 이동해도 같은 수업의 정체성을 유지한다. 새 보강은 별도 ID로 만들되 원수업을 명시 참조한다.

### 시간과 기간

- 학교 시간대는 실제 설정한 IANA timezone을 사용한다.
- 날짜 효력은 `[from, until)`, 시각 점유도 `[start, end)`이다.
- 기존 학교 관리의 `lastDay`·수업의 `validThrough`는 종료일 포함이다. 어댑터에서 한 번만 exclusive 종료일로 변환한다.
- 같은 ‘3교시’여도 학년·학교 일과에 따라 실제 시간이 다를 수 있다. 충돌은 실제 시작·종료 시각으로 판단한다.
- 시각 구간의 끝과 다음 수업 시작이 같으면 중복 점유가 아니다. 이동 시간 조건이 있으면 별도 간격 검사를 수행한다.
- 지원하지 않는 순환주·분수 시수·캠퍼스 이동을 일반 5일 표로 손실 변환하지 않는다.

## 4. 기본자료 → 조건 → 생성

기준자료 확정 전에 수업별 필요 시수, 회차·연속 블록 합계, 담당 유효기간, 가용 수업 시간, 수강 중첩, 공간 용도·용량을 검사한다. 오류 0건만으로 학교 공식 정보 확인을 대체하지 않으며 관리자의 명시 확인을 받는다.

각 조건에는 대상, 필수/선호, 값, 유효기간, 출처, 확인 상태, 엔진 지원 상태가 필요하다. ‘수요일은 빼 주세요’처럼 기간·대상·필수 여부가 불명확한 입력은 질문으로 남긴다. 확정 출장 등 학교 공식 제약과 개인 희망을 구분한다.

`hard`와 `school_hard`는 모두 필수 검사에 포함한다. `school_hard`는 승인된 원본 절차를 통해서만 바뀐다. 미지원 필수조건은 실행을 막는다. 미지원 선호는 적용한 척하지 않고 이번 실행에서 제외할지 담당자가 확인하게 한다.

결과는 다음을 분리한다.

| 결과 | 표시 의미 | 다음 행동 |
|---|---|---|
| feasible | 필수 검사를 통과한 후보가 있음 | 후보 비교·조정 |
| optimal | 전체 입력에 대한 최적성 증명이 있음 | 증명 범위와 함께 표시 |
| infeasible | 전체 입력 불가능 증명이 있음 | 충돌 근거 확인·입력 검토 |
| unresolved | 제한 안에 결론을 얻지 못함 | 조건·한도 확인 후 재시도 |
| invalid_input / unsupported | 입력 오류 또는 기능 미지원 | 해당 항목 수정 |
| internal_error / cancelled | 실행 실패 또는 취소 | 입력 보존, 새 실행 여부 선택 |

시간초과는 불가능의 증거가 아니다. 후보 3개를 요청했더라도 1개만 검증됐다면 1개만 보여 준다. 서로 같은 안에 이름만 달아 선택지 수를 늘리지 않는다. 결과 저장에는 입력 지문·엔진/검증기 판·조건판·seed·실행 한도·종료 이유를 남긴다.

## 5. 후보 조정과 변경 비교

후보를 수정하면 이전 후보를 덮어쓰지 않고 새 파생 후보를 만든다. 이전안으로 되돌리는 행동도 새 후보 선택/파생으로 남긴다. 후보가 잘못되어도 초안은 보관할 수 있지만 확정하지 못한다.

수동 이동 전에 목적지와 예상 영향을 보여 준다. 적용 후 독립 검증을 다시 수행한다. 교사, 실제 참여집단, 교실, 시수, 연속 수업, 필수 불가시간을 같은 검사기로 확인한다. AI 제안도 이 경로를 사용한다.

후보 비교는 위치뿐 아니라 **교사·과목/수업·참여집단·공간·실제 시간·회차 구조**를 비교한다. 같은 칸에서 담당 교사가 바뀌어도 ‘변경 0’으로 표시하지 않는다. 시수·블록 구조가 달라진 경우 이전 단위 번호에 억지 연결하지 않고 구조 변경으로 설명한다.

고정한 수업의 원본 배정·회차가 달라지면 고정을 자동 재해석하지 않는다. 무효 고정 목록을 확인하고 해제 또는 새 회차 연결을 선택한다.

## 6. 확정과 교사 공유

확정 직전 서버가 기준자료·조건판·후보 지문·달력·자원 점유를 다시 검사한다. 사용자가 확인한 변경 영향과 현재 영향이 다르면 다시 확인해야 한다. 브라우저에서 ‘유효’였다는 이유만으로 저장하지 않는다.

미래 일정 일부를 새 표로 교체할 때 앞뒤 기간을 모두 보존한다. 예를 들어 기존 9월~12월 표에서 11월만 바꾸면 9~10월, 새 11월, 복원할 12월의 세 구간을 함께 검토한다. 뒤 기간이 조용히 사라지면 안 된다.

기존 미래 교환·대강·보강은 유지 가능/재검토 필요로 각각 분류한다. 실제 실시 기록과 학생 활동 참조는 보존한다. 미해결 영향이 있으면 전체 확정을 보류한다.

한 번의 확정으로 주간판, 날짜별 수업, 자원 점유, 감사·접수증·알림 원장이 같은 트랜잭션에서 바뀐다. 교사/학급/교실 시간표는 같은 날짜별 원장을 조회한다. 알림 전송 실패는 시간표 반영을 되돌리지 않으며 알림만 별도 재시도한다.

## 7. 확정 이후 변경 흐름

### 7.1 교사 경험

1. 내 날짜별 수업을 선택한다.
2. ‘수업 교환 / 다른 시간으로 이동 / 대강 요청 / 휴강·보강’을 구분한다.
3. 날짜·수업·변경 목적을 입력하거나 Claude와 정리한다.
4. 현재 자료로 계산한 가능한 안과 바뀌는 사람·수업·시간을 비교한다.
5. 정확한 변경안으로 동의를 요청한다.
6. 각 교사가 같은 변경안에 수락/거절한다.
7. 담당자가 최신 조건을 확인하고 승인과 반영을 한 번에 수행한다.
8. 관련 교사에게 실제 반영 결과와 바뀐 시간표 링크를 제공한다.

‘전송됨’, ‘읽음’, ‘동의함’, ‘반영됨’을 다른 상태로 표시한다. 무응답과 읽음은 동의가 아니다. 메신저 자유문에 ‘네’라고 답한 것만으로 동의를 기록하지 않는다.

### 7.2 변경 종류

| 종류 | 보존할 의미 |
|---|---|
| swap | 두 개 이상 수업의 배치가 순환 이동. 모든 수업·자원을 함께 검사 |
| move | 한 수업을 다른 시간으로 이동. 원래 빈칸/대체 활동 처리도 표시 |
| substitute | 수업과 학급은 유지하고 담당 변경. 대강 가능 관계 확인 |
| cancel | 예정 취소와 실제 미실시를 구분. 필요 보강량을 계산할 근거 보존 |
| makeup | 미실시 원수업을 참조하는 새 수업. 중복 충당 금지 |
| 장기 변경 | 특정 날짜부터 새 주간표 확정. 일회 변경을 무한 복제하지 않음 |
| 실시 정정 | 새 실시판과 보상 원장. 과거 이력을 UPDATE로 지우지 않음 |

초기 동의 정책은 ‘관련 교사 전원 + 담당자 최종 승인’을 권고한다. 학교 정책 확정 전 자동 승인을 켜지 않는다. 요청 당사자인 담당자는 지정 대리 승인자가 승인해야 하며, 같은 계정의 다른 소속으로 자기승인을 우회하지 못한다.

### 7.3 상태와 재동의

`draft → awaiting_consent → ready_for_approval → applied`

`rejected / withdrawn / expired / superseded`는 종결이다. 적용 결과가 불명확한 브라우저 상태는 별도 복구 표시이며 서버 성공/거절 상태로 추정하지 않는다.

기준 수업 판, 날짜·시각, 담당자, 참여집단, 공간, 영향, 필요한 동의자 중 하나라도 바뀌면 기존 동의를 재사용하지 않는다. 새 변경안으로 다시 동의를 받는다. 명칭 오타 수정처럼 효력 없는 표시 변경도 서버 정규화 규칙에 따라 판단하며 클라이언트가 임의 면제하지 않는다.

적용된 변경의 ‘취소’는 현재 상태에서 되돌리는 새 변경 요청이다. 그 뒤 다른 교환·실시가 있었다면 단순 과거 복원이 불가능할 수 있고, 영향과 대안을 보여 준다.

## 8. 동시성·중복·실패

브라우저 검사와 DB 최종 검사를 분리한다. 브라우저 검사는 편의를 위한 사전 안내이고 승인 근거가 아니다. 현재 순수 검사에서는 서버가 승인한 수업별 `allowedSpans`와 정확히 일치하는 목적 시간만 받는다. 조회 기간 `complete=true`가 하루의 모든 시각을 수업 가능하게 만든다는 뜻은 아니다. 학생 집단/학생 자원이 빠진 교사만의 입력도 거부한다.

서버는 공통 권한/멱등 처리 후 관련 학교·학기·교사·수업집단·학생·교실 자원키를 정렬해 같은 규약으로 잠근다. 배포, 불가시간, 공간 예약, 수강 변경, 교환이 모두 같은 자원 잠금을 사용한다. 아직 점유 행이 없는 자원도 잠근다.

잠금 뒤 최신 권한·자료·수업 기대판·동의·불가시간·용량을 다시 확인한다. 일부 수업만 바뀌는 부분 성공은 없다. 표 제약은 마지막 방어이며 사전 SELECT만으로 경쟁을 해결하지 않는다.

| 상황 | 사용자 안내와 처리 |
|---|---|
| 다른 담당자가 먼저 수정 | 내 입력 보존, 최신안과 전후 비교, 새 확인 |
| 응답 중 연결 끊김 | 원래 명령·요청 번호 보존, 같은 요청 결과 확인 |
| 같은 키로 내용 변경 | 자동 재전송 금지, 원래 요청 결과부터 확인 |
| 권한·학교 변경 | 이전 학교 자료 숨김, 늦은 응답 무시 |
| AI 응답만 실패 | 조건·변경안 직접 입력 가능 |
| solver 제한 도달 | ‘불가능’ 대신 종료 이유, 이미 검증한 후보 보존 |
| 알림 실패 | 실제 시간표 반영 상태 유지, 알림만 재시도 |
| 기준자료/동의 만료 | 확인한 내용을 재사용하지 않고 다시 검토 |

복구 정보는 현재 탭 메모리 범위를 정확히 알린다. 민감한 학교·교사·학생 자료를 임의 localStorage에 보관하지 않는다. 장기 보관을 제공할 때는 별도 서버 초안 저장과 권한·보존 정책이 필요하다.

## 9. Claude 연결 계약

Claude가 만들어도 되는 결과는 **확인 질문, 조건 제안, 후보 설명, 변경안 제안**이다. 이를 저장/동의요청/승인 명령으로 바로 실행하지 않는다.

공통 제안에는 `contextId, basisRevisionId, sourceFingerprint, proposalKind, sourceRefs, questions, proposedChanges, explanation`을 둔다. sourceRefs는 현재 학교의 허용된 자료 ID와 판만 사용한다. 자연어 사유·문서 본문에 들어 있는 지시를 시스템 명령으로 실행하지 않는다. 개인정보 사유는 필요한 최소 범위로 줄인다.

도구 기능은 다음 경계로 한정한다.

| 도구 성격 | 허용 결과 | 사람이 할 확인 |
|---|---|---|
| 자료 상태 읽기 | 누락·불일치·지원 여부 | 관리자 기준자료 확인 |
| 자연어 조건 정리 | typed 조건 초안/질문 | 강도·기간·대상·근거 확인 |
| 후보 비교 읽기 | 검증 결과와 변경 요약 | 선택할 후보·고정 해제 |
| 교환안 탐색 | 최신 날짜별 수업 기반 제안 | 전후 비교·동의 요청 |
| 요청 상태 읽기 | 현재 응답/승인/적용 상태 | 동의·최종 승인 |

AI에는 범용 SQL 실행·임의 RPC 호출 도구를 주지 않는다. 모델·키·비용 한도·재호출 정책은 기존 승인 구조를 따른다. 공급자 결과 미상 상태에서 같은 작업을 자동 재호출하지 않는다. Claude가 ‘충돌 없음’이라고 말해도 검증기 보고가 없다면 검증 완료 표시를 하지 않는다.

과거 사용자 요청에 따라 초기 세팅·후보 조정·확정 후 교환의 상세 대화/프롬프트 설계는 Claude 검토 대상이다. Codex는 typed 경계와 양식/검증 경로를 제공하며 현재 모델/비용 설정을 임의 변경하지 않는다.

## 10. 학교급과 지원 판정

‘초등학교 지원’ 같은 학교급 한 단어보다 **운영형별 지원 행렬**을 관리한다. 자동편성, 독립 검증, 날짜별 변경 각각이 별도 지원 여부를 갖는다.

| 운영형 | 필수로 표현·검사할 것 |
|---|---|
| 중학교 학급 중심 | 시수·담당·교사/학급 충돌·특별실·고정·불가시간 |
| 초등 담임+전담 | 학년별 일과, 실제 비수업 칸, 담임과 전담 담당, 블록 |
| 고교 선택/분반 | 행정학급과 수업집단 분리, 수강학생 중첩, 팀티칭, 합반 |
| 순환주/분수 시수 | 순환 주기·회차와 주기 전체 시수 |
| 캠퍼스/공동교육과정 | 실제 시각, 이동시간, 외부 자원과 학교 경계 |

명단이 없는데 학생 중첩 0으로 처리하지 않는다. 합반/선택반을 한 행정학급으로 축약해 지원한다고 표시하지 않는다. 미지원 기능은 자동편성만 막는 것이 아니라 해당 기능의 충돌을 검증하지 못하는 수동 배포도 막는다.

## 11. 서버 연결 완료 전에 필요한 증거

- 실제 규모의 합성 중학교, 학년별 일과 초등, 선택수강 고교 각각 입력/해/독립 검증을 비교.
- 한 수업 교환과 3자 순환, 팀티칭, 강의실 용량, 인접 구간, 일과 시각이 다른 교시를 시험.
- 같은키 재전송·다른내용, 기대판 변경, 소속 종료, 자기승인, 동의자 누락, 동의 후 변경을 거부.
- 두 DB 연결로 교환 대 교환, 교환 대 출장, 교환 대 공간 예약, 배포 대 교환 경쟁을 재현.
- 부분기간 배포 후 앞뒤 기간·승인된 미래 변경·과거 실시·학생 기록 유지.
- 예정/실시/미실시/보강의 합계와 정정 보상 원장에서 중복 계상 0.
- 실제 PostgREST 응답을 현재 parser에 대조. 합성 RPC 통과와 실제 연결 성공을 구분.
- 교사 이름·부재 사유·학생 정보가 로그/AI context/알림에 불필요하게 복제되지 않음.
- AI를 끈 상태에서도 양식으로 준비·조정·변경 요청을 마칠 수 있음.

## 12. 판단해서 정한 것

- 학교 관리 원본을 기준으로 준비하되, 현재 없는 시수·일과는 누락으로 처리한다. 조용한 기본값이 교사에게 틀린 표를 주는 일을 막기 위해서다.
- 주간 후보와 날짜별 수업을 나눈다. 반복 변경과 일회 변경을 구분하고 기존 학생 기록을 보존하기 위해서다.
- 담당자 승인과 반영을 한 원자 명령으로 묶는다. 승인됐지만 실제 시간표는 못 바뀐 상태를 장기간 만들지 않기 위해서다.
- 생성기는 후보를 제시하고 독립 검증기가 판정한다. 탐색 최적화가 바뀌어도 안전 검사를 같은 기준으로 유지하기 위해서다.
- 운영형 미지원은 명시 차단한다. 데이터 구조가 담을 수 있는 것과 현재 계산기가 검증하는 것을 구분하기 위해서다.

변경하려면 관련 타입·검증기·SQL 계약·인수시험을 함께 수정한다. 이 문서는 학교 운영 규정이나 DECISIONS 확정 D번호를 새로 승인한 기록이 아니다.
