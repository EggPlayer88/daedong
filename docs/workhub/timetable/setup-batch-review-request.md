# Claude 검토 요청 — 시간표 준비 엑셀·순차 저장·점검표

시간표 앱 후속 `feat/workhub-timetable-setup-batch`를 검토해 주세요. 기준은 PR #68 `463445d`이며 검토할 PR/head는 새 PR 설명을 사용해 주세요. Claude가 진행 중인 SQL 설치와 독립된 앱 변경입니다. SQL·인증·비용·공개 범위를 바꾸거나 실제 DB에 접속하지 않았습니다.

구현 설명과 시험 범위: [setup-batch-implementation.md](setup-batch-implementation.md).

이번 변경은 현재 공간·수업 연결의 XLSX 편집 → 명시 비교/선택 → 기존 T1 RPC로 순차 저장, 부분 성공·응답 유실 복구, 준비 점검에서 실제 편집으로 이동하는 기능입니다. 기존 시수·일과 보존과 준비 원본 채택까지 연결했습니다.

중점적으로 확인해 주세요.

1. `setup-workbook.ts`: 기존 공간 수정/수업 연결 외의 변경이 명령으로 나가지 않는지. 학교·학기·기준일·전체 원본 대조, null 정원, 동명 ID, 미선택 이름 변경과 연결 비교, 삭제된 원본 참조를 확인해 주세요.
2. `setup-batch.ts`: 한 항목씩 기존 `workhub_timetable_setup_execute`를 호출하는 방식입니다. 저장한 앞 항목의 접수증과 원래 요청 번호를 보존하며, 다음 항목의 최신 자료를 다시 확인하는지 검토해 주세요. 전체 원자 저장은 아닙니다.
3. 부분 성공/모듈 중지/CONFLICT/응답 유실/NOT_FOUND 이후 원키 복구와 명시 재개가 T1 응답과 맞는지 확인해 주세요. 자기 저장으로 해소된 학생 겹침과 새 진단을 구별하는 두 회귀도 포함했습니다.
4. 실제 `TimetableWorkspace` → 준비 → setup → batch에서 재진입 시 보관 영역이 열리고, 새 요청이나 다른 편집을 동시에 시작하지 않는지 확인해 주세요. 조회 장애 뒤 입력을 버리지 않고 다시 불러올 수 있어야 합니다.
5. 일괄 저장 뒤 공식 자료 재조회와 시수·일과 보존, 명시 채택, 다른 담당자의 준비 초안 판 변경 차단이 유지되는지 확인해 주세요.
6. 점검 숫자가 전체 시간표 완성률로 오해되지 않는지, 진단 대상 바로가기·학교 관리 이동·다운로드가 정확한지 확인해 주세요.

부수 시험 수정도 확인해 주세요. `test_workhub_hwpx_basic_server.py`의 oversized HTTP 시험은 Windows에서 본문 송신과 서버의 조기 413 종료가 경합해 간헐적으로 실패했습니다(100회 중 15회 재현). 본문 송신 전 과대 길이 헤더로 413과 검사 함수 미호출을 확인하도록 시험만 수정했고 같은 100회 모두 통과했습니다. 서버 코드는 바꾸지 않았고 예외를 성공으로 삼거나 재시도로 숨기지 않았습니다.

별도 SQL 변경은 요청하지 않습니다. `timetable.setup.v1`과 기존 공개 RPC 계약은 그대로입니다. 실제 T1 저장 응답으로 순차 저장/복구를 추가 대조할 때 차이가 있으면 최소 재현 입력·응답·영향과 권장 수정으로 알려 주세요.

브라우저 시험은 실제 제품 코드와 합성 RPC입니다. 실제 Supabase 성공이나 교사 시범 준비 완료로 판정하지 말아 주세요. 병합·SQL 적용·활성화·일반 교사 공개 판단은 구분해서 남겨 주세요.
