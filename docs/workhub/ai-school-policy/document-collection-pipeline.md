# 질문형 HWPX 생성부터 수합 ZIP까지

2026-10-21 · PR #77 후속 · DB 적용·실제 회원 연결·외부 AI 호출 없음.

## 이번에 연결해 검증한 흐름

| 단계 | 교사·담당자의 동작 | 완료 근거 |
|---|---|---|
| 1. 답변 작성 | 게시된 질문형 양식의 답변을 저장 | 해당 양식판·응답판의 서버 접수증 |
| 2. 파일 생성 | 저장한 답변으로 HWPX 생성 | 실제 원본의 지정 문단만 채운 파일·해시 |
| 3. 파일 확인 | 내려받고 내용을 확인했다는 체크 | 내려받기 전에는 확인·수합 전달 불가 |
| 4. 수합 이동 | 연결된 수합에서 내 제출 단위를 열고 첨부 | 문서함 파일 ID를 재사용하지 않고 수합 파일을 별도로 예약 |
| 5. 기본 검사 | 업로드 후 HWPX 최소 검사를 통과 | 준비 완료 파일만 초안에 포함 |
| 6. 최종 제출 | 초안 저장 후 별도로 최종 제출 | 제출 접수증. 파일 생성·첨부·초안 저장만으로 제출되지 않음 |
| 7. 담당자 다운로드 | 완료본 또는 최신 제출본을 선택해 ZIP 준비 | 파일·제출판·권한을 다시 확인한 뒤 ZIP과 현황 CSV 제공 |

AI 작성 도움은 기존 질문형 답변 검토·반영 흐름을 사용한다. 위 단계에서 AI가 자동으로 파일을 제출하거나 담당자의 확인을 대신하지 않는다.

## 수정한 결함

1. **생성 파일명의 두 경로 불일치**: 긴 한글 제목과 Windows 예약명은 다운로드에서는 정규화됐지만 수합 전달에서는 원래 이름이 남았다. 공용 `safeDownloadName`을 먼저 적용해 다운로드와 첨부 이름을 일치시켰다.
2. **Storage 응답 정체로 화면 잠금 지속**: 원본 업로드·생성물 다운로드·파일 해시 읽기에 제한시간을 적용했다. 쓰기 결과가 미상이면 원래 파일과 요청 번호를 유지하며, 읽기 실패는 재시도할 수 있다.
3. **제한시간 뒤 새 요청 시작**: 상위 작업의 만료 검사를 RPC의 신원 조회 전후에도 전달한다. 늦은 신원 조회가 완료돼도 이미 끝난 파일 작업이 준비 요청을 새로 보내거나 늦은 예약을 등록하지 않는다. 기존 인증·권한 정책은 유지한다.

가상 생성물 37개에는 정정판 1개가 포함된다. 기존 양식 사본 6개를 더해 파일 생성·검사 대상은 43개다. 동명이인 18쌍과 동일한 파일명도 제출 단위·순번·판을 기준으로 구별한다. 최종 제출 응답 유실은 같은 키로 재확인하고, ZIP 파일 하나가 실패하면 누락된 ZIP을 내주지 않고 실패 파일만 다시 준비한다. 파일 변조 또는 준비 중 제출판 변경은 기존 묶음을 폐기한다.

브라우저는 답변·초안·제출 응답 유실 후 재진입, 학교 전환 중 늦은 응답 폐기, 다운로드 중 원본 변경, 제한시간 뒤 잠금 해제·재시도, 320px 및 키보드 다운로드를 포함한다. 실제 결과 건수와 최종 전체 검증은 [verification.md](verification.md)에 기록한다.

Python은 `lxml`이 필요하다. `PYTHON`으로 실행 파일을 지정할 수 있다. 시험 자료·계정은 가상이며 외부 AI나 운영 DB에 접속하지 않는다.

## 남은 실제 연결과 범위

- 운영 DB 적용·기능 활성화, 실제 Supabase/Storage 왕복, 학교 API 키 설정, 기존 회원 학교 연결, 최종 Claude 검토는 사용자 요청대로 뒤로 둔다.
- 한글 프로그램의 시각적 배치·인쇄 호환성은 자동 XML/ZIP 검사와 별개다.
- 자동 HWPX 수합 연결은 **질문형 수합 양식** 경로다. 일반 문서는 TXT와 저장판 인쇄/PDF 출력을 제공한다. 기존 평가계획서 화면 전체를 새 수합에 자동 제출하는 기능을 추가한 것은 아니다.
- ZIP은 파일·CSV 합계 100MiB 및 ZIP 512항목 상한을 유지하면서 여러 묶음으로 나눈다. 한 묶음만 준비·다운로드하고 다음 묶음으로 이동한다. ZIP 생성 중 내부 복사와 브라우저 다운로드까지 포함한 전체 메모리 사용량이 100MiB 이하라는 뜻은 아니다.
- 수합에서 돌아오면 같은 학교 범위에 기억한 양식 ID로 저장 답변·생성물을 다시 조회한다. 작성 중 입력과 미확정 요청은 기존 보존 방식이 우선한다. 확인 체크는 재진입 후 다시 받는다. 이 기억은 같은 탭 메모리이며 브라우저 종료 후 복구를 약속하지 않는다.

## 후속 구축: 여러 ZIP과 작업 복귀

전체 파일은 기존 제출 단위·판·파일 순서로 결정적으로 나눈다. 각 ZIP의 CSV는 실제 들어간 파일명·해시와 전체 미제출·제외 단위를 담는다. 특정 단위의 파일이 여러 ZIP으로 나뉠 수 있으며 ZIP별 포함 단위 수를 단순 합산하지 않는다.

모든 묶음은 같은 전체 현황 지문을 사용한다. 다음 묶음 준비 또는 내려받기 직전에 제출판·파일 접근이 바뀌면 진행 표시를 폐기하고 최신 현황으로 다시 시작한다. 실패 파일만 재확인할 수 있지만 누락 상태로 ZIP을 성공 제공하지 않는다. 화면의 ‘다운로드 요청 n/m’은 브라우저에 넘긴 요청 수이며 실제 디스크 저장 완료 증거가 아니다. 자동 연속 다운로드는 하지 않는다.

추가 검증은 가상 교사 36명의 파일 540개를 ZIP 두 개로 받아 누락·중복·CSV 경로·해시를 대조했다. 별도 단위 시험은 총 바이트 상한 분할, CSV 용량, 부분 재시도와 판 변경을 검사한다. 원래 양식 복귀는 최신 답변 재조회·조회 실패 재시도·삭제·학교 전환을 포함한다.
