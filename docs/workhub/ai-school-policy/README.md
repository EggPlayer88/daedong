# 학교 공통 AI 정책·키·예산 통합

2026-10-21 · `feat/workhub-ai-school-policy` 작업 기록. 이 문서는 구현과 배포 준비를 설명한다. 운영 SQL 실행, 실제 API 키 등록, 유료 호출, 기능 공개를 완료했다는 뜻이 아니다. 최종 검증 결과는 [verification.md](verification.md)를 따른다.

## 1. 사용자 승인 기준

사용자는 일반 업무에 Haiku를 기본으로 사용하고, 필요한 답변만 직접 Sonnet 정밀 검토를 요청하는 구조, 학교별 API 키, 학교 전체가 공유하는 월 USD 100 예산, 기존 평가계획서 AI의 동일 정책 편입을 승인했다. 학생 기록 초안은 일반 답변을 먼저 만들지 않고 Sonnet으로 작성한다. 운영 적용·키 등록·활성화·병합은 별도로 진행한다.

| 구분 | 이번 기준 |
|---|---|
| 학교 업무 안내·개인 업무·문서 초안·문답형 수합 | Haiku 기본 답변 |
| 기존 기본 답변의 정밀 검토 | 사용자가 `이 답변 정밀 검토`를 눌러 Sonnet 요청, 원답변은 보존 |
| 정밀 검토 반복 | 원래 quick 답변의 1단계 검토만 허용, 검토 결과를 자동 재검토하지 않음 |
| 학생 기록 초안 | 서버가 확인한 학생·수업 관계와 선택한 관찰·평가 근거를 바탕으로 Sonnet 직접 작성 |
| 평가계획서 | 기본 작성은 Haiku, 화면에서 명시 선택하면 Sonnet |
| 자동 승격·자동 재생성 | 없음. 오류나 형식 실패도 새 유료 호출은 명시 요청 필요 |
| 예산 | 학교별 월 USD 100을 업무실 비서와 평가계획서가 함께 사용 |
| 공개 범위 | 기존 모듈·회원 승인·소속·역할 조건 유지 |

학생의 공식 식별값·이름은 브라우저가 임의로 작성한 값을 신뢰하지 않고 서버가 현재 학교 자료에서 조회해 공급자 입력에 넣는다. 전송 범위는 학생 초안 화면에 표시하며, 격리 DB·서버 대조 결과는 [검증 상태표](verification.md)에 기록한다. 개인 상담 자료는 근거로 포함하지 않는다. AI 결과는 검토할 초안이며 학생 기록, 메시지, 문서 제출을 자동 확정하지 않는다.

## 2. 모델·한도·예산 계산

앱·서버의 기준 자산은 [`model-routing.json`](../../../apps/main/api/workhub-ai/_assets/model-routing.json)이다. 자산 판은 `2026-10-21.1`이며 임의의 클라이언트 모델 이름·단가·상한을 받지 않는다. SQL 정책과 자산이 맞지 않으면 공급자 호출 전에 중지한다.

| 경로 | 모델 | 입력 USD/100만 토큰 | 출력 USD/100만 토큰 | 시작 전 예약액 |
|---|---|---:|---:|---:|
| quick | `claude-haiku-5-5` | 0.10 | 0.50 | USD 0.014 |
| review | `claude-sonnet-5-5` | 2.00 | 10.00 | USD 0.28 |

단가는 2026-10-21 확인한 [Haiku 5.5 공식 문서](https://platform.claude.com/docs/en/models/haiku-5-5/overview), [Sonnet 5.5 공식 문서](https://platform.claude.com/docs/en/models/sonnet-5-5/overview), [공식 요금표](https://platform.claude.com/docs/en/about-claude/pricing)를 근거로 한다. Haiku는 입력 100,000토큰을 넘으면 단가가 달라지므로 아래 경계를 함께 적용한다.

- 사전 입력 허용: 토큰 계수 결과 **80,000 이하**.
- 사전 예약: 추정 오차를 포함해 **입력 100,000 + 출력 8,000**의 비용을 모두 확보.
- 실제 자동 정산: 관측 입력 **100,000 이하**, 출력 **8,000 이하**일 때만 수행.
- 계수 실패: `COUNT_FAILED`, 답변 생성 0회. 계수 요청은 공급자에 도달할 수 있으므로 외부 통신 0회라는 뜻은 아니다.
- 시작 전 입력 초과: `INPUT_TOO_LARGE`, 예약 해제 후 입력을 보존.
- 시작 후 결과 불명: 원래 예약을 유지하고 같은 요청의 결과만 확인. 새 공급자 요청을 자동 실행하지 않음.
- 실제 사용량이 예약 범위를 초과: 관측 사용량과 원래 예약을 보존하고 학교의 새 요청을 차단(`overage_blocked`). 무제한 자동 정산으로 전환하지 않는다.

예약액은 매 요청의 확정 요금이 아니다. 정상 완료 뒤 확인된 사용량으로 정산한다. 학교 현지 월을 기준으로 원장에 집계하며, 동시에 여러 교사가 요청해도 학교 전체 예산을 함께 검사한다. 같은 키를 다른 사이트에서 사용하는 비용이나 공급자 측 별도 결제는 이 원장 밖이므로, 이 기능이 공급자 계정 전체 청구를 USD 100으로 제한한다고 표현하지 않는다.

이번 통합에서는 캐시를 사용하지 않는다. Sonnet 5.5는 강제 도구 호출과 `thinking.type=disabled`를 지원하지 않으므로 지원되는 `adaptive` 설정과 구조화된 텍스트 응답을 사용한다. 추론 블록은 화면·대화 원문에 저장하지 않고 실제 사용량에는 포함해 처리한다. 근거: [Sonnet 5.5 이전 안내](https://platform.claude.com/docs/en/models/sonnet-5-5/migration-guide).

### 학교 키 경계

- 브라우저에서 사용자가 입력한 키는 관리자 저장 요청으로만 전달한다. 복구 명령, localStorage, 출력 파일에는 넣지 않는다.
- DB에는 AES-256-GCM 암호문과 마스킹된 마지막 네 글자만 저장한다. 평문 키는 서버에서 복호화해 고정된 Anthropic 호스트로만 전송한다.
- 암호문은 `schoolId`와 `credentialVersion`에 묶인다. 다른 학교·다른 판에 복사한 암호문은 복호화에 실패한다.
- AAD는 `JSON.stringify(['workhub.ai.school-key.v1', schoolId, credentialVersion])`이며 Node/Python이 같은 구조를 사용한다.
- 키 교체 결과가 불명확하면 평문을 다시 보관하지 않고 기존 요청 번호로 접수 결과만 확인한다. 닫기 결과를 확인하기 전 새 저장으로 바꾸지 않는다.

### 요청 생명주기

`검증된 계정 → 서버가 학교 확인 → 원번호 예약 → 같은 본문 토큰 계수 → 1회 시작권 → 공급자 1회 호출 → 검증된 결과·사용량 정산` 순서다.

같은 번호·같은 내용은 원결과를 반환하고, 같은 번호에 내용·quality를 바꾸면 거부한다. 네트워크 오류 뒤 새 번호로 자동 요청하지 않는다. 시작 전 닫기는 취소 장벽을 남겨 늦은 원요청을 막는다. 시작한 요청은 닫기를 눌러도 완료로 꾸미거나 예약을 해제하지 않는다. 닫기 응답이 유실되면 같은 닫기만 재확인한다.

평가계획서는 화면을 닫았다 같은 탭에서 다시 열어도 계정별 메모리에 원요청을 보관한다. 브라우저 종료 이후 복구까지 보장하지 않는다. 계정이 바뀌면 이전 입력·응답을 표시하지 않는다. 기존 저장 대화는 기존 개인 대화 저장소를 그대로 사용한다.

Node 평가는 인증 시작부터 50초 이내로 제한하고 정산을 위해 8초를 남긴다. 실행 전 시간이 부족하면 예약을 종료하고, 실행 이후 시간초과는 결과미상으로 보존한다. 외부 함수 실행시간 설정 자체는 바꾸지 않는다.

## 4. 배포 순서 — 기존 평가계획서와 함께 전환

**2026-10-21 추가 지시:** 지금은 구축과 가상 교사 반복 시험에 집중한다. Claude 검토와 기존 평가계획 회원의 실제 학교 연결은 마지막 전환 단계로 미룬다. 아래 운영 순서는 나중에 실행할 준비 순서이며 이번 작업에서 실행하지 않았다.

현재 `학교 관리 → AI → 가상 교사 연습`은 별도의 메모리에서 실행되므로 새 SQL·실제 키·기존 회원 연결이 필요하지 않다. 학교별 36명·9학급의 가상 자료, 별도 가상학교, 기본 답변·명시 정밀검토·가상 학생 초안·예산 소진·응답 유실·복구·닫기를 시험한다. 실제 모델 품질이나 실제 청구를 검증하는 화면은 아니다. 입력/미확정 요청이 있으면 전환을 막으며 명시 초기화도 연습실 자료에만 작용한다.

**이번 변경은 SQL·서버·브라우저·학교 연결·키 설정을 같은 전환 작업으로 준비해야 한다.** 새 평가계획서 서버는 기존 전역 `ANTHROPIC_API_KEY`·`ANTHROPIC_MODEL`로 돌아가는 대체 경로를 사용하지 않는다. 공통 설정이 없으면 AI 작성이 준비되지 않았다고 중지한다. 확정 HWPX 생성·검증 엔진은 변경하지 않는다.

| 순서 | 담당·할 일 | 다음 단계 전 확인 |
|---|---|---|
| 1 | 검토할 앱·SQL을 고정하고 자동 검증 완료 | 전체 시험·빌드·보호 검사, SQL 사전·사후 점검 파일, 동일 모델 자산 |
| 2 | 사용자와 운영 전환 시점·영향 교사 범위 결정 | 기존 AI 실행 중 요청·미상 요청 처리 방안, 전환 중 새 요청 사용 안내 |
| 3 | 승인 후 Production 서버 환경값 준비 | 마스터 키 ID/32바이트 키, Supabase 서비스 키, 브라우저 노출 없음 |
| 4 | 승인된 신규 AI SQL을 설치 | `P10-01 → 02 → 03 → 04 → 09 → 10 → 11`, 별도 실행안내의 지문·권한·비활성 점검 통과 |
| 5 | 학교 정책 준비, 실제 기존 회원 연결은 아직 보류 | 월 USD 100, 학교 관리자 승인 근거. 테스트용 가상 자료는 운영에 자동 생성하지 않음 |
| 6 | 평가계획서와 업무실 비서·설정 화면을 같은 앱 판으로 배포 | Node 게이트웨이·Python 서버·라우팅 자산 모두 배포, 옛 탭은 새로고침 |
| 7 | 학교 관리자 화면에서 학교 API 키 등록 | 전체 키 재노출 없음, 키 판·마스킹·예산 상태 확인 |
| 8 | 사용자 승인 후 학교 공통 정책·기존 필요한 비서 모듈 활성화 | 관리자 범위에서 준비 상태·미상 복구·실제 서비스 왕복 확인 |
| 9 | 최종 검토·실제 학교 연결·별도 유료 확인 | 기존 평가계획 이용자의 승인된 ID만 마지막에 연결. 실제 호출 결과·정산·권한 확인 뒤 사용자 결정 |

이 표는 실행 순서를 설명하는 준비 문서다. 실제 운영 실행은 SQL 패키지의 사전·사후 점검과 사용자 승인 절차를 따라 한 단계씩 진행한다. 키 등록이나 정책 설치만으로 모듈 공개 범위를 확대하지 않는다.

기존 평가계획 회원에게 업무실 소속이 없더라도 서버가 사용자를 어느 학교로 보낼지 추정하지 않는다. 승인된 기존 사용자 ID를 학교 연결표에 명시한다. 이 연결은 업무실 관리자 권한을 부여하는 절차가 아니다.

실제 회원 연결을 보류하는 동안 새 평가계획 AI의 실계정 호출은 미준비로 중지된다. 현재 운영 AI를 유지해야 할 때는 이 공통 전환 PR을 먼저 배포하지 않는다. 가상 연습실은 이 제약 없이 사용할 수 있다.

구버전 전역 키 경로를 실행하는 배포본이 남아 있으면 해당 비용은 새 학교 원장에 포함되지 않는다. 이전 배포와 실행 중 요청까지 확인해야 전환이 끝난다. 장애 시 앱만 구버전으로 되돌려 공통 원장을 우회하게 하지 말고, 새 호출을 중지한 상태에서 SQL·앱·미확정 원장을 함께 확인한다. 과거 전역 환경변수의 삭제·정리는 사용자가 외부 설정을 확인한 뒤 수행한다.

### 필요한 Production 서버 설정

| 환경값 | 목적 |
|---|---|
| `VITE_SUPABASE_URL` 또는 서버가 사용하는 기존 Supabase URL | 동일한 운영 프로젝트 연결 |
| `SUPABASE_SERVICE_ROLE_KEY` | 서버 전용 공통 RPC 실행. `VITE_` 접두사를 붙이지 않음 |
| `WORKHUB_AI_KEY_ENCRYPTION_KEYS` | `{keyId: base64 32바이트 키}` 형식의 서버 전용 마스터 키 목록 |
| `WORKHUB_AI_ACTIVE_KEY_ID` | 새 암호문을 만들 때 사용할 마스터 키 ID |

환경값 예시에는 실제 비밀을 넣지 않는다. 마스터 키 백업·교체·분실 대응은 운영 담당자가 정해야 한다. 키가 없거나 복호화하지 못하면 다른 학교 키나 전역 키로 대체하지 않는다.

## 6. 판단해서 정한 것

1. 가격·모델·토큰 한도는 공통 자산과 서버 정책이 일치할 때만 실행한다. 두 언어의 호출이 다른 가격을 적용하는 것을 막는다.
2. 사전 허용 입력 80,000과 예약 입력 100,000을 구분했다. 계수 오차를 이유로 무제한 정산하지 않고, 예약 범위를 넘으면 관측·예약 보존과 학교 새 호출 차단으로 처리한다.
3. 기존 평가계획 AI도 별도 전역 키 대체 경로를 제거했다. 학교 공통 예산이 일부 기능만 통제하는 상태를 피하기 위해 동시 전환을 요구한다.
4. 자동 인사·형식 복구 호출을 명시 버튼으로 바꿨다. 사용자가 의도한 유료 요청과 새 비용 발생을 구별할 수 있게 한다.
5. 결과미상에서 잠금을 푸는 근거는 서버 완료/종료 접수증으로 한정했다. 닫기 응답 유실도 새 요청을 만드는 이유가 되지 않는다.
6. 학생 기록은 정확한 학교 학생 식별값·현재 관계·선택한 관찰/평가 근거를 서버가 확인하며, 상담 자료와 자동 확정은 범위에서 제외한다.

되돌릴 때도 운영 원장과 실제 청구 이력은 삭제하지 않는다. 코드 변경은 검토된 후속 커밋으로 조정하고, 모델·가격·권한·SQL 정책 변경은 사용자 결정과 별도 증분으로 준비한다.

## 7. 운영 화면과 비용 없는 준비 진단

학교 AI 화면은 `가상 교사 연습 / 학교 키·예산 / 운영 현황·진단`으로 나눈다. 연습을 첫 화면으로 열며 입력 중인 키나 미확정 요청이 있으면 탭 이동을 막는다. 신규 모듈의 기존 superadmin 공개 범위를 유지한다.

- 운영 현황은 현재 학교 관리 권한으로 이번 달 확정 비용·예약·남은 예산, 두 기능과 모델별 합계, 최근 요청을 25개씩 읽는다. 화면은 최대 500개를 표시하지만 집계는 전체다.
- 결과가 미상인 과거 달 요청도 전체 기간 예약 요약에서 확인한다. 요청 제목·질문·답변·교사/학생 이름·키는 조회하지 않는다. 상태·비용은 재조회 시 갱신된다.
- 서버 준비 진단은 현재 관리자 권한, SQL, 정책, 학교 키 존재, 서버 암호화 설정, 현재 키 복호화만 확인한다. Anthropic 연결·모델 이용권·실제 응답·과금은 항상 **미확인**이다. 비용 예약·공급자 호출·설정 저장은 하지 않는다.
- 지원 JSON에는 집계와 진단 상태만 담고 학교·회원·요청 번호·키·내용을 제외한다.
- 운영 조회가 준비되지 않아도 가상 연습실은 별도로 작동한다. 운영 화면에서 예약을 임의 해제하거나 유료 재호출하지 않는다.

정확한 목록·서버 내부 진단 계약은 [Operations-contract.md](../../../database/workhub-ai-policy/p10/Operations-contract.md)를 따른다. 새 `P10-09/10`은 새 함수·조회 인덱스·설치 기록만 추가한다. 기존 `P10-01~08`은 변경하지 않았다.

추천 운영 순서는 **가상 반복 시험 → 최종 코드·SQL 검토 → 서버/정책/키 설정 → 실제 회원 연결 → 제한된 실호출 확인**이다. 미상 비용 확인 담당은 첫 시범에서 계란님으로 두고 수동 확인하는 방식을 권장한다. 담당자·정기 자동화·보관 삭제 주기는 아직 활성화하지 않으며 별도 결정 없이 청구를 확정하거나 자료를 자동 삭제하지 않는다.

## 9. 업무 화면 연결·복귀 보강

AI로 이동하거나 받은 초안을 메시지·문서·수합 화면으로 전달하면 원래 화면으로 돌아갈 수 있다. 현재 학교와 이동한 화면이 맞을 때만 복귀 링크를 표시한다. 작성 중 입력이나 결과 미상 요청이 화면 이동을 잠그면 복귀도 잠그고 이유를 표시한다. 일반 메뉴 이동과 학교 변경은 과거 복귀 경로를 지운다.

- 일정에서 특정 수업을 열면 과거의 시간표 확정·교환 탭보다 선택한 수업을 우선한다. 미확정 확정/실시 기록 요청이 있으면 기존 원수업·요청 복구가 먼저다.
- 질문형 수합에서 AI 도움을 요청한 뒤 돌아오면 원래 질문형 탭과 보관한 답변을 다시 연다. 보관 기간은 같은 브라우저 탭 메모리다.
- 교사가 답변을 명시 저장해 접수 확인까지 마치면 이전 답변판의 AI 비교를 종료한다. 저장 실패·결과 미상에는 제안과 답변을 보존한다. 완료한 제안은 재진입해도 다시 표시하지 않으며 새 도움 요청은 가능하다.
- 화면 이동이나 AI 답변 수신만으로 메시지 전송, 문서 저장, 수합 첨부·최종 제출을 실행하지 않는다.

가상 반복 시험은 2개 학교 × 36명으로 확장했다. 실제 앱 도메인과 서비스/parser, 기존 연습 저장소를 조합한다. 메시지 접수증·AI 응답은 합성이며 수합 저장은 연습 저장소이므로 운영 DB나 파일 저장소의 성공 증거와 구분한다. 실제 연결 셸을 통과하는 브라우저 시험도 별도로 유지한다.

현재 남은 연결: 운영 SQL·서버 설정·키 등록, 실제 PostgREST/Storage/공급자 왕복, 마지막 실제 회원 연결. 교사 외부 사이트 연동은 이번 범위에서 제외한다. 이 묶음은 DB·모델·비용·인증·공개 범위를 변경하지 않았다.

## 10. 문서 생성·수합·전체 다운로드 연결

질문형 양식의 답변 저장 → HWPX 생성 → 내려받아 명시 확인 → 연결된 수합 첨부·기본 검사 → 초안 저장 → 최종 제출 → 담당자 ZIP을 하나의 브라우저 흐름으로 검증했다. 긴 한글 파일명의 다운로드/첨부 불일치와 Storage 응답 정체 시 화면 잠금을 수정했다. 가상 36교사·9학급의 실제 생성 파일, 정정판, 동일 이름, 응답 유실과 ZIP 원본 보존을 함께 확인한다.

[구현·검증 경계와 남은 연결](document-collection-pipeline.md)을 참고한다. 운영 DB·Storage 성공이나 기존 평가계획서 전체의 자동 제출을 의미하지 않는다.

## 11. 대량 다운로드·작업 복귀·전송 복구 후속

이번 후속은 새 SQL·권한·비용 정책을 바꾸지 않고 기존 계약 안의 연결을 마무리한다.

| 흐름 | 구현 |
|---|---|
| 큰 수합 전체 다운로드 | 한 ZIP에 파일·CSV 100MiB, 총 512항목을 넘기지 않게 여러 묶음으로 분할. 전체 제출 지문을 고정하고 각 묶음을 준비·재확인·명시 다운로드. 현재 묶음 파일만 보관 |
| 수합 후 원래 양식 | 저장 완료 양식 ID만 같은 학교·탭 메모리에 보관. 복귀 때 최신 답변·생성물을 조회하고 파일 확인은 다시 받음 |
| 문서 TXT 출력 | 일반 인쇄/PDF와 마찬가지로 정확한 저장판·조회 권한을 재조회. 작성 중 입력은 출력에 섞지 않음. 읽기 실패·배경 오류·미상 저장 중 다운로드 차단 |
| 학교 HWPX 원문 가져오기 | 파일 해시·신원 확인·Storage·추출 HTTP를 제한시간으로 감싸 원파일·원키를 보존. 만료 뒤 후속 RPC·추출·화면 갱신 차단 |
| AI 할 일 원본 | 사용자 확인으로 저장된 접수 결과의 원본 ID를 사용해 해당 할 일을 열고 비서로 돌아옴. 이동 자체로 새 저장이나 유료 호출을 하지 않음 |

학교 원문과 질문형 HWPX는 공통 `createScopedFileOperation`을 사용한다. 일반 파일 전송은 기존 공통 파일 제한시간, 원문 추출은 기존 HWPX 검사 예산을 유지한다. 제한시간은 UI에서 결과를 더 기다리지 않도록 하는 경계이며, 이미 외부로 나간 업로드/추출을 취소하거나 서버 처리 취소를 증명하지 않는다. 따라서 쓰기 만료는 결과 미상으로 남기고 원번호로 확인한다. 읽기 만료는 재조회 실패로 처리한다.

AI 할 일 원본 이동도 현재 학교·입력 잠금·미확정 요청 조건을 따른다. 목록에 아직 없는 원본은 기존 단건 조회로 확인하고, 조회 불가를 임의의 같은 제목 업무로 대체하지 않는다.

자동 시험과 현재 CI 수정 근거는 [verification.md](verification.md), 전체 구축과 남은 계약/설정은 [전체 상태표](../school-timetable-pilot/system-status.md)에 기록한다. 실제 회원 연결과 Claude 검토는 마지막으로 유지한다.

## 전체 메뉴 검색·과거 원문 조회 후속 묶음

[구축 결과와 남은 연결](search-history.md): 기존 12개 메뉴와 9종 업무 자료를 검색하고 문서·학교 자료의 정확한 판을 바로 연다. 과거 자료 조회 K1 SQL은 별도 준비물이며 운영 적용은 하지 않았다. 모바일 검색·입력 보관·권한 변경 보호를 포함하고 최종 시험 수는 해당 문서에 구분했다.

## 빈 문단 연결 후보 먼저 보기 (2026-10-21)

짧은 후속 작업으로 질문형 양식의 기존 검사 결과에서 아직 질문에 연결하지 않은 빈 문단을 먼저 표시한다. 빈 후보가 없으면 전체 위치를 보여 주고, 사용자가 전체 보기로 전환하면 글이 있는 위치도 기존처럼 선택할 수 있다. 연결·삭제에 따라 후보를 다시 계산하며 기존 원문, 질문, 요청 번호는 바꾸지 않는다.

- 판단: 빈 문단이 실제 입력란이라는 보장은 없으므로 자동 적합성 판정·질문 생성·일괄 연결은 하지 않는다. `GuidedAnchorPicker.tsx`에서 후보 표시를 조정할 수 있다.
- 검증: 후보/SSR 8건, 기존 문서함·질문형 수합 브라우저와 새 연결 흐름 15건, TypeScript·메인 빌드 통과. 가상 교사와 합성 서비스로 확인했다.
- 미완료: 자동 수합 방식 추천, 질문·칸 매핑 제안, 장기 AI 기억 관리. DB 적용·실제 회원 연결·Claude 검토는 계속 마지막 단계다.
