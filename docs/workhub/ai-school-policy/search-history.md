## 검색의 정확한 범위

- 메뉴는 현재 연결 업무실의 등록 메뉴 12개다. 신규 일반 교사 공개는 하지 않는다.
- 일정·개인 업무·수합·수업은 읽은 목록에서 검색한다. 날짜·협업 당사자 등의 로컬 필터와 서버 제목·본문 검색을 같은 범위라고 표현하지 않는다.
- 문서·학교 자료·협업의 **자료 검색**은 기존 SQL이 지원하는 입력 문구 검색이다. 단어가 떨어져 있는 AND 전문검색이나 의미 검색은 추가하지 않았다.
- 빈 검색으로 받은 문서·학교 자료 본문은 최대 320자 요약으로만 검색 상태에 둔다. 전체 본문에 있는 문구는 명시 검색으로 다시 조회한다. 대화는 제목과 참여자만 읽는다.
- 학생 기록 문서, 학생 명단·평가·상담 본문, 메시지 본문·첨부, AI 대화는 전역 검색 대상에서 제외한다.
- 자료원 동시 조회는 최대 3개, 한 번의 검색은 자료원별 최대 20쪽·4,000항목, 화면은 50건씩 표시한다. 끝까지 읽지 않았거나 연결에 실패한 범위를 전체 0건으로 표시하지 않는다.
- 검색어를 바꾸고 명시 검색하기 전에는 이전 검색의 커서로 다음 페이지를 읽지 않는다. 커서는 종류·학교·소속·검색어에 묶는다.
- 검색어와 선택 ID를 URL이나 브라우저 영속 저장소에 남기지 않는다. 닫힌 검색의 늦은 응답은 폐기한다. 권한 변경의 `CANCELLED` 응답은 앞서 읽은 다른 자료원 결과까지 지운다.
- 문서·학교 자료를 열 때 현재 접근 권한과 정확한 판을 다시 확인한다. 목록 조회는 저장 완료나 파일 다운로드 확인을 의미하지 않는다.

## DB 준비물과 남은 적용

[K1 계약과 실행 준비](../../../database/workhub-knowledge-history/k1/README.md)는 별도 패키지다.

- `K1-01_학교자료_판별조회.sql`: 기존 불변 원문판을 읽는 `workhub_knowledge_get`, `workhub_knowledge_history` 두 함수만 추가한다.
- `K1-02_사후점검.sql`: 함수 인자·소유자·권한·기존 판 기록 보호를 확인한다.
- 기존 P4 SQL·표·RLS·회원·활성화 값은 수정하지 않았다. 새 조회도 기존 P4의 모듈·작성자·관리자·학교 경계를 따른다.
- **K1 미적용 환경에서는 검색·AI 인용의 학교 자료 원문 직접 조회와 이전 판 목록이 준비되지 않은 상태다.** 최신 자료를 대신 보여 주지 않으며 기존 목록·편집 기능은 독립적으로 유지된다.
- 적용 전 최종 통합 지문을 갱신해야 한다. 기존 P4 고정 함수 개수 점검은 23개, K1 추가 후 25개이므로 기존 점검의 FAIL을 무시해서는 안 된다. 이번 K1 한정 점검이 전체 설치 승인이나 운영 전체 점검을 대신하지 않는다.

초기 브라우저 시험에서 가짜 문서 목록이 계약의 50건을 초과한 문제는 시험 자료를 현재/보관 두 페이지로 바로잡았다. 새 검색 범위가 9종으로 늘어 기존 2종 기대값도 갱신했다. 실제 앱에서 발견한 추가 조회의 권한 변경 후 결과 잔존과 모바일 상단 버튼 겹침은 코드 수정 및 회귀 시험으로 해결했다.

K1 격리 시험은 GitHub 필수 `test` workflow에도 추가했다. 작업 시작 시 #77 `76e59ab`의 test·Vercel은 성공이었다. 이번 커밋의 원격 검사는 업로드 후 별도로 확인하며, 로컬 통과를 원격 CI 성공이라고 기록하지 않는다.

## 판단해서 정한 것과 다음 작업

1. 별도 전역 검색 DB를 만들지 않고 기존 권한별 조회를 조합했다. 자료 중복 저장과 별도 권한 동기화를 피하기 위한 선택이다. 조회 동작과 한도는 `search/connected-sources.ts`, `limits.ts`, `WorkspaceSearch.tsx`에서 조정한다.
2. 과거 자료는 기존 불변 판을 읽는 두 함수로 확장했다. 오래된 문서를 현재 규정으로 잘못 사용할 수 있어 AI 재전달은 최신·유효·게시 판만 허용한다. 변경 지점은 `knowledge/KnowledgeCitationPanel.tsx`와 K1 계약이다.
3. 자동 양식 유형 추천·질문/칸 매핑 제안, 장기 AI 기억 관리는 아직 추가 구축 항목이다. PDF 원문 추출·임의 복잡 서식의 범용 작성도 기존 HWPX 기능과 구분한다.
4. 마지막 연결 묶음에는 준비 SQL들의 최종 통합 점검, 운영 적용, 서버 전용 설정·학교 API 키·Storage·모듈 활성화, 실제 회원 연결, Claude 검토가 남아 있다. 이번 작업에서는 실행하지 않았다.
