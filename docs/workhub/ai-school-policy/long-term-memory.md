# 개인 AI 장기 기억 관리

2026-10-21 · PR #77. 앱과 신규 M1 SQL을 함께 준비한다. 운영 DB 적용·실제 회원 연결·Claude 검토·활성화는 마지막 전환 단계로 보류한다.

## 교사의 사용 흐름

`AI 비서 → 나의 AI 기억 → 직접 작성·확인해 저장 → 필요할 때 선택 → 최신 내용 재확인 → 이번 질문에 복사 → 질문을 검토하고 전송` 순서다.

1. 업무 선호나 반복 업무 메모를 직접 등록한다. 예: ‘답변은 핵심부터 짧게’, ‘행사 계획에 준비물과 담당자를 함께 적기’.
2. 제목·본문·종류·사용 여부·선택적인 사용기한을 확인하고 저장한다. 대화나 학생 기록에서 자동 수집하지 않는다.
3. 검색해서 내용을 열고 수정·일시중지·다시 사용·삭제할 수 있다. 만료되면 새 질문에 넣을 수 없지만 확인·삭제는 가능하다.
4. 최대 5개를 선택하고 실제로 넣을 내용을 확인한다. 서버에서 같은 판인지, 중지·만료·삭제되지 않았는지 다시 확인한다.
5. 일반 학교 업무 안내·개인 비서·문서 초안의 현재 질문에 제목·본문을 복사한다. 이 단계에는 유료 AI 호출이 없다. 학생 기록 초안과 질문형 수합의 구조화된 요청에는 넣지 않는다.

기억 패널은 기본으로 접혀 있다. 열기 전에는 기억 조회를 하지 않는다. M1이 설치되지 않았거나 조회가 실패해도 일반 AI 질문 기능과 기존 입력은 유지한다.

## 보관과 사용의 정확한 범위

| 항목 | 구현 기준 |
|---|---|
| 소유 범위 | 현재 학교 + 원래 학교 소속의 본인만. 같은 학교 관리자도 다른 교사의 개인 기억을 읽는 경로 없음 |
| 내용 | 직접 확인한 업무 선호·반복 업무. 학생 개인·상담·건강 정보, 비밀번호를 저장하지 않도록 안내 |
| 한도 | 소속당 50개, 제목 80자, 본문 1,000자. 공통 `memory-limits.json`과 SQL 대조 시험으로 고정 |
| 선택 | 최대 5개. 현재 질문과 합친 결과는 기존 AI 질문 4,000자 한도를 지킴. 초과하면 자르지 않고 거절 |
| 사용기한 | 서버가 학교 현지 날짜로 판정. 비우면 직접 중지·삭제할 때까지 보관. 자동 삭제 작업 없음 |
| 삭제 | 현재 기억 표의 제목·본문을 비우고 목록에서 제외. 접수 원장에는 요청 해시·결과 식별정보만 남기며 본문 사본 없음 |
| 삭제의 한계 | 이미 질문에 복사한 내용, 보낸 대화, 공급자 입력, 내려받은 파일을 되돌리거나 삭제하는 기능이 아님 |
| AI 연결 | 명시적으로 선택한 내용의 **참고 사본**을 편집 가능한 현재 질문에 넣음. 모든 대화에 자동 주입하지 않음 |

기억은 학교 규정이나 학생 사실의 공식 근거가 아니다. 질문에 넣은 내용은 일반 사용자 입력으로 기존 AI 경로를 거치며, 모델·예산·권한·확정 명령을 바꾸지 않는다. 원래 AI 대화의 보관 정책도 변경하지 않는다. 소속 변경 후 이전 소속의 기억을 자동 이관하지 않는다.

## 오류와 입력 보존

- 저장 성공 응답에는 본문을 되돌리지 않고 접수증만 준다. 성공 뒤 현재 목록을 다시 읽으므로 과거 요청 복구가 삭제·수정 전 본문을 되살리지 않는다.
- 수정 중 판이 바뀌면 내 입력을 보존하고 최신 목록을 다시 읽는다. 바뀐 판에 예전 입력을 자동 덮어쓰지 않는다.
- 저장 결과가 미상이면 원래 명령과 요청 번호를 현재 탭 메모리에 보관한다. 같은 요청 결과 확인 또는 같은 내용·번호 재전송만 허용한다.
- ‘이 기억 요청 닫기’는 서버의 적용 접수증 또는 닫힘 확인 뒤에만 잠금을 푼다. 미접수 요청을 닫으면 늦은 원요청이 반영되지 않는다.
- 삭제 확인 중에는 다른 기억 편집을 시작하지 못하게 하여 삭제 결과가 새 입력을 지우지 않도록 한다.
- 계정·학교·소속이 바뀌거나 조회가 실패하면 이전 목록을 현재 목록처럼 표시하지 않는다. 작성 중·미확정 요청 보관은 현재 탭 메모리이며 브라우저 종료 이후 복구를 보장하지 않는다.

## 서버 준비와 나중 적용 순서

신규 패키지 경로는 `database/workhub-ai-memory/m1/`이다. 기존 R0~P8, 학교 자료 P9/P10, AI 비용 P10과 다른 패키지이며 기존 SQL을 수정하거나 재실행하지 않는다.

1. 마지막 통합 검토에서 M1과 다른 미적용 증분의 의존성·통합 지문을 함께 확인한다.
2. 승인 후 `M1-00` 사전 지문 → `M1-01` 모델·함수 설치 → `M1-02` 사후 점검 → `M1-00` 재대조를 실행한다.
3. 앱 배포와 실제 PostgREST 왕복을 확인한다. 최초 학교 제어값은 꺼짐이다.
4. 사용자가 적용 시점을 승인한 뒤 `M1-03` 학교 승인 양식을 채운다. 켜기/끄기는 기억의 새 저장·수정·선택 사용을 제어한다. 본인 조회·삭제·원요청 복구·닫기는 유지한다.

이 문서는 실행 준비 설명이며 지금 운영에 실행하라는 안내가 아니다. 실제 API 키·모델 호출 없이 격리 PostgreSQL 17과 가상 교사의 응답으로 검증한다. 자세한 자동 검증 수치는 [verification.md](verification.md)에 기록한다.

## 남은 작업

- 다른 미적용 SQL까지 포함한 최종 통합 점검과 M1 운영 설치·학교 승인.
- 실제 Supabase/PostgREST와 앱의 왕복 확인, 기존 회원 연결 뒤 본인 소속별 접근 확인.
- AI 서버·키·예산의 마지막 설정과 실제 모델 응답 확인. 현재 기억 기능 시험이 실제 모델 품질·과금을 증명하지 않는다.
- 자동 기억 추출·전 대화 자동 주입·이전 대화까지 소급 삭제·학교 간 기억 이관은 이번 구현 범위가 아니다. 필요하면 별도 목적과 보관 정책을 먼저 정한다.
