# 수합 방식 추천·질문과 빈칸 연결 제안

2026-10-21 · PR #77 후속. 기존 HWPX 검사 결과와 질문형 수합 계약을 사용한다. 이번 묶음은 SQL·실제 회원·키·모델·예산·메뉴 공개 범위를 바꾸지 않는다.

## 담당자가 사용하는 순서

1. 문서함의 질문형 수합 양식에서 검사된 HWPX 초안을 연다.
2. 빈 문단 수, 이미 연결한 질문, 검사 범위 밖 문단에 따른 수합 방식 안내를 본다. 최종 방식은 담당자가 고른다.
3. 질문형을 고르면 아직 연결하지 않은 빈 문단과 앞 문단의 짧은 문맥을 확인한다. 짧은 콜론 항목 이름은 질문 초안에 넣고, 불명확하면 질문을 비워 둔다.
4. 필요한 후보만 선택하고 질문·답변 형식·필수 여부·길이·선택 항목을 조정한다.
5. 필요하면 선택한 후보를 기존 비서로 보낸다. 전달 범위를 확인한 뒤 비서 화면에서 실행해야 기존 Haiku·학교 예산 정책으로 요청한다. 기존 명시적 Sonnet 정밀 검토도 유지한다.
6. 돌아온 AI 제안은 원본을 다시 조회한 뒤 표시한다. 위치와 질문을 확인하고 필요한 후보를 선택해 편집 화면에 반영한다.
7. 기존의 `질문·위치 매핑 저장`을 눌러야 서버에 저장된다. 교사의 답변 저장·HWPX 생성·명시 첨부·최종 제출은 기존 절차를 따른다.

파일형을 고르면 기존 수합 화면으로 이동한다. 원본 파일·대상 교사 등록은 그 화면에서 하며, 추천 선택만으로 수합을 만들거나 파일을 자동 이관하지 않는다.

## 추천의 정확한 범위

| 검사 결과 | 안내 |
|---|---|
| 연결하지 않은 빈 문단이 있고 복합 문단이 없음 | 질문형 검토 가능 |
| 빈 문단이 없거나 질문 용량을 다 사용함 | 원본 확인 후 방식 선택 |
| 복합 문단이 있음 | 원본 확인 후 방식 선택. 표를 감싼 문단도 포함될 수 있어 개수만으로 파일형으로 단정하지 않음 |
| 미연결 빈 문단이 양식의 전체 질문 한도보다 많음 | 파일형 우선 검토. 필요한 일부 칸만 질문으로 받을 수도 있음 |

빈 문단은 여백일 수도 있으므로 입력란이라고 보장하지 않는다. 후보는 기존 질문 한도에서 남은 개수까지만 표시하고 나머지 위치는 기존 원본 목록에서 직접 연결할 수 있다. 글이 있는 문단을 새 후보로 덮어쓰지 않는다.

검사 계약에는 표 식별자가 없으므로 행·열이나 인접성만으로 같은 표의 질문이라고 단정하지 않는다. 같은 절의 바로 앞 문단만 참고로 표시한다. 긴 문맥은 임의로 자르지 않고 제외하며, 한도는 `guided-suggestions.json` 자산에서 관리한다.

## AI 전달과 반영 계약

- 기존 `guided_collection` 요청을 사용한다. 새 RPC·SQL·유료 자동 호출은 추가하지 않는다.
- 프롬프트에는 양식 제목, 선택한 위치 ID, 제안 질문, 화면에 표시된 짧은 앞 문단만 포함한다. 저장된 답변·전체 원문·파일 해시를 AI 프롬프트에 넣지 않는다.
- 원본의 파일 해시·검사 위치·저장 매핑·답변판은 브라우저의 제안 출처 정보에 보관해 돌아온 제안과 대조한다.
- AI 응답은 방식·이유·질문 배열로 검증한다. 선택하지 않은 위치, 중복 위치, 모르는 필드·형식·범위를 거부한다. AI가 원문·해시·위치를 새로 정의하지 못한다.
- 일부 질문만 돌아오거나 질문이 0개인 결과는 허용한다. 모르는 칸을 억지로 채우지 않는다.
- 제안 반영은 기존 질문을 유지하면서 선택한 질문만 뒤에 추가한다. 기존 답변과 원문은 바꾸지 않는다. 하나라도 검증에 실패하면 전체 반영을 중지한다.
- 직접 수정한 후보는 먼저 반영하거나 원본 기준으로 되돌린 뒤 AI에 보낸다. 수정 내용을 몰래 버리고 다른 내용으로 요청하지 않는다.

## 원본 변경·복구

AI 전달 전, AI 복귀 시, 편집 화면 반영 전에 현재 양식을 조회한다. 학교·소속·작성 권한·초안 상태·양식 ID/판·파일/검사/매핑·답변 ID/판이 맞아야 진행한다. 배경 갱신이나 학교 변경 뒤 늦게 온 응답은 반영하지 않는다.

AI 복귀 원본 조회에 실패하면 `돌아온 제안 다시 확인`으로 조회만 재시도한다. 공급자를 다시 호출하지 않는다. 형식이 잘못된 AI 제안을 읽기 재시도로 고쳐지는 것처럼 표시하지 않으며 기존 질문은 그대로 둔다.

후보 편집과 선택은 학교·소속·양식 ID/판별 같은 탭 메모리에 보관한다. 다른 양식을 보고 돌아와도 유지되지만 최종 확인은 다시 받는다. 브라우저 종료·새 탭 이후 복원이나 장기 AI 기억을 뜻하지 않는다.

매핑 저장 결과가 불명확할 때는 기존 저장 번호와 원래 명령으로 복구한다. 제안 번호를 새 저장 번호로 바꾸거나 자동 저장하지 않는다.

## 자동 검증

최종 전체 시험 수와 빌드 결과는 [verification.md](verification.md)에 기록한다.

- 추천/후보: 용량·기존 연결·빈 원문·문맥·질문 형식·중복·변조·원자적 반영 및 SSR.
- AI 계약 22건: 선택한 문맥만 전달, 길이 초과 거절, 위조/중복/추가 필드 차단, 원본판·답변판 대조.
- 새 브라우저 17건: 실제 업무실→비서→양식 복귀, 명시 반영·저장, 기존 질문·답변 보존, 권한/판/학교/revision 변경, 늦은 응답, 같은 번호 복구, 양식별 편집 보존, 무료 조회 재시도, 320px.
- 기존 관련 브라우저: 문서함·답변 AI·문서 생성/수합·문서 열기 4파일 58건, 전체 연결 18건 통과.

브라우저 시험은 실제 React·서비스 어댑터·응답 parser를 사용하며 DB·Storage·공급자 응답은 합성이다. 실제 Claude의 추천 품질·운영 Supabase 왕복·학교 실문서 적합성을 시험한 것은 아니다.

## 이번에 판단한 것과 남은 일

1. 단순 추천은 기존 검사 결과로 즉시 제공하고, AI는 선택 후보의 질문·방식 제안을 맡겼다. 새 비용 정책이나 SQL 없이 사용할 수 있고 모든 후보를 공급자에 전송하지 않는다.
2. 방식 선택·질문 반영·서버 저장을 구분했다. 잘못된 추천이 문서와 제출 상태를 자동 변경하지 않게 한다.
3. 기존 질문 편집이 남아 있으면 먼저 저장하게 했다. 미저장 편집과 새 원본을 섞어 저장하지 않는다.
4. 변경 지점은 `guided-suggestions.ts`/자산(로컬 추천), `guided-setup-ai.ts`(AI 계약), `GuidedSetupPanel.tsx`(화면)로 나눴다. 기존 수합 저장·생성 엔진은 그대로다.

남은 구축은 장기 AI 기억의 목록·확인·수정·삭제·보관 범위와 서버 계약이다. 운영 적용·서버 설정·학교 키 등록·실제 회원 연결·최종 Claude 검토는 기존 계획대로 마지막 단계에 진행한다. 이번 제안 기능 자체에 추가 SQL은 필요 없다.
