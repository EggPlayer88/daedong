# 6차 개발 — 오늘의 업무와 원본 찾기

작성일: 2026-10-12 · 기준: 5차 사이트 기본 구조(PR #10)

## 목적과 범위

DB 구축은 사용자의 요청으로 보류하고, 5차에서 연결한 공통 사이트 구조를 이어 개발했다. 교사가 홈에서 자신의 할 일을 구분하고 필요한 원본으로 이동하는 흐름을 구체화했다. 기존 로그인·회원 자료와 서버 어댑터 계약을 재사용한다.

이번 증분은 화면·읽기 조합·시험·문서다. SQL, 인증·가입 승인, AI 모델·키·비용, 외부 서비스 설정, 운영 공개 범위는 변경하지 않는다. 시간표도 보류한다. 사이트 AI는 사용자가 지정한 Claude를 전제로 유지한다.

## 교사가 보는 변화

| 공간 | 동작 | 현재 연결 수준 |
|---|---|---|
| 오늘 — 내 업무 | 기한 지남·오늘까지·예정·기한 없음의 미완료 건수, 우선 4건과 짧은 메모 | 같은 TaskPanel을 합성 저장소와 기존 서버 어댑터에 연결 |
| 오늘 — 수합 | 제출 책임·공동작성·지정 검토·제출 후 대기를 구분하고 정확한 제출 단위로 이동 | 합성 미리보기만 |
| 공통 헤더 — 업무 찾기 | 제목·내용·표시 정보 검색, 종류 선택, 원본 열기 | 연결 화면: 일정·개인 업무 / 미리보기: 수합 추가 |
| 원본 | 일정 상세, 완료 업무 포함 최신 업무 카드, 해당 수합 요청·단위 | 기존 열람 함수로 다시 확인, 편집 자동 시작 없음 |

등록·수정 동작을 새로 복제하지 않는다. 검색·홈 요약은 동일한 원본을 읽어서 연결하는 입구다. 새로운 모듈을 공개하거나 연결 전 수합·학생을 실제 메뉴에 추가하지 않는다.

## 홈의 분류 계약

개인 업무에서 `done`과 `cancelled`를 제외하고 현재 학교의 기준일로 기한을 분류한다. 오늘까지는 기준일과 같은 기한이며 예정은 기준일 이후 전체다. 기한 없는 업무는 마지막에 두며 전체 목록의 기한 필터로 연결한다. 조회 중·실패는 0건으로 표시하지 않는다. 간단 메모는 Unicode 글자 단위로 90자까지 표시하고 원문을 변경하지 않는다.

수합은 기존 `listCollections → listUnits → unitSummary`를 사용한다. 응답 초안 본문이나 전체 저장 스냅샷을 읽지 않는다. 담당자라는 이유만으로 모든 요청을 개인 할 일로 세지 않는다.

| 구분 | 판단 기준 | 행동 |
|---|---|---|
| 내 제출 필요 | 본인이 책임자이고 미제출·보완 요청이 남음 | 응답 작성·제출 또는 보완 제출 |
| 공동작성 참여 | 참여 단위에 미제출·보완이 남음 | 공동 초안 작성, 최종 제출 권한은 책임자 유지 |
| 내 검토할 일 | 본인이 지정 검토자이며 현재 제출판이 검토 대기 | 해당 단위의 제출판 검토 |
| 제출 후 검토 대기 | 본인 책임/참여 단위의 현재 제출판이 검토 대기 | 접수 상태 확인; 직접 처리할 건수에서 제외 |

한 단위의 역할이 겹쳐도 카드·건수는 중복하지 않고 역할을 함께 표시한다. 전체 합계에서 우선 4개 카드만 보여 주고 수합 전체로 연결한다. 완료본이 있어도 남은 보완은 표시한다. 여러 보완 기한은 가장 이른 미완료 기한을 기준으로 홈과 상세를 일치시키며 상세에 남은 기한 목록을 함께 표시한다.

## 검색과 화면 이동 계약

```text
WorkspaceShell의 업무 찾기
  ├─ 일정: 현재 소속의 CalendarAdapter.list → 열람 가능한 일정
  ├─ 내 업무: TaskAdapter.list → 기존 응답 검증 → 본인 업무
  └─ 수합: WorkflowStore.listCollections → 요청 메타데이터 (미리보기)
               ↓ 공백·대소문자·한글 NFC 정규화, 모든 검색어 일치
          최대 50개 표시 / 전체 일치 건수 안내
               ↓ 기존 편집 보호를 통과한 화면 이동
     일정 상세 / 최신 개인 업무 카드 / 정확한 수합 단위
```

- 검색창을 열 때만 각 범위를 조회한다. 다른 범위가 실패해도 성공한 결과를 남기고 실패한 범위만 재시도한다. 일부 조회 실패를 전체 0건으로 오인하지 않게 표시한다.
- 첫 결과는 제목 완전 일치·앞부분 일치·제목 포함·나머지 순으로 정렬한다. 검색은 현재 조회된 자료에 대한 클라이언트 검색이며 전국 자료 검색이나 AI 검색이 아니다.
- 수합 검색은 요청 제목·안내·기한·역할 정보만 다룬다. 학생 기록·수합 답변·문서 본문은 검색 범위에 넣지 않는다.
- 검색어·결과·원본 ID는 주소와 영속 저장소에 쓰지 않는다. 닫기, 학교·계정 변경은 결과를 비우고 늦게 도착한 이전 조회를 무시한다. 화면 이름의 기존 `?view=` 동작은 유지한다.
- 원본 선택에는 일회성 요청 번호를 부여한다. 같은 원본 재선택도 처리하되 목록 새로고침마다 원본을 반복해서 열지 않는다.
- 업무 원본은 `get` 응답을 기존 검증기로 확인한다. 완료 업무도 필터를 풀어 표시하며 목록보다 최신 원본을 유지한다. 없는 원본은 늦은 목록 응답으로 부활하지 않는다.
- 수합은 원본이 속한 받은/내가 만든 목록을 선택한다. 본인 비공개 초안을 열었는데 왼쪽 목록이 비어 보이는 모순을 없앴다. 요청한 제출 단위가 없거나 열람 불가이면 임의의 다른 단위를 선택하지 않는다.
- 검색창의 취소는 실행 버튼으로 초점을 돌린다. 원본 선택 성공은 목적지의 초점을 유지한다. 페이지를 벗어나면 이전 일정 상세를 닫는다.
- 입력 중·저장 결과 확인 중에는 기존 이동 보호를 사용한다. 현재 계정의 접근 상실을 이동 보호로 막지는 않는다.

## 판단해서 정한 것

| 선택 | 이유 | 변경 위치 |
|---|---|---|
| DB를 기다리지 않고 현재 어댑터에 검색 연결 | 실제 서버 계약을 추측해 추가하지 않고 화면 동선을 완성 | `search/sources.ts`, `ConnectedWorkspace.tsx` |
| 같은 자료를 홈과 검색에서 원본으로 연결 | 복제된 할 일이나 수합 상태가 서로 달라지는 것을 방지 | `app/resource-navigation.ts`, `PreviewApp.tsx` |
| 대기와 행동 필요를 분리 | 제출한 교사에게 다시 제출해야 하는 것처럼 보이지 않게 함 | `workflows/presentation.ts` |
| 원본은 자동 편집하지 않음 | 찾기 행동만으로 작성 상태가 되거나 내용이 바뀌지 않게 함 | `TaskPanel.tsx`, `CalendarPanel.tsx`, `WorkflowPanel.tsx` |
| 검색 결과 50개 표시, 서버 검색은 후속 | 기본 동선을 먼저 검증하고 대규모 검색 성능을 과장하지 않음 | `search/WorkspaceSearch.tsx`, `search/presentation.ts` |

## 검증과 한계

전체 `npm test` 1,015건(Python 포함), 신축 TypeScript 검사, 기존·신축 빌드를 통과했다. 신규 자동 시험 53건은 업무 기한 12, 역할별 수합·기한·직접 열기 17, 검색 소스 8, 검색 UI·비동기 상태 16건이다.

실제 Chrome 시험은 `tests/browser/workhub-home-search.mjs`(공통 홈·검색·원본·학교 변경·연결 화면), `workhub-task-navigation.mjs`(원본 최신판·지연 응답·학교 변경), 기존 공통 구조·탐색·연결·일정 복구·수합과 학생 흐름을 사용한다. 모든 자료와 인증 응답은 합성이며 실제 교사 자료를 읽거나 쓰지 않는다. 실행 결과와 오프라인 검증은 [누적 현황](PROGRESS.md)에 기록한다.

실제 Supabase 적용·Google 로그인 종단 검증·운영 배포는 이번 결과에 포함되지 않는다. 수합과 학생은 미리보기 단계다. 대량 자료에서 서버 검색·페이지 나누기·검색 제한은 실제 DB 구축 시 권한 계약과 함께 설계해야 한다.
