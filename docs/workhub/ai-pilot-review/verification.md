## 검증 구분

브라우저 시험은 실제 React·전송 어댑터·parser를 사용하고 DB/RPC/Storage/provider 응답은 합성이다. 실제 새로고침과 `sessionStorage`, 페이지 크기 변경, 선택창 Escape, 오류 주입·원요청 복구를 확인한다. 독립 시험 사례는 합성 fixture 진입 시 보관함을 비우며, 새로고침 복구 전용 시험은 이를 비우지 않고 6가지 흐름을 검증한다. 기대 결과나 권한 판정을 낮추지 않았다.

모바일 폭은 390×844, 390×360, 320×420 등에서 실제 클릭 위치·가림을 검사했다. 실제 휴대폰 OS 키보드/IME 확인과 같지 않다.

초기 제한 환경에서 Git Bash·로컬 HTTP 테스트가 실행되지 않은 항목은 로컬 실행 권한을 갖춘 환경에서 전체 재실행해 통과했다. 운영 주소·DB DSN·API 키는 사용하지 않았다.

## 새 회귀의 주요 근거

- B1: 계획 instance/단계/질문 원키/접수증을 대조한다. 확정 완료 재선택 거절, 결과 유실 재확인, 뒤늦은 답변의 다른 계획 연결 거절.
- B2·B7·B9: 질문형·존댓말·희망 표현·두 문장·요일·시각 ‘반’, 검색어 정리·무결과 입력 유지. 저장 중과 결과 미상에서는 이어 입력 버튼이 없다.
- B3: 실제 RPC로 본인 제외·학교 격리·공동작성자 중복·동시 재전송·알림 INSERT 실패 롤백을 확인한다. 기존 자료 지문 유지, 신규 객체 11개만 추가.
- B4: 계정/소속 재검증 전 비노출, 명시 복원/버리기, 접힌 메시지 원문, 원키 및 계획 접수증 보존, 파일 재선택, 복원 자동 저장 0, 저장소 실패·변조 방어.
- B5·B6·B10: 권한 밖 예시와 원본 없는 질문형 전달 제한, 기본 시간표 대체 조회 표시, 오류를 AI 내부에 표시하고 답변 유지.
- R6: 수정 전 완료된 할 일 화면이 다음 일정을 막는 경로 재현. 완료 결과만 닫고 미저장·결과 미상 잠금은 유지.
