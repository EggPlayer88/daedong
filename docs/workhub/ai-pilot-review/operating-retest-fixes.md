## 변경 범위

| 항목 | 반영 내용 |
| --- | --- |
| F1 필수 | 관리자·시험 교사의 메시지 알림에서 `메시지 원본 열기`를 표시한다. 알림의 `source.id`를 기존 `openRequest`에 전달해 정확한 대화를 연다. 일반 메시지 메뉴·AI 안의 알림·업무 참여 화면을 함께 연결한다. |
| U2 | 복구할 입력의 종류를 목록으로 표시하고, 미확정 요청이 없으면 먼저 열 업무를 선택한다. 다른 입력도 기존 저장소에 복구해 보존한다. |
| U3 | 원래 요청 결과를 확인해야 하는 할 일 카드에는 입력 오류를 겹쳐 표시하지 않는다. 실제 입력 검증과 손상된 요청 차단은 유지한다. |
| U4 | 요청이 정상 진행 중이면 처리 중 문구를 표시한다. 결과를 잃었거나 새로고침으로 복원한 경우에만 미확정 요청 패널을 표시한다. |
| U5 | `… 할 일 추가하고, … 일정도 추가해줘`처럼 업무 두 개가 명시된 문장을 기존 업무 나누기의 후보로 만든다. 선택 전에는 실행하지 않는다. 더 넓은 표현에는 번호를 붙여 줄을 나누는 방법을 안내한다. |

SQL 실행은 필요 없다. 기존 NT1, DB·권한·공개 범위·모델·예산·파일 생성 방식과 실제 자료·시험 자료는 변경하지 않는다. 운영 전체 점검 기준은 INT-15다.

## 판단해서 정한 것

- 알림을 열 때 대화 조회만 한다. 메시지 전송, 알림 읽음, 업무 완료를 자동 실행하지 않는다. 원본 조회의 현재 권한 확인과 늦은 응답 배제는 기존 메시지 경로를 그대로 사용한다.
- U1 자동 읽음 연계는 보류한다. 현재 알림 계약에는 메시지 순번이 없고 알림 목록은 페이지로 나뉜다. 클라이언트가 대화에 속한 알림을 모두 읽음 처리하면 아직 화면에 보지 못한 새 답장까지 처리할 수 있다. 정확한 연계를 하려면 기존 `read_thread`의 확인 순번과 알림을 연결하는 별도 계약 검토가 필요하다.
- U2는 일부 자료를 선택적으로 삭제·복구하는 새 저장소가 아니다. 보관한 입력을 모두 유지하면서 먼저 보여 줄 화면만 선택한다. 결과 미확인 요청이 하나라도 있으면 화면 선택 버튼을 숨기고 기존 요청 번호 복구를 우선한다. 본문·수신자·학생 정보는 복구 선택 전 목록에 노출하지 않는다.
- U5는 모든 `하고`를 자르는 방식이 아니다. 할 일과 일정의 종류·동사·쉼표가 명시되고 두 단계가 기존 파서에서 각각 검증될 때만 후보로 표시한다. 원문 전체는 계획에 보존한다. 인용문·검색어·메시지 본문·조건부 부탁을 임의로 분리하지 않는다.
- 되돌릴 때는 이 PR의 화면·파서·시험 변경만 되돌리면 된다. 운영 SQL·시험 계정·자료에 대한 되돌리기 작업은 없다.

## Claude 재검토 뒤 R1·R2 보완

`faa4bfc5`는 Claude 재검토에서 병합 전 필수 결함 없음으로 확인되었고, CI의 전체 시험 5,873건·브라우저 204/204파일 및 Vercel 미리보기도 통과했다. 이후 아래 비차단 권장 두 건을 같은 PR에서 추가 보완한다.

- **R1 조건부 요청**: `자료 확인 할 일 추가하고, 비가 오면 내일 회의 일정도 추가해줘`가 두 개의 독립 업무로 나뉘는 것을 수정 전 재현했다. 접속문장의 인용 밖 `-면` 어절을 보수적으로 판단해 업무 후보 분리를 중단하고, 기존 번호·줄바꿈 안내를 제공한다. 동사를 몇 개 열거하는 방식으로는 `오면·가면·주면` 등을 빠뜨릴 수 있어 어미 기준으로 보강했다. 인용한 제목·본문은 유지하며 단일 요청과 번호 목록의 기존 문법은 변경하지 않는다. 인용하지 않은 `화면` 등 명사도 접속문장 안에서는 확인 안내로 보류될 수 있다.
- **R2 돌아갈 위치**: 알림에서 연 대화는 `업무 알림으로 돌아가기`를 표시한다. 관리자 일반 메뉴·AI 안·업무 참여 화면 모두 동일하며, 실제 홈에서 연 대화의 `홈으로 돌아가기`는 유지한다. 돌아갈 때 원본 조회 세대를 종료해 늦은 응답이 대화를 다시 열지 않도록 한다. 작성 중·미확정 요청의 잠금과 접어 둔 답장 입력, 미읽음 상태는 유지한다.

이번 보완도 SQL·DB·권한·공개 범위·비용 정책을 변경하지 않는다. R1의 보수적인 판정과 R2의 화면 출처는 해당 파서·열기 요청 메타데이터에서만 정의하며 서버 계약으로 전달하지 않는다.

추가 검증: 최종 `npm test` 전체 **5,875건 통과**, 실패·건너뜀 없음. 조건부 문장 관련 단위 시험 93건과 브라우저 50건(업무 나누기 14·메시지 알림 23·기존 홈 메시지 13)도 통과했다. 형식 검사와 운영 앱 빌드도 통과했다. 전체 시험의 첫 실행에서 변경하지 않은 CP-SAT 시험이 실패했으나, 동일 시험의 단독 재실행 29건과 전체 재실행 모두 통과했다. 최초 실행 로그가 오류 끝부분만 보관해 실패 원인은 확정하지 않는다. 제품·시험 기대값·설정을 바꾸지 않고 전체 재실행에서는 다른 무거운 검증을 병렬 실행하지 않았다. 새 커밋의 CI 결과는 PR에서 별도로 확인하며 이전 커밋의 성공으로 대신하지 않는다.

추가 재검토는 R1의 조건부 문장·인용문 보존, R2의 출발 위치·돌아가기·작성 중 잠금·늦은 응답 배제를 중심으로 한다. 운영 자료나 유료 모델 호출 없이 합성 응답 시험으로 확인할 수 있다.
