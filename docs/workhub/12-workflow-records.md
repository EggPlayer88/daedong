# 7차 개발 — 수합 진행 현황과 학생 기록 찾기

작성일: 2026-10-12 · 기준: 6차 홈·업무 찾기(PR #13)

## 개발 범위

사용자의 DB 구축·시간표 보류 요청을 유지하면서 기존 수합과 학생 기록 화면을 이어 개발했다. 요청이 많아졌을 때 처리할 제출 단위를 찾고, 기록이 쌓였을 때 학생과 기간에 맞는 근거를 확인하는 작업을 다룬다.

이번 기능은 합성 자료 미리보기에 적용한다. 실제 연결 메뉴는 일정·개인 업무까지 유지하며 운영 교사에게 수합·학생 메뉴를 새로 공개하지 않는다. SQL, 기존 로그인·회원, 권한 계약, 문서 엔진, AI 공급자·비용, 외부 서비스 설정은 변경하지 않는다. 사이트 AI는 Claude를 전제로 한다.

## 수합 담당자의 작업

받은 수합과 내가 만든 수합의 기존 구분 안에서 요청을 찾고, 선택한 요청의 제출 단위 현황을 확인한다. 진행 표에서 원하는 단위의 원본으로 이동한 뒤 작성·제출·검토·보완의 기존 동작을 수행한다.

| 화면 정보 | 판단 기준 |
|---|---|
| 제출 단위 | 현재 소속으로 열람 가능한 단위. 공동작성자 여러 명도 한 부 |
| 미제출 | 현재 유효 제출이 없는 단위. 초안 본문은 진행 표에서 읽지 않음 |
| 검토 대기 | 현재 제출판이 지정 교사의 검토를 기다림 |
| 보완 필요 | 미완료 보완 요청이 남음. 완료본이 있어도 숨기지 않음 |
| 완료 | 검토 불필요 제출 또는 검토 완료본. 실제 원본 상태에서 계산 |
| 완료본과 새판 | 과거 완료본과 현재 처리 중인 새 제출판을 함께 표시 |
| 숫자 합계 | 기존 collectionSummary의 완료본만 집계. 필터 결과·초안으로 대체하지 않음 |

최초 제출이 늦었던 이력, 현재 미제출 상태의 기한 초과, 보완 기한 초과를 같은 의미로 합치지 않는다. 진행표의 다섯 상태는 서로 배타적이며 남은 보완을 먼저 분류한다. 별도로 표시하는 제출·완료본·보완 이력 지표는 서로 겹칠 수 있으므로 그 건수를 더해 전체 단위 수로 계산하지 않는다. 교사가 현재 보고 있는 범위와 원본의 전체 집계 범위를 화면에 구분한다.

진행표는 20부씩 표시하되 기존 단위 상세는 유지한다. 이 화면 페이지 처리는 서버 페이지 조회나 전체 상세 렌더링의 대규모 최적화를 대신하지 않는다. 모바일에서는 표 내부를 좌우로 이동해 기한과 원본 이동 버튼을 확인한다.

요청 찾기·진행 표 필터는 읽기 기능이다. 검색이나 필터를 바꿨다고 제출·검토·완료 처리가 이루어지지 않는다. 기존 원본 상세와 편집 상태를 보존하고, 작성 중인 내용을 숨기거나 없애는 이동은 기존 EditSession을 통과한다.

## 교사의 학생 기록 찾기

명부는 해당 수업 기준일에 승인된 수업·수강·학적의 결과만 사용한다. 이름과 번호는 찾기 위한 표시 정보이며 학생 ID를 대신하지 않는다. 명부를 검색해도 선택한 학생이 다른 학생으로 자동 변경되지 않는다.

기록 검토 범위는 선택한 학생·현재 수업과 본인의 전체 기록을 구분한다. 전체 기록에서는 현재 담당 수업 목록에서 빠진 이전 수업의 기록도 기존 작성자 조회 범위 안에서 찾을 수 있다. 기간·기록 종류·유효/재검토/철회 상태로 범위를 좁힌다.

수업 기준일과 기록 검색 기간은 별개다. 검색 기간을 바꾸는 동작은 새 관찰 또는 정정 대상의 발생일을 바꾸지 않는다. 학적·수강·담당 배정은 종료일 제외, 공통 소속의 validThrough는 마지막 유효일 포함이라는 기존 계약을 유지한다.

학생 관찰·정정·철회 입력과 외부 활동의 채택 입력을 필터 변경으로 버리지 않는다. 필터 0건, 현재 날짜 명부 없음, 본인 기록 없음, 조회 실패는 다른 상태로 안내한다. 다른 교사 자료는 검색·건수·미리보기·출력 어느 범위에도 보태지 않는다.

## 근거 출력의 범위와 최신성

현재 근거 출력은 기존 exportEvidence(member.id)가 검증하는 **현재 학교의 본인 전체 유효 기록**이다. 화면에서 보고 있는 학생·기간 필터의 일부 출력이라고 표시하지 않는다. 필터로 재검토 기록을 숨겨도 전체 근거 검증을 우회할 수 없다.

텍스트 파일을 내려받기 직전에 원본을 다시 검증한다. 원자료판·질문판·학생 연결판이 바뀌어 재검토가 필요해진 경우 오래된 텍스트 파일을 만들지 않는다. 이전에 내려받은 파일의 자동 회수나 공식 생기부 입력 기능으로 설명하지 않는다.

## 구현 경계

```text
수합 요청 목록/진행 표                    학생 명부/기록 보기
    listCollections                          listCourses/listStudents
    listUnits/unitSummary                    listRecords/listActivities
    collectionSummary                        exportEvidence (출력 시 재검증)
              │                                         │
      기존 열람 범위의 읽기 결과 → 화면용 분류·검색·요약
              │                                         │
      기존 수합 단위 상세                         기존 관찰/정정/철회 폼
              └────────── EditSession 입력 보호 ──────────┘
```

표시용 선택 함수는 이미 허용된 결과를 분류하는 함수이며 서버 권한 검사를 대신하지 않는다. 원시 저장 스냅샷을 사용자 화면 조회에 사용하지 않는다. 합성 store와 운영 어댑터의 구분을 유지한다.

## 검증 및 운영 전 남은 작업

전체 자동 회귀 1,046건, TypeScript 검사와 기존·신축 앱 빌드가 통과했다. 신규 단위·SSR 31건과 실제 Chrome 회귀 63개(새 수합 10, 새 학생 기록 13, 기존 흐름·기본 구조·검색 32, 독립 HTML 8)를 포함한다. 별도 교차검토의 근거 출력 Chrome 재현 4개도 통과했다. PC·390px 화면을 이미지로 확인했고 오프라인 파일은 360px에서도 확인했다. 자세한 실행 결과는 [누적 진행 현황](PROGRESS.md)에 기록한다.

DB 재개 전에는 합성 상태의 업무 동선과 오류 복구를 검증할 수 있다. 실제 서비스 전환에는 통합 DB 설계 확정·검증 환경 적용, 작성자 전용 학생 조회와 수합 권한의 서버 강제, 실제 계정·학교·명부 연결이 필요하다. 파일 수합·문서 생성·디지털윤리 수업의 실제 데이터 연결·Claude 에이전트는 후속 구현이다.

이번 작업이 문서 출력과 학생 기록의 법적·운영 적합성 확인을 대신하지는 않는다. 실제 학생 자료를 넣기 전에 기존 계획의 자료 범위·보존·정정 정책을 확인해야 한다.
