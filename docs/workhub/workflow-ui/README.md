# 메신저·수합·내 업무 입력 화면 정리

> 2026-10-28 마감: #85–#97은 main에 병합·운영 배포됐다. 현재 상태와 보류 범위는 [UI·UX 운영 마감 기록](../ui-ux-closeout/README.md)을 따른다. 아래 검증 내역은 각 작업 당시의 기록이다.

PR #86을 포함한 main `71c04e7`에서 이어지는 화면 작업이다. 운영 화면 확인은 사용자 요청에 따라 뒤로 미루고, 실제 React에 합성 서버 응답을 연결해 검증한다.

| 화면 | 이번 변경 | 유지하는 처리 |
| --- | --- | --- |
| 메신저 | 넓은 화면에서 받는 사람과 본문을 나란히 배치. 선택 인원·대상 표시, 소속 번호 상세, 본문 아래 HWPX 첨부, 하단 전송 전 확인 | 수신자 재확인, 전송 방식별 공개 안내, 확인 후 전송, 원래 요청 번호 복구, 파일 검사·제외, 입력 보관과 이동 잠금 |
| 수합 작성 | 내용 → 제출 대상 → 양식 순서. 대상 이름·소속 검색, 대상과 파일을 나란히 배치. 검토·추가 질문은 선택 설정으로 정리 | 단위별 책임·공동 작성자, 대상 검증, HWPX 검사·업로드, 초안과 공개의 구분 |
| 수합 제출 | 작성 제목·입력·저장 영역을 같은 체계로 정리. 제출 단계 안내와 최종 제출 경계를 유지 | 입력 보존, 보완 요청, 저장 후 책임 교사의 명시적 최종 제출, 충돌·권한 검사 |
| 내 업무 | 제목·기한을 첫 줄에 배치하고 개인 메모와 저장 영역을 분리. 중복 화면 제목 축소 | 제목 120자·메모 2,000자 한도, 기한 선택, 저장·충돌·재전송·취소 처리 |

공통 카드·입력·하단 행동 영역은 `apps/workhub/src/app/composer-layout.css`를 사용한다. 기존 프리텐다드·토스페이스와 화면 설정을 이어받는다. 작은 화면에서는 세로로 배치하며 큰 글씨와 어두운 화면에도 대응한다.

## 판단해서 정한 것

1. **중요한 입력은 접지 않는다.** 메시지 수신자·본문, 수합 제목·기한·대상·양식, 업무 제목·기한·메모는 바로 보인다. 선택 설정만 접고, 오류·복구·최종 확인은 항상 기존 위치에 남긴다.
2. **소속 번호는 필요할 때 펼친다.** 이름·부서는 유지하며 동명이인 구별 규칙은 바꾸지 않았다. 전송 전 확인에는 기존의 소속 확인 정보가 그대로 표시된다.
3. **수합 대상 검색은 표시만 바꾼다.** 검색 결과에서 사라진 교사를 제출 대상에서 해제하지 않는다. 선택한 제출 단위는 검색 아래에서 확인·수정한다.
4. **저장된 추가 질문은 처음부터 펼친다.** `ComposerOptions`가 펼침 상태를 따로 보관하므로 마지막 질문을 지우거나 검토자를 해제해도 입력 영역이 갑자기 닫히지 않는다.
5. **저장 단계를 합치지 않는다.** 메시지 확인→전송, 수합 초안→공개, 제출 초안→최종 제출은 각각 명시적 행동으로 유지한다.

배치를 되돌릴 때는 각 화면의 `wh-composer` 마크업과 공통 CSS를 조정한다. 대상 검색과 선택 설정의 펼침 상태는 별도로 유지할 수 있다. 서버 계약·어댑터·DB 변경이나 데이터 되돌리기는 필요하지 않다.

## 이후

이 작업에는 추가 SQL·환경변수 설정이 없다. 사용자 확인과 병합·운영 배포는 별도이며 실제 교사 연결과 운영 기능 시험도 이번 작업에 포함하지 않는다. 후속 화면 정리 후보는 일정·협업·인계의 입력 화면과 목록/상세 화면이다.
