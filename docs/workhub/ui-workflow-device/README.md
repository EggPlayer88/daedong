# 업무 완료 흐름·작은 화면 점검

후속 확인: [처리 중 안내 수정과 운영 완료 흐름](../operational-flow-finish/README.md)에서 시간표 원상 복귀·인계 왕복·문서 최종 제출·ZIP 대조 결과를 기록했다. 아래 내용은 #96 당시 기록이다.

## 운영에서 직접 확인한 결과

기존 관리자와 일반 교사 시험 계정으로 현재 Production 화면을 사용했다. 실제 교사 연결, 권한 부여, SQL 실행, 서비스 설정, AI 호출은 하지 않았다.

| 흐름 | 실제 확인 결과 |
|---|---|
| 협업 만들기 | 관리자 → 기존 시험 교사, `[완료흐름 시험 2026-10-28] 협업 확인` 저장. 응답 대기·1판 확인 |
| 교사 수락 | 진행 중·2판 확인 |
| 교사 완료 요청 | 완료 확인 대기·3판, 관리자 보낸함에서도 동일 상태 확인 |
| 관리자 완료 확인 | 서버 저장 안내·완료 확인됨·4판·처리 이력 4건 확인 |
| 같은 조건으로 협업 검색 | 새 요청이 나타나지 않음. 검색어를 변경했을 때만 새 요청이 도착해 결함 재현 |
| 시간표 이동 미리보기 | 기존 시험 수업 `3-1 국어 · 시험 교사 연결 1회`, 2026-10-30 11:45–12:30 → 13:20–14:05, 변경 수업 1건·관련 교사 본인 1명 확인 |
| 시간표 요청 전송 | 본인 동의 후 전송 버튼 1회 클릭. 전송 중 요청 번호 보관 안내까지 확인. 서버 최종 접수 결과·관리자 승인·원상 복귀는 미확인 |
| 오래 열린 교사 탭 | 이전 배포의 `CooperationWorkspace-CmgDod9m.js` 로딩 실패. 화면 재시도만으로 복구되지 않았고, 새 탭의 최신 배포에서는 정상 진입 |

시간표 요청 전송 뒤 Chrome 확대 화면 점검을 시작하는 과정에서 제어 도구가 현재 URL을 확실히 식별하지 못해 컴퓨터 제어를 중단했다. 이후 운영 브라우저를 조작하지 않았고, 요청이 남은 새 시험 교사 탭은 다음 확인을 위해 보존했다. 운영 시간표 승인이나 수업 시각 변경을 완료했다고 판정하지 않는다.

다음 실제 확인은 보존한 탭에서 **원래 요청의 결과 확인**이 먼저다. 이미 접수됐으면 기존 요청을 열어 관리자 승인 → 교사 시간표·일정 반영을 확인하고, 같은 절차로 원래 11:45–12:30으로 되돌린다. 결과가 불명확한 상태에서 새 번호로 중복 요청하지 않는다. 일반 교사는 그대로 유지한다.

## 수정

1. **협업 검색 갱신**: 같은 검색어라도 명시 검색하면 목록과 열린 상세를 다시 읽는다. 다른 검색어로 바꾸면 이전 선택을 지운다. 자동 polling, 쓰기 요청, 권한 조건은 추가하지 않았다.
2. **협업 확인창의 빈 공간**: 공통 footer가 세로 배치되는 720px 이하에서도 확인 문구의 가로폭 `flex-basis:260px`가 세로 높이로 남았다. 세로 배치에서는 문구 높이만 차지하도록 수정했다. 640px·200% CSS 확대에서 재현됐고 수정 뒤 저장 버튼과 확인 문구가 붙어 나온다.
3. **시간표 전송 안내**: 정상 전송 중에는 “시간표 요청을 처리하고 있습니다”로 표시한다. 응답 미확인 상태가 남았을 때만 기존 결과 확인 안내를 표시한다. 잠금·요청 번호·복구·승인 명령은 그대로다.
4. **화면 파일 오류 안내**: 파일 로딩 실패를 일반 렌더 오류와 구분해 가능한 원인을 안내한다. 재시도 후에는 입력 보관 → 미확정 요청 결과 확인 → 수동 새로고침 순서를 보여준다. 자동 새로고침이나 자동 재전송은 하지 않는다. 파일 URL·서버 오류 원문은 표시하지 않는다.

## 자동 검증 범위

합성 응답을 사용하는 실제 React·어댑터 브라우저 회귀를 실행했다. 합성 시험 통과를 운영 왕복 성공으로 계산하지 않는다.

| 시험 | 통과 |
|---|---:|
| 협업·일정 일괄 (동일 검색 갱신·모바일 완료 포함) | 20 |
| 모듈 로딩·입력 보존·실제 import 실패 캐시 | 10 |
| 시간표 교환·동의·승인·요청 복구 | 24 |
| 시간표 작업 화면·명시 승인·확대 키보드 실행 | 8 |
| 모바일 메뉴·낮은 화면·ShadowRoot | 16 |
| 협업 인계 | 15 |
| 학교 인계 | 51 |
| 문서 생성→HWPX→수합 제출→전체 다운로드 | 10 |
| 일정·협업·인계 UI | 7 |
| 홈·일정→시간표 연결 (월말·연말·윤년 포함) | 13 |
| **브라우저 합계** | **174** |

320px, 390px/낮은 높이, 640px, 200% CSS 확대에서 줄바꿈·가로 넘침·확인 버튼 위치·키보드 실행을 확인했다. CSS 확대는 브라우저의 실제 200% 확대나 휴대전화의 가상 키보드 시험과 다르다. **실제 Chrome 확대와 실제 모바일 키보드는 미완료**다.

전체 `npm test` **5,204건**, TypeScript 검사와 운영 빌드를 통과했다. 최초 전체 실행에서는 기존 릴리스 실행기 안전 시험 1개 파일이 실패했다. 기준을 바꾸지 않고 단독 64건 및 독립 임시 경로의 전체 5,204건을 재실행해 통과했으며, 최초 실패 원인은 확정하지 않았다. main CI는 브라우저 145개 중 `workhub-timetable-connected` 1개가 실패했다. 기준일이 10월 31일, 선택일이 11월 2일인데 시험이 10월 달력에서 11월 2일을 찾은 것이 원인이다. 실제 다음 달 버튼을 눌러 이동하도록 시험을 고치고, 같은 달·월말·연말·윤년 2월말 시각을 고정해 선택일·수업 ID·미리보기의 일치와 쓰기 0건을 검증했다. 이 파일은 로컬 13건 통과했고, main의 기존 실패 기록과 수정 PR의 새 CI 결과는 구분한다. 상태는 `verification.json`에 기록한다. 브라우저 이미지와 상세 JSON은 작업 폴더 `.tmp-workflow-device-evidence/`에 보관한다.

## 판단해서 정한 것

- 목록은 사용자의 검색 동작으로 갱신한다. 불필요한 반복 조회·화면 깜박임을 늘리지 않기 위해 자동 갱신은 넣지 않았다. 되돌릴 곳은 `CooperationWorkspace.tsx` 검색 처리다.
- 오래된 배포 탭은 임의로 새로고침하지 않는다. 탭 메모리의 입력과 미확정 요청을 보호하기 위해 안내만 보완했다. `ModuleBoundary.tsx`에서 변경한다.
- 전송 중/확인 필요 구분은 기존 `busy` 상태를 그대로 사용한다. 실행·복구 계약에 새 상태를 만들지 않았다. `TimetableOperationsWorkspace.tsx`의 안내 영역만 바뀐다.
- 확인 문구와 버튼의 간격만 조정하고 명시 확인 단계를 유지했다. `cooperation.css`의 720px 규칙에서 변경한다.

## 남은 작업

1. 보존한 시험 교사 탭에서 시간표 요청 결과 확인 → 관리자 승인 → 반영 확인 → 원래 시각 복귀.
2. 실제 계정의 인계 수락·문서 최종 제출 연속 흐름. 이번에는 합성 회귀만 통과했다.
3. 실제 Chrome 200% 확대와 휴대전화 키보드·스크롤 점검.
4. 이번 PR의 CI·미리보기 확인 뒤 사용자 병합. 수정은 아직 운영에 적용되지 않았다.

DB·인증·권한·메뉴 공개 범위·AI 비용·HWPX 생성 방식 변경은 없다. 새 SQL은 필요 없다.
