# PDF 압축 저장·HWP 실문서 호환성 보완

2026-10-15 · PR #38 `a4b4677` 기준 후속 작업 · `feat/workhub-document-compatibility`

## 목적과 경계

이전 검사에서 정상 공개 PDF의 압축 색인을 읽지 못하고 HWP는 추가 헤더 정보·기본 문서 옵션 때문에 전부 미지원으로 남았다. 정상 구조를 더 읽고 검증할 수 있도록 파서를 확장한다. 특정 파일명이나 해시로 검사를 면제하지 않고 원본을 수정하거나 다른 형식으로 변환하지 않는다.

`inspect_document(data, extension, limits)`의 반환 계약과 기존 수합 RPC/SQL 요청은 유지한다. 구조 검사 통과는 악성 검사나 전체 문서 렌더링 성공이 아니다. 실제 스캐너가 없는 제출은 계속 미검사·대기 상태다. 이번 작업은 DB·Storage에 연결하거나 수합 준비 상태를 켜지 않는다.

## PDF

- 일반 색인뿐 아니라 **xref stream·object stream·PNG predictor**가 있는 단일 저장본을 검사한다. `/W`·`/Index`·객체 종류·위치·세대·xref 자기 참조·직접 필드와 실제 해제 길이를 대조한다.
- pypdf가 원본에 없는 색인이나 손상 길이를 추측해서 복구하지 않도록 검증한 색인만 설치한다. 압축 객체의 개수·ID·소유자·순서·멤버 경계를 대조하고, 사용하지 않는 객체도 실행 기능/외부 참조 검사에 포함한다.
- PNG의 None/Sub/Up/Average/Paeth 필터를 한도 안에서 복원한다. 행 크기·색상 수·비트 수·전체 확장량·압축률을 검사한다. xref뿐 아니라 해당 필터를 사용하는 일반 스트림에도 같은 검사를 적용한다.
- 압축된 구조가 추가돼도 기존 일반 trailer의 필드를 빼먹지 않는다. 직접 길이 및 실제 stream 길이를 대조하여 음수 `/Length`의 자동 복구도 거부한다.
- Catalog의 시작 보기 설정은 문서 안의 실제 페이지에 대한 명시적 목적지/GoTo만 검사해 허용한다. 페이지 소속·보기 방식별 인자 개수·유한한 좌표·타입을 확인한다. 자동 외부 URI·JavaScript·연쇄 동작·고아 페이지는 거부하고, 이름으로 지정된 목적지는 미지원으로 남긴다. 단순 첫 페이지 보기까지 실행 코드로 분류하던 제한을 정교화한 것이다.
- Flate→JPEG처럼 여러 단계로 해제하는 경우 중간 확장량도 합계에서 사라지지 않게 보완했다.

공개 PDF **8개 모두 구조 검사 통과**했다. 기존 4개는 3→4개 통과로 개선됐고, 새로 추가한 pdfTeX 이미지·4쪽·목차·다단 표본 4개도 통과했다. 같은 8개를 이전 PR #38 코드로 소급 검사하면 3개 통과이며 나머지 5개는 압축 색인 미지원이었다.

**증분 저장·혼합 색인, TIFF predictor, 일부 이미지 코덱과 인라인 이미지는 아직 미지원**이다. 증분 저장은 이전 개정의 객체까지 검사하고 세대 교체를 증명해야 하므로 최신 개정만 보고 통과시키지 않는다. 지원 표본은 늘었지만 모든 PDF에 대한 지원을 뜻하지 않는다.

## HWP

알고리즘 정보 `EncryptVersion`과 실제 암호 설정 여부를 분리한다. 알려진 알고리즘 값이 있어도 보호 플래그가 없고 평문 구조 검사를 통과하면 계속 검사한다. 보호/DRM/배포 문서를 해제하거나 우회하지 않는다.

`DocOptions/_LinkDoc`는 길이 524바이트 전체가 0인 빈 형식만 확인한다. 외부 경로나 첫 NUL 뒤의 알 수 없는 내용을 빈 여유 공간이라고 추정하지 않는다. 이 제한 때문에 일반 문서도 여전히 미지원일 수 있다.

공식 명세의 호환 문서·레이아웃·변경 추적 정보를 실행 기능과 구분한다. 길이·레벨·부모·중복·대상 프로그램 값을 검사한다. 메타데이터의 모든 의미를 해석하거나 변경 추적을 렌더링한다는 뜻은 아니다.

편집 후 남은 미참조 그림도 검사한다. 표준 스트림 이름·지원 이미지 확장자·문서 기본 압축 방식 한 가지로 해제한 뒤 실제 이미지 디코딩과 자원 한도를 적용한다. 참조한 파일이 없으면 계속 거부하고, 임의 바이너리나 실행 객체는 허용하지 않는다.

**5.1.0.0·5.1.0.1·5.1.1.0만 별도 프로필로 지원**한다. 5.1 전체를 5.0처럼 읽도록 바꾼 것이 아니다. 문단 헤더·글자/문단 모양 길이, ID 목록의 개수·부모·레벨, 필수 호환 레코드, 10단계 문단 번호의 UTF-16 문자열과 확장 시작번호 경계를 검사한다. 버전별로 확인되지 않은 길이나 기능을 자동 보정하지 않는다.

공식 명세와 공개 작성기의 직접 실측을 교차 확인했다. 문단 번호 표의 합계와 구성 필드 합이 다른 부분은 실제 5.1 원본에서 경계를 대조했다. 문단 모양의 마지막 DWORD는 원저자 코드와 실측에서 `ParaLevel` 0~9로 확인돼, 항상 0인 패딩으로 가정하지 않았다. 근거: [버전별 직접 실측](https://github.com/STAIxBWLB/hwp-cli/blob/main/docs/design/19-hwp5-spec-supplement.md), [hwplib의 문단 모양 해석](https://github.com/neolord0/hwplib/blob/main/src/main/java/kr/dogfoot/hwplib/reader/docinfo/ForParaShape.java). 외부 구현 코드는 복사하지 않았다.

HWP 공개 원본 **30개 중 8개 통과, 22개 미지원**이다. 통과 표본은 제한된 5.0 문서 1개와 5.1.1.0의 본문·머리말/꼬리말·표 테두리·여러 구역·인라인 개체·문단 번호 등 7개다. 나머지는 연결 옵션 19개, 보호 문서 1개, 미지원 기능 2개로 분류된다. 일반 학교 HWP 전체의 호환 완료나 렌더링 확인으로 해석하지 않는다.

## 재현과 시험 결과 해석

[공개 표본 명세](../../tests/fixtures/document-corpus.json)는 URL·길이·SHA-256·이전 판정·현재 예상 판정을 보존한다. 파일 자체를 재배포하지 않는다. [재현 안내](../../tests/fixtures/README.md)에 따라 로컬 원본을 준비한 뒤 다음 명령으로 검사한다.

```bash
tests/.venv/bin/python tests/check_document_corpus.py tests/.venv/format-fixtures
```

Windows는 `tests/.venv/Scripts/python.exe`를 사용한다. 원본 누락·해시 변경·예상 판정 불일치는 실패다. `matched`는 미지원 예상값이 맞는 경우도 포함하며 `structure_passed`와 다르다. 고정 시험 한도는 결과 JSON에 함께 기록한다. 특히 한컴 명세 PDF는 PDF 단위 시험의 객체 상한 1,000으로는 거부되며, 공개 실측은 이전과 같은 10,000 상한을 사용한다. 이는 운영 학교의 정책을 변경한 것이 아니다.

CI 회귀는 독립적으로 만든 PDF/CFB 바이트를 사용한다. 공개 원본 실측은 별도 실행하여 외부 사이트 상태에 CI가 의존하지 않게 한다. 프로그램 렌더링·현재 Supabase·실제 스캐너 종단 검증은 이 시험으로 대체하지 않는다.

최종 자동 회귀는 PDF **197건**, HWP **148건**, 제출 검사 접수 **76건**, 코퍼스 도구 **8건**이다. 기존 HWPX/ZIP 검사 **118건**과 정리 처리 **48건**도 유지된다. PR #38 대비 PDF +97, HWP +75, 접수 +21, 코퍼스 도구 +8로 **201건 추가**됐다.

독립 검토에서 발견한 음수 PDF 길이의 자동 복구, Flate→JPEG 확장량 누락, HWP 5.1 ID 목록 자녀의 부모·레벨 누락, PDF 시작 보기의 구조 타입을 수정하고 원래 재현 입력이 차단되는지 확인했다. 최종 공개 원본은 **38개 모두 고정 예상 판정과 일치**하며 실제 구조 통과는 PDF 8 + HWP 8 = **16개**, 나머지 HWP **22개는 미지원**이다. 예상 결과 일치 38개를 지원 성공 38개로 보고하지 않는다.
