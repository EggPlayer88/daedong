이번에는 기능을 더 늘리기보다, “깔끔하고 직관적인 핵심 화면 + 필요할 때 여는 세부 기능 + AI 옆자리”가 실제 업무 흐름에 맞는지 봐 주세요. Pretendard·Tossface를 적용했고, 홈·시간표·AI·메신저·수합·업무·일정·협업·인계·학교/수업/학생·문서/자료/양식·기존 평가계획·공통 메뉴까지 정리했습니다.

중점 확인 사항은 다음과 같습니다.

1. **화면의 우선순위와 이동:** 핵심 정보와 다음 행동이 먼저 보이는지, 홈·메뉴·검색·알림에서 원래 업무로 이동/복귀하기 쉬운지. 세부 기능을 접으면서 필수 오류·확인·마감 정보를 숨기지는 않았는지.
2. **입력·대기·복구:** 정상 처리 중과 결과 미상을 구분하는지. 입력·원래 요청 번호·명령이 보존되는지. 처리 중 복구/제출 중복 실행을 막고 결과 미상에서는 기존 번호로 확인하는지. 오래된 배포 탭의 안내가 작성 중 입력을 임의로 지우지 않는지.
3. **시간표·협업·인계:** 준비/편성/확정/날짜별 운영 구분이 쉬운지. 교환 요청→영향 교사 동의→승인 흐름, 협업 읽음/수락/완료 요청/완료 확인, 인계 확인/수락/반려/취소가 분명한지. 기존 승인 조건이 약해지지 않았는지.
4. **문서·수합:** 원본·정리본, 양식 초안/게시, 답변 저장/파일 생성/파일 확인/명시 첨부/최종 제출이 구별되는지. HWPX 다운로드·ZIP·현황표와 처리 결과를 찾기 쉬운지. 생성만으로 제출되거나 게시되지 않는지.
5. **학교·수업·학생·기존 평가계획:** 목록과 정정 화면의 맥락, 평가 당시 기준판, 상담 분리, 원문 보존, 기존 평가계획 기능의 접근성이 유지되는지.
6. **AI:** 답변·근거의 판/원문 인용·줄바꿈, 개인 기억 상태, 관리자 정책/키/예산 표시가 이해하기 쉬운지. Haiku 기본·Sonnet 명시 정밀 검토, 기존 예산/비용 구조가 유지되고 화면 이동이나 제안만으로 유료 호출·전송·제출이 발생하지 않는지.
7. **작은 화면·접근성·권한:** 핵심 버튼, 키보드 포커스, 긴 문장/목록, 빈 화면/오류/준비 중 안내, 관리자와 기존 일반 교사 시험 계정의 화면 차이를 봐 주세요. 메뉴를 숨기는 것과 서버 권한 검사를 혼동하지 말아 주세요.
