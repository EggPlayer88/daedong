# 파일형 수합 — 연결 화면의 전체 ZIP 다운로드

2026-10-15 · `feat/workhub-collection-export` · PR #35 후속

## 교사가 보는 변화

수합 담당자는 공개된 파일형 수합의 상세 화면에서 **제출 파일 모아 받기**를 연다. 기본 화면에서는 접혀 있으며, 필요한 때만 기준과 진행 상황을 표시한다.

1. **완료본**: 검토가 필요한 수합은 검토 완료판을 모은다. 새 정정 제출이 검토 중이면 이전 완료판을 유지한다. 검토 없는 수합은 접수된 완료판을 모은다.
2. **현재 제출본**: 검토 대기·보완 요청 상태도 포함한다. 철회 후 현재 포인터가 이전 완료판으로 돌아갔으면 그 판을 사용한다. 이력의 가장 큰 일련번호를 무조건 고르지 않는다.
3. **최신 현황으로 묶음 준비**: 전체 대상과 파일을 확인해 ZIP을 만든다. 파일 하나라도 확인하지 못하면 내려받기 버튼을 제공하지 않고 실패 목록과 재시도를 표시한다.
4. **ZIP 내려받기**: 현재 제출 현황과 각 파일을 다시 확인한 뒤 브라우저 다운로드를 요청한다. 내용이 바뀌었거나 권한 확인이 실패하면 기존 묶음을 폐기한다.

ZIP의 첫 항목은 UTF-8 BOM CSV 현황표다. 모든 제출 단위, 선택한 제출판, 현재 검토 상태, 미제출·완료본 없음·첨부 없음 등 제외 사유, 원본 이름, 실제 ZIP 안 이름, SHA-256을 담는다. 파일이 없으면 현황표만 받는다. 미제출 초안·양식·철회판은 넣지 않는다.

## 기존 서버 계약으로 구현하는 범위

- PR #34의 `CollectionServer.detail`과 `download`만 사용한다. RPC 9개와 DTO, SQL 요청서, 인증·Storage 어댑터는 변경하지 않는다. Claude의 R1 SQL 작성 범위를 늘리지 않는다.
- 상세 응답은 기존 `collectionDetail` 검사기를 다시 거친다. 수합의 공개 대상 목록과 반환된 단위의 이름·책임자·공동 작성자가 일대일로 일치해야 한다. 일부 단위만 조회된 응답을 전체 ZIP으로 표시하지 않는다.
- 제출 포인터·승인·철회·판 연결 검증을 통과한 파일만 선택한다. 미제출 초안을 조회하는 호출은 없다.
- 각 파일은 `submission` 부모의 수합·단위·제출판 식별자로 요청한다. 기존 어댑터가 현재 접근 권한 → 파일 원문 → 크기·해시 → 현재 접근 권한을 확인한다. ZIP 엔진도 받은 바이트의 크기·SHA를 대조한다.
- 상세와 파일의 배열 정렬이 달라져도 같은 계획으로 판단한다. 반면 제출·검토·철회·대상·원본 메타데이터가 바뀌면 준비 결과를 무효화한다.
- CSV 셀의 수식 실행과 이름의 경로 구분자를 방어하고, 모든 ZIP 항목에 순번을 붙여 동일 이름 파일의 덮어쓰기를 막는다. 기존 검증된 STORE 방식 ZIP 생성기를 재사용한다.

## 오류·취소·화면 전환

- 부분 파일 실패는 전체 성공으로 숨기지 않는다. 실패 파일만 다시 읽되, 재시도 전후 전체 현황을 다시 대조한다. 이미 받은 파일도 최종 다운로드 전에는 다시 읽고 접근 권한·본문을 확인한다.
- 접근 거부·잘못된 상세·판 변경 등은 묶음을 폐기한다. 원시 SQL·Storage 경로·예외 본문을 화면에 출력하지 않는다.
- 준비·최종 재확인 중 목록 이동, 새 수합, 다른 파일 다운로드, 관리 입력을 잠근다. 취소하면 잠금을 풀고 늦은 응답을 반영하지 않는다.
- 계정·학교·수합·날짜·연결 변경, 화면 종료, 다른 관리 입력 시작 시 캐시를 폐기한다. React 상태 반영 전 연속 클릭도 ref 잠금으로 한 번만 실행한다.
- 파일과 ZIP은 현재 탭 메모리에만 둔다. localStorage·sessionStorage에 쓰지 않으며 제출 자료를 삭제·수정하는 서버 요청도 없다.
- 취소는 이후 처리와 다운로드를 막는다. 기존 어댑터 인터페이스에 AbortSignal이 없으므로 이미 진행 중인 HTTP 요청 자체의 즉시 중단을 보장하지 않는다.

## 기술 한도와 보장하지 않는 것

현재 브라우저 구현은 `FILE_TECHNICAL_LIMITS`를 따른다. CSV 1개를 포함해 최대 512항목이므로 첨부 파일은 최대 511개이며, 파일과 CSV의 내용 합계는 100 MiB 이하다. 다운로드를 시작하기 전에 한도를 검사한다. 이는 학교의 제출 정책이 아니라 브라우저 처리 상한이다. ZIP 헤더·중간 버퍼·캐시 때문에 실제 메모리 사용량은 100 MiB보다 크다. 대용량 스트리밍/서버 ZIP은 후속 범위다.

기존 상세 DTO의 단위 100개·이력 배열별 1,000개 상한도 그대로다. 상한을 넘는 응답을 조용히 잘라 내지 않는다. 대상이 늘면 페이지 계약과 서버 export manifest를 별도로 설계해야 한다.

**현재 구현은 단일 수합의 조회 가능한 전체 대상을 대조하는 브라우저 묶음이다. 서버 전체를 잠그는 원자적 스냅샷이나 서버 export manifest의 확정본은 아니다.** 마지막 조회 이후 동시 변경을 완전히 배제하거나 이미 내려받은 파일을 회수하지 않는다. 서버 manifest·감사 export job이 완료됐다고 표시하지 않는다.

|---|---|---|
| 담당자의 단일 수합 전체 묶음 | 학교 전체 다운로드 권한·새 RPC를 추정하지 않음 | `collectionExportPlan`, 부모 화면 표시 조건 |
