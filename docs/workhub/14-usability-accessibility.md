# 9차 개발 — 화면 사용성과 접근성

작성일: 2026-10-13 · 기준: 8차 작성·확인(PR #15) · 브랜치: `feat/workhub-accessibility` · [검토용 PR #16](https://github.com/EggPlayer88/daedong/pull/16)

## 목적과 범위

교사가 키보드로 작성·저장·취소를 이어 가고, 작은 화면에서도 입력과 다음 행동을 찾을 수 있도록 기존 다섯 화면을 보완했다. DB 구축과 시간표는 사용자 요청대로 보류한다. 기존 로그인·회원 데이터, 인증·권한·저장 계약, SQL, Claude 공급자와 비용, 운영 공개 범위는 변경하지 않았다.

학교 일정·개인 업무는 기존 연결 화면에도 같은 구성요소를 사용한다. 수합·학생 기록은 계속 합성 자료 미리보기 단계다. 기능이 보인다고 실제 학교 자료가 서버에 저장되는 것은 아니다.

## 이번에 개선한 동작

| 영역 | 재현한 문제 | 개선한 결과 |
|---|---|---|
| 개인 업무 | 취소·저장·완료로 버튼이나 카드가 사라지면 키보드 초점이 본문 밖으로 빠짐 | 신규 취소는 등록 버튼, 수정 취소는 원래 수정 버튼, 저장·완료는 결과 안내로 이동 |
| 업무 충돌 | 충돌 원본을 다시 불러오면 재조회 버튼이 사라지거나 비활성화되어 위치를 잃음 | 성공·실패 안내로 이동하고 최신 내용 사용 시 제목 입력으로 복귀, 내 입력·재시도 명령 유지 |
| 학교 일정 | 삽입 화면의 편집기에서 일반 document의 초점을 저장해 취소 시 복원 실패 | 편집기가 속한 ShadowRoot의 실제 조작 요소를 기억하고 복원 |
| 일정 저장·필터 | 저장 후 목록 재조회 또는 필터/전체 기간 버튼 제거로 초점 유실 | 저장 결과 안내 또는 검색 입력으로 연결 |
| 모바일 메뉴 | 더보기의 현재 메뉴를 다시 누르거나 Escape를 눌러도 열림 유지 | 현재 메뉴 재선택은 닫고 본문으로 이동, Escape는 닫고 더보기 버튼으로 복귀 |
| 수합 | 반복되는 검토·응답 필드의 단위 맥락 부족, 편집·단위 추가/삭제·게시·검토 후 위치 유실 | 고유 ID·레이블·단위 설명 연결, 해당 입력·단위·원본으로 초점 이동 |
| 학생 기록 | 정정·철회·활동 채택·취소 및 조회 복구 뒤 위치 유실 | 해당 기록·입력·저장 결과로 이동하며 과거 초점 요청을 반복 실행하지 않음 |
| 좁은 화면 | 긴 영문 원자료와 불변 이력이 가로로 넘침 | 원문을 유지하면서 줄바꿈, 320px·390px에서 입력·버튼 배치 보완 |
| 일정 모달 | 작은 너비의 날짜 입력과 낮은 화면의 고정 하단이 조작 영역을 좁힘 | 작은 화면은 한 열 입력, 높이 600px 이하는 하단도 함께 스크롤, 닫기·선택 영역 확대 |

기존 버튼의 보이는 명칭과 자연스러운 Tab 순서를 유지했다. 일반 버튼 묶음을 별도 화살표 조작이 필요한 ARIA 탭으로 바꾸지 않았다. 반복 필드는 단위·학생·날짜 등 실제 맥락과 연결하고, 오류는 오류가 발생한 양식과 연결했다.

## 교사 화면 확인 순서

1. **내 업무:** 할 일 등록 → 공백 제목 저장 → 오류 확인 → 정상 저장 → 수정 → 취소 → 완료. 각 단계의 초점과 다음 행동을 확인한다.
2. **학교 일정:** 원본 열기 → 수정 → 취소, 다시 수정 → 저장. 검색 결과가 없을 때 모든 날짜에서 찾기와 필터 지우기를 확인한다.
3. **자료 수합:** 수합 만들기 → 단위 추가·삭제 → 초안 저장 → 게시 → 응답 작성·취소 → 검토. 같은 필드명이라도 어느 단위인지 확인한다.
4. **학생 기록:** 관찰 저장 → 정정·취소 → 철회 사유·취소 → 철회 완료, 활동 학생 연결 → 채택. 저장된 학생과 기록이 정확한지 확인한다.
5. **모바일:** 더보기 → Escape → 다시 열기 → 현재 화면 선택. 긴 이력을 펼친 상태에서도 입력과 버튼을 사용할 수 있는지 확인한다.

## 판단해서 정한 것

| 선택 | 이유 | 위치 |
|---|---|---|
| 저장 성공은 결과 안내, 취소는 원래 조작 위치로 복귀 | 목록에서 원본이 사라지거나 필터에 숨더라도 사용자가 처리 결과를 확인할 수 있음 | TaskPanel, CalendarPanel, WorkflowPanel, StudentsPanel |
| 연결 화면은 ShadowRoot 안의 초점 사용 | 기존 앱에 삽입된 업무실도 동일한 키보드 경험 제공 | EventEditor |
| 오류 이후 입력을 자동 교체하지 않음 | 접근성 보완이 기존 충돌·멱등·입력 보존을 깨뜨리지 않게 함 | 기존 저장 명령 유지, 화면 ref·설명 연결만 보강 |
| 기존 버튼 이름을 유지하고 설명·form 이름으로 맥락 추가 | 교사가 익힌 메뉴와 동작을 보존하면서 반복 항목을 구분 | 수합·학생 입력과 개인 업무 카드 |
| 좁은 너비와 낮은 높이를 각각 처리 | 휴대전화·가로 화면·글자 확대 때 마지막 버튼까지 도달 가능하게 함 | style.css, workspace-shell.css, 영역별 CSS |

## 검증 범위와 남은 것

신규 자동 SSR 검증은 18개(일정 2·수합 8·학생 8)다. 신규 실제 Chrome 접근성 검증은 46개(공통 24·수합 9·학생 13)다. 공통 24개는 일반 DOM과 ShadowRoot에서 각각 12개씩 실행한다. 수합·학생 신규 시험은 production React 구성요소를 일반 DOM에 묶어 실행한다.

전체 자동 회귀 1,095개, 기존 Chrome 핵심 91개, 일정 보기·저장 복구·개인 업무·원본 이동도 통과했다. 실제 Vite 서버 통합 10개와 독립 HTML 8개도 확인했다. 최종 집계와 실행 상태는 [진행 현황](PROGRESS.md)을 따른다. 최초 전체 실행에서 고정 `editor-title`을 가정하던 기존 테스트는 고유 ID가 실제 제목을 가리키는지 검사하도록 갱신했다.

PC·320px·390px, 루트 글자 크기 200% 및 낮은 화면을 확인했다. CSS 확대 시험을 실제 보조기기 음성 검증이나 접근성 인증으로 해석하지 않는다. 화면읽기 프로그램의 읽기 순서·중복 안내·발음, 사용자 브라우저 확대, 색 대비와 다양한 운영체제·모바일 환경의 종합 점검은 교사 파일럿과 함께 남아 있다.

사용자 피드백에 따른 화면 정보량·문구·간격 조정, 많은 업무·학급·기록에서의 목록 성능, 학교 자료·문서 작업 공간과 Claude 도구 통합은 후속 개발이다. 실제 DB·계정 종단 연결과 시간표는 이번 작업에서 재개하지 않았다.
