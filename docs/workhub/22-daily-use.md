## 날짜와 연결의 계약

- 기기 시계는 재조회 신호로만 사용한다. **화면의 기준일과 소속 유효성은 서버가 반환한 날짜로 판단**한다.
- 매분 실행하는 것은 로컬 날짜 비교다. 같은 날짜라는 이유만으로 매분 서버를 조회하지 않는다.
- 숨김 탭에서는 날짜 검사를 미루고 보이는 순간 확인한다. 기존 창 포커스 재검증도 유지한다.
- 이미 진행 중인 조회는 완료를 기다린 뒤 최신 신호 하나를 처리한다. 오래된 화면 응답은 적용하지 않는다. 기존 전송 계층의 타임아웃·취소 정책은 바꾸지 않는다.
- 날짜만 달라지고 계정·소속이 같으면 편집 중 날짜를 오늘로 자동 변경하지 않으며, 입력과 저장 복구용 요청 번호를 유지한다.
- 계정 변경·확인된 권한 상실은 기존 규칙대로 화면·입력을 폐기한다. 조회 실패는 오류로 보여 주며 이전 화면을 계속 노출하지 않는다.
- 실제 소속이 만료되면 새 기준일을 사용해 화면에서 제거한다. 날짜 갱신이 소속 권한을 연장하지 않는다.
- 기기 시계가 크게 틀렸거나 서버 날짜가 장기간 잘못된 상황을 자동 교정하는 기능은 아니다. 제한된 추가 확인이 끝나면 기존 포커스/사용자 재확인 경로를 사용한다.
- 합성 미리보기의 기준일 **2026-10-19**는 재현 가능한 검토를 위해 유지한다. 전달용 HTML은 실시간 서버 날짜 갱신의 증빙이 아니다.

## 일정 표의 입력 계약

연도가 있는 기존 세 형식 `YYYY-MM-DD`, `YYYY. M. D.`, `YYYY/M/D` 뒤에 `(화)` 또는 `(화요일)`과 같은 일곱 요일 표기를 허용한다. 괄호 앞 공백도 허용한다.

요일이 없으면 기존 입력 규칙을 따른다. 요일이 있다면 실제 날짜와 반드시 같아야 하며, 잘못된 윤일·없는 날짜·연도 없는 날짜·불완전한 괄호를 추정해 고치지 않는다. 시작일과 종료일의 문제는 따로 표시한다. 정상 행도 기존 편집기에서 제목·날짜·공유 대상을 확인한 뒤 한 행씩 등록한다.

실제 학교에서 복사한 표본 파일이 현재 작업 폴더에 없어 **합성 자료로 검증**했다. 인용부호가 들어간 TSV의 해석을 새로 바꾸거나 연도·학년을 자동 추정하는 범위까지 확대하지 않았다. 원본 ID 관리·일괄 등록·구글 시트 동기화는 후속이다.

## 판단해서 정한 것과 조정 위치

1. **서버 날짜를 유지한다.** UI 날짜만 바꾸면 소속 판단과 어긋날 수 있다. `app/school-day.ts`는 신호만 만들고 `app/ConnectedWorkspace.tsx`가 기존 조회 경로를 사용한다.
2. **재확인은 1·5·15분으로 제한한다.** 작은 PC 시계 차이를 복구하면서 잘못된 기기 시계가 무한 조회를 만들지 않게 한다. 상한·간격 조정은 `school-day.ts`의 `retryAfter`에 있다.
3. **새 신호는 최신 하나로 합친다.** 신호마다 병렬 읽기를 만들지 않아 응답 순서에 따른 연결 문맥 역전을 방지한다. 조정 위치는 `ConnectedWorkspace`의 `refresh/drain`이며 인증 통과 조건 자체는 그대로다.
4. **요일을 오류 검증에 사용한다.** 표기를 없애기만 하면 담당자가 입력한 날짜의 모순을 놓친다. 조정 위치는 `calendar/import-table.ts`의 `dateValue`, 안내는 `CalendarImport.tsx`다.
5. **#23 위의 후속 PR로 둔다.** 현재 Claude 검토 범위를 흔들지 않고 이번 변경만 검토하기 위함이다. #23을 먼저 병합한 뒤 이 PR의 기준 브랜치와 차이를 확인해 사용자가 병합한다.
