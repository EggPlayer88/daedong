## 모듈화 완료 상태

수합·질문형 문서·시간표 편성·메신저·AI 비서 5개 진입점에서 컨트롤러/표시/순수 모델을 분리했다. 질문형 문서·시간표의 단계별 표시 8개도 분리했다. 공통 검증·복구 범위는 React·RPC로부터 독립하고 정적 순환 import를 검사한다. 저장·원번호 복구는 기능별 컨트롤러 하나가 소유한다. 이후 필요한 단위만 추가 분리한다.

화면은 하나의 공통 메뉴를 사용한다. 평가계획서는 관리자 기간 업무 설정으로 표시한다. 메뉴 숨김은 기존 권한 회수나 제출 마감이 아니다. 신규 교무계획서·권한 확대·AI 재설계는 이번 완료 범위에 넣지 않는다.

## 운영 점검 기준의 정정

10월 26일 도구가 내보내던 INT-10·OP1-02는 AF1 이전 함수 원문을 비교한다. AF1·AF2가 설치된 정상 격리 DB에서도 FAIL이 재현됐다. 이를 실제 운영 훼손으로 오해하거나 FAIL을 무시하지 않도록 새 기준을 제공한다.

- 현재 전체 구조: `database/workhub-current/int11/INT-11_SQL편집기용_통합점검.sql`
- 연간 운영: 기존 AF1-05, 수합 보강: 기존 AF2-02, 기간 업무: 기존 SP1-02
- `npm run check:workhub:current-checks`: 파일 해시와 목록 확인만
- `npm run prepare:workhub:current-checks -- --output-parent <폴더>`: 기존 파일을 덮지 않고 점검 원문 4개 내보내기
- 새 INT-11은 읽기 전용이며 **설치 SQL이 아니다**. 이번 작업 완료를 위해 사용자가 지금 실행할 필요는 없다. 도구는 운영 DB를 호출하지 않는다.
- 새 점검의 격리 결과와 실제 운영 결과를 구분한다. INT-11을 운영에서 실행한 것으로 기록하지 않는다.

INT-11은 OP1까지의 기존 구조와 AF1·AF2·SP1을 함께 검사하고, 현재 기준 48단계가 하나라도 없으면 첫 행이 FAIL이다. 전체 18행 중 12·13은 info, 나머지는 ok가 정상이다. 사용 정책의 active 여부와 계정의 현재 접근 가능성을 확정하는 검사는 아니다.
