# 전체 구축 마감 검증 — 2026-11-03

## 기준과 변경

기준은 main `52bfe57e4811e6353844ce0e2c632ae2cb20d52f`(#107 병합)다. [main 자동 검사](https://github.com/EggPlayer88/daedong/actions/runs/41571685293)는 success이고, 같은 커밋의 Vercel Production 성공 상태를 확인했다. 이 기록은 이번 도구 보완의 운영 배포 완료를 뜻하지 않는다.

기능별 코드와 기존 검증 기록을 대조한 결과, 이번에 고칠 대상으로 확정한 것은 **현재 점검 파일 내보내기가 AF1 이전 기준을 사용하는 문제**다. 정상 DB에서도 INT-10과 OP1-02가 FAIL을 내는 현상을 새 임시 PostgreSQL 17에서 재현했다.

- 새 읽기 전용 INT-11을 생성했다. OP1 위의 AF1-01~04·AF2-01·SP1까지 48단계를 요구한다.
- 공통 카탈로그의 함수·소유자·실효 권한·RLS·트리거·열·제약 등에 기간 업무 스키마와 함수를 포함했다.
- 현재 점검 내보내기는 INT-11·AF1-05·AF2-02·SP1-02의 네 파일만 허용한다. 크기와 LF 정규화 해시가 모두 맞아야 새 폴더를 만든다.
- 확정 SQL은 수정하지 않았다. 새 INT-11은 설치·활성화 파일이 아니며 운영 DB에 실행하지 않았다.
- 앱 코드·기존 기능·권한·공개 범위·AI 비용·파일 생성 방식은 변경하지 않았다.

## 전체 기능 연결 확인

공통 메뉴와 12개 업무실 페이지의 진입점, main/API와 업무실 연결 어댑터의 리터럴 RPC 이름을 SQL 함수 선언과 대조했다. 추출한 문자열 이름 168개 중 164개는 선언과 일치했다. 나머지 네 개는 다음처럼 구분했다.

| 항목 | 확인 |
|---|---|
| `workhub_ai_gateway_` | `_school_policy.py`의 동적 RPC 이름 접두사 |
| `workhub_ai_school_` | 같은 파일의 학교 정책 RPC 접두사 |
| `workhub_template_` | `_guided_service.py`의 문서 RPC 접두사 |
| `workhub_timetable_operations_school_day_preview` | 이미 대체된 옛 읽기 전용 계약. SQL 생성 대상 아님 |

실제 `TimetableOperationsWorkspace`는 `schoolDayExecution`을 만들고 `SchoolDayChangePanel`에 넘긴다. 이 경로는 `workhub_timetable_school_day_preview`를 호출한다. 옛 이름은 [계약 문서](../timetable/operations-next-api.md)에 대체됐다고 명시돼 있으며 호환용 연습/회귀에 남아 있다. 새 SQL alias를 추가하지 않았다.

정적 이름 대조는 동적 인자의 정확성·실제 배포된 RPC의 존재·운영 권한·왕복 성공을 증명하지 않는다. 해당 동작은 기존 기능별 시험 및 이후 실제 환경 점검과 구분한다. 이번 확인에서 새로운 화면 기능의 구현 누락은 찾지 못했다.

## 판단해서 정한 것과 남긴 일

- 옛 INT-10과 OP1-02를 덮어쓰거나 FAIL을 무시하지 않고 새 읽기 전용 기준을 제공한다.
- INT-11은 최신 운영 완료 상태 전용이다. 아직 적용하지 않은 단계가 있는 시험 DB를 정상 운영 상태로 판정하지 않는다.
- 네 점검 파일은 출력 목록·경로·해시를 고정하며 실행 기능을 추가하지 않는다. 지금 운영에 SQL을 다시 실행할 필요가 없다.

- 실제 브라우저, 운영 Supabase/Storage, AI 호출, 휴대폰 입력, 실제 PDF 저장은 이번에 실행하지 않았다. #107의 수합 보완 재제출 계정 시험도 완료로 바꾸지 않았다.
