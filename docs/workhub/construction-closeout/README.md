## 이번에 끝낸 구축

1. 기존 연결 점검 17개에 대강·보강(T3), 업무 참여 설정(OP1)을 더해 **19개**로 확장했다. 각 기능의 실제 응답 검증기를 재사용하며 조회 RPC 하나만 호출한다.
2. 승인 담당자 부족을 일반 조회 실패와 구분한다. 만료된 참여 허용이나 업무 참여 목록을 조회했다고 사용 준비·가져오기 성공으로 표시하지 않는다. 취소·학교 변경·늦은 응답 폐기와 개인정보 없는 점검 결과 내보내기를 유지한다.
3. 업무 참여 목록 검증기를 화면에서 분리해 진단과 화면이 같은 계약을 사용하게 했다. 기존 권한·API·DB 계약은 변경하지 않았다.
4. 현재 운영에 맞는 **읽기 전용 점검 묶음**을 만들었다. 승인된 OP1 목록의 해시를 확인한 INT-10·OP1-02만 내보낸다. 설치·활성화·권한 변경 SQL은 포함하지 않고 이전 폴더를 덮어쓰지 않는다.
5. 이전 문서의 ‘OP1 미적용/참여 0명/두 번째 승인 담당 미설정’은 당시 기록으로 표시하고 이 보고서로 연결했다.

T4의 `workhub_timetable_import_get`은 내부 `t1_mark`로 원본 판 추적값을 갱신한다. 따라서 읽기 전용 앱 진단에는 넣지 않았다. T4 설치 구조는 INT-10에서 확인하고 원본 가져오기는 사용자가 해당 화면을 열 때 기존 경로로 수행한다.
