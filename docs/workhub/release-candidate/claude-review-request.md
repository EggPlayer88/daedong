## 이번 수정의 중점 검토

1. **학생 기록 출력 U1:** 팝업 차단·인쇄 창 닫힘·CSV 시작 실패는 미리보기·선택·확인·페이지를 유지합니다. 재시도 전 최신 권한·자료를 확인하고 자료 정정은 재확인을 요구합니다. 권한 회수·학생 관계 변경·조회 실패까지 보존해 버리지는 않는지 확인해 주세요.
2. **관계 관리 오류:** snapshot의 `UNAVAILABLE`을 해당 학교·소속·수업·조회 세대에만 기억합니다. preview가 잘못 `QUERY_FAILED`로 바꾸지 않고, 원래 commit 번호 복구는 막지 않아야 합니다. 결과 미상 오류와 최신 조회 상태가 화면에서 모두 보이는지 확인해 주세요.
3. **인계 복구:** 101개 기록(50+50+1)에서 마지막 쪽의 공식 담당 승인·수락, 응답 유실 후 첫 쪽 재진입, 모듈 중지·목록 실패 후 원키 복구를 시험했습니다. 순환 커서와 50쪽 한도에서 잘못된 기록을 처리하지 않는지 봐 주세요. C8 새 명령=`mutate`, 원키 복구=`recover` 구분은 유지합니다.
4. **교사용 사용 안내:** 12개 업무 안내의 문구가 실제 기능과 맞는지, 메뉴 이동이 입력 잠금을 우회하지 않는지 확인해 주세요. 별도 메뉴를 늘리지 않고 업무실 상단의 ‘사용 안내’에서 엽니다.
5. **읽기 전용 연결 점검:** 12개 기존 조회 어댑터의 응답 검증을 재사용합니다. 조회 허용 목록 이외의 호출은 거부하고, 닫기·중지·학교 변경·늦은 인증 뒤 추가 요청과 오래된 결과 반영을 막습니다. 저장·읽음·파일 요청·Claude 호출은 없어야 합니다. 지원 JSON은 기능 코드·시각만 담고, 조회 성공을 실제 저장 성공이나 활성화 완료로 설명하지 않아야 합니다.
6. **통합 시험 실행기:** `scripts/verify-workhub-release-sql.sh`와 결과 판정기를 봐 주세요. 고정 SQL 원문·현재 앱 사본을 전용 로컬 PG17에서 시험하며, 새 WARN/FAIL/KNOWN·0건·하위 실패를 성공으로 처리하지 않습니다. 기존 비차단 오류코드 차이만 근거·원문·건수와 함께 남깁니다. 원본 P8 하네스가 실패 snapshot을 앱에 주지 않고 preview를 호출하는 한계는 그대로 기록하고, 실제 실패 snapshot→preview는 별도 보충 시험으로 검증합니다. 시험 분기 환경값 상속도 차단합니다.
7. **문서 작성 초점 경합:** 첫 GitHub CI에서 문서함 파일 1개가 실패해 추가 조사했습니다. 작성창의 `setTimeout(0)` 초점이 제목 입력 사이에 실행되면 글자가 본문으로 들어가거나 제목이 비어 저장이 시작되지 않는 상황을 재현했습니다. DOM 반영 직후 한 번만 초점을 처리하도록 바꾸고 지연 작업·실제 키보드 입력·원키 복구 회귀를 추가했습니다. 초점이 뒤늦게 사용자 입력을 가로채지 않는지, 새 작성·수정·사본 흐름을 함께 확인해 주세요.

기존 클라이언트의 잘못된 식별자·기간·판·권한 사전 차단은 유지했습니다. SQL 오류 이름과 맞추려고 잘못된 명령을 서버에 보내지는 않습니다. 남는 권장 오류코드 차이는 별도 기록하며 0 WARN으로 보고하지 않습니다.
