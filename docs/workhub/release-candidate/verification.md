## 실제 환경과의 경계

- 브라우저는 실제 UI와 전송 어댑터를 사용하지만 DB·Storage·provider 응답은 합성이다. 로그인·파일 전송·비용 발생을 포함한 운영 왕복 성공이 아니다.
- SQL은 로컬 PostgreSQL의 합성 계정·자료를 사용한다. 실제 PostgREST와 Supabase 확장 권한, 운영의 기존 객체 차이는 운영 기준선 이후 확인한다.
- SQL 원본과 원본 시험 기대값은 변경하지 않는다. 입력을 사전에 차단할 때 서버와 다른 코드를 보이는 알려진 비차단 경고만 정확한 허용 목록으로 기록한다. 새로운 경고는 검사 실패다.
- 원본 P8 하네스는 실패 snapshot을 앱에 전달하지 않고 preview를 호출하는 사례가 있다. 이 경고를 해결 완료로 지우지 않고, 실제 실패 snapshot→preview 순서는 별도 보충 대조 시험으로 확인한다. 보충 시험 실패도 전체 실패다.
- 설치 전후 보존 지문, 실제 업로드·서명 URL·ZIP, 교사 PC의 인쇄/PDF/Excel, 비용 보류 비서는 [후속 확인 절차](verification-runbook.md)로 구분한다.

## 발견 후 정리한 사항

- 첫 전체 회귀에서 과거 Windows 작업 사본의 셸 7개가 CRLF로 남아 LF 검사에 실패했다. 각 파일을 Git 원문과 비교해 줄바꿈 외 차이가 없음을 확인한 뒤 원문의 LF 바이트로 복원했다. SQL·스크립트 내용의 Git 변경은 없으며 재검사 통과했다.
- 비활성 설치의 실제 효과와 앱 배포 기준이 오래된 SQL 안내 두 곳을 발견해 S1·S2로 남겼고, 현재 `5c05c2d`에는 Claude 정정본이 포함되어 있다. [정정 확인](sql-review.md)에 남은 운영 안내 문구 두 곳도 구분해 적었다.
- 독립 검토에서 로컬 시험 분기 환경값이 원본 하네스에 상속될 수 있는 경계를 찾아 실행기에서 차단했다. 보강 있음/없음 경로가 실수로 같은 조건에서 실행되지 않도록 회귀를 추가했다.
- 첫 GitHub CI는 SQL·회귀·빌드는 통과했으나 브라우저 57개 파일 중 문서함 1개가 실패했다. 저장 요청 전 제목이 비어 HTML 필수값 검사가 막힐 수 있는 지연 초점 경합을 별도 통제 시험으로 재현했다. 첫 CI의 직접 원인은 당시 입력 값 로그가 없어 단정하지 않는다. 제품의 타이머 초점을 DOM 반영 직후 처리로 고치고, 지연 작업→제목 입력→저장 결과 미상→같은 번호 복구 회귀를 추가했다. Chromium 문서함 14건이 통과했다. 최종 GitHub 결과는 이 PR의 최신 commit 검사를 기준으로 한다.
  - 같은 정식 회귀에 수정 전 `34e16e0`의 문서함 구현만 메모리에서 대입하면 제목 빈값·서버 호출 0으로 실패한다. 수정본에서는 동일 시험이 통과한다. 원본 파일을 덮어쓰거나 기대값을 바꾸지 않고 비교했다.
