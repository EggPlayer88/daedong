# 통합 후보 자동 검증 결과

2026-10-16. 아래는 최종 앱 및 실행기 보강을 포함한 로컬 검사 결과다. 운영 DB 실행·main 병합·실제 서비스 연결 검증은 하지 않았다. PR의 CI는 같은 검사를 Linux에서 다시 실행한다.

각 검사에는 겹치는 경로가 있어 통과 건수를 합쳐 실사용 완료율로 환산하지 않는다. 원본 SQL 하네스의 기존 비차단 경고는 통합 4줄·P8 2줄, **총 6줄**이며 원문·건수·근거를 `summary.json`에 보존했다. 그중 실패 snapshot을 생략하는 시험 경로는 보충 21건으로 확인했다. 수정 전 앱을 같은 보충 시험에 넣으면 **17 통과 / 4 실패**가 되어 잘못된 경로를 실제로 잡는다.

SQL 원문 변경 0개, Linux 시험 사본의 셸 LF 보정 0개, 최종 종료 코드 0과 전용 PostgreSQL 종료를 확인했다. 소스 manifest·분기 증거·로그는 바탕화면 `GPT작업/2026-10-16_통합배포후보/SQL검증/최종완료`에 보관한다. 브라우저 결과는 같은 폴더의 `브라우저`에 보관한다.

## 실제 환경과의 경계

- 브라우저는 실제 UI와 전송 어댑터를 사용하지만 DB·Storage·provider 응답은 합성이다. 로그인·파일 전송·비용 발생을 포함한 운영 왕복 성공이 아니다.
- SQL은 로컬 PostgreSQL의 합성 계정·자료를 사용한다. 실제 PostgREST와 Supabase 확장 권한, 운영의 기존 객체 차이는 운영 기준선 이후 확인한다.
- SQL 원본과 원본 시험 기대값은 변경하지 않는다. 입력을 사전에 차단할 때 서버와 다른 코드를 보이는 알려진 비차단 경고만 정확한 허용 목록으로 기록한다. 새로운 경고는 검사 실패다.
- 원본 P8 하네스는 실패 snapshot을 앱에 전달하지 않고 preview를 호출하는 사례가 있다. 이 경고를 해결 완료로 지우지 않고, 실제 실패 snapshot→preview 순서는 별도 보충 대조 시험으로 확인한다. 보충 시험 실패도 전체 실패다.
- 설치 전후 보존 지문, 실제 업로드·서명 URL·ZIP, 교사 PC의 인쇄/PDF/Excel, 비용 보류 비서는 [후속 확인 절차](verification-runbook.md)로 구분한다.

## 이번에 확인한 주요 경계

- 인쇄·CSV 시작 실패 시 입력·미리보기·페이지 유지, 재시도 전 권한·자료 재검증.
- 관계 `UNAVAILABLE`의 소속·수업·조회 세대 격리와 원키 복구 유지.
- 101개 인계 기록·3쪽 이동, 마지막 쪽 대상 탐색, 원키 복구, 미접수 현재 조건 거절, 순환·50쪽 상한.
- 도움말 검색·메뉴 이동과 실제 업무실 입력 잠금, 320px·큰 글자·차콜, 키보드 닫기·초점 복구.
- 연결 점검의 조회 허용 목록, 취소·학교 변경·늦은 응답, 지원 JSON의 개인정보 제외.
- SQL 시험 실행기의 외부 접속 환경·타 폴더·새 WARN·실패 결과 차단과 종료 후 전용 서버 정지.

## 발견 후 정리한 사항

- 첫 전체 회귀에서 과거 Windows 작업 사본의 셸 7개가 CRLF로 남아 LF 검사에 실패했다. 각 파일을 Git 원문과 비교해 줄바꿈 외 차이가 없음을 확인한 뒤 원문의 LF 바이트로 복원했다. SQL·스크립트 내용의 Git 변경은 없으며 재검사 통과했다.
- 비활성 설치의 실제 효과와 앱 배포 기준이 오래된 SQL 안내 두 곳을 발견했다. SQL 자체를 임의 변경하지 않고 [Claude 정정 요청 S1·S2](sql-review.md)로 남겼다.
- 독립 검토에서 로컬 시험 분기 환경값이 원본 하네스에 상속될 수 있는 경계를 찾아 실행기에서 차단했다. 보강 있음/없음 경로가 실수로 같은 조건에서 실행되지 않도록 회귀를 추가했다.
