# 전체 시범 사용 통합 후보

2026-10-16 · 작업 브랜치 `feat/workhub-release-candidate` · main 대상의 단일 검토 후보.

이번 후보는 앱 PR #63의 C8 수정과 Claude PR #61의 R1S·1~8단계 SQL 이력을 함께 포함한다. 사용자가 요청한 **큰 구축 → Claude 검토 → 필요한 DB 작업 → 배포와 테스트**를 한 번에 진행하기 위한 기준본이다. 실제 SQL 적용, 기능 활성화, main 병합, 일반 교사 공개는 하지 않았다.

| 실행 인계 | SQL 원문·커밋·해시, 설치 효과, 배포 확인과 모듈 활성화, 실제 시험 항목 구분 | 여러 PR·파일 판을 섞지 않고 다음 단계 진행 |

사용 안내는 업무실 상단의 **사용 안내**에서 연다. 안내를 열기 전에는 상세 화면과 안내 자료를 지연 로딩한다. 입력 중에는 안내를 읽을 수 있고, 입력을 잃을 수 있는 메뉴 이동과 연결 점검은 잠금 상태를 따른다.

기능 연결 점검은 전체 또는 한 항목을 명시적으로 눌렀을 때만 시작한다. 학교·계정 변경, 닫기, 탭 전환, 중지 후 늦게 온 결과는 반영하지 않는다. 이름·이메일·학교/회원 식별자·학생 및 문서 내용을 지원 파일에 넣지 않는다. 조회 결과를 저장·제출·파일 전송 성공이나 기능 활성화 완료로 표시하지 않는다. AI 비용·모델 설정은 별도이며 점검에서 Claude 호출을 하지 않는다.

## 검토 기준과 보존

- 앱 원본: #63 `ed9ea32148b7b6b5dabbc3a53a03c2db06fd913e`.
- SQL 원본: #61 `edd743f978a8cf04f52b71d9892be209a89484ad`.
- 이전 #43/#45/#46/#48/#59/#60/#62 등은 위 앱 이력에 포함된다. SQL #47/#49/#50/#51/#52/#53/#55/#57/#58도 위 SQL 이력에 포함된다.
- `npm run check:workhub:release`가 포함·제외 이력과 SQL 원문, 기존 인증·공개 범위·양식·API·비용 관련 경계를 확인한다. 이 검사는 이번 후보에 대한 보존 기준이며, 미래의 승인된 변경은 기준 갱신과 검토를 거친다.
- Claude가 소유한 SQL 원문을 Codex가 고쳐 시험 결과를 맞추지 않았다. SQL 정정이 오면 Claude 커밋을 merge하고 기준 커밋·해시를 갱신한 뒤 통합 검사를 다시 한다.
- `sql-package.json`은 Git 원문의 LF 바이트 기준이다. Windows 편집기의 줄바꿈 변환 후 파일 해시와 다를 수 있으므로 실행 패키지는 같은 커밋의 원문으로 준비한다. 시험용 SQL과 제거·중지·활성화 파일은 자동 실행 순서로 해석하지 않는다.

## 다음 한 사이클

1. **Claude 검토:** 이번 앱 변경과 SQL 원문 보존, 검사 실행기, 이전 검토 사항을 한 후보에서 검토한다. SQL 실행 안내 S1·S2는 Claude가 정정한다.
2. **DB 기준선과 설치:** 사용자와 Claude가 현재 R0·R1 기준선부터 확인한다. 승인된 최신 순서로 R1S→P1~P7→별도 승인 P7-05→P8을 설치하고 각 지문·사후 점검을 보관한다. R0/R1 재실행과 제거 SQL을 정상 설치 순서에 넣지 않는다.
3. **앱 배포:** 검토·자동 검사·미리보기 확인 뒤 사용자가 이 통합 후보를 merge commit 방식으로 main에 병합한다. #60·#62만 먼저 배포하여 C8을 되살리지 않는다.
4. **관리자 제한 시험:** 배포 commit과 기존 로그인 보존을 확인하고 사용자와 Claude가 시험할 모듈을 각각 활성화한다. 실제 읽기·쓰기·첨부·복구를 모아서 확인한다.
5. **시범 범위 결정:** 통과한 기능과 남은 문제를 기록하고 일반 교사 공개 여부를 별도 결정한다. 비서 비용 미확정이나 시간표 보류를 자동으로 해제하지 않는다.

‘비활성 설치’도 Q4 새 학년도 검사와 공식 담당 인계 보호는 즉시 적용한다. 따라서 설치만으로 기존 동작이 전혀 달라지지 않는다고 설명하지 않는다. 세부 정정은 [SQL 검토](sql-review.md)를 따른다.

## 판단해서 정한 것

- 사용 안내·연결 점검을 별도 주 메뉴로 늘리지 않고 기존 헤더의 작은 도움말에 넣었다. 홈 정보량을 늘리지 않으며 향후 안내 내용은 `support/guide-data.json`에서 갱신할 수 있다.
- 새로운 준비 상태 RPC를 만들지 않고 각 기능의 기존 검증된 조회 어댑터를 재사용했다. DB 변경 없이 연결 실패 지점을 보여 주되 기능 활성화를 추측하지 않는다.
- 인쇄·다운로드의 로컬 실패는 재시도할 수 있게 보존하고, 권한·자료 최신성 실패는 이전 미리보기를 숨기는 구분을 유지했다.
- 클라이언트의 잘못된 입력 사전 차단은 유지했다. 서버와 오류 이름만 맞추기 위해 잘못된 명령을 보내지 않는다. 알려진 비차단 경고는 시험 결과에 그대로 기록한다.
- 한 후보에 큰 작업을 묶되 내부 커밋은 역할별로 나눴다. 이력 보존과 검토 대상 확인을 위해 squash/rebase/force push를 사용하지 않는다.
