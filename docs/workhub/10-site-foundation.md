# 5차 개발 — 공통 사이트 구조와 화면 연결

작성일: 2026-10-11

## 이번 단계의 목적과 범위

시간표 작업은 사용자 요청에 따라 보류했다. 기존 로그인과 회원 자료를 보존하는 신축 방향을 유지하면서, 기능을 추가할 때마다 메뉴·학교 전환·입력 보호를 다시 만드는 문제를 먼저 줄였다. 실제 연결 화면과 합성 자료 미리보기가 같은 사이트 틀을 사용한다.

이번 작업은 프론트엔드와 검증·인계 문서에 한정한다. DB/SQL, 기존 인증·가입 승인, AI 모델·비용, 외부 서비스 설정, 일반 교사 공개 범위는 바꾸지 않았다. 변경 사항은 작업 브랜치와 PR로 검토하며 운영 main에는 직접 반영하지 않는다.

## 교사가 이용하는 기본 구조

| 공간 | 역할 | 현재 연결 수준 |
|---|---|---|
| 오늘 | 내 업무, 처리할 수합, 오늘 관련 일정, 다가오는 7일을 모아 보기 | 실제 연결: 일정·개인 업무 / 수합은 합성 미리보기 |
| 내 업무 | 본인의 할 일을 등록·수정·완료·재개 | 실제 서버 어댑터와 미리보기가 같은 TaskPanel 사용 |
| 학교 일정 | 월·주·목록 보기, 날짜 이동, 검색, 나와 관련된 일정 | 실제 서버 어댑터와 합성 어댑터 모두 같은 화면 |
| 자료 수합 | 요청·공동 초안·제출·검토·보완·정정·완료 집계 | 합성 로컬 계약 검증, 서버 전환은 후속 |
| 수업과 학생 | 담당 수업·학생, 관찰·정정·철회, 수업 활동 근거 연결 | 합성 로컬 계약 검증, 실제 학생 저장소 아님 |

내 업무는 오늘의 하위 기능으로 분류한다. 데스크톱에서는 왼쪽 메뉴, 모바일에서는 오늘·내 업무·학교 일정과 더보기로 연결한다. 학교·회원 표시, 현재 위치, 저장 위치, 본문 건너뛰기, 페이지 이동 시 제목 초점, 오류 복구 방식은 공통이다.

실제 앱의 신규 기능 진입 권한은 기존 main 모듈 레지스트리와 연결 계층이 판단한다. workhub의 메뉴 목록은 화면 구성용이며 권한 검사를 대신하지 않는다. 수합·학생은 서버 준비가 끝나기 전 실제 연결 메뉴에 표시하지 않는다.

## 구현 구조

```text
기존 main 앱 /workhub                 독립 합성 DemoBootstrap
  기존 인증·소속 연결                    합성 store·미리보기 adapter
          └───────────────┬──────────────────┘
                     WorkspaceShell
                modules + navigation
              학교 맥락 / 메뉴 / 오류 복구
                        │
        ┌───────────────┼──────────────────┐
   CalendarPanel     TaskPanel      수합·학생 미리보기
   월·주·목록/홈      홈·전체목록        EditSession
        │                │                  │
     CalendarAdapter  TaskAdapter       합성 domain store
        │                │
   기존 Supabase 연결 또는 합성 adapter
```

- `modules.ts`: 공간명·그룹·연결 모드 목록. 이후 메뉴 추가는 여기부터 검토한다.
- `WorkspaceShell.tsx`: 사이트 공통 틀. 업무 자료를 직접 조회·저장하지 않는다.
- `navigation.ts`: 화면 주소와 이동 보호. 주소에는 화면 이름만 넣고 학교·계정 권한의 근거로 삼지 않는다.
- `ModuleBoundary.tsx`: 렌더링 실패를 해당 화면으로 격리하고 다시 열기 제공. 오류 원문·스택은 표시하지 않는다.
- `EditSession.tsx`: 여러 수합 응답·학생 카드의 편집 상태를 합산한다. 하나를 저장했다고 다른 미저장 카드의 보호가 풀리지 않는다.
- `preview/task-adapter.ts`: 합성 개인 업무 store를 실제 TaskPanel 계약에 맞춘다. 별도 미리보기 입력 화면의 중복을 제거했다.

오류 경계는 렌더링 오류를 다룬다. 네트워크·저장 실패는 각 모듈의 오류·재시도 화면에서 처리한다.

## 주소·이동·학교 전환 계약

`?view=calendar`, `?view=tasks`처럼 화면을 주소로 열고 새로고침·뒤로/앞으로 가기로 복원한다. 사용할 수 없는 값과 중복된 view는 오늘로 정리한다. 기존 경로·다른 검색 매개변수·해시는 보존한다. 같은 화면을 다시 눌러 중복 이력을 만들지 않는다.

작성·충돌 확인·저장 결과 확인 중에는 사이트 메뉴, 홈 바로가기, 학교 변경, 같은 탭의 기존 앱 링크, 브라우저 이력 이동을 보호한다. 새로고침·창 닫기에는 브라우저 기본 이탈 경고를 사용한다. 저장 또는 명시적인 편집 취소 후 이동한다. 새 탭 열기·다운로드·본문 위치 이동은 편집 화면을 없애지 않으므로 유지한다.

**호스트 통합 조건:** BrowserRouter보다 먼저 popstate 방어를 등록해야 한다. 따라서 기존 앱의 정적 WorkhubPage import가 navigation 모듈을 먼저 불러온다. lazy 컴포넌트 내부로 import를 옮기면 브라우저 뒤로가기에서 호스트가 먼저 편집 화면을 해제할 수 있다. 별도 브라우저 회귀시험으로 이 순서를 확인한다.

로그아웃·소속 종료·접근 승인 회수처럼 권한을 없애는 흐름을 편집 보호로 막지는 않는다. 강제 창 종료 후 미저장 원문이나 미확정 요청을 복구하는 영속 임시 저장은 이번 범위가 아니다. idx가 없는 외부 코드의 history 항목에서는 초안을 보존하기 위해 해당 항목을 기존 주소로 교정하는 제한적인 대체 경로를 쓴다.

## 일정 보기와 저장 복구

월·주·목록은 동일한 열람 가능 원본에서 파생한다. 날짜 범위와 겹치는 다일 일정을 표시하고 원본 건수는 중복 집계하지 않는다. 종일 일정 종료일은 포함한다. 목록은 선택한 달이 기본이며 전체 기간으로 바꿀 수 있다. 제목·장소·안내 검색, 나와 관련/열람 가능 전체 필터, 필터 초기화를 제공한다.

홈의 다가오는 일정은 내일부터 7일 이내 시작하는 관련 일정 중 최대 4개로 제한하고 전체 관련 일정으로 연결한다. 월 보기에서는 날짜 선택과 키보드 이동을 지원한다.

일정 저장 응답이 모호하게 실패하면 **원래 입력과 요청 번호를 고정**한다. 사용자는 같은 요청으로 결과를 다시 확인한다. 이 상태에서 내용을 바꾸거나 닫아 새 요청을 생성할 수 없게 했다. 확정된 입력 거부·권한 거부·충돌은 별도 처리한다. 충돌을 확인하고 다시 적용할 때는 최신 버전과 새 요청 번호를 사용한다. 이 복구는 어댑터/서버의 기존 멱등 계약을 사용하며 DB 계약을 바꾸지 않는다.

## 수합·학생 입력의 기본 보호

- 공동 초안을 저장한 뒤 정규화된 반환값으로 입력을 맞춘다. 앞뒤 공백 때문에 제출 버튼이 계속 막히던 문제를 수정했다.
- 저장 완료된 초안은 이동할 수 있다. 미저장 수정·다른 작성자와의 충돌·정정 사유는 계속 보호한다.
- 수합 선택·받은/보낸 요청 전환·새 요청 시작도 보호를 거친다.
- 학생 선택·수업·날짜·활동 전환 중 미저장 관찰이 사라지지 않도록 보호한다.
- 학생 관찰, 정정, 철회 사유, 수업 활동 입력에 명시적인 취소 경로를 제공한다.
- 합성 개인 업무의 글자 수와 날짜 정규화도 실제 TaskPanel과 같은 검증기를 쓴다.

이는 아직 로컬 계약 검증이다. 실제 학생 정보와 문서 파일을 넣는 권한·보존·서버 저장 기능을 완료했다는 의미가 아니다.
