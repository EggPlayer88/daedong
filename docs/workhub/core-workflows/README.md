# 일정 취소·AI 이어 수정·기본표 운영 연결

2026-11-16. #133의 메시지 알림 원본 이동·복구 안내 위에 이어지는 세 가지 핵심 작업이다. 운영 계정·권한·자료·AI 정책을 변경하지 않고 구현과 격리 시험을 준비한다. 이 문서는 운영 적용 완료 기록이 아니다.

## 1. 일정 취소

학교 일정 또는 AI 안의 일정 목록에서 원본을 열고 **일정 취소 → 사유 입력 → 대상·사유 확인 → 이 일정 취소** 순서로 진행한다. 작성자·기존 일정 관리 담당자의 수정 가능 범위를 그대로 사용한다. 공식 학사·휴업 일정과 남의 비공개 일정은 서버에서 차단한다.

원본과 이전 판은 삭제하지 않는다. 취소된 일정은 예정 목록과 홈에서 빠지고, **일정 상태 → 취소한 일정**에서 사유와 원본을 확인한다. 취소한 원본의 후속 편집·가져오기 덮어쓰기는 서버에서도 막는다. 취소 알림 수신자를 새로 추가하는 변경은 없다.

전송이 끊기면 원래 요청 번호·명령을 보관한다. **취소 결과 확인**은 조회만 한다. 미접수 응답은 실패 확정이 아니므로, 새 요청을 만들지 않는다. 사용자가 **같은 취소 요청 다시 보내기**를 선택했을 때만 같은 번호로 재전송한다. 요청을 보관하고 창을 닫거나 같은 탭을 새로고침한 뒤에도 결과 확인부터 이어간다.

## 2. AI 초안 이어 수정

작성 중인 할 일·일정·메시지·수합에 항목을 명시해서 수정한다.

| 초안 | 대화 예 | 유지하는 정보 |
|---|---|---|
| 할 일 | `제목은 자료 검토`, `기한만 내일로 바꿔줘` | 같은 제안·원본 판, 나머지 입력 |
| 일정 | `날짜는 11월 18일`, `장소는 회의실` | 제목·다른 시각·대상 조건 |
| 메시지 | `본문: 자료를 확인해 주세요.` | 기존 제목·선택한 수신자 |
| 수합 | `기한은 11월 19일`, `안내: 수정 자료를 올려 주세요.` | 제목·기존 제출 대상·다른 설정 |

본문 안의 명령어는 본문으로 보존한다. 대상을 바꾸려면 후보에서 다시 선택하며, 기존 대상이 조용히 다른 사람으로 바뀌지 않는다. 해석할 수 없으면 입력과 초안을 유지하고 다시 묻는다. 유료 일반 답변으로 우회하거나 임의로 저장·전송·공개하지 않는다.

일정 검토 단계에서 **내용 이어 수정**으로 돌아가 바꾼 뒤 재검토한다. 이미 서버로 보낸 요청이나 결과 미상 요청은 수정하지 않고 원래 번호의 결과를 먼저 확인한다. `일정 취소`라는 독립 요청은 일정 목록을 열며, 특정 일정을 자동으로 취소하지 않는다.

## 3. 기본 주간표를 날짜별 운영에 연결

가입 전 교사 명부의 확정 기본표(TR1)와 날짜별 수업·교환·실시 기록(T2)은 별도 자료다. TR2는 기본표의 교사·학급·수업·교시 시각과 실제 소속·담당 배정을 특정 기간에 대조하고, 검토된 변경만 기존 T2 발행 경로에 전달한다.

화면은 기존 시간표 관리 권한으로 진입한다. **기본 주간표 선택 → 적용 시작일·마지막 날 → 날짜별 연결 미리보기 → 변경 수업 확인 → 확인한 날짜별 수업 반영** 순서다. 미리보기만으로 날짜별 수업을 공개하지 않는다.

- 명부 원본을 불변 연결 자료로 보존한다. 기존 편성 기준판·준비 입력을 교체하지 않는다.
- 담당 교사 연결·유효 기간·학급·수업·실제 시각을 확인할 수 없으면 차단한다. 가입 전 이름을 로그인 계정으로 추정하지 않는다.
- 다른 출처의 기존 시험·운영 수업은 자동 취소하지 않는다. 겹치는 수업은 충돌로 표시한다.
- 휴업·특별 일과·교환으로 이미 변경된 수업은 기존 T2의 보존 규칙을 사용한다.
- 같은 요청 재확인·명시 재전송·요청 닫기에서 서버 접수증 또는 취소 기록을 확인한 뒤에만 새 요청을 허용한다.

운영의 시험 교사 연결에는 유효 기간이 있다. 그 기간을 넘는 기본표 발행을 위해 권한이나 소속을 자동 연장하지 않는다.

## PR #134 CI 회귀 보완

첫 CI에서 SQL·단위 검사는 통과했고 브라우저 파일 206개 중 204개가 통과했다. 기존 공개 결과/학기 공개 확정 두 시험의 합성 서버가 새 기본표 조회에도 옛 시간표 응답을 반환해 불필요한 오류가 하나 더 생겼고, 전체 화면의 오류 탐색이 두 항목을 찾아 실패했다.

두 합성 서버에 새 조회 계약의 정상 빈 기본표 응답을 추가하고, 오류 검증을 저장 초안 확정 영역으로 한정했다. 기본표 영역의 빈 안내와 오류 0개도 확인한다. 오류 응답 시 확정 금지·쓰기 0회·원키 복구 기대값은 유지했다. 앱·SQL·권한은 변경하지 않았다. 수정한 두 파일을 다시 실행해 공개 결과 41건·학기 공개 확정 18건, 합계 59건이 통과했다. 새 커밋의 전체 CI 결과는 별도 확인한다.
