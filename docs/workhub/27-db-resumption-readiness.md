# DB 준비 재개 인계 — 기초 연결과 미해결 설계 항목

2026-10-14 · 상태: **DB 준비 재개 · F6의 4표 계약·정적 회귀 보완 / 확정 SQL·실제 적용·운영 검증은 미완료**

## 1. 이번 문서의 범위와 권위

사용자는 DB 준비를 재개하도록 승인했다. 이번 단계는 기존 자료 보존 기준, 설계의 모순, 학교 초기 설정과 서버 연결에 필요한 계약을 구체화하는 작업이다. 이 문서는 SQL 실행본이나 인증·권한 변경본이 아니며, 실제 Supabase에 접속하거나 변경하지 않았다. SQL 확정본은 Claude Web이 작성하고, 검증·운영 환경 적용은 사용자가 수행한다. 코드·문서 PR은 Claude 교차 검토 후 사용자가 병합한다.

시간표 실행과 문서작성 AI 개발은 계속 보류한다. 시간표 보류 때문에 일반 학교·학기·수업 기반까지 생략하지 않으며, 보류된 시간표 표를 앞 단계의 필수 FK로 참조하는 순서는 설계에서 바로잡는다. 학교 지식 상담·개인 비서 전체를 문서작성 AI 보류와 동일하게 취급하지 않는다.

현재 [통합 DB v1.1](database-integrated/README.md)은 **목표 설계**다. 190개 테이블·29개 API 기능군·114개 인수 시나리오가 실제로 구축됐다는 뜻이 아니다. 이번 작업은 v1.1의 F6 중 확인된 4표의 계약과 생성기를 부분 보완했다. 나머지 해결안은 제안이며, 전체 F6 해결·확정 SQL 작성·실제 DB 검증 완료를 뜻하지 않는다.

## 2. 이미 정해진 방향과 아직 정하지 않은 정책

다음 방향을 다시 선택하게 하지 않는다.

| 방향 | 확정 출처 | 준비 단계의 처리 |
|---|---|---|
| 기존 Google 로그인·Auth UID·기존 가입 회원 보존 | 사용자: “특히 로그인 인증 및 기존 회원가입 데이터는 남겨야돼”; IDB-03 | 재가입·이메일 추정 연결·회원 초기화 금지. 기존 실사용 문서·파일 참조도 보존 대상으로 조사 |
| 여러 학교가 각각 사용하는 서비스 | 사용자 운영 범위 답변 | 학교 키·관계·권한을 처음부터 분리. 실제 첫 학교/관리자 식별값은 별도 확인 |

| 신규 모듈 superadmin 기본 공개, 공개 확대는 사용자 승인 | CLAUDE.md §2-1 | 학교 관리자 승인만으로 전체 공개를 넓히는 API 문구를 정정할 수정 티켓 작성 |
| 모델·토큰 상한·캐시 등 비용 구조 변경은 사용자 승인 | CLAUDE.md §2 | 기본 승인 주체를 사용자로 유지. 운영자에게 위임하는 새 권한은 승인된 것으로 추정하지 않음 |

| 문서작성 AI·시간표를 제외한 기능 완성 후 시범 공개 | 사용자 최근 시범 공개 목표 | 학교 연결만 된 상태를 전체 시범 운영 준비 완료로 표시하지 않음 |

DB 준비 재개는 위 보존 조건이나 SQL 담당 분담을 없애지 않는다. 과거 D18의 초기화·force push 기록은 당시 완료된 이력이며, 현재 회원 보존 요구를 뒤집는 재실행 지시가 아니다.

## 3. 먼저 닫을 기초 단계

R0는 **동일한 기존 계정으로 학교 연결 → 일정·업무 조회/저장 → 재조회·재로그인 후 확인**까지의 최소 실제 왕복이다. 최종 시범 공개와 구분한다. B00~B11은 기존 배치명을 인용한 것이며, 아래 제안만으로 배치 정본이 변경되지는 않는다.

| 준비 구간 | 지금 가능한 산출물 | 실제 구현 전 차단 항목 |
|---|---|---|
| B00 보존·현황 준비 | 읽기 조사 항목, 기존 회원/파일 대응표 양식, 검증 환경·복구 증거 목록 | 대상 프로젝트·적용 상태·백업/복구 경계의 실제 확인. 이 문서에서 운영 명령 실행 안 함 |
| B01 학교·회원·역할·감사·접수 | 초기 학교 설정 입력 계약, 승인 전 미리보기, 가입/소속 상태 설명 | **F5** 공통 의존 순서, **F6** 접수의 서비스 actor 제약, **F8** 기존 승인·공개 범위 보존 명시. Q25는 승인 gate 변경/신규 학교 가입·승인 전환 때 필수. 실제 bootstrap·회원 API 계약 확정 |
| 학년도·학기·담당 기초 | 학교 시간대, 학년도·학기 기간, 기본 관계의 입력·검증안 | **F5** 학년도/학기를 참조하는 앞 배치와 뒤 배치 충돌, **F7** 담당 관계의 역사 보존. 생성/정정/종료 명령과 기간 경계 명세 누락 |
| B02 R0 일정·업무 | 기존 RPC/DTO와 통합 목표 차이표, 어댑터 전환 계획 | B01 통과, 학년도 참조 선행, 보류 시간표 FK 분리, 현재 권한/멱등/충돌·응답 유실 시험 |
| 공통 파일 | 업로드·검사·연결·다운로드·차단·파기 상태/명령 계약 | **F2** 읽기권의 재공개 전환 차단, **F9** 파기 대상별 증거·재시도, **F5/F6** 작업/원장 선행 및 제약 대조 |
| 수합·학생·Claude 연결 | 각 기능의 정상/거부 시나리오를 설계 수정 티켓에 연결 | F3·D9·D7/D8는 수합 전에, F1/F7·Q23·상담 권한은 학생 전에, F4·비용 정책은 실제 AI 호출 전에 통과 |

**R0 확정 SQL 작성의 우선 조건은 F5·F6·F8의 기초 적용분이다.** 기존 승인 gate와 최고관리자 공개 범위를 유지하고 이미 승인된 기존 계정의 R0 왕복만 여는 경우에는, 신규 유입/승인 전환을 구현하지 않고 진행할 수 있다. Q25를 모든 R0의 별도 재승인 조건으로 삼지 않는다. 역할별 SQL 검증·회원 보존 확인은 여전히 필수다. 나머지 모든 도메인을 완성할 때까지 학교 설정 화면을 멈출 필요는 없다. 대신 파일·학생·AI를 실제로 열 때 각 도메인의 미해결 항목을 다시 완료 조건으로 적용한다. 준비 화면은 검토용 값과 안내만 제공하며 실제 학교/회원 생성 완료를 가장하지 않는다.

## 4. F1~F9 수정 티켓

공통 제출물은 ① 변경 이유와 반례, ② 수정 계약, ③ 표·열·제약·명령 영향표, ④ 정상/거부/경합 시험, ⑤ 단계별 적용·되돌림 조건이다. JSON 카탈로그, 도메인 문서, SQL 인계서, 수용 시험을 같이 맞춘 뒤 SQL로 옮긴다. 실행 시험의 오류가 fixture·문법·객체 누락 때문이면 권한 거부 성공으로 세지 않는다.

### F1 — 학급 단위 수업에서 수강 행을 무조건 요구

- **현재 사실:** participant_mapping_revisions의 confirmed 제약은 student_id·enrollment_id·course_membership_id 모두 NOT NULL이다. observation_revisions도 course_group_id가 있으면 수강과 승인 담당을 요구한다. class_enrollment 방식의 학급 수업은 별도 course_memberships 행 없이 명부를 만드는 정의와 충돌한다.
- **실사용 반례:** 일반 학급에 학생·학적·그날 유효한 수업-학급 연결·담당 교사가 모두 있어도 별도 수강 행이 없다는 이유로 관찰 작성/학생 매핑 확정을 거절한다.
- **수정 대상:** participant_mapping_revisions, observation_revisions, assessment_revisions, course_groups의 명부 기준, course_group_classes, student_enrollments, course_memberships, course_group_teachers. cmd_classroom_import_apply/remap/adopt 및 관찰·평가 확정 명령의 관계 검사.
- **해결안:** 명부 근거별 검증을 하나의 권위 있는 규칙으로 정의한다. class_enrollment는 활동일의 학적+학급 연결, course_membership은 그날의 유효 수강을 사용한다. 교사 담당·같은 학교/학생/수업 검사와 정확한 근거판 고정은 양쪽 모두 유지한다. 편의상 학생×수업 수강 행을 중복 생성하지 않는다.
- **우선 배치:** 수업 공통 기반 명세 시 반영, B07~08 학생·활동 쓰기 전에 필수.
- **통과 조건:** 정상 학급 수업/선택 수강 모두 성공. 해당일 반·수강 불일치, 타학생·타학교, 만료 담당, 매핑판 변경은 각각 의도한 오류로 거부. 관찰과 외부 수업 앱 채택이 같은 결과를 내야 한다.
- **상태:** 미해결. 수정안·시험 미구현.

### F2 — 파일 읽기권을 이용한 공개 범위 확대

- **현재 사실:** 일반 file_links는 “파일읽기+목적쓰기+공개범위 상승 허용 검사”라고만 정의한다. 메신저의 새 미연결 업로드·양식 원본/답변 분리는 v1.1에서 보강됐으나 일반 파일의 재연결 허용 판정은 불완전하다.
- **실사용 반례:** 제출물 검토자가 읽을 수 있는 다른 교사의 제출 파일을 자신이 편집할 수 있는 학교 공유 문서에 연결하면, 읽기·쓰기 검사는 모두 참인데 새 독자에게 원문을 공개할 수 있다.
- **수정 대상:** file_links, submission_files, document_inputs, document_revisions의 출력 파일 관계, 파일 grant와 원본 resolver, 문서 저장/첨부 명령, cmd_file_download. 후속 메신저/수합 typed 관계도 공통 규칙을 사용한다.
- **해결안:** “읽을 수 있음”과 “대상을 넓혀 재공개할 수 있음”을 분리한다. 허용되는 원본 내부 이전을 명시하고, 그 밖의 연결/복사는 원본의 공개 권한·대상·민감도 조건을 만족해야 한다. 단순 복사나 새 소유자 지정만으로 원본 ACL을 제거하지 않는다. 타인 원본은 현재 원본 권한을 유지하거나 별도 승인된 재공개 절차를 요구한다.
- **우선 배치:** 공통 파일의 연결/다운로드를 열기 전.
- **통과 조건:** 위 반대 방향 재연결 거부. 정상 업로드→자기 초안→제출판→승인 export는 성공. 원본 권한 축소 뒤 기존 grant/미리보기/ZIP/사본도 새 요청에서 차단. 링크 부모 UPDATE·원본 없는 파일 ID 입력 거부.
- **상태:** 일부 신규 경로 보강, 일반 반례 미해결.

### F3 — 공동작성자·대리의 자기검토 우회

- **현재 사실:** submission_reviews는 실제 제출자·당시 책임자·현재 책임자 계정만 forbid 비교에 넣는다.
- **실사용 반례:** 공동작성자 또는 제출하지 않은 유효 대리가 검토자도 맡으면 자신이 작성한 단위의 제출을 승인할 수 있다.
- **수정 대상:** submission_reviews, submission_versions의 계정 snapshot, collection_unit_members, collection_reviewers 및 수합 검토 명령. 기존 명시 자기검토 예외 정책과도 대조.
- **해결안:** 세 계정에 현재 유효한 단위 구성원·대리 계정을 더해 금지 집합을 정의한다. membership ID가 바뀌어도 account로 비교한다. 과거 공동작성자까지 어느 범위로 보존할지, 예외를 허용할지는 정책으로 명시하고 임의 관리자 우회를 만들지 않는다.
- **우선 배치:** 수합 검토 기능 전에.
- **통과 조건:** 공동작성자·대리·인계 후 전임 제출자·동일 계정 새 소속의 자기검토 거부. 무관한 현재 지정 검토자 정상 승인. 승인 정책 없는 예외와 공백 사유 거부. 검토 중 권한 회수 경합도 거부.
- **상태:** 미해결.

### F4 — 공급자가 실행하지 않았다고 확정한 실패를 구분할 수 없음

- **현재 사실:** job_external_calls.state는 prepared/request_started/response_received/unknown/confirmed_not_run/confirmed_succeeded/cancelled다. confirmed_not_run은 사람이 사후 확인한 증거를 요구하여 공급자가 실행하지 않았음을 즉시 증명한 응답과 구분되지 않는다.
- **실사용 반례:** 실행되지 않은 요청도 불명확 상태로 남아 사람이 처리해야 하거나, 불변 결과를 저장하지 않았는데 response_received로 기록하게 된다. SDK의 숨은 자동 재시도는 원장 한 건에 실제 여러 요청을 감출 수 있다.
- **수정 대상:** job_external_calls, job_attempts, jobs, usage_events, 공급자 어댑터 및 claim/reap/retry/finalize 경로, ai_policy_versions의 재시도 정책.
- **해결안:** provider_rejected 같은 명시 상태 또는 동등한 확정 비실행 사유·증거·전이 계약을 추가한다. 공급자 자료로 비실행이 증명된 응답과 처리 여부가 불명확한 응답을 분리한다. SDK 재시도를 원장이 전부 관측하도록 하며 시도별 call_key와 비용을 기록한다. 특정 HTTP 코드만으로 무조건 미실행을 추정하지 않고 구현 시점의 공식 공급자 계약을 확인한다.
- **우선 배치:** 실제 Claude 호출을 여는 B09~10 해당분 전에. 초기 학교/회원 연결의 선행 조건은 아님.
- **통과 조건:** 확정 비실행의 승인된 재시도, 재시도 불가 오류 종료, timeout/전송 후 crash의 unknown 보존, 결과 저장 후 finalize만 재개, 늦은 옛 lease의 업무 확정 거부, 실제 전송 횟수와 원장/비용의 일치.
- **상태:** 미해결. 불명확 호출의 자동 재호출 횟수·중복 비용 허용은 사용자 미결정 사항.

### F5 — 공통 배치와 FK·트리거·outbox 생성 순서

- **현재 사실:** 190표에 표별 batch 메타데이터가 없다. 공통 명령은 receipt/audit/outbox 원자 저장을 요구하지만 outbox는 B03에 배치되어 있다. calendar_days와 tasks는 academic_years를 참조하지만 학기 기반은 뒤 배치로 적혀 있다.

- **반례:** B01/B02만 생성한 DB에서 outbox INSERT 또는 뒤 배치 객체를 조회하는 함수가 실패한다. 일정을 만들기 위해 보류 중인 시간표 전체를 억지로 생성하는 역전이 생긴다.

- **해결안:** 07 배치표를 유일한 정본으로 삼고 표·열·FK·트리거·허용 API의 생성 단계를 정형화한다. outbox 및 B01 접수·감사에 필요한 최소 의존은 B01로 당기는 안을 검토한다. 학년도/학기는 최초 참조 전에 생성한다. 시간표 전용 열/FK/트리거/API는 후속 활성화 단계로 명시하며 그 전 입력도 받지 않는다.
- **주의:** 최종 카탈로그에 시간표 FK가 있다는 사실 자체는 오류가 아니다. v1.1은 메신저 시간표 카드 FK의 후속 생성을 이미 서술했다. 빠진 것은 전체 최종 계약과 각 중간 배치의 정확한 차이/검증 가능한 manifest다. 최종 FK를 영구 삭제하거나 초기 배치에 NOT VALID로 남겨 해결하지 않는다.
- **우선 배치:** **B01/R0 확정 SQL 작성 전 최우선.**
- **통과 조건:** 빈 격리 DB에 선행 배치만 순차 적용하여 그 단계의 정상 명령 전부 성공. 미생성 객체 참조 0, 노출 표의 필수 제약/권한 누락 0, 보류 시간표 입력 거부. 후속 FK 추가 시 기존 자료 전수 검증. outbox 또는 감사 실패는 업무·접수 모두 롤백.
- **상태:** 공통 부분 미해결. 신규 메신저 후속 FK 순서의 서술만 부분 보강.

### F6 — 상속 제약과 새 열·정책 규칙의 모순

- **수정 전 확인한 객체:**
  - collections에서 삭제된 visibility/view_audience_set_id를 참조하는 collections_check, collections_visibility_check, collections_visibility_not_null, collections_school_id_view_audience_set_id_fkey가 남아 있다. 같은 FK는 inherited_foreign_keys에도 있어 보고서의 “5건”을 서로 다른 제약 5개로 오해하지 않는다. 이번 대조에서 고유 제약명은 4개다.
  - NULL을 허용한 idempotency_receipts.actor_account_id, collection_units.responsible_membership_id, usage_events의 input/output/cache_read/cache_write_tokens에 상속 NOT NULL이 남아 있다.
  - usage_events 토큰 네 열은 설명에 DEFAULT 제거라고 쓰였지만 default 값은 0이다.
  - submission_versions의 날짜 마감·철회 CHECK, correction_one_open과 보완 충족판 철회 시 재개 규칙, file_links/인계 품목의 기존 유일 조건도 전수 판정 대상이다.
- **반례:** 서비스 actor 접수는 사람 actor가 NULL이어야 하는데 옛 NOT NULL에 걸린다. 삭제한 열을 참조하는 CHECK/FK를 복사하면 DDL이 성립하지 않는다. 비용 미확인을 0으로 저장하거나 정상 철회를 옛 CHECK가 거부한다.
- **수정 대상:** 모든 160개 상속표의 constraints/indexes/triggers/policies와 수정 열, 특히 위 표·제약. 기존 source baseline은 근거로 보존한다.
- **해결안:** inherited 항목별 유지/대체/삭제와 대체 대상·이유·배치를 기록한다. superseded_constraints가 현재 6표에만 있는 상태를 전수 대조로 확장한다. 정형 검사에 삭제 열 참조, NULL 허용/NOT NULL 모순, 기본값/설명 모순, 중복·충돌 유일 조건을 추가한다. 순서를 맞추려고 검사를 통째로 제거하지 않는다.
- **우선 배치:** **B01/R0는 actor/접수·기초 참조분부터 필수**. 각 후속 배치 진입 전 해당 표 전부 판정 완료.
- **통과 조건:** 상속 제약마다 처분과 근거가 존재. 최종 SQL 역추출과 목표 카탈로그 차이 0 또는 승인된 차이만 존재. 사람/서비스 actor 각각 정상·위조 거부, 책임자 공백, 토큰 NULL/실제0, 날짜 마감 경계, 철회·보완 재개 정상/충돌 시험. 구조 검사 통과를 PostgreSQL 실행 증거로 대체하지 않음.
- **상태:** 확인된 4표의 명시 제약 모순은 계약·생성기에서 수정했고 격리 생성/변조 회귀 17건이 통과했다. 전체 160표의 제약 처분, 날짜 마감·철회·보완 재개 등의 나머지 F6, 실제 SQL·DB 시험은 미완료다.

이번 F6 부분 보완의 산출물:

- schema-contract.json/09-table-dictionary.md/validation-result.json은 수정 목록에서 재생성했다. 정적 검사 오류·경고 0은 이 검사 범위의 결과이며 전체 F1~F9 해결을 뜻하지 않는다.

### F7 — 학적·수강·담당 수정으로 과거 기록의 의미가 바뀜

- **현재 사실:** student_enrollments, course_memberships, assignments, course_group_teachers는 changed=false이며 mandatory 규칙이 비어 있다. 관계 ID가 같아도 당시 반·담당 의미가 고정된다는 계약이 부족하다.
- **과거 실험 반례:** Claude는 학적 행을 다른 반·번호로 제자리 수정했을 때 참조 관찰 19건의 당시 반이 바뀌었다고 보고했다. 학적 밖 수강 기간·미래 관찰일 사례도 보고했으며 이번 문서에서는 재실행하지 않았다.
- **수정 대상:** 네 관계표, 이를 참조하는 관찰·평가·상담·채택 snapshot, cmd_assign과 학적/수강/담당 변경 명령, 관찰 저장/정정 명령.
- **해결안:** 이미 기록이 참조한 학생·학교·학급·수업·담당 의미와 유효기간의 역사 해석을 고정한다. 정정은 새 관계/판+대체 관계로 남기고 기존 근거를 덮지 않는다. 현재 권한의 즉시 회수는 상태·회수시각으로 별도 처리하여 역사 보존이 퇴직 권한 유지를 뜻하지 않게 한다. 수강/담당 기간과 학기/학적의 포함 규칙, 관찰일의 학교 시간대·미래 금지를 명시한다.
- **우선 배치:** 학교 담당/학기 기초 명세 때 반영, 학생 쓰기 전에 완결.
- **통과 조건:** 기록 이후 반·번호·담당 정정이 기존 기록의 당시 의미를 바꾸지 않음. 정상 전입·분반·담당 교체·조기 종료 성공. 기간 밖 관계/미래 관찰/타학생 연결 거부. 종료된 관계의 현재 권한은 즉시 차단.
- **상태:** 미해결.

### F8 — 사용자 결정과 설계 제안을 구분하지 않음

- **현재 사실:** Q23 과거 학생 기록 재열람, Q25 legacy 승인 혼합안이 계약의 확정 문장으로 남아 있다. API-02의 학교 관리 권한 설명이 cmd_set_feature_visibility의 공개 확대에도 포괄 적용된다. 10-decision-register에는 IDB-01~14와 기능 요구 추가만 있다.
- **반례:** 담당자가 이 문장을 실행 지시로 읽으면 승인제 전환·재임용 접근·학교 관리자 공개 확대를 사용자 결정 없이 구현할 수 있다.
- **수정 대상:** memberships/accounts 접근 규칙, legacy bridge, API-01/02와 cmd_set_feature_visibility, 학생 기록 읽기 규칙, ai_policy_versions 승인 주체, 결정 제안/인계 문서.
- **해결안:** §5처럼 이미 확정/추가 결정/구현 제안을 분리한다. 공개 확대는 기존 사용자 승인 규칙으로 바로잡는다. Q25 선택 전에 현재 인증 경로를 변경하지 않는다. 공급자 Claude는 다시 미결정으로 돌리지 않는다. 승인된 제품 방향을 반복 질문하는 대신 구체적인 미정 경계와 영향만 제시한다.
- **우선 배치:** **B01/R0 전에 기존 승인 gate·최고관리자 공개 범위 보존과 실제 적용 범위 명시가 필수**. 기존 승인된 계정의 제한된 R0에서 승인 체계를 바꾸지 않으면 Q25 결정 대기로 전체를 막지 않는다. 기존 gate 변경, 신규 학교 가입·승인 전환 구현 전에는 Q25 결정이 필요하고 일반 교사/다학교 공개 전에 정리한다. Q23은 학생 과거 자료를 열기 전에 필수.
- **통과 조건:** 모든 관련 계약에 확정 출처 또는 결정 대기 표시가 있음. 결정 대기 기능은 명시적으로 차단. 기존 회원/신규 회원/승인 회수/재임용/다중 학교 각 분기 시험. 학교 관리자 단독 공개 확대 거부.
- **상태:** 미해결. §5는 재분류 제안이며 새 D번호를 확정하지 않음.

### F9 — 파기의 항목별 실행·거절·재개를 표현하지 못함

- **현재 사실:** deletion_ledger는 원본별 유일이고 상태에 rejected/withdrawn이 없다. “대조 후 완료”라는 문장만으로 대상별 결과를 보관할 구조가 부족하다. 학생 기록 판의 가림/파기 본문 상태도 명시되어 있지 않다.
- **반례:** 승인 거절된 요청을 종료할 수 없거나 같은 원본의 후속 요청을 막는다. 본문은 지웠지만 파일/색인/캐시/출력 일부가 남아도 어떤 대상이 남았는지 입증할 수 없다.
- **수정 대상:** deletion_ledger의 state CHECK·원본별 UNIQUE·deletion_ledger_check2(요청 이후 승인/차단 시각 필수), 학생 기록 revision의 본문 수명 상태, 삭제 대상 manifest/항목별 실행 기록, files·file_links·추출·색인·파생 출력·export와 복구 재적용 원장, cmd_file_delete_request 및 파기 worker.
- **해결안:** 승인 manifest에 정확한 대상 ID/판/지문을 고정하고 항목별 대기·처리·실패·보류·확인 결과를 보관한다. rejected/withdrawn 등 종료를 정의하고 중복 제한은 열린 요청에 적용한다. 일반 수정 불변과 승인된 본문 가림/파기 전이를 구분한다. 삭제 대상 전체의 종료와 증거 대조가 있어야 완료이며, hold/일부 실패는 완료로 표시하지 않는다.
- **우선 배치:** 공통 파일 수명주기 전에 구조 확정, 실제 학생/파일 자료 수집·파기·복원 전에 해당 실행 경로 검증.
- **통과 조건:** 거절→새 요청, 철회→새 요청, 부분 실패→남은 항목만 재개, hold 중 차단, 원본/사본/파일/색인/캐시/출력의 대조, 백업 복원 후 삭제/권한 회수 재적용. 파일 bytes·hash 확인 없이 DB행 삭제만으로 완료하지 않음.
- **상태:** 미해결. 보존연수·법적 근거·백업 만료 수치를 이 문서가 정하지 않음.

## 5. 과거 ‘사용자 결정 8건’의 현재 재분류

아래 D7/D8/D9는 **Claude 재평가 안에서 사용한 발견 번호**다. 저장소 docs/DECISIONS.md의 같은 D번호와 다른 번호 체계이며, 기존 확정 결정을 바꾸지 않는다. 질문을 한꺼번에 다시 제출하지 말고 기능을 열기 직전 필요한 미정 항목만 구체화한다.

|---|---|---|---|
| 1 / Q23 | 같은 학교 재임용 후 옛 자료 재열람 | **미결정:** 같은 계정 보존은 확정이지만 학생 기록 자동 재열람까지 승인한 근거는 확인되지 않음 | 개인 업무 자료와 민감 학생 자료를 분리. 업무는 현재 학교 권한, 학생 과거 기록은 확인 절차를 두는 Claude ③안을 검토. 학생 과거 자료 열람 전 사용자 결정 |

| 5 | 결과 불명확 Claude 호출 자동 재호출 | **미결정:** Claude 선택은 재시도/중복 비용 승인이 아님 | 외부 부작용 있는 전송과 읽기·글 생성 분리. 처리 여부 불명확의 자동 재호출 여부/상한/비용 표시를 실제 AI 연결 전에 승인. 보고서의 “처음 1회”는 제안일 뿐 확정값 아님 |

따라서 “8건 모두 미결정이니 8개를 다시 답해 달라”는 결론은 부정확하다. Q25는 승인 체계 변경/신규 학교 가입 전환의 핵심 미정 정책이지만, 현행 gate를 유지하는 기존 계정 R0의 의무 질문은 아니다. 적용 범위를 먼저 정하고 전환이 필요할 때 구체 선택안을 요청한다. Q23·제출 지연·AI 재호출·상담 관계도 관련 기능을 열기 전에 확정하면 된다. Q6 스키마 분리, Q24 개인 공간, Q26 안내/결과 범위 분리는 기존 설계 제안과 사용자 기능 의도에 맞춰 유지하되, 이것을 운영 스키마·보안 변경 실행 승인으로 표시하지 않는다.

민감 파일 인증 프록시, 보존기간, 파일 한도, 실제 지원 양식, 담당자 부재의 대리 승인 등도 기존 설계의 운영 정책 검토 항목이다. 값을 임의로 채우지 않으며 해당 기능의 적용본과 함께 검토한다.

학교 초기 설정은 테이블 명세만으로 끝나지 않는다. 최초 학교 생성·관리자 지정·학년도/학기 생성·기간 정정·학교 활성화마다 누가, 어느 상태에서, 어떤 expectedVersion/requestKey로 실행하는지와 현재 학교 전환/재조회 결과를 계약에 적는다. preparing 상태의 학교를 학교 업무 사용 가능으로 보여주거나, 학교 이름 입력만으로 로그인 회원을 관리자에 연결하지 않는다.

계약상 API 이름이 없는 기능은 새 이름을 이미 구현된 함수처럼 문서에 쓰지 않는다. 학교 설정·회원 연결 API의 최종 명칭과 기존 7개 RPC/DTO 호환 방식은 현행 어댑터 조사 결과를 합쳐 PREP-05에서 확정한다.

## 7. 완료 보고와 다음 인계 방식

각 티켓은 **제안 작성 → 계약 수정 → SQL 확정 → 격리 실행 검증 → 실제 연결 확인 → 공개 승인**을 별도 칸으로 기록한다. 문서·화면이 준비됐다는 이유로 뒤 단계를 완료 처리하지 않는다.

인수 증거에는 적용 환경, commit/SQL 지문, 선행 배치, 시험 역할·학교·기간·정책판, 정상/거부의 실제 이유, 남은 제한, 되돌림 경계를 남긴다. 원문 학생 자료·키·서명 URL은 보고서에 복사하지 않는다.

현재 [16장](16-pilot-db-activation.md)은 PR23 검토 때 지적된 “v1.1이 F5/F6을 해결했다”는 문구를 이미 정정했고, B01/B02는 F5/F6/F8 반영 계약의 재검토 후 시작한다고 적고 있다. 이 정정은 **오해를 줄인 문서 수정**이며 DB 결함 자체의 해결 증거는 아니다. 다음 보고에서는 이 둘을 분리해 기록한다.
