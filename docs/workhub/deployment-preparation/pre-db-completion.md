# DB 적용 전 앱 흐름 마무리

2026-10-21 · PR #77 · 운영 DB·실제 회원·유료 AI·Claude 검토는 계속 보류한다.

## 이번 점검에서 고친 세 가지

| 발견한 문제 | 수정 결과 | 확인한 경계 |
|---|---|---|
| 지연 로딩이 한 번 실패하면 같은 `React.lazy`가 거절된 결과를 계속 반환하여 화면 재시도가 실패함 | 오류 경계별 로딩 시도를 분리하고, 사용자가 다시 열기를 누른 경계만 로더를 재실행 | 정상 화면의 입력·공유 보관소의 원래 요청 번호 유지. 자동 저장·자동 새로고침 없음 |
| 학교 자료의 비서 전달 실패가 원문 조회 오류로 처리되어 본문·원본 파일·재전달 버튼까지 사라짐 | 조회 오류와 전달 오류를 분리하여 확인한 원문을 보면서 재시도 가능 | 학교·계정·권한·자료 판 변경으로 재조회하는 경우에는 이전 원문을 숨김. 늦게 도착한 전달 오류는 새 자료에 표시하지 않음 |
| 여러 날에 걸친 시간 지정 일정이 오늘도 첫날의 시작·종료 시각을 반복 표시함 | 홈에서 시작일·중간일·종료일을 구분하고 전체 날짜·시각을 함께 표시. 주·월 카드의 날짜는 선택한 날짜 사용 | 단일일·종일 일정 의미와 저장 데이터 유지. 상세 화면도 시작일/시각과 종료일/시각을 명확히 구분 |

공통 로딩 복구는 React의 거절된 결과를 새로 시도하는 기능이다. 실제 Chromium에서 동일 URL의 `import()`가 한 번 네트워크 실패한 뒤에는 서버가 정상이어도 두 번째 시도가 네트워크에 도달하지 않는 경우를 확인했다. 따라서 이를 모든 다운로드 오류의 해결로 안내하지 않는다. 반복 오류 안내에는 수동 새로고침 전에 다른 화면의 입력과 결과 미상 요청을 정리하도록 적었다. 현재 탭 메모리에만 있는 자료는 새로고침으로 사라질 수 있다. 이 동작은 [Vite의 배포 후 로딩 오류 설명](https://v6.vite.dev/guide/build#load-error-handling)과도 구분하여 기록한다.

## 전체 구축 흐름 확인

| 영역 | 현재 코드에서 확인한 범위 | 이번 판정 |
|---|---|---|
| 공통 셸·메뉴·홈 | 오류 경계, 재시도, 정상 화면의 입력 유지, 일정 요약·전체 목록·원문 이동 | 이번 복구·표시 결함 수정. DB 없이 확인 가능한 변경 완료 |
| 문서 생성·수합 | 질문형 초안→HWPX 생성/검사→명시 첨부→최종 제출→담당자 ZIP, 실패 파일 재시도 | 기존 구현·회귀 유지. 새 필수 계약 누락은 이번 점검에서 발견하지 않음 |
| 메신저·협업 | 대상 확인, 접수증, 원래 번호 복구, 첨부 실패와 인계 | 기존 구현 유지. 실제 Storage/서버 연결은 별도 |
| 학교 자료·비서 | 최신·과거 판 원문, 정확한 판의 HWPX, 인용/질문 왕복, 자동 호출 방지 | 원문 보존 결함 수정. 학교 키·실제 AI 응답 연결은 보류 |
| 학교·수업·시간표 | 자료 준비·정정·복귀, 편성·운영, 공유·교환·독립 승인·실시 기록 | 기존 구현·격리 SQL 대조 유지. T3/T4 등 미적용 SQL과 실제 관계 연결 필요 |
| 배포 준비 | 7패키지 40개 SQL의 목록·해시·의존 순서·설치/승인 파일 분리 | 원문 변경 없음. 실제 운영 기준선과 대조하지 않음 |

위 표는 코드·시험 범위를 점검한 결과이며 전체 코드에 결함이 없다는 보증이 아니다. 검사 건수와 화면 수를 전체 완성률로 환산하지 않는다. PDF 원문 추출, 범용 복합 HWPX 서식 편집, 자동 기억 수집, 외부 수업 사이트 자동 연동은 별도 범위이며 이번에 완료했다고 표시하지 않는다.

## 검증과 재현

- `test_workhub_calendar_time.mjs`: 단일일·시작일·중간일·종료일·종일·연도/윤일 경계·자정 8건.
- `workhub-calendar-views.mjs`: 홈·주·월·상세에서 여러 날 일정 표시, 기존 검색/원본/편집/시트 가져오기·모바일.
- `workhub-module-loading.mjs`: 실제 React·공유 요청 보관소로 10건. 브라우저의 실제 동적 모듈 다운로드 실패 캐시와 수동 새로고침 후 복구도 구분한다.
- `workhub-knowledge-assistant.mjs`: 기존 17건에 전달 실패/권한 실패/늦은 전달 오류 3건을 추가한 20건.
- 공통 로딩 변경 관련 기존 기본 셸·학교 연결·시간표 연결·학교 AI 화면 4개 파일 51항목을 통과했다.
- 기존 일정 저장 복구·시트 가져오기·홈 배치 회귀도 통과했다.

```powershell

npm run check:workhub
```

DB/Storage/AI 응답은 합성이다. 최종 전체 시험과 정확한 CI 커밋의 결과는 [검증 기록](verification.md)에 기록한다. 새 브라우저 파일을 공통 실행 목록에 등록했다. SQL 원문이 바뀌지 않았으므로 앞선 격리 DB 결과를 이번에 재실행한 것처럼 표시하지 않는다.

## 판단해서 정한 것

1. **자동 새로고침을 하지 않는다.** 다른 화면의 미저장 입력과 결과 미상 요청을 지울 수 있기 때문이다. 관련 위치는 `ModuleBoundary.tsx`·`retryable-lazy.tsx`이다.
2. **비서 전달 실패만 원문을 보존한다.** 권한 재조회 실패와 섞지 않는다. 관련 위치는 `KnowledgeCitationPanel.tsx`이다.
3. **여러 날 일정은 연속된 한 구간으로 표시한다.** 저장 형식이나 반복 규칙을 새로 만들지 않는다. 관련 위치는 `calendar/formatting.ts`·`CalendarPanel.tsx`이다.

## 마지막 단계로 남겨 둔 일

1. 최종 코드 검토 뒤 실제 운영 기준선과 미적용 여부 확인, 승인된 SQL 순차 적용.
2. 동일 앱/서버 판의 배포, HWPX 엔드포인트·Storage·학교 API 키·예산 연결.
3. 승인된 실제 회원·학교 자료·독립 승인자 연결과 모듈별 활성화.
4. 실제 서비스 왕복과 배포 상태 확인. 실사용 피드백은 이 구축·연결 단계와 별도로 기록.

모델 배정, 학교별 키, 월 USD 100은 기존 결정을 유지한다. 결과 미상 확인 담당/주기·보관 정책·전환 시점 등 사용자 결정이 남은 항목은 [전체 현황](../school-timetable-pilot/system-status.md)을 따른다. 이번 작업은 SQL·인증·비용·공개 범위를 변경하지 않는다.
