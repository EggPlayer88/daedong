## 3. 이번 CI 실패 수정

[실패 실행](https://github.com/EggPlayer88/daedong/actions/runs/39617609822/job/119282574595)의 `workhub-pilot-connected`가 학교 자료 조회 실패의 화면 안내를 너무 일찍 판정했다. `readFailures` 배열 변경은 RPC 거절 처리와 React 렌더가 끝났다는 뜻이 아니다. 실패 화면 기록에는 실제 오류 안내가 있었지만, 그보다 앞선 `count()`는 0이었다.

수정은 브라우저 시험에 한정한다. 모든 메뉴에서 실제 `role=alert`가 보일 때까지 조건 대기하고, 학교 자료 실패 응답을 시험에서 명시적으로 보류/해제해 로딩과 오류 표시를 분리한다. 임의 sleep, 자동 재시도, 기대값 완화, 앱·SQL·권한 변경은 없다. 기존 메뉴 이동·가용 일정·쓰기 0 판정은 유지한다.

로컬 연결 셸 18건을 통과했다. 전체 `npm test`, 두 앱 빌드, SQL 목록 검사와 최신 원격 CI의 결과는 최종 PR 본문 및 작업 보고서에 실행 링크와 함께 기록한다. 이전 커밋의 성공이나 로컬 항목을 합쳐 최신 CI 성공으로 표시하지 않는다.

3. HWPX 확인/문서 서버용 `SUPABASE_SERVICE_ROLE_KEY`를 Production 서버 전용으로 설정한다. `VITE_` 접두어를 붙이지 않는다. 별도 검사기 서버는 필요 없다. 외부 설정 변경은 사용자와 함께 진행한다.
4. AI 연결 단계에서만 `WORKHUB_AI_KEY_ENCRYPTION_KEYS`(키 ID→base64 32바이트 키 JSON), `WORKHUB_AI_ACTIVE_KEY_ID`를 준비한다. 마스터 키는 새로 만들기 전에 기존 암호문/설정 유무부터 확인하며 이미 사용 중인 키를 임의 교체하지 않는다. 기존 암호문이 있는데 키를 잃으면 학교 API 키를 복호화할 수 없다. 학교 Anthropic 키는 이후 관리자 화면에서 등록한다.
5. 환경값이 바뀌면 같은 승인 소스 커밋을 다시 배포하고 Production Ready를 재확인한다. 브라우저·Node·Python 서버와 공통 AI 자산이 한 배포에 포함되어야 한다. `lxml`, `cryptography`, 서버 로그의 import 오류·설정 누락 여부를 확인한다.
6. 기존 관리자 계정으로 준비 상태를 먼저 읽는다. 실제 회원 17명 연결을 대신하지 않는다. 파일 처리의 실제 Storage 접근, 원본 해시·크기, 서명 URL, 원번호 복구를 확인한 뒤 필요한 R1S/P3/문서 모듈을 별도 승인한다. 준비를 확인하지 못한 상태에서 활성화 SQL을 먼저 실행하지 않는다.
7. 학교 AI 키·월 $100·Haiku 기본/Sonnet 검토 정책이 맞는지 확인한 후 유료 시험 호출과 활성화를 별도 승인한다. 실제 회원 연결과 최종 Claude 검토는 마지막에 묶는다. 가상 교사는 운영 로그인 계정이 아니며 실제 회원으로 자동 치환하지 않는다.

**기존 평가계획 AI 주의:** 새 서버는 학교 키·정책·원장을 사용한다. 실제 회원 학교 연결을 계속 미루는 동안 해당 회원의 평가계획 AI도 준비 안 됨으로 막힐 수 있다. 기존 로그인·회원·제출 자료가 삭제된다는 뜻은 아니다. 구 전역 API 키로 우회하거나 연결되지 않은 회원에게 임의 권한을 주지 않는다.
