## 3. 기존 #77 CI와 브라우저 시험

작업 시작 커밋 `9a532ed`는 Vercel 미리보기 성공, 단위·SQL·빌드 성공 후 **전체 CI는 브라우저 단계 실패**로 끝났다. 130개 브라우저 파일 중 129개는 통과했고 개인 기억 시험 1개가 실패했다.

실패 지점은 조회 오류 안내가 뜨자마자 이전 목록 개수를 확인하던 부분이다. 로컬에서도 같은 실패를 재현했다. 삭제 확인이 부모 비서의 잠금에 전달되는 과정에서도 같은 즉시 판정 문제를 재현했다. 기대값(이전 목록 0개·추가/전송 버튼 비활성)은 그대로 두고 해당 화면 상태가 실제로 반영될 때까지 조건 대기한다. 쓰기 요청 0도 확인했다. 제품 코드·SQL·권한·공개 범위 변경은 없다. 수정한 개인 기억 브라우저 **18/18을 연속 두 번 통과**했다. 새 head의 전체 CI는 push 뒤 다시 판정하며, 이전 129개 파일 통과와 수정본 18개 항목을 합쳐 새 head 전체 통과라고 표시하지 않는다.

### 2026-10-21 후속 확인

`81bc226`의 [전체 CI](https://github.com/EggPlayer88/daedong/actions/runs/39582956364)는 단위·SQL 통합·빌드가 통과했고, 브라우저 130개 파일 중 시간표 운영 시험 1개가 실패했다. 앞서 수정한 개인 AI 기억 시험은 CI에서도 통과했다.

시간표 실패는 AI 이동 제안을 넘긴 뒤 부모 잠금이 풀리자마자 사유 입력을 확인한 시험이다. 입력은 자식 화면의 다음 효과에서 채워지므로 잠금 해제만 기다려서는 반영 완료를 보장하지 못했다. 실제 ‘확인한 제안을 입력에 채웠습니다’ 안내를 기다린 뒤 기존 사유·종류·자동 쓰기 0을 그대로 검사하도록 수정했다. 제품 로직·SQL 변경은 없다. 원본은 로컬에서 26/26이었고 수정본은 연속 **26/26 + 26/26**을 통과했다. 환경에 따라 나타나는 순서 경쟁이므로 임의 대기 시간이나 기대값 완화는 추가하지 않았다.

동시에 [사용 안내·점검](help-readiness.md)을 보완했다. 후속 전체 단위시험은 **5,097건**, 도움말 브라우저 **26건**, 타입·두 앱 빌드·SQL 40개 해시 검사를 통과했다. 새 head의 전체 CI 결과는 push 뒤 해당 실행으로 확인하며 앞선 결과를 새 head 전체 통과로 합산하지 않는다.
