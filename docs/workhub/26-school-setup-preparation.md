# 학교 초기 설정 준비 화면

작성: 2026-10-14 · 실제 DB 연결을 위한 입력 준비 · 운영 DB 미변경

## 교사가 보는 변화

최고관리자 메뉴에 **학교 설정 준비**가 생긴다. 주소는 `/workhub/setup`이다. 기존 학교 연결이 실패한 상태에서도 기존 로그인·승인·최고관리자 모듈 공개 판정을 통과하면 열 수 있다.

학교명·학교 구분 코드·학교급·학년 수, 학년도와 학기, 부서 이름, 학급 목록을 입력하고 검사한다. 이 화면은 학교를 생성하거나 회원을 배정하지 않는다. 입력은 현재 탭의 메모리에만 있으며 운영 미반영임을 표시한다.

## 사용 순서

1. 학교 기본 정보와 실제 학년도 기간을 입력한다. 학기는 하나 이상 추가한다. 부서와 학급은 필요한 만큼 추가한다.
2. 잠시 중단하려면 **작성 초안 내려받기**로 JSON 파일을 보관한다. 빈칸이 있어도 가능하다.
3. 다시 이어서 작성하려면 **초안 파일 불러오기**를 누른다. 올바른 파일이어도 기존 내용을 바꾸기 전에 확인한다.
4. **입력 내용 검사**를 누른다. 오류 항목을 누르면 해당 페이지의 입력칸으로 이동한다.
5. 검사가 통과하면 **검토용 계획 내려받기**로 SQL 작성자에게 전달할 정리 파일을 만든다. 계획 파일은 다시 편집 화면에 불러오는 파일이 아니다.
6. 다른 메뉴로 이동하려면 필요한 초안을 내려받고 **현재 초안 비우기**를 확인한다. 내려받기만으로 현재 입력을 버리지 않는다.

학교 구분 코드는 서비스 내부 식별 후보이며 NEIS 코드가 아니다. 학교 코드 중복·기존 학교와의 일치 여부는 서버 연결 때 별도로 검사한다. 반 번호는 선택이고 학급 이름은 필수다. 일반·특수·복식·기타 학급을 구분할 수 있다.

## 입력·파일 계약

- `apps/workhub/src/setup/contract.ts`가 화면·검사·파일의 공통 기준이다.
- 작성 초안은 `kind=school-setup-draft`, 검토 계획은 `kind=school-setup-plan`이다. 둘 다 `schemaVersion=1`, `deploymentState=not_applied`를 담는다.
- 초안은 입력 문자열과 행 식별자를 보존한다. 계획은 검사 후 이름의 가장자리 공백을 정리하고 숫자를 변환한다.
- 화면의 마지막 날은 **포함**이다. 계획의 `endsBefore`는 다음 날로 변환하며 **포함하지 않는다**. 윤년·월말·연말·하루 기간을 검사한다.
- 학기는 학년도 안에 있어야 하고 서로 겹칠 수 없다. 학교 학년 수를 벗어난 학급, 이름/학기 번호 중복은 계획 생성을 막는다.
- 초안의 알 수 없는 필드, 권한·계정 추가 필드, 중복 행 ID, 잘못된 배열/버전/종류를 거부한다. 가져오기 실패는 기존 입력에 영향을 주지 않는다.
- 초안은 UTF-8 1MB 이하, 학기 4개·부서 100개·학급 2,000개 이하로 제한한다. 부서·학급·오류 목록은 20개씩 표시한다. 파일·목록 한도는 이 준비 화면의 처리 한도다.
- 기존 DB 설계에서 확인한 이름 길이·학교급·학년/반/학기 값 범위만 검사한다. 새 운영 정책을 확정하지 않는다.
- 검토 계획에 남는 서버 확인 항목: 학교 코드 중복, 신규 개설/기존 학교 연결, 부서 종류·유효 기간, 회원·학교 소속·담당 연결, 서버 권한·기간·관계, 확정 SQL 검토와 사용자 적용.

두 파일은 SQL이나 운영 데이터 백업이 아니다. 가져온 파일 내용으로 관리자 권한을 주거나 실제 학교에 연결하지 않는다. 서버 쓰기·localStorage·외부 AI 호출이 없다.

## 검증과 남은 한계

`npm test`에 계약 25개, 실제 화면 SSR 2개와 모듈 공개/현재 메뉴 검사를 포함한다. 브라우저 시험 `tests/browser/workhub-school-setup.mjs`는 실제 설정 컴포넌트와 BrowserRouter를 사용한다. 최종 실행 결과는 [누적 진행 현황](PROGRESS.md)과 PR에 기록한다.

운영 DB 객체나 실제 로그인 계정을 확인한 시험은 아니다. 확정 SQL과 서버 명령이 준비되면 이 초안을 서버에서 재검증하고 승인한 학교 생성/수정으로 연결해야 한다. 클라이언트 검사 통과만으로 학교 개설·권한 부여를 허용하지 않는다.

## 판단해서 정한 것

- **독립된 준비 경로:** 학교 연결 오류가 설정 준비까지 막지 않도록 했다. 기존 App의 로그인·공개 판정은 유지한다. 되돌리려면 MODULES/SCREENS의 `workhub-setup`과 SchoolSetupPage 연결을 제거한다.
- **명시적 파일 보관:** 기존 초안을 잘못된 파일로 덮어쓰지 않고 다운로드를 실제 서버 저장처럼 표시하지 않기 위해 작성 초안/검토 계획을 구분했다. 정책 변경 시 계약·화면·브라우저 회귀를 함께 바꾼다.
- **확정 전까지 권한·회원 제외:** 기존 계정 보존과 학교 승인 정책은 DB 전환 계약에서 결정한다. 이 화면에 임시 계정/자동 승인을 추가하지 않는다.
- **기간 의미 명시:** DB 목표의 종료 제외 방식과 교사의 마지막 날 입력을 구분해 하루씩 틀어지는 것을 막았다. 변경 시 모든 기간 회귀와 확정 SQL 입력 계약을 함께 검토한다.
