## 새 UI에서 확인한 것

1. 홈의 긴급 업무·오늘 수업·일정이 표시되고 기존 원본 행동으로 이동한다.
2. 메시지를 작성하면서 AI 옆자리를 열어도 양쪽 입력이 보존된다. 여는 행동만으로 전송하지 않는다.
3. 시간표 최초 진입은 확정표를 보여 주고 선택 수업 상세를 옆에 연결한다.
4. 결과 미상 AI 요청은 패널을 닫았다 열어도 원래 요청 번호로만 복구한다.
5. 모바일 AI는 modal로 표시되고 Escape로 닫으면 원래 버튼으로 초점이 돌아간다.
6. AI가 열린 채 데스크톱↔모바일로 바뀌어도 입력이 유지된다. 숨겨진 버튼 대신 보이는 진입점으로 초점을 돌린다.
7. 320px·390px·큰 글씨·어두운 화면에서 핵심 메뉴와 긴급 업무가 잘리지 않는다.
8. 사용 안내의 AI 전체 화면과 옆자리 사이에서 같은 답변을 보존한다.
9. 학교 변경 후 숨겨진 AI 화면에 이전 학교 답변을 복원하지 않는다.

## 회귀 처리

전체 브라우저 첫 실행은 135개 중 125개 통과였다. 메뉴 제목과 위치가 바뀐 10개 실패 파일은 새 메뉴 동선으로 수정한 뒤 해당 파일 전체를 다시 통과시켰다. 메시지의 상단 진입점, ‘편성 관리’ 진입, 접힌 운영 진단을 명시적으로 선택한다. 서버 호출·저장 내용·원래 요청 번호·권한 거절·파일 바이트의 기대값은 낮추지 않았다. 로그인 직후 아직 그려지지 않은 메뉴를 ‘없는 메뉴’로 판단하던 공통 보조 함수는 실제 기본 메뉴가 나타나 클릭될 때까지 기다린다.

새 기본 시간표 화면이 읽는 대체·보강 준비 상태를 합성 학교 준비 fixture에도 추가했다. 이를 쓰기 호출에서 제외하는 방식으로 검사를 우회하지 않았다.

시간표 운영 컴포넌트를 단독으로 사용하는 경로는 기존 조회 기간 버튼이 펼쳐져 있도록 유지했다. 업무실의 새 시간표 화면 안에서만 ‘조회 기간 조정’으로 접는다.

Windows 중간 회차에서 기존 CP-SAT·로컬 작업자 시험에 시간 제한/복구 판정 실패가 있었고, CP-SAT 단독 재실행에서는 Python 프로세스의 비정상 종료도 발생했다. 계산기 구현·시험 기대값·계산 시간 제한은 변경하지 않았다. 브라우저와 빌드가 끝난 뒤 아래 환경에서 전체 시험을 실행해 **5,203/5,203, 종료 코드 0**을 확인했다. 스레드 설정은 이 검사 프로세스에만 적용하며 앱·CI·운영 설정에 추가하지 않았다. 환경 설정이 이전 비정상 종료의 원인을 증명하는 것은 아니다.

```powershell
$env:OMP_NUM_THREADS='1'
$env:OPENBLAS_NUM_THREADS='1'
$env:MKL_NUM_THREADS='1'
npm test
```

## 적용과 남은 확인

추가 SQL·DB 마이그레이션·환경변수·기능 활성화는 없다. 사용자가 PR 미리보기를 확인하고 병합하면 Vercel 앱 배포로 적용된다. 운영 배포 뒤 현재 학교·권한에 따른 실제 화면 연결은 별도로 확인한다. 이번 시험으로 운영 DB·Storage·실제 AI 왕복 성공을 새로 주장하지 않는다.

기존 회원 연결·공개 범위·학교별 모델/예산·자동 정리·외부 교사 사이트는 변경하지 않았다.
