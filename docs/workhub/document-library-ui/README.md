# 문서함·학교 자료·질문형 양식 화면 정리

기준 main: `5f8844b8aa12df03c50c752c97d291f068dabcfe` (#90 병합). 작업 브랜치: `feat/workhub-document-library-ui`.

## 교사가 보는 변화

| 화면 | 기존 불편 | 이번 변경 |
|---|---|---|
| 문서함 | 본문 아래에 작업 버튼이 있어 긴 문서에서는 찾기 어려움 | 수정·내려받기·확인 버튼을 본문 앞에 모으고 목록·선택 문서·저장 이력을 구분 |
| 문서 작성 | 제목·메타정보·본문이 길게 이어짐 | 제목 다음에 종류·기준일·공개 범위를 묶고 본문과 저장 영역을 분리 |
| 학교 자료 | 본문·HWPX·판·게시 상태를 구분하기 어려움 | 카드에 게시 상태·적용 기간·근거 위치를 모으고 저장된 본문과 HWPX 원본을 구분 |
| 학교 자료 입력 | 긴 세로 입력과 제각각인 조작 요소 | 제목·종류·근거·적용 기간을 정돈하고 큰 본문 입력 및 일관된 저장 버튼 제공 |
| HWPX 가져오기 | 업로드 이후 어느 단계인지 설명에서 찾아야 함 | 파일 선택 → 본문·누락 확인 → 초안 저장 안내 제공 |
| 질문형 양식 | 연결·답변·생성·게시가 길게 이어짐 | 지금 할 일과 단계 바로가기, 파일 확인·수합 연결 영역 분리 |
| 빈칸 제안 | 후보 0개에도 선택·반영 확인이 노출됨 | 후보가 없으면 기존 질문·원본 위치 확인을 안내하고 불필요한 확인 조작 숨김 |

단계 바로가기는 입력을 다시 만들거나 저장하지 않고, 현재 영역으로 키보드 초점과 스크롤만 옮긴다. 생성하지 않은 파일·수합 연결 단계는 열 수 없다. 원래 입력과 같은 요청 번호 복구는 유지한다.

## 유지한 범위

- DB·SQL·RPC 계약·권한·인증·메뉴 공개 범위 변경 없음.
- AI 모델·예산·토큰·호출 방식 변경 없음. 단계 이동과 화면 열기로 AI를 자동 실행하지 않음.
- 파일 검사·HWPX 생성 엔진·원본 보관·다운로드 방식 변경 없음.
- 초안 저장, 파일 생성, 다운로드 확인, 게시, 수합 첨부, 최종 제출을 각각 기존 명시 조작으로 유지.
- 파일 확인 전 게시·첨부 차단, 변경된 답변의 옛 생성물 숨김, 미확정 요청의 원래 번호 복구 유지.
- 글자·간격·스킨 설정 유지. 기본 서체와 아이콘 자산 추가·변경 없음.

## 병합 전 확인

1. 문서함에서 선택한 문서의 상태·정확한 판을 확인하고 수정 또는 내려받기로 이동.
2. 학교 자료에서 본문·연결된 HWPX·이전 판의 차이를 확인.
3. 질문형 양식에서 미저장 입력을 둔 채 단계 바로가기로 이동해 내용 유지 확인.
4. 파일 다운로드·확인 전에는 수합 게시 또는 첨부를 실행할 수 없는지 확인.
5. 휴대폰 너비·큰 글씨에서 입력칸과 주요 버튼 확인.

추가 SQL 실행은 없다. PR CI와 미리보기를 확인한 뒤 사용자가 merge commit으로 병합하고 Vercel Production을 확인한다.
