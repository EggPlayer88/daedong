# 문서작성 AI·시간표를 제외한 시범 공개 완료 계획

작성 기준: 2026-10-13 · 11차 개발 착수 · 사용자 요청을 반영한 실행·수용 목록

## 1. 이번 공개 목표

목표는 **기존 청사진의 핵심 업무를 실제 교사 계정과 학교 자료로 끝까지 처리한 뒤 시범 공개하는 것**이다. 화면 시연만을 시범 운영으로 부르지 않는다. 일정과 개인 업무만으로 공개 범위를 줄이지 않으며, 문서작성 AI와 시간표를 제외한 아래 모든 기능의 수용 조건을 확인한다.

기준은 바탕화면 `GPT작업/업무혁신시스템 기획서.md`의 M00~M15·공통 계약·수용시험이다. 이번 문서는 새 제품 아이디어나 새 D번호 결정을 추가하지 않고, 사용자가 정한 제외 범위를 적용해 남은 구현을 실행 순서로 나눈다. 원 기획에서 이미 후속으로 분류한 기능까지 이번 공개에 다시 포함하지 않는다.

| 범위 | 이번 공개에서의 처리 |
|---|---|
| 학교·계정, 업무분장, 일정·시트 전환, 홈·할 일, 수합, 학생·수업·평가, 학교 자료, 알림, 인계, 관리자·운영 | 포함. 합성 구현에 머물지 않고 실제 저장·권한·복구·교사 과제까지 확인 |
| 학교 규정 상담·담당자 안내·개인 비서 | 포함. Claude를 사용하며 출처·자료 범위·실행 확인·기억 관리까지 구현 |
| 문서작성 AI | 이번 공개 대상에서 제외. 문서 초안 생성·기존 파일을 이용한 자동 작성·문서팩 확장·생기부 AI 문장 생성이 해당 |
| 일반 파일 업무 | 포함. 학교 자료 등록·양식/업무 파일함·파일 제출·다운로드는 AI 문서 작성과 별개 |
| 학생 기록·평가·생기부 기초자료 | 포함. 교사의 직접 기록·상담·루브릭/평가 확정·근거 검토·정정·수동 작성/출력은 유지. AI 자동 문장 생성은 위 제외 범위 |
| 시간표 | 편성·조회/가져오기 신축 통합·교체·대강·보강·실시·시간표 AI 지원을 이번 공개 대상에서 제외 |
| 학생 기능의 수업 집단·담당·수강 관계 | 포함. 시간표를 개발하지 않아도 실제 명부와 기록 접근에 필요한 독립 기반 |
| 기존 운영 기능 | 제외는 신축 시범 공개의 완료 조건에서 빼는 뜻이다. 기존 평가계획서·시간표 코드와 보호 자산을 삭제하거나 운영 기능을 중단하지 않음 |

생기부 AI 생성 제외는 이번 요청의 ‘문서작성 AI’를 적용한 구현 경계다. 이를 재개할 때는 M12의 생성·문장별 근거·최종 검사 조건을 다시 적용한다. 일반 상담 창에서 문서 작성이나 시간표 작업을 가능하다고 안내해 우회 제공하지 않는다.

원 기획의 후속 범위인 반복 일정의 이번/이후/전체 편집, 메일·캘린더 구독, 완전 자동 수업 앱 연결, 고급 인계 복사 마법사, 예산·학부모/학생 포털·결재 대체는 이번 완료 목록에 새로 넣지 않는다. 웹 푸시는 지원 기기에서 별도 검증하며 앱 알림함을 기본 전달 경로로 둔다.

## 2. 완료 상태를 기록하는 방법

각 기능을 다음 다섯 칸으로 관리한다. 앞 칸의 완료가 뒤 칸의 완료를 뜻하지 않는다.

| 단계 | 인정할 증거 | 인정하지 않는 대체물 |
|---|---|---|
| 설계 | 데이터 범위·상태·권한·예외·수용 조건을 설명한 계약 | 메뉴 이름이나 구현 예정 문구 |
| 합성 구현 | 실제 UI/도메인 코드에 합성 자료를 넣고 정상·실패 흐름 실행 | 스크린샷만 있는 시안 |
| 서버 코드 | 실제 어댑터·명령·조회·파일 경로와 서버 강제 규칙 구현, 격리 시험 | 브라우저 store의 권한 분기만 존재 |
| 실제 DB 연결 | 승인된 환경에 확정 SQL 적용, 기존 계정과 두 독립 세션으로 저장·조회·권한·경합 확인 | 제안 SQL, PGlite 또는 일회용 PostgreSQL 회귀만 통과 |
| 현장 검증 | 역할별 교사가 도움 없이 대표 과제를 수행하고 결과·오류 복구·자료 대조 확인 | 테스트 건수·빌드 성공을 완성률로 환산 |

현재 판단의 기준은 [누적 진행](PROGRESS.md), `apps/workhub/src/modules.ts`, 실제 연결 화면인 `ConnectedWorkspace.tsx`, 각 모듈의 계약·저장소·어댑터다. `productionEnabled: false`가 유지되고, 실제 연결 메뉴는 오늘·일정·내 업무이며 수합·학생은 합성 미리보기다. 새 화면이 미리보기에 보인다고 운영 공개됐다고 기록하지 않는다.

## 3. 역할별 실제 과제와 수용 조건

아래 과제는 모두 **시작 → 입력 → 저장 → 다른 계정 확인 → 실패 복구**를 하나의 시험으로 묶는다. ‘다른 계정 확인’에는 허용 확인과 비공개 자료의 거부 확인이 함께 들어간다. 본문이 비공개면 검색·건수·알림·파일·AI 조회·내보내기에서도 비공개여야 한다.

### P01 첫 로그인·학교·공식 담당 — M00·M01

1. 기존 교사가 기존 로그인으로 들어와 승인 상태와 소속 학교를 확인한다. 운영자는 학교를 개설하고 학교 관리자는 기간·공식 담당을 설정한다.
2. 교사는 프로필 변경/담당 확인 요청을 입력한다. 관리자는 승인된 교과·부서·담임·업무·기간을 확인해 저장한다. 본인 신고로 권한이 올라가지 않는다.
3. 새로고침·다른 기기에서도 같은 계정 ID와 승인 상태·담당이 유지된다. 같은 이름의 다른 학교 자료가 섞이지 않는다.
4. 다른 학교 교사는 업무 URL·조회 요청을 직접 사용해도 접근할 수 없다. 학교 관리자는 개인 기록·대화를 볼 수 없다.
5. 승인 대기·중지·소속 없음·종료·겸임·토큰 만료·조회 오류를 구분한다. 실패를 계정 재가입/삭제나 임의 학교 배정으로 해결하지 않는다.

증거: 계정 보존 전후 대조, 두 학교·두 독립 세션, 기간 경계·회수·직접 요청 결과, 실제 OAuth 복귀/로그아웃 기록. 원 기획 V01~V06.

### P02 일정 등록·관련 홈·시트 기준 전환 — M02

1. 활성 교사는 공유 일정을 등록하고 지정 담당은 공식 학사일정을 확정한다. 시작 화면에서 학교·기준일·공식/공유/개인 구분을 확인한다.
2. 제목·시간·열람 범위·관련 대상·담당을 입력한다. 시트는 원본·열 대응·날짜/시간·안정 ID와 오류를 먼저 확인한다. 미리보기를 저장 완료로 표시하지 않는다.
3. 서버 접수 후 월/주/목록·원본·해당 교사 홈에 같은 판이 반영된다. 관련 대상과 열람권한은 별도로 동작한다.
4. 다른 교사는 허용된 공유 일정과 자신에게 관련된 카드만 확인한다. 개인 일정·지정 대상 자료는 허용 범위 밖으로 노출되지 않는다.
5. 저장 응답 유실·동시 수정·중복 행·정렬·행 삽입·ID 소실·날짜 오류를 복구한다. 이번 파일에서 빠진 행을 삭제하지 않는다. 원본과 사이트가 모두 바뀌면 사용자가 차이를 확인한다.
6. 병행 기간 자료를 대조한 뒤 자료 종류별 쓰기 기준을 전환한다. 사이트 기준이 된 자료를 옛 시트가 덮어쓰지 못하고, 전환을 되돌릴 때 새 사이트 입력까지 대조한다.

증거: 실제 시트 표본의 매핑표·오류표·변경 전후/서버 접수 대조·기준 전환 기록·재시도 결과. V07~V10·V24. 반복 일정 고도화는 원 기획의 후속 범위다.

### P03 오늘·개인 업무·업무 페이지·협조 — M01·M03

1. 교사는 홈에서 지금 할 일·관련 일정·받은 수합과 다음 행동을 확인하고 정확한 원본으로 이동한다. 업무 페이지는 승인된 업무 ID에 연결된 자료를 모은다.
2. 개인 할 일·메모·기한을 입력한다. 학교 업무와 순수 개인 공간을 구별한다. 협조 요청은 상대방의 수락·거절·대체자 제안을 받는다.
3. 저장 후 다른 기기에서도 같은 상태를 본다. 원본에서 생성된 할 일은 중복되지 않으며 원본 변경이 개인 메모를 덮지 않는다. 제출 의무는 수동 체크로 접수 완료가 되지 않는다.
4. 배정자는 자신이 보낸 요청의 상태만 확인한다. 다른 교사·관리자는 개인 할 일 본문을 볼 수 없다. 순수 개인 공간은 학교/학생 원자료를 참조하지 않는다.
5. 한 모듈 조회 실패 중에도 다른 홈 정보와 수동 작업은 계속 가능하다. 이전 자료의 기준 시각·미확인 상태를 표시하고 충돌/재시도에서 입력을 보존한다.

증거: 대표 교사 하루 과제, 원본 변경/중복 사건/권한 종료, 검색→마지막 페이지 원본, 두 기기 재조회. V05·V11·V12·V35.

### P04 다양한 응답·공동 수합·파일 — M04·M08 파일 공통 부분

1. 요청자는 목적·대상 단위·책임자·공동 작성자·검토 유무·마감·공유 범위를 정한다. 교과×학년·교사·부서·학급·수업 집단·직접 단위를 표현한다.
2. 응답 항목은 예/아니오·단일/복수 선택·숫자·짧은 글·날짜·파일을 지원한다. 숫자 0과 미입력, 선택 안 함과 ‘아니오’를 구별한다. 파일이 필요 없는 요청에 파일을 강제하지 않는다.
3. 공동 초안 저장 → 책임자/명시 대리의 제출 → 접수증 → 검토/보완 → 완료본 확인이 서버에서 이어진다. 공동 작성자 수와 무관하게 한 단위는 한 의무다.
4. 요청자·검토자는 미제출 초안을 볼 수 없고 해당 버전의 제출본만 본다. 검토 없음은 정상 접수로 완료되며 승인 버튼을 요구하지 않는다. 검토 있음의 새 판 대기 중에는 기존 완료본과 대기판을 구별한다.
5. 파일 업로드 성공 후 DB 확정 실패를 접수 성공으로 표시하지 않는다. 재전송·동시 제출·검토 충돌·부분 ZIP 실패·마감 후 정정·철회·면제·책임 인계에서 접수증과 의무 수가 유지된다.
6. 목록·통계·내려받기는 허용된 완료본을 사용한다. 파일명을 통해 단위·버전·상태를 확인하고 내려받은 실물을 연다. 구성원 제거 후 이전 링크도 접근할 수 없다.

증거: 요청자·공동 작성자·책임자·검토자 별도 세션, 모든 응답 유형, 파일 검사/원본 권한, 한 파일 실패 후 재개, 완료본 집계 대조. V13~V18·V24. 실제 철회·자기검토·마감 정책은 승인된 기본값을 적용한다.

### P05 학생 명부·관찰·상담·평가 — M11·M12의 비생성 부분

1. 담당 교사는 학교·학기·수업 집단·명부를 확인한다. 명부 담당은 동명이인·번호 재사용·반 이동·전입/전출 후보를 검토해 불변 학생 ID와 기간 관계를 연결한다.
2. 교사는 직접 확인한 관찰 사실과 별도 상담을 입력한다. 평가에서는 루브릭 판·배점·근거를 선택하고 0점·결시·미제출·미확인·연결 오류를 구별한다. Claude의 근거 기반 평가안 제시는 평가 지원으로 포함하며 점수는 교사가 확정하고 합계·범위는 코드가 검사한다.
3. 저장 후 작성자만 조회·정정·철회한다. 개정은 기존 본문을 덮지 않으며 루브릭 변경으로 과거 점수가 자동 변환되지 않는다. 상담을 일반 생기부 근거로 자동 포함하지 않는다.
4. 다른 담당·담임·관리자는 타인의 개인 기록 본문뿐 아니라 건수·요약·검색·AI 근거도 볼 수 없다. 학급 명부 조회 권한이 타 교사의 기록 권한을 뜻하지 않는다.
5. 명부 누락을 삭제로 추정하지 않는다. 학생 오연결·학적/담당 종료·과거 학년도 정정·동시 수정·조회 실패를 복구한다. 근거가 바뀐 기록/평가/출력은 재검토가 필요하다고 표시한다.
6. 본인이 확인한 근거를 모아 교사가 직접 작성·검토·출력한다. 출력 직전에 현재 근거와 권한을 다시 검사한다. 공식 입력 여부와 파일 출력 여부를 구분한다.

증거: 명부 실제 표본의 매핑·기간 경계, 작성자/타인 세션, 상담 제외, 평가 계산·정정, 다운로드 실물/근거 대조. V04·V40~V44 중 AI 생성 제외 부분. 시간표 기능 없이 이 과제를 수행해야 한다.

### P06 디지털윤리 수업 자료 연결 — M13

1. 교사는 학교·학기·수업·활동 회차·활동일·질문/루브릭 판을 먼저 선택한다.
2. 실제 두 CSV 형식 `dilemmas`·`grading`을 읽고 원문을 확인한다. 자리번호·별명은 후보이며 학생을 자동 확정하지 않는다. BOM·따옴표·쉼표·줄바꿈·빈 답변·수식 보호 작은따옴표를 보존한다.
3. 교사가 당시 수강 관계와 학생 매핑을 확인한 뒤 관찰/평가 근거로 채택·보류·제외한다. ‘심화 (평가 제외)’는 점수에 포함하지 않는다.
4. 다른 교사/학교가 원본 파일·미채택 답변·연결 기록을 조회할 수 없다. 명시적으로 채택한 자료만 본인의 후속 근거가 된다.
5. 같은 파일 재전송과 다른 활동에서 같은 파일 사용을 구별한다. 수정 파일의 행 순서/별명으로 이전 답변을 덮지 않는다. 원문 정정·학생 재연결·철회·삭제가 파생 근거에 반영된다.
6. 일부 학생 삭제 시 원본 CSV·해석본·색인·파일·백업 복구 후 상태까지 처리 범위를 기록한다. 외부 수업 사이트나 교사 PC의 파일까지 삭제했다고 표시하지 않는다.

증거: 실제 익명화 표본, 교사 확인 매핑표, 활동 회차별 중복·정정·삭제 후 재수입 결과. V45~V48. 현 외부 앱에 없는 영구 참가자 ID/개정 번호를 존재한다고 가정하지 않는다. 자동 연결은 후속이다.

### P07 학교 자료·규정·일반 파일함 — M06·M08의 파일 부분

1. 교사는 자료를 제안하고 지정 자료 책임자는 학교/공통 범위·대상·학년도·시행 기간·원본·확인자를 지정한다.
2. HWPX·텍스트 PDF·직접 입력의 추출 결과를 원본 쪽/조/항/표와 대조한다. 스캔·암호화·일부 잘림은 확인한 텍스트가 없으면 답변 근거로 게시하지 않는다.
3. 등록→추출→검토→게시와 검색 색인 상태를 구분한다. 양식/업무 파일은 권한에 따라 조회·다운로드하며 실제 파일 본체가 있어야 한다.
4. 다른 교사는 허용된 현행 자료를 검색한다. 미래 시행판은 기준일 전 질문에서 현행판을 밀어내지 않고 타학교 자료를 답변 근거로 가져오지 않는다.
5. 철회·만료·재게시·색인 지연·충돌 자료·다운로드 실패를 처리한다. 색인이 남아 있어도 원본 권한/판 검사가 철회 자료를 차단한다.

증거: 실제 학교 자료 표본의 출처/시행일/추출 대조, 권한별 검색·파일, 원본 철회 직후 응답. V21~V23·V24·V33. 파일 제출 허용과 AI 추출 지원은 별개로 표시한다.

### P08 Claude 학교 상담·개인 비서 — M07

1. 교사는 같은 창에서 현재 학교·자료 범위·현재 작업을 확인하고 규정·업무 담당·자기 마감을 질문한다.
2. 최소한의 허용 자료를 조회해 요점·적용 조건·기준일·출처·다음 행동을 제공한다. 자료가 없거나 충돌하면 학교 규칙을 추측하지 않고 확인 대상으로 남긴다.
3. 할 일 추가·일정 후보·업무 정리 등의 실행안을 보여 주고 필요한 확인을 받은 뒤 서버가 최신 권한·기간·원본 판을 검사해 한 번 적용한다. 대화 속 지시만으로 권한이 생기지 않는다.
4. 다른 학교·다른 작성자의 기록/대화/기억은 검색·도구·요약으로 전달되지 않는다. 기억은 사용자의 명시적 확인 후 저장하고 확인·수정·삭제·만료를 제공한다.
5. 모델 실패·도구 지연·중복 요청·확인 후 원본 변경·소속 종료에서 결과를 조작하지 않는다. 실행 여부를 확인하고 같은 요청의 재시도와 새 요청을 구분한다. 수동 업무는 계속 가능하다.

증거: 허용/금지 근거 질문 세트, 상충·만료·무근거 답변, 실제 도구 결과와 접수 대조, 프롬프트 인젝션/학교 전환/취소/기억 삭제. V22·V23·V31~V36 중 문서 생성·시간표 제외 부분. 모델·호출 상한·키·비용 설정은 구체안 검토 후 연결한다.

### P09 전달사항·알림·문의 — M05

1. 승인된 업무/부서 관계 안에서 전달사항을 게시하고 교사는 앱 알림함과 수신 설정을 연다.
2. 읽음·명시적 확인 요청·마감 안내를 구별하고 조용한 시간·묶음·필요한 알림 설정을 입력한다. 문의는 가림 처리된 재현 정보부터 받는다.
3. 원본 사건당 수신자별 알림을 한 번 저장한다. 조회/확인 상태는 업무 접수·승인과 별개다. 문의는 접수→확인→계획/안내→해결 상태를 보여 준다.
4. 관련 교사에게만 원본 접근이 가능한 알림을 보낸다. 권한 없는 사람에게 제목·이름·본문을 보내지 않는다. 확인 명단은 요청자가 허용 범위에서 본다.
5. outbox 재시도·조용한 시간·기기 미지원·권한 회수·원본 삭제를 복구한다. 전송 실패가 원본 업무를 실패/중복 접수로 바꾸지 않는다.

증거: 동일 사건 재전송·권한 밖 수신자·삭제 직후 알림 열기·부분 전송 실패 재개·문의 처리. V19·V20·V24·V35. 푸시 미지원 시 앱 알림함을 사용할 수 있어야 한다.

### P10 학기 전환·업무 인계 — M01·M14

1. 관리자는 새 학년도/학기·기간을 만들고 전임/후임은 적용일·진행 업무·제외 자료를 확인한다. 과거 자료를 계속 구분해 조회한다.
2. 담당·할 일·수합 책임·검토 권한의 이전 대상을 입력하고 후임이 수락한다. 개인 관찰·상담·대화는 인계 목록에 넣지 않는다.
3. 최신 대상 지문·버전·양측 소속·효력일을 확인해 한 트랜잭션으로 적용한다. 같은 의무 ID·접수증·검토 이력을 유지한다.
4. 전임과 후임의 실제 권한이 적용일에 맞게 바뀐다. 인계 미수락이 종료된 소속의 접근권한을 연장하지 않으며 담당 공백은 관리자에게 표시한다.
5. 중복 수락·실행 중 실패·대상 변경·후임 소속 종료는 전체 미적용 또는 재확인으로 처리한다. 과거 개인 기록의 정정은 작성자와 학교의 확인된 절차를 따른다.

증거: 양측 세션·효력일 전후·의무 수/ID 대조·중간 실패 롤백·needs_owner 처리·과거 정정. V06·V27·V41. 완료 상태나 개인 기록을 새 학년으로 자동 복제하지 않는다.

### P11 운영·지원·보존·복구·공개 — M15와 공통 계약

1. 학교 관리자는 가입/담당/게시/수합 운영/전환 대조를, 서비스 운영자는 학교별 상태·실패·용량·호출 합계를 확인한다.
2. 학교별 공개표와 자료별 보존·파기·접근 종료 정책을 적용하고 실패 작업의 원인·다음 조치를 확인한다. 운영 로그에는 본문·학생 답변·개인 대화·키를 넣지 않는다.
3. 작업 재시도는 동일 요청 키로 복구한다. DB와 파일 본체를 함께 백업·격리 복원하고 삭제/권한 회수 원장을 다시 적용한다.
4. 학교 관리자·지원 담당은 작성자 전용 기록·상담·대화·미제출 초안·건수를 보지 못한다. 필요한 지원은 요청자가 이미 열람 가능한 공유 업무자료만 승인된 기간/행동 안에서 수행한다.
5. 장애·로그인 실패·파일 누락·용량/호출 한도·복원 후 삭제자료 재등장·구형 API/Storage 우회 접근을 확인한다. 배포를 되돌려도 DB 쓰기와 신축 자료가 자동 복구되지 않음을 반영한 복구 절차를 실행한다.

증거: 복구 실물·권한 회수 재적용·구형 경로 격리·관측/문의·롤백 연습·모바일/키보드/화면읽기 실제 과제. 원 기획 G01·G02·G04~G07의 이번 범위와 V01~V04·V24·V34~V36. G03은 시간표 재개 시 적용하며 G04의 AI 문장 생성 시험은 문서작성 AI 재개 시 적용한다.

### 공통 화면 수용 조건

P01~P11의 화면은 작은 화면·확대·키보드·화면읽기에서 같은 업무를 수행할 수 있어야 한다. 입력 오류는 해당 항목과 연결하고, 저장 중/미저장/실패를 구별하며, 원본 이동·필터·쪽 이동·학교 전환에서 초점과 작성 중 입력을 보호한다. 화면 공유 가림은 이름·본문·개인 일정·AI 창·알림을 함께 가리고, 학생 원문·상담·대화를 브라우저 영구 저장이나 잠금화면 미리보기에 기본 포함하지 않는다.

목록의 20개 DOM 분할과 서버 조회 성능은 별개다. 실제 서버에서는 학교·기간·상태·담당 범위의 커서 조회·전체 집계 계약을 구현하고, 교사별 검색/추천과 내보내기도 최신 권한을 재검사한다. 연결 장애와 빈 목록을 구별하며 긴 작업은 상태·취소 가능 여부·재시도·실패 항목을 보여 준다.

## 5. 이번 11차에서 바로 진행하는 시트 입력 보완

이번 구현은 R1-2의 **복사한 표를 개별 일정 입력으로 안전하게 옮기는 경로**다. 현재의 일정 편집기와 저장 어댑터를 재사용하며 새 DB·인증 설정을 요구하지 않는 부분부터 진행한다.

1. 시트에서 복사한 표/CSV 텍스트 입력 → 열 매핑 → 날짜/시간·누락·중복 검사 → 행별 확인.
2. 검토 가능한 최대 200행을 명시하고 초과분을 조용히 잘라 저장하지 않는다.
3. 각 행을 기존 일정 편집기로 열어 교사가 확인·등록한다. 초기 열람 범위는 ‘나만 보기’이며 필요한 공유 범위·대상은 교사가 확인한다.
4. 저장 결과는 기존 어댑터의 접수/오류/충돌 처리에 따른다. 아직 저장하지 않은 행과 실제 저장된 일정을 구분한다.
5. 붙여넣은 원본 ID는 검토 행 식별에 사용한다. 서버의 원본 원장에 영구 기록하거나 후속 가져오기를 자동 연결한다고 표시하지 않는다.

따라서 이 작업만으로 **M02 시트 전환 또는 C07 완료로 판정하지 않는다.** 안정 ID의 서버 원장·원본/마지막 반영/현재 사이트의 3방향 대조·충돌 해결·행 오류만 재시도·시험 반영/대조·사이트 기준 전환·역전환 기록은 후속 구현이다. 자동 Google Sheets 연결이나 양방향 동기화 완료로 안내하지 않는다.

시트 실제 표본과 수정 주체·안정 ID 추가 가능성을 확인한 뒤 열 매핑 기본값을 정한다. 확인 전에는 학교별 열 이름·공식 일정 여부·관계 대상을 추측해 확정하지 않는다.

## 6. DB·설정·공개를 실제로 이어 가는 방식

사용자는 이번 공개 목표를 향한 개발을 계속하도록 요청했다. 프런트·계약·시험·문서·준비 작업은 계속 진행한다. DB가 보류돼 있던 과거 상태를 최종 목표의 영구 제약으로 두지 않되, 실제 변경은 저장소의 역할과 구체안 확인 절차를 지킨다.

- DB 확정 전: 기존 제안 SQL과 통합 DB 설계의 차이·기간 경계·학교/회원 참조·API 계약·의존 순서·보존 영향을 정리한다. 서로 다른 세대의 SQL을 모두 적용해 맞춰 보지 않는다.
- 확정 SQL은 Claude Web이 작성하고 실제 SQL Editor 실행은 계란님이 한다. 계정 보존 사전 점검·검증 환경·복구 증거·적용 순서를 먼저 완성한다.
- 인증/보안 로직·외부 설정·모델/비용·공개 범위가 바뀌는 단계는 변경 대상·검증 결과·되돌리기 절차가 구체적인 상태에서 확인한다. 기능 개발을 요청받았다는 이유로 운영 메뉴를 전체 공개하거나 기존 회원을 재생성하지 않는다.
- 병합은 사용자 담당이며 선행 PR부터 Claude 교차검토·자동 검사·Vercel 화면 확인을 거친다. PR이 열려 있다는 사실을 사용자 사이트에 반영됐다고 보고하지 않는다.

근거: [`CLAUDE.md` 2절·3-1절](../../CLAUDE.md). 이 문서는 SQL·RLS·인증·공개표·D번호를 확정하거나 변경하지 않는다.

## 7. 시범 공개 판정표

공개 후보마다 아래 표에 증거 위치·담당·실행일·결과를 연결한다. 실패·미실행·보류를 통과로 합치지 않는다. 원 청사진의 전체 90점 가중치는 문서 AI·시간표를 포함하므로 이번 범위에 그대로 적용해 점수를 만들지 않는다.

| 확인할 항목 | 공개 조건 |
|---|---|
| 범위 | P01~P11의 포함 기능을 실제 사용할 수 있고 제외 기능은 오해 없이 표시 |
| 기존 계정/자료 | 회원 ID·승인·기존 서비스·보호 파일 보존, 이관 대조와 복구 확인 |
| 권한 | 학교/기간/작성자/파일/AI/구형 경로 모두 허용·거부 시험 통과 |
| 업무 확정 | 중복·응답 유실·동시 수정·제출·검토·정정·인계의 결과가 일관됨 |
| 저장/파일/전환 | 다른 기기 재조회·원본 실물·시트 기준 전환·실패 재개 대조 완료 |
| 학생/평가 | 실제 명부 연결·작성자 전용·근거 최신성·정정/삭제·출력 확인 |
| Claude | 출처·현재판·권한·실행 확인·실패 수동 경로·기억 관리 검증 |
| 운영 | DB+파일 격리 복원, 삭제/회수 재적용, 문의·관측·작업 재시도·공개표 준비 |
| 사용성/성능 | 실제 교사 역할 과제, 모바일/확대/키보드/화면읽기, 합의한 데이터량의 서버 조회·저장 성능 확인 |
| 최종 검토 | 자동 검사·Claude 교차검토·사용자 미리보기 확인과 공개 승인 |

학교급별 지원은 실제 검증한 학교 정책·자료 유형에 한해 표시한다. 다중 학교로 설계됐다는 사실을 전국 모든 초·중·고의 현장 검증 완료로 표현하지 않는다. 공개일이 다가오더라도 포함 핵심을 조용히 빼서 완료 처리하지 않고, 사용자에게 남은 증거와 일정 영향을 보고한다.
