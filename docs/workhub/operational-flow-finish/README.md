## 수정한 문제

인계와 질문형 문서는 요청 번호를 먼저 보관한 다음 서버를 기다린다. 기존 화면은 보관된 요청이 있다는 이유만으로 정상 처리 중에도 “이전 요청의 결과를 먼저 확인”하라고 표시했다. 실제 수합 초안·제출에서도 같은 혼동을 확인했다.

| 화면 | 서버를 기다리는 동안 | 응답을 확인하지 못한 뒤 |
|---|---|---|
| 학교 인계 | 인계 요청을 처리하고 있습니다 | 기존 인계 결과 확인 안내·버튼 |
| 질문형 문서 저장·생성 | 문서 요청을 처리하고 있습니다 | 같은 양식 요청 다시 확인 |
| 수합 저장·제출 | 수합 요청을 처리하고 있습니다 | 이전 요청 그대로 다시 확인 |

처리 중 버튼은 비활성 상태로 `처리 결과 확인 중…`을 표시한다. 화면 읽기 도구에는 상태 변경을 알린다. 기존 `busy`와 보관 요청 상태만 사용하며 새 상태·타이머·자동 재전송을 만들지 않았다. 입력, 원본, 요청 번호, 명령, 복구 경로, 명시 확인·제출 조건은 그대로다.

변경 위치는 `SchoolTransitions.tsx`, `GuidedWorkspace.tsx`, `CollectionServerPanel.tsx`의 안내 영역이다. DB·서버 계약·권한·메뉴 공개 범위·AI 비용·파일 생성 코드는 변경하지 않았다. SQL 실행과 신규 회원 연결도 하지 않았다.

## 자동 검증

실제 React·어댑터와 합성 HTTP/RPC/Storage 응답으로 지연·응답 유실·복구를 검증했다. 운영 왕복 결과와 합성 시험 결과를 구분한다.

| 검사 | 통과 |
|---|---:|
| `npm test` | 5,204 |
| 학교 인계 브라우저 | 53 |
| 문서 생성 → 수합 → ZIP 브라우저 | 11 |
| 서버 수합 브라우저 | 38 |

새 회귀는 정상 대기 안내와 응답 유실 뒤 복구 안내를 구분하고, 입력·원래 요청 번호·명령이 유지되며 반영은 한 번인지 확인한다. 인계 신청·수락, 답변 저장·생성, 수합 초안·최종 제출을 포함한다. 640px·200% CSS 확대에서 문서 입력 보존·단계 키보드 이동과 인계 복구 버튼 실행도 확인했다.

전체 시험의 첫 실행은 제한된 실행 환경에서 로컬 소켓·Git Bash·임시 경로 접근 오류로 7개 파일이 실패했다. 시험과 기대값은 바꾸지 않고 로컬 실행 권한과 독립 임시 경로로 전체를 다시 실행해 5,204건이 통과했다. 문서 전체 흐름의 첫 실행은 다운로드 임시 파일 접근이 취소됐고 독립 임시 경로에서 다시 통과했다. 첫 실패를 제품 결함이나 성공으로 계산하지 않는다.

## 판단해서 정한 것

- 복구 문구를 없애지 않고 정상 대기 중일 때만 바꾼다. 결과 미상 시 원래 요청으로 확인해야 중복 실행을 피할 수 있기 때문이다. 되돌릴 곳은 위 세 컴포넌트의 조건부 안내 문구다.
- 수합도 같은 증상이 있어 함께 수정했다. 저장·제출 서비스나 예약 파일 처리는 그대로 두었다.
- 시험 자료는 기존 시험 계정 1명에 한정했다. 기존 수합 담당과 시간표는 복구했고, 새 시험 수합은 제출·ZIP 대조 근거로 남겼다.
- CSS 확대와 실제 Chrome 확대를 구분한다. 브라우저 제어의 확대 단축키는 배율 변화가 확인되지 않아 실제 200% 확대 통과로 기록하지 않았다.

## 남은 작업

3. 실제 교사 연결·전체 교사 공개·대량 시범은 별도 범위다. 이번 작업에서 변경하지 않았다.
