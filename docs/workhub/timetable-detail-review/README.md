## 운영 사이트에서 직접 확인한 범위

현재 시험 수업의 운영 날짜가 10월 30일로 지나 있어 **새 이동 요청 → 다른 교사 동의 → 담당자 승인**을 이번 운영 점검에서 새로 실행하지 않았다. 기존 이력 조회가 새 쓰기 왕복 성공의 증거는 아니다. 실제 자료를 연장하거나 소속·역할을 바꾸지 않고, 미래 수업·동의·승인·충돌·원래 요청 복구는 합성 응답 브라우저 회귀로 확인한다.

## 자동 검증

- 수정 전 재현: 최초 5개 중 4개 실패(입력 숨김 3경로, 사라진 공식 시간 1경로).
- 운영에서 관찰한 확정 탭 깜빡임도 별도 지연 응답 시험에서 수정 전 실패.
- 신규 회귀 `workhub-timetable-exchange-draft-recovery.mjs`: 9/9 통과.
- 새 시험은 `tests/browser/run.mjs`에 등록해 CI에서도 실행한다.
- 전체 `npm test`: **5,275건 통과**, Python 건너뜀 없음.
- 시간표 브라우저: 최초 **48개 파일 중 47개 통과**. `workhub-timetable-local-engine` 첫 사례에서 실제 Python 자식 계산이 `ENGINE_EXITED`로 끝나 1파일 실패.
- 같은 코드·기준의 계산기 단독 재실행: **19/19 통과**. 최초 종료 원인은 확정하지 않았으며 계산기 코드나 시험 기준을 완화하지 않았다.
- 마지막 탭 표시·시각 문구 수정 뒤 운영 동선·새 회귀·확정·결과 복구·요청 닫기 **5개 파일 재실행 전부 통과**.
- 중복 실행을 빼고 각 파일의 최종 결과로 집계: **48/48파일·591개 사례 통과**. 이 숫자를 최초부터 실패가 없었던 결과로 해석하지 않는다.
- `npm run check:workhub`, 통합 사이트 `npm run build`, 업무실 `npm run build:workhub` 통과. 통합 빌드의 기존 500 kB 초과 청크 경고는 남아 있다.

```powershell
npm test
npm run check:workhub
npm run build
npm run build:workhub
node tests/browser/run.mjs timetable
node tests/browser/run.mjs operation-navigation exchange-draft-recovery operation-recovery publication-commit request-close
```

브라우저 회귀는 실제 React 화면·탭 메모리·전송 어댑터를 사용하지만 서버 값은 합성이다. 실제 운영 승인 왕복이나 실기기 모바일 키보드 시험으로 계산하지 않는다.

## 판단해서 정한 것

1. 조회 범위를 바꾸어도 보내지 않은 입력은 버리지 않는다. 전송 가능 여부는 기존 `inputFor`와 서버 검증에 맡기고, 화면에서 입력 정리를 할 수 있도록 한다.
2. 조회 실패·새 요청 권한 없음에는 보관 입력을 계속 숨긴다. 화면이 다시 열릴 때까지 임의의 이전 자료로 전송하지 않는다.
3. 확정 탭을 숨기더라도 기존 관리자 입력·결과 미상 요청을 복구할 경로는 남긴다. 권한 자체는 변경하지 않는다.
4. 운영 시험 자료를 임의로 미래로 옮기지 않는다. 새 승인 왕복을 다시 확인하려면 별도로 미래 시험 수업을 준비한다.

앱 변경을 되돌릴 대상은 `TimetableExchangePanel.tsx`, `TimetableOperationsWorkspace.tsx`이다. DB 되돌리기나 환경변수 변경은 없다.
