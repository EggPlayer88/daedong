## 교사가 보는 변화

업무나 일정을 작성하다가 다른 탭에 다녀와도 동료 교사 이름·명부 순서 변경 때문에 입력창이 초기화되지 않는다. 계정 또는 학교 문맥 조회가 잠깐 실패하면 업무 화면은 숨기고 작성 중인 내용은 현재 탭의 메모리에 보관한다. 같은 계정·학교·권한을 다시 확인한 뒤 입력창을 복원한다.

현재 탭을 새로고침하거나 닫으면 보관 내용은 사라진다. 서버 자동 저장이나 영구 초안 보관 기능은 아니다. 연결 오류 화면에서도 미저장 내용이 있으면 탭 종료 확인을 요청한다.

## 입력 복구의 동작 계약

| 상황 | 처리 |
|---|---|
| 동료 이름·명부 순서·내 표시 이름만 변경 | 현재 입력창 유지, 표시 자료 갱신 |
| 계정/학교 문맥 조회의 일시 오류 | 기존 화면 숨김, 현재 탭 초안 보관, 같은 범위 재확인 후 복원 |
| 계정 변경 후 보류 조회와 새 인증 신호가 겹침 | 이전 화면을 숨기고 재검증 성공 전까지 오류 안내 유지; 소속 없음으로 잘못 표시하지 않음 |
| 내 계정·학교·역할·소속 유효성 등 실제 범위 변경 | 기존 초안 폐기; 다시 이전 범위로 돌아와도 부활하지 않음 |
| 기존 업무/일정 수정 초안 복원 | 현재 원본 접근 가능 여부를 다시 확인한 뒤 표시 |
| 원본 재조회 일시 실패 | 입력 본문을 숨긴 상태로 보관, 재시도 제공 |
| 원본 없음 또는 확정 접근 거부 | 해당 초안과 부모의 복구 위치도 폐기 |
| 재연결 중 원본 버전 변경 | 이전 expectedVersion 유지; 저장 시 충돌 비교를 거쳐 명시적으로 재적용 |
| 저장은 됐지만 응답만 끊김 | 일반 초안보다 미확정 명령 우선; 기존 요청 키·입력으로 결과 확인 |
| 취소/저장 완료/가져오기 종료 | 해당 초안 제거, 늦은 이전 콜백이 다시 쓰지 못하게 차단 |
| 업무 저장·취소 후 다른 업무 상태 변경 충돌 | 새 충돌도 보관 대상으로 다시 활성화하여 재연결 뒤 비교/재적용 유지 |
| 시트 가져오기 중 연결 오류 | 원문·구분자·열 연결·행 입력·이미 등록한 행을 복구 |
| 가져오기 복원 후 새 행 등록 | 기존 일정 목록을 다시 비교한 뒤 허용; 완료 행 재등록 방지 |

인증 통과 조건·토큰 검증·서버 어댑터·RLS 전제는 유지한다. 복구 저장소는 권한 판정을 대신하지 않으며 기존 연결 결과에 따라 읽기를 열거나 잠근다. 운영 SQL·회원 정보·메뉴 공개 범위도 변경하지 않았다.

## 구현 위치와 판단 근거

1. `app/edit-drafts.tsx`: 현재 탭 메모리 저장소. 세대 번호로 이전 화면의 늦은 쓰기/삭제를 무효화한다. localStorage/sessionStorage에 업무 내용을 남기지 않는다.
2. `app/ConnectedWorkspace.tsx`: 전체 명부 대신 내 선택 학교의 유효 권한 범위를 비교한다. 실제 권한 변화와 표시 정보 변화를 구별한다.
3. `tasks/TaskPanel.tsx`, `calendar/EventEditor.tsx`: 초안·원본 버전·충돌 보관과 복원 전 원본 재확인. 확인된 권한 상실을 보관으로 우회하지 않는다.
4. `CalendarPanel.tsx`, `CalendarImport.tsx`: 화면 위치와 가져오기 진행 정보를 함께 보관한다. 일반 일정과 행 편집 초안의 저장 칸을 분리한다.
5. 기존 입력 유실의 원인은 화면 생명주기였으므로 DB나 인증 계약 변경 없이 화면 상태 계층에서 해결했다. 영구 초안이 필요해지면 별도 보존·동기화 설계가 필요하다.

되돌릴 때는 위 제품 파일과 관련 회귀를 함께 되돌려야 한다. 저장소만 제거하면 폼의 복구 계약과 맞지 않는다.
