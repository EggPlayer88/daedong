## 독립 검토에서 추가로 고친 경계 사례

- 다른 교사의 이름이나 명부 배열 순서가 바뀌어도 내 저장 키를 잃지 않는다.
- 역할·부서·학년·교과·유효기간이 바뀌거나 소속이 끝나면 이전 권한 범위의 요청을 제거한다.
- 같은 교사가 학교를 바꾸는 동안에는 요청을 학교별로 구분한다. 다른 로그인 계정으로 바뀌면 폐기한다.
- 재접속 후 명부 순서가 달라져도 유효한 기존 선택 학교로 돌아간다.
- 새 일정의 보관 요청에 다른 기존 일정의 ID가 섞이지 않도록 원본 선택을 분리하고 상세 수정 진입을 막는다.
- 일정/가져오기 입력을 접은 뒤 복구 안내에 초점을 둔다. 시트 편집 취소는 원래 행 버튼으로 돌아간다.

## 판단해서 정한 것

1. **결과 불명은 새 키로 재전송하지 않는다.** 서버 저장 후 응답만 사라진 경우 중복 생성이 가능하기 때문이다. 구현 위치는 `app/pending-requests.tsx`, `TaskPanel.tsx`, `EventEditor.tsx`다.
2. **복구 명령은 현재 탭 메모리에만 둔다.** 새로고침·탭 종료를 막는 안내를 제공하지만 재시작 이후 복구를 보장하지 않는다. 실제 운영에서 장기 미확정 요청을 처리할 접수 조회/관리 기능은 DB 재개 후 별도 설계 대상이다.
3. **교사의 읽기 흐름을 풀고 미확정 쓰기는 제한한다.** 결과가 불명확한 상태에서 같은 내용을 새 요청으로 만드는 것은 허용하지 않는다. 앱 전체를 모달에 가두는 문제는 해소했다.
4. **보완 제출과 일반 정정은 구분한다.** 요청된 보완이 지연되어도 접수하고 지연을 기록한다. 일반 정정/철회 권한을 넓히지 않는다. 수정 위치는 `workflows/store.ts`다.
5. **기존 학생 데모 자료를 자동 삭제하지 않는다.** v2 원본은 남기되 자동 표시·새 학생 내용의 영속 저장을 중단했다. 현재 창의 학생 기록은 내보내기에도 넣지 않는다. 위치는 `preview/persistence.ts`다.
6. **실제 복사 표본이 없는 TSV 따옴표 규칙은 추측으로 완화하지 않는다.** 정상 표본을 확보한 뒤 구분자별 검토한다.
7. **브라우저 검사는 재현한 사용자 흐름을 검증한다.** 변경된 명세는 기대값을 함께 바꾸고, 비동기 렌더가 끝나기 전 검사하던 경합은 완료 상태를 기다리도록 수정했다. 검사를 건너뛰거나 실패를 무시하지 않는다.
8. 되돌릴 때는 영역별 변경과 테스트를 함께 되돌린다. v3 데모 저장을 되돌리면 학생 자료 자동 복원 문제가 재발할 수 있으므로 단순 저장키 교체는 피한다.
