- 앞서 받은 UI·UX 통합검토의 AI 입력 이동 잠금(R1), 처리 중 안내(R2)도 관련 수정에 포함했다.

Claude는 가상 2027-03-01~2028-03-01을 22역할로 순차 시험했다. 실제 22명이 동시에 접속한 부하 시험은 아니다. 월별로 시간을 넘겼으므로 실시간 자정 전환도 모두 검증된 것은 아니다. Haiku 2회, 누적 예약 상한 계기 $0.16/$9, 정산액 1센트 미만은 **Claude 보고값**이다.

파일 SHA-256·HWPX 치환 범위·중복 방지·교환 동의/승인·인계 후 권한·학생 기록 비노출이 통과했다는 보고는 유효하다. 그러나 학년도 전환과 기간 휴업은 보완이 남아 있으므로 “실운영 전체 완료”로 판정하지 않는다.

원본 보고서는 수정하지 않았다. 운영 DB에 접속하거나 변경하지 않았으며, 진행 중인 시험 시계·계정·예산·기록을 초기화하지 않았다. 앱 수정은 `fix/annual-feedback-recovery`, 복제 설치 보강은 `fix/sandbox-clock-safeupdate`로 분리했다. 시험 사이트가 추적하는 `feat/accelerated-school-sandbox`에는 커밋하지 않는다.

## 3. 다음 수정 계획 — 우선순위와 완료 조건

### 1순위: 학년도 전환·관리자 연속성(F44)

권장 설계는 **학교 소속과 학년도 담당 배정을 분리**하는 것이다. 재직 중 학교 소속을 매년 복제하지 않고 학급·담임·수업 담당만 학년도별로 관리한다. 전출/휴직 등 의도한 소속 종료를 자동으로 연장해서는 안 된다.

- 새 학년도 준비에서 다음 학년도 기간과 교사 소속/역할 만료일을 대조한 사전 점검표 제공.
- 관리자 0명 예정, 수업 담당 소속 만료, 새 담당 미배정 등을 날짜별로 표시.
- 다음 학년도 배정 초안 → 영향 비교 → 명시 확정. 개인 상담·개인 기억·메시지 내용을 복사하지 않음.
- 이미 모두 만료된 학교는 일반 교사에게 관리자 화면을 열어 해결하지 않음. 별도 관리자 복구 승인 경로와 감사 근거 필요.
- SQL: 새 증분·원문 지문·원 요청 번호 접수증·변경 전후 자료 보존 시험. 기존 R0/P1/P9 확정본 덮어쓰기 금지.
- 완료 조건: 2월 사전 배정, 3월 전환, 의도한 퇴직 만료, 마지막 관리자 종료 차단/복구, 같은 요청 재전송, 기존 연도 조회를 두 학교 교차 시험.
- **결정 필요:** 학교 소속 유지 원칙, 마지막 관리자 소속/역할 종료를 막을지 별도 복구 절차로 처리할지.

### 2순위: 기간 휴업·방학과 보강(F26·F16·F6·F45)

현재 `t2_closed_days`의 분류는 신규 공개·교환 검증에 쓰인다. 일정 분류만 추가한다고 이미 공개된 날짜별 수업이 일괄 취소되는 것은 아니다.

- 시작/종료일·사유·학급 범위·방학/법정 공휴일/재량휴업/일시 휴업 선택.
- 기존 수업·교환·특별 일과·합반·실시 기록을 모두 포함한 영향 미리보기.
- 합반 일부만 휴업이면 기존 차단 규칙 유지. 이미 실시한 수업을 무단 취소하지 않음.
- 기간 크기 제한과 단일 미리보기 지문, 판/원 요청 번호로 확정. 부분 성공을 전체 완료로 표시하지 않음.
- 반복 실행은 같은 취소를 중복 생성하지 않음. “휴업 철회”는 원 변경을 근거로 복구 미리보기를 다시 거침.
- 보강 필요 여부는 휴업 분류와 승인한 학교 정책으로 판정. 기존 보강 할 일을 자동 삭제하지 않으며 종결 사유·처리자 기록 필요.
- **결정 필요:** 공식 방학·공휴일의 정규 미편성 처리 기준과 기존 보강 검토 건 종결 기준. 정책 확정 전 서버 계산 변경 없음.

### 3순위: 초기 연결·조회 성능(F2·F3·F4)

- INITIAL_SESSION, 토큰 갱신, 실제 UID 변경을 각각 재현. 현재 보고의 초기 이벤트 원인은 추정이므로 인증 로직을 임의로 완화하지 않음.
- 동일 시점의 프로필 조회를 묶을 후보와 직렬 RPC 의존관계 측정. 승인/역할 철회가 지연되는 장기 캐시는 사용하지 않음.
- 시간표 조회/추천의 읽기 전용 실행 계획·행 수 확인 후 인덱스/쿼리 보강을 새 SQL로 준비.
- 쓰기 요청을 타임아웃만으로 새 번호 재전송하지 않음. 읽기 재시도도 횟수·계정 변경 취소를 제한.
- 완료 조건: 동일 자료/동일 계정에서 호출 수와 첫 표시 시간을 전후 비교, 만료/계정 전환/오래된 응답 거부 시험. 이번 작업에서 “11초→3초” 실측 성과를 주장하지 않음.
- **검토·승인 경계:** 인증 이벤트·검증 경로 변경은 CLAUDE.md 2절에 따라 구체적 패치 검토 후 진행.

### 4순위: 교환 추천·인계 도착 동선(F5·F34·F35)

- 추천 검색 한도·대상 범위·하드조건 탈락 사유를 분리해 기록. “40개 후보 없음”을 전체 교환 불가능으로 안내하지 않음. 같은 학급 후보를 먼저 확인하되 유효한 합반/다른 학급 교환을 일괄 제거하지 않음.
- 인계 알림의 source 계약과 수락 화면 이동을 연결. 일반 교사를 학교 관리 첫 화면으로 보내기보다 본인 인계 수신함으로 연결. 서버 당사자 검사 유지.
- 관리자 대리 인계는 현재 권한에서 지원되지 않는 정책 확장. 이유·관리자 확인·받는 사람 수락·감사 이력을 갖춘 새 명령으로 설계. 이전 담당자 사적 자료는 제외.
- **결정 필요:** 관리자 대리 인계를 허용할지. 사용자 승인 전 공개 범위/권한 확대 없음.

## 4. 검증과 배포 경계

- SB-03 별도 브랜치: 격리 PGlite 회귀 **9건 통과**. PostgreSQL 함수 동작과 상태 보존을 검증했고, 실제 Supabase safeupdate 확장 자체를 로컬에서 시험한 것은 아니다.
- 실제 시험 DB에는 읽기 전용 함수 정의/지문 조회만 실행했다. 실제 AI 호출, 학교 자료 수정, 계정 역할 변경, 시계 이동은 0회.
- 앱 PR은 main 대상. SB-03 PR은 #99 브랜치 대상이다. 자동 병합/배포/SQL 실행은 하지 않는다.

## 5. 판단해서 정한 것

1. F44를 “모든 학교가 3월 1일 자동 만료”로 단정하지 않았다. 시험 seed의 명시적 종료일을 확인했기 때문이다. 그래도 관리자 연속성은 학교 운영 전에 필요한 보강이다.
2. 기한 경과와 마감은 다른 상태다. 표시만 추가하고 기한이 지났다고 자동으로 접수를 닫지 않았다.
3. 마감 후 새 정정 차단과 기존 요청 결과 복구를 분리했다. 이미 반영된 요청을 미반영으로 오인해 중복 처리하지 않기 위해서다.
4. 같은 파일명은 자동 교체하지 않는다. 사용자가 기존 첨부 선택을 제거해야 하며 과거 제출본은 보존한다.
5. 숫자 단위를 자동으로 붙이지 않는다. 문단 전체 치환 계약을 유지하고 담당자가 생성 결과를 확인하게 한다.
6. UI 변경을 되돌리려면 이 앱 PR을 되돌릴 수 있다. SB-03은 별도 복제 설치 변경이며 운영 DB에는 영향이 없다. 진행 중 시험의 자료를 초기화하는 되돌리기는 제공하지 않는다.
