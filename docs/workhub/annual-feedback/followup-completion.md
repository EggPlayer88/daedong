# 연간 시험 후속 묶음 — 구현·검토 기록

2026-10-30. 앱 #100, 가상 학교 전용 #101. 운영 사이트와 진행 중 시험 자료는 유지했다. 아래 ‘구현’은 브랜치와 자동 시험 기준이며 운영 적용 완료를 뜻하지 않는다.

| 피드백 | 이번 처리 | 반영 조건 |
|---|---|---|
| F13·F29 수합 상태 | 목록과 홈에 서버의 초안/공개·접수/마감/보관·학교 날짜를 사용. 기한 지남을 자동 마감으로 취급하지 않음. 추가 조회가 늦어도 기존 목록 조작을 막지 않음 | AF2 → 앱 배포 |

판 번호는 오류·충돌·생성물 검증에서 중요한 근거여서 없애지 않았다. 같은 이름의 교사·수업 구분에 필요한 식별도 보존했다. 내부 UUID를 모든 화면에서 무조건 숨기는 변경은 하지 않았다.

## 검증 경계

| 검증 | 결과 |
|---|---|
| 앱 전체 회귀 | 5,255건 통과, 실패 0 |
| 복제 학교 전체 회귀 | 5,238건 통과 |
| 타입 검사·앱/복제 빌드 | 통과 |
| AF2 격리 PostgreSQL 17 | 33건 통과, 실패 0 |
| AF2 실제 응답 → 앱 parser | 정상 응답 13건 + 예상 거절 응답 14건 확인 |
| 후속 화면 브라우저 | 서로 다른 29개 파일, 433개 시나리오 통과(재실행 중복 제외) |

계산기 지속 작업자 시험은 병행 실행 중 첫 결과에서 두 번째 작업 접수 대기 실패가 있었다. 다른 시험과 겹치지 않은 전체 재실행에서는 해당 파일 55건이 통과했다. 원인은 확정하지 않았고 계산기 코드·시간 제한·검사 기준을 바꾸지 않았다. UI 명칭·상세 접기 변경에 따른 시험 선택자를 현재 화면 범위로 좁혔으며 행동과 요청 수 검사는 유지했다. 기존 AF1 60건·T2 114건·SQL 응답 대조 15건과 이전 브라우저 검증은 README의 앞선 결과로 구분한다.
- 브라우저의 DB·Storage·AI 응답은 합성이며 실제 AI 유료 호출은 없다.
- 320px·큰 글씨·CSS 200% 확대를 포함한다. 실제 휴대폰 키보드/운영 Chrome 점검을 대신하지 않는다.
- AF2 전후 기존 자료·기존 함수·권한 지문 비교, 후반 실패 시 원자 롤백, 경쟁 게시 1회, 중지 후 원접수증 복구를 확인한다.

## 남은 일

1. #100/#101 최신 커밋의 CI와 Claude 검토.
2. 사용자 승인 후 AF1·AF2 설치 및 전후 지문/사후 점검. [AF2 실행안내](../../../database/workhub-annual/af2/AF2_실행안내.md).
3. 사용자 앱 병합·배포 후 기존 시험 계정으로 실제 왕복 재확인. #101은 진행 중인 가상 학교에 임의 배포하지 않음.
4. 초기 로딩 실제 배포 전후 측정·실제 휴대폰 키보드·실제 교사 연결.
5. 관리자 대리 인계·학교 전체 수합 조회·일반 교사 양식 제작은 사용자 결정대로 설계만 유지. 이번 완료 범위에 포함하지 않음.

## 판단해서 정한 것

- 초안 동시 게시를 새 명령으로 나누었다. 기존 게시의 의미를 바꾸지 않고 동일 번호의 다른 명령 충돌을 검사하기 위해서다.
- 조회 실패를 접수 중 상태로 추정하지 않았다. 권한·판·학교가 확인된 응답만 상태 표시로 사용한다.
- 유료 검토는 별도 확인을 추가했지만 모델·토큰·예산·자동 승격 정책을 바꾸지 않았다.
- 시각 안내는 시험 전용 브랜치에 두었다. 실제 운영 시계와 진행 중 시험 날짜를 바꾸지 않는다.
