# 일정·협업·인계 자동 검증

## 검증 경계

실제 React 컴포넌트와 기존 전송·응답 검증을 사용하되 학교·교사·RPC·저장은 합성 자료다. 운영 DB·실제 회원·유료 AI는 사용하지 않았다. 새 UI 시험은 외부 요청을 차단하며 브라우저 오류와 외부 요청이 모두 0건인지 검사한다.

## 결과

## 신규 화면 시험

1. 일정의 공유 영역과 기본 입력을 함께 보고 대상 설정을 접거나 화면을 줄여도 입력을 보존한다. 저장 명령의 포함 교사와 장소가 일치한다.
2. 일괄 가져오기에서 열을 연결하면 단계 표시만 옮겨지며 실제 저장은 하지 않는다.
3. 협업 상세에서 응답 대기·수락과 완료 확인을 구분한다. 목록/상세 배치는 1440px에서 두 열, 390px에서 한 열이다.
4. 내 업무 연결을 접어도 연결 ID·판이 유지된다. 내용을 고치면 이전 전송 확인이 해제되며 재확인 뒤 한 번만 보낸다.
5. 인계 미리보기에서 제외 자료를 보여준다. 입력을 고치면 미리보기·동의를 해제하고 최종 요청은 선택한 범위만 전달한다.
6. 인계 응답 유실 뒤 원래 명령·요청 번호로 복구하며 접수는 1건이다.
7. 320px·큰 글씨·어두운 화면에서 입력·버튼의 가로 범위를 검사한다. 새 학년도 공식 날짜 6칸은 빈칸을 유지한다.

## 발견과 보완

- 인계 기록의 제목과 상태를 시각적으로 분리하면서 기존 제목 탐색이 달라졌다. 스크린리더 제목에는 기존 제목·상태 이름을 유지해 기록 탐색을 보존했다. 기존 51건 기대값은 바꾸지 않았다.
- 선택 업무 연결을 접었으므로 기존 협업 시험에서 해당 설정을 직접 펼친 뒤 같은 명령·내용 검증을 수행하도록 했다.
- 신규 시험의 화면 이동이 미저장 일정의 beforeunload에 막혔다. 시험 하네스가 beforeunload만 승인하고 다른 대화상자는 거절하도록 수정했다. 앱의 이탈 보호는 유지했다.
- 첫 전체 시험은 샌드박스 임시 디렉터리의 HWPX 생성 권한 오류가 반복되어 중단했다. 테스트 기대값이나 앱 코드를 바꾸지 않고 일반 로컬 실행 권한으로 전체 시험을 다시 실행했다.

- 전체 회귀의 기존 SSR 시험 2곳은 HTML 속성 순서와 정확히 일치하는 문자열에 묶여 있었다. 스타일 클래스 추가에도 폼의 접근성 이름·저장 버튼 disabled를 그대로 검사하도록 속성 단위 검사로 바꿨다. 협업 43건·일정 접근성 2건은 단독 재실행에서 통과했다.
- 기존 작업자 회귀의 실패 요청 → 다음 정상 요청 시험에서 15초 대기가 한 번 초과됐다. 같은 시험의 단독 재실행 55건은 통과했다. 최종 수정은 이미 사용 중인 접수증 직접 조회 도우미를 예상 종료 상태별로 일반화하여 반복 Python 실행을 제거한다. 계산 제한·종료 여유를 반영해 기다리고, 잘못된 종료 상태와 작업자의 조기 종료는 즉시 실패로 처리한다. 마지막 CLI 상태 재확인, INVALID_REQUEST 코드, 잘못된 결과 파일 없음, 정리 가능 검사는 모두 유지한다. 실제 계산기 코드는 변경하지 않았다. 이 보완 뒤 최종 전체 실행에서도 작업자 55건이 통과했다.

운영 기능 시험·실제 교사 연결·Claude 최종 검토는 사용자 요청대로 뒤로 미룬다. 이 문서의 자동 검증을 운영 확인 완료로 취급하지 않는다.
