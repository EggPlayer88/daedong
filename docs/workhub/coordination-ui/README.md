# 일정·협업·인계 화면 정리

PR #87의 입력 화면 공통 구성(`c2deb58`)을 이어받는 후속 작업이다. 기존의 프리텐다드·토스페이스와 화면 설정을 사용한다. 운영 확인은 사용자 요청대로 뒤로 미루며 실제 React·전송 어댑터·합성 응답으로 자동 검증한다.

| 화면 | 바뀌는 사용 흐름 | 유지하는 경계 |
| --- | --- | --- |
| 일정 작성 | 일정 제목·날짜·장소·내용과 공유 범위를 나란히 표시. 공유 영역 안에서 대상 미리보기를 확인. 홈 추천·관련 조건은 필요한 때 펼침 | 열람 범위와 홈 추천 구분, 포함·제외 우선순위, 충돌 전체 비교, 원래 요청 번호 복구 |
| 일정 일괄 입력 | 원본 입력 → 열 연결 → 비교·선택 → 저장 완료 단계 표시. 원본 표와 파일 입력 배치 정리 | 원본 ID, 공개 범위, 제외 열·보류 행, 충돌 교체 확인, 중복 방지와 일괄 접수 |

## 판단해서 정한 것

1. **일정 공유 범위와 대상 미리보기는 접지 않는다.** 기본 입력을 쉽게 찾게 하면서도 누가 읽는지는 저장 전에 확인해야 한다. 관련 대상 설정은 접을 수 있으며 기존 개별 조건은 처음부터 펼친다. 공개 범위를 바꿀 때도 현재 값을 보존한다.
2. **협업의 선택 업무 연결만 접는다.** 받는 교사·요청 본문·기한과 확인 체크는 바로 보인다. 연결한 업무가 있으면 다시 열 때 설정을 펼친다. 마지막 값을 지워도 편집 영역을 갑자기 접지 않는다.
3. **상태별 설명은 처리 권한이 아니다.** 버튼 노출·활성화는 기존 `allowedActions`와 서비스 검사를 그대로 사용한다. 수락을 완료로, 관리자 확인을 인수 완료로 안내하지 않는다.
4. **인계 단계를 새 마법사로 만들지 않는다.** 한 화면에서 앞선 입력을 고칠 수 있고, 입력 변경 시 기존 미리보기와 동의가 해제되는 동작을 유지한다. 표시는 현재 준비 단계만 안내하며 자동 저장이나 자동 승인을 추가하지 않는다.
5. **오류·미확정 요청은 접힌 선택 설정에 넣지 않는다.** 원래 명령·요청 번호 재확인과 최신 원본 비교 버튼을 계속 노출한다.
6. **반응형 배치는 입력을 재생성하지 않는다.** 화면 너비에 따른 변경은 CSS로 처리한다. 320px·큰 글씨·어두운 화면을 자동 확인한다.

배치를 되돌릴 때는 `EventEditor.tsx`, `CalendarBatchImport.tsx`, 협업 `editors.tsx`·`CooperationWorkspace.tsx`, `SchoolTransitions.tsx`와 각 화면 CSS를 조정한다. 서버·SQL·인증·비용·메뉴 공개 범위 변경이나 운영 데이터 되돌리기는 없다.

## 병합과 이후

추가 SQL·서버 설정은 필요 없다. #87이 아직 병합 전이므로 후속 PR의 base는 `feat/workhub-workflow-ui`다. #87을 먼저 main에 병합한 뒤 이 PR의 base를 main으로 바꾸고 최신 검사·미리보기를 확인한다. main 병합과 운영 배포는 사용자 단계다.

다음 화면 정리 후보는 시간표 관리의 준비·조건·결과 검토·교환 요청/승인이다. 실제 교사 연결, 운영 기능 시험과 Claude 최종 검토는 이번 작업에 포함하지 않는다.
