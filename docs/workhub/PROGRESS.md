## 남은 작업 순서

1. **실제 연결:** PR 검토·병합 순서 정리 → 계정 보존/복구 사전 점검 → 제안 SQL 확정·검증 환경 적용 → 기존 계정과 학교 소속 연결.
2. **일정 실사용 실증:** 실제 Google 계정 진입·진단 → 일정 저장·재조회·홈 반영 → 실제 계정 두 개의 열람/충돌/종료 검증.
3. **개인 업무 실증·수합 서버 전환:** 내 업무 004 검증 환경 적용·홈/수정/완료 왕복 확인 → 수합 상태 전이와 초안 비공개를 DB에서 강제하고 파일·문서 초안 연결.
4. **학생 자료 연결:** 승인 담당·명부·작성자 권한·보존/삭제를 서버에 적용한 뒤 디지털윤리 사이트 연동.
5. **시간표·문서·AI 통합:** Claude 결과와 공통 계약을 맞추고 검증된 문서 엔진 배포 및 근거 기반 에이전트 구현.
6. **파일럿·전국 운영 검증:** 기존 경로 격리, 알림·인계·반복 업무, 성능·복구·접근성·실제 교사 사용성 확인.

실제 환경 연결에는 기존 로그인 세션과 검증 DB 설정이 필요하다. 현재 로컬에 해당 설정이 없다는 사실을 확인했으며 임의 계정 재생성·운영 DB 초기화로 대체하지 않았다.

## 판단해서 정한 것

기존 회원과 운영 앱을 보존하면서 신축 계약을 단계적으로 서버로 옮긴다. 학교 소속 진단의 성공을 저장·OAuth·회원 전체 보존의 성공으로 표시하지 않는다. 합성 로컬 자료를 실제 학생 저장소로 전환하지 않는다. 변경 지점은 각 모듈의 어댑터와 RPC/RLS이며, 실제 적용 전 동일 계약을 검증한다.

개인 업무는 학교·소속 단위로 보관한다. 학교와 무관한 개인 공간, 전출 후 업무 이관, 대량 목록의 페이지 처리와 보관 기간 정책은 후속 범위다. 미확정 요청은 현재 화면의 메모리에 보관하므로 브라우저 강제 종료 후까지 복구하는 기능은 별도 과제다.
