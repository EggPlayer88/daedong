# 업무혁신시스템 누적 진행 현황

최종 갱신: 2026-10-13 · 10차 개발 · 목록 성능 · 기준 [PR #16](https://github.com/EggPlayer88/daedong/pull/16)

이 문서는 **이번 작업 / 누적 진행 / 남은 작업 / 검증 / 판단해서 정한 것**의 인계 기준이다. 화면 구현·코드 검증·실제 서버 연결·운영 공개를 구분하며 테스트 수를 출시 완성률로 계산하지 않는다.

## 이번 작업 — 10차 개발

- 개인 업무·수합 요청·제출 단위 원본·관찰 기록·수업 활동을 **20개씩 표시**하고, 전체 수·현재 범위·쪽 이동을 제공한다.
- 관찰 개정 이력과 제출 이력은 펼칠 때만 본문 DOM을 생성한다. 이력 원본은 그대로 보존한다.
- 검색·홈·진행 표에서 연 원본이 마지막 쪽에 있어도 해당 쪽과 카드로 정확히 이동한다.
- 전체 집계·완료본 합계·현재 학교 본인 전체 근거 출력, 최신 권한·원자료 확인은 표시 페이지와 관계없이 유지한다.
- 작성·검토·연결 확인·저장 재시도 중 쪽 이동을 보호한다. 필터 변경·마지막 쪽 소멸·자료 재증가·조회 실패 후 같은 쪽 입력 복구를 검증했다.
- 동일 합성 자료에서 DOM은 개인 업무·관찰·활동·수합 요청 **97~99%**, 제출 단위 **약 81%** 감소했다. 서버 조회 시간 개선율은 아니다.
- 선행 PR #16의 수합 비노출 검사에서 난수 ID를 응답 숫자로 오인한 시험을 바로잡았고, GitHub 자동 검사 통과를 확인했다.
- 바탕화면 GPT작업에 **10차 목록 성능 HTML**, 검증 이미지·JSON, 누적 보고서와 상세 인계를 제공한다.
- **DB 구축·시간표는 계속 보류. AI는 Claude 전제 유지.** 로그인·회원·인증·권한·SQL·보호 자산·외부 설정·운영 공개 범위는 변경하지 않았다.

수합·학생 기능은 현재 미리보기에만 연결한다. 실제 앱의 연결 메뉴는 준비된 일정·개인 업무까지만 사용한다. 기본 틀이 통합됐다고 모든 모듈의 서버 저장이 끝난 것은 아니다.

## 남은 작업 순서

1. **검토본 통합 준비:** 선행 PR부터 Claude 교차 검토와 사용자 화면 확인. 의존 순서를 지켜 병합한다.
2. **DB 보류 중 화면 개발:** 작성·조회 동선의 사용자 피드백을 반영하고, 실제 교사의 키보드·화면읽기·확대 사용을 확인하고 잔여 오류 복구와 서버 연결 전 데이터 규모의 한계를 보완한다. 목록 DOM 분할은 10차에서 완료했고 서버 조회 성능은 남아 있다. 학교 자료·문서 작업 공간은 기존 청사진·도구 계약을 바탕으로 설계하되 실제 AI·서버 연결 준비와 구분한다.
3. **DB 재개 후 실제 연결:** 통합 설계 [PR #12](https://github.com/EggPlayer88/daedong/pull/12) 확정 → 계정 보존/복구 점검 → 격리 검증 환경 적용 → 기존 계정·학교 소속 연결 → 일정·개인 업무 실사용 실증. SQL 확정은 Claude Web, 실제 적용과 main 병합은 사용자 담당이다. 두 실제 계정의 열람/충돌/승인 회수/소속 종료를 확인한다.
4. **수합 서버 전환:** 초안 비공개·상태 전이·접수·검토 권한을 서버에서 강제하고 파일·문서 초안을 연결한다.
5. **학생 자료 연결:** 담당·명부·작성자 권한·보존/삭제를 적용한 뒤 디지털윤리 수업 사이트와 연결한다.
6. **Claude·문서 통합:** 학교 지식의 근거·유효기간·학교 범위, 개인 비서와 문서 도구 계약을 구현한다. 시간표는 별도 재개 요청 후 진행한다.
7. **교사 파일럿·전국 운영 검증:** 홈 정보량·모바일 동선·접근성, 실제 사용성과 성능·복구·인계·반복 업무를 검증한다.

실제 연결에 필요한 검증 DB 설정과 기존 로그인 세션은 별도 준비 사항이다. 임의 계정 재생성이나 운영 DB 초기화로 대체하지 않았다.

## 판단해서 정한 것

1. **20개 명시적 쪽 이동:** 기존 진행 표와 맞추고 키보드·원본 위치를 유지한다. 변경 위치는 `app/list-window.ts`, 각 Panel과 `ListPagination.tsx`다.
2. **접힌 이력 본문만 지연 생성:** 이력 데이터는 보존하고 보이는 항목만 DOM으로 만든다. 변경 위치는 학생 `RecordCard`, 수합 `UnitPanel`이다.
3. **전체 집계 후 화면 분할:** 학생 근거와 수합 합계를 현재 쪽으로 제한하지 않는다. 저장소·권한·최신성 계약은 그대로 유지한다.
4. **실패를 자료 삭제로 처리하지 않음:** 학생 조회 실패 중 쪽 상태를 초기화하지 않아 보존한 입력으로 돌아간다. 변경 위치는 `StudentsPanel.tsx`의 쪽 보정 effect다.
5. **화면 성능과 서버 성능 분리:** 합성 DOM 측정만 개선 결과로 보고한다. 전체 조회·정렬·집계 비용은 서버 커서 조회·집계와 함께 후속 구현한다.

개인 업무는 현재 학교·소속 단위다. 학교와 무관한 개인 공간, 전출 시 이관, 서버 페이지 조회, 실제 자료의 보존·삭제 정책은 아직 남아 있다.
