## 배포와 개발 구분

**통합 PR 생성은 main 배포 완료가 아니다.** 현재 main 기준은 #25이고 사용자가 통합 PR을 병합해야 앱 배포가 갱신된다. 원본 17개 PR을 하나씩 운영에 병합할 필요 없이 이번 통합 후보를 검토할 수 있다. 이력 보존을 위해 Create a merge commit 방식으로 병합한다.

지정 Supabase는 `dhaoszbqtbofqftgjfyb`다. R0·R1-00~04 적용 결과는 사용자 제공 자료로 확인했다. R1-05/06은 미적용이라 `verification_missing`이 정상이다. 코드 병합만으로 검사기가 가동되지 않는다. 작업자 배포와 서버 비밀값·실제 ClamAV·승인 정책이 남았다. 이번 CI는 전용 로컬 합성 DB만 사용한다.

화면과 서버 연결 코드가 있다는 사실을 **문서 수합 실사용 완료 또는 전체 목표 90% 달성으로 계산하지 않는다.** 수합 미리보기는 새로고침하면 초기화되며 미확정 입력의 복구는 현재 탭 메모리 범위다. 서버에 접수된 자료는 DB 기준이고, 검사 작업자의 재시작 복구는 R1 임대/멱등 계약으로 처리한다.

## 검증 범위와 다음 순서

2차 통합에서는 전체 브라우저 36개 파일을 다시 실행했다. 로컬 PostgreSQL 17.6의 원본 SQL 시험과 실제 작업자 코드를 대조했지만, PostgREST/Storage HTTP는 합성 서버이며 실제 Supabase의 HTTP·Storage 검증은 아니다. ClamAV는 소켓 대역 시험으로 실제 엔진/서명 DB를 확인한 것이 아니다. 컨테이너 빌드·배포도 아직 하지 않았다. 각 시험의 최신 결과 수치는 [자동 검증 결과](integration-r2/verification.md)를 기준으로 한다.

#34 화면 두 결함은 #41에서 수정돼 포함됐다. #27 학교 설정 초안의 중/고 학년 범위와 동일 학년/반 중복 검사는 실제 학교 설정 저장 연결 전 보완한다. 전체 미래 DB 설계의 F1~F9와 R1 SQL 리뷰의 해결된 F1~F7은 서로 다른 범위다.

1. 통합 PR을 Claude가 검토한다. 특히 #41 입력·기존 요청번호 보존과 #42 실제 SQL 작업자 계약을 확인한다. 필요한 보완과 동일 최신 커밋의 CI/미리보기 확인 후 사용자가 병합한다.
2. main에서 17개 원본 SHA 포함을 확인한 뒤 남아 있는 원본 PR을 정리한다. 보류 #3/#5는 유지한다.
3. 서버 실행 위치·비밀값·ClamAV·작업자 실행 방식을 준비한다. 사용자/Claude가 R1-06 정책과 R1-05 학교/작업자 연결을 적용한 뒤 준비 상태를 활성화한다.
4. 실제 PostgREST·Storage·파일 검사/다운로드·공동 제출/정정·ZIP·모바일·다중 교사, 일정/업무 저장과 기존 기능 확인을 모아서 진행한다.
5. 학생 기록 실제 연결, 메신저·학교 자료·Claude·알림·관리 기능을 순차 구축한다. 문서작성 AI·시간표는 계속 보류한다.
