# 업무혁신시스템 누적 진행 현황

최종 갱신: 2026-10-15 · 수합 충돌 비교·미확정 요청 복구

목표는 문서작성 AI·시간표를 제외한 기능을 실사용 가능한 수준으로 완성한 뒤 시범 공개하는 것이다. 사용자 승인으로 **DB 조사·준비를 재개**했다. SQL은 Claude 작성 → 검토 → 사용자 직접 적용 순서다. 현재 Supabase·Vercel·GitHub를 개발·검증 환경으로 사용하며, 별도 Supabase 프로젝트를 요구하지 않는다. 기존 로그인과 회원 자료는 보존한다.

## 이번 작업

- PR #34 검토에서 지적된 화면 두 건을 `fix/workhub-collection-recovery`에서 수정했다. PR #40 `6ad6694`를 기준으로 이어지는 후속 수정이며, Claude의 SQL 브랜치에는 커밋하지 않았다.
- 수합 설정 11개 항목과 제출 답변 3개 항목을 편집 시작 원본·현재 서버·내 입력으로 비교한다. 내가 수정하지 않은 항목은 최신 서버 값을 보존하고, 양쪽이 다르게 바꾼 항목은 선택해야 편집을 계속한다. 숫자 답변·필수 여부·검토 교사·파일 정책·공동 제출 구성도 포함한다.
- 저장 성공 직후 다른 교사가 다시 수정한 경우에는 방금 접수된 요청 원문을 비교 기준으로 보관한다. 과거 원본을 잘못 기준으로 삼아 다른 교사의 되돌림을 덮어쓰지 않게 했다.
- 수합 준비가 해제돼도 이미 보낸 미확정 요청은 기존 번호·본문 그대로 재확인할 수 있다. 재확인의 `NOT_READY`와 `IDEMPOTENCY_CONFLICT`에서는 기존 요청을 버리거나 새 번호로 대체하지 않는다.
- 당장 복구할 수 없으면 입력과 요청을 현재 탭에 보관하고 업무실 내부 메뉴를 이용한다. 다시 열면 현재 접근 권한과 원본을 재확인한다. 보관 메모리가 사라지는 기존 앱으로의 SPA 이동·학교 변경은 차단하고, 새 탭 열기는 허용한다. 새로고침·탭 닫기는 경고하며 영속 보관은 아니다.
- [구현·검증·Claude 인계](39-collection-conflict-recovery.md)에 검증 결과와 한계를 정리했다. 실제 DB 적용·파일 삭제·악성 검사기 배포·인증/공개 범위 변경은 하지 않았다.
- Claude R1 SQL PR #39 `edbb874`의 F7을 재검토했고, 사전 점검이 정상일 때 R1-00~04 적용 가능으로 회신했다. 사용자가 Claude와 적용을 진행하며, 이 문서 시점에는 적용 완료 결과를 아직 받지 않았다. R1-05/06은 후속이다.

## 배포와 개발 구분

2026-10-15 작업 시작 시 원격 main은 #25까지(`ebdc064`)였다. 이번 수정은 #37(서버 파일 처리) → #38(형식 검사 기반) → #40(실제 문서 호환성, `6ad6694`)을 기준으로 이어진다. #39는 Claude의 R1 SQL로 별도 브랜치이며 앱 수정과 병합 순서를 구분한다. 앞선 PR은 #26(내 업무 분리), #27(학교 설정 준비), #28(DB 일부 제약), #29(연결 조사), #30(파일형 수합), #31(Claude SQL), #32(수합 사용성), #33(파일 수명), #34(수합 서버 연결), #35(공동 제출·관리), #36(전체 ZIP)이다. #23에 포함된 과거 PR도 일부 열려 있으므로 열린 PR 수와 미통합 기능 수는 같지 않다. SQL의 사용자 적용과 GitHub PR 병합은 별도다.

현재 지정 Supabase는 `dhaoszbqtbofqftgjfyb`다. 사용자 실행 결과로 B01/B02, 초기 설정 8개 검증 및 전후 구조 지문 7개 일치를 확인했고, 두 회원 표는 각각 18행이다. 사용자가 대동여자중학교 표시·업무실 진입을 확인했다. 자료 값 전체와 Storage 파일 본문 보존을 이 비교만으로 증명하지 않는다. 이번 코드 작업이 DB에 쓰거나 SQL을 바꾼 것은 아니다.

**앱의 서버 연결 코드와 서버 처리 코어를 준비했지만, 수합용 DB·Storage·서버 검사기 적용이 완료된 것은 아니다. 실제 교사 간 수합이나 전체 목표 90% 달성으로 계산하지 않는다.** 미리보기 자료는 여전히 새로고침하면 초기화된다. 연결 화면의 미저장 입력과 결과 미확정 요청 복구도 현재 탭 메모리 범위다. 서버 검사 결과의 재전송도 현재 프로세스·유효 임대 범위이며 재시작/만료 복구는 후속이다. 서버에 확정 접수된 자료의 영속성은 R1 적용 후 별도로 검증한다.

## 검증과 다음 순서

이번 수정의 전체 회귀·브라우저·빌드 결과는 [화면 수정 인계](39-collection-conflict-recovery.md)에 기록한다. 이전 #40의 PDF/HWP 공개 원본 호환성 결과는 [원본 호환성 인계](38-document-compatibility.md)에 보존한다. 공개 PDF 8/8, 공개 HWP 8/30 통과·22개 미지원이며 HWP 전체 호환 완료를 뜻하지 않는다.

R1 재검토에서는 로컬 PostgreSQL 17.6에서 설치/사후 점검·지문 일치, 시나리오 244건, 최신 앱 응답 대조 11건, 별도 F7 확인 25건을 확인했다. Claude의 Linux 전체 러너 285건을 여기서 그대로 재실행한 것은 아니며 실제 Supabase Storage 연결도 아직 검증하지 않았다.

1. 사용자가 Claude와 R1-00 → 01 → 02 → 03 → 04 → 00 비교를 진행한다. R0 재실행·회원 재생성 없이 기존 사이트 보존을 확인한다. R1-05/06은 작업자 배포와 정책 결정 후 별도 진행한다.
2. 이번 화면 수정과 #26~#40을 Claude 검토 결과에 따라 단계적으로 통합한다. 병합은 사용자가 한다.
3. 준비한 파일 처리 코어를 확정 SQL·실제 Storage·승인 악성 검사기에 연결한다. 임대 만료/재시작 복구와 실행 자원 제한을 보완하고 자동 통합 시험 후 준비 상태를 켠다. SQL만 적용하고 수합 완료로 표시하지 않는다.
4. ZIP·공동 단위·철회/정정의 실제 서버 연결, 일정·업무 저장/재로그인, 기존 평가계획서 다운로드, 수합 다중 교사·모바일 시험은 이후 통합 실사용 확인으로 모은다.
5. 학생 기록 실제 연결, 메신저·학교 자료·Claude·알림·관리 기능을 순차 구축한다. 문서작성 AI·시간표는 계속 보류한다.
