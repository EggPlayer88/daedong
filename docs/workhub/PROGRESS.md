# 업무혁신시스템 누적 진행 현황

최종 갱신: 2026-10-13 · 8차 개발 · [PR #15](https://github.com/EggPlayer88/daedong/pull/15) (기준 PR #14)

이 문서는 **이번 작업 / 누적 진행 / 남은 작업 / 검증 / 판단해서 정한 것**의 인계 기준이다. 화면 구현·코드 검증·실제 서버 연결·운영 공개를 구분하며 테스트 수를 출시 완성률로 계산하지 않는다.

## 이번 작업 — 8차 개발

- 수합 요청 작성을 **안내·기한·검토 / 응답 문항 / 제출 대상**으로 정리하고, 작성 중 미리보기와 저장된 원본의 게시 전 점검을 추가했다. 부수·작성 교사 수·책임자·검토자·필수 문항을 구분한다.
- 제목·문항 누락, 중복 단위·자기 검토·소속 문제와 기존 요청당 100개 단위 한도를 안내한다. 동시 수정은 실제 최신 원본을 비교한 뒤 저장 기준판을 선택하며 입력을 보존한다.
- 응답의 초안 저장과 책임자 최종 제출을 구분하고 필수 응답·재제출 사유를 안내한다. 숫자 칸의 미완성 `-` 입력을 빈 선택 응답으로 잘못 제출하는 문제를 수정했다. 0·음수·소수는 기존 계약대로 허용한다.
- 학생 관찰·정정 입력에 **학생·수업·관찰일**, 누락·글자 수·확인 안내와 오류 위치 이동을 추가했다. 입력 시작 시 대상 ID를 유지하며 명부가 바뀌어도 다른 첫 학생에게 저장하지 않는다.
- 저장 결과에 실제 학생·날짜·개정판을 표시하고 **저장한 기록 보기 / 같은 학생 새 기록**으로 연결했다. 이전에 저장한 학생과 새로 명시 선택한 학생을 혼동하지 않는다.
- 수업 활동의 미확정 학생 선택과 실제 확정 연결이 다른 상태에서 이전 학생에게 채택되는 문제를 수정했다. 작성 중 원문·연결판 변경 및 임시 조회 오류가 나면 직접 입력을 보관하고 다시 확인한다. 조회 실패 중 원문·명부 화면을 남겨 표시하지 않는다.
- 바탕화면에 서버 없이 열리는 **8차 작성과 확인 HTML**, PC·모바일 검증 이미지와 누적 진행 보고서를 제공한다. 합성 자료 전용이다.
- **DB 구축·시간표는 계속 보류. AI는 Claude 전제 유지.** 기존 로그인·회원·권한 저장소·SQL·보호 자산·외부 설정·운영 공개 범위는 변경하지 않았다.

## 남은 작업 순서

1. **검토본 통합 준비:** 선행 PR부터 Claude 교차 검토와 사용자 화면 확인. 의존 순서를 지켜 병합한다.
2. **DB 보류 중 화면 개발:** 작성·조회 동선의 사용자 피드백을 반영하고, 화면별 오류 복구·접근성과 실제 규모의 목록 성능을 보완한다. 학교 자료·문서 작업 공간은 기존 청사진·도구 계약을 바탕으로 설계하되 실제 AI·서버 연결 준비와 구분한다.
3. **DB 재개 후 실제 연결:** 통합 설계 [PR #12](https://github.com/EggPlayer88/daedong/pull/12) 확정 → 계정 보존/복구 점검 → 격리 검증 환경 적용 → 기존 계정·학교 소속 연결 → 일정·개인 업무 실사용 실증. SQL 확정은 Claude Web, 실제 적용과 main 병합은 사용자 담당이다. 두 실제 계정의 열람/충돌/승인 회수/소속 종료를 확인한다.
4. **수합 서버 전환:** 초안 비공개·상태 전이·접수·검토 권한을 서버에서 강제하고 파일·문서 초안을 연결한다.
5. **학생 자료 연결:** 담당·명부·작성자 권한·보존/삭제를 적용한 뒤 디지털윤리 수업 사이트와 연결한다.
6. **Claude·문서 통합:** 학교 지식의 근거·유효기간·학교 범위, 개인 비서와 문서 도구 계약을 구현한다. 시간표는 별도 재개 요청 후 진행한다.
7. **교사 파일럿·전국 운영 검증:** 홈 정보량·모바일 동선·접근성, 실제 사용성과 성능·복구·인계·반복 업무를 검증한다.

실제 연결에 필요한 검증 DB 설정과 기존 로그인 세션은 별도 준비 사항이다. 임의 계정 재생성이나 운영 DB 초기화로 대체하지 않았다.

## 판단해서 정한 것

1. **게시·저장 전에 대상과 결과를 확인:** 수합의 책임자·문항·검토 방식, 관찰의 학생·수업·날짜를 분명히 보여 준다. 변경 위치는 `workflows/CollectionEntryGuide.tsx`, `students/ObservationEntry.tsx`다.
2. **안내는 기존 저장 계약을 따름:** 입력 안내를 통과해도 기존 소속·권한·기간·버전 검사는 다시 수행한다. 변경 위치는 `workflows/entry-guide.ts`, `students/entry.ts`와 각 화면의 store 호출이다. 수합의 100개 단위 한도는 기존 기술 계약이며 학교 정책을 신설한 것이 아니다.
3. **화면 선택과 확정 연결을 구분:** 미확정 학생 선택으로 이전 학생에게 잘못 채택하지 않게 한다. 변경 위치는 `StudentsPanel.tsx`의 `ActivityCard`다.
4. **활동 입력만 현재 화면의 메모리에 보관:** 조회 실패 시 원문·명부는 표시하지 않으면서 직접 입력은 복구할 수 있게 한다. 학교·소속 전환 때 기존 컴포넌트 수명에 따라 폐기하며 브라우저 저장소를 추가하지 않는다. 변경 위치는 `StudentsPanel.tsx`의 활동 입력 Map과 편집 보호다.
5. **동시 수정은 실제 원본 비교 후 처리:** 원본판 숫자만 바꾸지 않고 최신 제목·문항·대상을 보여 준다. 변경 위치는 `WorkflowPanel.tsx`의 수합 작성 양식이다.

개인 업무는 현재 학교·소속 단위다. 학교와 무관한 개인 공간, 전출 시 이관, 대규모 목록 페이지 처리, 실제 자료의 보존·삭제 정책은 아직 남아 있다.
