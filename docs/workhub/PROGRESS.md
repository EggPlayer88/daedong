# 업무혁신시스템 누적 진행 현황

최종 갱신: 2026-10-12 · 7차 개발 · [PR #14](https://github.com/EggPlayer88/daedong/pull/14) (기준 PR #13)

이 문서는 **이번 작업 / 누적 진행 / 남은 작업 / 검증 / 판단해서 정한 것**의 인계 기준이다. 화면 구현·코드 검증·실제 서버 연결·운영 공개를 구분하며 테스트 수를 출시 완성률로 계산하지 않는다.

## 이번 작업 — 7차 개발

- 수합 요청의 제목·게시 상태 검색과 **제출 단위별 진행표**를 추가했다. 미제출·검토 대기·보완 필요·완료·완료본과 새 판 처리 중을 구분하고, 책임자·단위·기한 초과로 좁혀 원본 상세로 이동한다.
- 진행표는 20부씩 나누고 현재 제출판·완료판을 함께 표시한다. 진행표를 필터해도 기존 완료본 숫자 합계는 유지되며, 초기 지각과 현재 보완 기한 초과를 구분한다.
- 학생 이름·번호 검색과 **선택 학생/본인 전체 기록**, 기간·직접 관찰/수업 활동·유효/재검토/철회 필터를 추가했다. 검색으로 선택 학생을 자동 변경하지 않고 입력 중인 관찰·정정·철회 내용을 보호한다.
- 근거 출력은 현재 학교의 본인 전체 유효 기록임을 명시하고 다운로드 직전에 원본을 재검증한다. 원자료가 바뀐 오래된 출력은 막고, 직접 관찰의 개정판이 바뀌면 최신 미리보기를 다시 확인하도록 했다. 잘못된 조회 응답은 0건 대신 실패로 안내한다.
- 바탕화면에 서버 없이 열리는 **7차 수합과 학생 기록 HTML**, PC·모바일 검증 이미지, 누적 진행 보고서를 저장했다. 합성 자료만 사용하며 실제 서버에 접속하지 않는다.
- **DB 구축·시간표 작업은 사용자 요청에 따라 보류. 사이트 AI는 Claude 전제 유지.** 기존 로그인·회원·SQL·AI 비용 설정·운영 공개 범위는 변경하지 않았다.

수합·학생 기능은 현재 미리보기에만 연결한다. 실제 앱의 연결 메뉴는 준비된 일정·개인 업무까지만 사용한다. 기본 틀이 통합됐다고 모든 모듈의 서버 저장이 끝난 것은 아니다.

## 남은 작업 순서

1. **검토본 통합 준비:** 선행 PR부터 Claude 교차 검토와 사용자 화면 확인. 의존 순서를 지켜 병합한다.
2. **DB 보류 중 화면 개발:** 수합 요청 작성·응답 양식과 학생 기록 입력의 사용성, 빈 화면·오류 복구·접근성을 보완한다. 합성 시나리오에서 먼저 검증하고 실제 자료 연결은 분리한다.
3. **DB 재개 후 실제 연결:** 통합 설계 [PR #12](https://github.com/EggPlayer88/daedong/pull/12) 확정 → 계정 보존/복구 점검 → 격리 검증 환경 적용 → 기존 계정·학교 소속 연결 → 일정·개인 업무 실사용 실증. SQL 확정은 Claude Web, 실제 적용과 main 병합은 사용자 담당이다. 두 실제 계정의 열람/충돌/승인 회수/소속 종료를 확인한다.
4. **수합 서버 전환:** 초안 비공개·상태 전이·접수·검토 권한을 서버에서 강제하고 파일·문서 초안을 연결한다.
5. **학생 자료 연결:** 담당·명부·작성자 권한·보존/삭제를 적용한 뒤 디지털윤리 수업 사이트와 연결한다.
6. **Claude·문서 통합:** 학교 지식의 근거·유효기간·학교 범위, 개인 비서와 문서 도구 계약을 구현한다. 시간표는 별도 재개 요청 후 진행한다.
7. **교사 파일럿·전국 운영 검증:** 홈 정보량·모바일 동선·접근성, 실제 사용성과 성능·복구·인계·반복 업무를 검증한다.

실제 연결에 필요한 검증 DB 설정과 기존 로그인 세션은 별도 준비 사항이다. 임의 계정 재생성이나 운영 DB 초기화로 대체하지 않았다.

## 판단해서 정한 것

1. **남은 보완을 우선 분류:** 완료본이 있어도 보완 의무가 가려지지 않게 한다. 현재판·완료판은 별도 표시한다. 변경 위치는 `workflows/collection-workbench.ts`다.
2. **진행표만 20부씩 표시:** 필터로 기존 상세·입력 상태와 완료본 집계가 바뀌지 않게 한다. 변경 위치는 `workflows/CollectionWorkbench.tsx`, `WorkflowPanel.tsx`다. 서버 페이지 조회나 대규모 전체 상세의 최적화까지 끝낸 것은 아니다.
3. **빠른 기록과 과거 근거 조회를 구분:** 기본은 선택 학생·현재 수업이며 본인 전체 기록에서 과거 수업까지 찾는다. 변경 위치는 `students/presentation.ts`, `StudentsPanel.tsx`다.
4. **근거 출력은 전체 원본 재확인:** 필터로 재검토 대상을 숨겨도 출력 검증은 유지한다. 내용이 바뀌면 다시 확인 후 내려받는다. 변경 위치는 `StudentsPanel.tsx`의 근거 보기·다운로드다.
5. **단계별 연결 유지:** 수합·학생은 합성 화면에만 두고 DB·시간표·Claude 연결은 후속 단계로 남긴다. 실제 서버로 전환할 때는 각 어댑터와 서버 계약을 검증한다.

개인 업무는 현재 학교·소속 단위다. 학교와 무관한 개인 공간, 전출 시 이관, 대규모 목록 페이지 처리, 실제 자료의 보존·삭제 정책은 아직 남아 있다.
