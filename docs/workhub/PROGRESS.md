# 업무혁신시스템 누적 진행 현황

최종 갱신: 2026-10-16 · PR #43 통합 검토 중 · `feat/workhub-hwpx-simple` 후속 후보

목표는 문서작성 AI·시간표를 제외한 기능을 실사용 가능한 수준으로 완성한 뒤 시범 공개하는 것이다. 기존 로그인과 회원 자료를 보존한다. 현재 Supabase·Vercel·GitHub를 개발·검증 환경으로 사용하며, SQL은 Claude 작성 → 검토 → 사용자 직접 적용 순서다. 실사용 확인은 사용자 요청에 따라 나중에 모아서 진행한다.

## 이번 작업

- 사용자 결정에 따라 신규 문서 수합과 새 업로드를 **HWPX 전용·최소 확인**으로 간소화한다. 담당자의 양식 등록·필요한 정보 입력·제출·현황·다운로드를 중심에 둔다. 기존 PDF 등 역사 자료의 읽기·다운로드는 유지한다.
- 기존 Supabase 비공개 직접 업로드와 `prepare`·`complete` 흐름을 유지하고, 기존 Vercel에서 호출할 `/api/collections/check-hwpx`를 준비했다. 로그인 확인 후 서버가 DB 지정 원본을 읽어 크기·해시·HWPX 기본 구조를 확인하는 코드다. ClamAV·심층 XML 검사·별도 서버는 이번 흐름에 필요하지 않다.
- 새 readiness와 서버 전용 claim/finish를 요구하도록 앱을 연결한다. 새 SQL·정책·배포가 없으면 준비 중으로 닫으며 기존 작업자 readiness로 우회하지 않는다. 파일·입력·기존 요청 번호를 보존해 결과가 불명확한 요청을 다시 확인한다.
- Claude에게 필요한 DB 변경을 [HWPX 전용 수합 R1S 요청서](42-hwpx-basic-collection-request.md)에 정리했다. SQL 확정본·운영 DB·Vercel 환경값·서버 키는 변경하지 않았다. **이 단계는 구현·자동 검증 완료이며 실제 수합 활성화 완료가 아니다.**
- PR #43은 열린 통합 후보로 Claude 검토를 기다린다. PR #44의 독립 검사 서버 배포 준비는 보류하며 이번 후보에 포함하지 않는다. 이번 후속 후보 브랜치는 `feat/workhub-hwpx-simple`이고 새 PR 번호는 아직 기재하지 않는다.
- HWPX 경계 파일·서버 API·권한/응답·클라이언트 복구·기존 파일 보존의 자동 검증을 진행한다. 전체 회귀 2,375건과 브라우저 37개 파일의 실행·필요한 수정 후 재검증을 마쳤다. [검증·인계](43-hwpx-basic-verification.md)에 실제 시험 범위와 한계를 기록했다.

## 보존한 2차 통합 이력

- main #25(`ebdc064`)에서 `chore/workhub-integration-r2`를 만들고 **#26~#42의 17개 PR을 원본 이력과 함께 통합**했다. 이전 1차 통합 19개 PR과 #24·#25도 보존한다. #3 운영 자동화와 #5 시간표 엔진은 제외했다.
- #42에 없던 #26~#29 학교 설정·진단·DB 설계 보완과 #31 R0·#39 R1 SQL을 별도로 합쳤다. 앱 코드는 자동 병합됐고 충돌은 진행 현황·시험 안내 두 문서에서 해결했다.
- R0 24파일·R1 24파일은 각각 원본 PR과 동일하다. 기존 인증·회원·확정 문서 자산과 메뉴 공개 범위를 보호하는 2차 통합 검사 및 실패 주입 시험 22건을 추가했다.
- 원본 R0/R1 전체 SQL 시험과 실제 작업자 연결 시험을 로컬 전용 PostgreSQL 17.6에서 이어서 실행하는 도구를 만들고 필수 CI에 연결했다. 운영 DB 접속이나 SQL 재실행은 하지 않는다.
- 통합본 검증 결과와 Claude 검토 요청은 [2차 통합 인계](integration-r2/README.md), [자동 검증 결과](integration-r2/verification.md)에 정리한다. 원본 PR을 닫거나 main에 병합하지 않았다.

## 배포와 개발 구분

**통합 PR 생성은 main 배포 완료가 아니다.** 이번 기록의 main 기준은 #25이고 PR #43은 열린 검토 후보다. 사용자가 통합 PR을 병합해야 앱 배포가 갱신된다. 원본 17개 PR을 하나씩 운영에 병합할 필요 없이 통합 후보를 검토할 수 있다. 이력 보존을 위해 Create a merge commit 방식으로 병합한다. HWPX 간소화는 #43을 기반으로 한 별도 후속 후보이며, #44의 별도 서버 구성은 활성화 대상에서 제외한다.

지정 Supabase는 `dhaoszbqtbofqftgjfyb`다. R0·R1-00~04 적용 결과는 사용자 제공 자료로 확인했다. R1-05/06 적용 보고는 없으며 현재 기존 R1의 `verification_missing`은 정상이다. **이제 기존 작업자 연결을 채워 여는 대신, R1S로 HWPX 기본 프로필을 별도로 준비한다.** 새 SQL이 없는 앱은 준비 중으로 남고, `allowUnscanned=true`만 게시해 열지 않는다. 서버 전용 환경값과 실제 배포 확인도 남았다. 이번 작업은 운영 DB나 외부 서비스 설정을 바꾸지 않았다.

화면과 서버 연결 코드가 있다는 사실을 **문서 수합 실사용 완료 또는 전체 목표 90% 달성으로 계산하지 않는다.** 수합 미리보기는 새로고침하면 초기화되며 미확정 입력의 복구는 현재 탭 메모리 범위다. 서버에 접수된 자료는 DB 기준이다. 새 최소 확인 경로의 복구에는 R1S 임대·멱등 SQL이 필요하며, 아직 실제 DB와 왕복한 것으로 기록하지 않는다. 자동 파일 정리를 켜지 않으므로 미첨부 파일이 보존일 경과만으로 자동 삭제되지는 않는다.

## 검증 범위와 다음 순서

2차 통합 당시에는 전체 브라우저 36개 파일을 다시 실행했다. 로컬 PostgreSQL 17.6의 원본 SQL 시험과 실제 작업자 코드를 대조했지만, PostgREST/Storage HTTP는 합성 서버이며 실제 Supabase의 HTTP·Storage 검증은 아니다. 당시 ClamAV는 소켓 대역 시험으로 실제 엔진/서명 DB를 확인한 것이 아니다. **이 수치와 범위는 PR #43 통합 검증 기록**이며 [자동 검증 결과](integration-r2/verification.md)를 따른다. 후속 #44의 컨테이너 배포 준비는 별도 이력으로 보존하고 활성화는 보류한다.

이번 HWPX 간소화는 전체 회귀 2,375건, 브라우저 37개 파일의 실행과 수정 대상 재검증, 타입 검사와 두 앱 빌드를 통과했다. 세부 경과는 [검증·인계](43-hwpx-basic-verification.md)를 따른다. 새 RPC는 요청 계약과 대역으로 확인하며, Claude가 실제 R1S SQL을 작성한 뒤 SQL 응답과 다시 대조해야 한다. 실제 서버 환경값·Supabase Auth/PostgREST/Storage·학교 문서 호환성은 아직 확인하지 않았다. [R1S 요청서](42-hwpx-basic-collection-request.md)에 자동 SQL 시험과 실제 환경에서 남은 확인을 구분했다.

#34 화면 두 결함은 #41에서 수정돼 포함됐다. #27 학교 설정 초안의 중/고 학년 범위와 동일 학년/반 중복 검사는 실제 학교 설정 저장 연결 전 보완한다. 전체 미래 DB 설계의 F1~F9와 R1 SQL 리뷰의 해결된 F1~F7은 서로 다른 범위다.

1. PR #43과 HWPX 후속 후보를 Claude가 검토한다. #41 입력·기존 요청 번호 보존, 통합 이력·기존 자료 보존, 새 기본 확인 API의 권한·복구 계약을 확인한다. 필요한 보완과 동일 최신 커밋의 CI/미리보기 확인 후 사용자가 병합한다.
2. main에서 17개 원본 SHA 포함을 확인한 뒤 남아 있는 원본 PR을 정리한다. 보류 #3/#5는 유지한다.
3. Claude가 R1S 증분 SQL을 작성·시험하고 Codex가 재검토한다. 계란님이 지문을 저장하고 **프로필 비활성 상태의 SQL**부터 적용한다. 기존 R1-00~04를 다시 실행하거나 R1-05/06을 그대로 적용하지 않는다.
4. 앱/API의 배포와 서버 전용 환경값을 준비한다. 서버 키를 브라우저에 넣지 않으며 실제 준비가 확인되기 전에는 프로필을 열지 않는다. 이후 사용자/Claude가 학교 정책·배포 확인값을 확정하고 학교별 기본 프로필을 활성화한다. 독립 서버·ClamAV·정리 스케줄러는 배포하지 않는다.
5. 실제 Auth/PostgREST·Storage·HWPX 업로드/최소 확인/다운로드·공동 제출/정정·ZIP·모바일·다중 교사, 일정/업무 저장과 기존 기능 확인을 모아서 진행한다. 문제 발생 시 새 쓰기를 비파괴 중지하고 입력·기존 요청 번호를 보존한다.
6. 학생 기록 실제 연결, 메신저·학교 자료·Claude·알림·관리 기능을 순차 구축한다. 문서작성 AI·시간표·보류한 운영 자동화는 계속 보류한다.
