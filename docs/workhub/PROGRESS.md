# 업무혁신시스템 누적 진행 현황

최종 갱신: 2026-10-16. 사용자 승인에 따라 **시간표를 제외한 사이트 전체 시범 범위**를 한 앱 통합 후보로 구축했다. 문서 AI 보류는 해제됐고 별도 검사기 서버·운영 자동화는 계속 제외한다. 실사용 시험은 마지막에 모아서 한다.

## 이번 작업

- 학교 관리, 협업, 일정 일괄 가져오기, HWPX 수합 운영, 문서함·질문형 양식, 학교 지식, Claude 비서, 메시지·알림, 수업·학생·평가·CSV, 인계/새 학년도의 화면·도메인·서버 연결 계약을 구축했다.
- 새 모듈을 공통 업무실의 11개 메뉴와 모바일 동선에 연결하고 필요한 시점에만 코드를 불러온다. 학교/계정 범위와 입력·요청 번호 보존, 오류 격리를 공통화했다.
- 실제 HWPX ZIP/XML을 읽는 서버의 기본 확인·양식 채우기·지식 추출을 준비했다. 기존 평가계획서 엔진은 변경하지 않고 새 탭으로 연결했다.
- [전체 14묶음 상태표](pilot-completion/README.md), [Claude SQL 요청](pilot-completion/sql-handoff.md), [검증 결과](pilot-completion/verification.md), [최종 사용 확인](pilot-completion/activation-checklist.md)을 기준 문서로 정리한다.

## 남은 작업과 순서

1. **Claude 코드 검토**: 이번 통합 앱과 계약을 검토하고 같은 최종 커밋의 자동 검사·미리보기를 확인한다. 계획상의 #47은 실제로 Claude R1S SQL PR이므로 앱 PR 번호와 구분한다.
2. **R1S 재검토**: #47 기준 `884056f`의 현재 앱 대조는 410/411. 짧은 다운로드의 RESULT_UNKNOWN과 L44의 rejected 기대 차이, 셸 CRLF 실행성 문제를 Claude와 정리한다. [SQL 요청 5절](pilot-completion/sql-handoff.md)을 참고한다.
3. **증분 DB 구축**: 학교 관리 → 협업/일정 → 메시지/문서/지식 → 수업/평가 → AI → 홈/수합 운영/인계 순으로 Claude 작성, 사용자 적용. 각 단계는 기존 자료 지문·실제 출력 parser·권한/동시성 시험을 통과해야 한다.
4. **서비스 연결**: 사용자 승인 환경값과 정책을 설정한다. 실제 Storage·PostgREST·Claude 연결을 확인하기 전 기능을 임의 활성화하지 않는다.
5. **모아서 실사용 확인**: 기존 계정/자료 보존, 관리자·교사·다른 학교, 파일 업로드/최종 제출, 모바일, 실문서 서식, 학생 근거·AI 답변 품질을 함께 확인한다.
6. **시범 공개**: 위 확인과 중대 결함 해결 후 사용자가 공개 범위를 정한다. 현재 앱 코드량과 자동 시험 건수로 전체 실사용 완성률 90%를 주장하지 않는다.

## 적용과 롤백

새 기능 RPC가 없어도 기존 일정/개인 업무/로그인을 막지 않게 구성했다. 준비되지 않은 항목은 빈 목록·0건으로 위장하지 않는다. 앱 배포와 DB 활성화는 별도 기록하며, DB 변경은 Git 되돌리기로 취소되지 않는다. 장애시 새 쓰기 비활성화와 기존 결과/자료 보존을 우선한다.
