- [구현·검증·판단·Claude 재검토 인계](30-collection-followup.md).
- PR #30을 기준으로 만든 후속 브랜치다. #26~#29 및 Claude SQL #31을 합친 통합본은 아니다.

## 배포와 개발 구분

2026-10-14 확인 시 main은 #25까지(`ebdc064`)다. #26(내 업무 분리), #27(학교 설정 준비), #28(DB 일부 제약), #29(연결 조사), #30(파일형 수합), #31(Claude SQL 초안)은 열려 있다. #23에 포함된 과거 PR도 일부 열려 있으므로 열린 PR 수와 미통합 기능 수는 같지 않다.

현재 지정 Supabase는 `dhaoszbqtbofqftgjfyb`다. #31 최초 검토에서는 로컬 PostgreSQL 17.6의 기존 128개 대응 항목과 추가 승인 회수 경합 1개를 확인하고, 화면/SQL 대상 규칙과 시험 도구의 보완점 3건을 전달했다. 후속 SQL 커밋은 별도 재검토해야 하며, 이번 수합 작업은 실제 DB 적용 여부를 확인하거나 DB에 쓰지 않았다.

**파일형 수합의 화면·로컬 동작·오류 처리와 사용성을 보완한 단계다. 실제 교사 간 서버 파일 수합이나 전체 목표 90% 달성으로 계산하지 않는다.** 새로고침하면 파일형 수합은 초기화된다.

## 검증과 다음 순서

최종 npm **1,322건**, 두 앱 빌드/타입 검사 통과. 브라우저 33개 파일의 시나리오 모두 최종 통과했다. 첫 전체 실행은 30/33이었으며 대상 선택 시험 2개를 수정·재검증했고, 외관 시험 1개는 전체 캡처의 임시 화면 폭 변경을 확인해 뷰포트 캡처로 수정 후 13/13 통과했다. 상세 실행 이력과 재검토 항목은 [이번 인계서](30-collection-followup.md)를 따른다.

- 실제 DB/Storage·운영 자료·Google 로그인 종단 검증은 별도다.
- 이번 작업에서는 인증·메뉴 공개·SQL·HWPX 엔진/양식·규정·외부 설정을 변경하지 않았다.

1. Claude의 #31 수정 SQL을 재검토하고, 사용자가 학년도·학기 값을 확인하여 현재 Supabase에 적용한다.
2. 기존 Vercel에서 학교 연결 → 일정·업무 저장/재조회와 기존 계정 보존을 확인한다.
3. #26~#30 및 수합 후속 PR을 검토 결과에 따라 통합한다. 공통 파일 변경을 합칠 때 main merge 후 회귀 시험한다.
4. 수합/파일 서버 계약·Storage·실물 검사·접수 복구·임시 파일 회수를 연결하고 실제 여러 계정으로 검증한다.
5. 학생 기록 실제 연결, 메신저·학교 자료·Claude·알림·관리·운영 검증 후 시범 공개를 판단한다.
