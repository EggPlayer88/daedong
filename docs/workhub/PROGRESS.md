# 업무혁신시스템 누적 진행 현황

최종 갱신: 2026-10-15 · 서버 파일 검사·임시 파일 정리 처리 코어

목표는 문서작성 AI·시간표를 제외한 기능을 실사용 가능한 수준으로 완성한 뒤 시범 공개하는 것이다. 사용자 승인으로 **DB 조사·준비를 재개**했다. SQL은 Claude 작성 → 검토 → 사용자 직접 적용 순서다. 현재 Supabase·Vercel·GitHub를 개발·검증 환경으로 사용하며, 별도 Supabase 프로젝트를 요구하지 않는다. 기존 로그인과 회원 자료는 보존한다.

## 이번 작업

- PR #36의 전체 ZIP 다운로드에 이어 서버 파일 검사·검사 결과 접수·임시 파일 정리의 독립 처리 코어를 구현했다. 브랜치는 `feat/workhub-file-workers`, 기준은 `feat/workhub-collection-export`다.
- HWPX·DOCX·XLSX·PPTX 컨테이너의 실제 압축 확장량·CRC·XML·필수 파트·관계를 검사한다. PDF/HWP 전용 파서는 아직 없으며, 기존 HWPX 양식 6개 중 스크립트가 포함된 3개는 현재 엄격 프로필에서 거부된다. 악성 판정이 아닌 호환성 제한이다.
- 원문 크기·SHA-256·실물 식별·정책·작업 임대를 검사 전후 확인한다. 구조 검사와 악성 검사를 분리하고, 스캐너 미연결/오류를 `clean`으로 처리하지 않는다. 동일 키/증거로 결과 접수를 재확인한다.
- 임시 파일 정리는 기본값이 후보 조회다. 저장 초안·과거 제출·양식 참조, hold, 진행 작업, 복구 요청을 보호하고, 실제 삭제 부재 확인과 원장 접수증을 구분한다. DB 영구 차단·Storage 어댑터는 후속이다.
- [이번 구현·검토 인계](36-collection-file-workers.md), [실행/지원 범위](../../workers/collection_files/README.md). SQL은 기존 [R1 Claude 요청서](32-collection-server-sql-request.md)를 그대로 사용하며 내부 포트를 확정 SQL에 맞춰 연결할 예정이다.
- 실제 DB·Storage 호출, 파일 삭제, SQL 변경, 외부 설정, 준비 상태 활성화는 하지 않았다. 화면과 기존 인증 로직도 바꾸지 않았다.

## 배포와 개발 구분

2026-10-15 이번 작업에서 재확인한 main은 #25까지(`ebdc064`)이며 #36(전체 ZIP, `09dd890`)은 열려 있다. 앞선 확인에서 #26(내 업무 분리), #27(학교 설정 준비), #28(DB 일부 제약), #29(연결 조사), #30(파일형 수합), #31(Claude SQL), #32(수합 사용성), #33(파일 수명), #34(수합 서버 연결), #35(공동 제출·관리)도 열려 있었다. #23에 포함된 과거 PR도 일부 열려 있으므로 열린 PR 수와 미통합 기능 수는 같지 않다. SQL의 사용자 적용과 GitHub PR 병합은 별도다.

현재 지정 Supabase는 `dhaoszbqtbofqftgjfyb`다. 사용자 실행 결과로 B01/B02, 초기 설정 8개 검증 및 전후 구조 지문 7개 일치를 확인했고, 두 회원 표는 각각 18행이다. 사용자가 대동여자중학교 표시·업무실 진입을 확인했다. 자료 값 전체와 Storage 파일 본문 보존을 이 비교만으로 증명하지 않는다. 이번 코드 작업이 DB에 쓰거나 SQL을 바꾼 것은 아니다.

**앱의 서버 연결 코드와 서버 처리 코어를 준비했지만, 수합용 DB·Storage·서버 검사기 적용이 완료된 것은 아니다. 실제 교사 간 수합이나 전체 목표 90% 달성으로 계산하지 않는다.** 미리보기 자료는 여전히 새로고침하면 초기화된다. 연결 화면의 미저장 입력과 결과 미확정 요청 복구도 현재 탭 메모리 범위다. 서버 검사 결과의 재전송도 현재 프로세스·유효 임대 범위이며 재시작/만료 복구는 후속이다. 서버에 확정 접수된 자료의 영속성은 R1 적용 후 별도로 검증한다.

## 검증과 다음 순서

최종 npm **1,634건 전부 통과**했다(PR #36의 1,471건 대비 **163건 추가**: 컨테이너 검사 80, 검증 처리 35, 정리 처리 48). 실제 압축/XML 파싱과 합성 원장/Storage/스캐너의 응답 유실·변경·참조·임대 경계를 실행했다. 화면·앱 빌드 경로는 변경하지 않아 이번에는 브라우저/빌드를 재실행하지 않았다.

직전 #36에서는 전체 Chromium **35개 검사 파일**, 연결 수합 **29개**, ZIP **13개 시나리오**, 두 앱 빌드·타입 검사·통합 이력/보호 경계 검사가 통과했다. PR #34의 서버 계약과 SQL 요청서는 이번에도 변경하지 않았다. [ZIP 인계](35-collection-server-export.md), [공동 제출·관리 인계](34-collection-management.md), [서버 연결 인계](33-collection-server-connection.md)에 이전 검증을 보존한다.

- 이번 자동 시험은 로컬 파서와 합성 포트 기준이다. 실제 Supabase/PostgREST/Storage의 원자성·권한·물리 삭제·악성 검사기 탐지·Google 로그인 종단 검증은 별도다.
- 이번 작업에서는 인증 로직·일반 교사 공개 범위·SQL·HWPX 엔진/양식·규정·외부 설정을 변경하지 않았다. 자료 수합은 슈퍼관리자 업무실에서만 접근한다.

1. Claude가 R1 SQL·Storage 권한·검증 job/봉인 계약·비파괴 중지 절차를 작성한다. Codex가 기존 자료 보존과 앱 계약을 교차 검토한 뒤 사용자가 적용한다.
2. 준비한 파일 처리 코어를 확정 SQL·실제 Storage·승인 악성 검사기에 연결한다. PDF/HWP·정상 HWPX 지원, 실행 자원 제한, 임대 만료/재시작 복구를 보완하고 자동 통합 시험 후 준비 상태를 켠다. SQL만 적용하고 완료로 표시하지 않는다.
3. ZIP·공동 단위·철회/정정의 실제 서버 연결을 검증한다. 현재 ZIP은 원자적 서버 스냅샷이 아니며, 상세 대조와 파일별 접근 재확인 범위다. #26~#36 및 이번 후속 PR은 검토 결과에 따라 단계적으로 통합한다.
4. 학생 기록 실제 연결, 메신저·학교 자료·Claude·알림·관리 기능을 순차 구축한다.
5. 사용자 요청에 따라 일정·업무 저장/수정/재로그인, 기존 평가계획서 다운로드, 수합 다중 교사·모바일 시험은 이후 통합 실사용 확인으로 모은다. 문서작성 AI·시간표는 계속 보류한다.
