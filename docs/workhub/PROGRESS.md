# 업무혁신시스템 누적 진행 현황

최종 갱신: 2026-10-15 · 수합 R1 서버 연결·검사기

목표는 문서작성 AI·시간표를 제외한 기능을 실사용 가능한 수준으로 완성한 뒤 시범 공개하는 것이다. 기존 로그인과 회원 자료를 보존한다. 현재 Supabase·Vercel·GitHub를 개발·검증 환경으로 사용하며, SQL은 Claude 작성 → 검토 → 사용자 직접 적용 순서다. 실사용 확인은 사용자 요청에 따라 나중에 모아서 진행한다.

## 이번 작업

- 사용자에게 R1-00~04 적용 완료와 전후 보존 지문 일치, 기존 기능 정상 확인 결과를 전달받았다. 승인 후 바뀐 정책 권한 사전 점검도 재검토했다. 최신 SQL `f4754d5`와 문서 보완 `2d38c5b`를 기준으로 연결했다.
- 서버에서 실제 Supabase RPC·비공개 Storage API를 부르는 전송 코드와 R1 검사/정리 실행기를 구현했다. 기존 앱 계약은 맞아 프런트엔드를 불필요하게 변경하지 않았다.
- 기존 문서 파서를 별도 프로세스에서 실행하며 시간·Linux CPU/메모리를 제한하고 자식의 서버 키 환경을 제거했다. ClamAV Unix 소켓 연결·서명 시각·자체시험·오류 처리를 추가했다.
- 검사 전후 정책·실물·임대를 확인하고, 봉인 응답 유실은 같은 인자만 재전송한다. 실패는 SQL의 유한 재시도·임대 만료 재인수로 처리한다. 정리는 객체 정체성과 첨부 여부를 확인하고 Storage API로 삭제한 뒤 실물 부재를 재확인한다.
- 서버 실행 CLI·환경값 예시·비관리자 컨테이너 준비와 [배포·Claude 인계](40-collection-r1-connection.md)를 정리했다. 기본 실행은 로컬 자체 점검으로 외부 요청을 하지 않는다.
- 전체 회귀 **2,198건**(새 시험 103건 포함), 실제 로컬 PostgreSQL 17.6 R1 SQL과 작업자 통합 **23건**, Windows·Ubuntu WSL 런타임 **각 39건**을 통과했다. 실제 Supabase/ClamAV/컨테이너 배포 검증으로 확대 해석하지 않는다.

## 배포와 개발 구분

현재 main은 #25까지(`ebdc064`)인 상태를 기준으로 개발했다. 이번 브랜치 `feat/workhub-r1-worker-connection`은 #41(`fix/workhub-collection-recovery`, `dbfe57c`)을 잇는다. 앱 체인은 #26~#38 → #40 문서 호환성 → #41 화면 복구이고, Claude의 #31 R0·#39 R1 SQL은 별도 브랜치다. 병합은 사용자가 한다. 열려 있는 PR 수를 남은 기능 수로 계산하지 않는다.

지정 Supabase는 `dhaoszbqtbofqftgjfyb`다. R1 적용 결과는 사용자 제공 자료로 확인했으며, 이번 개발 중 운영 DB에 직접 접속/SQL 실행하지 않았다. R1-05/06은 미적용이라 `verification_missing`이 정상이다. 코드 병합만으로 검사기가 가동되지 않는다. 작업자 배포와 서버 비밀값·실제 ClamAV·승인 정책이 남았다.

화면과 서버 연결 코드가 있다는 사실을 **문서 수합 실사용 완료 또는 전체 목표 90% 달성으로 계산하지 않는다.** 수합 미리보기는 새로고침하면 초기화되며 미확정 입력의 복구는 현재 탭 메모리 범위다. 서버에 접수된 자료는 DB 기준이고, 검사 작업자의 재시작 복구는 R1 임대/멱등 계약으로 처리한다.

## 검증과 다음 순서

이번 실제 SQL 통합 시험은 독립 로컬 PostgreSQL 17.6과 합성 HTTP PostgREST/Storage를 사용했다. 정상 검사·응답 유실·감사 중복 방지·해시 오류·임대 만료·중지/재개·heartbeat 만료·정리 실물 고정/보존을 확인했다. ClamAV는 소켓 대역 시험으로 실제 엔진/서명 DB를 확인한 것이 아니다. 컨테이너 빌드도 아직 하지 않았다.

이전 #41의 브라우저 35개 파일/수합 서버 38시나리오 검증과 #40의 공개 PDF 8/8·HWP 8/30 통과(22개 미지원)는 각 인계 문서에 보존한다. 이번에 프런트엔드를 변경하지 않아 브라우저 전체를 불필요하게 반복하지 않았으며 앱 빌드를 다시 확인한다.

1. 이번 서버 연결 PR과 선행 앱·SQL PR을 Claude 검토 후 단계적으로 통합한다.
2. 서버 실행 위치·비밀값·ClamAV·스케줄러를 준비한다. 사용자/Claude가 R1-06 정책과 R1-05 학교/작업자 연결을 적용한 뒤 준비 상태를 활성화한다.
3. 실제 PostgREST·Storage·파일 검사/다운로드·수합·공동 제출/정정·ZIP·모바일·다중 교사, 일정/업무 저장과 기존 기능 확인을 모아서 진행한다.
4. 학생 기록 실제 연결, 메신저·학교 자료·Claude·알림·관리 기능을 순차 구축한다. 문서작성 AI·시간표는 계속 보류한다.
