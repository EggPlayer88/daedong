최종 갱신: 2026-10-15 · 문서 수합 미저장 파일 회수·저장본 보호

목표는 문서작성 AI·시간표를 제외한 기능을 실사용 가능한 수준으로 완성한 뒤 시범 공개하는 것이다. 사용자 승인으로 **DB 조사·준비를 재개**했다. SQL은 Claude 작성 → 검토 → 사용자 직접 적용 순서다. 현재 Supabase·Vercel·GitHub를 개발·검증 환경으로 사용하며, 별도 Supabase 프로젝트를 요구하지 않는다. 기존 로그인과 회원 자료는 보존한다.

## 이번 작업

- 선택 후 제거·교체·편집 취소 시 해당 편집에서 만든 미저장 파일 실물 회수. 반복 선택으로 임시 용량이 쌓이는 문제 보완.
- 한 번 저장한 양식·공동 초안·제출판·과거 멱등 접수 결과의 원문 보호. 오류·충돌 때 선택 유지.
- 사용자 R0 적용 결과를 진행 기록에 반영. 실사용 시험은 사용자 요청에 따라 이후 통합 시험으로 모은다.
- [구현·검증·판단·Claude 재검토 인계](31-file-lifecycle.md).
- PR #32를 기준으로 만든 후속 브랜치다. #26~#29 및 Claude SQL #31을 합친 통합본은 아니다.

## 배포와 개발 구분

2026-10-15 확인 시 main은 #25까지(`ebdc064`)다. #26(내 업무 분리), #27(학교 설정 준비), #28(DB 일부 제약), #29(연결 조사), #30(파일형 수합), #31(Claude SQL), #32(수합 사용성)은 열려 있다. #23에 포함된 과거 PR도 일부 열려 있으므로 열린 PR 수와 미통합 기능 수는 같지 않다. SQL의 사용자 적용과 GitHub PR 병합은 별도다.

현재 지정 Supabase는 `dhaoszbqtbofqftgjfyb`다. 사용자 실행 결과로 B01/B02, 초기 설정 8개 검증 및 전후 구조 지문 7개 일치를 확인했고, 두 회원 표는 각각 18행이다. 사용자가 대동여자중학교 표시·업무실 진입을 확인했다. 자료 값 전체와 Storage 파일 본문 보존을 이 비교만으로 증명하지 않는다. 이번 코드 작업이 DB에 쓰거나 SQL을 바꾼 것은 아니다.

**파일형 수합의 화면·로컬 동작·오류 처리와 사용성을 보완한 단계다. 실제 교사 간 서버 파일 수합이나 전체 목표 90% 달성으로 계산하지 않는다.** 새로고침하면 파일형 수합은 초기화된다.

## 검증과 다음 순서

최종 npm **1,331건**, 두 앱 빌드/타입 검사 통과. 신규 수명 시나리오 9개를 추가했다. Chromium 전체 회귀 **33개 파일 모두 통과**했으며 파일 선택기 19개 시나리오는 개발 StrictMode에서 확인했다. 브라우저 결과와 재검토 항목은 [이번 인계서](31-file-lifecycle.md)를 따른다. 이전 1,322건 및 브라우저 실행 이력은 [지난 인계서](30-collection-followup.md)에 보존한다.

- 실제 DB/Storage·운영 자료·Google 로그인 종단 검증은 별도다.
- 이번 작업에서는 인증·메뉴 공개·SQL·HWPX 엔진/양식·규정·외부 설정을 변경하지 않았다.

1. 수합/파일 서버 계약·비동기 저장 경계·Storage·실물 검사·접수 복구·서버 임시 파일 수명 관리를 준비한다.
2. 필요한 후속 SQL은 Claude 작성 → 검토 → 사용자 적용 후 서버에 연결한다.
3. #26~#32 및 이번 후속 PR을 검토 결과에 따라 통합한다. 공통 파일 변경을 합칠 때 main merge 후 회귀 시험한다.
4. 학생 기록 실제 연결, 메신저·학교 자료·Claude·알림·관리 기능을 순차 구축한다.
5. 사용자 요청에 따라 일정·업무 저장/수정/재로그인, 기존 평가계획서 다운로드, 수합 다중 교사·모바일 시험은 이후 통합 실사용 확인으로 모은다.
