# 업무혁신시스템 누적 진행 현황

최종 갱신: 2026-10-15 · 수합 공동 제출·철회·정정·제출 이력

목표는 문서작성 AI·시간표를 제외한 기능을 실사용 가능한 수준으로 완성한 뒤 시범 공개하는 것이다. 사용자 승인으로 **DB 조사·준비를 재개**했다. SQL은 Claude 작성 → 검토 → 사용자 직접 적용 순서다. 현재 Supabase·Vercel·GitHub를 개발·검증 환경으로 사용하며, 별도 Supabase 프로젝트를 요구하지 않는다. 기존 로그인과 회원 자료는 보존한다.

## 이번 작업

- PR #34 검토와 R1 SQL 작성을 함께 부탁하는 전달문을 바탕화면에 작성했다. #34의 GitHub 자동 검사·Vercel 미리보기 성공을 확인했다.
- 개인별 제출과 공동 제출 단위를 함께 설정하고 책임 교사·공동 작성자를 지정하는 화면을 구현했다.
- 기존 서버 명령으로 제출 철회·단위별 정정 기간을 관리한다. 현재 제출과 완료본을 나누고 과거판·검토·보완·철회 이력을 20판씩 표시한다.
- 검토/철회 대상판을 고정하여 이전 의견이 새 제출에 적용되지 않게 했다. 철회 후 재제출 사유 누락, 상세 조회 실패 시 입력 닫기 불가, 명부 밖 검토자 이름 표시를 보완했다.
- [이번 구현·검토 인계](34-collection-management.md). SQL은 기존 [R1 Claude 요청서](32-collection-server-sql-request.md)의 계약을 그대로 사용한다.
- PR #34(`feat/workhub-collection-server`) 기준 `feat/workhub-collection-management` 후속 브랜치다. 실제 DB/Storage 적용과 파일 검사기 구현·배포는 아직 하지 않았다.

## 배포와 개발 구분

2026-10-15 확인 시 main은 #25까지(`ebdc064`)다. #26(내 업무 분리), #27(학교 설정 준비), #28(DB 일부 제약), #29(연결 조사), #30(파일형 수합), #31(Claude SQL), #32(수합 사용성), #33(파일 수명), #34(수합 서버 연결)은 열려 있다. #23에 포함된 과거 PR도 일부 열려 있으므로 열린 PR 수와 미통합 기능 수는 같지 않다. SQL의 사용자 적용과 GitHub PR 병합은 별도다.

현재 지정 Supabase는 `dhaoszbqtbofqftgjfyb`다. 사용자 실행 결과로 B01/B02, 초기 설정 8개 검증 및 전후 구조 지문 7개 일치를 확인했고, 두 회원 표는 각각 18행이다. 사용자가 대동여자중학교 표시·업무실 진입을 확인했다. 자료 값 전체와 Storage 파일 본문 보존을 이 비교만으로 증명하지 않는다. 이번 코드 작업이 DB에 쓰거나 SQL을 바꾼 것은 아니다.

**이번에는 실제 서버를 호출할 앱 코드까지 준비했지만, 수합용 DB·Storage·서버 검사기 적용이 완료된 것은 아니다. 실제 교사 간 수합이나 전체 목표 90% 달성으로 계산하지 않는다.** 미리보기 자료는 여전히 새로고침하면 초기화된다. 연결 화면의 미저장 입력과 결과 미확정 요청 복구도 현재 탭 메모리 범위다. 서버에 확정 접수된 자료의 영속성은 R1 적용 후 별도로 검증한다.

## 검증과 다음 순서

최종 npm **1,431건 전부 통과**했다(PR #34의 1,396건 대비 35건 추가). Chromium 전체 **34개 검사 파일 통과**, 그중 수합 연결은 **29개 시나리오 통과**(이전 14개 대비 15개 추가). 두 앱 빌드·타입 검사·통합 이력/보호 경계 검사도 통과했다. PR #34의 서버 계약과 SQL 요청서는 변경하지 않았다. 이전 작업의 검증 이력은 [서버 연결 인계](33-collection-server-connection.md), [파일 수명 인계](31-file-lifecycle.md)에 보존한다.

- 위 자동 시험은 합성 RPC 응답·파일과 로컬 Chromium 기준이다. 실제 Supabase/PostgREST/Storage·운영 자료·Google 로그인 종단 검증은 별도다.
- 이번 작업에서는 인증 로직·일반 교사 공개 범위·SQL·HWPX 엔진/양식·규정·외부 설정을 변경하지 않았다. 자료 수합은 슈퍼관리자 업무실에서만 접근한다.

1. Claude가 R1 SQL·Storage 권한·검증 job/봉인 계약·비파괴 중지 절차를 작성한다. Codex가 기존 자료 보존과 앱 계약을 교차 검토한 뒤 사용자가 적용한다.
2. 서버 파일 검사 작업자·만료/회수 처리를 구현하고, 실제 Storage와 PostgREST 자동 시험을 진행한다. SQL만 적용하고 파일 검증 준비를 완료로 표시하지 않는다.
3. 전체 ZIP 다운로드의 서버 원본·권한·완전성 계약과 화면을 연결한다. 공동 단위·철회/정정은 R1 적용 후 실제 서버에서도 검증한다. #26~#34 및 이번 후속 PR은 검토 결과에 따라 단계적으로 통합한다.
4. 학생 기록 실제 연결, 메신저·학교 자료·Claude·알림·관리 기능을 순차 구축한다.
5. 사용자 요청에 따라 일정·업무 저장/수정/재로그인, 기존 평가계획서 다운로드, 수합 다중 교사·모바일 시험은 이후 통합 실사용 확인으로 모은다. 문서작성 AI·시간표는 계속 보류한다.
