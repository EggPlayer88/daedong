# 업무혁신시스템 누적 진행 현황

최종 갱신: 2026-10-13 · 11차 개발 · `feat/workhub-calendar-import` (기준 PR #17)

목표는 **문서작성 AI·시간표를 제외한 기능을 완성한 뒤 시범 공개**하는 것이다. 구현·합성 검증·실제 서버 연결·운영 공개를 구분하며 테스트 수를 완성률로 환산하지 않는다.

## 이번 작업 — 11차 개발

- **시트 일정 입력:** 표 붙여넣기·UTF-8 CSV/TSV·열 연결·날짜/시간/누락/중복 검사·20행씩 검토를 구현했다.
- 정상 행은 기존 편집기의 나만 보기 초안으로 연결한다. 교사가 내용·공유 대상·홈 추천 대상을 확인해 한 행씩 등록한다.
- 읽기 취소·늦은 응답 폐기·기존 후보 재비교·조회 실패 보호·부분 등록 유지·기존 저장 응답 유실/같은 요청 재확인을 검증했다.
- 원본을 읽거나 검사하는 것만으로 저장하지 않는다. 첫 저장 후 원본/열 연결을 고정하며 종료할 때 미등록 행이 사라짐을 안내한다.
- **DB 연결 준비 재개:** 기존 제안 001~004와 통합 설계의 스키마·계정·기간·RPC 차이, 기존 회원/파일 보존·적용 분기·복구 절차를 정리했다.
- **시범 공개 계획:** 문서 AI·시간표 외의 전체 기능을 P01~P11 실제 과제와 증거로 나눴다. 일반 파일·Claude 상담/개인 비서·평가·알림·인계·운영도 남은 범위에 포함했다.
- SQL 확정은 Claude Web, 실제 실행과 main 병합은 사용자 담당이다. SQL·인증·회원·권한·보호 자산·비용·외부 설정·운영 공개 범위는 변경하지 않았다.
- 바탕화면 `GPT작업`에 11차 합성 HTML·검증 이미지/JSON·진행 보고·시범 공개 계획·DB 인계를 저장한다.

## 누적 진행

| 영역 | 구현·검증 상태 | 실제 서버·운영 상태 |
|---|---|---|
| 사이트 기본 구조 | 공통 셸·메뉴·학교 맥락·주소·모바일·키보드·오류 설명·편집 보호·업무 찾기 | main 직접 변경 없음, 기존 superadmin 노출 유지 |
| 로그인·회원 | 공유 인증 재사용·회원 보존 회귀·읽기 진단 | 실제 OAuth·신축 학교 연결 검증 남음 |
| 학교·소속·DB | 기반 제안·격리 시험, 통합 목표와 차이/전환/보존/복구 인계 | 통합 확정 SQL·검증 환경 적용·기존 회원 연결 남음 |

| 홈·내 업무 | 관련 일정·7일 요약·기한별 할 일·수합 요약·원본 이동·20개 표시, 일정/할 일 서버 어댑터 | 통합 DB 대응·실제 계정 시험 남음. 수합 홈은 합성 |

| 학생·수업 기록 | 합성 명부/담당·본인 관찰·정정·철회·활동 연결·필터·근거 출력·페이지·복구 | 실제 명부/서버·상담·루브릭/평가·디지털윤리 CSV·보존/삭제 남음 |
| 학교 자료·Claude | 청사진·통합 DB/도구 계약, Claude 사용 전제 | 자료 게시/검색·출처·상담·비서·기억·실제 호출 미구현 |
| 업무 운영 | 공통 상태/오류/연결 진단 기반 | 업무분장·협조·알림·문의·학기 전환·실행 인계·관리자/복구 화면 남음 |
| 문서작성 AI·시간표 | 기존 코드·검토 기록·보호 자산 보존 | 이번 신축 시범 공개 완료 범위에서 제외 |
| 전국 서비스 | 다학교 경계 설계와 일부 격리 시험 | 구형 API/Storage 격리·학교별 정책·부하·복구·학교급 현장 검증 남음 |

수합·학생은 현재 합성 미리보기에 연결한다. 실제 연결 메뉴는 오늘·일정·내 업무다. 시트 입력 경로가 추가됐어도 실제 DB 연결이나 전체 시트 전환이 완료된 것은 아니다. 상세 상태표는 [시범 공개 계획](17-pilot-release-plan.md) 2절을 따른다.

## 남은 작업 순서

1. **검토본 통합:** 선행 PR부터 Claude 교차검토·사용자 화면 확인 후 병합한다.
2. **실제 DB 기반:** [DB 인계](16-pilot-db-activation.md)에 따라 Claude가 통합 B00~B02/R0 SQL·호환표·검증/복구를 확정한다. 사용자가 격리 환경 조사·회원/파일 복원 확인·확정 SQL 적용을 수행한 뒤 Codex가 실제 계정 왕복을 검증한다.
3. **일정·업무 실사용:** 학교/기간/담당·업무분장·협조, 안정 시트 원장·변경 대조·기준 전환과 홈을 연결한다.
4. **공통 파일·수합:** 업로드/다운로드·파일 권한·원자 접수·공동 작성·제출/검토·완료본·실패 재개를 구현한다.
5. **학생·수업·평가:** 실제 명부/수강/담당·관찰/상담·평가와 디지털윤리 CSV를 연결하고 근거/정정/삭제/출력을 검증한다.
6. **학교 지식·Claude:** 자료 게시/시행 기간/검색·근거 출처와 상담/개인 비서를 구현한다. 모델·키·비용은 구체안을 갖춘 뒤 확인한다.
7. **알림·관리·인계·운영:** 전달사항·문의·학기 전환·원자 인계·실행 실패 재시도·DB와 파일 복원·구형 경로 격리를 완성한다.
8. **시범 공개 후보:** 실제 교사 과제·자료 대조·다계정/다학교 권한·성능·접근성·복구·공개표를 확인한다.

첫 실제 연결은 내부 구축 단계이며 사용자 목표의 전체 기능 공개 범위를 축소하지 않는다. 종료 조건은 [17-pilot-release-plan.md](17-pilot-release-plan.md)의 P01~P11이 기준이다.

## 이번 검증

- 전체 자동 회귀 **1,150건**(이전 1,119 + 도메인 25 + 실제 SSR 6), Python 포함 통과.
- TypeScript·기존 앱·신축 앱 빌드 통과.
- 신규 가져오기 Chrome **19개**: 입력/매핑/오류/후보·개인 공개·저장·부분 등록·읽기 취소/지연·응답 유실·파일·페이지·320px·Shadow DOM.
- 영향 경로 Chrome **65개**: 일정 복구 8·공통 접근성 24·기본 구조 10·연결 11·홈 검색 12. 실제 CalendarPanel의 가져오기 왕복을 포함한 일정 보기 통합 스크립트도 통과.
- 실제 Vite의 기존 업무 통합 **10개**, 독립 HTML **8개** 통과. 독립 HTML 외부 HTTP 요청·브라우저 오류 0건.
- 읽기 지연 시 탈출 불가, 입력값에 따른 필드 이름 변경 문제를 보완했다. Codex 독립 코드 검토 후 추가 중요 지적은 없다. Claude 교차검토는 별도다.
- 실학교 Supabase·Google OAuth·화면읽기 음성·운영 부하·교사 과제 검증은 남아 있다.
- 제안 DB 테스트는 일회용 시험 환경이다. 운영 DB 실행·초기화는 하지 않았다.

이번 브라우저 확인은 **102개 명명된 시나리오와 일정 보기 통합 스크립트**다. 같은 검사의 재실행은 중복 집계하지 않았다. 10차까지의 목록/수합/학생 회귀 이력은 [10차 인계](15-scaled-lists.md)에 보존하며 이번에 전부 다시 실행했다고 표시하지 않는다.

## 판단해서 정한 것

1. 시트 행별 확인은 기존 편집기와 멱등 저장을 재사용한다. 일괄 등록·동기화는 별도 서버 계약이 필요하다.
2. 가져온 일정은 나만 보기로 시작한다. 학교 전체 공유 여부를 표 내용으로 추정하지 않는다.
3. 중복 후보가 검사 시점 기준임을 명시하고 재비교를 제공한다. 동시 등록까지 자동 방지한다고 표시하지 않는다.
4. 기존 제안과 통합 DB 설계 차이를 먼저 해소한다. 임시 구 구조를 만들었다가 바로 버리는 이중 구축을 피한다.
5. 문서 AI·시간표만 제외하며 일반 파일·Claude 상담/개인 비서·평가·운영은 완료 대상에 남긴다.

개인 업무는 현재 학교·소속 단위이며 학교 밖 개인 공간·전출 이관·서버 커서 조회는 남아 있다. 판단에 따른 변경 위치는 [11차 상세 인계](18-calendar-import.md)에 기록한다.
