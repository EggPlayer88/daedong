# 업무혁신시스템 누적 진행 현황

최종 갱신: 2026-10-15 · 압축 PDF·HWP 실제 원본 호환성 보완

목표는 문서작성 AI·시간표를 제외한 기능을 실사용 가능한 수준으로 완성한 뒤 시범 공개하는 것이다. 사용자 승인으로 **DB 조사·준비를 재개**했다. SQL은 Claude 작성 → 검토 → 사용자 직접 적용 순서다. 현재 Supabase·Vercel·GitHub를 개발·검증 환경으로 사용하며, 별도 Supabase 프로젝트를 요구하지 않는다. 기존 로그인과 회원 자료는 보존한다.

## 이번 작업

- PR #38 `a4b4677`의 파서를 기준으로 `feat/workhub-document-compatibility`에서 실제 원본 호환성을 보완했다. #38의 GitHub 회귀·DB 시험·앱 빌드·브라우저 검사 및 Vercel 미리보기 성공을 확인한 상태에서 이어지는 작업이다.
- PDF 압축 xref·object stream·PNG predictor를 지원하고, 정상적인 문서 내부 시작 보기와 외부 실행을 구분했다. 공개 원본 **8개 모두 통과**한다. 같은 8개를 PR #38 코드로 소급 검사하면 3개 통과였다. 증분/혼합 저장·미지원 코덱 등 제한은 남는다.
- HWP 평문 헤더·빈 연결 옵션·정적인 호환/변경 이력 정보·미참조 그림 검사를 보완하고 **5.1.0.0/5.1.0.1/5.1.1.0 별도 프로필**을 추가했다. 공개 원본 **30개 중 8개 통과, 22개 미지원**이다. 본문·표·머리말/꼬리말·여러 구역·인라인 개체·문단 번호의 실제 표본이 통과한다. 일반 HWP 전체의 호환 완료는 아니다.
- 이전에 보완한 HWPX 보호 양식 **6개 모두 통과**를 기존 회귀로 유지한다. 양식·엔진·토큰은 그대로다. 임의 스크립트 제한도 유지한다.
- 새 형식도 원문 검사→스캔→접수 흐름으로 검증했다. 스캐너가 없으면 구조가 정상이어도 미검사로 남는다. 임시 파일 정리는 계속 기본 후보 조회이며 실제 서버 연결은 후속이다.
- 공개 원본 **38개**의 출처·해시·기준 커밋·형식별 시험 한도를 고정하고 재현 도구를 추가했다. 38개 모두 예상 판정과 일치하지만 실제 구조 통과는 16개, 미지원은 22개다. 표본 비율을 전체 문서 호환률로 일반화하지 않는다.
- [이번 호환성 인계](38-document-compatibility.md), [이전 형식 지원 인계](37-document-format-support.md), [처리 코어 인계](36-collection-file-workers.md), [실행 안내](../../workers/collection_files/README.md). 기존 [R1 Claude 요청서](32-collection-server-sql-request.md)는 그대로 유지한다.
- 실제 DB·Storage 호출, 파일 삭제, SQL 변경, 외부 설정, 준비 상태 활성화는 하지 않았다. 화면과 기존 인증 로직도 바꾸지 않았다.

## 배포와 개발 구분

2026-10-15 작업 시작 시 원격 main은 #25까지(`ebdc064`)였다. 이번 작업은 #37(서버 파일 처리, `977fa7e`) → #38(형식 검사 기반, `a4b4677`)을 기준으로 이어지며 #38의 GitHub test 성공을 확인했다. 앞선 PR은 #26(내 업무 분리), #27(학교 설정 준비), #28(DB 일부 제약), #29(연결 조사), #30(파일형 수합), #31(Claude SQL), #32(수합 사용성), #33(파일 수명), #34(수합 서버 연결), #35(공동 제출·관리), #36(전체 ZIP)이다. #23에 포함된 과거 PR도 일부 열려 있으므로 열린 PR 수와 미통합 기능 수는 같지 않다. SQL의 사용자 적용과 GitHub PR 병합은 별도다.

현재 지정 Supabase는 `dhaoszbqtbofqftgjfyb`다. 사용자 실행 결과로 B01/B02, 초기 설정 8개 검증 및 전후 구조 지문 7개 일치를 확인했고, 두 회원 표는 각각 18행이다. 사용자가 대동여자중학교 표시·업무실 진입을 확인했다. 자료 값 전체와 Storage 파일 본문 보존을 이 비교만으로 증명하지 않는다. 이번 코드 작업이 DB에 쓰거나 SQL을 바꾼 것은 아니다.

**앱의 서버 연결 코드와 서버 처리 코어를 준비했지만, 수합용 DB·Storage·서버 검사기 적용이 완료된 것은 아니다. 실제 교사 간 수합이나 전체 목표 90% 달성으로 계산하지 않는다.** 미리보기 자료는 여전히 새로고침하면 초기화된다. 연결 화면의 미저장 입력과 결과 미확정 요청 복구도 현재 탭 메모리 범위다. 서버 검사 결과의 재전송도 현재 프로세스·유효 임대 범위이며 재시작/만료 복구는 후속이다. 서버에 확정 접수된 자료의 영속성은 R1 적용 후 별도로 검증한다.

## 검증과 다음 순서

최종 npm **2,066건 전부 통과**했다(PR #38의 1,865건 대비 **201건 추가**: PDF +97, HWP +75, 검증 처리 +21, 코퍼스 도구 +8). 현재 관련 시험은 PDF 197·HWP 148·통합 구조 검사 118·검증 처리 76·정리 처리 48·코퍼스 도구 8건이다. 보호 HWPX 6/6, 공개 PDF 8/8 통과, 공개 HWP 8/30 통과·22개 미지원도 별도로 기록했다. 독립 검토에서 찾은 PDF 자동 복구/확장량/타입 경계와 HWP 부모·레벨 누락을 수정하고 재확인했다.

기존 가상환경과 CI의 파서 의존성을 그대로 사용한다. 이번에는 새 의존성·기존 웹 API 배포 의존성·앱 화면을 변경하지 않았다. 화면·앱 빌드는 로컬에서 이번에 재실행하지 않았으며 GitHub의 기존 필수 검사에 남겨두었다.

직전 #36에서는 전체 Chromium **35개 검사 파일**, 연결 수합 **29개**, ZIP **13개 시나리오**, 두 앱 빌드·타입 검사·통합 이력/보호 경계 검사가 통과했다. PR #34의 서버 계약과 SQL 요청서는 이번에도 변경하지 않았다. [ZIP 인계](35-collection-server-export.md), [공동 제출·관리 인계](34-collection-management.md), [서버 연결 인계](33-collection-server-connection.md)에 이전 검증을 보존한다.

- 이번 자동 시험은 로컬 파서와 합성 포트 기준이다. 실제 Supabase/PostgREST/Storage의 원자성·권한·물리 삭제·악성 검사기 탐지·Google 로그인 종단 검증은 별도다.
- 이번 작업에서는 인증 로직·일반 교사 공개 범위·SQL·HWPX 엔진/양식·규정·외부 설정을 변경하지 않았다. 자료 수합은 슈퍼관리자 업무실에서만 접근한다.

1. Claude가 R1 SQL·Storage 권한·검증 job/봉인 계약·비파괴 중지 절차를 작성한다. Codex가 기존 자료 보존과 앱 계약을 교차 검토한 뒤 사용자가 적용한다.
2. 준비한 파일 처리 코어를 확정 SQL·실제 Storage·승인 악성 검사기에 연결한다. HWP 미해석 연결 옵션·PDF 증분 저장/미지원 코덱, 실행 자원 제한, 임대 만료/재시작 복구를 보완하고 자동 통합 시험 후 준비 상태를 켠다. SQL만 적용하고 완료로 표시하지 않는다.
3. ZIP·공동 단위·철회/정정의 실제 서버 연결을 검증한다. 현재 ZIP은 원자적 서버 스냅샷이 아니며, 상세 대조와 파일별 접근 재확인 범위다. #26~#38 및 이번 후속 PR은 검토 결과에 따라 단계적으로 통합한다.
4. 학생 기록 실제 연결, 메신저·학교 자료·Claude·알림·관리 기능을 순차 구축한다.
5. 사용자 요청에 따라 일정·업무 저장/수정/재로그인, 기존 평가계획서 다운로드, 수합 다중 교사·모바일 시험은 이후 통합 실사용 확인으로 모은다. 문서작성 AI·시간표는 계속 보류한다.
