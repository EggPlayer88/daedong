## 통합 중 발견해 수정한 내용

- 시간초과 뒤 늦게 끝난 승인 조회/파일 포트 로딩이 새 저장·업로드·검사를 시작하는 경로를 재현하고 차단했다. 이미 보낸 요청은 결과 미상·원래키 복구로 유지한다. 안전한 학교관리 개별 bounded 경로는 불필요하게 고치지 않고 회귀로 확인했다.
- 비서 제안이 아직 전송되지 않았는데 서버 준비가 내려가면 검토창을 닫지 못하는 문제를 수정했다. 미확정 쓰기가 있으면 원키 보존을 우선한다.
- 수합 마감 뒤 새 답변·파일·최종제출을 막고 읽기/기존 접수증은 유지한다. 실제 SQL의 상태 재검사는 별도 계약으로 요구했다.
- 서버 연결을 확인하지 못한 상태를 정책 미설정으로 단정하던 안내를 수정했다.
- 학교 설정과 학년도 전환의 기간 범위, 특수/기타 학교와 학생 학년 상한을 같은 자산으로 정합화했다. 실제 학교별 gradeCount는 서버에서 추가 검증한다.
- 손상 CRC/압축 본문을 가진 HWPX 원본은 확정 양식 오류로, 전송 중 짧게 받은 원본은 결과 미상으로 구분했다.
- 실제 Python HTTP 서버에서 잘못된 Content-Type 요청의 미소비 본문이 Windows 연결을 리셋하는 경로를 재현했다. 작은 본문을 한도/timeout 내 읽은 뒤 형식을 거부하도록 수정, 반복 30회 응답 확인.
- HWPX 간소화 전 문구를 기대하던 브라우저 3개, 연결 안내 기대 1개를 현재 동작과 맞춰 수정했다. 마지막 전체 브라우저 실행은 모두 통과했다.

## 전체 셸과 시각 확인

새 `workhub-pilot-connected`의 7개 동선은 실제 ConnectedWorkspace에 R0 조회만 제공했다. 선택 모듈 미준비 격리, 기존 일정 유지, 일괄 가져오기 실패 후 닫기, 입력/연결 복구, 렌더 예외 격리, 학교 전환, 모바일 더보기를 검증했다. 쓰기 요청0·외부 요청0·예상 밖 pageerror0. 인위적 렌더 예외는 별도로 기록했다.

PC 1280과 모바일390의 홈·일정·더보기·학생 준비 안내 스크린샷을 직접 확인했다. 글꼴은 저장소 Pretendard 자산이며 화면은 합성 학교/교사다. 실제 사이트의 사용자 화면 캡처로 오해하지 않는다.

## R1S는 별도 결과

PR #47 `884056f`의 격리 PostgreSQL 17.6 대조는 **410/411**. L44의 짧은 다운로드 실패 분류와 현재 앱의 RESULT_UNKNOWN 유지가 다르다. 셸 CRLF는 시험 사본에서 LF로 보정했다. 이 결과를 전부 통과 또는 R1S 적용 승인으로 기록하지 않는다. [수정 요청](sql-handoff.md#5-r1s-pr-47-재현-메모--먼저-확인할-두-항목)을 따른다.

기존 R0/R1 SQL 원문과 작업자 코드는 이번에 변경하지 않았다. CI의 기존 PG16 독립 연결 경합과 PG17 R0/R1 원본/작업자 검사는 유지한다. 새 모듈 SQL이 아직 없으므로 해당 SQL의 RLS·동시성·실제 PostgREST 출력을 이번 앱 테스트가 검증했다고 주장하지 않는다.

## 미검증 영역

실제 Supabase Auth/PostgREST/Storage·서명 URL 차단, 실제 학교 HWPX 호환/생성 서식, 실제 Claude 답변·과금·모델설정, 학교별 정책/명부·교사 소속, 실제 다중사용자 동시성, 일반 교사 공개 이후 사용성은 [활성화 체크리스트](activation-checklist.md)에 남겼다. 현재 코드는 NOT_READY를 실제 준비 완료로 우회하지 않는다.

## 재실행

```text
npm ci
npm test
npm run check:workhub
npm run check:workhub:pilot
npm run build
npm run build:workhub
npm run test:workhub:browser
```

Python 시험에는 기존 `workers/requirements.txt` 의존성이 필요하고 브라우저는 Playwright Chromium/Chrome이 필요하다. Linux CI는 저장소 workflow가 설치한다. 테스트가 실제 서비스 키를 요구하지 않으며 기존 운영 DB에 연결하지 않는다. GitHub CI/미리보기 결과는 PR의 최종 커밋에서 별도로 확인한다.
