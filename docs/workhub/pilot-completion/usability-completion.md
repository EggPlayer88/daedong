# 학생 출력·스킨·관계 목록·홈 메시지 사용성 마무리

기준: 2026-10-16. PR #60 `eee059f` 위에서 사용자 요청 네 항목을 한 작업 브랜치로 구현했다. DB 적용, SQL 수정, 외부 설정, 메뉴 공개 범위 확대, 실제 학교 자료로 하는 실사용 확인은 포함하지 않는다. 기존 로그인·회원·확정 평가계획서 양식과 엔진을 보존한다.

## 1. 학생 기록 출력

- 수업 → 학생 선택 → **기록 출력·내보내기**에서 기간과 관찰/평가 종류, 철회 기록 포함 여부를 고른다. 먼저 미리보기를 읽고 범위를 확인한 뒤 CSV 또는 인쇄를 실행한다. 브라우저 인쇄에서 PDF 저장을 선택할 수 있다.
- 현재 계정이 해당 수업·학생에 대해 조회할 수 있는 관찰·평가의 **현재 판**을 출력한다. 상담, 활동 원문, 정정 이전판 전체 이력은 포함하지 않는다. 상담 조회 함수도 호출하지 않는다.
- 평가에는 평가 당시 기준판과 항목별 점수·상태를 사용한다. 현재 기준으로 과거 점수를 다시 해석하지 않는다. 철회, 원문 변경에 따른 근거 재검토, 교사 평가 확인 여부를 별도로 표시한다.
- 이것은 교사용 참고 출력이다. 공식 생활기록부 제출 양식이나 AI 근거 재사용 자격을 만들지 않는다. CSV에 수업·학생·기간·상태·기록판·평가 기준과 출력 범위 설명을 포함한다.
- 기존 읽기 RPC를 끝 페이지까지 조회한다. 중복 기록·반복 커서·잘못된 학교/학생/작성자·손상된 과거 평가 기준을 발견하면 중단한다. 기술 한도는 50페이지·2,000기록·본문 8MiB이며 초과 자료를 일부만 성공한 것으로 내보내지 않는다. 설정은 `record-export-policy.json`으로 분리했다.
- 실제 내보내기 직전에 전 범위를 다시 읽는다. 미리보기와 지문이 달라지면 새 내용을 보여 주고 다시 확인하도록 한다. 명부와 첫 페이지도 다시 대조하며, 학교·계정·소속 전환이나 읽기 실패 시 자료를 숨기고 출력을 막는다.
- **일관성 한계:** 여러 읽기 RPC를 순차 호출하므로 DB 원자 스냅샷은 아니다. 재조회 도중 후속 페이지에서 일어난 모든 동시 변경을 증명하는 기능은 현재 서버 계약에 없다. 출력 이후 정정한 내용은 다시 출력해야 한다.
- CSV의 수식 시작 문자는 텍스트로 처리한다. 인쇄는 사용자 문자열을 HTML로 해석하지 않는다. 인쇄 창은 클릭 직후 빈 상태로 열고 조회 성공 뒤 채우며, 취소·범위 변경·인쇄 종료 시 닫는다. 이전 조회의 늦은 실패가 새 인쇄 창을 닫지 않도록 실행별로 관리한다.

## 2. 스킨 정리

- 문서함·질문형 양식의 기존 미정의 색상 변수를 공통 `--ui-*` 변수에 연결했다. 화이트/블루, 차콜, 따뜻한 톤의 기존 세 스킨에서 카드·본문·선택·오류·초점 표시가 일관되게 바뀐다.
- 수업·관계·학생 출력 화면에도 같은 변수를 사용한다. 전역 테마나 다른 메뉴의 디자인을 교체하지 않는다.
- 활성 텍스트 대비, 긴 제목/설명, 320px 너비, 키보드 초점을 자동 확인했다. 200% 문자 확대는 CSS로 모사한 확인이며 모든 브라우저의 네이티브 확대 조합을 검증했다는 뜻은 아니다.
- 상세 확인: [문서 화면 스킨](document-appearance.md).

## 3. 관계 관리 목록

- 수업 담당 교사와 수강 학생 목록에 각각 이름 검색·상태 필터·20개 단위 페이지를 제공한다. 검색은 이미 조회한 전체 목록에 적용하며, 현재 보이는 20개만 검색하지 않는다.
- `현재 유효 / 시작 예정 / 종료 / 시작 전 취소`를 기준일과 유효기간으로 판단한다. 마지막 날도 유효한 날에 포함한다. 학생의 수강 상태와 학적 상태는 별도로 표시한다.
- 검색이나 페이지 이동 중에도 선택한 변경 대상·사유·기존 요청 번호를 유지한다. 편집 중 다른 대상을 잘못 선택하지 않도록 변경 버튼을 제한하고, 선택한 대상 이름은 편집 영역에 계속 보여 준다.
- 목록이 줄면 유효한 페이지로 보정한다. 조회 실패나 권한 재확인 중에는 이전 목록으로 새 변경을 시작하지 않는다. 기존 충돌 처리와 같은 요청 복구를 유지한다.
- 이는 **화면 렌더링과 탐색 개선**이다. 서버 페이지 계약이나 관계 변경 SQL은 바꾸지 않았다.

## 4. 홈에서 메시지 바로 열기

- 홈의 메시지 카드가 해당 대화 ID를 기존 메시지 조회 함수에 전달한다. 첫 목록 페이지에 없는 대화도 직접 확인할 수 있다.
- 정확한 대화를 찾지 못하거나 권한이 없으면 해당 오류를 표시한다. 다른 첫 번째 대화를 대신 열지 않는다. 목록 또는 홈으로 돌아갈 수 있다.
- 작성 중인 메시지는 접어서 보관한 뒤 이동한다. 내용·수신 대상·원래 전송 요청 번호를 유지하며, 결과 미상 요청을 새 번호로 다시 보내지 않는다. 보관 범위는 현재 탭 메모리다.
- 대화 조회만으로 읽음 표시, 메시지 전송, 알림 확인 처리를 하지 않는다. 읽음은 기존 명시 버튼을 사용한다. 늦은 조회 응답이 새 선택을 덮어쓰지 않으며 상세 제목/오류로 키보드 초점을 옮긴다.
- 기존 P7 홈의 `message.sourceId`는 대화 ID이고 P3의 `workhub_message_get`으로 조회한다. 새 SQL 함수는 요청하지 않는다. 홈의 학생 후속 카드는 기존 학생 목록 연결을 유지한다.

## 5. 자동 검증

전용 시험은 실제 React·도메인·어댑터·Chrome을 사용하되 DB/Storage 응답은 합성이다. 운영 Supabase의 적용/권한/응답이나 실제 Google 로그인·Claude 호출 성공을 대신하지 않는다. 실제 OS 인쇄 결과도 이번 자동 검증의 범위 밖이다.

| 확인 | 최종 결과 |
|---|---|
| `npm test` | 2,975건 통과, 실패·건너뜀 없음. 학생 출력 28건과 관계 목록 12건을 새로 포함 |
| 전체 브라우저 러너 | 등록한 56개 파일 모두 확인. 최초 실행 55/56, 아래 선택자 수정 후 실패 파일과 영향 화면 재검증 통과 |
| 새 전용 브라우저 | 학생 출력 15, 문서 스킨 22, 관계 목록 9, 홈 메시지 10 시나리오 통과 |
| 기존 관계 회귀 재검증 | 13 시나리오 통과. 목록 제목과 새 입력 대상 표시를 각각 확인하도록 선택자 보완 |
| 타입·빌드 | `check:workhub`, 기존 사이트 `build`, `build:workhub` 통과 |
| 통합 보호·공백 | `check:workhub:pilot`, `git diff --check` 통과 |

최초 브라우저 실패는 새로 표시한 선택 대상 이름과 기존 목록의 같은 이름을 텍스트 하나로 찾던 구형 검증 코드의 중복 선택이었다. 제목과 입력 폼을 각각 명시해 검증을 보완했다. 독립 UI 검토에서는 긴 수업명·학생명이 좁은 화면에서 넘치는 경계를 찾아 줄바꿈을 보완하고, 실제 120자 이름·320px·본문 14/28px·세 스킨 조합으로 재검증했다. 전체 실행 로그와 후속 결과는 바탕화면 `GPT작업/2026-10-16_사용성마무리/전체검증`에 보관했다.

- 학생 출력: 범위·전체 페이지·과거 평가 기준·CSV/인쇄·재확인·늦은 응답·학교/명부/권한 변경.
- 관계 목록: 1,000명 검색, 교사/학생 독립 필터, 페이지 보정, 선택/사유/미확정 요청 보존, 모바일/스킨.
- 홈 메시지: 실제 연결 셸에서 목록 밖 대화·오류·원래 입력/요청 보존·자동 쓰기 없음·좁은 화면.
- 문서 스킨: 세 스킨·대비·긴 내용·200% 문자 확대 모사·320px 화면·키보드.
- 전체 단위/회귀, 전체 브라우저, TypeScript, 기존 사이트 빌드, 업무실 빌드, 시범 통합 보호 검사, diff 공백 검사를 수행한다.

이번 작업의 4개 앱 항목 진척도와 전체 실사용 준비율은 다른 수치다. 이전의 19개 영역/단계별 동일 가중치 추정 기준을 유지하면 전체는 **약 60%**다. 이것은 작업량·품질 점수나 자동 시험 통과율이 아니며, 이번 사용성 보완만으로 DB 활성화와 실서비스 검증 단계를 완료로 올리지 않는다.

## 판단해서 정한 것

- 학생 출력은 기존 권한이 확인된 읽기 경로를 재사용한다. 새 SQL이나 상담 정보까지 요구하지 않고 교사가 요청한 관찰·평가 정리에 집중하기 위해서다. 범위를 확장할 때는 출력 모듈/정책과 서버 읽기 계약을 함께 검토한다.
- 출력 미리보기와 관계 목록은 20개 단위로 보여 준다. 화면 부담을 줄이되 검색/내보내기의 전체 대상 의미는 유지하기 위해서다.
- 새 카드 링크는 기존 공통 이동 경계를 사용한다. 메시지만 별도의 이동 체계로 만들면 입력 보존과 나가기 확인이 갈라지기 때문이다.
- PR #60 위에 후속 PR 한 개로 제공한다. Claude가 검토 중인 #60 브랜치와 SQL 브랜치를 수정하지 않으며 병합은 사용자가 결정한다.
