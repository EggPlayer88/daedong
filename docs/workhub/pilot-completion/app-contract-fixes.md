### C1 계약·호환

새 이력의 `actorName`, `recipientMemberId`, `previousRecipientMemberId`를 모든 행에서 검증한다. 최초 수신자부터 구간을 따라가며 handover의 처리자=새 수신자, 이전 수신자=직전 수신자, 상태 유지와 마지막 수신자의 일치를 확인한다. 과거 행의 담당자를 현재 담당자로 바꾸거나 일부 필드를 누락한 응답을 거절한다.

새 필드가 전혀 없고 인계도 없는 구형 P2만 호환한다. 중간 P7의 구형 handover 응답은 최신 계약을 확인할 때까지 차단한다. 세 필드를 모두 제거하여 약한 추론 검사로 되돌아갈 수 없도록 한 결정이다. 인계 SQL/앱 최종 계약 대조와 배포 전에는 기능 활성화 완료로 표시하지 않는다.

상세 검증 오류는 실제 어댑터에서 QUERY_FAILED와 서버 이력 확인 안내로 변환한다. 교사의 입력 오류로 오안내하지 않는다. 상세 재조회 실패와 원래 쓰기 요청의 결과 확인을 분리하여 복구가 막히지 않게 했다.

### C4 정렬·멱등성

포함·제외 ID만 DISTINCT 및 코드포인트 순으로 정렬한다. 격리 PGlite에서 실제 PostgreSQL `COLLATE C` 결과와 대조했다. all·조건 묶음·포함/제외 겹침은 그대로 유지하며 제외 우선 의미를 바꾸지 않는다.

새 prepare 입력은 기존 지문을 먼저 검사하고 복사본을 정렬한 뒤 새 지문을 만든다. 변조된 지문을 새 값으로 덮어 통과시키지 않는다. commit은 정규화 경로를 거치지 않는다. 대상 입력을 제공하는 합성 시험과 기존 CSV 화면은 구분한다. 현재 CSV UI에 새 대상 선택칸을 추가한 것은 아니다.

### C5 종료·미확정 구분

예약 성공 뒤 fileId를 탭 메모리에 함께 저장한다. 복구 시 ready 파일의 이름·크기·SHA-256이 원본과 같은지도 확인한다. known ID의 진행 중 예약은 같은 키의 조회 전용 prepare로 경로와 ID를 재확인하고 이어간다.

fileId 없이 첫 요청이 서버 도착 전에 끊겼으면, 활성 상태에서 원래 키와 본문으로 prepare하여 복구한다. 비활성 상태의 NOT_FOUND는 보존한 뒤 활성화 시 같은 키로 이어간다. 비활성 상태에서 새 업로드·complete·검사를 시작하지 않는다.

검증된 prepare 업무 응답의 CONFLICT만 종료된 예약으로 분류한다. 일반 충돌·잘못된 응답·접근 오류·시간초과로 파일을 버리지 않는다. 현재 SQL은 거절 원인을 따로 주지 않으므로 ‘확인에서 거절되었거나 업로드 기한이 지났습니다’라고 안내한다. 명시적으로 새 파일을 선택할 때만 새 첨부 키를 만든다.

제품은 recoveryScope(member) key로 소속 전환 시 화면을 다시 생성한다. 늦은 응답은 이전 pending 기록·첨부 목록을 되살리지 않는다. 보존은 현재 탭 메모리이며 브라우저 종료 후 영구 복원은 범위 밖이다.
