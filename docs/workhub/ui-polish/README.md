## 바뀐 사용 방법

| 화면 | 개선 |
| --- | --- |
| 편성 관리 | 편성 단계부터 연다. T1의 빈 `lessons` 배열을 공개 시간표가 없다는 뜻으로 보여 주지 않는다. ‘공개 시간표 보기’는 기존 T2 조회 화면으로 이동한다. |
| AI 옆자리 | 질문 입력과 실행 버튼을 앞에 배치한다. 미확정 요청 복구·오류는 입력보다 위에 두고, 예산·이전 대화·기억은 아래에서 펼친다. |
| 주간 시간표 | 기본 칸에는 수업명·학급을 중심으로 표시한다. 실제 시각은 행 제목, 날짜는 열 제목에 유지한다. ‘수업 정보 자세히’로 반복 정보를 펼칠 수 있다. |
| 시험 교사 업무 참여 | 기존 참여 범위로 공통 메뉴·글꼴·화면 설정을 구성한다. 메시지·시간표·업무·일정을 중심으로 두고, 허용된 세부 화면은 관련 메뉴와 더보기에 둔다. |

## 기능과 권한 보존

- DB·SQL·RPC·인증·소속 및 권한 판정·공개 범위·AI 비용/모델은 변경하지 않는다. 추가 SQL과 환경변수는 없다.
- T1 편성 조회와 T2 공개 조회의 역할 차이를 화면에서 설명한다. 서버가 없는 수업을 만든 것처럼 표시하지 않는다.
- 기존 편성 입력과 미확정 요청 복구가 새 진입 순서보다 우선한다. 입력 중에는 공개 시간표로 이동하는 기존 잠금도 유지한다.
- 시간표의 조회 범위 밖 안내, 교사/학급 선택, 취소·실시 상태, 초 단위 시각, 자정을 넘는 종료 날짜를 유지한다. 전체 접근성 이름과 선택 상세에는 숨긴 반복 정보도 제공한다.
- AI 입력을 재배치해도 명시 요청·정밀 검토·기억 선택·근거 확인 절차는 그대로다. 패널 열기나 화면 크기 변경으로 유료 요청을 보내지 않는다.
- 업무 참여 화면은 기존 `ParticipantWorkspace`가 받은 승인 범위만 셸에 전달한다. 시간표 편성·AI·학교 관리 메뉴를 새로 부여하지 않는다. `transitions`의 표시 목적지는 기존처럼 업무 인계 컴포넌트다.
- 현재 참여 허용·소속·기한 재검증과 서버의 RPC 권한 검사는 그대로다. 메시지 작성 중 이동 잠금, 소속 무효화 후 내용 숨김도 보존한다.
- 메신저 단독 MP1 경로와 기존 평가계획서 화면은 이번 변경 대상이 아니다.

## 판단 기록

| 결정 | 이유 | 위치 |
| --- | --- | --- |
| 연결된 편성 화면은 설계부터 시작 | T1 공개 함수의 빈 수업 배열로 T2 공개 여부를 추측하지 않기 위해서다. | `timetable/TimetableWorkspace.tsx` |
| 질문 입력의 DOM 순서도 앞으로 이동 | CSS로만 순서를 바꾸면 키보드 이동이 화면 순서와 달라지기 때문이다. | `assistant/AssistantPanel.tsx` |
| 상세 표시 토글은 화면 상태 | 학교 공통 설정이나 DB 변경 없이 교사가 필요할 때만 펼친다. | `timetable/PublishedTimetableBoard.tsx` |
| 참여 셸은 표시 목록을 주입 | 관리자 셸 전체를 열지 않고 공통 시각 요소만 재사용한다. | `app/WorkspaceShell.tsx`, `participation/ParticipantWorkspace.tsx` |

## 남은 개선 후보

긴 AI 대화를 읽으면서 입력하는 배치와 여러 수업이 겹친 칸의 가독성은 실제 사용 의견을 모아 다음 개선에서 다룬다. 이번에는 입력 보존·조회 정확성·기존 승인 절차를 유지한 채 네 가지 화면 문제를 정리한다.
