# 사이트 전체 UI·UX 개편

## 교사가 보는 변화

홈의 정보량은 유지하고, 일상 업무·도움 도구·관리 정보를 구분한다. 빈 목록형 시안 대신 **확인할 일 / 내 수업 / 오늘 일정 / 내 할 일의 2×2 카드**를 사용한다. 좁은 화면에서는 같은 순서의 한 열로 바뀐다. 긴급 업무와 조회 오류는 접거나 높이로 자르지 않는다.

| 영역 | 이번 변경 |
| --- | --- |
| 기본 메뉴 | 홈 · 일정 · 시간표 · 내 업무 · 수업·학생 · 문서·자료. 교사별 기존 허용 목록만 배치한다. |
| 모바일 | 홈 · 일정 · 시간표 · 내 업무 · 더보기. 허용되지 않은 항목은 나타나지 않으며 수업·문서는 더보기에서 연다. 제한 참여 계정은 기존 허용 메뉴를 우선한다. |
| 홈 | 2×2 카드, 실제 업무 건수, 수업 시각·학급, 일정, 할 일. 다가오는 일정은 하단 한 영역에서 확인한다. |
| AI 비서 | 범위 선택 → 질문 → 답변 중심. 이전 대화·기억·예산은 보조 도구로 모으고 기존 요청 종류만 바로 선택한다. 옆자리에서는 입력과 실행 버튼부터 보인다. |
| AI 관리자 | 학교 키·예산을 첫 탭에 두고 가상 연습은 마지막 탭으로 옮긴다. 키 저장·비용·모델 계약은 바꾸지 않는다. |
| 메시지·수합·협업 | 중복 헤더와 상시 설명을 줄이고 현재 작업 제목과 주요 버튼을 앞에 둔다. 대상 확인과 최종 전송·제출 확인은 유지한다. |
| 문서·학교 자료·양식 | 목록과 편집의 구분, 선택 전 안내, 질문 연결을 명료하게 한다. 복사·보관은 문서 작업 더보기, 검사 설명은 원본 확인 도움말에서 연다. |
| 시간표·수업·학교 관리 | 반복된 진입 설명을 줄이고 일관된 제목·탭·입력·빈 상태로 맞춘다. 배정·승인·실시 기록 계약은 그대로다. |
| 계정·평가계획·기간 업무 | 같은 글자·색상·입력·카드 규칙을 기존 화면에 적용한다. 기간 업무의 메뉴 표시 정책은 유지한다. |
| 서비스 정보 | 글꼴 고지와 학교 연결 정보·운영 진단을 일반 업무 본문에서 분리한다. 연결 실패 시 진단은 실패 화면에서도 제공한다. |

## 판단해서 정한 것

1. 정보가 충분한 홈을 원한다는 피드백에 따라 네 카드를 동일 너비로 배치했다. 긴급 업무를 먼저 읽고 나서 수업·일정·할 일로 이어진다. 구조와 밀도 조정은 `calendar/CalendarPanel.tsx`, `calendar/home-dashboard.css`에서 되돌릴 수 있다.
2. 메뉴 배치와 접근 허용을 분리했다. `navigation-groups.ts`는 기존 목록을 묶기만 하며, `modules.ts`, main의 공개 레지스트리, 참여 권한, 서버 인증을 수정하지 않았다. 모바일에서 접힌 주 메뉴도 더보기로 접근한다.
3. 글꼴 라이선스는 삭제하지 않고 `ServiceInfoDialog.tsx`로 옮겼다. 같은 창에 기존 연결 진단을 제공한다. 진단을 열었다는 이유만으로 쓰기나 AI 요청을 시작하지 않는다.
4. 전체 AI와 옆자리는 원래 같은 대화 상태를 유지한다. 시작 제안은 기존 요청 종류 선택만 하고 데이터를 추가하거나 요청을 보내지 않는다. 학교/개인 범위, 학생 자료 확인, Sonnet 추가 비용, 결과 미상 복구는 그대로 보인다.
5. 밝은 중립 배경·선명한 글자·절제된 강조색을 공통 토큰으로 묶었다. Pretendard와 Tossface는 기존 로컬 자산을 재사용한다. `site-experience.css`와 각 영역 CSS에서 표시만 조정한다.
6. Storage 성공 시험의 기본 100ms 제한은 병렬 실행 중 파일 해시 계산을 시간 초과로 오인했다. 시험의 성공 대기만 1000ms로 늘리고, 단절 시나리오의 명시적 15ms와 제품 시간 제한은 유지했다.

## 유지한 경계

- DB·SQL·RLS·인증·권한·공개 범위 변경 없음. 추가 SQL 실행 없음.
- AI 모델·예산·토큰 상한·API·자동 호출 정책 변경 없음.
- HWPX 검사·생성·업로드·다운로드·ZIP 방식 변경 없음.
- 현재 탭의 입력 보존을 브라우저 종료 후 자동 저장처럼 안내하지 않는다.
- 결과 미상 요청의 원 번호, 재확인, 제출·승인, 학교 변경 시 원본 비노출을 유지한다.
- 실제 운영 자료 수정이나 유료 AI 호출 없이 합성 전송 계층으로 시험한다.

## 병합·배포

SQL 적용 없이 PR 미리보기 → 자동 검사 확인 → 사용자 merge commit → Vercel Production Ready 순서다. 일반 교사 공개·실제 회원 연결·AI 운영 정책 변경은 이 PR에 포함하지 않는다. 실제 학교 업무를 사용하며 받는 기능 피드백은 별도 후속 작업이다.
