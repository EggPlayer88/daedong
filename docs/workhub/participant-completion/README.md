# 참여 흐름 구축 마무리 — 2026-10-26

사용자 요청에 따라 실제 기능 시험과 UI·UX 개편을 미루고, 남아 있던 일반 교사 참여 연결을 한 묶음으로 구현했다. 기준 main은 PR #82 병합 `f4ed481`이다. 이 문서는 구축 산출물 보고서이며 운영 사용 준비 완료 판정은 아니다.

## 이번 구현

| 업무 묶음 | 이번에 채운 연결 | 운영 반영 뒤 확인할 것 |
|---|---|---|
| 메신저·협업 | 기존 MP1 보존, OP1 지정 계정의 메시지·알림·협업 요청·할 일 이동 | 서로 다른 계정의 전송·수락·읽음·첨부 |
| 수합·인계 | 동일 학교 지정 참여자의 수합/파일 접근과 인계 수락·반려 경로 | 소유권 변경·독립 관리자 확인·원번호 복구 |
| 시간표 운영 참여 | 허용된 교사의 운영 화면, 일정의 내 수업→해당 날짜/수업, 알림→정확한 요청 | 교사 동의·독립 승인·실시 기록·동시 변경 |
| 수업·평가 | 현재 담당/수강 관계를 사용하는 기존 수업 화면의 일반 교사 진입 | 타 수업·학교 차단, 평가 기준판·출력 |
| 운영 관리 | 지정 계정·범위·기간·판·현재 효과·승인 담당 수 조회, SQL 승인·중지·T3 명단 변경 양식 | 설정된 담당자와 실제 역할 확인 |
| 배포 준비 | OP1 설치·사전/사후 점검·INT-10 전체 지문·회수 절차·변경 목록 | 운영 SQL 적용, 앱 배포, 명시 허용 |

앱은 승인된 범위만 구성하며 URL을 바꿔 다른 메뉴로 진입할 수 없게 한다. 서버도 같은 업무 범위를 검사한다. 기존 작업 화면의 요청 번호 복구와 입력 보관, 학교·역할·소유권·수업 관계·독립 승인 검사는 유지한다. 신규 참여 화면의 AI 호출은 열지 않았다.

## 검증을 미룬 경계

사용자가 테스트를 나중으로 요청했다. 이번에는 코드 타입/배포 빌드와 SQL 설치문·점검 목록 컴파일을 확인하며, 실제 브라우저 업무·운영 DB·Storage·유료 AI·교사 계정을 사용한 기능 시험은 하지 않는다. 새 회귀 코드와 기존 MP1 시험의 전용 조회 응답 갱신은 준비했지만, 현장 검증 결과로 취급하지 않는다. 기존 GitHub 필수 CI는 PR 생성 시 정상 실행된다.

구체적인 명령별 기록은 [검증 범위](verification.md), SQL 실행 순서는 [OP1 안내](../../../database/workhub-participation/op1/README.md)가 기준이다.

## 남은 것: 종류별 구분

| 구분 | 남은 항목 | 이번에 처리하지 않은 이유 |
|---|---|---|
| 운영 반영 | 새 OP1 SQL 적용·앱 병합/배포·지정 계정 범위 활성화 | 검토 가능한 새 구축물이며 아직 운영에 반영하지 않음 |
| 운영 설정 | 시험 참여 계정·담당 수업/학생 관계·두 번째 승인 담당자 | 가상 데이터 ID가 실제 로그인·승인 권한을 대신하지 않음 |
| 실제 기능 시험 | 메시지/협업/인계/시간표/수업 평가의 다자 왕복, 권한 회수·응답 유실·첨부 확인 | 사용자 요청으로 보류 |
| 최종 검토 | Claude 검토 및 발견 결함 수정 | 사용자 요청대로 마지막에 묶음 |
| 실학교 전환 | 기존 가입 교사 연결·실제 학급/수업/명부·시간표 교체 | 사용자 요청으로 보류. 시험 기록을 실제 동의/제출로 옮기지 않음 |
| 별도 작업 | UI·UX 일괄 정리, 교사 외부 사이트 자동 연결 | 이번 구축 범위에서 제외 |
| 운영 결정 | 결과 미상 AI 요청 확인 담당·주기, 자료 보관/백업 운영 기준 | 코드가 학교의 운영 방침을 임의 확정하지 않음 |

이미 사용자가 확인한 Haiku/Sonnet 응답·정산, 수합 HWPX와 ZIP, 질문형 문서 생성, 학교 자료 원문·인용, 개인 기억 등의 결과는 이전 기록에 남긴다. 이번에 다시 시험하거나 모두 성공으로 재판정한 것은 아니다. 전체 시스템의 모든 미래 확장 기능까지 완성했다는 의미도 아니다. PDF 가져오기·범용 서식 자동 편집·자동 운영 예약 작업 등 기존 제외 범위를 이번에 다시 추가하지 않았다.

## 후속 시험을 한 번에 할 순서

1. 운영 반영 준비를 마치고, 현재 시험 일반 교사와 필요한 별도 승인 담당자를 명확히 지정한다.
2. OP1과 모듈별 정책·수업 관계를 확인한다. 역할을 임의로 superadmin으로 올리지 않는다.
3. 메시지→협업→인계, 시간표 요청→교사 동의→독립 승인→일정·실시 기록, 수업→평가→출력을 묶어서 시험한다.
4. 실패 항목만 수정하고 최종 검토·실학교 전환·UI·UX 순서로 진행한다.

따라서 현시점에 “테스트만 남았다”고 표시하지 않는다. **구축물 작성**, **운영 반영/설정**, **기능 검증**을 별도로 보고한다.
