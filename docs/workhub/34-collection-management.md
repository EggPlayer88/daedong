# 파일형 수합 후속 — 공동 제출·철회·정정·이력

2026-10-15 · `feat/workhub-collection-management` · PR #34 후속

## 교사가 보는 변화

기본 개인별 제출에 더해 학년·교과 등 여러 교사가 함께 한 부를 작성할 제출 단위를 설정할 수 있다. 단위 이름, 책임 교사, 공동 작성자를 지정하고 초안에 함께 저장한다. 기존 개인별 선택과 공동 설정을 함께 유지한다. 공개 이후의 대상·문항 변경은 제공하지 않는다.

책임 교사는 현재 제출의 철회를 사유와 대상 확인 후 요청할 수 있다. 검토 완료본의 직접 철회는 제공하지 않는다. 수합 관리자는 특정 제출 단위의 정정 종료일과 허용 사유를 설정한다. 최종 허용 여부·마감·현재 권한은 서버가 판정한다. UI에서 과거판을 복원하거나 전체 기한을 바꾸지 않는다.

현재 제출과 완료본을 구분하며 과거 제출, 검토 의견, 보완 응답, 철회 이력을 접어서 보여 준다. 열었을 때 20판씩 추가 표시한다. 과거 파일은 선택한 정확한 제출판으로 접근을 요청하고, 철회된 파일의 다운로드는 제공하지 않는다. 이름은 당시 단위 구성원 기록을 우선하고, 없는 검토자는 현재 허용된 학교 명부에서 찾는다. 시각은 명시한 한국 표준시이며 접수일·기한은 서버 날짜다.

## 함께 고친 오류

1. **철회 후 재제출 사유 누락**: 현재 제출이 null이어도 과거 제출이 있으면 사유를 입력한다. 철회로 다시 열린 보완 요청도 현재판 존재와 관계없이 선택한다. 기한이 지났다는 표시만으로 보완 응답을 막지 않는다.
2. **검토 대상의 묵시적 교체**: 검토·철회 폼을 열 때 `submissionId`와 `unit.version`을 고정한다. 포커스 재조회로 새 제출판이 나타나면 기존 의견·사유를 적용하지 않는다. 같은 제출의 상태판만 바뀌었으면 원본 비교 후 명시적으로 최신판을 채택할 수 있다. 이미 검토된 제출은 다시 처리하지 않는다.
3. **상세 조회 실패 뒤 닫기 불가**: 학교·목록 연결은 정상이어도 상세 조회 실패로 폼이 숨겨지는 경우를 처리했다. 전송하지 않은 입력은 명시적으로 버리고 이동할 수 있다. 결과 미확정 요청·파일 업로드는 그대로 보호한다.
4. **검토자 이름 누락**: 검토자가 공동 작성자 명단 밖에 있어도 현재 학교의 활성 명부에 있으면 이름을 표시한다. 다른 학교·종료된 명부를 이름 조회에 쓰지 않는다.

## 계약·권한 경계

- PR #34의 RPC 9개 및 `CollectionCommand`·`CollectionDetail` 계약을 그대로 사용한다. SQL 작성자가 새 함수·필드를 추가할 필요가 없다.
- `withdraw`, `open_correction` 기존 명령의 UI를 연결한다. 응답 미확정은 같은 명령·키로 복구한다. 새로고침 이후 복구를 제공하는 영속 저장소는 아니다.
- 여러 제출 단위에 같은 교사가 참여할 수 있다. 공동 작성자는 초안 저장만, 최종 제출·직접 철회는 책임 교사만, 정정 기간은 수합 관리자만 조작한다. 서버 권한 검사는 계속 필요하다.
- 관리자·검토자라는 이유로 미제출 초안을 조회하지 않는다. 실제 책임/관리 권한을 잃으면 보관한 관리 입력을 폐기한다.
- 현재 명부에서 빠진 대상은 자동 삭제하지 않는다. 화면에 남겨 직접 해제하거나 수정하게 하고 잘못된 단위로 저장하지 않는다.
- 서버 파일 검사, Storage 구성, 새 DB 적용은 이번 범위가 아니다. R1 준비 전에는 수합 작성이 계속 차단된다.

## 자동 검증

- 전체 `npm test`: **1,431건 통과**, PR #34 대비 **35건 추가**(단위 입력/SSR 16, 이력 요약/SSR 19).
- 수합 브라우저에는 공동 단위 저장, 명부 변경, 정정·철회 응답 유실, 철회 후 재제출, 이전 완료본 유지, 검토/철회 대상 교체, 같은 판 충돌 비교, 이미 검토된 원본, 역할 분리, 과거 파일 부모, 상세 조회 실패 이탈, 보완 응답판 철회 후 재개를 추가했다.
- 타입 검사·메인/독립 업무실 빌드·통합 이력/보호 경계 검사 통과.
- 합성 서버·파일과 로컬 Chromium 기준이며 실제 Supabase/Storage 및 다중 교사 실사용 증거가 아니다. 최종 브라우저 결과는 [누적 현황](PROGRESS.md)과 PR에 기록한다.
