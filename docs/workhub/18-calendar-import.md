# 11차 — 시트 일정 입력과 시범 운영 준비

2026-10-13 · [PR #18](https://github.com/EggPlayer88/daedong/pull/18) · `feat/workhub-calendar-import` · 기준: 10차 PR #17

## 교사가 할 수 있는 일

학교 일정의 **시트에서 가져오기**에서 스프레드시트 표를 붙여넣거나 UTF-8 CSV/TSV 파일을 선택한다. 열을 연결하고 오류·중복 후보를 확인한 뒤 각 행의 **내용·공유 대상 확인**을 눌러 기존 일정 편집기에서 등록한다. 표를 읽거나 검사하는 것만으로는 저장되지 않는다.

```text
표 붙여넣기 / UTF-8 파일
  → 열 연결 확인: 제목·시작일 필수, 모호한 열은 직접 선택
  → 행 검사 + 현재 열람 가능한 일정과 비교
  → 오류 행 수정 / 중복 후보 확인 / 정상 행 선택
  → 기존 일정 편집기: 내용·시간·열람 범위·홈 추천 대상 확인
  → 기존 CalendarAdapter.save: 접수·응답 복구
  → 완료 행 표시 + 학교 일정 재조회 → 남은 행 검토
```

합성 미리보기와 실제 연결 화면이 같은 컴포넌트를 사용한다. 실제 연결은 기존 7개 RPC 중 일정 목록·저장 계약을 이용하므로 새 RPC나 SQL을 요구하지 않는다. 실제 DB 적용 자체는 완료되지 않았으며, 기존 연결 준비 상태에서는 먼저 DB 인계 절차를 진행해야 한다.

## 입력·중복·저장 계약

| 항목 | 실제 동작 |
|---|---|
| 처리 한도 | 텍스트 250,000자, 자료 200행, 30열, 파일 1MB. 초과분을 자르지 않고 거부 |
| 파일/구분자 | UTF-8, BOM·CRLF, CSV/TSV 인용 셀·쉼표·탭·줄바꿈·큰따옴표. 모호한 구분자는 직접 선택 |
| 열 연결 | 원본 ID·제목·시작일·종료일·시작/종료 시간·장소·설명. 정확한 별칭만 제안, 중복 별칭은 미지정 |
| 날짜 | `YYYY-MM-DD`, `YYYY.M.D`, `YYYY/M/D`. 실제 달력·윤년 검사, 연도 생략·시트 일련번호·수식 거부 |
| 시간 | 두 시간 모두 비면 종일. 그 외 시작/종료 `HH:mm` 필수, 날짜/시간 순서 확인 |
| 종료일 | 빈칸은 시작일과 같은 날. 종료일 포함이라는 기존 일정 계약 유지 |
| 입력 오류 | 필수 열·중복 연결·열 수·길이·날짜·시간을 행별 안내. 정상 행은 별도 검토 가능 |
| 표 내부 중복 | 같은 원본 ID 또는 같은 제목·기간·시간은 관련 행 모두 차단. 원본을 확인해 재입력 |
| 기존 후보 | 현재 열람 가능한 같은 제목·기간·시간의 원본만 후보 표시. 장소·설명은 식별 근거로 추정하지 않음 |
| 기본 초안 | `private`(나만 보기). 기존 편집기에서 공유 범위·홈 추천 대상을 확인해 변경 |
| 개별 등록 | 교사가 수정한 내용으로 기존 저장 경로를 호출. 원본 시트나 기존 일정 덮어쓰기·삭제 없음 |
| 부분 등록 | 실제 응답을 받은 행만 완료 표시. 첫 저장 후 원본/매핑 잠금, 오류 행은 별도로 다시 가져오기 |
| 조회 지연 | 읽기 취소 가능. 원본 유지, 늦은 응답 폐기. 다시 비교하기 전 미확인 행 등록 차단 |
| 조회 실패 | null·문자열·깨진 행·다른 학교 응답을 빈 목록으로 처리하지 않음. 기존 완료 행 유지 |
| 저장 불명확 | 기존 편집기의 같은 요청키 재확인. 입력·새 제출·두 창 닫기/Escape를 차단해 중복 등록 방지 |
| 종료 | 원본 표와 미등록 행이 사라짐을 확인. 등록 완료 원본은 유지. 학교 일정에 완료 건수 표시 |

표 내용은 가져오기 창의 메모리에만 유지한다. 검토 행은 20개씩 표시하며 원본 행번호와 검사 결과는 전체를 보존한다. 원본 ID는 이번 표에서의 검토용이며 서버 원장에 영구 저장되지 않는다. 합성 미리보기에서 실제 등록한 결과는 기존 합성 저장소의 보존 계약을 따른다.

중복 후보는 **검사 시점의 스냅샷**이다. 등록 시작 후에도 **기존 일정 다시 비교**를 사용할 수 있고, 비교를 다시 하면 이전 중복 인정 체크를 초기화한다. 타 교사의 동시 등록이나 비공개 일정까지 중복을 완전히 막는 기능은 아니다. 행 편집기에서 제목·시간을 바꾼 결과의 유사 일정 자동 판정도 제공하지 않는다.

## 코드와 검증

- `calendar/import-table.ts`: 파서·매핑·초안·후보 비교. 기존 `normalizeDraft` 재사용.
- `calendar/CalendarImport.tsx`, `import.css`: 읽기 취소·검토·페이지·완료 상태·재비교·고유 필드 이름.
- `calendar/EventEditor.tsx`: `initialDraft` 입력 추가. 기존 수정 원본이 우선하며 전달 객체를 복제한다.
- `calendar/CalendarPanel.tsx`: 진입점·이동/새로고침 보호·등록 후 재조회·종료 후 완료 안내.
- `scripts/export-workhub-preview.mjs`: 11차 합성 HTML. 운영 연결 코드는 내보내지 않는다.

전체 `npm test` **1,150건**(기존 1,119 + 도메인 25 + 실제 SSR 6), 타입 검사·기존/신축 앱 빌드 통과. Chrome 가져오기 **19개**, 기존 일정 저장 복구 8·공통 접근성 24·기본 구조 10·연결 11·홈 검색 12개를 통과했다. 실제 CalendarPanel의 시트 등록 왕복을 포함한 일정 보기 통합 시험도 통과했다.

실행 중인 Vite의 기존 업무 통합 10개, 독립 HTML 8개를 확인했다. 독립 HTML의 외부 HTTP 요청·브라우저 오류는 0건이다. 합성 시험과 기존 앱 연결 시험은 실제 Supabase/OAuth 검증을 대신하지 않는다. 이번 브라우저 수치는 재실행을 중복 집계하지 않았다.

Chrome 시험은 표 검사 중 쓰기 0건, 기본 개인 공개, 편집 후 저장, 기존 후보 인정, 부분 등록, 조회 실패/취소/늦은 응답, 접수 후 응답 유실·같은 키 재확인, 파일, 페이지, 일반/Shadow DOM 초점, 320px을 검사한다. 320px에서 대화상자 너비/스크롤 너비는 304/304px, 문서는 320/320px이었다. 실 화면읽기 프로그램과 실제 교사 과제는 별도 확인이 필요하다.

## 현재 시트 전환의 한계와 다음 단계

이 기능은 **개별 일정 입력 보조**다. C07 전체 시트 전환 완료로 판정하지 않는다. 다음 단계는 실제 시트 표본을 기준으로 안정 원본 ID 원장, 원본/마지막 반영/현재 사이트의 3방향 대조, 충돌 해결, 시험 반영·대조·오류 재시도, 자료 종류별 쓰기 기준 전환이다. Google Sheets 자동 연결·양방향 동기화·행 누락에 따른 자동 삭제는 이번 범위에 없다.

전체 공개 범위와 기능별 남은 과제는 [17-pilot-release-plan.md](17-pilot-release-plan.md), 실제 DB를 연결하는 선행 조건은 [16-pilot-db-activation.md](16-pilot-db-activation.md)를 따른다. 문서작성 AI·시간표는 제외하고 Claude 상담·개인 비서와 일반 파일 업무는 포함한다.

## 판단해서 정한 것

1. **행별 확인:** 검증된 편집기·저장 복구를 재사용하고 제목/날짜만으로 공유 대상을 자동 추정하지 않는다. 바꾸려면 가져오기 UI와 별도의 일괄 접수 계약부터 검토한다.
2. **개인 공개 기본:** 원본 표의 일정명으로 학교 전체 공개를 결정하지 않는다. 변경 위치는 `prepareImportRows`의 초안 생성부다.
3. **유한한 검토량:** 브라우저 입력·검토 부담을 제한한다. 학교 운영 한도가 아니며 변경 위치는 `IMPORT_LIMITS`, `MAX_FILE_BYTES`다.
4. **첫 저장 후 매핑 고정:** 완료 행과 원본 행의 대응을 유지한다. 수정 자료는 남은 행만 새로 검토한다. 변경 위치는 `CalendarImport`의 `savedCount` 잠금이다.
5. **읽기와 저장 구분:** 읽기는 취소해 늦은 결과를 버릴 수 있고, 저장 결과 불명확은 기존 접수 확인으로 처리한다. 실제 권한·서버 저장·인증 규칙은 변경하지 않았다.

SQL·인증·보호 자산·외부 서비스·비용·운영 공개 범위는 이 PR에서 변경하지 않는다. Claude 교차검토와 사용자 미리보기 확인 후 선행 PR부터 병합한다.
