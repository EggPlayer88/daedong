# 파일형 문서 수합 · 임시 파일 정리와 저장본 보호

2026-10-15 · Codex · 기준 PR #32 `b0e24dd` · `fix/workhub-file-lifecycle`

## 교사가 보는 변화

파일을 선택했다가 제거하거나 새 파일로 바꾸고, 작성을 취소하는 작업을 반복해도 사용하지 않는 임시 파일이 계속 쌓이지 않도록 보완했다. 검사에 성공한 새 파일로 선택 목록이 바뀐 뒤에만 이전 미저장 실물을 회수한다. 파일 검사 실패·취소·저장 실패 때는 계속 편집할 선택을 유지한다.

양식·공동 초안으로 한 번 저장한 파일은 보호한다. 현재 선택에서 제거하거나 제출을 정정해도 과거 저장·제출판과 같은 요청 재시도 결과에 들어 있는 원문을 지우지 않는다. 저장된 자료를 자동 파기하는 기능이 아니다.

## 구현과 판단

| 위치 | 처리 | 이유 |
|---|---|---|
| `files/FileControls.tsx` | 해당 선택기가 직접 취득한 파일만 추적, 목록에서 빠지거나 편집 종료 시 회수 요청 | 다른 화면·학교·공동 작성자의 파일을 추정 수집하지 않음 |
| `files/contracts.ts` / `preview-repository.ts` | 선택적 `retainSaved`로 저장한 실물 보호, 보호된 파일은 `discardStaged`에서 제외 | UI가 저장 여부를 추측하지 않게 함 |
| `workflows/store.ts` | 성공한 저장 결과와 복원된 원본의 파일 보호 | 화면 종료가 저장된 원문을 지우는 경합 방지 |
| 접수 결과 `receipts.result` | 이전 요청 결과의 파일도 보호 | 멱등 재시도가 과거 원문을 참조하므로 최신 초안만으로 수명을 정하면 안 됨 |

보호 기능이 없는 다른 저장소에는 자동 회수를 적용하지 않는다. 새 파일 검사에 필요한 여유 공간이 부족하면 교체를 거부하고 기존 파일을 유지한다. 공간 확보를 위해 저장본을 먼저 지우지 않는다. 모든 저장 이력을 유지하는 한, 보관된 자료 자체가 100MiB 기술 상한에 도달하는 경우는 남는다.

수명 관리는 현재 창의 합성 미리보기 저장소에 한정된다. 서버 Storage의 권한·보존 기간·임시 업로드 만료·악성코드 검사·접수 트랜잭션을 대신하지 않는다. 파일형 수합은 여전히 새로고침하면 초기화된다.

## 자동 검증

- `npm test` **1,331건 통과**, Python 건너뜀 없음. 기존 1,322건에 파일 수명 시나리오 9개를 추가했다.
- `npm run check:workhub`, 기존 앱·업무실 두 빌드 통과.
- 고정 Chromium 전체 회귀 **33개 파일 중 33개 통과**. 이번 실행에서 실패한 파일 없음.
- 파일 선택기 **19개 시나리오**(기존 15 + 새 4)는 개발 StrictMode로 effect의 초기 재실행까지 확인했다. 저장본 보존/미저장 교체·제거·종료·반복 선택을 실제 브라우저에서 검사했다.
- 기본 파일 수합 종단 **14개 시나리오**에서 공동 작성·저장 실패·보완·정정·실제 파일 바이트·ZIP을 확인했다. 오프라인 전달 HTML도 11개 검사를 통과했다.

브라우저 시험은 합성 명부·현재 창 저장소를 사용한다. 실제 Supabase 수합/Storage 왕복을 검증한 것은 아니다. 사람의 수동 사용 시험은 사용자 요청에 따라 통합 시험으로 모은다.

재검토할 핵심 경로:

1. 미저장 A 선택 → B로 교체 → 취소: A와 B 모두 회수.
2. 저장된 A → B로 교체 → 취소: A 보존, B 회수.
3. 저장 실패·버전 충돌: 선택한 파일을 유지하고 다시 저장 가능.
4. 공동 작성자 초안 → 책임자 제출 → 정정/철회: 양식과 과거 제출 파일·ZIP 유지.
5. 이전 저장 요청 재시도: 당시 파일이 실제로 남아 있음.
6. 교사/학교 전환·화면 해제·초기화와 늦은 검사 응답: 해당 편집의 미저장 파일만 회수.
7. 제거/선택 반복: 미저장 파일이 쌓이지 않고 용량을 다시 사용 가능.

## 누적 상태와 남은 작업

사용자 실행 결과로 R0 기반 SQL·7개 호환 함수·학교/관리자/학년도/학기 설정을 확인했다. 초기 설정 8개 검사와 전후 구조 지문 7개가 통과했고, 두 회원 표의 행 수는 각각 18로 유지됐다. 사용자가 대동여자중학교 표시와 업무실 진입을 확인했다. 이것은 자료 내용 전체 또는 파일 본문 보존을 증명하지 않는다. 일정·개인 업무 실제 저장/수정/재로그인, 기존 평가계획서 다운로드 시험은 합쳐서 진행한다.

수합 다음 개발 순서는 수합/파일 API 계약 및 비동기 저장 경계 정리 → Claude SQL 작성/검토 → 사용자 적용 → 서버 어댑터/Storage 연결 → 다중 교사·동시 편집·종단 오류 복구 검증이다. SQL·인증·공개 범위·기존 회원·외부 설정은 이번 PR에서 변경하지 않았다. 문서작성 AI와 시간표는 계속 보류한다.
