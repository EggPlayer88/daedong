# PR #34 화면 검토 후속 — 충돌 비교와 입력·요청 복구

작성: 2026-10-15 · 기준: PR #40 `6ad6694` · 작업: `fix/workhub-collection-recovery`

## 교사가 보는 변화

### 1. 다른 교사의 변경을 덮어쓰지 않는 비교

기존 비교에는 제목·안내·기한 등 일부 내용만 보였다. 이후 “내 입력 유지”를 선택하면 보이지 않은 검토 방식·담당 교사·필수 답변·숫자·파일 정책까지 예전 값으로 덮어쓸 수 있었다.

이제 수합 설정 11개 항목과 제출 답변 3개 항목을 모두 비교한다. 편집 시작 원본, 현재 서버, 내 입력을 대조해 다음 규칙을 적용한다.

| 변경 상태 | 편집에 반영할 내용 |
|---|---|
| 나만 변경 | 내 입력 |
| 다른 사람만 변경 | 현재 서버 내용 |
| 양쪽이 같은 내용으로 변경 | 같은 내용 |
| 양쪽이 서로 다르게 변경 | 교사가 현재 서버/내 입력 중 선택 |

- 검토 방식·검토 교사·추가/숫자 답변의 이름과 필수 여부·제출 구성·파일 설정과 양식까지 확인한다.
- 제출 단위/공동 작성자와 파일 목록/정책은 각각 묶음으로 비교한다. 배열 요소를 임의로 합쳐 잘못된 구성이나 허용 개수 초과를 만들지 않는다.
- 같은 이름의 파일이나 같은 수의 교사가 교체되어도 감지한다. 파일 식별 정보는 펼쳐 볼 수 있다.
- 모든 충돌 항목을 선택해야 **비교한 내용으로 편집 계속**을 누를 수 있다. 이 버튼은 저장하지 않는다. 저장 시 서버가 최신 버전을 다시 검사한다.
- 이미 저장 접수를 확인한 직후 더 최신 초안이 조회되면, 접수한 요청 원문을 `confirmedInput`으로 보관해 비교 기준으로 사용한다. v1→내 저장 v2→다른 사람의 되돌림 v3에서 v3를 보존한다. 서버 초안 객체를 추정 생성하지 않는다.
- 모바일에서는 서버/내 입력이 세로로 배치되며 라디오를 키보드로 선택할 수 있다. 바뀌지 않은 항목과 비교 기준 원본은 접어 둔다.

### 2. 결과가 불명확한 저장을 같은 요청으로 복구

기존에는 저장 응답이 끊긴 뒤 수합 준비가 해제되면 재확인 버튼까지 잠겨 새로고침 외에는 나갈 수 없었다.

- 이미 보낸 요청에 한해 **동일 요청 번호 + 동일 본문**으로 재확인한다. 준비 해제 중 새 수합/새 저장을 허용하는 변경이 아니다.
- 재확인의 `NOT_READY`는 입력·요청을 유지하고 준비 복구를 기다린다. `IDEMPOTENCY_CONFLICT`는 기존 기록과 다르다는 안내를 표시하며 새 번호로 자동 저장하지 않는다.
- 당장 확인하기 어렵다면 **입력 보관하고 다른 메뉴 이용**을 누른다. 탭 메모리에 입력·파일 작업 상태·원문·요청 번호를 남기며 업무실 내부 메뉴를 이용할 수 있다.
- 다시 수합을 열고 **보관한 입력과 요청 다시 열기**를 누르면 현재 접근 권한과 원본을 재조회한다. 결과가 확인되기 전에는 다른 저장을 막는다.
- 저장/업로드/내려받기 진행 중에는 보관을 실행하지 않는다.
- 미확정 요청을 없애는 “입력 버리기” 버튼을 새로 만들지 않았다. 이미 서버에 반영됐을 수 있기 때문이다.

### 3. 보관 메모리가 살아 있는 이동 범위

`ConnectedWorkspace` 안의 기존 메모리 저장소를 그대로 쓴다. 업무실 밖의 기존 앱 경로로 SPA 이동하면 이 저장소가 사라지므로, 보관 자료가 있을 때는 내부 이동과 외부 이탈을 구분한다.

| 행동 | 보관 상태에서의 동작 |
|---|---|
| 업무실 내부 메뉴·내부 링크·내부 뒤로가기 | 허용, 입력/요청 유지 |
| 기존 앱으로 같은 탭 이동·업무실 밖으로 뒤로가기 | 안내 후 차단 |
| 학교 선택 변경 | 차단 |
| 기존 앱 새 탭 열기 | 허용 |
| 새로고침·탭 닫기 | 브라우저 경고, 사용자가 떠나면 메모리는 사라짐 |
| 계정/권한 회수·실제 소속 변경 | 기존 보호 규칙대로 이전 자료 제거 |

**서버 저장 또는 재시작 복구가 아니다.** localStorage에 학교 입력이나 파일을 넣지 않는다. 사용자 강제 새로고침·브라우저 종료 뒤 복구는 이번 보장 범위가 아니다.

## 구현 경계와 판단해서 정한 것

| 판단 | 이유 | 변경/되돌림 위치 |
|---|---|---|
| 비교 로직을 별도 순수 모듈로 분리 | 화면 상태와 병합 규칙을 독립 검증 | `conflict-comparison.ts`, `CollectionInputComparison.tsx` |
| 필드 이름 목록을 타입 전체 키로 검사 | 새 필드가 비교에서 빠지면 타입 검사 실패 | `collectionComparisonLabels`, `answerComparisonLabels` |
| 묶음 비교 | 제출 책임·파일 한도 등 연관 규칙을 임의 조합하지 않음 | 비교 모듈의 `units`, `fileCollection`, `files` |
| 접수 원문을 별도 기준으로 보관 | 접수 직후 다른 변경을 예전 원본과 잘못 비교하지 않음 | `CollectionServerPanel.tsx`의 `confirmedInput` |
| 준비 해제 예외는 기존 요청 재전송만 | 중복 저장을 막으면서 접수 결과 확인 | 같은 파일의 `mutate` |
| 입력 보관은 기존 탭 메모리 | 학생/교사 자료의 영속 브라우저 저장 범위를 늘리지 않음 | 같은 파일의 `parkEditing`/`resumeEditing` |
| 내부 이동과 외부 이탈을 분리 | 전체 이동 잠금은 풀되 저장소 unmount로 인한 유실 차단 | `navigation.ts`의 `exitLocked`, `ConnectedWorkspace.tsx` |

이 수정은 SQL·RLS·파일 검사기·인증 게이트·회원 정보·모듈 공개 범위를 바꾸지 않는다. PR #34를 기반으로 누적된 #40 뒤에 별도 후속 PR로 제출한다. Claude SQL 브랜치의 소유권을 유지하며 병합은 사용자가 한다. 이 UI 수정에 별도 SQL 실행은 필요 없다.
