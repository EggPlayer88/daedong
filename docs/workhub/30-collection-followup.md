## 교사가 보는 변화

기본 파일 수합(#30)의 양식 배부 → 공동 초안 → 책임자 확인 → 제출 → 검토 → ZIP 흐름에 다음 세 가지를 보완했다. 저장·접수 규칙을 바꾸지 않고 담당자의 반복 입력과 제출판 혼동을 줄였다.

1. **교사마다 1부씩 일괄 추가**: 수합 만들기 3단계에서 현재 학교의 교사를 검색하고 선택한다. 검색을 바꿔도 선택은 유지되며, 기존 단위를 그대로 두고 개인별 책임 단위를 추가한다. 기존 책임자·지정 검토자는 후보에서 제외한다. 추가 직후 첫 새 단위 이름으로 초점이 이동한다.
2. **검토·보완·철회 이력**: 현재 제출판의 검토 결과만 현재 영역에 표시한다. v1에서 보완을 요청하고 v2를 제출하면 v1 의견은 이력에 남고, v2는 검토 대기로 표시된다. 남은 보완은 원래 판·사유·기한을 함께 보여 준다.
3. **파일 바꾸기**: 기존 파일을 먼저 제거할 필요 없이 새 파일을 선택한다. 검사에 성공한 경우에만 같은 자리에서 교체한다. 형식 오류·중복·취소·늦은 응답에서는 원래 첨부를 유지하며, 최대 첨부 개수에서도 교체할 수 있다.

새 요청은 계속 초안 저장 → 대상 확인 → 게시 절차를 거친다. 교사 선택이나 파일 교체만으로 저장·게시·제출되지 않는다.

## 구현 경계

- `CollectionReviewHistory.tsx` / `collection-review-history.ts`: 이미 접근을 확인한 단위 요약·제출판·명부만 받아 표시한다. 다른 단위의 이력을 섞지 않고 원본을 수정하지 않는다. 기존 제출 파일 이력도 유지한다.

- `WorkflowPanel.tsx`: 두 화면을 연결하고 일괄 추가 후 초점을 처리한다.
- SQL·스키마·인증·회원·메뉴 공개 범위·AI·시간표·외부 설정은 변경하지 않았다.
