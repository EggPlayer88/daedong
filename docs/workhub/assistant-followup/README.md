# 일정 이어 쓰기와 내 할 일 변경

AI 옆자리에서 이미 입력한 일정 내용을 다시 적지 않고, 기존 개인 할 일은 변경할 한 건을 골라 처리한다. 두 동작은 모델을 호출하지 않고 기존 일정·업무 권한과 저장 경로를 사용한다.

| 교사가 입력하는 예 | 다음에 보이는 화면 | 저장 시점 |
|---|---|---|
| “내일 회의 잡아줘” → “오후 3시부터 4시까지” | 처음 받은 제목과 날짜를 유지하고 시간만 묻는다. 다 채우면 나만 보는 일정 초안이 열린다. | 일정 편집기에서 저장 |
| “제출 자료 확인을 금요일까지로 바꿔줘” | 내 할 일 후보를 고르면 기존 기한과 새 기한을 나란히 볼 수 있다. | 확인한 변경 저장 |
| “제출 자료 확인 메모를 부장 검토로 바꿔줘” | 선택한 할 일에서 메모만 교체한다. 제목과 기한은 보존한다. | 확인한 변경 저장 |
| “제출 자료 확인을 완료해줘” | 선택한 할 일의 상태가 어떻게 바뀌는지 보여준다. | 확인한 할 일 완료 |

일정은 학교의 기준일로 날짜를 풀고, 종일을 명시하면 시각을 요구하지 않는다. 잘못된 시각이나 앞선 답과 다른 값은 원본을 덮어쓰지 않는다. “취소”는 미저장 대화만 닫는다. 같은 학교·소속·기준일이면 창 복귀 후에도 탭에서 입력을 이어갈 수 있고, 기준일이나 권한이 실제로 바뀌면 이전 답을 재사용하지 않는다. 반복 일정이나 여러 날에 걸친 일정, 공유 대상은 기존 편집기에서 확인한다.

할 일은 기존 개인 업무 검색 범위에서 찾는다. 한 건만 나와도 사용자가 선택해야 하며, 동명 업무에는 구별할 표시가 붙는다. 선택한 뒤 원본을 다시 조회해 소유자·학교·소속·업무 번호·판을 비교한다. 원본이 바뀌면 최신 항목을 다시 선택하게 하고, 저장 결과가 불확실하면 같은 요청 번호와 변경 내용으로만 확인한다. 새 할 일 생성에 사용하는 기존 AI 제안 경로는 바뀌지 않았다.

## 자동 검증과 배포

- 새 단위 시험: 일정 대화 13건, 개인 업무 변경 11건. 누락 필드, 잘못된 날짜·시각, 대상 제한, 원본 판·저장 결과, 일반 문체 편집 요청과의 구분을 검사한다.
- 관련 Chrome 시험: AI 작업 화면 19건, 앱 화면 간 연결 15건, 전체 검색 11건. 동명 업무 선택, 취소, 동시 변경, 응답 유실 후 같은 번호 복구, 창 복귀와 학교·권한·날짜 변경, 안내문의 문체 수정이 기존 AI 경로를 쓰는 경우를 포함한다.
- [일정 대화 화면](screenshots/calendar-followup.png) · [할 일 확인 화면](screenshots/task-review.png). 두 화면은 합성 학교로 실행한 실제 앱의 브라우저 시험에서 캡처했다.
- 사용자 병합 후 Vercel Production 배포만 필요하다. SQL 실행·서버 변수 설정·권한 변경은 없다. 브라우저 시험은 운영 DB를 변경하지 않고 외부 AI를 호출하지 않는다.
