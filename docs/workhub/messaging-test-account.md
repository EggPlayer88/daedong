# 메신저 임시 계정 로그인과 연결 순서

2026-10-24. 실제 교사 회원 연결은 보류하고, 사용자가 만든 시험 계정 한 개로 수신·읽음·HWPX 다운로드를 확인한다.

## 이번 앱 변경

- 로그아웃 상태에서 `/?login=email`로 접속하면 이메일·비밀번호 로그인 화면을 제공한다.
- 기본 주소는 기존 Google 로그인 화면을 유지한다. URL 값은 화면 선택일 뿐 접근 권한이 아니다.
- 공통 Supabase 클라이언트의 `signInWithPassword`를 사용하고, 기존 AuthProvider·가입 승인·역할·학교 소속 검사를 그대로 거친다.
- 새 계정을 만들거나 승인·역할·학교 소속을 자동 부여하지 않는다. SQL, 인증 제공자 설정, 메뉴 공개 범위는 바꾸지 않는다.
- 비밀번호 입력란은 요청 직후 비운다. 앱이 비밀번호를 URL·로그·브라우저 저장소에 기록하지 않는다. 인증 성공 후 Supabase가 관리하는 세션은 기존 정책을 따른다.

## 진행 순서

1. PR 자동 검사와 미리보기를 확인한 후 사용자가 병합한다. Vercel Production의 새 커밋이 Ready인지 확인한다.
2. 기존 관리자 창은 유지한다. 별도 브라우저 프로필 또는 시크릿 창에서 `https://daedong-school.vercel.app/?login=email`을 연다. 같은 프로필의 새 탭은 로그인 세션이 분리되지 않는다.
3. 사용자가 보관한 시험 계정 이메일과 비밀번호로 로그인한다. 비밀번호를 채팅으로 보내지 않는다. 미승인 계정의 정상 첫 화면은 **승인 대기중입니다**이다.
4. 관리자 창의 **사용자 관리 → 가입 대기**에서 정확히 그 시험 계정 한 건만 확인한다. 승인과 학교 소속 연결, 업무실 접근 권한은 서로 다른 단계다.
5. 아래 권한 범위를 설명하고 사용자가 선택한 뒤에만 역할·학교 연결 실행문을 준비한다. UID·이메일·현재 상태를 읽기 전용으로 대조하고, 기존 값·시험 종료 후 복구 방법을 함께 기록한다.
6. 학교 연결은 기존 P9의 후보 승인 → 화면 미리보기 → 확정을 사용한다. P9-03은 후보 UID 목록을 교체하므로, 이미 승인된 목록을 먼저 조회하고 보존해야 한다. 가입 승인 전에는 이 양식을 실행하지 않는다. 다른 실제 교사는 새로 포함하지 않는다.
7. 수신자 목록에서 시험 계정이 보이는 것을 확인한 뒤 관리자 → 시험 계정으로 메시지 한 건을 전송한다. 시험 계정에서 읽고 HWPX를 내려받아 원본과 비교한다. 관리자 창에서도 읽음 상태를 확인한다.
8. 시험 종료 시 별도로 승인받은 절차로 시험 소속·역할·로그인 가능 상태를 회수한다. 메시지·첨부 증거를 지우거나 계정을 즉시 삭제하지 않는다.

## 권한 단계에서 반드시 구분할 것

현재 `modules.js`, `WorkhubPage.jsx`, R0 `legacy_gate`, P2 `p2_member_reachable`은 모두 `public.users.role = 'superadmin'`을 요구한다. 학교 소속만 있는 일반 교사는 업무실이나 메신저 수신 대상이 되지 않는다.

기존 경로로 시험하려면 사용자가 직접 관리하는 시험 계정에 임시 superadmin 역할과 활성 학교 소속이 필요하다. **이 역할은 메신저 전용 권한이 아니며 기존 관리자 기능에도 영향을 준다.** 업무실의 학교 관리 역할을 추가하지 않더라도 기존 시스템의 superadmin 권한은 생긴다. 적용 전 범위·기간·회수 절차에 대한 별도 확인이 필요하다. 이번 PR에서는 부여하지 않는다.

시험 계정을 메신저에만 제한하려면 앱·서버·DB의 범위를 제한하는 별도 설계가 필요하다. 메뉴만 노출하거나 일반 교사 역할을 관리자라고 간주해서 우회하지 않는다.

가상의 이메일에는 수신함이 없으므로 Send magic link나 이메일 비밀번호 재설정으로 로그인할 수 있다고 안내하지 않는다. 시험용 계정의 비밀번호는 사용자가 보관한다.

## 검증

- 전체 `npm test` 5,136건과 `npm run build` 통과. 제한 환경에서 임시 폴더 권한으로 실패한 첫 실행은 정상 권한에서 전체 재실행해 확인했다.
- `tests/test_email_login.mjs`: 실제 로그인 화면 렌더·공통 클라이언트 호출·인증 실패 전파 5건.
- `tests/browser/email-login.mjs`: 실제 App/AuthProvider에서 기본 로그인, 중복 접수, 비밀번호 비우기, 오류 안내, 좁은 화면, 승인 대기, 일반 교사 업무실 차단 8건. DB·인증 응답은 합성이다.
- 실제 계정 로그인·가입 승인·학교 연결·메시지 수신 시험은 배포 뒤 별도로 진행한다.

## 판단해서 정한 것

- 기본 로그인 화면에 버튼을 추가하지 않고 별도 안내 주소에서 제공한다. 기존 교사의 진입 화면을 유지하면서 이미 생성한 이메일 계정을 사용할 수 있기 때문이다. 되돌릴 때는 로그인 화면과 공통 export를 되돌리고, 운영 계정은 별도로 정리한다.
- 계정의 이름·UID·비밀번호·승인 실행문은 앱 코드에 넣지 않는다. 계정별 운영 절차와 앱 로그인 구현을 분리한다.
