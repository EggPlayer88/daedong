## 기존 앱 초기 로딩

아래 표는 동일 설치 환경에서 **통합 직전 코드와 I1 구조 개선 후 코드**를 비교한 Vite 출력이다. 운영 main과의 비교가 아니다. 네트워크 실측이나 체감 속도 측정은 아니다.

| 산출물 | 변경 전 | 변경 후 |
|---|---:|---:|
| 첫 JavaScript | 495.77 kB | 491.26 kB |
| 첫 JavaScript gzip | 148.16 kB | 146.61 kB |
| 첫 CSS | 13.70 kB | 9.11 kB |
| 첫 CSS gzip | 4.59 kB | 2.48 kB |

Claude의 PR #23 교차검토에서는 운영 main `6165bcc`와 통합본 `b49f6e5`를 같은 환경에서 별도로 빌드했다. 첫 JavaScript는 **488.05 → 491.26kB, 약 3.21kB 증가**(gzip 약 1.4kB 증가), 첫 CSS 증가는 0이다. 이 수치는 Claude 검토 보고서의 측정값이며, 위 통합 전후 개선량과 구분한다. 운영 main보다 첫 로딩이 줄었다거나 실제 체감 속도가 개선됐다는 근거로 쓰지 않는다.

작은 popstate 전달기는 Router보다 먼저 등록한다. 업무실을 열지 않았을 때는 구독자가 없어 이동을 막지 않는다. 전체 탐색 코드와 글꼴 CSS를 필요할 때 불러온다. [탐색 브라우저 시험](../../../tests/browser/workhub-navigation.mjs)은 실제 ESM 분리 청크로 기존 화면→업무실 지연 로딩→입력 중 뒤로가기→편집 취소 후 이동을 확인한다.

검색 데이터 변환은 React 편집기 대신 순수 표시 함수를 사용한다. [검색 계약 시험](../../../tests/test_workhub_search_sources.mjs)은 실제 번들 입력 그래프에 React/TSX 화면이 들어오면 실패한다.

## 이번 통합에서 확정하지 않은 것

- 실제 Supabase 적용, Google OAuth 왕복, 실사용 회원/학교 연결.
- 최신 v1.1 DDL/RLS/Storage의 구현·격리·복원/부하 검증.
- 수합/학생 자료의 실제 서버 연결, 메신저 구현, Claude 호출.
- 시간표 엔진 및 확정·교체 흐름의 구현/통합.
- 실제 iOS/Android 키보드·안전 영역·보조공학, 교사 과제 실증.
- 자정 기준일 전환과 실학교 TSV 표본의 추가 검증.
- Claude의 통합본 교차검토와 사용자 화면 승인.

기존 SQL 시험은 과거 제안의 회귀이며 통합 DB 설계 구현 완료로 계산하지 않는다. 기존 공개 범위·인증 정책·운영 배포 설정을 이 단계에서 확대하지 않았다.
