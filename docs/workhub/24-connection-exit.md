# 연결 오류 화면의 이동 안내와 입력 폐기

기준: PR #24 병합 커밋 `78e2392` · 2026-10-13

학교 연결 재조회가 실패하면 작성 중 입력을 보호하느라 기존 메뉴 이동이 막히지만, 이유가 화면에 나오지 않았다(Claude R1). 오류·연결 확인 화면에도 이동 차단 이유와 다음 행동을 표시한다.

| 현재 보관 상태 | 교사가 할 수 있는 행동 |
|---|---|
| 저장 전 입력만 있음 | 연결 재확인, 입력 폐기 확인 후 기존 메뉴 이용, 새 탭에서 기존 메뉴 이용 |
| 저장 결과가 불확실한 요청 있음 | 현재 탭을 유지하고 재연결 후 같은 요청으로 결과 확인, 새 탭에서 기존 메뉴 이용 |
| 보관한 입력·요청 없음 | 기존 메뉴로 바로 이동 |

폐기는 확인을 거친 뒤 현재 탭의 미전송 업무·일정 입력과 시트 가져오기 진행 정보만 비운다. 서버 자료는 삭제하지 않는다. 자동으로 이동하지 않고 메뉴 잠금만 해제하며, 해제 사실을 표시한다. 확인 시작 시 ‘계속 보관’, 취소 시 원래 버튼, 완료 시 결과 안내로 초점을 옮긴다.

미확정 요청은 이미 서버에 저장됐을 수 있으므로 폐기를 제공하지 않는다. 확인창을 연 이후에도 실행 직전 요청 저장소를 다시 검사한다. 오류·로딩 중 미확정 요청만 남은 경우도 기존 메뉴 클릭과 뒤로가기를 보호한다. 새 탭 이용은 현재 탭을 유지한다.

요일 불일치 문구도 ‘입력한 요일 / 실제 날짜’ 형식으로 정리했다. 날짜 판정 규칙은 동일하다.

## 검토 초점

1. 업무를 작성하고 연결 재조회를 실패시킨 뒤 기존 메뉴·뒤로가기를 누르면 현재 화면에 남고 이동이 막힌 이유가 보이는가?
2. 폐기 확인에서 ‘계속 보관’을 선택하고 재연결하면 제목·메모가 돌아오는가?
3. 폐기를 확정하면 자동 이동 없이 안내가 나오고 메뉴를 이용할 수 있으며, 다시 들어가도 버린 초안이 돌아오지 않는가?
4. 응답만 유실된 저장 요청은 폐기를 제공하지 않고, 재연결 후 같은 키·같은 내용으로 확인해 한 번만 저장되는가?
5. 일정 미확정 요청과 별개 업무 초안이 함께 있어도 각각 복구되는가?
6. 보관할 정보가 없는 오류·확정된 권한 회수는 이동을 막지 않는가?
7. 새 탭 이용, 320px 키보드 조작, 390px 확인 안내가 작동하는가?

## 검증과 재실행

- 변경 전 기준본의 ‘초안 이동 차단 안내 없음’과 ‘미확정 요청만 남으면 SPA 이탈 가능’을 메모리 번들에서 재현했다.
- `npm test`: **1,227건** 통과(Python 포함). 새 연결 복구 SSR 4건 포함.
- `npm run build`, `npm run build:workhub`: 타입 검사와 두 앱 빌드 통과.
- 새 브라우저 시험 **9건** 통과. 실제 연결 컴포넌트·라우터에 합성 RPC를 연결한다.
- 고정 Chromium 전체 회귀 **29/29 파일** 통과. 320px/390px 키보드·초점 검증과 390px 화면 3장 육안 확인을 마쳤다.

저장소 루트에서 기존 의존성과 Chromium을 준비한 뒤 실행한다.

```bash
npm test
npm run build
npm run build:workhub
PLAYWRIGHT_CHANNEL=chromium node tests/browser/workhub-connection-exit.mjs
PLAYWRIGHT_CHANNEL=chromium npm run test:workhub:browser
```

Windows PowerShell:

```powershell
npm test
npm run build
npm run build:workhub
$env:PLAYWRIGHT_CHANNEL = 'chromium'
node tests/browser/workhub-connection-exit.mjs
npm run test:workhub:browser
```

실제 운영 DB·OAuth·실기기·스크린리더 검증을 대신하지 않는다. 현재 탭 메모리에 보관하며 새로고침·탭 종료 후 복구는 제공하지 않는다. 인증·권한 판정, DB·SQL, 메뉴 공개 범위, AI 호출, 시간표는 변경하지 않았다.
