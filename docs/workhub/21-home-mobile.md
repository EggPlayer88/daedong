# 업무혁신시스템 14차 — 홈 정보량과 모바일 동선 개선

2026-10-13 · 기준 PR #20 · 작업 브랜치 `feat/workhub-home-mobile`

## 이번 작업

홈에서 오늘의 일정과 다음 행동을 먼저 찾게 하고, 휴대폰에서 긴 메뉴를 지나지 않고 본문에 도착하도록 정리했다. DB 구축·시간표·문서작성 AI는 계속 보류한다. 저장·인증·회원·권한·메뉴 공개 계약과 Claude API 설정은 변경하지 않았다.

| 구분 | 변경 전 문제 | 최종 화면 |
|---|---|---|
| 홈 읽기 순서 | 개인 업무와 수합을 지난 뒤 오늘 일정이 나옴 | 오늘 일정 → 내 할 일 → 수합 → 다가오는 7일. DOM 순서와 모바일 표시 순서가 같다 |
| 오늘 일정 | 당일 관련 일정 수에 따라 홈 길이가 계속 증가 | 먼저 3개, 전체 건수와 “모두 보기”를 표시. 같은 화면에서 펼치고 원본을 열 수 있다 |
| 다가오는 일정 | 많은 행사 내용이 홈을 차지 | 먼저 3개와 전체 건수, 기존 전체 관련 일정 이동 제공 |
| 일정 카드 | 시간·제목·장소·추천 이유가 여러 줄로 반복 | 제목과 시간·장소 중심. 여러 날 범위와 개인 일정 표시는 유지하고 상세에서는 전체 정보 제공 |

| 수합 | 총수·4역할 수·그룹명·역할·설명이 반복 | 처리/대기 총수와 행동을 우선. 역할별 현황은 펼침 영역으로 이동 |
| 수합의 중요한 상태 | 안내를 줄일 때 보완 의무를 놓칠 위험 | 남은 보완·기한 초과·완료본/현재판·최종 책임자 구별을 유지 |
| 모바일 상단 | 메뉴·AI·설정·학교 선택이 본문을 밀어냄 | 브랜드·현재 학교·검색으로 축소 |

| 보조 기능 | 설정·계정 맥락이 본문보다 먼저 노출 | 더보기에서 수합·학생·AI 준비 안내·화면 설정·학교 선택 |
| 설정과 접근성 | 새로운 UI가 기존 설정/입력 보호와 충돌할 수 있음 | 3스킨·간격·큰 글자, 작성 중 이동 잠금, 대화상자 전환과 초점 복원 검증 |

홈의 기본 화이트·차콜·블루 및 Pretendard 글꼴은 유지했다. AI 비서는 연결 준비 안내이며 실제 대화 기능을 추가한 것은 아니다.

## 실제 화면 측정

동일한 합성 자료, 새 브라우저 맥락, 390×844px, 기본 스킨의 독립 HTML로 비교했다.

- 13차: 오늘 일정 제목의 화면 상단 기준 위치 **약 1,342px**.
- 14차: **약 275px**. 첫 화면에서 오늘 일정을 확인할 수 있다.
- 14차의 가로 스크롤 폭은 390px으로 화면과 같았다.
- 하단 메뉴 높이 69px, 첫 세 업무와 더보기는 한 번 누르면 접근한다. 더보기에서 보조 기능은 한 번 더 누른다.

특정 합성 화면의 배치 측정이다. 전체 업무 처리 시간이 줄었다는 실사용 성과 측정으로 해석하지 않는다.

근거: `GPT작업/개발14차_검증/독립검토/baseline-390-layout.json`, `home-layout-final.json`, `home-390-viewport.png`, `home-1440-final.png`, `mobile-more-final.png`.

## 입력·초점·권한 유지

- 탐색 landmark는 하나이며 현재 페이지를 표시한다. 연결 모드의 업무 화면은 기존 오늘·일정·내 업무만 허용한다.
- 더보기는 네이티브 dialog이며 내부 Tab/Shift+Tab을 순환한다. Escape·닫기는 하단 더보기로, 화면 선택은 본문 제목으로 초점을 연결한다.
- 더보기에서 화면 설정·AI를 열 때 기존 dialog를 먼저 닫는다. 동시에 두 개의 초점 함정을 만들지 않는다.
- PC↔모바일 전환에서 숨겨진 버튼/대화상자에 초점을 남기지 않는다.
- 입력 중 화면/학교 이동 보호는 유지한다. 외형 설정은 입력을 보존하며 사용할 수 있다.
- 화면 하단에 메뉴·safe-area 여백을 확보한다. 일반 DOM과 기존 앱의 ShadowRoot 두 형태를 검증했다.
- 일정 조회 실패에도 개인 업무와 수합의 독립된 표시를 유지한다. 실패를 0건으로 오인하게 만들지 않는다.
- 이전 단계의 저장 결과 복구는 현재 탭 메모리 범위이며, 이번 UI 변경이 영구 복구 기능을 추가한 것은 아니다.

## 판단해서 정한 것과 조정 위치

1. **오늘 일정을 첫 읽기 영역으로 둔다.** 모바일에서 지금 필요한 정보를 찾기 위함이다. `calendar/CalendarPanel.tsx`, `home-dashboard.css`에서 순서·열·상한을 조정한다. 날짜별 추천/권한 선별 함수는 그대로다.
2. **오늘/예정 일정은 각 3개부터 표시한다.** 전체 건수와 원본 접근은 보존한다. 개인 업무/수합의 기존 선별 상한 4개는 유지한다. 일정의 기존 정렬을 유지했으므로 여러 날 행사가 먼저 나올 수 있다.
3. **반복 설명을 접고 행동에 필요한 상태를 남긴다.** `workflows/WorkflowPanel.tsx`의 HomeWorkSummary와 `home-summary.css`가 조정 위치다. 보완·기한·대기 구분을 숨기는 방식으로 되돌리지 않는다.
4. **모바일 4칸 탐색을 고정한다.** 모든 기능을 아래에 나열하면 글씨와 터치 영역이 작아지므로 보조 메뉴를 더보기로 묶었다. `app/WorkspaceShell.tsx`, `mobile-navigation.css`에서 조정한다. 새 페이지/권한은 만들지 않았다.
5. **학교 전환은 더보기로 옮긴다.** 현재 학교 이름은 상단에서 계속 보이며 전환에 쓰는 select는 하나만 렌더한다.
6. **기준일을 클라이언트 날짜로 임의 교체하지 않는다.** 서버 맥락의 날짜는 소속 권한 판정과 연결되어 있다. 이번에는 기준일을 명시하고 자세한 표시 규칙만 접었다. 자정 갱신은 연결 재검증과 함께 후속 검토한다.
7. **간격 설정을 새 홈에도 반영한다.** 고정 여백 때문에 촘촘한 설정이 적용되지 않던 초안은 CSS 변수로 보완했다.
8. **검증을 바뀐 사용자 행동에 맞춘다.** 홈 제목·일정 이동 버튼이 조회 중에도 보이므로 재조회 검사는 실제 일정 도착을 기다린다. 과거 카드의 테두리 기대값은 새 평면 배치/CSS 적용 검사로 바꿨다. 데이터·권한·복구 단언은 유지했다.

## 검증

- `npm test`: Python 포함 **1,201개 통과**.
- TypeScript, 기존 앱·신축 앱 빌드 통과.
- 고정 Chromium 전체 **26/26 파일 통과**. 결과: `개발14차_검증/chromium-verified/summary.json`.
- 전달용 HTML 자체의 오프라인 검사 **11개 통과**, 글꼴 내장·외부 HTTP 요청 0·예상하지 않은 브라우저 오류 0.
- 신규 홈 배치 7개, 모바일 탐색 14개(일반 DOM/ShadowRoot), 수합 단위 회귀 4개와 홈·검색 회귀 1개를 추가했다.
- 모바일 320·390px, 큰 글자, 낮은 화면 높이, 다섯 화면, 설정/AI 전환, 학교 맥락, 작성 중 보존을 검증했다.
- 독립 재검토에서 모바일 14개를 다시 실행했으며 추가로 차단할 중대한 오류는 발견하지 못했다.
- iPhone/Safari·Android 실기기의 키보드와 안전 영역은 별도 실측이 남아 있다. 실제 학교 DB 왕복이나 전체 접근성 인증을 완료했다는 뜻은 아니다.
