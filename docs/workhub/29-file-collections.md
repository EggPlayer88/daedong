# 기본 파일형 문서 수합 구현·검토 인계

2026-10-14 · Codex 담당 · 기준 main ebdc064 (#25) · DB 적용 없음

## 구현 범위

담당자가 양식을 배부하고, 교사가 작성한 파일을 제출하며, 담당자가 제출판을 검토하고 모아 받는 직접 파일형 수합을 구현했다. 기존 글·숫자 수합의 초안·책임 제출·검토·보완·정정·철회·완료본 구조를 확장했다.

진입점은 개발 서버 또는 독립 HTML의 **자료 수합 → + 파일 수합 만들기**다. 운영 서버의 업로드 기능으로 공개한 것이 아니다. 인증·회원 데이터·메뉴 공개 범위·SQL·외부 설정은 변경하지 않았다. 별도 검토 중인 #26~#29 코드는 이번 브랜치에 포함하지 않는다.

## 이용 순서

1. 담당자가 제목·안내·마감·검토 여부·제출 단위/책임자를 정한다.
2. 양식을 선택하고 기본 검사·대상 미리보기를 확인한다. 양식은 선택 사항이고 제출 파일 필수 여부를 정할 수 있다.
3. 요청 초안을 저장한다. 게시 전에는 작성자만 보며 대상 확인 후 게시하면 제출 의무가 생긴다.
4. 대상 교사는 양식을 내려받아 외부 프로그램에서 작성하고 제출할 파일을 선택한다.
5. 공동 초안을 저장한다. 책임자는 저장한 파일을 확인했다는 체크 후 최종 제출한다. 선택·저장만으로 제출되지 않는다.
6. 공동 작성자는 초안을 고칠 수 있지만 최종 제출하지 않는다. 충돌 시 최신 내용·파일명과 비교하고 내 입력을 보존한다.
7. 검토 없는 수합은 접수 시 완료본이 된다. 검토형은 지정 교사의 검토 후 완료본이 된다. 새 정정판을 제출해도 이전 완료본은 보존한다.
8. 현재 제출·과거 제출판 파일을 각각 내려받는다.
9. 담당자는 **제출 파일 모아 받기 → 최신 현황으로 묶음 준비 → ZIP 내려받기**를 사용한다. 기본은 완료본, 최신 제출본(검토 대기·보완 요청 포함)은 명시 선택이다.
10. ZIP에 파일과 CSV 현황표를 담는다. 미제출·완료본 없음·첨부 없음도 현황표에 남기고 미제출 초안은 제외한다. 일부 읽기에 실패하면 묶음 제공을 막고 실패 항목을 다시 확인한다.

## 저장과 검사

- 파일 바이트와 파일형 수합 전체는 **현재 창 메모리**에만 보관한다. 새로고침·초기화 시 사라진다. 합성 파일로 체험한다.
- 파일명·SHA·참조뿐 아니라 연결된 요청·단위·초안·제출·검토·보완·철회·접수 결과도 localStorage에서 제외한다. 기존 글·숫자 수합과 개인 업무 저장은 유지한다.
- 미리보기 정책: PDF/HWP/HWPX/DOCX/XLSX/PPTX, 파일당 10MiB, 최대 3개. **운영 정책 확정값이 아니다.** 정책/저장소를 주입하지 않은 화면은 파일 수합 생성 버튼을 제공하지 않는다.
- 빈 파일, 확장자, 이름, 크기·개수, MIME, 기본 파일 표식, 이름·내용 중복을 검사한다. SHA-256·크기를 기록하고 참조와 실제 보관 파일의 일치를 확인한다.
- 기본 표식 검사는 전체 문서 유효성·압축 내부 구조·악성코드/매크로 검사와 다르다. 서버 보안 검사 완료로 안내하지 않는다.
- 창당 100MiB, 파일 작업 15초, ZIP 512항목은 메모리 구현 기술 상한이다. 100단위 × 3파일 + 현황표를 수용한다. ZIP은 비압축 STORE 방식이다.
- ZIP 이름은 순번·단위·제출판·원본명으로 구분한다. 긴 이름도 확장자를 보존하며 경로문자 제거·UTF-8·CRC를 적용한다. CSV에 실제 ZIP 내부 이름·SHA를 기록하고 수식 실행을 방지한다.

## 오류 처리

| 상황 | 처리 |
|---|---|
| 여러 파일 선택 중 실패 | 새 선택 전체를 반영하지 않고 기존 목록 유지, 이번 배치 실물만 회수 |
| 취소·교사/학교 변경·언마운트 | 늦은 결과 반영과 새 임시 실물 잔류 방지 |
| 초안 저장 실패 | 선택 파일과 입력 유지, 제출 완료 표시 없음 |
| 제출 실패 후 재시도 | 동일 요청의 중복 제출판 생성 방지 |
| 공동 초안 충돌 | 최신 파일명/본문 비교, 내 입력 유지, 재확인·저장 |
| 파일 변경·저장·외부 초안 변경 | 파일 확인 체크를 다시 요구 |
| 실물 유실·참조 변조·범위 불일치 | 읽기/저장 거부 |
| 묶음 일부 읽기 실패 | ZIP 버튼 없음, 실패 항목 재확인 |
| 준비 중/후 제출·검토·철회 변경 | 준비 계획 무효화, 재준비 요구 |
| 다운로드 직전 원본/소속 변경 | 모든 원본을 다시 읽기 확인한 뒤 제공 차단 |
| 다운로드 취소·화면 해제 | 뒤늦은 다운로드 요청 차단 |

성공 안내는 “다운로드를 요청했습니다”이며 디스크 저장 완료를 단정하지 않는다.

### Claude 재검토 항목

1. 파일 요청 생성·양식 첨부·초안 저장·게시.
2. 공동 작성자 첨부→책임자 이어쓰기→확인→제출.
3. 중복·크기·빈 파일·확장자 불일치와 기존 선택 보존.
4. 저장 실패·초안 충돌·늦은 취소 응답에서 입력/제출판 보존.
5. 완료 v1 뒤 v2 접수: 완료 ZIP은 v1, 최신 ZIP은 v2.
6. ZIP 준비 후 제출/검토 변경: 재준비 요구.
7. 일부 읽기 실패: 부분 묶음 없음, 실패 재확인.
8. 390px·키보드·취소 후 초점.
9. 새로고침 후 파일 수합 제거, 글·숫자/개인 업무 보존.
10. 인증·SQL·보호 자산·메뉴 공개 범위 변경 없음.

## CI 환경의 비동기 검사 보완

첫 Linux CI에서는 새 파일 시험은 통과했지만 기존 일정 보기와 수합 입력 시험 2곳에서 화면 반영 전 상태를 읽었다. 일정의 시트 입력 후 잠금은 자식 effect→부모 상태→잠금 콜백을 거치므로 잠금 완료 조건을 기다린 뒤 동일 assertion을 유지했다. 수합 시험의 actor 전환은 fixture의 소속·요청·호출 토큰이 실제 React commit에 반영된 것을 기다린다. 고정 시간 sleep이나 기대 결과 완화 없이 검사 시작 시점만 바로잡았고 제품·권한 코드는 변경하지 않았다. 해당 로컬 재검증과 최신 PR 전체 CI 결과를 별도로 확인한다.
