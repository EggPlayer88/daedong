# 학생·수업·관찰 기록 로컬 계약 미리보기

실제 학생 자료·운영 DB·AI 호출 없이 합성 자료로 실행한다. 학생 모듈은 `apps/workhub/src/students/` 안에서만 구현하며 Claude의 시간표 엔진과 기존 운영 앱을 수정하지 않는다.

## 연결 인터페이스

```tsx
import { StudentsPanel, createStudentStore } from './students'

const store = createStudentStore({
  members: memberships,
  date: basisDate,
  snapshot: savedSyntheticSnapshot, // 없으면 가상 명부·승인 배정 생성
  onChange: snapshot => saveSyntheticPreview(snapshot),
})

<StudentsPanel member={currentMember} members={memberships} date={basisDate} store={store} />
```

`exportState()`는 합성 자료 스냅샷, `reset()`은 초기 가상 명부로 복원, `setContext(members,date)`는 최신 소속·기준일 반영이다. Panel이 매 렌더에 최신 소속을 전달한다. 부모가 영속화를 적용한다면 **합성 개발 데이터만** 저장한다. 동기 `onChange(nextSnapshot)`가 성공한 뒤 메모리를 변경하며, 콜백이 예외를 던지면 기록·버전·접수증·초기화를 함께 취소한다. 비동기 저장에는 별도 비동기 계약이 필요하다. 실제 학생 원문은 브라우저 영구 저장에 연결하지 않는다. `exportState()`는 개발 전용이며 운영 사용자 API가 아니다.

## 되는 흐름

- 승인된 내 수업·기준일 → 학급 명부 → 학생 선택 → 직접 확인한 사실 저장.
- 학생 ID와 학년도 학급·번호·학적·수강·담당을 분리한다. 학적·수강·배정은 시작 포함/종료 제외다. 기존 셸의 `Membership.validThrough`만 ‘마지막 유효일’ 의미를 따르므로 변경 시 공통 어댑터에서 함께 전환해야 한다.
- 작성자 자신의 현재 학교 기록만 목록·직접조회·건수·정정·철회·출력한다. 일정 관리자에게도 예외가 없다.
- 정정은 기대 버전과 사유를 요구하고 새 불변 개정본을 추가한다. 학생 오연결 정정은 해당 날짜 수강·학적을 다시 검사한다. 철회는 새 판이며 기존 사실 이력은 남긴다.
- 본인 과거 기록은 현재 소속이 유효하고 당시 승인된 수업·학적이 남아 있을 때 새 개정본으로 정정한다. 학교 소속 종료를 과거 작성자라는 이유로 우회하지 않는다.
- 근거 목록은 본인의 유효 원기록·기록판·활동일·학생 ID·출처판을 텍스트로 보여 주고 파일로 내려받는다. 생기부 AI 문장·공식 NEIS 입력·성적 확정을 구현한 것으로 표시하지 않는다.

## 가상 외부 활동 계약

실제 디지털윤리 앱에 연결하지 않는다. 현재 외부 앱 CSV를 파싱하는 구현도 아직 없으며 화면에 명시한다. 원자료 수신·검토 계약을 검증하기 위한 합성 사건이다.

`receiveActivity(memberId,event)`의 필드는 `sourceSystem,eventId,activityId,itemId,revision,operation,courseId,occurredAt,questionVersion,question,answer,alias`다. `schoolId/ownerUserId`는 입력을 신뢰하지 않고 현재 소속에서 정한다.

1. 사건 접수는 학교·작성자·연결·event ID로 멱등 처리한다. 같은 사건의 다른 본문은 오류다.
2. 원항목은 학교·작성자·연결·활동·item ID로 식별한다. 새 사건이어도 같거나 낮은 판은 반영하지 않는다.
3. 질문과 질문 판·원답변을 보존한다. 별명으로 학생을 자동 연결하지 않는다.
4. `confirmMapping`은 원문판과 현재 연결판을 검사하고 해당 날짜 수강·학적을 검증한다.
5. `adoptActivity`는 현재 원문판·연결판, 교사가 직접 작성한 사실과 확인을 모두 요구한다. 같은 원자료의 유효 관찰을 두 번 만들지 않는다.
6. 원문·질문 판·학생 연결 정정 또는 철회는 이미 채택한 기록을 즉시 재검토 상태로 계산한다. 내보내기도 동기 검사해 차단한다.
7. 정정 후에는 기존 채택 기록을 철회하고 새 원문·학생 연결을 확인해 재채택한다. 원문과 관계없는 수동 정정으로 오래된 출처를 유지하지 않는다.
8. `delete` 사건은 재생성 차단 이력을 남긴다. **현재 합성 저장의 delete는 접근 상태와 재생 방지 계약이지 원문 물리 파기 구현이 아니다.** 이전 불변 원자료판을 보존하며 물리 삭제 완료라고 표시하지 않는다. 실제 파일/CSV의 부분 삭제·보존·백업 삭제 원장 적용은 별도 서버 구현이 필요하다.

현재 화면은 가상 사건 수신·원문 정정·철회를 시험할 수 있다. 실제 CSV의 영구 ID 부재를 가상 사건 계약으로 해결했다고 주장하지 않는다. 실제 연계에는 활동 회차·파일 해시·교사 학생 매핑·확인형 정정이 별도로 필요하다.

## 보안과 운영 연결의 경계

이 메모리 store는 실제 인증/RLS가 아니다. 운영 연결 전 필요한 조건은 서버가 확정하는 현재 학교·소속·역할·기간, 학교별 복합 참조 강제, 승인 담당에 근거한 명부 접근, 작성자 전용 서버 조회와 RLS, 파일·AI·캐시·로그의 동일 제한, 권한 종료와 진행 작업 취소다. 학생 본문과 건수를 관리자 통계로 우회 제공하지 않는다. 화면 공유·다운로드·로그 보호도 서버·셸의 통합 검증 대상이다.

시간표와 학적 학급을 같은 식별자로 결합하지 않는다. 본 모듈의 수업 집단은 학적·수강 관계가 확인된 합성 일반학급만 다룬다. 고교 다학급 선택분반 지원을 검증한 것은 아니다.

## 검증

`node tests/test_workhub_students.mjs`에서 학교/작성자/기간, 학생 오연결, 종료 소속, 불변 이력, 기대판 충돌, 명령 멱등, 원자료 중복/역전/정정/철회/삭제 재생 방지, 정정 후 재채택과 출력, JSX 문구·원문 이스케이프를 검사한다. 이 결과는 합성 코드 계약 검증이며 운영 DB·RLS나 실제 학생 자료의 안전성 검증을 대신하지 않는다.

판단해서 정한 것: 파일 단위 독립과 합성 전용 경계를 유지하고, 초기 내보내기는 원기록 근거 목록으로 한정했다. 원자료 정정 때 내용을 조용히 덮어쓰는 대신 철회·재채택을 요구했다. 되돌리거나 조정하려면 `students/store.ts`, 화면과 전용 CSS, 이 테스트를 함께 검토한다.
