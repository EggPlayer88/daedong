# OP1 — 지정 계정의 업무 참여 연결

2026-10-26. **운영 비활성 설치 완료, 새 참여 허용은 0명이다.** OP1-01은 이미 설치했으므로 재실행하지 않는다. 적용 후 점검은 OP1-02·INT-10을 사용한다. 일반 교사 회원을 관리자 등급으로 바꾸지 않고, 승인된 계정·학교·소속·업무 범위·기간을 서버에서 확인한다. 기존 MP1 메신저 전용 경로는 계속 사용할 수 있다.

## 구현 범위

| 범위 키 | 기존 화면·서버에 연결하는 기능 | 함께 필요한 범위 |
|---|---|---|
| messages | 메시지·알림·HWPX 첨부 | 없음 |
| tasks | 개인 할 일 | 없음 |
| calendar | 일정 조회·현재 권한 내 등록·일괄 등록 | 없음 |
| cooperation | 요청·수락·반려·완료 확인·연결 할 일 | tasks, messages |
| collections | 본인 대상 수합·파일 제출·현재 담당 범위 | 없음 |
| transitions | 협업·수합·공식 담당 인계 | cooperation, collections와 그 의존 범위 |
| teaching | 현재 수업 관계 내 학생·평가·기록·출력 | 없음 |
| timetable | 날짜별 수업·교환·대강·보강·실시 기록·일정 연결 | calendar, messages, teaching |

범위 원본은 `apps/workhub/src/participation/scopes.json`이다. SQL 생성기와 앱이 함께 읽는다. 범위 허용은 수업 담당 배정, 수강 관계, 자료 소유권, 학교 역할, 모듈 정책, 독립 승인자를 대신하지 않는다. 학교 관리·키 관리·AI 호출·기존 회원 관리의 진입점은 추가하지 않았다. 일반 회원에게 신규 메뉴를 일괄 공개하지 않는다.

## 파일과 실행 순서

| 순서 | 파일 | 결과·중단 기준 |
|---|---|---|
| 0 | 기존 `INT-09_SQL편집기용_통합점검.sql` | 18행, FAIL 없음. 현재 운영 원본이 다르면 설치 중단 |
| 1 | `OP1-00_사전점검.sql` | 5행. P01 ok, P02 미설치, F01·F02 CSV 저장. 이미 설치됐으면 설치문 재실행 금지 |
| 2 | `OP1-01_업무참여_모델과함수.sql` | 하나의 트랜잭션. 1행 ok. 계정 허용은 0명 |
| 3 | `OP1-02_사후점검.sql` | 8행. 01~06·08 ok, 07 info. FAIL이면 다음 단계 중단 |
| 4 | `INT-10_SQL편집기용_통합점검.sql` | 18행. 12·13 info, 나머지 ok. 이후 전체 점검은 INT-10 사용 |
| 5 | `OP1-00_사전점검.sql` 재조회 | F01·F02 설치 전과 비교. P02가 이미 설치됨으로 바뀌는 것은 정상 |
| 6 | 앱 병합·운영 배포 | 사용자가 처리. 배포 커밋·시각 기록. OP1 미허용 계정은 기존 경로 유지 |
| 7 | `OP1-03_참여범위_승인양식.sql` | 지정 대상·범위·기간·현재 판·승인 근거 확인 후 실행. 신규 판은 0, 변경은 조회한 현재 판 |
| 8 | `OP1-04_참여연결_준비상태.sql` | 실제 허용과 시간표 승인 담당 수를 따로 확인 |
| 9 | 필요한 경우 `OP1-05_시간표참여_시범승인양식.sql` | T3 명단의 최초 승인/변경. 현재 판 일치, T2 활성화, 서로 다른 승인 담당 계정 2개 필요 |

최초 구축 뒤 추가 요청으로 2026-10-26에 위 0~5단계를 운영 DB에서 수행했다. OP1-02는 8행, INT-10은 18행 모두 FAIL 0이고 기존 회원·소속 지문도 동일하다. 앱 병합/배포·계정 허용·실제 기능 시험은 별도이며, 상세 기록은 [운영 설치 결과](../../../docs/workhub/participant-completion/operations-2026-10-26.md)를 따른다. 이전에 적용한 R0~MP1 SQL 파일은 수정하지 않았다.

### 입력값과 잠금

- OP1-03은 이미 있는 일반 교사 계정과 같은 학교의 활성 소속만 받는다. Auth 계정/소속/학교 역할을 만들지 않는다. 다른 학교의 기존 허용을 옮기지 않는다.
- 승인자는 대상과 다른 계정의 현재 학교 관리자여야 한다. 브라우저에 등록·권한 변경 RPC를 공개하지 않고 SQL Editor 관리 연결만 받는다.
- `expectedRevision`으로 오래된 승인·연장을 거부한다. 신규는 0, 이후는 관리 화면 또는 OP1-04에서 조회한 값이다.
- 시범 허용은 최대 7일이다. 기간 만료 시 예약 작업 없이 서버 요청에서 거부하며 화면도 만료 타이머로 닫는다. 연장은 현재 판을 다시 확인하고 승인 양식을 실행한다.
- 쓰기 요청은 허용 행을 공유 잠금으로 읽는다. 중지/연장은 같은 행을 갱신한다. 이미 완료된 요청·파일·감사 이력을 삭제하지 않는다.
- OP1-05는 기존 T3 정책의 현재 `revision`과 맞아야 한다. 진행 중 요청의 당사자를 새 명단에서 빼면 전체를 취소한다. 새 정책판을 기록하고 승인 근거를 감사에 남긴다.
- T3 명단에 들어가도 OP1이 만료/중지되면 일반 교사는 참여할 수 없다. 승인 담당이 2명이라는 것만으로 모든 요청의 독립 승인이 가능하다는 뜻은 아니다. 요청자와 영향을 받는 교사를 제외한 적격 승인자가 필요하다.

## 중지·복구

`OP1-80_참여중지.sql`은 대상·현재 판·승인자를 확인하고 `active=false`와 새 판을 기록한다. 만료/정지된 대상도 회수할 수 있으며 기존 회원·수업·파일·요청 이력은 지우지 않는다. 다시 사용할 때는 OP1-03에 현재 판을 넣는다.

MP1 메신저 허용은 독립된 기존 승인이다. **OP1을 중지해도 아직 유효한 MP1이 있으면 메신저 전용 이용은 남는다.** 두 경로를 모두 닫으려면 기존 MP1-80 절차도 확인한다. 앱만 되돌려도 서버의 OP1 허용이 없어지는 것은 아니다. 먼저 허용을 중지하고 앱을 되돌린다. 설치 구조를 제거하는 DROP 파일은 제공하지 않는다.

## 보호 경계와 생성 방법

- `legacy_gate`, `member_actor`, `p2_member_reachable`의 본문·권한은 유지한다. 84개 고정 함수의 해당 도메인 진입/후보 검사만 새 helper로 연결한다. 변경 목록은 `patches.json`이다.
- 설치 전에 서명·원문 지문·소유자·search_path·언어·반환형·API 실효 실행 권한을 대조한다. 다른 원본은 추정해서 바꾸지 않는다.
- 새 표 2개는 RLS를 켜고 API 직접 접근을 주지 않는다. 공개 RPC 3개는 본인 허용/소속 조회와 기존 관리자 조회뿐이다. 그 외 helper는 API 실행 권한이 없다.
- 일정·수합을 허용한 context는 응답 작성자·대상 검증에 필요한 같은 학교 소속 정보를 포함한다. 다른 학교 정보, 이메일, 키는 포함하지 않는다.
- `python database/workhub-participation/op1/build.py write`: 설치문·변경 목록 생성. 인자 없이 실행하면 일치 확인.
- `build-catalog.py`: 외부 DB 접속 인자를 받지 않고 새 로컬 PG17에 선행 SQL과 OP1을 설치해 OP1-02·INT-10을 생성한다. 실제 업무 요청·계정 허용을 수행하지 않는다. `WORKHUB_DEPLOYMENT_PG_BIN`으로 전용 실행 파일 경로만 지정한다.
- 카탈로그 컴파일 결과는 **138개 객체 속성 변화**다. 138개 기능 또는 시험 통과라는 뜻이 아니다. 실제 RPC 권한·동시성·복구·Storage 왕복은 후속 시험 항목이다.

## 판단해서 정한 것

1. 전체 교사 공개 대신 계정별·업무별·기한 있는 허용을 택했다. 기존 서비스에 영향을 제한하면서 시험 계정을 일반 교사로 유지하기 위해서다. 범위 변경은 scopes 자산과 새 증분으로 진행한다.
2. 한 계정의 허용은 한 학교 소속으로 고정했다. 다른 학교로 변경할 때 이전 자료를 잘못 노출하지 않도록, 현재 양식으로 자동 이전하지 않는다.
3. 관리자 화면은 허용 상태 조회만 제공한다. 이번에는 운영 권한을 설정 화면 클릭 한 번으로 넓히지 않으며, 검토 가능한 SQL 실행본과 승인 근거를 남긴다.
4. 기존 작업 화면·원래 요청 번호·입력 보관 체계를 재사용했다. 입력 보관은 탭 메모리이며, 로그아웃·브라우저 종료·허용 만료 이후 자동 복원을 약속하지 않는다.
