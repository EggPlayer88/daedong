# 학교 자료·시간표 운영 확장 설치 순서

이 문서는 PR #76의 검토용 설치 계획이다. 운영 DB에 아직 적용하지 않았다. 지금 실행을 요청하는 문서가 아니다.

## 순서

1. 기존 운영 기준 **T2-07**을 읽기 전용으로 실행해 설치 상태를 저장한다. FAIL이 있으면 신규 설치로 넘어가지 않는다.
2. **P9-01 → P9-02 → P9-04 → P9-05**. 기존 가입 교사를 학교에 연결할 준비를 한다. P9-03은 학교별 허용 회원과 담당자가 확정된 뒤 별도 실행한다.
3. **P10-01 → P10-02**. 수업·학생·수강 정정 및 이력 보호를 설치한다. P10의 별도 사후 점검을 수행하고 정책은 끈 상태로 둔다.
4. **T3-01 → T3-02 → T3-03**. 대강·휴강·보강·휴업 취소, 알림 출처, 기존 운영 보호를 설치한다. 별도 사후 점검을 수행하고 정책은 끈 상태로 둔다.
5. **T4-01 → T4-02**. 실제 시간표 가져오기와 사후 점검이다. 기존 T1 관리자 권한을 그대로 쓰며 추가 권한을 부여하지 않는다.
6. **INT-04**. 현재 적용 단계에 맞는 전체 표·제약·함수·트리거·권한을 대조한다. 전 행 FAIL 0을 확인한다.
7. 앱 배포 확인 뒤 실제 회원·시범 명단·승인 담당자·학교 자료를 확인하고 **P9/P10/T2/T3의 학교별 활성화 양식**을 각각 검토한다.

각 파일은 해당 폴더 README의 선행 조건과 실행 후 결과를 먼저 확인한다. P9가 이미 적용된 환경에서는 P9-01·02를 재실행하지 않고 해당 단계 점검 결과로 확인한다.

## 설치만으로 영향을 주는 부분

- P9-02는 기존 승인 회원의 담당 후보 판정을 별도 업무실 연결 자격으로 보강한다.
- P10-02는 과거 자료를 보호하면서 정정 원장을 거친 변경만 허용하도록 기존 보호 트리거를 보강한다. 취소·보관된 수업과 취소 학생의 새 기록을 막고, 시간표 기초 자료에서 제외한다.
- T3-01은 시간표 이력의 변경 사유에 `intervention`을 추가한다.
- T3-03은 기존 T2의 충돌·재공개·교환·학사 변경 경로를 보강한다. 정책 행이 없는 학교의 기존 교환 흐름은 유지한다. 시범 정책을 등록한 학교에는 명단과 독립 승인 검사가 함께 적용된다.
- T4는 기존 T1의 활성 상태와 관리자 권한을 이용한다. SQL이 설치되고 앱이 배포되면 자격을 갖춘 관리자에게 가져오기가 가능하다.

따라서 “새 정책이 꺼져 있으니 모든 기존 함수가 설치 전과 완전히 같다”고 설명하지 않는다. 적용 전 원본 함수가 예상과 다르면 증분 파일은 멈춘다.

## 보존·되돌림

기존 적용 SQL 파일은 수정하거나 재실행하지 않는다. 실제 회원을 가상 회원으로 대체하지 않는다. 신규 설치 파일에는 운영 자료를 지우는 DROP 되돌림을 두지 않는다. 문제가 있으면 신규 정책을 중지하고 원접수증과 이력을 먼저 확인한다. 구조 변경을 되돌릴 때는 저장된 이력의 의존 관계를 검토한 별도 수정 SQL이 필요하다.

INT-04는 스키마의 예상 정의를 대조하는 읽기 전용 점검이다. 파일 본문, 운영 자료의 의미, 실제 Storage·PostgREST 왕복이나 교사의 동의를 증명하지 않는다.

## 자동 재현

운영 접속 문자열은 받지 않는다. `P9_PG_BIN`에 PostgreSQL 17 바이너리 폴더를 지정하고 `psycopg2-binary`를 설치한다.

```sh
python database/workhub-school-data/integration/test/run_integrated.py
```

생성 SQL을 변경할 필요가 있을 때만 검토용 작업 브랜치에서 `WORKHUB_WRITE_INT04=1`을 지정한다. 일반 시험·CI는 생성 결과가 저장된 INT-04와 다르면 실패한다.
