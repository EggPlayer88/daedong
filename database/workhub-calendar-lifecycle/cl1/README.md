# CL1 일정 취소

기존 일정 원본과 이전 판을 남기면서 취소할 수 있게 한다. 현재 `INT-15` 설치 기준 위의 새 증분이다. 기존 확정 SQL을 덮어쓰지 않으며 설치만으로 일정·권한·AI 정책이 바뀌지 않는다.

## 동작과 권한

- 기존 작성자와 `calendar.shared_manage` 담당자의 수정 가능 범위를 그대로 사용한다. 남의 비공개 일정·다른 학교 일정·공식 학사/휴업 일정은 취소할 수 없다.
- 취소 사유는 1~500자다. 취소하면 상태·판·취소 시각·사유를 기록하고 원문과 대상은 보존한다. 삭제·되살리기는 이번 범위에 없다.
- 기존 목록은 `active` 일정만 반환한다. 취소한 일정은 별도 취소 목록과 원본 조회로 확인한다.
- 취소 상태의 원본은 생성 시점과 관계없이 옛 편집기·일괄 가져오기·나이스 변경 반영에서도 수정할 수 없다. 현재 공식 학사 일정 복원 RPC는 없으며, 이번 취소 기능으로 공식 일정을 취소하지 않는다. 새 일정이 필요한 경우 별도 작성한다.
- 취소 전에 성공한 저장을 원래 번호로 다시 확인하는 동작은 유지한다. 기존 저장 RPC의 응답 원칙대로 현재 판을 반환하며, 취소 상태도 함께 반환한다.
- 기존 알림 전달 정책은 바꾸지 않는다. 취소 감사·outbox 기록은 남지만 새 수신자 알림을 추가하지 않는다.

## RPC 계약

`workhub_calendar_cancel(p_member_id text, p_command jsonb, p_request_key text, p_recover_only boolean DEFAULT false)`

명령은 `{eventId, expectedVersion, reason}`이다. 성공은 `{contractVersion:'calendar.lifecycle.v1', ok:true, schoolId, memberId, ownerUserId, requestKey, event, recordedAt}`를 반환한다. `event`에는 기존 일정 DTO와 `status`, `cancelledAt`, `cancelReason`이 있다. 접수증에는 본문을 복제하지 않고 원본 ID·판·접수 시각만 저장한다. 취소 원본은 변경되지 않으므로 같은 키의 재전송·조회는 동일한 결과를 반환한다.

확정 업무 거절은 같은 신원·학교·명령 해시·요청 번호와 `ok:false, outcome:'rejected', code`를 반환한다. 신원·권한 확인이 실패하거나 통신이 끊긴 경우에는 앱이 원래 번호를 보관한다.

`recover_only=true`는 접수된 결과만 조회한다. 아직 접수되지 않았다면 `SAVE_UNCERTAIN, outcome:'unknown'`이다. **이것은 취소되지 않았다는 확정 답변이 아니다.** 늦은 최초 요청이 도착할 수 있으므로 번호를 버리거나 새 번호를 만들지 않는다. 사용자가 명시적으로 같은 요청 재전송을 선택하면 원래 번호·내용으로만 실행한다.

`workhub_calendar_cancelled_list(p_member_id text)`는 기존 조회 권한으로 보이는 취소 일정 배열을 반환한다. `workhub_calendar_get`은 취소 원본도 조회한다. 기존 `workhub_calendar_list/get/save`는 상태 메타데이터를 추가하되 기존 필드는 유지한다.

## 운영 적용 순서

운영 실행과 병합은 사용자 확인 후 진행한다. 이 작업에서는 운영 SQL을 실행하지 않았다.

1. 현재 `INT-15_알림연결포함_통합점검.sql`: 18행, 12·13 `info`, 나머지 `ok`.
2. `CL1-00_전후점검.sql`: 7행. 설치 전 F1~F5 CSV 보관.
3. `CL1-01_일정취소_조회와원키복구.sql`: `CL1-01 / ok` 한 행.
4. `CL1-02_사후점검.sql`: 7행 모두 `ok`.
5. `CL1-00` 다시 실행하여 F1~F5가 설치 전과 같은지 비교한다. 동시 실사용으로 자료가 바뀌었다면 변경 원인을 별도 확인한다.
6. `INT-16_일정취소포함_통합점검.sql`: 18행, 12·13 `info`, 나머지 `ok`.
7. 앱 PR 병합·배포. 기존 앱도 조회·저장 응답의 추가 필드를 허용하므로 SQL 선행 적용이 가능하다.

가드 오류가 나면 원문이나 권한이 기준과 다르므로 중단한다. 자동 덮어쓰기 또는 가드 제거로 진행하지 않는다. 설치는 한 트랜잭션이다. 기능 사용으로 생긴 취소 판과 접수증은 보존하며, 앱만 되돌려도 취소 원본 변경 보호는 유지된다.

## 자동 검증

`python database/workhub-calendar-lifecycle/cl1/build_checks.py`는 외부 DSN·API 키를 받지 않고 새 localhost PostgreSQL17에 기존 전체 설치 기준을 만든다. 설치 전후 자료·권한·비용 지문, 사후 점검/INT-16 재생성, 원문/권한 훼손 탐지, 일반 교사/관리자/다른 학교, 취소와 저장의 경합, 같은 번호 재전송, 미접수 조회 뒤 지연 도착, 후속 실패 전체 롤백을 검증한다. `--write`는 새 CL1 점검 산출물만 재생성한다.

검증 중 실제 회원·운영 자료·유료 AI는 사용하지 않는다. CI에서는 기존 NT1 회귀까지 포함하는 이 실행기를 사용한다.
