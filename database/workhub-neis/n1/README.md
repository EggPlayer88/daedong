# N1 — 나이스 연결 적용 안내

**아직 운영 DB에 실행하지 않았다.** 사용자가 결과를 확인하며 아래 순서로 진행한다. 운영 기준은 INT-11(기존 48단계)이다. 기존 설치 SQL을 재실행하지 않는다.

## 1. 설치 전 읽기 전용 점검

1. 기존 `database/workhub-current/int11/INT-11_SQL편집기용_통합점검.sql` 실행. 18행, 12·13 info / 나머지 ok를 확인하고 CSV를 보관한다.
2. `N1-00_전후점검.sql` 실행. 5행. N1-00-01 ok, N1-00-02 미설치 안내, F1~F3 compare 값을 보관한다.
3. FAIL이나 예상 외 설치 상태가 있으면 결과를 확인한 뒤 진행한다. 운영 회원·일정 건수는 진행 중 업무로 변할 수 있다.

## 2. 새 연결 구조 설치

1. `N1-01_나이스연결_모델과함수.sql` 전체 실행. 마지막 N1-01 / ok를 확인한다.
2. `N1-02_사후점검.sql` 실행. **9행: 01~08 ok, 09 info**가 정상이다.
3. `INT-12_나이스포함_통합점검.sql` 실행. **18행: 12·13 info, 나머지 ok**. 기존 INT-11 전체 검사를 유지하면서 N1을 추가한 읽기 전용 점검이다.
4. N1-00 재실행: F1 기존 함수 원문은 설치 전과 같아야 한다. F2 회원·F3 일정 변화가 있으면 실제 사용에 따른 변화인지 대조한다. N1 설치만으로 이 자료는 바뀌지 않는다.

N1-01은 이미 설치된 상태에서 재실행하지 않는다. 실패하면 트랜잭션을 롤백하며, 성공 여부가 불분명하면 N1-02로 확인한다. INT-12는 약 632KB이며 이전 INT-11과 같은 사전 압축 방식이다. SQL Editor가 크기를 거부하면 SQL을 임의로 잘라 실행하지 말고 연결 방식으로 원문 전체를 실행해야 한다. 이후 현재 전체 구조 점검에는 INT-12를 사용한다.

## 3. 대동여중 연결 등록과 초기 공개 원본

`N1-03_대동여중_연결등록.sql`을 확인하고 실행한다. 기존 대동여자중학교 1개·한국시간·K10/7892043을 확인하며, 다른 학교 연결이 있으면 중단한다. 관리자 UID나 API 키를 SQL에 입력하지 않는다.

초기 자료를 바로 보여 주려면 다음 파일을 순서대로 한 번씩 실행할 수 있다.

1. `docs/neis/reference-2026/N1-10-1_schedule_초기원본.sql` — 학사일정 184건
2. `docs/neis/reference-2026/N1-10-2_timetable_초기원본.sql` — 11/2~11/15, 2학기 수업 612건
3. `docs/neis/reference-2026/N1-10-3_classes_초기원본.sql` — 9학급
4. `docs/neis/reference-2026/N1-10-4_meals_초기원본.sql` — 공개된 급식 20건

이 네 파일은 나이스 **원본 캐시**만 만든다. 기존 일정, 운영 확정 시간표, 교사 배정에는 쓰지 않는다. 같은 범위 자료가 있으면 덮어쓰지 않고 중단하므로, 서버 갱신이 먼저 끝났다면 초기 파일 대신 화면에서 최신 자료를 확인한다. 파일별 정상 결과는 ‘초기 원본 준비 완료’ 1행이다. 실행 후 N1-02를 다시 보관한다.

## 4. 서버 환경변수와 배포

Vercel 운영 프로젝트 → Settings → Environment Variables에서 아래 두 값을 **Production 서버 변수**로 등록한다. VITE_ 접두사는 사용하지 않는다.

| 이름 | 값 |
|---|---|
| NEIS_API_KEY | 사용자가 바탕화면에 보관한 기존 나이스 API 키 |
| CRON_SECRET | 32바이트 이상 난수로 새로 생성한 예약 실행용 비밀값 |

기존 SUPABASE_SERVICE_ROLE_KEY 등 서버 연결값은 재사용하며 변경하지 않는다. 값을 채팅·SQL·Git에 붙이지 않는다. 환경변수 등록만으로 기존 배포에 적용되지 않는다.

PR 자동 검사·미리보기 확인 뒤 사용자가 merge commit으로 main에 병합하고 Production Ready를 확인한다. 미리보기에도 실제 키를 공유하려면 별도 범위 결정이 필요하며 이번 준비에서는 운영 키를 미리보기로 복사하지 않았다. 예약 실행은 배포 설정에 하루 1회(UTC21:00, 한국시간 다음날06:00)로 정의했다. 예약 요청은 Bearer CRON_SECRET 검사를 통과해야 한다. 정확한 실행 시각·성공은 Vercel 실행 로그와 마지막 갱신 시각으로 확인한다.

## 5. 배포 후 사이트 반영

1. 관리자 → 학교 관리 → 나이스 학교 자료 → 학사일정 비교를 연다.
2. 학년도 2026을 확인하고 최신 자료를 가져온다. 최초 자료 후 30분 이내면 캐시를 사용한다.
3. 기존 일정과 중복 여부를 확인한다. 필요한 일정은 최대 50건씩 선택한다. 기존 일정이 있다면 자동 복제하지 말고 연결한다.
4. 제목·설명·날짜 충돌과 공개 범위를 확인해 선택 반영한다. 이후 기존 일정 화면에 표시된다.
5. 학급 시간표에서 2026-11-02 주와 9학급을 확인한다. 다음 주는 날짜를 바꿔 확인한다. 공개 시간표와 운영 확정 시간표를 구분한다.
6. 홈에서 오늘의 급식과 마지막 확인 시각을 확인한다. 등록된 급식이 없는 날은 ‘없음’으로 표시한다.

시간표 운영 확정에는 기존 담당 교사·수업·학급 연결과 교시 시각 확인이 남아 있다. 이 단계에서는 교사·학생 연결을 새로 만들거나 기존 시험 수업을 실제 수업으로 바꾸지 않는다.

## 중지와 검증

`N1-80_연결중지.sql`은 대동여중 나이스 연결만 비활성으로 둔다. 원본·접수증·이미 반영한 일정은 삭제하지 않는다. 원본 접수증 복구·요청 닫기는 현재 소속·일정 권한을 다시 확인한다.

`build_checks.py`는 외부 DB 접속을 받지 않고 임시 localhost PostgreSQL17에서 기존 48단계와 N1을 설치한다. INT-12 재생성·해시·기존 자료 보존·훼손 검출을 검증한다. `--write`는 이 폴더의 생성 점검 파일과 목록만 갱신한다.
