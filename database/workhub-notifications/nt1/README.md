# NT1 — 메시지 도착·수합 공개 알림

Claude의 B3 재현은 화면에서 알림을 빠뜨린 문제가 아니라, 기존 전송·공개 트랜잭션에서 알림을 만들지 않는 문제였습니다. NT1은 기존 메시지와 수합 명령을 그대로 사용하면서, 이후 새로 보내거나 공개한 항목에 업무 알림을 만듭니다.

## 변경 범위

- 메시지를 보내면 대화 참여자 중 발신자를 제외한 사람에게 각 1건을 알립니다. 새 대화와 답장 모두 포함합니다.
- 수합을 처음 공개하면 제출 책임자와 공동 작성자에게 각 1건을 알립니다. 같은 사람이 여러 제출 단위에 있어도 한 번만 받고, 수합 작성자 본인은 제외합니다.
- 알림은 원본 저장과 같은 트랜잭션입니다. 알림 생성이 실패하면 원본도 함께 취소됩니다. 성공한 요청의 같은 번호 재전송은 기존 접수증만 돌려주므로 알림을 추가하지 않습니다.
- 메시지 본문을 알림에 복제하지 않습니다. 기존 `messages / threadId`, `collections / collectionId` 출처로 해당 업무를 엽니다.
- 기존 알림·메시지·수합의 소급 생성, 읽음 변경, 교사 권한·메뉴 공개·학교 AI 정책 변경은 없습니다.

기존 확정 SQL과 함수는 수정하지 않습니다. 새 비공개 함수 2개, 메시지·수합 트리거, 설치 기록만 추가합니다. 설치 시 기존 `p3_post`, `c_cmd_publish`, `p3_notify`의 원문 지문과 소유자를 대조하며 다르면 트랜잭션을 중단합니다. 원문 CRLF/LF 차이는 정규화합니다.

## 적용 순서

이 PR에서는 운영 DB에 실행하지 않습니다. 사용자 승인 뒤 운영의 `postgres` 역할로 진행합니다. **NT1-01 설치가 성공한 시점부터 새 메시지·공개 수합에 알림이 생기며, 별도 켜기 SQL은 없습니다.**

1. 현재 전체 기준 `database/workhub-teacher-pilot/tp1/INT-14_시험교사포함_통합점검.sql`을 실행합니다. 18행 중 12·13만 `info`, 나머지는 `ok`여야 합니다. SQL Editor 길이 제한이 있으면 기존 점검 절차처럼 DB 직접 연결을 사용합니다.
2. `NT1-00_전후점검.sql`을 실행해 CSV를 저장합니다. 6행이며 `NT1-00-01=ok`, `NT1-00-02=미설치`, F1~F4는 `compare`입니다.
3. `NT1-01_메시지_수합공개_알림.sql` 전체를 한 번 실행합니다. 마지막 결과 `NT1-01 / ok`를 확인합니다. 일부만 선택해 실행하지 않습니다.
4. `NT1-02_사후점검.sql`의 7행이 모두 `ok`인지 확인합니다.
5. `NT1-00`을 다시 실행합니다. 기존 자료의 F1~F4 지문이 그대로인지 비교합니다. 설치 중 실제 메시지 전송·공개가 있었다면 해당 변화인지 따로 대조하고, 지문 차이를 임의로 정상 처리하지 않습니다.
6. `INT-15_알림연결포함_통합점검.sql` 18행에 `FAIL`이 없는지 확인합니다. 설치 이후 전체 점검은 INT-15를 씁니다. 기존 INT-14는 새 함수·트리거를 추가 객체로 보고 FAIL을 표시할 수 있습니다.
7. 앱 배포 뒤 기존 시험 계정끼리 메시지 1건과 수합 공개 1건을 확인합니다. 수신자의 업무 알림에서 해당 대화·수합이 열리고, 발신자 자신에게 알림이 생기지 않아야 합니다. 실제 교사에게 시험 메시지를 보내지 않습니다.

오류·FAIL이 있으면 다음 파일로 넘어가지 않습니다. NT1-01은 실패 시 전체 롤백되며, 성공 후 재실행하면 설치 완료 안내와 함께 중단합니다. 자동 삭제나 되돌리기 SQL은 제공하지 않습니다.

## 검증

2026-11-13 로컬 PostgreSQL 17 검증은 **94 통과 / 실패 0**입니다. 전체 기준의 설치·훼손 검증을 포함한 숫자이며, 그 안의 앱 계약 대조 1개 항목은 실제 SQL 응답 6건(3명 알림 목록·새 메시지·답장·수합 공개 접수증)을 현재 앱 parser로 확인합니다. 새 함수·트리거 11개 catalog 객체만 추가됐고 기존 자료 지문은 동일했습니다.

`build_checks.py`는 기존 전체 INT-14 설치·훼손 검증을 먼저 수행한 뒤, 새 localhost PostgreSQL 17에서 NT1을 검증합니다. 운영 DSN·API 키·유료 AI 호출은 사용하지 않습니다.

```powershell
$env:WORKHUB_DEPLOYMENT_PG_BIN = 'PostgreSQL 17의 bin 절대 경로'
$env:WORKHUB_DEPLOYMENT_TEST_PORT = '55841'
python database/workhub-notifications/nt1/build_checks.py
```

점검 파일 재생성은 마지막에 `--write`를 붙입니다. `sources.json`은 선행·신규 함수의 정규화 본문 지문, `checks.json`은 생성한 INT-15 파일 해시입니다. 사후 점검은 기존 함수·소유자·API 실행권한·트리거 동작 조건을 확인합니다. 통합 점검은 현재 전체 구조를 대조합니다.

실제 전송·공개 RPC를 이용해 새 메시지, 일반 교사 답장, 공동 작성자 중복 제거, 본인 제외, 원본 링크, 재전송 접수증 보존, 동시 재전송, 알림 INSERT 실패의 전체 롤백을 확인합니다. 내부 함수 직접 호출과 다른 학교 조회는 거부되어야 하며, 기존 메시지 읽음 순번은 바꾸지 않습니다. 설치 전 동일 RPC에서 알림 0건이 발생하는 B3도 재현합니다.

운영 Supabase의 실제 왕복·화면 알림은 이 격리 시험과 구분합니다. 설치·배포 후 확인 항목이며 이 작업에서 완료로 표시하지 않습니다.
