# 학교별 AI 정책·공통 비용 원장 P10

업무실 비서와 기존 평가계획 AI가 같은 학교의 BYOK와 월 100 USD 예산을 사용하도록 준비한 신규 증분이다. 운영 실행·실제 키 등록·유료 호출은 하지 않았다. 기존 확정 SQL, Auth, 기존 회원, legacy_gate, 메뉴 공개 범위를 수정하지 않는다.

## 설치와 활성화

기존 P6-01/02가 설치된 DB에서 다음 순서로 검토·적용한다.

1. `P10-01_학교AI_모델.sql`: 학교 정책·암호문·공통 원장·명시 학교 연결표와 불변 조건.
2. `P10-02_학교AI_공통실행.sql`: 두 AI 경로의 예약·시작·정산·복구·닫기와 기존 P6 결합.
3. `P10-03_학교AI_관리.sql`: 키 관리·정책 등록·학교 연결·별도 켜기/중지·제한된 비용 확인 RPC.
4. `P10-04_사후점검.sql`: 읽기 전용 점검. FAIL이 없어야 한다.
5. `P10-09_운영현황_조회.sql` → `P10-10_서버진단_조회.sql`: 서버 전용 관리자 조회. 기존 실행·비용·키 저장 함수는 변경하지 않는다.
6. `P10-11_운영조회_사후점검.sql`: 새 조회의 설치·권한 검사. 기존 04도 함께 확인한다.

설치만으로 학교 정책·키·기존 교사 연결·기능 활성화가 생기지 않는다. 활성화는 승인된 학교와 현재 관리자를 확인한 뒤 다음을 별도로 진행한다.

- 05 양식으로 승인된 모델·가격·예산 정책을 등록한다. 기본 꺼짐 상태다.
- 서버의 AES-256-GCM master key 환경 설정과 키 관리 화면에서 학교 공급자 키를 등록한다. DB에는 암호문과 끝 4글자만 남는다.
- 06 양식에 실제 확인한 기존 평가계획 회원 UID를 적어 학교에 연결한다. 소속을 추정하거나 새 Auth/업무실 회원을 만들지 않는다.
- 07 양식으로 공통 AI 정책을 켠다. 업무실 assistant 모듈의 기존 활성화·공개 승인 절차는 별개다.

05~08의 자리표시자는 그대로 실행하면 실패한다. 실제 UID·키·승인 근거를 포함하지 않는다. 적용 전 기존 P6 상태와 사용 중 요청을 확인하고 새 앱/서버 배포를 함께 계획해야 한다. 새 SQL 설치 후 기존 서버의 직접 prepare/start는 차단된다.

2026-10-21 사용자 지시에 따라 **06 실제 회원 연결은 마지막**, 지금은 가상 교사 반복 시험만 수행한다. 연습실은 DB를 쓰지 않는다. 격리 SQL 시험에서 생성하는 가상 Auth/교사 행은 localhost의 새 임시 DB에만 있으며 운영에 넣는 시드 파일은 없다. 현재 운영 AI에 영향을 주는 실제 배포·SQL·키 설정은 이번에 진행하지 않았다.

## 비용·복구 경계

모델/한도는 `apps/main/api/workhub-ai/_assets/model-routing.json` 2026-10-21.1 판에 맞춘다. quick은 Haiku, review는 Sonnet이며 학생 기록 초안은 review가 기본이다. 자동 승격·캐싱은 사용하지 않는다. 사전 입력 검사는 80,000, 출력 상한은 8,000이다. 사용량 추정과 실제 사용량 차이에 대비해 입력 100,000을 예약하므로 요청별 예약은 quick 14,000 / review 280,000 microUSD다.

공통 원장이 두 경로의 학교 월예산을 직렬화한다. 기존 P6 비용/대화 원장은 함께 유지하되 합산해 두 번 청구하지 않는다. 적용 전에 있던 P6 요청은 한 번 이관하며, 시작된 요청의 기존 finish 접수 경로는 보존한다.

공급자 결과를 확인하지 못하면 예약을 계속 잡는다. 시작 전 요청만 명시적으로 닫아 해제하며, 미접수 원키에도 닫힘 기록을 남겨 늦은 요청을 차단한다. 만료·키 회전·예산월 변경·정책 중지 자체는 예약 해제 사유가 아니다. 시작 후 비용은 권한 회수 뒤에도 기록하되 답변은 노출하지 않는다.

실제 입력 100,000/출력 8,000을 초과한 관측은 자동 정산하지 않는다. 관측값과 예약을 보존하고 해당 학교의 새 호출을 차단한다. 이 경우 08 양식도 거부하며 별도 승인·증분이 필요하다. 08은 승인 범위 안에서 공급자 청구를 확인한 결과미상 요청만 처리한다. 공급자 청구 이상까지 월예산을 절대 보장한다고 해석하지 않는다.

정밀검토는 완료된 원 quick 답변·원질문·원근거를 서버에서 확인한다. 원답변이 최신 history 창 밖에 있어도 reviewSnapshot으로 제공한다. 학생 기록에서는 현재 수업·학생·근거 권한 검증 후 등록 학생 식별번호와 이름을 전달하며 상담 자료를 추가 조회하지 않는다.

## 검증

`test/run_p10_ai.py`는 localhost의 새 임시 PostgreSQL 17만 사용한다. 운영 DSN·실제 키·공급자 API를 받지 않으며 종료 시 DB를 중지한다. 기존 P9 테스트의 Supabase 모의 환경과 적용 SQL을 재사용하고 응답 원문을 임시 경로의 `captures.json`에 저장한다.

```powershell
$env:P10_AI_PG_BIN = '<PostgreSQL 17 bin 경로>'
$env:P10_AI_PORT = '55549'
python database/workhub-ai-policy/p10/test/run_p10_ai.py
```

Python에는 psycopg2가 필요하다. 테스트는 원키·접수증·닫힘 장벽, 현재 권한, 학교 연결 회수, 키 회전, 월 변경, 두 경로 예산 경합, 학생 근거, 원답변 정밀검토, 초과 관측 차단, 기존 회원/권한 함수 보존과 사후점검을 포함한다. 캡처는 프런트 설정/대화 파서와 Node 평가계획 gateway에서도 따로 대조한다. 자세한 RPC 형식은 `API-contract.md`에 있다.

확장 실행기 `test/run_p10_operations.py`는 원래 72개 회귀를 먼저 실행하고 새 조회·진단·가상 일반교사 36명의 216개 시나리오·다른 학교·36개 동시 예약을 이어 실행한다. 일반교사의 기존 비서 공개 게이트를 우회하지 않는다. 같은 번호 재전송, 변경 본문 거절, 시작 전 닫기, 시작 후 미상, 실패 전 예약 해제, 비용 확인 완료를 포함한다. 새 회귀 총 117개이며 시나리오와 RPC 수는 assertion 개수와 별도로 기록한다.

`npm run test:workhub:ai-sql`이 이 확장 실행기와 실제 응답의 TS·Node·Python 대조까지 수행한다. `WORKHUB_AI_SQL_REPORT`에 로그·캡처·operations-report.json·summary.json을 남긴다. 반복 횟수와 호출 수는 실제 보고서 기준으로 판단하며, 유료 공급자 호출은 0이다. 더 많은 반복 시험도 같은 명령을 새 임시 DB에서 다시 실행할 수 있다.
