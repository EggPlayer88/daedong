## 6. 고치지 않은 기존 규칙(관찰)

- R1-04-03·04 는 이름이 `workhub_collection_` 으로 시작하는 함수를 센다. P7 함수 2개(이름은 앱 계약이 정함)가 더해져 값이 +2 가 되고 `FAIL` 로 보인다. R1-04 를 고치지 않고 `P7-03-12` 가 대신 확인한다.
- R1 수합 단위는 1~100개라 계약의 "2,000 단위 넘으면 잘라서 정상처럼 응답하지 말 것"에 걸릴 일이 없다.

## 부록 — P7-05 가 바꾸는 R1 · P2 원본 정의(되돌릴 때 기준)

P7-05 는 아래 정의가 그대로일 때만 실행됩니다(`collections_guard` 본문 md5 `192396592ea201a158dcadb4b92d7b33`, 나머지는 정의 문자열 비교).

R1-02 `collections_guard`:

```sql
CREATE FUNCTION workhub_private.collections_guard() RETURNS trigger
LANGUAGE plpgsql SET search_path = '' AS $$
BEGIN
  IF TG_OP = 'DELETE' THEN RAISE EXCEPTION 'IMMUTABLE_ROW' USING DETAIL = '수합은 지우지 않습니다.'; END IF;
  IF OLD.state = 'published' THEN
    RAISE EXCEPTION 'IMMUTABLE_ROW' USING DETAIL = '게시된 수합 요청은 바꿀 수 없습니다(R1 에는 게시 후 변경 명령이 없습니다).';
  END IF;
  NEW.updated_at := clock_timestamp();
  RETURN NEW;
END $$;
```
