2026-10-16 · 작성: Claude Code · 검토: Codex · 실행: 계란님

P1 은 통합 SQL 요청서(`docs/workhub/pilot-completion/sql-handoff.md`)의 **1단계 — 학교 구성·소속·공식 담당** 증분 SQL 입니다.
앱 계약은 PR #48 의 `school-admin-contract.md` 와 `apps/workhub/src/setup/school-admin-contract.ts` 입니다.

- **SQL 을 적용해도 아무 학교도 켜지지 않습니다(비활성 설치).** 준비 상태는 모든 학교 `not_configured` 이고,
  조회·변경은 `NOT_READY` 로 멈춥니다. 켜는 것은 `P1-04` 이고, 그것은 앱 병합·배포 뒤 별도 승인입니다.
- 기존 로그인·가입 승인·회원·평가계획서·수합 자료는 건드리지 않습니다(`P1-00` 지문으로 확인).
- **R0·R1·R1S 를 다시 실행하지 않습니다. R0-90 도 쓰지 않습니다.**

## 4. 멈춤 기준

아래 중 하나라도 보이면 **다음 파일로 넘어가지 말고** 그 행·메시지를 알려 주세요.

- P1-00 실행 전 결과에 `FAIL`
- P1-01/02 가 `ERROR` 로 끝남, 또는 마지막 결과에 `ok` 가 아닌 행
- P1-03 에 `FAIL`
- P1-00 실행 후 구조 지문(S1~S6)이 실행 전과 다름
- 6번 사이트 확인에서 기존 기능 하나라도 이상

P1-01·02 가 이미 적용된 뒤 멈춰야 한다면 **되돌리는 SQL 을 즉석에서 만들지 않습니다.** 활성화 행이 없으면 학교 관리 함수는
모두 `NOT_READY` 이고, 교체한 `member_relations` 는 공식 담당 표가 비어 있어 R0 와 같은 빈 관계를 돌려줍니다
(시험 II: R1 시험 244건 그대로 통과). 그대로 두고 원인을 먼저 봅니다.

## 6. 계란님이 정할 값

이 SQL 은 어떤 값도 정해 두지 않았습니다. 칸이 남아 있으면 아무것도 쓰지 않고 멈춥니다.

**P1-04 (활성화)**

| 칸 | 무엇 | 예 |
|---|---|---|
| `approver_user_id` | 승인한 학교 관리자(school_admin)의 회원 id(Auth UID). 대상 학교는 그 사람이 지금 관리자인 학교 1곳 | — |
| `approval_ref` | 승인 근거 1~200자 | "2026-10-20 교무회의, 학교 관리 시범 운영 승인" |

P1-04 가 활성화 전에 확인하는 것: 승인자가 정확히 한 학교의 관리자, 이미 활성화 행 없음, 학년 수가 학교급 앱 범위 안,
학교 이름·코드가 앱 형식, 학년도 1~100개이고 각각 학기 1~4개, 학기 이름이 앱 형식, 소속 5000건 이하.

**P1-80 / P1-81 (중지·재개)**

| 칸 | 무엇 | 예 |
|---|---|---|
| 학교 코드 | R0-03 에서 정한 code | `daedong-ms` |
| 사유 | 1~200자 | "2026-10-21 담임 배정 오류 확인 중" |

## 7. 실제 환경에서 시험하지 못한 것

시험은 로컬 PostgreSQL 17 에 Supabase 의 역할·`auth.uid()` 를 흉내 낸 DB 에서 했습니다(`P1_시험결과.md`).
다음은 실제 Supabase·Vercel 에서 처음 확인하게 됩니다.

- 실제 PostgREST 를 거친 호출(시험은 같은 경로 authenticator → set role → `request.jwt.claims` 를 직접 흉내)
- 실제 회원·소속 자료에서의 기본 학년도 선택과 소속 목록(시험 자료는 R0 시험의 흉내 자료)
- 실제 앱 화면(PR #48)의 왕복. 앱 parser·어댑터는 실제 코드로 대조했지만 브라우저·Supabase 클라이언트는 거치지 않았습니다
- 운영 DB 의 잠금 대기(학교별 advisory lock)와 응답 시간. 시험은 동시 요청 4건까지
