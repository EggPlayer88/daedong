# 수업 · 학생 · 관찰 · 상담 · 평가 · 활동 CSV(P5) 실행 안내

2026-10-16 · 작성: Claude Code · 검토: Codex · 실행: 계란님

P5 는 통합 SQL 요청서(`docs/workhub/pilot-completion/sql-handoff.md`)의 **5단계 — 수업 · 학생 · 관찰 · 상담 · 평가 · 활동 CSV** 증분 SQL 입니다.
앱 계약은 PR #48 의 `apps/workhub/src/teaching/*.ts`(`teaching.v1`)입니다.

- **SQL 을 적용해도 아무 학교에서도 켜지지 않습니다(비활성 설치).** 모든 함수가 `UNAVAILABLE`, 준비 사유는 `policy_missing` 입니다.
- 켜는 것은 `P5-04` 하나입니다(앱 배포 뒤 별도 승인). 상담 기록 범위(`counseling_scope`)는 학교가 정하는 입력 칸이고 기본값이 없습니다.
- 시간표와 독립입니다. 담당 교사는 **수업 담당 지정(`course_assignments`)** 으로만 정하고 시간표에서 추측하지 않습니다.
- 학생 개인 기록(관찰 · 상담 · 평가 · 활동 원문)은 **쓴 교사 본인만** 봅니다. 학교 관리자도 다른 교사의 기록을 보지 못합니다. 감사 기록에는 본문을 남기지 않습니다.
- P4(문서함)가 있으면 학생 기록 검토 초안의 근거를 P5 의 실제 판으로 대조합니다. P4 가 없어도 P5 는 그대로 동작합니다(둘 다 시험함).
- 기존 로그인 · 가입 승인 · 회원 · 평가계획서 · 수합 · 업무실 일정/업무 · 학교 관리 · 협업 · 메시지 · 자료/문서함은 건드리지 않습니다(`P5-00` 지문으로 확인).
- **R0 · R1 · R1S · P1~P4 를 다시 실행하거나 고치지 않습니다. R0-90 도 쓰지 않습니다.**

## 4. 멈춤 기준

아래 중 하나라도 보이면 **다음 파일로 넘어가지 말고** 그 행·메시지를 알려 주세요.

- P5-00 실행 전 결과에 `FAIL`
- P5-01/02 가 `ERROR` 로 끝남, 또는 마지막 결과에 `ok` 가 아닌 행
- P5-03 에 `FAIL`
- P5-00 실행 후 구조 지문(S1~S6)이 실행 전과 다름
- 6번 사이트 확인에서 기존 기능 하나라도 이상

P5-01·02 가 이미 적용된 뒤 멈춰야 한다면 **되돌리는 SQL 을 즉석에서 만들지 않습니다.** 활성화 행이 없으면 P5 함수는 모두
`UNAVAILABLE` 이고, 새 표에는 API 역할 권한이 없으며, 기존 표·함수는 그대로입니다
(시험 II: P1~P5 비활성 설치 위에서 R1 시험 244건 그대로 통과). 그대로 두고 원인을 먼저 봅니다.

## 7. 실제 환경에서 시험하지 못한 것

시험은 로컬 PostgreSQL 17 에 Supabase 의 역할 · `auth.uid()` 를 흉내 낸 DB 에서 했습니다(`P5_시험결과.md`).
다음은 실제 Supabase · Vercel 에서 처음 확인하게 됩니다.

- 실제 PostgREST 를 거친 호출. 시험은 PostgREST 와 같은 경로(authenticator → set role → `request.jwt.claims`)로 불렀습니다
- 실제 앱 화면(PR #48)의 왕복. 앱 어댑터 · parser · 명령 검사는 실제 코드로 대조했지만 브라우저 · Supabase 클라이언트는 거치지 않았습니다
- 실제 교사가 내보낸 CSV(엑셀 저장 형식 · 아주 긴 셀 · 500행 가까운 파일). 시험은 BOM · CRLF · 따옴표 · 셀 안 줄바꿈 · `=` 로 시작하는 셀을 넣은 합성 CSV 로 했습니다
- 운영 DB 의 잠금 대기와 응답 시간. 시험은 동시 요청 2~4건, 학생 105건 기록의 쪽 넘김까지
- 실제 학적 자료(학교내학생번호 체계). 시험은 합성 학생키
