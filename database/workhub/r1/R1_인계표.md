## 3. 남은 승인·결정 (계란님)

1. R1 SQL 적용 (R1-00 → 01 → 02 → 03 → 04 → 00) — Codex 재검토 후.
2. 수합 정책값: 허용 형식, 파일 크기·개수, 미검사 파일 허용 여부, 업로드 예약 시간, 직접 철회·정정 허용과 최대 기간, 미첨부 보존 일수.
   압축 해제 한도(ZIP 항목 수·확장 크기·압축률·XML 크기)를 정책 항목으로 둘지도 함께 — 지금은 정책에 없어 작업자 기술 상한을 씁니다.
3. 작업자 구현 착수와 실행 위치(Vercel cron 등), service_role 키 보관 위치.
4. 작업자 연결(R1-05).
5. 공개 범위 — 업무실은 지금처럼 superadmin 전용.

## 4. SQL 실행과 병합 순서

DB 변경은 브랜치로 되돌릴 수 없습니다.
이 PR 은 SQL·문서·시험 도구만 담고 앱 코드를 바꾸지 않으므로, **병합과 SQL 실행의 순서는 서로 묶이지 않습니다**.
앱 PR(#34·#35)이 SQL 보다 먼저 배포되면 수합 화면은 함수가 없어 조회 실패 또는 "연결 준비가 필요합니다" 로 보일 수 있습니다(쓰기는 일어나지 않음).
업무실은 superadmin 전용이라 교사에게는 보이지 않습니다.
권장: Codex 검토 → SQL 실행(R1-00~04) → 이 PR 병합.
