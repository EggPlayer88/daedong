# R1 호환 함수 입출력

2026-10-15 · 앱(PR #35 `apps/workhub/src/collections/supabase-collections.ts`)이 부르는 이름·인자 이름과 같습니다.
예시는 시험 DB 의 실제 응답에서 옮겼습니다(ID 는 시험값).

## 1. 공통

### 봉투

모든 앱 함수(9개)는 `jsonb` 하나를 돌려줍니다.

```json
{"contractVersion": 1, "schoolId": "<학교>", "memberId": "<호출 소속>", "data": { ... }}
{"contractVersion": 1, "schoolId": "<학교>", "memberId": "<호출 소속>", "error": {"code": "CONFLICT"}}
```

- `error.code` 는 `NOT_READY | INVALID_INPUT | FORBIDDEN | INACTIVE_MEMBERSHIP | NOT_FOUND | CONFLICT | IDEMPOTENCY_CONFLICT | FILE_NOT_READY | FILE_FAILED` 중 하나.
- 오류 봉투가 나간 명령은 원본·접수증·감사·outbox 를 하나도 남기지 않습니다.
- **소속 gate 실패는 봉투가 아니라 R0 와 같은 SQL 예외**입니다(`FORBIDDEN` / `INACTIVE_MEMBERSHIP`, PostgREST 오류의 `message`).
  로그인 없음, 승인 대기, superadmin 아님, 남의 소속 ID, 끝난 소속이 여기에 해당합니다. 앱의 `ContractError` 경로가 받습니다.
- 그 밖의 예기치 못한 DB 오류는 봉투로 감싸지 않고 그대로 올라갑니다 → 앱은 쓰기면 `RESULT_UNKNOWN`, 읽기면 `QUERY_FAILED`.

### 접수증 (명령·파일 공통)

```json
{"requestId": "22ab385e-…", "resourceId": "22ab385e-…", "resourceVersion": 1, "recordedAt": "2026-10-15T01:50:10.553Z", "requestKey": "k-e188e3…"}
```

같은 `requestKey` + 같은 본문 → 최초 접수증 그대로(변경 0건). 같은 키 + 다른 본문 → `IDEMPOTENCY_CONFLICT`.
재전송 때 그 원본을 지금 읽을 수 없으면 `NOT_FOUND`. 요청 번호는 8~200자.

### 접수 연산 이름 (R0 `idempotency_receipts.operation`)

| 연산 | 함수 |
|---|---|
| `collection.mutate` | `workhub_collection_mutate` (명령 8종 공통) |
| `file.prepare` | `workhub_file_prepare` |
| `file.complete` | `workhub_file_complete` |

감사(`audit_events.operation`): `collection.<명령 종류>`(create·update·publish·save_draft·submit·review·withdraw·open_correction), `file.prepare`, `file.upload_confirm`(실물 확인 때 한 번), `file.access`, `file.verify`, `file.verify_fail`(일시 실패와 최종 거부 모두, `final` 표시), `file.cleanup_block`, `file.cleanup`.
outbox 주제: `collection.<명령 종류>`, `file.prepared`, `file.uploaded`, `file.verified`(봉인과, claim·fail 의 최종 거부로 파일이 rejected 가 될 때).

## 2. 앱 함수 9개 (`authenticated` 만)

| 서명 | data | 주요 오류 |
|---|---|---|
| `workhub_collection_readiness(p_member_id text)` | `{available, reason, policy}` | — |
| `workhub_collection_list(p_member_id text, p_cursor text)` | `{items: CollectionRequest[≤50], nextCursor}` | 위조·남의 cursor `INVALID_INPUT`, 전체 중지 `NOT_READY` |
| `workhub_collection_get(p_member_id text, p_request_id text)` | `{request, units, submissions, reviews, supplements, withdrawals}` | 볼 수 없음·게시 전(관리자 아님) `NOT_FOUND`, 제출판 1,000 초과 `NOT_READY` |
| `workhub_collection_draft_get(p_member_id text, p_request_id text, p_unit_id text)` | `CollectionDraft` 또는 `null` | 관리자·검토자(공동 구성원 아님) `FORBIDDEN`, 다른 단위 `NOT_FOUND` |
| `workhub_collection_mutate(p_member_id text, p_command jsonb, p_request_key text)` | 접수증 | 아래 명령표 |
| `workhub_file_prepare(p_member_id text, p_parent jsonb, p_file jsonb, p_request_key text)` | `{fileId, bucket, path, expiresAt, state}` | 제출판 부모 `INVALID_INPUT`, 정책 밖 `FILE_FAILED`, 부모 판 `CONFLICT`, 열린 예약 100개 초과 `NOT_READY` |
| `workhub_file_complete(p_member_id text, p_file_id text, p_request_key text)` | `{fileId, state, file}` | 남의 파일 `NOT_FOUND` |
| `workhub_file_status(p_member_id text, p_file_id text)` | `{fileId, state, file}` | 남의 파일 `NOT_FOUND` |
| `workhub_file_access(p_member_id text, p_parent jsonb, p_file_id text)` | `{file, bucket, path}` | 초안 비구성원 `FORBIDDEN`, 판 다름 `CONFLICT`, 철회판 `FORBIDDEN`, 다른 단위 `NOT_FOUND`, 파일 문제 `FILE_NOT_READY`/`FILE_FAILED` |

모든 쓰기(`mutate`·`prepare`·`complete`)는 준비 상태가 `ready` 가 아니면 `NOT_READY` 입니다.
`access` 는 중지(writes_stopped)·검증기 중단 중에도 됩니다(이미 받은 파일 내려받기 유지). 전체 중지면 `NOT_READY`.

### 준비 상태

```json
{"available": false, "reason": "verification_missing", "policy": null}
{"available": true, "reason": "ready", "policy": {"extensions": ["pdf", "hwpx", "docx"], "maxFileBytes": 8000000, "maxFiles": 4}}
```

`reason`: `database_missing`(R1 미적용·중지) → `storage_missing` → `verification_missing` → `policy_missing` 순으로 처음 걸린 것.
`policy` 는 학교 업로드 정책 ∩ 공통 하한(형식은 정해진 순서, 크기·개수는 작은 값).

### 명령 8종 (`p_command.kind`)

| kind | 필수 키 | 결과(resourceId) | 대표 거부 |
|---|---|---|---|
| `create` | `input` | 새 수합(판 1) | 배부 파일 포함·키 누락/추가·검토자=책임자 계정(`FORBIDDEN`)·대상 소속 무효 `INVALID_INPUT`, 오늘이 든 학년도 없음/중복 `NOT_READY` |
| `update` | `requestId, expectedVersion, input` | 수합(판+1) | 관리자 아님 `FORBIDDEN`(게시 전 비관리자 `NOT_FOUND`), 판 `CONFLICT`, 게시 후 `FORBIDDEN` |
| `publish` | `requestId, expectedVersion` | 수합(판+1) | 위와 같음. 대상·정책·파일을 다시 검사 |
| `save_draft` | `requestId, unitId, expectedVersion(0=첫 저장), input{text, number[, files]}` | 초안(판+1) | 공동 구성원 아님 `FORBIDDEN`, 판 `CONFLICT`, 미검증 파일 `FILE_NOT_READY`, 다른 단위 파일 `FORBIDDEN` |
| `submit` | `requestId, unitId, draftId, expectedDraftVersion, expectedVersion, reason[, correctionRequestId]` | 제출판 | 책임자 아님 `FORBIDDEN`, 재제출인데 사유 없음 `INVALID_INPUT`, 마감 뒤 재제출(정정창 없음) `FORBIDDEN` |
| `review` | `requestId, unitId, submissionId, expectedVersion, decision, note, dueDate` | 단위(판+1) | 지정 검토자 아님 `FORBIDDEN`, 이미 검토 `CONFLICT`, 보완 기한 과거 `INVALID_INPUT` |
| `withdraw` | `requestId, unitId, submissionId, expectedVersion, reason` | 단위(판+1) | 책임자 아님·완료본(승인판)·정책상 직접 철회 불가·마감 뒤 `FORBIDDEN` |
| `open_correction` | `requestId, unitId, expectedVersion, dueDate, reason` | 단위(판+1) | 관리자 아님 `FORBIDDEN`, 정책 최대 일수 초과 `INVALID_INPUT` |

숫자 자리에 문자열·NaN, 모르는 키, 제어문자, JS 길이 기준 초과(이모지 2) → `INVALID_INPUT`.

### 파일 부모 (`p_parent`)

```json
{"kind": "template", "requestId": "…", "version": 3}
{"kind": "draft", "requestId": "…", "unitId": "…", "version": 5}
{"kind": "submission", "requestId": "…", "unitId": "…", "submissionId": "…"}
```

`prepare` 는 `template`·`draft` 만(제출판에는 새 파일을 붙이지 않음). `access` 는 셋 다.

### 파일 예시

```json
// prepare
{"fileId": "937615b8-…", "bucket": "workhub-collection-files", "path": "<학교>/<fileId>/dabd8b513c4c4e1f86402e4185d04ed4", "expiresAt": "2026-10-15T02:20:10.736369Z", "state": "awaiting_upload"}
// complete / status
{"fileId": "937615b8-…", "state": "pending_verification", "file": null}
// access
{"file": {"id": "a625a079-…", "name": "보고서.pdf", "extension": "pdf", "bytes": 3000, "sha256": "7493…d154"}, "bucket": "workhub-collection-files", "path": "<학교>/<fileId>/234a…8d96"}
```

`state`: `awaiting_upload`(실물 없음) → `pending_verification`(실물 있음, 검사 전·중) → `ready`(서버 검증값이 담긴 `file`) 또는 `rejected`.
만료된 예약은 실물이 없으면 `rejected` 로 보입니다. `file` 은 `ready` 일 때만 있습니다.
`expiresAt` 은 마이크로초까지(6자리), 접수증 `recordedAt` 은 밀리초(3자리)입니다 — 앱 `instant()` 는 둘 다 통과합니다(앱 대조 시험).

## 3. 작업자 함수 8개 (`service_role` 만, 봉투 없음)

오류는 SQL 예외 코드 문자열: `FORBIDDEN`(연결·범위 없음, 사람 JWT), `NOT_FOUND`, `INVALID_INPUT`(NULL 인자 포함), `CONFLICT`(lease 불일치·만료·옛 token·다른 주체·다른 결과),
`NOT_READY`(전체 중지 중의 새 봉인·정리 확정). 세부와 Codex 코어 대응은 `R1_검증작업자_후속명세.md`.

| 서명 | 반환 |
|---|---|
| `workhub_file_worker_heartbeat(p_school_id text, p_worker_id text, p_capability jsonb, p_ttl_seconds integer)` | `{servicePrincipalId, expiresAt}` |
| `workhub_file_worker_claim(p_school_id text, p_worker_id text, p_limit integer)` | `[{jobId, leaseToken, leaseExpiresAt, fileId, bucket, path, storageObjectId, extension, claimedBytes, claimedSha256, maxFileBytes, policy}]` |
| `workhub_file_worker_job_inspect(p_job_id text, p_lease_token bigint)` (읽기 전용) | `{jobId, fileId, state, outcome, lastErrorCode, leaseValid, leaseExpiresAt, fileState, bucket, path, storageObjectId, objectMatches, policy}` |
| `workhub_file_worker_seal(p_job_id text, p_lease_token bigint, p_file_id text, p_path text, p_storage_object_id uuid, p_result jsonb)` | `{fileId, state, replayed}` |
| `workhub_file_worker_fail(p_job_id text, p_lease_token bigint, p_error_code text, p_retry_after_seconds integer)` | `{fileId, state, final}` |
| `workhub_file_worker_cleanup_claim(p_school_id text, p_worker_id text, p_limit integer)` | `[{ledgerId, leaseToken, fileId, bucket, path, storageObjectId, reason}]` |
| `workhub_file_worker_cleanup_inspect(p_ledger_id text, p_lease_token bigint)` (읽기 전용) | `{ledgerId, fileId, state, outcome, retainedReason, leaseValid, leaseExpiresAt, linked, verifying, bucket, path, storageObjectId, objectPresent, objectMatches}` |
| `workhub_file_worker_cleanup_done(p_ledger_id text, p_lease_token bigint, p_outcome text, p_reason text)` | `{fileId, ledgerId, outcome, replayed}` |

`policy` = `{uploadPolicyId, commonPolicyId, currentUploadPolicyId, currentCommonPolicyId, extensions, maxFileBytes, allowUnscanned}` — 예약 때 고정한 정책판 ∩ 오늘 유효한 정책.
`maxFileBytes` 는 `policy.maxFileBytes` 와 같습니다(전에는 기술 상한 100MiB 고정값이었음).

## 4. Storage 정책 판정 (앱이 직접 부르지 않음)

| 요청 | 허용 조건 |
|---|---|
| 업로드(INSERT) | 요청 종류가 직접 업로드(`storage.object.upload`) + 이 JWT 계정이 만든 만료 전 예약의 **정확한 경로**, 소속·승인 gate 다시 통과, 스위치 open |
| 읽기(SELECT) | 업로드 요청 안에서 본인 되읽기, 또는 요청 종류가 직접 내려받기(`storage.object.get_authenticated`) + `ready` 파일 + 이 계정의 만료 전·미회수 접근 기록 + 그 소속으로 원본 해석을 지금 다시 통과 |
| 서명 URL 발급(`sign`·`sign_many`·`sign_upload_url`)·목록·이동·복사·TUS·S3 | 거부. 앱(PR #35)은 SDK `upload`·`download` 만 쓰므로 영향 없음 |
| 교체(UPDATE)·삭제(DELETE) | 정책 없음 → 불가 |
