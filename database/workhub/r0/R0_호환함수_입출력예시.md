# R0 앱 호환 함수 7개 — 입력·출력 예시

시험 DB(PostgreSQL 17.6)에서 **실제로 호출해 받은 값**이다. 호출 경로는 PostgREST 와 같게 `authenticator` 로그인 → `authenticated` 역할 → JWT claims(sub = Auth UID) 순서로 맞췄다. id 는 시험 때 생성된 값이라 운영에서는 다르다.

## 공통 규칙

| 항목 | 내용 |
|---|---|
| 위치 | `public` (SECURITY DEFINER, `search_path = ""`). 실제 자료는 `workhub` schema |
| 실행 권한 | `authenticated` 만. `anon`·`service_role`·PUBLIC 은 없음 |
| 공개 범위 | 로그인 + `public.is_approved()` + `public.get_my_role() = superadmin` (기존 함수 그대로 호출) |
| 오류 | `message` = 코드 문자열 (앱 `rpcFailure` 가 그대로 읽음). `CONFLICT` 는 `details` 에 현재 원본 JSON |
| 오류 코드 | `FORBIDDEN` 로그인·승인·superadmin 아님 / `INACTIVE_MEMBERSHIP` 내 소속이 아니거나 현재 유효하지 않음 / `NOT_FOUND` 없거나 열람 불가 / `INVALID_INPUT` 형식 위반 / `CONFLICT` 판 불일치 / `IDEMPOTENCY_CONFLICT` 같은 요청 번호에 다른 입력 |
| 날짜 | 앱은 마지막 날 포함(`validThrough`), DB 는 종료 제외(`valid_to`). 함수가 하루를 빼서 돌려준다. 무기한은 `9999-12-31` |
| 시각 | `startTime`/`endTime` 은 학교 시간대(Asia/Seoul) HH:MM, DB 는 UTC timestamptz. `updatedAt` 은 UTC ISO(`Z`) |

| 함수 | 인자 | 반환 |
|---|---|---|
| `workhub_context()` | 없음 | `{schools, memberships, basisDate, schoolLabels}` |
| `workhub_calendar_list(p_member_id text)` | 내 소속 id | 일정 배열 |
| `workhub_calendar_get(p_member_id text, p_event_id text)` | 소속 id, 일정 id | 일정 |
| `workhub_calendar_save(p_member_id text, p_command jsonb)` | `{draft, id?, expectedVersion?, idempotencyKey}` | 저장된 일정 |
| `workhub_task_list(p_member_id text)` | 소속 id | 본인 업무 배열 |
| `workhub_task_get(p_member_id text, p_task_id text)` | 소속 id, 업무 id | 업무 |
| `workhub_task_mutate(p_member_id text, p_command jsonb, p_request_key text)` | `{kind:create,input}` / `{kind:update,taskId,input,expectedVersion}` / `{kind:status,taskId,status,expectedVersion}`, 요청 번호 | 저장된 업무 |
