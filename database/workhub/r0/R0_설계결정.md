## 2. 먼저 닫은 설계 항목

### F5 — 배치 순서와 미래 참조

- **접수·감사·outbox 를 B01 로** 당겼습니다. B01 의 첫 쓰기(초기 설정)부터 감사가 남습니다.
- **학년도·학기**를 B01 에 두어 일정·업무(B02)보다 먼저 생깁니다. 업무는 만들 때 오늘이 속한 학년도에 연결됩니다.
- **아직 없는 표를 가리키는 열**은 열은 만들고, FK 대신 이름 붙은 `*_pending CHECK (열 IS NULL)` 로 입력을 막았습니다. 후속 배치는 그 CHECK 를 지우고 FK 를 붙이면 됩니다. FK 를 지우거나 `NOT VALID` 로 우회하지 않습니다.

  | 보류 표식 | 기다리는 표 | 후속 배치 |
  |---|---|---|
  | `accounts_legacy_run_pending` | migration_runs | 교사 일괄 연결 |
  | `memberships_join_code_pending` | school_join_codes | 신규 가입 |
  | `terms_timetable_basis_pending` | timetable_basis_revisions | 시간표 |
  | `events_duty_pending`, `events_source_record_pending` | duties, source_records | 업무 분장·원천 기록 |
  | `audit_events_support_pending`, `audit_events_job_pending` | support_sessions, jobs | 지원·작업 큐 |
  | `tasks_source_pending` (direct + manual 만) | 수합·일정 연동 | 수합 |

### F6 — 접수증·감사 계약 교체

- `idempotency_receipts`: 기존 `actor_account_id` 기반 PK → **`PRIMARY KEY (actor_key, scope_key, operation, idem_key)`**, `actor_key` 는 생성 열(`a:<계정>` 또는 `s:<서비스 주체>`, 통합 설계 정의 그대로), **사람 XOR 서비스 주체** CHECK. 결과(`result`)에는 id·판·시각만 담고 본문은 담지 않습니다(트리거로 강제). 접수증은 수정 불가.
- `audit_events`: `<= 1` CHECK → **`= 1`(XOR)**. 소속이 있으면 계정도 있어야 하고, 3열 FK 로 그 소속이 같은 학교·같은 계정임을 DB 가 보장합니다. 감사 기록은 수정·삭제 불가.
- 모든 쓰기 명령은 **한 트랜잭션에** 원본 변경 + 접수증 + 감사 + outbox 를 씁니다. 마지막 단계(outbox)가 실패하면 앞의 것도 모두 취소되는 것을 시험했습니다(T41).

### F8 — 기존 승인 gate 와 공개 범위 보존

- 새 gate `workhub_private.legacy_gate` 는 기존 함수를 **그대로 호출**합니다: `auth.uid()` 있음 AND `public.is_approved()` AND `public.get_my_role() = 'superadmin'`.
- 쓰기 경로에서는 `public.users` 의 본인 행을 `FOR SHARE` 로 잡습니다. 저장 도중 기존 사이트에서 승인을 해제하면 그 해제는 저장이 끝날 때까지 기다립니다(T52). 회원 행을 바꾸지는 않습니다.
- 공개 범위를 넓히는 설정 표는 **만들지 않았습니다.** 교사에게 여는 것은 별도 SQL 배치로만 가능하고, 그것은 계란님 승인 사항입니다.
- 기존 사이트에서 승인을 해제하면 업무실도 **즉시** 막힙니다(T27).

## 3. 구조 요약

```
public (기존, 변경 없음)
  └ workhub_context / calendar_list·get·save / task_list·get·mutate   ← 새로 7개, authenticated 만 실행
        │ SECURITY DEFINER, search_path = ''
        ▼
workhub_private (API 노출 없음)
  legacy_gate → caller_account → member_actor → member_has_perm
  claim_receipt / store_receipt / write_audit / emit_outbox
  bootstrap_first_school (SQL Editor 전용)
        ▼
workhub (API 노출 없음, RLS 켬, API 역할 표 권한 0)
  schools · accounts · service_principals · service_principal_scopes · departments
  role_catalog · role_permissions · memberships · membership_roles
  academic_years · terms · idempotency_receipts · audit_events · outbox
  audience_sets · audience_groups · audience_conditions · audience_members
  events · event_revisions · tasks
```

- `workhub` schema 를 API 에 노출하지 않으므로 **Supabase 대시보드 설정을 바꿀 필요가 없습니다.**
- 잠금 순서: 회원(`public.users`) → 계정 → 학교 → 소속 → 역할 → 요청 번호(advisory) → 원본.
- 서비스 주체는 함수 인자나 세션 변수로 넘기지 않고, **DB 실행 역할(session_user)을 허용 목록**(`workhub_private.db_identity_principals`)으로 해석합니다. R0 의 서비스 주체는 초기 설정용 `svc_bootstrap` 하나이고, 초기 설정이 끝나면 범위 승인이 모두 회수됩니다(T61).

## 5. 승인이 필요한 것 (CLAUDE.md 2절)

- **DB 스키마 추가** — R0 전체가 승인 대상입니다. 실행은 계란님이 현재 프로젝트 SQL Editor 에서 합니다(`R0_실행안내.md`).
- 인증·보안 로직: 기존 gate 를 **호출만** 하고 바꾸지 않았습니다. 새 gate 자체는 승인 대상입니다.
- 비용 구조·외부 서비스 설정·D번호: 변경 없음.
