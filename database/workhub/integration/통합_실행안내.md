# 1~7단계 SQL 통합 실행 안내 (계란님용)

2026-10-16 · Claude Code. **이 문서는 안내입니다. Claude 는 SQL 을 실행하지 않습니다.** 실행은 계란님이 Supabase SQL Editor 에서 합니다.
각 단계의 자세한 칸 설명은 그 단계의 `*_실행안내.md` 에 있고, 이 문서는 **한 DB 에 차례로 올릴 때의 전체 순서 · 정상 결과 · 멈춤 기준**만 모읍니다.

## 0. 먼저 읽을 것

- **R0 · R1 은 이미 적용되어 있으므로 다시 실행하지 않습니다.** `R0-*` · `R1-01~03` 재실행, R0 되돌림(R0-90)은 이 안내에 없습니다.
- 이번 안내는 **비활성 설치**까지입니다. 설치만으로는 어떤 화면도 켜지지 않고(모든 새 함수가 `NOT_READY`), 외부 호출(Claude · 파일 검사)도 0회입니다.
  **SQL 만 적용했다고 "준비 완료"가 아닙니다.** 켜는 것(각 단계 `-04` · `-05` 양식)은 6절의 조건을 갖춘 뒤 따로 승인합니다.
- 파일은 **GitHub 에서 받은 그대로**(통합 PR 의 head) 씁니다. 붙여 넣기 전에 파일 첫 줄의 단계 이름을 확인해 주세요.
- 한 파일은 **한 번에 통째로** 실행합니다(일부만 선택 실행하지 않음). 각 설치 파일은 실패하면 전부 되돌아가서 아무것도 남기지 않습니다(시험 I 구간).
- 결과 표에 `FAIL` 이 한 줄이라도 있으면 **거기서 멈추고** 그 행을 그대로 알려 주세요. 다음 파일로 넘어가지 않습니다.

## 1. 시작 전 기준선 (읽기만)

| 순서 | 할 일 | 정상 결과 | 아니면 |
|---|---|---|---|
| 0-1 | `integration/INT-03_통합사후점검.sql` 실행 → 결과 저장 | 13행. `INT-03-01` 의 값이 `R0 · R1`, `FAIL` 없음 | 멈춤. **운영 DB 의 R0 · R1 이 시험 DB 와 다르다는 뜻**이라, 그 행 값을 알려 주시면 원인을 먼저 봅니다 |
| 0-2 | `R1-04` 실행 | 지금까지와 같은 결과(`FAIL` 없음) | 멈춤 |

> **0-1 은 설치 승인과 별개인 읽기 전용 기준선입니다.** 이것을 돌린다고 설치를 승인하는 것이 아니고, 설치는 이 결과를 보고 따로 정합니다.
> 특히 볼 행: `INT-03-04`(API 역할 실행 권한 — 직접 부여와 **상속으로 생긴 실효 권한** 둘 다), `INT-03-08`(함수 소유자가 허용표 `postgres` 인지).
> 시험 DB 의 소유자 · 역할 구성은 Supabase 를 흉내 낸 것이라, 운영 DB 에서 다르게 나오면 **그 결과를 정답으로 삼아 허용표를 고치지 않고** 멈춰서 원인을 봅니다.
> 0-1 은 이번에 처음 실제 DB 에서 돌리는 점검입니다. 시험 DB 는 Supabase 를 흉내 낸 것이라, 운영 DB 의 R0 · R1 함수 권한이나 소유자가
> 다르게 나올 가능성이 있습니다. 그 경우 설치를 시작하지 않고 차이부터 확인합니다(코드로 덮지 않습니다).

## 2. 단계별 설치 순서

모든 단계가 같은 모양입니다: **`-00`(지문, 저장) → `-01` → `-02` → `-03`(사후 점검) → `-00` 다시(비교) → 사이트 확인 → `INT-03`.**
각 단계의 정상 결과 숫자는 그 단계 `*_실행안내.md` 3절 표에 있습니다. 여기서는 단계를 넘어갈 때 볼 것만 적습니다.

- 각 단계 뒤 **`INT-03` 을 같이 돌립니다.** 정상은 13행 · `FAIL` 없음 · `INT-03-01` 값이 위 표의 조합입니다. 이 한 파일이 지금까지 올린 모든 단계의 함수 이름 · 인자 · 실행 권한(직접 · 상속) ·
  SECURITY DEFINER · search_path · 본문 · 소유자(허용표) · 트리거 · 제약 · 정책을 한꺼번에 봅니다(이미 있던 R1 함수 권한이 바뀐 것도 잡음).
- 앞 단계의 `-00` 을 뒤 단계 설치 후 다시 돌리면 구조 지문이 바뀌는 것은 정상입니다(뒤 단계 표 · 함수를 같이 세기 때문). 비교는 **그 단계 안에서(설치 직전 ↔ 직후)만** 합니다.
- 단계 사이에 시간이 떠도 됩니다. 순서만 지키면 됩니다(P3 · P4 · P5 · P6 은 선행 단계가 없으면 `-01` 이 "먼저 적용해 주세요"로 멈춤).
- **P7-05 는 R1 · P2 원본 정의를 바꾸는 유일한 파일**입니다(마감 · 연장 · 수합/협업 인계 · 마감 뒤 보완의 바탕). 결정표 Q1 · Q6 결정 뒤에만 실행합니다.
  P7-05 없이도 P7 은 설치되고, 마감 · 연장 · 수합/협업 인계는 `NOT_READY` 로 남습니다.

## 3. 멈춤 기준 (어느 단계든 공통)

| 보이는 것 | 뜻 | 할 일 |
|---|---|---|
| `-00` 에 `FAIL` | 선행 조건이 맞지 않음(앞 단계 미적용 · 같은 이름 객체 있음 등) | 그 단계 시작하지 않음. 행을 알려 주세요 |
| `-01` · `-02` 가 오류로 멈춤 | 파일이 스스로 멈춤(선행 조건 · 이미 적용 · 이름 충돌). **아무것도 남지 않음** | 메시지를 그대로 알려 주세요. 다시 실행하지 않음 |
| `-03` 또는 `INT-03` 에 `FAIL` | 설치 결과가 예상과 다름 | 다음 단계로 가지 않음. 행 값을 알려 주세요 |
| `-00` 재실행 지문이 다름(구조 행 S1~S6 등) | 설치가 기존 구조를 건드림 | 멈춤. 다른 행 이름을 알려 주세요(자료 지문 D1 은 그사이 사용이 있으면 다를 수 있음) |
| 사이트 확인에서 기존 기능 이상 | 로그인 · 평가계획서 · 수합 · 업무실 | 멈춤. 증상을 알려 주세요 |

## 4. 멈추는 방법 (자료를 지우지 않음)

- **설치 도중 멈춤**: 그냥 다음 파일을 실행하지 않으면 됩니다. 이미 올린 단계는 비활성이라 화면 · 외부 호출에 영향이 없습니다.
- **켠 뒤 멈춤**(나중 일): 학교 단위 `R1S-80` · `P1-80`, 모듈 단위 `P2-80`(P2~P7 모듈 공통). 다시 켤 때는 `-81`. 자료 · 기록은 그대로 남습니다.
- **되돌리는(지우는) 파일은 이번 범위에 없습니다.** P7-05 도 되돌림 파일이 없고 원래 정의는 `P7_설계결정.md` 부록에 있습니다. 되돌릴 일이 생기면 먼저 상의합니다.
- R0 되돌림(R0-90) · R1 제거(R1-82 계열)는 쓰지 않습니다.
