# 학교 자료 · HWPX 원문 가져오기 · 문서함 · 질문형 양식(P4) 실행 안내

2026-10-16 · 작성: Claude Code · 검토: Codex · 실행: 계란님

P4 는 통합 SQL 요청서(`docs/workhub/pilot-completion/sql-handoff.md`)의 **4단계 — 학교 자료 · 원문 가져오기 · 문서함 · 질문형 양식** 증분 SQL 입니다.
앱 계약은 PR #48 의 `apps/workhub/src/knowledge/*.ts` · `apps/workhub/src/documents/*.ts` 와
서버 API `apps/main/api/workhub-documents/extract-knowledge.py` · `guided.py` 입니다.

- **SQL 을 적용해도 아무 학교에서도 켜지지 않습니다(비활성 설치).** 네 모듈 모두 `NOT_READY`, 준비 사유는 `policy_missing` 입니다.
- 켜는 것은 둘로 나뉩니다. `P4-04` = 학교 자료 + 문서함(앱 배포 뒤 별도 승인). `P4-05` = 원문 가져오기 또는 질문형 양식(모듈 하나씩,
  **서버 API 운영 배포를 확인한 기록**을 받아야만 실행됨). **SQL 만 적용했다고 원문 가져오기·양식이 준비 완료로 보이지 않습니다.**
- 서버 API 의 HWPX 처리는 구조·크기·SHA 확인과 본문 추출·칸 채우기입니다. **악성코드 검사가 아니고 그렇게 기록하지도 않습니다**
  (P4-05 감사 기록에 `malware_scan: false`).
- 학생 기록 검토 초안(`student_record`)은 5단계(학생·수업)가 근거 확인 함수를 넣기 전까지 `NOT_READY` 입니다(확인한 척하지 않음).
- 기존 로그인·가입 승인·회원·평가계획서·수합·업무실 일정/업무·학교 관리·협업 자료·메시지는 건드리지 않습니다(`P4-00` 지문으로 확인).
- **R0·R1·R1S·P1·P2·P3 를 다시 실행하거나 고치지 않습니다. R0-90 도 쓰지 않습니다.**

## 4. 멈춤 기준

아래 중 하나라도 보이면 **다음 파일로 넘어가지 말고** 그 행·메시지를 알려 주세요.

- P4-01/02 가 `ERROR` 로 끝남, 또는 마지막 결과에 `ok` 가 아닌 행

- P4-00 실행 후 구조 지문(S1~S6)이 실행 전과 다름

`NOT_READY` 이고, 새 버킷 두 곳에는 아무도 올리거나 읽을 수 없으며, 기존 표·함수·수합·메시지 버킷은 그대로입니다
(시험 II: 비활성 설치 위에서 R1 시험 244건 그대로 통과). 그대로 두고 원인을 먼저 봅니다.

## 7. 실제 환경에서 시험하지 못한 것

시험은 로컬 PostgreSQL 17 에 Supabase 의 역할·`auth.uid()`·`storage.objects` 를 흉내 낸 DB 에서 했습니다(`P4_시험결과.md`).
다음은 실제 Supabase·Vercel 에서 처음 확인하게 됩니다.

- 실제 PostgREST · **실제 Storage API** 를 거친 업로드·내려받기. 시험은 `storage.objects` 행 INSERT/SELECT 와
  `storage.operation` 설정으로 RLS 판정만 흉내 냈습니다(Storage 서버가 실제로 그 값을 넣는지는 R1S·P3 와 같은 전제)
- 운영 SQL Editor 의 `postgres` 역할이 `storage.objects` 에 정책을 만들 수 있는지 — P4-02 가 먼저 시험해 보고 안 되면 멈춥니다
- 실제 Vercel 에서 서버 API(`extract-knowledge.py` · `guided.py`)의 실행·시간 제한·메모리·서비스 키. 시험은 PR #48 의 실제
  `_knowledge_import.run` · `_guided_service.run` 을 가져와 Supabase 호출만 시험 DB(service_role)와 메모리 저장소로 바꿔 끼워 돌렸습니다
- 생성 파일을 서버가 Storage 에 올리는 실제 경로(service_role 업로드). 시험은 그 자리를 `storage.objects` 행 쓰기로 대신했습니다
- 실제 앱 화면(PR #48)의 왕복. 앱 어댑터·parser·서버 API 연결 코드는 실제 코드로 대조했지만 브라우저·Supabase 클라이언트는 거치지 않았습니다
- 실제 교사가 만든 HWPX(표 중첩·그림·긴 문서). 시험은 구조를 갖춘 작은 HWPX 로 했고, 그림은 누락 수로만 셉니다
- 운영 DB 의 잠금 대기와 응답 시간. 시험은 동시 요청 2~4건
