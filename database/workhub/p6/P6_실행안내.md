# Claude 비서 — 근거 · 대화 · 예산 · 할 일 제안 · 단일 호출 원장(P6) 실행 안내

2026-10-16 · 작성: Claude Code · 검토: Codex · 실행: 계란님

P6 는 통합 SQL 요청서(`docs/workhub/pilot-completion/sql-handoff.md`)의 **6단계 — Claude 근거 · 대화 · 예산 · 제안 · 단일 호출 원장** 증분 SQL 입니다.
앱 계약은 PR #48 의 `apps/workhub/src/assistant/*.ts` 와 서버 API `apps/main/api/workhub-ai/_assistant.py`(`assistant.v1`)입니다.

- **SQL 을 적용해도 아무 학교에서도 켜지지 않습니다(비활성 설치).** 준비 상태는 `not_configured`, 질문·대화는 `NOT_READY`, **모델 호출은 0회**입니다.
- 켜는 것은 `P6-04` 하나입니다(앱 배포와 서버 API 키 설정을 확인한 뒤, 별도 승인). **모델 · 가격 · 토큰 상한 · 일/월 예산은 모두 입력 칸이고 기본값이 없습니다.**
- 한 요청은 **모델을 한 번만** 부릅니다. DB 가 호출권(`start`)을 한 번만 내주고, 응답이 사라진 재전송은 원래 결과를 돌려줍니다. 결과를 모르는 호출을 0원 성공·실패로 치지 않습니다(`P6-05` 로 관리자가 확인).
- 근거는 사람 권한 그대로 고릅니다. 남의 나만 보기 문서 · 개인 일정 · 할 일, 다른 학교 자료, 초안 자료는 근거로 쓸 수 없습니다. 학생 근거는 P5 의 **현재 판 · 정확한 구간**만, 상담은 쓰지 않습니다.
- 원장에는 근거 **본문을 남기지 않습니다**(종류 · ID · 판 · 제목 · 위치만). 감사에도 질문 · 답 본문이 없습니다.
- 할 일 제안은 교사가 **확정해야** 할 일이 됩니다(R0 업무와 같은 규칙 · 감사 · outbox).
- 기존 로그인 · 가입 승인 · 회원 · 평가계획서 · 수합 · 업무실 · 학교 관리 · 협업 · 메시지 · 자료/문서함 · 수업은 건드리지 않습니다(`P6-00` 지문으로 확인).
- **R0 · R1 · R1S · P1~P5 를 다시 실행하거나 고치지 않습니다. R0-90 도 쓰지 않습니다.**

## 4. 멈춤 기준

`NOT_READY`(모델 호출 0)이고, 새 표에는 API 역할 권한이 없으며, 기존 표·함수는 그대로입니다

## 6. 계란님이 정할 값

이 SQL 은 어떤 정책값도 정해 두지 않았습니다. 칸이 남아 있으면 아무것도 쓰지 않고 멈춥니다.
숫자 칸은 **따옴표 없이 정수**로 씁니다(따옴표 · 소수 · 0 은 멈춤). 금액 단위는 micro USD(1 USD = 1,000,000)입니다.

**P6-04 (비서 켜기 · 설정 새 판)**

| 칸 | 무엇 | 규칙 |
|---|---|---|
| `approver_user_id` | 승인한 학교 관리자(school_admin)의 회원 id(Auth UID). 대상 학교 = 그 사람이 지금 관리자인 학교 1곳 | — |
| `approval_ref` | 승인 근거(결재 번호 등) | 1~200자 |
| `verification_ref` | 배포 확인 근거(앱 배포 · 서버 키 설정을 확인한 기록) | 1~200자 |
| `allowed_members` | 쓸 수 있는 사람. `all_members`(업무실을 쓰는 모든 소속 — 지금은 superadmin 만) · `school_admin`(학교 관리자만) | 둘 중 하나 |
| `model` | 모델 ID | 영문·숫자·`_.-` 1~150자 |
| `price_table_ref` | 가격표 근거(확인한 날짜 · 주소) | 1~200자 |
| `input_price_micro_usd_per_mtok` / `output_price_micro_usd_per_mtok` | 입력 · 출력 100만 토큰당 가격(micro USD) | 양의 정수 |
| `max_input_tokens` / `max_output_tokens` | 요청 1건 입력 · 출력 상한 | 양의 정수 |
| `member_daily_micro_usd` / `member_monthly_micro_usd` | 한 사람 하루 · 한 달 한도 | 1회 예약액 ≤ 사람 하루 ≤ 사람 한 달 |
| `school_daily_micro_usd` / `school_monthly_micro_usd` | 학교 하루 · 한 달 한도 | 사람 하루 ≤ 학교 하루 ≤ 학교 한 달, 사람 한 달 ≤ 학교 한 달 |

- **1회 예약액** = ceil((입력 상한 × 입력 가격 + 출력 상한 × 출력 가격) / 1,000,000). 질문마다 이만큼 먼저 잡고, 끝나면 실제 사용량으로 정산합니다.
- 하루 · 한 달은 학교 시간대(`schools.timezone`) 기준입니다.
- 설정 판은 고칠 수 없습니다. 바꾸려면 P6-04 를 다시 실행해 새 판을 만듭니다(이미 시작한 요청은 그때의 판으로 정산).
- 시험에서 쓴 숫자(예: 예약액 90,000)는 시험용입니다. 실제 값이 아닙니다.

| `resolution` | `charged`(콘솔에 사용량이 있음) · `not_charged`(사용량 없음) |

## 7. 실제 환경에서 시험하지 못한 것

시험은 로컬 PostgreSQL 17 에 Supabase 의 역할 · `auth.uid()` 를 흉내 낸 DB 에서, **PR #48 의 실제 서버 코드(`_assistant.execute`)** 에
가짜 DB 연결과 가짜 모델 응답기를 붙여 했습니다(`P6_시험결과.md`). 다음은 실제 Supabase · Vercel · Anthropic 에서 처음 확인하게 됩니다.

- 실제 PostgREST 를 거친 호출. 시험의 서버 API 호출은 PostgREST 와 같은 오류 변환(P0001 → `FORBIDDEN`/`INACTIVE_MEMBERSHIP` 만 403, 나머지 결과 불명)을 흉내 냈습니다
- **실제 Anthropic 호출**(응답 형식 · 사용량 숫자 · 거절 · 시간 초과). 시험은 가짜 응답기로 정상 · 거절 · 잘림 · 예외 · 인용 위조를 만들었습니다
- Vercel 함수 시간 제한과 응답 유실. 시험은 같은 경우를 서버 코드에 "응답 사라짐"으로 넣어 확인했습니다(G04~G07)
- 실제 콘솔 사용량과 원장 정산액의 일치(가격표가 맞는지)
- 실제 앱 화면(PR #48)의 왕복. 앱 연결 · parser 는 실제 코드로 대조했지만 브라우저는 거치지 않았습니다
- 운영 DB 의 잠금 대기와 응답 시간. 시험은 동시 요청 2~4건까지
