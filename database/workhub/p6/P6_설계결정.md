## 2. 요청 원장 · 단일 호출

| 번호 | 정한 것 | 이유 | 되돌리려면 |
|---|---|---|---|
| D-P6-1 | 요청 = `(사람, 학교, 요청 번호)` 1행. 같은 번호 · 같은 내용 재전송은 **준비 상태 확인보다 먼저** 원래 결과를 돌려줌. 같은 번호 · 다른 내용 → `IDEMPOTENCY_CONFLICT` | 중지 · 예산 소진 · 권한 축소 중에도 응답 유실을 복구할 수 있어야 한다(시험 H08·H11) | P6-02 `workhub_ai_prepare` 앞부분 |
| D-P6-1a | `prepare` 는 90초 임대(`p6_lease`)를 내주고, `start` 가 임대가 살아 있을 때 **딱 한 번** `true`. 시작 전 임대가 끝난 요청은 같은 번호 재전송에서 모든 확인을 다시 하고 새 임대를 받음. 시작한 요청은 임대가 끝나도 다시 부르지 않음 | 요청서 "start 후 lease 만료로 재호출하지 않는다". 시작 전에 끊긴 요청은 모델이 부르지 않았으므로 다시 해도 이중 청구가 아니다(시험 G16·G17) | `p6_claim`, `workhub_ai_start` |
| D-P6-1b | `finish` 는 요청을 `(사람 Auth UID, 소속, 요청 번호)` 로 찾고 임대 토큰을 대조. 같은 끝 재전송은 같은 응답, 다른 끝은 `IDEMPOTENCY_CONFLICT` | 호출 중 소속이 정지돼도 사용량은 정산해야 한다(시험 H13) | `workhub_ai_finish` |
| D-P6-1c | 결과 모름(`provider_unknown`) · 시작 뒤 끝 기록 없음은 **0원 성공·실패로 치지 않음**. 예약액을 그대로 잡아 두고, 관리자가 콘솔 사용량으로 `P6-05` 정산 | 요청서 "공급자 결과 미상은 0원 성공/실패로 처리하지 않는다" | P6-05, `p6_charge` |
| D-P6-1d | 시작한 지 10분(`p6_stale`)이 넘은 요청은 같은 대화를 더 막지 않고 P6-03-10 에 보임 | 끝 기록을 잃은 요청 하나가 대화를 영원히 잠그면 안 된다 | `p6_stale`, `p6_inflight` |
| D-P6-1e | 같은 대화 · 같은 판에 동시 질문 → 하나만 completed, 나머지 `CONFLICT` | 답이 겹쳐 붙으면 대화 순서가 거짓이 된다(시험 G09) | 대화 행 잠금 · `expectedVersion` |

## 7. 열린 결정(계란님)

1. **할 일 제목 · 메모 한도** — R0 120/2000 vs 앱 200/4000. (권장) 앱 초안 한도를 R0 에 맞추기. R0 를 넓히려면 R0 변경 승인이 필요합니다.
2. **결과 모름 요청 확인 담당 · 주기** — P6-05 를 누가 언제 돌릴지. 확인 전까지 예약액만큼 그 사람 · 학교 한도를 씁니다.
3. **대화 · 원장 보관 기간** — 지금은 영구. 자동 정리는 이번 범위 밖(보류).
4. **입력 토큰 사전 계산** — 지금은 입력 상한으로 예약하고 실제 사용량이 상한을 넘으면 그대로 정산합니다(예약보다 클 수 있음). 서버가 보내기 전에 세어 막으려면 PR #48 서버 코드 변경이 필요합니다.
