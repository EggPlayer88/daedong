## 재현·보존

P4의 실제 원본 예약·추출·초안 저장 RPC와 Python 추출 코드를 사용했다. 보강 전에는 접근 RPC와 본문 읽기가 성공하지만 정보 조회가 거절된다. S3 뒤에는 동일 파일·계정의 정보와 본문 읽기가 모두 통과한다.

초안의 다른 교사, 다른 학교, 익명, 서명·공개·목록 경로는 계속 거절된다. 게시 뒤에는 기존 정책대로 같은 학교의 유효 교사가 원문을 읽는다. 초안 정리본을 수정해도 이전 판과 원본은 남고, 게시 종료 후 과거 게시판은 읽되 타인의 과거 초안은 읽지 못한다. 게시판 직접 수정은 현재 계약상 CONFLICT다.

계정·소속·학교 중지, 승인 보류, 모듈 중지, 객체 ID 교체, 미고정 원본을 정보·본문 양쪽에서 확인했다. 자료·감사·활성화·Storage 행·정책·함수 ACL/소유자/실행 속성은 보강 전후 같다. CRLF·LF·재실행, 함수·권한 훼손 탐지와 알 수 없는 원본 거부를 검증했다.

## 처음 실행에서 수정한 시험 문제

1. PostgreSQL 실행 파일의 한글 경로가 Windows initdb의 UTF-8 초기화를 실패시켰다. 기존 영문 경로의 동일 17.6 런타임으로 실행했다.
2. 새 시험이 게시 뒤 본문 수정을 시도했다. 기존 정책은 초안에서만 수정 가능하므로, 초안 수정 → 게시 → 종료 → 과거판 조회로 바꾸고 게시판 직접 수정 거부도 명시 검사했다. 제품 SQL의 게시 보호를 바꾸지 않았다.
