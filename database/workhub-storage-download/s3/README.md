# 학교 자료 원본 다운로드 연결 — S3

학교 자료 원문을 읽을 자격이 있어도 Supabase Storage의 `object.get_authenticated_info` 단계가 거절되는 경로를 보강한다. 수합 S1·생성 문서 S2와 같은 종류의 호환 문제다. **운영 실행·활성화·병합은 사용자가 한다.**

변경 대상은 `workhub_storage.knowledge_readable(text,uuid)` 한 함수다. 현재 본문 읽기에 적용하는 소속·학교·객체 ID·모듈 상태·게시판 열람 조건을 그대로 정보 조회에 적용한다. 초안 타인, 다른 학교, 익명, 실물 교체, 목록·서명 URL·공개 URL은 계속 거부한다. 기존 SQL·인증·모델·비용·메뉴 공개 범위를 변경하지 않는다.

## 실행 순서

S1·S2 적용 및 INT-07 FAIL 0을 확인한 환경에서 진행한다. 이미 적용한 S1·S2와 P4 설치 파일을 재실행하지 않는다.

1. **S3-01_학교자료_Storage정보조회_호환.sql**: 전체를 실행한다. 입력 칸 없음. `S3-01 / ok` 1행이면 정상. 원문·소유자·권한·선행 보강이 예상과 다르면 덮어쓰지 않고 멈춘다.
2. **S3-02_사후점검.sql**: 읽기 전용. 7행 모두 `ok`.
3. **INT-08_SQL편집기용_통합점검.sql**: 읽기 전용. 18행, 12·13은 `info`, 나머지 `ok`, FAIL 0. CSV를 저장한다. 이후 전체 점검은 INT-08을 사용한다.
4. 운영 원문 서버가 배포되어 있고 학교 자료가 ready임을 확인한 뒤, 기존 **P4-05**의 `module=knowledge_import` 실행본을 사용자가 승인·실행한다. 기존 guided 활성화와 별개이며, 두 모듈을 한 번에 실행하지 않는다. 이미 등록됐으면 P4-05를 반복하지 않고 현재 상태부터 확인한다.
5. 가상 자료 HWPX 가져오기 → 추출문 확인 → 초안 저장·수정 → 원본 다운로드 → 게시 → AI 질문·인용 → 과거판 원문을 확인한다. 게시한 자료의 본문을 직접 덮어쓰는 기능은 없다. 개정 자료는 새 자료로 만들고 기존 게시를 종료하는 현재 정책을 따른다. 자동 시험의 합성 Storage 성공을 운영 성공으로 기록하지 않는다.
6. 별도로 기존 **M1-03**에서 개인 기억 저장·사용을 승인한다. 기억 등록 → 수정 → 선택 → 현재 질문에 복사 → 중지/만료 제외를 확인한다. 자동 수집·자동 주입은 제공하지 않는다.

S3 자체는 정책을 켜거나 자료·키를 만들지 않는다. 앱 수정이 없으므로 이 보강만으로 Vercel 재배포가 필요하지 않다. PR #79 병합은 이미 실행한 S1·S2·S3와 저장소를 맞추는 별도 절차다.

## 검증

`test/run_s3.py`는 새 로컬 PostgreSQL 17에 기반 전체 설치 → S1 → S2 → S3를 실행한다. 실제 Python 원문 추출과 실제 SQL 응답을 사용하되 파일 전송은 합성이다. 운영 DSN·실제 키를 받지 않는다.

```powershell
$env:WORKHUB_DEPLOYMENT_PG_BIN='설치된 PostgreSQL 17의 영문 경로/bin'
$env:PYTHONUTF8='1'
python database/workhub-storage-download/s3/test/run_s3.py
```

INT-08은 INT-05의 목록·판정식을 유지하고 세 다운로드 함수의 본문 지문만 바꾼다. 생성본 비교와 읽기 전용 실행 결과 비교를 회귀에서 확인한다. 기존 통합 점검을 덮어쓰지 않는다.
