## 발견한 시험 불안정성과 처리

첫 전체 실행에서 기존 CP-SAT 시험이 한 번 실패했다. 해당 코드를 바꾸지 않고 단독 29건 및 후속 전체 실행에서 통과했다. 기대값이나 계산 제한을 낮추지 않았다.

기존 AI 운영 진단 HTTP 시험은 잘못된 Content-Type을 거절할 때 Windows에서 `ConnectionAbortedError(10053)`가 반복됐다. 정상 본문 길이 2를 선언하되 본문은 보내지 않도록 시험 입력을 바꿨다. 헤더만으로 조기 400을 내야 통과하므로, 본문 파싱 오류나 길이 오류로 대신 통과할 수 없다. 서버 로직은 수정하지 않았고, 보강한 시험을 20회 반복해 매회 17건 모두 통과했다.

## 운영 확인 범위

운영에서 정상 파일 행·Storage 객체·본인 접근 허가와 본문 조회 권한을 읽기 전용 SQL로 확인했다. 다운로드 버튼 재현에서는 Storage의 `object.get_authenticated_info`가 `NoSuchKey`로 끝났다. S1은 이 단계에 기존 본문과 동일한 권한 검사를 적용한다.

S1 적용 후 실제 Supabase Storage HTTP 다운로드, 브라우저에 저장한 HWPX 열기는 아직 확인하지 않았다. 사용자 실행 후 사후 점검과 함께 확인한다. 운영 파일·초안을 다시 만들거나 공개하는 것은 필요하지 않다.

2026-10-23 사용자 후속 확인: S1-01·S1-02·INT-06을 적용·점검했고 FAIL이 없었다고 보고했다. 본인 대상 수합의 양식 다운로드, 공개, 제출 파일 업로드·초안 저장·최종 제출, 제출 파일 다운로드, 담당자 ZIP과 제출현황 CSV까지 정상이라고 확인했다. 내려받은 HWPX는 한글에서 열리고 원본과 같았다. 이 기록은 본인 한 명의 실제 운영 확인이며 다른 교사·학교의 운영 시험을 대신하지 않는다.
