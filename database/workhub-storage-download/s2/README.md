# 질문형 양식 생성 파일 다운로드 호환 보강 S2

생성 HWPX의 본문을 읽을 권한이 있어도 Supabase의 선행 파일 정보 조회가 거부되는 문제를 고친다. 사용자가 실행할 증분 SQL이며, 운영 DB에는 자동 적용하지 않는다. 기존 P4·S1 설치 파일을 바꾸지 않는다.

## 바뀌는 것

`workhub_storage.document_readable(text,uuid)`의 작업 이름 판정 두 곳에 `object.get_authenticated_info`를 추가한다. 정보 조회도 본문과 같은 생성자 계정·활성 소속·같은 학교·고정된 Storage 객체 ID·guided 준비 상태를 검사한다. 기존 함수 소유자·실행 권한·Storage 정책은 그대로다.

양식 원본은 여전히 서버가 분석할 때만 읽는다. 다른 교사·학교, 익명, 서명 URL, 공개 URL, 목록 조회, 동일 경로에 교체된 객체를 허용하지 않는다. 회원·문서·파일·활성화 자료도 수정하지 않는다.

앱 다운로드는 기존대로 접근 확인 → 파일 크기·SHA 확인 → 접근 재확인 순서다. 이 수정에 앱 재배포나 API 키 변경은 필요하지 않다.

## 사용자 실행 순서

1. Supabase 프로젝트 `dhaoszbqtbofqftgjfyb`인지 확인한다. S1 적용을 마친 상태에서 진행한다.
2. 새 SQL 쿼리에 **S2-01_생성문서_Storage정보조회_호환.sql** 전체를 붙여 실행한다. 채울 값은 없다. 정상 결과는 **1행 / S2-01 / ok**다. 오류면 다음 단계로 가지 않고 메시지를 공유한다.
3. **S2-02_사후점검.sql**을 실행한다. **6행 모두 ok**여야 한다.
4. **INT-07_SQL편집기용_통합점검.sql**을 실행하고 CSV를 보관한다. **18행, 12·13번 info, 나머지 ok, FAIL 0**이 정상이다.
5. 사이트 문서함 → 질문형 수합 양식에서 본인 시험 답변으로 HWPX를 생성하고 내려받는다. 한글에서 선택한 칸과 입력 내용이 맞는지 확인한다. 실제 회원 연결이나 양식 공개는 이 생성 시험에 필요하지 않다.

각 실행 결과를 확인한 뒤 다음 단계로 간다. 이 파일들은 SQL Editor 기본 postgres 역할로 실행한다.

S2 이후 전체 점검은 **INT-07**이다. INT-05에서 S1·S2의 승인된 함수 본문 지문 두 개만 교체한 기준이며, 그 외 목록과 판정식은 같다. INT-06은 S2 이전 원문을 기대하므로 S2 적용 뒤에는 이전 점검을 다시 사용하지 않는다. 설치 기록 표에 새 행을 넣지 않으므로 첫 행 단계 목록에 S2가 생기지 않는다. 적용 여부는 원문 지문으로 판정한다.

S2-01은 LF·CRLF를 모두 인식하고 재실행해도 자료를 바꾸지 않는다. 알 수 없는 함수 원문이나 바뀐 실행 권한은 덮어쓰지 않고 중단한다. 오류 시 트랜잭션을 되돌린다. 되돌림이 필요하면 기존 P4를 재실행하지 말고 별도 증분을 검토한다.

## 자동 검증 재실행

2026-10-23 최종 결과: 전체 시험 **5,122건**, 격리 SQL **193건**, 브라우저 흐름 **10건** 모두 통과했다. 실제 SQL·생성 바이트를 넣은 앱 다운로드 대조 4건과 원문 Storage 25건의 10회 반복도 통과했다. 범위와 초기 실패는 [검증 기록](verification.md)에 있다.

PostgreSQL **17**과 Python `psycopg2-binary`·`lxml`, 설치된 Node 의존성이 필요하다. `WORKHUB_DEPLOYMENT_PG_BIN`에 PG17 bin 경로, 필요하면 `WORKHUB_DEPLOYMENT_TEST_PORT`에 빈 로컬 포트를 지정한다. 실행기가 127.0.0.1의 임시 DB를 만들고 종료한다. 운영 접속 환경변수가 있으면 실행하지 않는다.

```sh
python database/workhub-storage-download/s2/test/build_s2_check.py
python database/workhub-storage-download/s2/test/run_s2.py
node tests/browser/workhub-document-collection-flow.mjs
npm test
```

S2 SQL 시험은 기존 전체 설치·S1 회귀를 먼저 실행한다. 실제 P4 RPC와 Python 생성기를 통해 양식을 분석하고 HWPX를 만든 다음, 실제 RLS의 정보·본문 조회와 현재 앱 다운로드 어댑터를 대조한다. Storage HTTP 전송과 파일 저장은 합성이다. 운영 Supabase의 생성·다운로드 성공까지 증명하는 시험은 아니며, 5단계에서 확인한다.

## 판단해서 정한 것

- 본문에 적용하던 동일한 권한 검사를 정보 조회에도 사용한다. 공개 버킷이나 관리자 다운로드 우회를 만들지 않는다.
- 같은 호환 문제를 해결하는 PR #79에 묶는다. 적용을 마친 S1 SQL은 수정하지 않고 새 S2 파일로 분리한다.
- `knowledge_import` 활성화, 메신저 첨부, 학교 자료 원문 다운로드는 이번 수정 범위에 넣지 않는다. 현재 사용자가 확인 중인 질문형 생성 파일부터 연결한다.
