## 실패를 실제로 재현한 범위

P4의 실제 예약·업로드·분석·매핑·답변·생성 RPC와 실제 Python 생성 코드로 HWPX를 만들었다. 수정 전에는 접근 RPC와 본문 RLS가 통과했지만 `object.get_authenticated_info`가 거부됐다. S2 뒤에는 같은 파일·계정으로 정보와 본문 모두 통과한다. 파일 내용도 질문의 답으로 채워졌고 출력 SHA와 일치한다.

다른 교사·학교·익명, 원본 양식, 공개·서명·목록 작업은 계속 거부된다. 소속·계정·학교 중지, 회원 승인 보류, 모듈 중지와 동일 경로 객체 교체도 정보·본문 양쪽에서 차단한다. 보강 후 원본 양식 업로드와 모듈 재개 후 생성 파일 읽기는 유지된다.

자료·활성화·Storage 행·감사와 함수 소유자·ACL·실행 속성을 전후 비교했다. LF·CRLF·재실행도 확인했다. 본문이나 익명 실행 권한을 훼손하면 국소·통합 점검이 FAIL로 잡고, S2는 덮어쓰지 않는다.

현재 앱 어댑터에 실제 SQL의 접근 응답과 생성 파일 바이트를 넣었다. 다운로드 전후 접근 재확인, 파일 바이트 보존, 변조 파일 거부, 내려받는 동안 접근 회수 응답 거부를 확인했다.

## 시험 환경에서 있었던 실패

Windows 샌드박스의 임시 하위 폴더 생성 제한으로 첫 격리 DB·전체 Python 시험이 실패했고 브라우저 다운로드도 취소됐다. 정상 로컬 임시 폴더에서 다시 실행했으며 기대값은 바꾸지 않았다. 새 앱 대조 도구는 기존 다운로드 반환값을 처음에 객체로 잘못 읽었다. 실제 계약인 `Blob`으로 고쳤고, 오류 코드는 `CONFLICT`와 `NOT_FOUND`를 정확히 확인하도록 했다.

정상 로컬 환경의 첫 전체 시험에서도 기존 `test_timetable_cpsat.mjs`가 실패했다. 같은 코드의 단독 29건은 통과했다. 시간표 구현과 시험 기대값은 변경하지 않았다.

그다음 전체 실행에서는 시간표 시험이 통과했지만 학교 원문 Storage 시험의 정상 예약 준비가 40ms를 넘겨 실패했다. `test_workhub_knowledge_storage.mjs`의 해당 신원 지연 사례만 시험 시계로 바꿨다. 준비 완료·신원 조회 도달을 기다린 뒤 39ms에는 미완료, 40ms에는 `RESULT_UNKNOWN`, 늦은 신원 응답 뒤 업로드 0회를 확인한다. 제품 어댑터·제한시간은 수정하지 않았다. 수정 후 이 파일 25건을 10회 반복해 모두 통과했다.
