# SP1 — 기간 업무 메뉴 표시

이 파일은 운영 적용 전 검토용 신규 증분이다. 기존 확정 SQL을 수정하지 않는다.
실제 설치·병합·공개 시점은 사용자가 결정한다.

## 범위

- 신규 내부 스키마 site_presentation, 표시 상태와 접수증 표 2개, 공개 RPC 2개.
- 기존 public.users의 승인·admin/superadmin 역할을 읽는다. 기존 회원·학교 소속·RLS는 변경하지 않는다.
- 인증된 승인 사용자는 표시 상태만 조회할 수 있다. admin/superadmin만 표시 설정을 바꾼다.
- 초기 enabled=false, version=1. 평가계획서 AI 작성과 제출 메뉴가 함께 숨겨진다.
- 사이트 전체의 표시 설정이다. 기존 평가계획서의 학교별 소속이나 자료 접근 권한을 새로 정의하지 않는다.
- 표시 설정은 제출 마감·기능 권한 차단과 다르다. 이미 연 편집기와 직접 주소는 기존 권한으로 계속 이용한다.

## 실행 순서

1. 검토된 같은 커밋의 파일을 사용한다. 운영 Supabase SQL Editor에서 postgres 역할로 SP1-01_기간업무_메뉴표시.sql 전체 실행.
2. 정상: SP1-01 / ok 한 행. 오류가 나면 트랜잭션 전체가 취소된다. 이미 설치된 파일을 반복 실행하지 않는다.
3. SP1-02_사후점검.sql 전체 실행. 정상: 7행, 01~06 ok, 07 info. 처음 값은 visible=false, version=1.
4. FAIL이 없을 때 앱 PR을 사용자 병합·배포한다. 먼저 앱만 배포하면 기간 업무 관리에 'SQL 설치 필요'가 표시되고 기간 메뉴는 숨겨진다.
5. 관리자 로그인 → 더보기 → 기간 업무 관리 → 평가계획서 업무 표시 선택 → 메뉴 표시 저장.
6. '메뉴에 표시 중'을 확인. 일반 사용자는 새 접속/창 복귀 때 최신 표시 설정을 읽는다.

미확정 저장은 같은 요청 번호로만 확인한다. 페이지 이동 뒤 돌아와도 해당 탭의 원래 요청이 유지된다.
다른 관리자와 같은 판에서 저장하면 나중 명령을 충돌로 거절하고 최신 상태를 다시 읽는다.
이전 접수증 재조회는 최신 표시 상태를 과거로 되돌리지 않는다.
브라우저를 완전히 닫으면 탭 메모리는 사라지지만 새 접속의 상태 조회로 현재 값을 확인할 수 있다.

## 점검 내용

01: 내부 표 2개 RLS / 02: API 역할 직접 표 권한 없음 / 03: 함수 소유자 postgres와 search_path 고정
04: 단일 기능 설정 / 05: authenticated 실행·anon 거부 / 06: 내부 스키마 접근 거부 / 07: 표시 상태

SQL 함수 계약: site.seasonal.v1, feature=assessment-plan, enabled, version, canManage, updatedAt.
오류: FORBIDDEN / INVALID_INPUT / CONFLICT / IDEMPOTENCY_CONFLICT.
인증 역할의 실행 권한만 부여하며 익명 역할·PUBLIC 실행 권한은 주지 않는다.

## 검증과 한계

tests/test_site_seasonal.mjs에서 격리 PGlite PostgreSQL에 실제 SQL을 설치하고 역할·접수증·판 충돌·앱 파서를 검사한다.
브라우저는 실제 관리자 화면과 표시 Provider에 합성 서비스 응답을 사용한다.
운영 Supabase의 실제 PostgREST 왕복·운영 설치는 아직 하지 않았다. 기존 운영 SQL 사후 점검을 통과했다고 대신 보고하지 않는다.

설치 후 앱을 되돌려도 기존 서비스는 이 신규 스키마를 사용하지 않는다. 표·접수증은 보존한다.
