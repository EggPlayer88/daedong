# AF1 — 연간 운영 피드백 보강: 검토·실행 안내

2026-10-29 사용자 확정: 재직 소속 유지, 의도한 퇴직·전출일 자동 연장 금지, 마지막 관리자 기간 보호. 공식 방학·법정 공휴일은 정규 미편성, 수련회·임시 휴업은 보강 검토. 기존 보강은 관리자의 명시 사유로 종결한다.

이 패키지는 **아직 운영·진행 중인 시험 DB에 적용하지 않았다.** 기존 SQL 확정본을 덮어쓰지 않는다. AF1-01~04는 각각 하나의 트랜잭션이며 앞 단계가 성공했다면 다음 단계 실패가 앞 단계까지 되돌리지는 않는다.

## 검토 후 적용 순서

1. 기존 최신 통합 점검(INT-09)과 AF1-00 실행 결과를 보관한다. AF1-00 P1 ok, P2 미설치인지 확인한다. F1~F6은 비교 지문이다. 사용 중 다른 사람이 자료를 변경했다면 단순 지문 차이를 곧바로 손실로 판단하지 않고 변경 시각·자료를 대조한다.
2. AF1-01: 관리자 연속성 보호와 읽기 전용 학년도 점검. 기존 소속·퇴직일을 수정하지 않는다.
3. AF1-02: 같은 학급 교환 추천 우선순위와 **새** 인계 알림의 원본 연결. 과거 알림은 소급 수정하지 않는다.
4. AF1-03: 기간 미리보기·확정·빈 날 휴업 해제·보강 검토 종결. 비공개 RLS 표 5개와 authenticated RPC 1개를 추가한다.
5. AF1-04: 기존 보강 집계·계획, 신규 공개·휴업 판정에 위 기록을 연결한다.
6. AF1-05 **8행 모두 ok**, AF1-00 F1~F6 동일인지 확인한다. 변경 원문의 지문이 다르거나 FAIL이면 다음 단계/병합을 멈추고 결과를 전달한다. 소유자·권한 검사나 지문을 제거해서 통과시키지 않는다.
7. 앱 PR #100 검토·CI·미리보기 후 사용자가 병합한다. 기존 메뉴 공개 범위는 유지한다. 새 SQL 없이 앱을 먼저 배포하면 새 기간 기능만 연결 준비 안내를 보이며 기존 하루 단위 기능은 유지된다.

AF1 후에는 변경한 함수/표가 추가되므로 이전 INT-09의 전체 구조 지문을 그대로 ‘모두 ok’라고 요구하거나 원문을 고치지 않는다. 설치 직전 INT-09 기준선 + AF1-05 + 전후 자료 지문을 함께 보관한다. 이 패키지의 격리 회귀가 운영 Supabase·PostgREST 실사용 검증을 대신하지 않는다.

## 적용 전 확인할 경계

- 선행: R0~P8, P9·학교자료 P10, T1·T2·T3. 실제 적용 단계 목록은 기준선 결과로 확인한다.
- 새 읽기/쓰기 RPC도 기존 소속·관리 권한과 모듈 활성 상태를 확인한다. 기존 접수증은 본인 계정·학교·소속 검증 후 원번호로 복구한다. 활성 상태 변경은 하지 않는다.
- 마지막 관리자 보호는 **소속·학교 관리자 역할의 변경/삭제**에 적용한다. 로그인 계정 정지, 이미 정해진 종료일 도래를 자동 연장하는 장치가 아니다. 사전 점검의 공백을 미리 해결해야 한다.
- 미래 전체를 맡던 마지막 관리자의 기간을 줄이려면 남은 기간을 담당할 정식 관리자를 먼저 배정해야 한다. 이 패키지가 임시 계정이나 역할을 자동 생성하지 않는다.
- 기간 휴업은 한 번에 62일·같은 학기·100개 학급·범위 내 3,000수업 이내. 초과하면 기간을 나눈다. 합반 일부, 실시 기록, 진행 중 변경 요청은 차단한다.
- 미리보기는 실제 15분 만료. 수업 날짜 판단은 기존 학교 시계를 이용한다. 확정 시 모든 날짜·원본 지문을 다시 대조하며 전체 성공 또는 전체 롤백한다.
- 수업이 없던 날도 휴업 기록을 남겨 재공개를 막는다. 빈 날만 사유 확인으로 해제할 수 있다. 수업을 실제 취소한 날의 재개는 기존 T3 동의·승인 흐름을 사용한다.
- 보강 종결은 현재 취소 수업의 판에만 유효하다. 원수업·이력·실시 기록은 삭제하지 않는다. 미래의 다른 취소 판을 자동 종결하지 않는다.
- 같은 요청 번호는 동일 접수증. 새 번호로 같은 미리보기를 재확정할 수 없다. 결과 미상 시 새 번호로 우회하거나 자동 재호출하지 않는다.
- 가속 시계 복제 DB는 함수 원문이 운영 기준과 다를 수 있다. AF1 지문이 다르면 별도 복제 호환 증분을 검토해야 하며, 진행 중인 Claude 시험에 임의로 적용하지 않는다. SB-03 설치 보강은 별도 PR #101이다.

## 되돌리기

앱은 일반 되돌리기 PR을 만들 수 있다. 이미 사용한 AF1 원장을 삭제하거나 과거 확정 SQL로 덮는 되돌리기 파일은 제공하지 않는다. 문제 발생 시 새 기간 작업을 중단하고 원 접수증·이력을 보존한 수정 증분으로 복구한다.

## 검증 명령

- `npm test`, `npm run check:workhub`, `npm run build`
- `node tests/browser/workhub-annual-operations.mjs`
- `P9_PG_BIN`에 격리 PG17 bin 경로 지정 후 `python database/workhub-annual/af1/test/run_af1.py`
- `AF1_CAPTURE`로 저장한 JSON을 `node tests/integration/annual-operations-capture.mjs <파일>`에 전달
- `python database/workhub-annual/af1/test/build_check.py`: AF1-05 함수 원문 검증표 재생성. CI에서는 재생성 차이도 실패 처리.

시험 하네스는 localhost 새 임시 DB만 만들고 종료한다. 운영 DSN·API 키를 받지 않는다.
