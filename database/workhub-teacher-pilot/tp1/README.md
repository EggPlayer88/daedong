# TP1 — 가입 전 교사 10명에 대응하는 기간 한정 시험 계정

이 파일 묶음은 운영 SQL의 새 증분입니다. 설치만으로 계정·연결·업무 허용은 생기지 않습니다. 기존 확정 SQL, 공통 로그인 gate, 모델·토큰·월 예산·가격 계산을 바꾸지 않습니다.

## 순서

1. `TP1-00_전후점검.sql`을 저장합니다. 선행 설치·기존 함수 9개가 `ok`이고 기존 명부·기본표 수치가 맞아야 합니다. 설치 전 전체 기준은 INT-13입니다.
2. `TP1-01_시험교사_기간연결.sql` → `TP1-02_시험AI_연결종료.sql`을 차례로 실행합니다. 두 파일 모두 `BEGIN/COMMIT`입니다. 실패한 파일은 원인을 해결하기 전 재실행하지 않습니다.
3. `TP1-03_사후점검.sql` 11행(01~10 `ok`, 11 `info`) → INT-14 18행 → `TP1-00` F1~F7 지문을 비교합니다. 등록 전에는 기존 자료 지문이 그대로여야 합니다.
4. 앱 배포를 확인한 뒤 시험 Auth 계정 10개의 비공개 등록 JSON을 검토하고 `teacher_pilot.register(...)`를 관리 SQL 연결에서 호출합니다. 결과는 `prepared`, `count=10`, `revision=1`입니다.
5. 시작 시각이 지난 뒤 `teacher_pilot.activate(...)`를 호출합니다. 기존 P9 교사 연결 정책이 켜져 있어야 하고, 공개된 기본표와 겹치는 담당 기간을 지정해야 합니다. 결과는 `active`, `count=10`, `revision=2`입니다.
6. 시험 종료 시 `teacher_pilot.stop(...)` → `TP1-03` → INT-14 → `teacher_pilot.cleanup_manifest(...)` 순으로 확인합니다.

`TP1-02`는 기존 TR1 연결·P1 담임 중복 제약을 보강합니다. 실제 연결의 기본 중복 금지는 유지하며, TP1이 만든 행의 종료 원장이 있는 경우만 조기 종료/미래 취소를 허용합니다. 등록 전에 설치해야 합니다. 이전 INT-13은 이 증분의 객체 변화를 모르므로 이후 전체 점검은 INT-14를 씁니다.

## 등록·활성화 계약

```sql
SELECT teacher_pilot.register(
  '<schoolId>', '<관리자 membership ID>', '<batchId>',
  '<startsAt>'::timestamptz, '<expiresAt>'::timestamptz,
  '<registration.json의 entries 배열>'::jsonb, '<승인 기록>'
);
SELECT teacher_pilot.activate(
  '<schoolId>', '<관리자 membership ID>', '<batchId>', 1,
  '<담당 시작일>'::date, '<담당 종료 경계일>'::date,
  '<배포 커밋·배포 확인 기록>'
);
```

- `batchId`: 영문 소문자로 시작하는 3~48자 영문·숫자·하이픈. 한 학교에 끝나지 않은 배치는 하나입니다.
- `entries`는 정확히 10개이고 각각 `slot,email,displayName,teacherId,authUserId`만 가집니다. `slot`은 T01~T10입니다.
- 계정 이메일은 `teacher-pilot-<batchId>-t01@example.com` 형식, 표시 이름은 `[시험] `으로 시작합니다. Auth 관리 메타데이터의 배치·학교·교사·슬롯·설정 해시가 맞아야 합니다. 열 계정의 설정 해시도 동일해야 합니다.
- 새로 만든 일반 교사 계정만 받아들입니다. 이미 학교 계정으로 연결되었거나 명부에 계정 연결 이력이 있는 교사는 거부합니다. 기존 실제 계정은 채택하지 않습니다.
- Auth 생성 도구의 `configHash`는 비공개 설정 파일 해시입니다. SQL의 `manifest_hash`는 승인한 학교·기간·10개 항목의 서버 해시로 서로 다른 목적입니다.
- 기간은 최대 7일이고 자동 연장하지 않습니다. 과거 시작 시각은 계정 준비 지연을 허용하지만 종료 시각은 미래여야 합니다. 활성화는 시작 시각 이전에 실행할 수 없습니다.
- 종료 경계일은 포함하지 않습니다. 예를 들어 11월 16일~19일 시험 담당은 `from=2026-11-16`, `until=2026-11-20`입니다. 담당 종료 경계는 배치 만료의 학교 날짜를 넘을 수 없습니다.
- 전역 역할은 `teacher`입니다. 학교 관리자 역할을 추가하지 않습니다. 기존 OP1의 8개 업무 범위와 이 배치 전용 AI 접근만 허용합니다. 기존 예산·모델 정책이 별도로 AI를 막으면 그 정책을 그대로 따릅니다.
- `register`의 같은 내용과 `activate`의 같은 기간·배포 근거를 재호출하면 원래 결과를 돌려줍니다. 다른 내용을 같은 배치로 보내면 거부합니다.

## 종료·실제 계정 연결

```sql
SELECT teacher_pilot.stop('<schoolId>','<관리자 membership ID>','<batchId>',2,'시험 종료');
SELECT teacher_pilot.cleanup_manifest('<schoolId>','<관리자 membership ID>','<batchId>');
```

`stop`은 시험 10명만 업무 허용 해제, 가입 승인 비활성화, 계정·학교 소속 중지합니다. 기존 자료나 Auth 계정을 삭제하지 않습니다. 같은 종료를 다시 호출하면 최초 종료 접수증을 돌려줍니다.

학교 날짜 기준 오늘까지의 담당 이력은 보존하고 내일부터 종료합니다. 아직 시작하지 않은 담당은 빈 유효기간으로 취소합니다. P5 원행은 고치지 않고 기존 P8 종료 원장에 기록합니다. 미래 담임만 취소 표시로 중복 제약에서 제외하며 원행·감사 기록은 남깁니다. 실제 교사 연결은 기존 TR1 화면에서 종료 경계일 이후로 진행합니다. 과거 연결은 조회용 단축 기간으로 남고, bridge는 종료한 시험 연결로 담당을 다시 만들지 않습니다.

AI를 시작한 뒤 중지·만료되어도 이미 사용한 비용은 기존 종료·정산 경로로 기록합니다. 권한이 사라졌다고 예약을 임의 삭제하거나 이미 쓴 비용을 돌려놓지 않습니다. 미정산 요청은 관리자가 기존 운영 절차로 해결합니다.

## 자료 정리 범위

정리 명세는 시험 10명의 Auth·소속·교사 ID, TP1이 만든 담당 ID, 시험 계정이 작업한 감사 대상 자료 ID와 AI 미정산 건수를 반환합니다. 자료 목록은 소유권이나 삭제 가능 목록이 아닙니다. `operations`에서 생성·수정을 구분하고 기존 공유 자료인지 별도로 확인합니다. `deletionAllowed=false`입니다.

기존 실제 22명·9학급·288교시 기본표, 실제 계정, 공유 자료, 감사·접수증·AI 대화·AI 비용 원장, Auth 외래키는 보존합니다. 관리자가 만든 시험 자료는 관리자 이름·날짜·제목만으로 골라 지우지 않습니다. 별도 명시 ID 목록을 확인한 뒤 기능이 지원하는 취소·보관을 사용합니다. 이 증분에는 일괄 삭제 기능이 없습니다.

시험은 같은 학교의 기존 업무 권한으로 수행합니다. 메시지·수합·공유 일정의 수신자를 시험 10명과 승인 관리자만으로 서버에서 격리하는 기능은 포함하지 않습니다. 시험 자료의 수신자·제출 대상은 이 명단으로 직접 확인해야 합니다. 학생·공유 자료 조회는 기존 권한 검사를 따릅니다.

## 검증

`test/run_tp1.py`는 운영 DSN과 자격증명 환경변수를 거절하고 새 localhost PostgreSQL 17에 기존 전체 증분과 TP1을 설치합니다. 22명·9학급·288교시 합성 자료로 등록·기간·AI·정지·재연결을 검증합니다. 실제 Claude 호출은 하지 않습니다.

`build.py`는 확정 SQL 원문을 읽어 함수 9개의 정확한 본문 지문과 교체문을 생성합니다. 허용한 CRLF/LF 차이를 제외한 원문·소유자·검색 경로·함수 속성 변경은 설치를 막습니다. 기존 파일을 수정하지 않습니다.
