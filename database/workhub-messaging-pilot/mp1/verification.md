## 실제로 검사한 경계

- 시험 교사는 끝까지 `teacher`이며 학교 관리자 역할을 받지 않는다. 다른 일반 교사·다른 학교·익명 접근은 거부한다.
- 메신저 전용 허용을 받아도 기존 업무실·학교 관리·시간표·문서·AI 권한은 열리지 않는다. 공통 `legacy_gate`, `member_actor`, P2 수신 자격 함수는 변경하지 않는다.
- 관리자와 시험 교사의 양방향 메시지, 원래 요청 번호 재전송, 읽음 처리, HWPX 예약·Python 기본 검사·완료·다운로드·원본 바이트 일치를 확인했다.
- 다른 대화 첨부·공개 다운로드·서명 URL·Storage 목록은 거부한다. 인증 다운로드 정보 조회도 기존 파일·객체·참여자 조건을 거친다.
- 시험 만료·소속 중지·계정 중지·가입 승인 취소·명시 중지 시 접근을 막는다. 명시 중지는 기존 관리자에게 보이는 메시지·첨부를 삭제하지 않는다.
- 두 번째 시험 계정 허용 시 전체 거부하며 기존 허용을 바꾸지 않는다.
- RLS 중지, API 표 권한 추가, 내부 함수 실행 권한 추가를 각각 MP1-02와 INT-09가 FAIL로 탐지한다.

## 시험 중 수정과 재실행

첫 전체 실행에서는 기존 공개 범위 시험의 호출 문자열 두 곳이 새 선택 인자를 반영하지 않아 실패했다. 역할별 기대값은 유지하고 문자열만 실제 호출에 맞췄다. 동시에 무거운 SQL·브라우저 검사가 돌아가던 실행에서는 기존 계산기 시간 제한 두 시험도 실패했다. 별도 실행과 최종 전체 재실행에서 계산기 포함 5,154건이 모두 통과했다. 제품의 시간 제한이나 시험 기대값을 낮추지 않았다.

브라우저 시험에서 직접 업무실 주소에 들어갈 때 프로필 조회 완료 전 대시보드로 보내던 순서를 고쳤다. 계정 전환 후 늦은 응답, 10초 조회 제한, 만료, 입력과 결과 미확정 요청이 있는 동안의 이동 차단도 함께 확인했다.

## 운영 확인과 구분

SQL은 실제 PostgreSQL 17을 사용했지만 회원·학교·메시지는 합성 자료다. Storage는 RLS를 적용한 합성 객체 표와 메모리 파일을 사용했다. 브라우저는 실제 React·전송 어댑터와 합성 Supabase 응답을 사용한다. 실제 Supabase/PostgREST·Storage·Vercel 왕복 성공을 뜻하지 않는다.

운영에서는 README의 순서대로 MP1 설치·점검 → 앱 배포 → 시험 계정 1명의 소속 연결·허용 → 관리자와 시험 교사의 전송·읽음·첨부 다운로드를 확인한다. 실제 교사 회원 연결과 일반 공개는 계속 보류한다. GitHub CI와 Vercel 미리보기 상태는 해당 PR의 현재 결과를 확인한다.
