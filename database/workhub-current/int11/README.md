# INT-11 — 현재 운영 읽기 전용 구조 점검

OP1 + AF1-01~04 + AF2-01 + SP1 설치 상태를 위한 점검이다. 기존 INT-10·OP1-02·AF1·AF2·SP1 SQL 원문은 변경하지 않는다. 새 설치·기능 활성화·권한 변경·자료 정리 파일이 아니다.

## 현재 점검 묶음

| 파일 | 정상 결과 |
|---|---|
| INT-11_SQL편집기용_통합점검.sql | 18행, 12·13 info / 나머지 ok. 01은 현재 기준 48단계 모두 설치 필요 |
| AF1-05_사후점검.sql | 8행 모두 ok |
| AF2-02_사후점검.sql | 4행 모두 ok |
| SP1-02_사후점검.sql | 7행, 01~06 ok·07 info |

`sql-package.json`은 네 점검 원문의 LF 정규화 SHA-256·크기·행 수·원본 경로를 고정한다. 아래 도구는 목록을 대조해 새 폴더로 복사만 한다. 임의 SQL이나 접속 정보는 받지 않는다.

```text
npm run check:workhub:current-checks
npm run prepare:workhub:current-checks -- --output-parent <기존 폴더>
```

INT-10은 새 함수·표와 바뀐 원문을 모른다. OP1-02도 AF1에서 바뀐 인계 함수 원문을 옛 값과 대조한다. 따라서 현재 운영에서는 INT-11로 대신 확인한다. 옛 파일 자체를 수정하거나 그 FAIL을 무조건 무시하는 방식은 사용하지 않는다.

실제 DB에서 확인해야 하는 시점에는 위 네 파일을 읽기 전용으로 실행하고 결과를 저장한다. FAIL이나 예상과 다른 행 수는 원인 확인 대상이다. **이번 도구 보완을 배포하기 위해 지금 SQL을 실행할 필요는 없다.** 통과는 구조·권한 확인이며 실제 업무 저장·파일 다운로드·AI 호출의 성공이나 현재 사용자 권한을 보증하지 않는다.

## 재생성과 검증

`build_checks.py`는 공통 시험 실행기를 사용한다. PG17의 새 임시 폴더·localhost DB에 기존 확정 SQL을 설치해 단계별 카탈로그 차이로 INT-11을 재생성하고 저장 파일과 대조한다. 외부 DSN·libpq 옵션·자격증명 환경은 공통 실행기가 차단한다. `WORKHUB_DEPLOYMENT_PG_BIN`만 PG17 bin 경로로 지정한다. `--write`는 이 폴더의 새 INT-11과 목록만 갱신한다. 운영 접속은 지원하지 않는다.

```text
python database/workhub-current/int11/build_checks.py
```

기존 기준의 오판 재현, READ ONLY 트랜잭션, 회원·역할·자료 보존, 함수 본문/소유자/상속 권한·트리거·RLS·열·설치 기록·함수 누락/추가의 훼손 회귀를 포함한다. CI도 같은 검증을 실행한다.
