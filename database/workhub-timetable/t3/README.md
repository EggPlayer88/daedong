# T3 시간표 운영 확장

대강, 개별 휴강, 원수업에 연결한 보강, 휴업 취소를 실제 공개 시간표에 반영한다. SQL 설치만으로 시범 기능이 활성화되지 않는다. 운영 SQL 실행과 시범 활성화는 사람이 검토한 뒤 진행한다.

적용 순서는 기존 R0/R1/P1~P8/T1/T2 및 P9/P10 → `T3-01` → `T3-02` → `T3-03` → 읽기 전용 `T3-04`이며, 이후 T4와 최종 통합 점검을 적용한다. 기존 적용 SQL은 수정하지 않는다. T3-03은 기존 T2 함수 전체 본문 지문이 일치할 때만 지정된 보호 훅을 추가한다. T2-07/P9의 예전 통합 지문은 이 증분 뒤 최종 통합 점검으로 대체한다.

`T3-05`는 빈 승인 양식이다. 현재 업무실에 접근 가능한 기존 회원 UID의 명시적 허용 목록과 서로 다른 실제 승인 담당자 계정 2개가 필요하다. 가입 교사를 새로 만들거나 일반 교사의 업무실 입구를 넓히지 않는다. `enable:false`와 빈 칸은 실행을 중단한다. 새 정책은 기존 T2 이동·교환에도 같은 시범 자격 및 독립 승인 조건을 적용한다.

판단해서 정한 것:

- 영향 교사는 원래 교사와 대강 교사의 합집합이다. 모든 영향 교사의 동의 후, 요청자 및 영향 교사와 계정이 다른 현재 관리자가 최종 승인한다.
- 보강은 취소 원수업의 판을 보존하고 동일 시간량·교사·학급·공간의 새 수업을 원수업에 연결한다. 한 원수업에 보강은 한 번만 연결한다.
- 휴업 취소는 원휴업 변경의 모든 수업이 당시 취소 판 그대로일 때 전체를 복원한다. 이미 보강한 원수업이 포함되면 차단한다.
- 시작한 수업, 실시 기록이 있는 수업, 자원 충돌, 다른 진행 요청, 현재 시범 자격이나 변경일의 소속 기간이 맞지 않는 교사는 차단한다.
- 동일 번호의 실행과 명시적 닫기는 같은 학교 시간표 잠금 및 단일 접수 원장을 사용한다. 기존 접수증을 먼저 반환하고 닫힌 번호의 늦은 실행은 차단한다. 모듈을 중지해도 본인의 기존 결과를 복구하거나 미반영 번호를 닫을 수 있다. 현재 회원·소속 검증은 계속 적용한다.
- 원수업과 변경 버전·요청 접수·보강 연결·휴업 복원 이력은 삭제하지 않는다. 재공개는 대강·휴강·보강·복원 결과를 보존한다.
- 학사 변경 알림은 원변경 출처 ID를 가지며 출처 조회는 현재 학교와 요청 가시성을 다시 확인한다. 홈 요약은 동의·승인·미보강 항목을 최대 20개 보여준다.

변경을 되돌릴 때는 활성 정책을 중지하고 기존 결과를 먼저 복구한다. 적용된 수업·접수 원장을 삭제하거나 이전 SQL로 덮어쓰지 않는다. 새 보정 SQL은 별도 검토한다.

격리 회귀는 `test/run_t3.py`로 PostgreSQL 17 임시 클러스터를 127.0.0.1의 시험 포트에 만들며 운영 DSN을 받지 않는다. `P9_PG_BIN`으로 PostgreSQL 17 bin, `T3_TEST_PORT`로 시험 포트를 지정한다. 실제 RPC 응답은 `T3_CAPTURE`의 JSON에 저장해 앱 parser와 대조한다. 기본 포트는 55529다.
