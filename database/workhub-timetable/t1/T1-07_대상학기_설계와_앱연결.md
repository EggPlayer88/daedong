# T1-07 준비 대상 학기 고르기 — 설계 · 계약 · 실행 · 앱 연결

2026-10-19 · Claude Code. 계란님 결정 **G-1 = A**(2026-10-19): 다음 학기 시간표를 지금 학기가 끝나기 전에 준비할 수 있게 한다.
SQL 은 Claude, 화면은 Codex 가 맡는다(CLAUDE.md 3-1). 이 문서의 5절이 Codex 에게 넘기는 계약이다.

## 1. 무엇이 문제였나

T1 의 대상 학기(`workhub_private.t1_term`)는 "닫히지 않았고 아직 끝나지 않은 학기 중 오늘이 든 학기"다.
학기를 닫는(`closed`) 기능은 아직 없고, 운영 DB 의 2학기는 2026-08-13 ~ 2027-02-28 이다. 그래서 2027학년도 1학기
시간표 준비는 2027-03-01 이 되기 전에는 시작할 수 없었다(검토 문서 G-1).

## 2. 어떻게 풀었나

시간표 담당자(`year.manage`)가 **준비할 학기를 직접 고른다.** 학교마다 한 칸(`workhub.timetable_term_targets`)에 저장한다.

- 고른 학기가 아직 고를 수 있으면(닫히지 않음 · 끝나지 않음) 그 학기가 대상 학기다. 아니면 지금과 같은 원래 규칙을 쓴다.
- `t1_term` 본문만 바꾼다. T1 의 준비 · 입력 · 기준판 · 편성 초안 함수 8곳이 모두 이 함수로 대상 학기를 정하므로 그대로 따라온다.
  원래 규칙은 `t1_term_auto` 로 옮겼다(본문 지문이 T1-01 의 `t1_term` 과 같음).
- **아무도 고르지 않으면 T1 과 똑같이 동작한다.** 그래서 앱이 이 기능을 모르는 채로 T1-07 을 설치해도 화면은 바뀌지 않는다.
- 고른 학기의 기준일은 그 학기 첫날이다(`max(학기 시작일, 오늘)`). 다음 학기를 준비하는 동안에는 준비 자료 엑셀의 기준일이 날마다 바뀌지 않는다.
  다만 지금 학기를 준비할 때의 "엑셀이 자정에 만료되는" 문제(U-1)는 그대로이고, 앱 쪽에서 따로 고친다.

## 4. 계약 `timetable.target.v1`

봉투는 다른 계약과 같다: `{contract:'timetable.target.v1', schoolId, memberId, data}` 또는 `{…, error:{code}}`.
켜기 전 · 중지 중이면 `NOT_READY`, `year.manage` 가 없으면 `FORBIDDEN`(일반 교사 · 다른 학교).

### 4-1. `workhub_timetable_target_get(p_member_id)` → data

```
{ termId: id | null,             // 지금 대상 학기(준비 · 입력 · 기준판 · 편성 초안이 이 학기를 쓴다)
  automaticTermId: id | null,    // 고르지 않았을 때의 학기(원래 규칙 = 오늘이 든 학기)
  selectedTermId: id | null,     // 담당자가 고른 학기(없으면 null). 고른 학기가 닫히면 남아 있지만 termId 와 달라진다
  version: 0 이상 정수,           // 고르기 판. 한 번도 고르지 않았으면 0
  terms: [{ id, schoolYear, label, firstDay, lastDay, state: 'planning'|'current', hasBasis, hasPreparationDraft }] }
```

- `terms` = 같은 학교의 닫히지 않고 아직 끝나지 않은 학기, 시작일 순, 20개까지. `firstDay` · `lastDay` 는 양 끝 포함 날짜(`YYYY-MM-DD`).
- `selectedTermId` 가 있는데 `termId` 와 다르면 고른 학기를 더 이상 준비할 수 없게 된 것이다(닫힘 · 끝남). 화면은 이것을 알려야 한다.

예(시험 응답, ID 줄임):

```json
{"termId":"term-n1","automaticTermId":"c27d…","selectedTermId":"term-n1","version":1,
 "terms":[{"id":"c27d…","schoolYear":2026,"label":"2학기","firstDay":"2026-08-16","lastDay":"2027-02-28","state":"current","hasBasis":false,"hasPreparationDraft":false},
          {"id":"term-n1","schoolYear":2027,"label":"1학기","firstDay":"2027-03-01","lastDay":"2027-08-17","state":"planning","hasBasis":false,"hasPreparationDraft":false}]}
```

### 4-2. `workhub_timetable_target_set(p_member_id, p_input, p_request_key, p_recover_only)` → data

입력(정확히 이 두 키): `{ termId: id | null, expectedVersion: 조회한 version }` — `termId: null` 은 "고르지 않음(원래 규칙으로)".

접수증: `{ requestKey, termId, version, effectiveTermId }` — `termId` = 저장된 고른 학기(null 가능), `version` = 저장 뒤 판, `effectiveTermId` = 저장 뒤 대상 학기.

| 상황 | 결과 |
|---|---|
| 칸이 빠지거나 남음 · `termId` 가 ID 형식 아님 · `expectedVersion` 이 0 이상 정수 아님 | `INVALID_INPUT` |
| `expectedVersion` ≠ 지금 판(다른 담당자가 그사이 바꿈) | `CONFLICT` |
| 없는 학기 · 다른 학교 학기 | `NOT_FOUND` |
| 닫혔거나 이미 끝난 학기 | `CONFLICT` |
| 지금과 같은 학기를 다시 고름 | 성공, 판 · 감사 그대로 |
| 요청 번호 | 같은 번호 · 같은 입력 → 원래 접수증, 다른 입력 → `IDEMPOTENCY_CONFLICT`, `p_recover_only=true` 이고 원장에 없으면 `NOT_FOUND`. 원장 확인이 켜기 · 권한 검사보다 먼저(중지 중에도 복구 조회는 됨) |

- 판은 되돌릴 때도 오른다(행을 지우지 않음). 옛 화면이 "되돌렸다 다시 고른" 상태를 덮어쓰지 못한다.
- 바뀔 때만 감사 1건(`timetable.target_set`, `{termId, previousTermId}`).
- 대상 학기가 바뀐 뒤 다른 화면이 들고 있던 준비 원본 · 기준판으로 저장하면 기존 검사(`termId` · 지문 · 기준판 판 대조)가 `CONFLICT` 를 낸다(시험 G04). 새 검사는 필요 없다.

## 5. 앱 연결 — Codex 작업 요청

T1-07 을 설치해도 앱이 이 계약을 쓰기 전까지는 아무것도 바뀌지 않는다. 다음 학기 준비를 쓰려면 아래가 필요하다.

1. **parser · 어댑터**: `timetable.target.v1` 의 조회 · 접수증 parser(4절 모양 그대로, 남는 키 거부), `createScopedRpc` 로 두 함수. 쓰기는 setup 과 같은 요청 번호 · 복구 조회 규칙(응답 유실 시 원래 번호 · 입력으로 `p_recover_only=true`).
2. **"준비할 학기" 고르기**: 준비 화면 진입부(기준판 없음 상태 포함)에 지금 대상 학기와 고를 수 있는 학기 목록을 보여 준다.
   - 학기 표시 = `schoolYear`학년도 `label`(`firstDay`~`lastDay`), 원래 규칙 학기에 "지금 학기" 표시, `hasBasis` · `hasPreparationDraft` 표시.
   - 바꾸면 `expectedVersion` 으로 저장하고, 성공하면 readiness · 준비 · 입력 조회를 다시 읽는다. `CONFLICT` 면 다시 조회해서 보여 준다(자동 재시도 금지).
   - 저장하지 않은 입력(공간 · 연결 · 시수 · 엑셀 선택)이 있으면 학기를 바꾸지 못하게 잠그거나 버릴지 묻는다. #69 의 "작업 중 이동 잠금"과 같은 규칙.
   - "원래대로(지금 학기)" = `termId: null`.
3. **안내**: `selectedTermId` 가 있는데 `termId` 와 다르면 "고른 학기가 닫혀 지금 학기로 돌아왔습니다" 같은 알림.
4. **시험**: parser 단위 시험, 브라우저 시나리오(학기 바꾸기 → 입력 · 준비 화면이 그 학기로, 판 충돌, 응답 유실 복구, 미저장 입력 잠금).
   실제 응답 예시는 `test/run_t1_07.py` 를 `T1_07_CAPTURE` 로 돌리면 나온다(4-1 예시가 그 일부).

공개 범위(superadmin) · 권한(`year.manage`)은 바꾸지 않는다.
