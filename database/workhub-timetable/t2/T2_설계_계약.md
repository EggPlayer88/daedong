## 3. 핵심 규칙

- **준비 조건**: T2-01 · 03 · 04 · 05 · 06 적용 + 시간표(T1, `timetable`) 준비 + 모듈 `timetable_operations` 켜짐. T2-02 는 알림만 좌우한다.
- **요청 원장 먼저**: 쓰기는 (학교, 소속, 종류, 요청 번호)로 원장을 먼저 읽는다. 같은 번호 · 같은 명령이면 원래 접수증, 다른 명령이면
  IDEMPOTENCY_CONFLICT, 복구 조회(`recover_only`)에 원장이 없으면 NOT_FOUND. 이 판단은 준비 상태 · 권한보다 먼저다(모듈을 꺼도 복구 조회는 됨).
- **요청 번호 포기(취소 기록)**: 결과를 모르는 번호(응답 유실 → 복구 NOT_FOUND → 재전송도 거절)를 앱이 `_abandon(종류, 원래 명령, 번호)`로 닫는다.
  같은 번호 잠금 안에서 이미 반영됐으면 `outcome: applied` + 원래 접수증, 아니면 취소 기록을 남기고 `outcome: abandoned`.
  취소 기록 뒤 그 번호로 오는 실행 · 재전송 · 복구 조회는 모두 CONFLICT(반영 안 함) — 늦게 도착한 최초 요청도 막힌다. 그래서 앱은 잠금을 풀고 새 번호를 써도 두 번 반영되지 않는다.
  다시 포기하면 같은 응답, 다른 명령이면 IDEMPOTENCY_CONFLICT. 모듈을 꺼도 된다. 원장 행은 고칠 수 없다. 모듈을 꺼도 본인 계정 · 소속 확인은 그대로다(시험 I01~I10).
- **공개**: 편성 초안의 주간 배치를 기간의 날짜마다 펼친다(휴업일 제외). 이미 시작한 수업 · 교환/학사 변경으로 옮긴 수업은 그대로 둔다.
  학사 변경(휴업)으로 취소한 수업도 그대로 두고(되살리지 않음), 새로 만들 수업은 그 학교 · 날짜의 **모든 휴업 기록 학급을 합쳐** 본다.
  수업의 학급이 전부 휴업이면 만들지 않고, 일부만 휴업인 합반이면 `PARTIAL_GROUP_SCOPE` 로 공개 전체를 막는다(lessonIds = 그 새 수업, 시험 L01~L06).
  기존 수업을 바꾸는 갱신도 **바뀐 뒤 학급**으로 같은 검사를 한다: 일부만 휴업 → `PARTIAL_GROUP_SCOPE`, 전부 휴업 → `SCHOOL_CLOSED`(lessonIds = 기존 수업 ID).
  전부 휴업 갱신을 건너뛰면 옛 학급 수업이 남고, 자동 취소하면 공개가 학사 변경을 대신하므로 둘 다 하지 않고 막는다(시험 M01~M06).
  일반 재공개로 취소한 이력은 보존 대상이 아니라 원래 배치로 돌아가면 다시 만든다(시험 K01~K09).
  미리보기 15분, 확정 때 같은 계산을 다시 해 지문이 다르면 CONFLICT. 12,000건 초과는 거절, 큰 공개는 200건씩 쪽 지문(확정 명세).
- **교환 · 이동**: 같은 주의 공식 시간대로만(옮길 시각 추정 없음). 본인만 참여하면 바로 승인 대기, 다른 교사가 있으면 동의 대기.
  승인 = year.manage 이면서 요청자와 **다른 계정**. 승인 때 시작 시각 · 자원 겹침 · 불가 시간 · 휴업일을 다시 본다.
  내가 담당한 수업에 그 사이 다른 요청이 걸렸으면 미리보기는 CONFLICT(앱이 다시 조회) — 차단 사유로 돌려주면 앱이 응답 오류로 본다(앱 대조에서 발견해 고침).
- **학사 변경**: 화면이 본 조회(asOf · 기간) 그대로 계산하고 그 뒤 범위 안이 바뀌었으면 CONFLICT. 고르지 않은 집단과 함께 듣는 수업 ·
  이미 시작한 수업 · 날짜를 넘는 수업 · 진행 중/반영된 교환이 걸린 수업이 있으면 차단(부분 반영 없음).
- **실시 기록**: 예정 수업과 분리. 끝난 예정 수업에만, 담당 교사 본인만 기록 · 정정. 수업 state · 판 · 담당 교사 · 시수를 바꾸지 않는다.
  수업마다 원장 1개(ID 고정), 정정은 판+1 · 사유 필수, 판마다 불변 이력. 이력 쪽은 서버 서명 cursor(학교 · 소속 · 수업 · 원장 · anchor · 다음 판).
  기록은 끝난 수업에만 생기고 공개 · 교환 · 학사 변경은 시작 전 수업만 바꾸므로, 기록된 수업의 판은 다시 바뀌지 않는다.
- **감사**: 공개 · 교환 제출/응답 · 학사 변경 · 실시 기록/정정 모두 `school` 민감도. 실시 기록 감사에는 메모 · 사유 원문을 넣지 않는다.
- **잠금**: 공개 · 교환 · 학사 변경 · 실시 기록 쓰기는 T1 과 같은 학교 시간표 잠금(`t1_lock`)으로 한 줄로 선다.

## 5. 앱과 맞춘 방법

- 한도는 PR #72 `operations-api-limits.json` · `operations-next-limits.json` · `execution-records-policy.json` 값 그대로(`t2_limit`).

- 시험 III: 시험 중 받은 **성공 응답 82건**을 PR #72(`a5ff182`)의 실제 parser 15종에 넣어 모두 통과
  (`parseOperationsView` · `parsePublishPreview` · `parseExchangePreview` · `parseSchoolDayExecutionPreview` · `parseExecutionRecordsView` · 접수증 parser 등).
