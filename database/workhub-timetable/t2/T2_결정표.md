## 1. D-T2-1 공개 범위 — 메뉴가 아니라 서버가 막아야 한다

- 지금: T2-08 로 켜면 그 학교의 **모든 활성 소속**이 RPC 로 공개 시간표를 보고 자기 수업 교환을 요청할 수 있다.
  업무실 메뉴는 superadmin 전용이지만, 주소 · RPC 를 직접 부르면 메뉴 숨김은 아무것도 막지 않는다(CLAUDE.md 2-1).
- 권장: **시범 명단을 서버가 판정**하게 한다.
  - 증분(가칭 T2-09): 표 `timetable_operations_pilot_members(school_id, membership_id, added_by, added_at, removed_at)`.
  - 명단이 있는 학교에서는 `t2_ready` 가 소속마다 판정: 명단에 있거나 `year.manage` 이면 통과, 아니면 `NOT_READY`.
  - 교환 미리보기 · 제출은 참여 교사 **전원**이 명단 안일 때만(명단 밖 교사의 수업은 차단 사유). 알림도 명단 안에게만.
  - 켜기 양식(T2-08)이 명단을 함께 받아 같은 트랜잭션에 넣는다 → "켜졌는데 명단이 비어 전원 공개" 상태가 생기지 않는다.
  - 명단 비우기 = 전체 공개이므로, 명단 삭제는 별도 승인 양식으로만.
- 대안: 시범 기간에는 T2-08 을 켜지 않는다(가장 확실하지만 실제 교사 시범이 불가).
- 비용: T2-09 SQL · 시험(Claude), 앱은 `NOT_READY` 를 이미 처리하므로 변경 없음(추정 — Codex 확인 필요).

## 2. D-T2-2 학사 변경 알림

- 권장: 휴업 · 특별 일과가 반영되면 **수업이 바뀐 교사**(실행한 사람 제외, 중복 없이)에게 알림 1건씩.
- 필요한 것:
  1. T2-05 증분: `t2_school_day_execute` 안에서 같은 트랜잭션으로 알림 생성(T2-04 `t2_notify` 재사용). T2-02 · 메신저 준비일 때만.
  2. **앱 계약(Codex)**: 지금 앱은 알림 `source.id` 를 교환 요청 ID 로만 연다. 학사 변경 ID 를 열 방법(예: `source.id` 에 변경 ID, 화면은 해당 날짜로 이동)을 정해야 한다.
- 정하지 않으면: 알림 없이 시간표 화면에서만 보인다(지금).

## 3. D-T2-3 거절된 요청 — 명시적 닫기 (확정 가능)

- 남은 것: Codex 앱 구현 → 실제 응답 대조(`T2_요청번호_포기_계약.md`).

## 5. D-T2-5 실시 기록 조회 — 담당 교사 + 승인된 관리 담당자

- 지금: 담당 교사와 `year.manage` 권한자(학교 관리자 등)만 조회. 다른 교사는 FORBIDDEN.
- "승인된 관리 담당자"를 `year.manage` 보다 좁히려면(예: 교무부장 역할만) 그 역할을 정해 T2-06 증분.

## 6. D-T2-6 교환 승인 — 다른 승인자, 최소 2명

- 지금: 승인 = `year.manage` 이면서 요청자와 **다른 계정**(T2-04). 요청자 본인 승인은 FORBIDDEN(시험 E06).
- 빈칸: 승인 가능한 사람이 1명뿐이면 **그 사람이 낸 요청은 아무도 승인할 수 없다**.
- 권장 증분: T2-08 사전 검사에 "그 학교의 `year.manage` 활성 소속이 2명 이상"을 넣어, 아니면 켜기를 멈춘다.
  켠 뒤 1명으로 줄면 readiness 는 그대로 두고, 그 사람의 제출만 미리보기 차단 사유로 알리는 안은 앱 parser 변경이 필요해 보류.
- **지금 운영 DB 는 업무실 소속이 계란님 1명**이다(10-19 읽기 확인). 이 조건을 넣으면 교사 소속 연결(학교 자료 G1)과
  두 번째 관리 담당자 지정이 끝나기 전에는 T2-08 을 켤 수 없다 — 의도한 순서인지 확인이 필요하다.
