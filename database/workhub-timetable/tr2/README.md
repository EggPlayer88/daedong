# TR2 — 확정 기본 주간표를 날짜별 운영 수업에 연결

TR1에서 확정한 기본표를 실제 T2 날짜별 수업으로 옮기는 증분이다. 운영 DB에는 아직 적용하지 않았다. 실제 22명·9학급·288교시 자료는 Git에 넣지 않으며 자동 검증에는 같은 규모의 합성 자료를 사용한다.

## 관리자에게 달라지는 것

시간표 → 확정·공유 → **기본 주간표를 날짜별 수업으로 연결**에서 기본표와 시작일·마지막 날을 고른다. 교사·학급·주당 교시 수와 날짜별 변경 수업을 미리 확인한 뒤 체크하고 반영한다. 기본표를 열었다는 이유만으로 운영 수업을 만들거나 `current_timetable_basis_id`를 바꾸지 않는다.

- 교사 명부가 전체 적용 기간에 실제 학교 소속·담당 수업과 연결돼야 한다. 미가입·만료된 시험 연결·중복 담당을 임의로 추정하지 않는다.
- 기본표의 명부 교사 ID를 로그인 소속으로 사용하지 않는다. 실제 담당 소속과 공식 학급 ID를 매핑한다.
- 원래 요일·교시·시각을 배치로 보존한다. 같은 길이의 기존 일과 슬롯만 향후 T2/T3 변경 후보가 될 수 있고, 실제 변경은 기존 충돌·권한·동의·승인 검사를 따른다.
- 기간 밖 수업과 다른 기본표/T1 시험 수업은 취소하지 않는다. 다른 계보와 겹치면 차단한다.
- 기존 휴업·교환으로 고정된 수업은 기존 T2 규칙을 그대로 적용한다. 같은 계획을 다시 반영하면 동일한 수업을 중복 생성하지 않는다.
- 응답이 끊기면 원래 요청 번호로 조회한다. 명시적으로 닫힌 번호는 늦게 도착해도 반영되지 않는다. 입력 보존과 동일 탭 복구 경로를 사용하며 자동 재전송하지 않는다.

## 설치 전에 검토할 구조 변화

새 private 스키마 `timetable_roster_bridge`에 불변 원본, 미리보기, 원요청 원장 세 표를 만든다. 기존 T1 기준판 표에는 `roster_source_id`와 별도 계보 FK를 추가한다. 기존 준비 초안 참조 두 열의 NOT NULL을 조건부 출처 제약으로 교체해 **T1 준비 초안 참조 또는 TR2 불변 원본 참조 중 하나만** 허용한다. 기존 준비 초안 FK, 기준판 불변 트리거와 RLS는 유지한다.

기존 확정 SQL 파일·T2 함수는 수정하지 않는다. 새 wrapper가 기존 `t2_publish_plan` 결과에서 다른 계보의 취소를 제외하고 충돌을 다시 계산하며, 같은 계보임을 확인한 경우에만 기존 `t2_publish_apply`로 반영한다. 예상 전신 함수 원문·소유자·search_path·기준판 제약이 다르면 설치 전체가 중단된다.

권한은 기존 `year.manage`/학교 관리와 수업 관리 판정을 함께 사용한다. 일반 교사는 새 관리 RPC를 쓸 수 없고 anon/authenticated/service_role은 새 표와 내부 함수에 직접 접근할 수 없다. AI 모델·토큰·요금과 공개 범위는 변경하지 않는다.

## 운영 적용 순서 (사용자 결정 후)

1. 앞선 CL1 일정 취소 설치와 `CL1-02`, `INT-16` 점검을 마친다.
2. `TR2-00_전후점검.sql` 실행: 6행, P1 ok, P2 info, F1~F4 compare. CSV 저장.
3. `TR2-01_명부시간표_운영연결.sql` 전체 실행. 일부 문단만 실행하지 않는다.
4. `TR2-02_사후점검.sql` 8행 FAIL 0, `INT-17_명부시간표운영연결포함_통합점검.sql` 18행 FAIL 0 확인. 12·13번 info는 안내다.
5. TR2-00을 다시 실행하여 F1~F4가 설치 전과 같은지 비교한다.
6. 앱 PR 검사/검토 후 사용자 병합, Vercel Production Ready를 확인한다.
7. 관리자 화면에서 명부 기본표와 **유효한 실제 담당 연결 기간**을 선택한다. 미리보기의 연결 누락·시간 충돌을 해결한 뒤 원문과 기간을 확인하고 반영한다.
8. 날짜별 공유 시간표/내 수업에서 결과를 확인한다. 기본표 참고 화면만 보이는 상태를 운영 완료로 기록하지 않는다.

자동 설치·활성화나 실제 자료 덮어쓰기는 없다. 현재 운영 DB의 교사 연결과 실제 날짜별 수업 상태는 이 로컬 검증만으로 확인되지 않는다. 이미 입력된 22명·9학급·288교시 자체의 원문 재검토, 실제 시범 계정 만료일과 운영할 기간 선택은 적용 전 읽기 확인이 필요하다.

## 검증

- `node tests/test_timetable_roster_bridge.mjs`: 입력/응답 범위·원키·동일 학교/소속·철회·접수증 대조.
- `node tests/browser/workhub-timetable-roster-bridge.mjs`: 실제 React 미리보기→명시 확정, 누락/만료 차단, 유실 복구/닫기, 늦은 응답·날짜 변경·표시 갱신 실패와 권한 재확인.
- `python database/workhub-timetable/tr2/build_checks.py`: 새 localhost PostgreSQL에서 전체 전신+CL1+TR2 설치, 원문/권한/자료 보존·훼손 검출, INT-17 재생성 대조와 `test/bridge_cases.py` 실제 RPC 회귀. 운영 DSN을 받지 않는다.

통합 점검 생성은 `--write`를 사용한다. 검사 파일을 재생성할 때만 사용하며 운영 DB 실행 인자가 아니다. 단순 삭제식 되돌리기 SQL은 제공하지 않는다. 실제 발행 후 원본·원장·동의 이력을 지우지 않도록 새 보강안으로 복구한다.
