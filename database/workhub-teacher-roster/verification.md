SQL 시험은 PG17 바이너리 경로를 각각 `P9_PG_BIN` / `WORKHUB_DEPLOYMENT_PG_BIN`으로 받고 **새 localhost 임시 DB**만 생성한다. 기본 시험 포트 55781 / 55791. 기존 환경변수의 운영 DSN·키를 읽지 않는다. 생성기는 `--write`일 때만 신규 INT-13 파일을 갱신하며, 인자 없이 실행하면 재생성 결과와 파일 해시를 대조한다. CI에도 두 SQL 검사를 추가했다.

## 경계와 재시험 기록

- 2026-11-10 CI 재확인: 최초 CI의 단위 검사·SQL 회귀·빌드는 통과했으나 전체 브라우저 156개 파일 중 3개가 실패했다. `published` 조회를 `publish` 저장으로 세던 양식 시험 2개와, 새 조회를 할 일 저장으로 분류하던 연결 이탈 fixture 1개였다. 조회 응답을 별도로 제공하고 RPC 동작 이름의 경계를 구분했다. 앱·SQL은 변경하지 않았으며 자동 저장 0건, 동일 요청 번호 복구 2회/실제 저장 1회 검증은 그대로다. 수정 뒤 양식 준비 17건·질문형 AI 15건·연결 이탈 12건, 합계 44건이 로컬에서 통과했다. 수정 커밋의 전체 CI 결과는 별도 확인해야 한다.

- 브라우저는 실제 React·어댑터에 합성 RPC 응답을 사용한다. 실제 Supabase/PostgREST·운영 로그인·실제 모바일 기기 성공으로 해석하지 않는다.
- SQL 응답 24건은 실제 격리 PG17 함수 결과다. 브라우저 합성과 구분한다.
- 기존 Windows 계산기 시험은 전체 회귀 두 차례에서 서로 다른 위치의 실행/대기 실패가 있었다. 단독 재시험 55건은 통과했다. 검증 기준을 낮추거나 계산기 코드를 변경하지 않았다. 다른 무거운 검사와 분리해 전체 재실행하니 5,457건 모두 통과했다. 환경 의존 재발 가능성은 남기며 초기 실패를 숨기지 않는다.
- 설치 전후 지문 보존과 새 계획 등록 후 보존은 구분한다. 명부를 **확정하면** 새 학급·교과·수업은 추가된다. 기존 계정·권한·시간표는 수정되지 않는다.
- 제공 Excel의 교실/공간 정보와 확인되지 않은 담임은 추정해 확정하지 않았다.
- TR1 기본표의 확정/조회와 기존 T2 날짜별 교환·휴업 처리는 다른 계약이다. 후자의 신규 명부 연결은 아직 포함하지 않는다.
