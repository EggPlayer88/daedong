# 가입 전 교사 명부와 기본 시간표 (TR1)

가입 계정이 없는 교사도 명부에 등록하고 수업·담임·주간 배치를 확정한다. 가입 후 관리자가 **명부 교사와 승인된 학교 소속을 직접 연결**하면 새 수업 담당과 교과·담임 배정이 해당 소속에 추가된다. 로그인 계정, 가짜 회원, 권한 역할을 만들지 않는다.

## 범위

| 경로 | 동작 |
| --- | --- |
| 학교 관리 → 교사 명부·기본 시간표 | 명부·학급·수업·시수·교시·담임 입력, 준비한 JSON 가져오기 |
| 초안 저장 미리보기 → 확인한 내용 반영 | 원본 판·적용 기간을 확인한 뒤 초안 저장 |
| 기본 시간표 확정 미리보기 → 확인한 내용 반영 | 시수 및 교사·학급 동시간 충돌 검증 후 별도 기본표 확정 |
| 시간표 → 기본 주간표 | 가입 여부와 관계없이 학급별·교사별 확정 기본표 조회 |
| 가입 후 담당 연결 | 명부 교사·실제 소속·유효기간을 선택하고 영향 검토 후 연결 |
| 내 기본 시간표 / 일정의 기본표 참고 | 해당 날짜에 계정과 연결된 명부 교사의 배치 표시 |

현재 제공 자료는 **22명·9학급·288교시·157수업**이다. 실제 자료는 로컬 전달 폴더에만 보관한다. Git에는 같은 구조의 익명 시험 자료만 포함한다. 12명의 기존 소속은 연결 후보이며 이름만으로 자동 연결하지 않는다. 미가입 10명은 명부만 만든다. 창체 교사를 근거로 찾은 담임 9명도 후보로만 남겨 관리자가 확인한다.

### 기존 시간표와의 관계

TR1의 `published`는 **기본 주간표 확정**이다. 기존 T1 기준판이나 T2의 날짜별 공개 접수증과 같은 뜻이 아니다. 기존 시험 시간표·날짜별 수업·휴업·교환 이력을 덮어쓰지 않는다. 일정에는 새 표를 **기본표 참고**로 구분해 보여 준다.

새 명부 기반 수업을 T2 날짜별 운영 및 교환·대강까지 발행하는 어댑터는 이번 TR1에 포함하지 않는다. 미가입 교사 ID를 기존 `teachers.id = membership_id` 계약에 억지로 넣지 않는다. 이 연결을 완료하기 전에는 새 기본표로 휴업·교환·실시 기록이 처리된다고 안내하면 안 된다. 공간 자료도 제공되지 않아 교실 충돌 검증은 하지 않는다.

## SQL 적용 순서

운영 SQL 실행과 병합은 사용자 담당이다. 이 PR은 운영 DB를 변경하지 않았다. 각 파일을 **통째로**, 앞 단계 결과를 확인한 뒤 실행한다. `TR1-01/02`는 각각 하나의 트랜잭션이며 재실행용 파일이 아니다.

| 순서 | 파일 | 정상 결과 |
| --- | --- | --- |
| 1 | 기존 `database/workhub-neis/n1/INT-12_나이스포함_통합점검.sql` | 18행, 12·13 info, 나머지 ok. 설치 전 기준선 |
| 2 | `tr1/TR1-00_전후점검.sql` | 6행: 01 ok, 02 미설치 info, F1~F4 compare. CSV 저장 |
| 3 | `tr1/TR1-01_가입전교사_모델.sql` | `TR1-01 / ok` 1행 |
| 4 | `tr1/TR1-02_명부_편성_연결.sql` | `TR1-02 / ok` 1행 |
| 5 | `tr1/TR1-03_사후점검.sql` | 9행: 01~08 ok, 09 info |
| 6 | `tr1/INT-13_교사명부포함_통합점검.sql` | 18행: 12·13 info, 나머지 ok. 전체 50단계 |
| 7 | `tr1/TR1-00_전후점검.sql` 재실행 | F1~F4가 2단계와 동일. CSV 저장 |
| 8 | PR 자동 검사·미리보기 확인 → 사용자 병합 → Production Ready | main 병합 커밋과 배포 커밋 대조 |
| 9 | 아래의 자료 등록 | SQL 설치와 별개로 관리자 화면에서 미리보기·확인 |

FAIL, SQL 오류, 예상 밖 지문 차이가 있으면 다음 파일을 실행하지 않는다. 여러 사람이 기존 자료를 동시에 저장하면 데이터 지문이 달라질 수 있으므로 원인을 대조하고, 차이를 자동 승인하지 않는다. **설치 후에는 INT-13이 새 전체 구조 기준**이다. 기존 INT-12와 과거 점검 내보내기 도구는 TR1의 추가 객체를 모른다.

INT-13 전달 해시는 `tr1/checks.json`에 있다. 파일이 SQL Editor 한도를 넘으면 본문을 임의로 나누지 말고 직접 DB 연결 또는 크기 제한에 맞춘 검증본을 별도로 준비한다.

## 실제 자료 등록

1. 학교 관리 → **교사 명부·기본 시간표** → 준비한 명부·시간표 가져오기에서 로컬 `가입전교사_288교시_가져오기.json` 선택.
2. 대상 학기와 적용 기간을 확인한다. 준비 파일은 원본 기준 주의 시작인 **2026-11-16**부터 **2027-03-01 직전**까지다. 실제 학기 범위 및 실행일에 맞는지는 서버가 다시 검사한다. 지난 날짜로 소급 확정하지 않는다.
3. 22명·9학급·288교시를 확인하고 기존 3학년 학급 연결을 확인한다. 다른 6학급은 새로 등록하는 안이다. 기존 시험 수업은 재사용하거나 변경하지 않는다.
4. 담임 후보는 자동 반영되지 않는다. 확인한 후보만 선택하고 초안을 저장한다. 확정본은 덮어쓰지 않으므로 담임 확인을 확정 전에 끝낸다.
5. **초안 저장 미리보기 → 대상·기간 확인 → 확인한 내용 반영**. 이후 별도로 **기본 시간표 확정 미리보기**를 확인·반영한다.
6. 기존에 확인한 계정 후보를 선택하거나 명부 교사와 현재 소속을 직접 선택한다. 영향 수업·담임 수와 시작일·종료 경계일을 확인한 뒤 연결한다. 역할 권한은 추가되지 않는다.
7. 아직 가입하지 않은 교사는 나중에 기존 가입 승인·학교 소속 연결 절차를 마친 뒤 6단계로 연결한다. 기존 수업 배치를 다시 작성하지 않는다.

결과 미상은 같은 요청 번호로 확인한다. 취소하고 싶으면 **이 요청 닫기**의 서버 응답을 받은 뒤에만 새 요청을 만든다. 조회 실패 중에도 작성 내용 파일 보관이 가능하다. 입력/미확정 요청의 복원은 현재 탭 메모리 범위이며 브라우저 종료 후 자동 복원을 약속하지 않는다.

## 보존·권한·동시성

- 기존 공개 RPC·SQL 파일을 교체하지 않는다. 전용 `teacher_roster` 스키마와 5개 RPC만 추가한다.
- 표·시퀀스·내부 함수는 anon/authenticated/service_role 직접 접근 금지. 표 10개 모두 RLS.
- 관리에는 기존 `year.manage`, 계정 연결에는 추가로 기존 `membership.approve`를 요구한다. 조회는 기존 OP1 시간표 접근과 T2 준비 상태를 재사용한다. 메뉴 및 일반 교사 공개 범위를 확대하지 않는다.
- 계정 연결 기간은 `[시작일, 종료 경계일)`이다. 같은 기간에 한 명부 교사↔한 계정만 허용한다. 현재 활성 소속·기간을 재검사한다.
- 새 계획의 수업과 명시 담임만 P1/P5에 추가한다. 기존 평가·상담 기록을 새 계정으로 옮기지 않는다.
- 미리보기 10분, 학교 판·원본 해시 대조, 동일 학교 잠금, 원번호 접수증, 닫기 방벽. 늦게 도착한 닫힌 요청은 쓰지 않는다.
- 기존 배정과 충돌하면 트랜잭션 전체를 거절한다. 기존 자료를 종료하거나 지워서 억지로 연결하지 않는다.
- API 모델·AI 예산·인증·파일 생성 엔진 변경 없음.

## 판단해서 정한 것

1. **가입 전 명부는 로그인 계정과 분리**: 가짜 계정에 실제 수업 기록을 쌓지 않기 위함. 연결 변경은 새 명부 계약에서 다룬다.
2. **이름 자동 매칭 금지**: 동명이인·별명을 방지한다. 가져온 후보도 확인 후 연결한다.
3. **기본표 확정과 기존 T2 운영 분리**: 기존 시험·운영 이력을 유지한다. 향후 T2 연계는 새 식별자 계약과 독립 증분으로 구현한다.
4. **확정·연결 이력은 불변**: 변경 필요 시 원본을 수정하는 SQL을 즉석 실행하지 않는다. 정정·후속 판 기능을 별도 설계해야 한다.

## 자동 검증

실행 방법과 결과는 `verification.md`를 따른다. 시험은 격리 PG17/합성 브라우저이며 운영 Supabase·배포 후 실제 계정 왕복은 포함하지 않는다.
