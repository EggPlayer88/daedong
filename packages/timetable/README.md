# 시간표 편성 계산 모듈

2026-10-18 추가: 실제 비동기 로컬 작업자와 브라우저 작업 폴더 연결을 제공한다. 접수·진행·취소·결과 확인·중단 복구는 [로컬 작업자 안내](../../docs/workhub/timetable/engine-jobs.md)를 따른다. 기존 단일 CLI와 계산 계약은 그대로 유지한다.

2026-10-17 현재 브라우저 작업실용 TypeScript 계산 계층과 같은 정규 계약을 직접 처리하는 Python CP-SAT 실행기를 제공한다. 기존 PR #5를 통째로 가져오거나 기존 입력으로 억지 변환하지 않았다. 브라우저 계산은 Web Worker에서 실행하며 Python 계산은 로컬 CLI로 실행한다. 계산 결과만으로 저장·게시·교환 승인하지 않는다.

## 책임과 지원 범위

- 입력은 학교·학기·원본 지문·판을 가진 `TimetableBasis`다. 학교 기본 자료에서 교사 배정·수업별 시수·명시적 활동·허용 시간대를 확정한 뒤 넘긴다.
- 수업 활동 하나에 교사, 학급, 수강 학생 집단, 실습실·장비를 모두 연결한다. 모든 교사·학급·학생 집단의 동시 수용량은 1이다. 실습실·장비는 지정한 수용량을 적용한다.
- 요일과 **실제 시작·종료 분**으로 겹침을 판정한다. 구간은 `[시작, 종료)`다. 교시명이 같거나 다른지만으로 충돌을 판단하지 않는다.
- `periods`는 활동과 시간대의 수업 시수다. 2교시 연속 활동은 2시수 시간대 하나에 통째로 배치한다. 중간 휴식도 포함한 전체 구간을 점유하는 보수적 모델이다. 휴식 중 자원 재사용을 지원한다고 해석하지 않는다.
- 학급별 빈칸을 억지로 채우지 않는다. 입력된 활동의 합과 `courseLoads`가 정확히 맞는지 확인한다. 학교가 원래 배정해야 하는 시수의 누락 여부는 원본 관리·서버 검증 책임이며 계산기가 자료에 없는 수업을 추정하지 않는다.
- 선택 수업의 중첩은 **실제 수강 집단의 교집합을 나타내는 자원**을 입력했을 때 검사한다. 수강 관계 추출이나 전국 학교 자동 지원이 완성된 것은 아니다. 격주·순환·이동 시간 등 표현되지 않은 조건은 `unsupportedFeatures`에 두고 탐색을 막는다.

## 호출 계약

```ts
validateBasis(value: unknown): { valid: boolean; issues: TimetableIssue[] }
validatePlacements(basis: TimetableBasis, value: unknown): { valid: boolean; issues: TimetableIssue[] }
solveTimetable(value: unknown, options?: { maxNodes?: number; maxMs?: number }): SolveResult
```

기초판·학교·학기·자원·시간대·활동·과목의 식별자와 모든 참조는 공통 RPC와 같은 `^[A-Za-z0-9_-]{1,100}$`를 사용한다. UUID 또는 영문·숫자·밑줄·하이픈의 합성 ID만 허용하고, 표시용 `label`과 `unsupportedFeatures` 설명에는 한국어 문장을 그대로 사용한다. 이름을 ID로 대체하거나 한글 이름을 강제로 영문화하지 않는다.

입력 검증은 미지원 필드, 잘못된 참조, 중복, 시수·블록·고정·자원 제약을 거부한다. `unsupportedFeatures`는 올바른 입력으로 표시하여 화면에서 안내할 수 있지만, 후보 검증과 탐색은 지원하지 않는 조건이 있다고 반환한다. 입력과 후보를 호출 과정에서 수정하지 않는다.

`preferences`의 `weight`는 해당 활동·시간대 배치의 비음수 벌점이다. 미지정은 0이며 작은 값이 선호된다. 교사 공강·요일 균형 등의 종합 최적화 점수가 아니다. 화면에서 100점 만점이나 만족도 수치로 환산하지 않는다.

## 탐색과 상태

가용 시간·고정 조건으로 도메인을 만든 뒤, 남은 선택지가 가장 적은 활동부터 한정 깊이우선 탐색한다. 분기에서 실제 시간의 자원 점유를 검사하고, 첫 완전한 유효안을 찾으면 종료한다. 출력 직전 별도 검증기가 모든 배치·참여자·시수를 처음부터 재집계한다. 이 검증기는 탐색 중 점유표를 읽지 않는다.

| status | 의미 |
|---|---|
| `feasible` | 원본에 표현된 모든 강제 조건을 만족하는 후보 1개. 품질 최적·최소 변경을 보장하지 않음 |
| `infeasible` | 특정 활동의 허용 시간이 없거나 한도 내에서 모든 분기를 확인하고 해가 없음. `exhausted:true` |
| `unknown` | 시간·탐색 횟수 한도 때문에 결론 없음. 불가능이라고 표시하면 안 됨 |
| `invalid` | 입력·옵션 오류 또는 내부 독립 검증 실패. 후보를 사용하면 안 됨 |
| `unsupported` | 명시된 미지원 조건 때문에 탐색하지 않음 |

`optimal`은 항상 false다. `score`는 배치 선호 벌점 합, `stats.nodes`는 배치를 시도한 횟수다. elapsedMs는 검증·탐색·최종 확인 시간을 포함하므로 종료 시간을 엄밀하게 보장하는 SLA가 아니다. 작업 취소는 Worker 종료로 처리한다. 이전 작업의 늦은 결과는 화면의 작업 ID·입력 지문 검사를 거쳐야 한다.

한도는 `_assets/browser-policy.json`에서 관리한다. 기본 50,000회·1,500ms, 상한 500,000회·10,000ms다. 활동 1,000개·자원 3,000개·시간대 3,000개·전체 허용 배치 300,000개 입력 상한은 브라우저 보호 기준이며 이 규모를 빠르게 해결한다는 보장이 아니다.

## 실제 CP-SAT 실행과 원본판 보존

기존 PR #5 `6595dbac`의 교사 교체를 변경 0칸으로 계산하던 문제와 새 교사 배정으로 과거 배치가 겹치면 복구 탐색을 거절하던 문제를 현재 정규 계약에서 회귀로 고정했다. 이전 배치는 `{ basis: 당시_기초판, placements: 당시_배치 }` 전체를 보관한다. 이전 배치의 적법성은 당시 기초판으로 검사하고 새 후보만 현재 기초판으로 검사한다.

`src/cpSat.ts`의 `buildCpSatRequest`가 현재 기초판, 당시 기초판, 전체 조건, 실행 옵션, 요청 번호를 SHA-256 지문으로 묶는다. `engine/runner.py`는 정확히 같은 계약을 별도로 검증한다. 후보를 받아들이는 `parseCpSatResponse`는 요청 지문, 배치 전체, 시수, 충돌과 아래 지표를 다시 계산한다. 임의로 적은 점수나 변조한 후보는 화면에 전달하지 않는다.

```sh
python -m pip install -r packages/timetable/requirements.txt
python packages/timetable/engine/runner.py --input "편성 요청.json" --output "계산 결과.json"
```

파일 방식은 Windows에서도 UTF-8·공백·한글 경로를 그대로 처리한다. 출력 파일이 이미 있으면 덮어쓰지 않는다. POSIX에서는 stdin/stdout 한 요청 방식도 지원한다. 운영 DB·네트워크·API 키를 읽거나 변경하지 않는다. 설치 대상은 로컬 계산 환경이며 Vercel 함수에 의존성을 추가하지 않는다.

### 최적화 순서

| 우선순위 | 지표 | 의미 |
|---|---|---|
| 1 | `changedLessons` | 이전 판 대비 추가·삭제·교과·시수·참여자·실제 시각이 달라진 수업 수. 같은 수업의 여러 변경을 중복 집계하지 않음 |
| 2 | `movedLessons` | 이전부터 있던 수업 중 실제 요일·시각이 이동한 수. 이미 교사가 바뀐 수업도 불필요하게 옮기지 않기 위해 별도 최소화 |
| 3 | `preferencePenalty` | 명시한 시간대 선호 벌점 합 |
| 4 | `teacherPeakPeriods` | 모든 교사의 하루 시수 중 최댓값 |
| 5 | `courseRepeats` | 같은 `courseId`의 활동이 같은 날 두 번 이상 배치된 초과 횟수. 하나의 연속 블록을 두 활동으로 세지 않음 |

각 단계를 순서대로 최적화하고 앞 단계의 최적값을 고정한다. 필수조건을 점수로 바꾸거나 임의로 완화하지 않는다. 이전 판이 없거나 `minimizeChanges:false`이면 1·2를 건너뛴다. `improveTeacherBalance`, `spreadCourses`로 4·5 사용 여부를 명시한다. 학교가 승인한 가중치를 임의로 추정하지 않는다.

최대 3개 후보를 요청할 수 있다. 첫 후보 이후는 이미 반환한 배치를 제외한 남은 해 중에서 다시 같은 순서로 계산한다. 따라서 두 번째 후보의 `optimal:true`는 **앞 후보를 제외한 범위의 최적**이며 첫 후보와 같은 점수라는 뜻이 아니다. 한 단계라도 최적성 증명을 마치지 못하면 유효 후보는 유지하되 `optimal:false`로 보고한다. 시간 안에 후보를 못 찾으면 `unknown`, 해가 없음을 증명했을 때만 `infeasible`이다.

일일 시수 최댓값과 교과 분산은 품질의 일부다. 과거 엔진의 모든 공강·연강·오전/오후·최악 교사 부담 최적화를 이식했다고 주장하지 않는다. `quality.ts`는 교사별 일별 시수와 수업 사이 분을 표시한다. `idleMinutes`는 점심·휴식까지 포함하므로 '공강 교시 수'로 표시하면 안 된다. 부분 배치나 충돌 초안에는 정상 품질 점수를 붙이지 않는다.

한도는 `_assets/engine-policy.json`에서 관리한다. 기본 15초, 최대 120초, 후보 최대 3개, 허용 조합 100,000개, 자원별 조합 합계 500,000개다. 모델 준비와 검증 시간이 있어 실제 벽시계 시간 상한을 보장하는 SLA는 아니다. 로컬 작업자는 별도 프로세스 감독으로 강제 한도·취소·중단 복구를 제공하며, 공용 서버의 인증·배포·격리는 후속 책임이다. 로컬 실행 성공은 운영 작업 서버·DB 저장·실시간 Claude 연결 성공을 뜻하지 않는다.

## 조건 레지스트리와 조합

`src/conditions.ts`는 시간 고정, 자원 불가 구간, 허용 시간 좁히기, 시간대 선호 벌점의 네 종류를 정확한 필드로 받는다. AI/엑셀에서 받은 제안은 사용자 확인 후 이 계층으로 넘긴다. 기존 필수 고정을 바꾸거나 허용 범위를 넓히지 않는다. 조건이 하나라도 잘못되면 전체 결과가 `basis:null`이며 원본을 건드리지 않는다. 격주·이동 시간·일일 최대 시수 등 별도 강제조건은 지금 레지스트리에서 지원하지 않으며 메모로 낮춰 몰래 적용하지 않는다.

학생 집단은 실제 수강 교집합을 추출해 넣었을 때만 충돌을 계산한다. 시간표 계산이 교사 수업 관계나 학생 기록 권한을 바꾸지는 않는다. 담당자의 게시·날짜별 교환·동의·동시 수정 처리는 이 계산 모듈 밖의 서버 책임이다.
