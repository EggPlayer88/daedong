## 책임과 지원 범위

- 입력은 학교·학기·원본 지문·판을 가진 `TimetableBasis`다. 학교 기본 자료에서 교사 배정·수업별 시수·명시적 활동·허용 시간대를 확정한 뒤 넘긴다.
- 수업 활동 하나에 교사, 학급, 수강 학생 집단, 실습실·장비를 모두 연결한다. 모든 교사·학급·학생 집단의 동시 수용량은 1이다. 실습실·장비는 지정한 수용량을 적용한다.
- 요일과 **실제 시작·종료 분**으로 겹침을 판정한다. 구간은 `[시작, 종료)`다. 교시명이 같거나 다른지만으로 충돌을 판단하지 않는다.
- `periods`는 활동과 시간대의 수업 시수다. 2교시 연속 활동은 2시수 시간대 하나에 통째로 배치한다. 중간 휴식도 포함한 전체 구간을 점유하는 보수적 모델이다. 휴식 중 자원 재사용을 지원한다고 해석하지 않는다.
- 학급별 빈칸을 억지로 채우지 않는다. 입력된 활동의 합과 `courseLoads`가 정확히 맞는지 확인한다. 학교가 원래 배정해야 하는 시수의 누락 여부는 원본 관리·서버 검증 책임이며 계산기가 자료에 없는 수업을 추정하지 않는다.
- 선택 수업의 중첩은 **실제 수강 집단의 교집합을 나타내는 자원**을 입력했을 때 검사한다. 수강 관계 추출이나 전국 학교 자동 지원이 완성된 것은 아니다. 격주·순환·이동 시간 등 표현되지 않은 조건은 `unsupportedFeatures`에 두고 탐색을 막는다.

## 호출 계약

```ts
validateBasis(value: unknown): { valid: boolean; issues: TimetableIssue[] }
validatePlacements(basis: TimetableBasis, value: unknown): { valid: boolean; issues: TimetableIssue[] }
solveTimetable(value: unknown, options?: { maxNodes?: number; maxMs?: number }): SolveResult
```

기초판·학교·학기·자원·시간대·활동·과목의 식별자와 모든 참조는 공통 RPC와 같은 `^[A-Za-z0-9_-]{1,100}$`를 사용한다. UUID 또는 영문·숫자·밑줄·하이픈의 합성 ID만 허용하고, 표시용 `label`과 `unsupportedFeatures` 설명에는 한국어 문장을 그대로 사용한다. 이름을 ID로 대체하거나 한글 이름을 강제로 영문화하지 않는다.

입력 검증은 미지원 필드, 잘못된 참조, 중복, 시수·블록·고정·자원 제약을 거부한다. `unsupportedFeatures`는 올바른 입력으로 표시하여 화면에서 안내할 수 있지만, 후보 검증과 탐색은 지원하지 않는 조건이 있다고 반환한다. 입력과 후보를 호출 과정에서 수정하지 않는다.

`preferences`의 `weight`는 해당 활동·시간대 배치의 비음수 벌점이다. 미지정은 0이며 작은 값이 선호된다. 교사 공강·요일 균형 등의 종합 최적화 점수가 아니다. 화면에서 100점 만점이나 만족도 수치로 환산하지 않는다.

## 탐색과 상태

가용 시간·고정 조건으로 도메인을 만든 뒤, 남은 선택지가 가장 적은 활동부터 한정 깊이우선 탐색한다. 분기에서 실제 시간의 자원 점유를 검사하고, 첫 완전한 유효안을 찾으면 종료한다. 출력 직전 별도 검증기가 모든 배치·참여자·시수를 처음부터 재집계한다. 이 검증기는 탐색 중 점유표를 읽지 않는다.

| status | 의미 |
|---|---|
| `feasible` | 원본에 표현된 모든 강제 조건을 만족하는 후보 1개. 품질 최적·최소 변경을 보장하지 않음 |
| `infeasible` | 특정 활동의 허용 시간이 없거나 한도 내에서 모든 분기를 확인하고 해가 없음. `exhausted:true` |
| `unknown` | 시간·탐색 횟수 한도 때문에 결론 없음. 불가능이라고 표시하면 안 됨 |
| `invalid` | 입력·옵션 오류 또는 내부 독립 검증 실패. 후보를 사용하면 안 됨 |
| `unsupported` | 명시된 미지원 조건 때문에 탐색하지 않음 |

`optimal`은 항상 false다. `score`는 배치 선호 벌점 합, `stats.nodes`는 배치를 시도한 횟수다. elapsedMs는 검증·탐색·최종 확인 시간을 포함하므로 종료 시간을 엄밀하게 보장하는 SLA가 아니다. 작업 취소는 Worker 종료로 처리한다. 이전 작업의 늦은 결과는 화면의 작업 ID·입력 지문 검사를 거쳐야 한다.

한도는 `_assets/browser-policy.json`에서 관리한다. 기본 50,000회·1,500ms, 상한 500,000회·10,000ms다. 활동 1,000개·자원 3,000개·시간대 3,000개·전체 허용 배치 300,000개 입력 상한은 브라우저 보호 기준이며 이 규모를 빠르게 해결한다는 보장이 아니다.

## 실제 CP-SAT 실행과 원본판 보존

기존 PR #5 `6595dbac`의 교사 교체를 변경 0칸으로 계산하던 문제와 새 교사 배정으로 과거 배치가 겹치면 복구 탐색을 거절하던 문제를 현재 정규 계약에서 회귀로 고정했다. 이전 배치는 `{ basis: 당시_기초판, placements: 당시_배치 }` 전체를 보관한다. 이전 배치의 적법성은 당시 기초판으로 검사하고 새 후보만 현재 기초판으로 검사한다.

`src/cpSat.ts`의 `buildCpSatRequest`가 현재 기초판, 당시 기초판, 전체 조건, 실행 옵션, 요청 번호를 SHA-256 지문으로 묶는다. `engine/runner.py`는 정확히 같은 계약을 별도로 검증한다. 후보를 받아들이는 `parseCpSatResponse`는 요청 지문, 배치 전체, 시수, 충돌과 아래 지표를 다시 계산한다. 임의로 적은 점수나 변조한 후보는 화면에 전달하지 않는다.

```sh
python -m pip install -r packages/timetable/requirements.txt
python packages/timetable/engine/runner.py --input "편성 요청.json" --output "계산 결과.json"
```

파일 방식은 Windows에서도 UTF-8·공백·한글 경로를 그대로 처리한다. 출력 파일이 이미 있으면 덮어쓰지 않는다. POSIX에서는 stdin/stdout 한 요청 방식도 지원한다. 운영 DB·네트워크·API 키를 읽거나 변경하지 않는다. 설치 대상은 로컬 계산 환경이며 Vercel 함수에 의존성을 추가하지 않는다.

### 기존 모드의 최적화 순서

다음 순서는 `qualityMode`를 생략한 요청에 적용한다. 기존 `timetable.solve.v1`, `canonical-cpsat-1`과 후보의 `objective` 형식, API의 기본 15초·후보 1개·`minimizeChanges:true`를 유지한다.

| 우선순위 | 지표 | 의미 |
|---|---|---|
| 1 | `changedLessons` | 이전 판 대비 추가·삭제·교과·시수·참여자·실제 시각이 달라진 수업 수. 같은 수업의 여러 변경을 중복 집계하지 않음 |
| 2 | `movedLessons` | 이전부터 있던 수업 중 실제 요일·시각이 이동한 수. 이미 교사가 바뀐 수업도 불필요하게 옮기지 않기 위해 별도 최소화 |
| 3 | `preferencePenalty` | 명시한 시간대 선호 벌점 합 |
| 4 | `teacherPeakPeriods` | 모든 교사의 하루 시수 중 최댓값 |
| 5 | `courseRepeats` | 같은 `courseId`의 활동이 같은 날 두 번 이상 배치된 초과 횟수. 하나의 연속 블록을 두 활동으로 세지 않음 |

각 단계를 순서대로 최적화하고 앞 단계의 최적값을 고정한다. 필수조건을 점수로 바꾸거나 임의로 완화하지 않는다. 이전 판이 없거나 `minimizeChanges:false`이면 1·2를 건너뛴다. `improveTeacherBalance`, `spreadCourses`로 4·5 사용 여부를 명시한다. 학교가 승인한 가중치를 임의로 추정하지 않는다.

최대 3개 후보를 요청할 수 있다. 첫 후보 이후는 이미 반환한 배치를 제외한 남은 해 중에서 다시 같은 순서로 계산한다. 따라서 두 번째 후보의 `optimal:true`는 **앞 후보를 제외한 범위의 최적**이며 첫 후보와 같은 점수라는 뜻이 아니다. 한 단계라도 최적성 증명을 마치지 못하면 유효 후보는 유지하되 `optimal:false`로 보고한다. 시간 안에 후보를 못 찾으면 `unknown`, 해가 없음을 증명했을 때만 `infeasible`이다.

일일 시수 최댓값과 교과 분산은 품질의 일부다. 과거 엔진의 모든 공강·연강·오전/오후·최악 교사 부담 최적화를 이식했다고 주장하지 않는다. `quality.ts`는 교사별 일별 시수와 수업 사이 분을 표시한다. `idleMinutes`는 점심·휴식까지 포함하므로 '공강 교시 수'로 표시하면 안 된다. 부분 배치나 충돌 초안에는 정상 품질 점수를 붙이지 않는다.

한도는 `_assets/engine-policy.json`에서 관리한다. 기본 15초, 최대 120초, 후보 최대 3개, 허용 조합 100,000개, 자원별 조합 합계 500,000개다. 모델 준비와 검증 시간이 있어 실제 벽시계 시간 상한을 보장하는 SLA는 아니다. 로컬 작업자는 별도 프로세스 감독으로 강제 한도·취소·중단 복구를 제공하며, 공용 서버의 인증·배포·격리는 후속 책임이다. 로컬 실행 성공은 운영 작업 서버·DB 저장·실시간 Claude 연결 성공을 뜻하지 않는다.

## 품질 우선 모드 `balanced`

`qualityMode:'balanced'`와 `minimizeChanges:false`를 함께 지정하면 새 품질 탐색을 사용한다. 최소 변경 옵션과 함께 켜는 요청은 거절한다. 요청 계약명은 `timetable.solve.v1`을 유지하고, 응답 엔진 버전은 `_assets/balanced-policy.json`의 `canonical-balanced-1`이다. 후보에는 기존 `objective`와 별도로 `quality`가 반드시 포함된다. 기존 모드에 새 필드를 붙여 받아들이거나 기존 요청을 자동 변환하지 않는다.

```ts
const request = await buildCpSatRequest(basis, requestId, previous, {
  qualityMode: 'balanced',
  minimizeChanges: false,
  maxSeconds: balancedPolicy.defaultSeconds,
  maxCandidates: balancedPolicy.defaultCandidates,
})
```

위 `balancedPolicy`는 `_assets/balanced-policy.json`에서 읽는다. **최적화 엔진으로 계산·후보 비교** 패널의 새 계산은 **품질 우선·60초·3개 이내**가 기본이며, **변경 최소·기존 배치 보존**도 선택할 수 있다. 저장된 기존 요청은 그 모드를 유지한다. 이 UI 기본값은 옵션을 생략한 API 기본값을 바꾸지 않는다. 범위를 좁힌 계산과 작업 고정은 기존 `prepareScopedSolve`를 거친다. 담당자가 후보별 패널티와 변경 내용을 확인한 뒤 직접 초안에 반영하며, 학교 서버 저장·확정은 별도다.

새 후보 비교는 이 패널에서 **이 PC에서 계산하기**로 로컬 작업자를 연결하거나 요청·결과 JSON을 주고받는 경로를 사용한다. 편성 화면의 기존 **배치 만들기/다시 계산** 버튼은 빠른 브라우저 계산으로 첫 유효안 하나를 초안에 반영하는 경로를 유지한다. 이 버튼이 새 CP-SAT 후보 3개를 생성한다고 해석하지 않는다.

### 로컬 계산기 갱신

진행 중인 작업을 먼저 끝내고 로컬 작업자의 종료를 확인한 뒤, 같은 버전의 `packages/timetable/engine/`과 `packages/timetable/_assets/` 전체를 함께 갱신한다. `runner.py`뿐 아니라 `balanced_engine.py`, `balanced_quality.py`, `jobs_contract.py`, `balanced-policy.json`도 필요하다. 요구 의존성은 `packages/timetable/requirements.txt`를 기준으로 확인하고, 기존 전용 작업 폴더를 지정해 `jobs.py work --store "기존 작업 폴더"`를 다시 실행한다. 이미 접수한 요청·결과를 삭제하거나 작업 폴더를 다시 초기화하지 않는다. 중단 작업은 [로컬 작업자 복구 안내](../../docs/workhub/timetable/engine-jobs.md)를 따른다.

실행 중인 작업자는 이미 읽은 Python 모듈과 정책을 메모리에 유지하므로 파일 갱신만으로 새 계약이 적용되지 않는다. 브라우저의 '계산기 연결/최근 실행 확인'은 동작 상태 확인이며 엔진 기능·버전 호환 검사도 아니다. 구형 계산기는 연결 상태로 보이더라도 새 `balanced` 요청을 거절할 수 있으므로 화면과 로컬 계산기를 함께 갱신하고 작업자를 재시작한다.

### 하드조건과 이전 유효안 보존

모든 활동의 정확한 한 번 배치, 과목 시수, 허용 시간·시수 일치, 필수 고정, 자원별 실제 구간 수용량, 불가시간을 기존 검증기와 같은 계약으로 적용한다. 공동수업의 교사 전원, 학급, 수강 교집합, 공간·장비도 입력된 자원을 그대로 점유한다. 필수조건 위반을 점수로 상쇄하거나 후보 수를 맞추려고 조건을 완화하지 않는다. 명시된 미지원 조건은 계속 탐색을 막는다.

현재 기초판에서도 유효한 이전 배치는 모델을 만들기 전 후보로 보존한다. 모델 준비나 탐색이 시간초과해도 확보한 유효안을 반환할 수 있고, 최고 후보의 현재 종합 패널티는 이 이전 안보다 나빠지지 않는다. 당시 기초판에서만 유효하고 현재 조건에서는 위반인 이전 배치를 반환하지 않는다. 보존할 안도 없고 탐색 안을 얻지 못했다면 `unknown`이며, 불가능 증명이 있을 때만 `infeasible`이다. 이 보존은 엔진의 정상 시간 제한에 관한 동작으로, 프로세스 강제 종료·실행 오류에서 결과 파일이 반드시 만들어진다는 뜻은 아니다.

Python은 후보를 보관할 때와 반환할 때 하드조건을 재검사한다. 로컬 작업자와 TypeScript 응답 parser도 원래 요청 지문, 전체 하드조건, 품질값, 실제 다양성, 이전 안 대비 최고안의 비악화를 다시 검사한다. 이 보장은 **현재 입력에 표현된 조건과 같은 평가식**에 한정된다. 모든 대안이 이전 안보다 좋거나 모든 교사의 개별 지표가 좋아진다는 보장은 아니다.

### 종합 패널티의 정의

`src/balanced.ts`와 `engine/balanced_quality.py`는 솔버의 변수·탐색 점유표를 사용하지 않고 완성 배치를 평가한다. `quality.totalPenalty`는 아래 여섯 원시 지표에 정책 가중치를 곱한 합이다. 작을수록 좋으며, 100점 만점·만족도·최적해까지의 백분율로 환산하지 않는다. 가중치는 비교를 위한 현재 제품 정책이며 학교별로 승인된 선호를 대신하지 않는다.

| 원시 지표 | 정의 | 현재 가중치 |
|---|---|---:|
| `preferencePenalty` | 명시한 활동·시간대 선호 벌점의 합 | 10 |
| `teacherDailyExcess` | 교사별·일별 `max(0, 일일 시수 - 목표 시수)²`의 합 | 30 |
| `teacherWorstExcess` | 교사별로 위 초과 제곱을 주간 합산한 값의 최댓값 | 20 |
| `courseDailyPairs` | 동일 과목·수강 집단의 같은 날 활동 수가 `n`일 때 `n(n-1)/2`의 합 | 80 |
| `courseAdjacency` | 동일 과목·수강 집단에 수업이 있는 `day`와 `day+1`의 쌍 수 | 8 |
| `teacherGapMinutes` | 교사별 첫 수업~마지막 수업 사이에서 배정 가능한 구간에 속하지만 수업이 차지하지 않은 분의 합 | 1 |

교사의 목표 시수는 `ceil(전체 담당 시수 / 배정 가능한 요일 수)`다. 배정 가능 구간은 담당 활동의 허용 시간대에서 참여 자원의 불가시간을 제외한 구간의 합집합이다. 고정 배치나 탐색 중 부분 동결로 이 기준을 좁혀 품질 점수를 유리하게 바꾸지 않는다. 목표 시수와 그 초과는 소프트 지표이며 새로운 일일 최대 시수 하드조건이 아니다. `improveTeacherBalance:false`면 세 교사 지표, `spreadCourses:false`면 두 과목 지표의 가중치를 0으로 적용하되 원시 지표는 계속 보고한다.

과목 분산의 그룹은 `courseId`와 학급·학생 집단 자원 목록으로 정한다. 표시 이름이 같다는 이유로 별도 과목 ID를 합치지 않는다. 2교시 연속 블록은 활동 하나로 세며, 인접 요일은 숫자상 `day+1`이다. 금요일과 다음 주 월요일을 연결하지 않는다.

`teacherGapMinutes`는 기존 `quality.ts`의 전체 수업 사이 `idleMinutes`와 다른 지표다. 허용 구간 밖 휴식은 빠지지만, 블록 시간대에 점심·휴식이 포함돼 있으면 그 구간도 계산에 영향을 준다. 학교의 정규 교시·점심 규정·이동·준비 시간을 추정하지 않으므로 **실제 공강 교시 수를 완전히 정확하게 센다는 보장은 없다**. 현재 화면도 이를 '배정 가능한 시간 사이의 빈 구간'으로 표시한다.

### 실제로 다른 후보의 기준과 탐색

후보의 실제 내용은 `(요일, 시작·종료 분, courseId, 전체 참여 자원)`으로 비교한다. 같은 입력에 있는 시간대의 경계로 구간을 나누고, 카드 ID·슬롯 ID·블록 경계만 다른 배치는 같은 내용으로 취급한다. 차이 분은 두 후보 사이에서 사라진 점유 분과 추가된 점유 분 중 큰 값이다. 같은 분에 여러 학급의 수업이 달라지면 각 수업 점유의 분을 합산하므로 학교 전체의 단순 경과 시간이나 변경 교시 수가 아니다.

화면의 **수업 카드 변경** 개수와 상세 변경표는 활동 ID 기준이므로 동일 내용의 카드끼리 자리를 바꾼 경우도 포함한다. 다른 후보에는 **최고안 대비 실제 수업 차이**를 분 단위로 별도 표시하여 이 카드 변경 개수와 구분한다.

현재 정책에서 최고안 패널티가 `B`, 그 안의 실제 내용 점유 분 합이 `M`이면 반환 후보 모두에 다음을 적용한다.

- 품질 상한: `B + max(10, floor(B × 0.10))` 이하.
- 다양성 하한: `max(1, ceil(M × 0.04))`분 이상. 최고안과의 차이뿐 아니라 **반환 후보의 모든 쌍**이 충족해야 한다.
- 최고안을 첫 후보로 두며 같은 실제 내용의 카드 순열이나 슬롯 별칭을 별도 후보로 세지 않는다.

상수의 원본은 `_assets/balanced-policy.json`이다. 품질 허용 범위와 충분한 차이를 만족하는 안이 없거나 시간 안에 찾지 못하면 1~2개만 반환할 수 있다. **어떤 학급 수·학교 조건에서도 3개가 존재하거나 1분 안에 나온다고 보장하지 않는다.**

탐색은 과목·시수·참여자·허용 범위·고정·개별 선호까지 같은 반복 활동을 묶어 카드 순열을 줄인다. 초기 전체 탐색 뒤 학급·요일·교사 관련 부분을 번갈아 다시 풀고, 개선 성과와 탐색 시간으로 다음 부분을 선택하며 주기적으로 전체 범위를 다시 푼다. 확보한 최고안은 유지하고, 품질 상한과 실제 차이 제약 안에서 후보를 추가한다. 여러 후보를 얻은 뒤에는 교사 빈 구간·부담·과목 분산의 다른 장점도 탐색한다.

부분 문제의 최적성은 원래 전체 문제의 최적성을 뜻하지 않는다. `balanced` 응답의 `optimal`은 항상 `false`이며, 전체 최적해 또는 최적값과의 차이 증명을 제공하지 않는다. 품질 개선은 현재 가중 합을 줄이는 목표로, 지표 사이의 상충을 없애지는 못한다. 현재 정책은 요청 한도에서 `min(4초, 요청 시간 × 10%)`를 탐색에 쓰지 않고 최종 검증·전달을 위한 여유로 남긴다. 따라서 60초 요청은 4초를 남기며, 짧은 요청에서는 이 여유가 요청 시간의 10%를 넘지 않는다. 로컬 연결의 `balanced` 결과 조회 간격은 250ms이고 기존 모드는 1초를 유지한다. 모델 작성·Python 기동·응답 검증 비용과 PC 부하가 있어 60초는 모든 입력에 대한 엄밀한 완료 SLA가 아니다.

### 동일 조건 벤치마크

`scripts/benchmark-timetable-quality.mjs`는 기준 커밋의 Python 엔진을 `git archive`로 분리하고 현재 엔진도 시작 시점에 복사해 같은 합성 입력으로 비교한다. 운영 DB나 실제 학교 자료를 사용하지 않는다. 9학급 기본/복합 문제와 18학급 복합 문제는 먼저 알려진 유효 배치를 만들며, 복합 문제의 공동 원어민 교사·수강 집단·수용량 2 공간·공유 장비·블록·담임 담당 고정 교과수업·불가시간을 유지한다. 이는 대동여중 실제 자료나 창체 배정 검증을 대신하지 않는다.

```sh
node scripts/benchmark-timetable-quality.mjs --baseline-ref <기준커밋> --scenario complex --seeds 11,12,13 --seconds 60 --output <결과.json>
```

`--scenario simple|complex|large`, `--fixture-seed`, `--warm`을 지원한다. `--warm`은 알려진 유효 배치를 이전 안으로 전달하므로 처음 생성하는 비교와 구분한다. 양쪽 모두 같은 시드·60초 등 지정 예산·최대 3개·`minimizeChanges:false`로 실행하며, 개선 엔진에만 `qualityMode:'balanced'`를 더한다. Python 프로세스를 동시에 실행하지 않고 실행 순서를 교대한다. **기존 엔진 1 워커와 새 엔진 8 워커의 같은 벽시계 시간 비교**이며 같은 CPU 사용량 비교는 아니다. 여러 워커의 탐색은 시드가 같아도 실행 결과와 시간이 달라질 수 있다.

실제 버튼부터 후보 표시까지는 별도로 다음과 같이 측정한다. `--classes`는 9 또는 18이며, 결과 JSON·화면 캡처·작업 폴더를 지정한 경로에 보존한다. 폴더 선택 대화상자만 시험 어댑터로 연결하고 실제 파일·Python 작업자·독립 검증·UI 조회와 렌더링을 거친다. 이 측정과 짝 비교를 동시에 실행하지 않는다.

```sh
node scripts/benchmark-timetable-button.mjs --classes 18 --output-directory .tmp-timetable-quality
```

기존 엔진 후보도 현재의 같은 독립 품질 평가기로 재평가한다. 보고서는 입력·소스 해시, 원시 배치, 하드조건 검사, 각 품질 지표와 최악 교사 부담, 실제 후보 수, 모든 쌍의 차이, 품질 상한을 만족하는 후보 수, 최적성 표시와 시간을 기록한다. `wallSeconds`는 Python 기동부터 종료까지이고 `verifiedWallSeconds`는 요청 생성부터 TypeScript 응답 검증 완료까지다. `threeHighQualityDiverseWithinBudgetRuns`는 이 검증 포함 시간 안에 품질·다양성 조건을 만족하는 3안을 받은 횟수다. 추가 보고용 재평가 시간은 제외한다. 단일 시드의 첫 결과를 확정 성능으로 일반화하지 않고, 여러 시드·규모·이전 안 유무의 반환율과 품질 악화 여부를 함께 확인한다.

### 2026-11-18 최종 측정

[측정 요약·원시 지표·소스 해시](benchmarks/2026-11-18-quality.json)를 보존했다. Windows, i7-1360P(논리 프로세서 16개), 메모리 16GiB, OR-Tools 9.15.6755에서 기준 `be379a8a`와 비교했다. 최종 정책으로 6회 비교했으며 종합 패널티 악화는 0회였다. 아래 시간은 요청 생성부터 응답 독립 검증까지이며 실제 버튼 시간은 별도로 적는다.

| 합성 조건 | 비교 횟수 | 평균 패널티 기존 → 개선 | 감소율 | 60초 내 고품질·실제 다른 3안 기존 → 개선 | 개선안 최대 검증 시간 |
|---|---:|---:|---:|---:|---:|
| 9학급 기본 | 2 | 7,698.5 → 2,103.5 | 72.7% | 1/2 → 2/2 | 57.21초 |
| 9학급 복합 | 2 | 9,172.5 → 4,526.5 | 50.7% | 0/2 → 2/2 | 56.92초 |
| 18학급 복합 | 1 | 24,281 → 12,524 | 48.4% | 0/1 → 1/1 | 57.75초 |
| 9학급 복합·이전 유효안 전달 | 1 | 12,899 → 3,355 | 74.0% | 0/1 → 1/1 | 57.03초 |

이전 안 전달 사례의 시작 패널티는 4,530이었다. 새 엔진은 이를 3,355로 개선했다. 기존 엔진은 다른 목적함수의 우선순위를 따르므로 같은 새 평가식에서 12,899가 됐다. 이 수치를 기존 엔진이 자기 목적함수를 틀리게 계산했다는 뜻으로 읽으면 안 된다.

실제 버튼 클릭부터 3안·품질 평가가 화면에 표시되기까지는 9학급 **58.006초**, 18학급 **59.674초**였다. 4초 여유를 적용하기 전 9학급 버튼 측정은 61.533초로 실패했으며 이를 통과 실적으로 세지 않았다. 최종 측정에서 검증한 기존·개선 후보 35개 모두 하드조건을 통과했다. 운영 학교 자료의 결과나 모든 PC·조건의 SLA는 아니다.

총점 개선은 주로 교사의 중간 빈구간 감소에서 나왔다. 9학급 기본 최선안은 빈구간이 6,075~6,480분에서 0~45분으로 줄었지만 선호 벌점은 0에서 48~50, 같은 날 과목쌍은 0에서 2로 늘었다. 복합 시드 11의 최선안은 개인별 최대 초과점수가 2에서 5로 악화했고, 같은 실행의 2안은 총점이 1안보다 1.17% 높으면서 개인별 최대 초과점수가 3으로 낮았다. **각 지표의 동시 개선이나 후보마다 고유한 품질 장점을 보장하지 않는다.** 화면의 후보별 손실·교사 일과를 보고 담당자가 선택해야 한다. 패널티 감소율은 만족도나 100점 만점 평가가 아니다.

## 조건 레지스트리와 조합

`src/conditions.ts`는 시간 고정, 자원 불가 구간, 허용 시간 좁히기, 시간대 선호 벌점의 네 종류를 정확한 필드로 받는다. AI/엑셀에서 받은 제안은 사용자 확인 후 이 계층으로 넘긴다. 기존 필수 고정을 바꾸거나 허용 범위를 넓히지 않는다. 조건이 하나라도 잘못되면 전체 결과가 `basis:null`이며 원본을 건드리지 않는다. 격주·이동 시간·일일 최대 시수 등 별도 강제조건은 지금 레지스트리에서 지원하지 않으며 메모로 낮춰 몰래 적용하지 않는다.

학생 집단은 실제 수강 교집합을 추출해 넣었을 때만 충돌을 계산한다. 시간표 계산이 교사 수업 관계나 학생 기록 권한을 바꾸지는 않는다. 담당자의 게시·날짜별 교환·동의·동시 수정 처리는 이 계산 모듈 밖의 서버 책임이다.

CP-SAT 시험은 고정 버전 OR-Tools가 없으면 실패한다. Python 명령은 해당 의존성이 설치된 인터프리터로 실행한다. 자동 검증은 실제 학교 전체 자료의 품질·성능 검증을 대신하지 않는다.
