# 교사 10명 한정 시험 계정 준비

이 도구는 승인된 학교의 시험용 Auth 계정 **정확히 10개**만 준비한다. 기존 실계정을 수정하지 않고, 가입 승인·소속·담임·수업 연결·AI 이용 허용도 여기서 수행하지 않는다. 해당 단계는 TP1 SQL의 사전 점검과 승인 함수로 분리한다.

## 실행 전

1. 운영 배포 기준, TP1 설치 여부와 10명 명부 ID를 확인한다.
2. `config.example.json`의 합성 예시를 **저장소 밖** 비공개 파일로 복사한다. 실명·학교 ID는 그 사본에만 넣는다.
3. `projectRef`, `schoolId`, `batchId`, `startsAt`, `expiresAt`와 T01~T10의 `teacherId`·`displayName`을 채운다. 이름은 반드시 `[시험] `으로 시작한다. 시작·종료는 UTC 밀리초 `.000Z`, 기간은 7일 이하다.
4. 명부 연결 기간과 실제 기본표 기간이 겹치는지 확인한다. 기본표 시작 전의 연결만으로 수업 시험이 가능하다고 판단하지 않는다.
5. 생성된 계정과 암호를 보관할 저장소 밖의 기존 개인 폴더를 지정한다. 도구는 그 아래 `batchId` 전용 폴더만 만들며, Windows에서는 현재 사용자만 허용하는 ACL을 확인한다. 공유 폴더·Git 폴더·브라우저 공개 경로를 사용하지 않는다.

기본 명령은 API 키·네트워크·파일 쓰기 없이 계획만 출력한다.

```powershell
node scripts/teacher-pilot/provision.mjs --config "<비공개 설정.json>"
```

이메일은 `teacher-pilot-<batchId>-t01@example.com`부터 `t10`까지 고정한다. 실제 교사의 이메일이나 비밀번호를 대신 사용하지 않는다. 계획의 10명·학교·프로젝트·기간을 확인하고 `configHash`를 기록한다.

## 승인한 생성 실행

로컬 프로세스 환경의 `SUPABASE_SERVICE_ROLE_KEY`를 사용한다. 키는 명령 인자·설정 JSON·로그·Git·채팅에 넣지 않는다. 기존 승인된 보관처에서 값만 읽어 환경에 주입하고 실행 후 제거한다. 도구는 서버 관리 SDK로만 사용하며 브라우저로 키를 보내지 않는다.

```powershell
node scripts/teacher-pilot/provision.mjs --config "<비공개 설정.json>" --execute --private-dir "<저장소 밖 개인 폴더>" --confirm-hash "<검토한 configHash>"
```

출력은 건수·경로·학교/AI 연결 여부뿐이다. 서비스 키와 비밀번호는 출력하지 않는다.

| 파일 | 내용 | 취급 |
|---|---|---|
| `credentials.private.json` | 계정별 무작위 암호, 접수 상태, Auth ID | 현재 사용자만 접근하는 비공개 보관본. 공유·Git 업로드 금지 |
| `registration.json` | 계정·교사·학교·기간·설정 지문 | 비밀번호 없음. 관리 SQL 등록 입력으로 사용 |

계정마다 192비트 무작위 값을 URL-safe 암호로 생성하고 **네트워크 호출보다 먼저** 보관한다. 생성 호출은 확인 메일을 보내지 않는 관리 API 방식이다. 기존 가입 트리거가 만든 `public.users` 행은 일반 교사·승인 대기 상태다. Auth 생성 성공만으로 소속 연결·AI 활성화까지 완료된 것으로 표시하지 않는다.

관리 API의 동작은 [Supabase createUser](https://supabase.com/docs/reference/javascript/auth-admin-createuser)와 [관리 사용자 목록](https://supabase.com/docs/reference/javascript/auth-admin-listusers)을 기준으로 한다.

## 실패·재실행

- `ACCOUNT_COLLISION`: 같은 이메일의 계정이 있으나 관리자 메타데이터·명부 ID·학교·시험 묶음이 다르다. 아무 계정도 수정하지 않고 중단한다. 기존 계정을 삭제·승격하거나 이름을 바꿔 맞추지 않는다.
- `CREATE_RESULT_UNKNOWN`: 생성 결과를 모른다. 원래 설정과 비공개 보관본으로 다시 실행하면 먼저 사용자 목록에서 같은 계정이 생성됐는지 확인한다. 암호 재설정·중복 생성·자동 재시도 루프는 없다.
- `CREDENTIALS_MISSING`: 계정은 있으나 암호 보관본이 없다. 자동 암호 재설정을 하지 않는다. 보관본 복구 또는 사용자 주도 자격증명 복구가 필요하다.
- `AUTH_ID_CHANGED` / `ACCOUNT_DISAPPEARED`: 기록한 계정이 교체·삭제됐다. 새 계정을 대신 만들지 않고 중단한다.
- `CONFIRM_HASH_MISMATCH` / `JOURNAL_MISMATCH`: 검토 후 설정이 바뀌었거나 다른 시험의 기록이다. 같은 시험을 임의로 재정의하지 않는다.
- `PRIVATE_ACL_FAILED`: 보관 위치의 현재 사용자 전용 접근을 확인하지 못했다. 해당 위치에 비밀을 새로 쓰지 않는다.
- `PROVISION_ALREADY_RUNNING`: 같은 시험 묶음의 생성기가 실행 중이거나 강제 종료된 잠금이 남았다. `provision.lock`의 PID와 실행 중 프로세스를 확인하고, 실제 생성기가 없음을 확인한 경우에만 관리자가 잠금 파일 하나를 제거한다. 암호 보관본은 지우지 않는다.

기존 계정 조회는 전체 페이지를 확인하되 대상 이메일 10개만 결과에 보관한다. 다른 사용자 정보와 API 오류 원문은 로그에 남기지 않는다.

## TP1 등록 입력

`registration.json`의 `entries`는 다음 다섯 필드만 가진다.

```json
{"slot":"T01","email":"teacher-pilot-example-t01@example.com","displayName":"[시험] 합성 교사 01","teacherId":"synthetic-teacher-01","authUserId":"00000000-0000-0000-0000-000000000001"}
```

관리 연결에서 `teacher_pilot.register(학교ID, 승인자소속ID, 시험묶음ID, 시작시각, 종료시각, entries, 승인근거)`를 실행한다. Auth 관리자 메타데이터와 기존 계정 여부를 SQL에서도 다시 확인한다. 비밀번호 보관본은 SQL에 붙이지 않는다. 이후 `teacher_pilot.activate(학교ID, 승인자소속ID, 시험묶음ID, 현재판, 연결시작일, 연결종료경계일, 앱배포근거)`로 임시 명부 연결·활성화를 진행한다. 실제 함수 인자·사전 조건은 TP1 실행안내가 기준이다.

## 시험 자료 관리와 종료

시험을 시작하기 전에 다음을 별도 기록한다.

- 시험 묶음 ID, 참가 Auth/소속/명부 ID, 허용 기간, 승인 근거.
- 보존 기준: 실제 계정·학교 소속, 확정 22명·9학급·288교시 기본표, 기존 자료의 개수/식별자/판.
- 관리자와 시험 교사가 새로 만든 업무별 자료 ID 및 파일 경로. 제목만 보고 삭제 대상으로 판단하지 않는다.
- 실제 AI 사용 전후 확정액·예약액·결과 미상 요청. 실제 비용 원장은 삭제 목록에서 제외한다.

종료 순서는 다음과 같다.

1. 미확정 전송·제출·AI 요청을 확인하고 원래 번호로 결과를 정리한다. 결과를 모르는 요청을 취소됐다고 추정하지 않는다.
2. `teacher_pilot.stop(학교ID, 승인자소속ID, 시험묶음ID, 현재판, 종료사유)`로 시험 허용과 임시 연결을 종료한다. 별도 MP1·OP1 허용이 있다면 각각 회수 여부도 확인한다. 기존 실제 교사의 역할이나 연결은 바꾸지 않는다.
3. 시험 계정의 **사이트 업무 접근**을 중지하고, 이미 열린 세션으로도 후속 업무 쓰기가 거절되는지 확인한다. `public.users.is_active=false`는 Supabase Auth 로그인 자체나 토큰 발급을 정지하는 조치가 아니다. Auth ban·세션 폐기가 필요하면 별도 관리 절차로 준비하며, 이 도구는 Auth 계정을 삭제하거나 ban하지 않는다.
4. `teacher_pilot.cleanup_manifest(학교ID, 승인자소속ID, 시험묶음ID)`의 읽기 전용 정리 목록과 별도 자료 ID 목록을 대조한다. 관리자 작성 자료는 작성자만으로 시험 자료를 판정할 수 없으므로 명시한 ID가 있는 것만 후보로 삼는다.
5. 실제 교사·실제 수업·공유 문서와 연결된 자료는 자동 정리에서 제외한다. 삭제 가능한 시험 초안·파일은 별도 검토 목록과 적용 승인을 준비한다. 읽음·제출·승인·감사·AI 비용 이력은 보존한다.
6. 정리 후 22명·9학급·288교시와 기존 계정·자료 기준선을 다시 확인한다. 실제 교사는 자기 계정으로 가입하고 종료된 임시 연결 이후의 기간으로 명부에 연결한다. 시험 계정의 메시지·관찰·상담 기록을 실제 교사 소유로 바꾸지 않는다.

이 도구에는 계정 삭제·자료 삭제·SQL 자동 실행 명령이 없다. 정리 목록이 있다는 사실은 삭제 승인을 대신하지 않는다. 현 스키마는 감사·AI 원장과 여러 담당 이력을 삭제하지 못하게 보호하므로 “모두 삭제 후 깨끗한 DB”를 약속하지 않는다.

## 검증

`node tests/test_teacher_pilot_provision.mjs`는 합성 Auth 관리 API와 메모리 보관소로 생성·충돌·응답 유실·재실행·비밀 비노출을 검증한다. 실제 Supabase 계정 생성·로그인·ACL 권한은 별도 결과로 기록한다. 비용 정책·로그인 인증·기존 권한을 바꾸지 않는다.
