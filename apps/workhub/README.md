# 신축 업무실

현재 목표는 **문서작성 AI·시간표를 제외한 기능을 완성한 뒤 시범 공개**하는 것입니다. [시범 공개 계획](../../docs/workhub/17-pilot-release-plan.md), [DB 연결·적용 인계](../../docs/workhub/16-pilot-db-activation.md), [11차 일정 가져오기](../../docs/workhub/18-calendar-import.md), [누적 진행 현황](../../docs/workhub/PROGRESS.md)을 기준으로 확인합니다. DB 연결 준비는 재개했으며 실제 SQL 확정·적용은 별도 단계입니다.

기존 로그인·회원 프로필을 재사용하는 일정·개인 업무 연결 기반과 별도의 가상 자료 미리보기를 제공합니다. 실제 Supabase에는 이번 SQL을 적용하지 않았습니다.

## 기존 앱에서 연결

기존 앱의 `/workhub` 경로는 승인된 `superadmin`에게만 열립니다. 기존 `@daedong/shared` 인증 클라이언트와 세션을 그대로 사용하며, 신규 계정·인증 공급자·회원 프로필을 만들지 않습니다. 화면은 Shadow DOM으로 격리해 기존 메뉴의 스타일과 충돌하지 않게 했습니다.

`database/workhub/`의 SQL은 **검토용 제안**입니다. 로컬 PostgreSQL 시험을 통과했지만 통합 DB 설계와 스키마·기간·계정 표현이 다르므로 번호순으로 일괄 적용하지 않습니다. 신규 테이블·함수 또는 학교 소속이 없으면 연결 준비 화면을 보여 주며 가상 자료로 대체하지 않습니다. 기존 [계정 보존·연결 절차](../../docs/workhub/03-account-preservation.md)를 참고하되, 현재 적용 준비와 차이 대조는 [11차 DB 인계](../../docs/workhub/16-pilot-db-activation.md)를 우선합니다. SQL 확정은 Claude Web, 실제 실행은 사용자 담당입니다.

연결 후 학교 선택, 오늘의 관련 일정, 일정 등록·조회·수정, 서버 버전 충돌과 재시도를 지원합니다. 열람 범위와 홈 추천 대상은 별개입니다. 학교 전체 열람이 가능해도 관련 조건이 맞지 않으면 홈 추천에서 제외됩니다. 개인 일정은 작성자만 열람합니다. 동일 계정의 토큰 갱신·창 전환은 작성 중 입력을 유지하고, 계정 변경·확인된 권한 상실은 기존 화면과 입력을 폐기합니다.

개인 업무 SQL 004까지 준비되면 홈과 **내 업무**에서 현재 학교의 본인 할 일을 등록·수정·완료·재개할 수 있습니다. 같은 학교의 관리자도 다른 사람의 개인 할 일을 열람하지 않습니다. 등록 응답이 끊긴 경우 같은 요청으로 재시도하며, 동시 수정은 최신 원본과 입력을 확인한 뒤 다시 적용합니다. 연결 진단의 학교 소속 조회 성공만으로 이 저장 기능까지 준비되었다고 판단하지 않습니다.

기존 시스템 전체에 학교별 격리가 적용된 것은 아닙니다. 전국 공개 전에 기존 경로의 권한·RLS를 별도로 정리해야 합니다.

화면 아래 **연결 상태 확인** 버튼은 기존 세션·가입 승인·최고관리자 권한·학교 소속을 읽어서 확인합니다. 자동으로 실행하지 않으며 회원·설정·학교 자료를 변경하지 않습니다. 로그아웃, 프로필 누락, 승인 미확인, 학교 소속 없음, 조회 함수 준비 문제, 네트워크 실패를 구분합니다. 지원용 JSON은 상태·코드·확인 시각·학교 수만 포함합니다. 확인 성공은 학교 소속 조회까지이며 일정 저장이나 실제 Google 로그인 절차의 검증 완료를 의미하지 않습니다.

## 가상 자료로 확인

```sh
npm ci
npm run dev:workhub
```

주소는 `http://127.0.0.1:5176`입니다. 실제 계정·학생·DB·외부 API 없이 가상 학교의 다섯 메뉴를 시험합니다.

| 메뉴 | 확인할 수 있는 흐름 |
|---|---|
| 오늘 | 관련 일정·다가오는 일정·기한별 할 일·제출/공동작성/검토/대기의 구분·정확한 원본 이동 |
| 학교 일정 | 공개/개인/지정 대상 일정, 대상 미리보기, 수정 충돌, 실패와 재시도, 시트 붙여넣기·CSV/TSV 검사와 행별 등록 |
| 내 업무 | 현재 학교의 본인 할 일, 기한·메모·진행/대기/완료/취소, 완료 후 재개 |
| 자료 수합 | 요청 작성 미리보기·게시 전 점검, 요청 찾기, 단위별 진행 표·원본 이동, 글/숫자 입력 안내·공동 초안·책임자 제출·보완·정정·철회·검토·완료본 집계 |
| 수업과 학생 | 승인된 명부의 학생 찾기, 학생·기간·종류·상태별 본인 기록, 관찰·정정의 대상/필수 입력 확인·저장 기록 보기·철회·최신 근거 출력, 외부 활동 가상 수신·학생 연결 확인·원문 정정 시 재검토 |

기준일은 **2026-10-19, 한국 시간**입니다. 일정과 공통 소속의 종료일은 포함하며 학생 학적·수강·배정의 종료일은 제외합니다. 한 일정 관련 조건 안의 부서·학년·교과는 모두 맞아야 하고, 같은 항목의 여러 값 및 여러 조건은 하나만 맞으면 됩니다. 직접 포함이 조건에 추가되고 제외가 우선합니다.

합성 자료만 `workhub:synthetic:v2:*` 브라우저 저장소에 보관합니다. Web Locks로 한 창만 편집하고, 해당 기능을 지원하지 않으면 임시 메모리로 동작한다는 안내를 표시합니다. 저장 실패는 성공 처리하지 않으며 입력을 유지합니다. 손상된 자료는 자동 삭제하지 않고 내보내기·명시적 초기화를 제공합니다. 실제 회원 인증 저장소는 읽거나 초기화하지 않습니다. 파일 URL의 저장 지원 여부는 브라우저마다 다르므로 개발 서버 실행을 기본으로 권장합니다.

세부 계약은 [업무·수합](../../docs/workhub/04-workflows.md), [학생 기록](../../docs/workhub/05-students.md)을 참고합니다. 이 가상 진입점은 서버에 연결하지 않습니다. 개인 업무의 실제 연결 코드는 기존 앱 `/workhub`에 별도로 구현했고, 수합·학생 기록의 서버 전환은 남아 있습니다. 화면 아래 가상 계정 전환은 실제 로그인 기능이 아닙니다. 실제 학생 자료를 입력하지 마세요.

이 진입점의 일반 프로덕션 빌드는 가상 자료 미리보기를 포함하지 않고 준비 화면을 제공합니다. 실제 연결 진입점은 `apps/main`의 `/workhub`입니다. 루트의 `dev`·`build`는 기존 앱을 대상으로 합니다.

공통 헤더의 **업무 찾기**에서 현재 열람 가능한 일정·개인 업무·수합 요청을 찾습니다. 실제 연결 화면은 준비된 일정·개인 업무만 검색합니다. 검색어와 결과는 창을 닫거나 학교를 바꾸면 지우며 주소와 영속 저장소에 남기지 않습니다. 학생 기록과 수합 응답 본문은 검색에 포함하지 않습니다.

수합 진행 표는 현재 열람 가능한 제출 단위를 20부씩 표시하며 기존 상세로 연결합니다. 필터가 원본의 완료본 합계를 바꾸지는 않습니다. 학생 기록은 선택 학생·현재 수업을 기본으로 보고, 이전 수업의 본인 기록은 ‘내 전체 기록’에서 찾습니다. 근거 텍스트 출력은 화면 필터와 관계없이 현재 학교의 본인 전체 유효 기록을 검증하고 내려받기 직전에 다시 확인합니다.

## 검증

```sh
npm run check:workhub
npm run build
npm run build:workhub
npm test
```

홈·검색·원본 이동의 통합 시험은 `node tests/browser/workhub-home-search.mjs`, 업무 원본의 지연 응답과 학교 변경은 `node tests/browser/workhub-task-navigation.mjs`입니다. Chrome과 Playwright를 사용하며 합성 자료만 주입합니다.

`test_workhub_database.mjs`는 PGlite의 실제 PostgreSQL 엔진에 기존 001~007 마이그레이션과 신규 SQL을 적용해 RLS·RPC·트랜잭션·회원 보존을 검증합니다. 실제 Supabase/PostgREST·Google OAuth·별도 연결 간 동시 실행 검증을 대신하지 않습니다. 브라우저 연결 시험은 Playwright와 Chrome 설치 후 `node tests/browser/workhub-connection.mjs`로 실행합니다. 이 시험도 주입된 가상 인증 응답을 사용합니다.

전체 가상 업무 브라우저 시험은 `node tests/browser/workhub.mjs`입니다. `PLAYWRIGHT_MODULE`로 설치된 Playwright 경로, `WORKHUB_QA_URL`로 시험할 URL, `WORKHUB_QA_OUTPUT`으로 스크린샷·결과 저장 폴더를 지정할 수 있습니다. 기본 실행은 합성 번들을 브라우저에 주입하며 개발 서버가 필요하지 않습니다. `WORKHUB_QA_URL`을 지정한 경우에는 해당 주소의 실행 중인 미리보기를 사용합니다.

수합 작성·게시 전 점검은 `node tests/browser/workhub-collection-entry.mjs`, 학생 관찰·정정·활동 채택의 입력 보호와 저장 확인은 `node tests/browser/workhub-student-entry.mjs`로 시험합니다. 기존 저장 명령과 합성 자료를 사용하며 운영 서버에 요청하지 않습니다.

진단 브라우저 시험은 `node tests/browser/workhub-readiness.mjs`입니다. 합성 응답을 주입한 실제 연결 화면을 시험하며 외부 학교 서버는 호출하지 않습니다.

실제 PostgreSQL 독립 연결 경합 시험은 `npm run test:workhub:postgres`입니다. GitHub Actions의 일회용 PostgreSQL 16 서비스에서 필수 `test` 검사에 포함됩니다. 로컬 실행 시 전용 빈 DB와 명시적 테스트 환경변수가 필요하며, 설정이 없다고 건너뛰어 성공 처리하지 않습니다. [실행 조건과 범위](../../docs/workhub/07-postgres-verification.md)를 먼저 확인해 주세요.

독립 실행 HTML은 `node scripts/export-workhub-preview.mjs [저장할 절대 경로]`로 만듭니다. 생략하면 `dist/workhub-preview.html`에 생성합니다. 번들 안에 합성 자료와 스타일을 포함해 외부 네트워크 없이 열 수 있으며 실제 Supabase 연결은 포함하지 않습니다.

연결 진단만 시연하는 HTML은 `node scripts/export-workhub-readiness-preview.mjs [저장할 절대 경로]`로 만듭니다. 8개 합성 상황을 선택해서 진단 화면을 확인하며 실제 접속 증빙으로 사용하지 않습니다.

4차 내 업무 HTML은 `node scripts/export-workhub-tasks-preview.mjs [저장할 절대 경로]`로 만듭니다. 실제 비동기 화면에 메모리 저장소를 주입해 등록·수정·상태 변경·홈 요약·응답 유실 재시도를 확인합니다. 실제 서버에 접속하거나 자료를 영구 저장하지 않습니다. 화면 검증은 `node tests/browser/workhub-tasks.mjs`, 앱 내 연결 회귀는 `node tests/browser/workhub-connection.mjs`입니다.

키보드 초점·모바일 메뉴·일정 모달은 `node tests/browser/workhub-accessibility.mjs`로 일반 DOM과 ShadowRoot를 함께 검사합니다. 수합/학생 반복 필드와 저장·취소 이후 동작은 각각 `workhub-collection-accessibility.mjs`, `workhub-student-accessibility.mjs`로 확인합니다. 실제 화면읽기 프로그램 음성 검증과 교사 파일럿은 별도로 남아 있습니다.

개인 업무·수합 요청·제출 단위 원본·관찰 기록·수업 활동은 20개씩 표시합니다. 원본 이동은 해당 쪽으로 연결되고 전체 집계·근거 출력은 쪽에 제한되지 않습니다. 접힌 개정/제출 이력은 펼칠 때 생성합니다. 작성 중에는 쪽 전환을 보호하고 일시 조회 실패 후에도 보존한 입력이 있는 쪽으로 복구합니다. 서버 조회의 커서·페이지 처리는 별도 미구현 사항입니다.

대량 목록 회귀는 `workhub-task-paging.mjs`, `workhub-collection-paging.mjs`, `workhub-student-paging.mjs`이며, `workhub-scale-baseline.mjs`는 동일 합성 자료의 이전 커밋 `137a871`과 현재 DOM 개수를 비교합니다. [10차 인계](../../docs/workhub/15-scaled-lists.md)에 측정 범위와 잔여 조회 비용을 기록합니다.

학교 일정의 **시트에서 가져오기**는 최대 200행의 표 또는 UTF-8 CSV/TSV를 읽고 열 연결·입력 오류·현재 열람 가능한 중복 후보를 확인합니다. 각 행은 나만 보기 초안으로 기존 편집기에 들어가며, 교사가 내용·공유 대상을 확인한 뒤 저장합니다. 읽기 취소·후보 재비교·부분 등록 안내와 기존 저장 재시도를 지원합니다. 서버의 원본 ID 원장·시트 변경 동기화·3방향 대조·기준 전환은 후속이며, 이번 기능을 시트 전환 완료로 판단하지 않습니다. 브라우저 시험은 `node tests/browser/workhub-calendar-import.mjs`입니다.
