# 신축 업무실

작업별 누적 상태와 남은 순서는 [진행 현황](../../docs/workhub/PROGRESS.md), 최신 연결 진단은 [3차 개발 인계](../../docs/workhub/08-activation-readiness.md)를 기준으로 확인합니다.

기존 로그인·회원 프로필을 재사용하는 일정 연결 기반과 별도의 가상 자료 미리보기를 제공합니다. 실제 Supabase에는 이번 SQL을 적용하지 않았습니다.

## 기존 앱에서 연결

기존 앱의 `/workhub` 경로는 승인된 `superadmin`에게만 열립니다. 기존 `@daedong/shared` 인증 클라이언트와 세션을 그대로 사용하며, 신규 계정·인증 공급자·회원 프로필을 만들지 않습니다. 화면은 Shadow DOM으로 격리해 기존 메뉴의 스타일과 충돌하지 않게 했습니다.

`database/workhub/`의 SQL은 **검토용 제안**입니다. 로컬 PostgreSQL 시험을 통과했지만 운영 적용은 별도 단계입니다. 신규 테이블·함수 또는 학교 소속이 없으면 연결 준비 화면을 보여 주며 가상 자료로 대체하지 않습니다. 적용 순서와 회원 보존 점검은 [계정 보존·연결 절차](../../docs/workhub/03-account-preservation.md)를 따릅니다.

연결 후 학교 선택, 오늘의 관련 일정, 일정 등록·조회·수정, 서버 버전 충돌과 재시도를 지원합니다. 열람 범위와 홈 추천 대상은 별개입니다. 학교 전체 열람이 가능해도 관련 조건이 맞지 않으면 홈 추천에서 제외됩니다. 개인 일정은 작성자만 열람합니다. 동일 계정의 토큰 갱신·창 전환은 작성 중 입력을 유지하고, 계정 변경·확인된 권한 상실은 기존 화면과 입력을 폐기합니다.

기존 시스템 전체에 학교별 격리가 적용된 것은 아닙니다. 전국 공개 전에 기존 경로의 권한·RLS를 별도로 정리해야 합니다.

화면 아래 **연결 상태 확인** 버튼은 기존 세션·가입 승인·최고관리자 권한·학교 소속을 읽어서 확인합니다. 자동으로 실행하지 않으며 회원·설정·학교 자료를 변경하지 않습니다. 로그아웃, 프로필 누락, 승인 미확인, 학교 소속 없음, 조회 함수 준비 문제, 네트워크 실패를 구분합니다. 지원용 JSON은 상태·코드·확인 시각·학교 수만 포함합니다. 확인 성공은 학교 소속 조회까지이며 일정 저장이나 실제 Google 로그인 절차의 검증 완료를 의미하지 않습니다.

## 가상 자료로 확인

```sh
npm ci
npm run dev:workhub
```

주소는 `http://127.0.0.1:5176`입니다. 실제 계정·학생·DB·외부 API 없이 가상 학교의 다섯 메뉴를 시험합니다.

| 메뉴 | 확인할 수 있는 흐름 |
|---|---|
| 오늘 | 관련 일정·다가오는 일정·할 일 추가와 체크·내 제출 의무에서 원본 이동 |
| 학교 일정 | 공개/개인/지정 대상 일정, 대상 미리보기, 수정 충돌, 실패와 재시도 |
| 내 업무 | 현재 학교의 본인 할 일, 기한·메모·진행/대기/완료/취소, 완료 후 재개 |
| 자료 수합 | 글/숫자 문항, 개인/공동 단위, 초안 비공개, 책임자 제출, 보완·정정·철회·검토·완료본 집계 |
| 수업과 학생 | 승인된 가상 수업 명부, 작성자 전용 관찰·정정·철회·근거 출력, 외부 활동 가상 수신·학생 확인 연결·원문 정정 시 재검토 |

기준일은 **2026-10-19, 한국 시간**입니다. 일정과 공통 소속의 종료일은 포함하며 학생 학적·수강·배정의 종료일은 제외합니다. 한 일정 관련 조건 안의 부서·학년·교과는 모두 맞아야 하고, 같은 항목의 여러 값 및 여러 조건은 하나만 맞으면 됩니다. 직접 포함이 조건에 추가되고 제외가 우선합니다.

합성 자료만 `workhub:synthetic:v2:*` 브라우저 저장소에 보관합니다. Web Locks로 한 창만 편집하고, 해당 기능을 지원하지 않으면 임시 메모리로 동작한다는 안내를 표시합니다. 저장 실패는 성공 처리하지 않으며 입력을 유지합니다. 손상된 자료는 자동 삭제하지 않고 내보내기·명시적 초기화를 제공합니다. 실제 회원 인증 저장소는 읽거나 초기화하지 않습니다. 파일 URL의 저장 지원 여부는 브라우저마다 다르므로 개발 서버 실행을 기본으로 권장합니다.

세부 계약은 [업무·수합](../../docs/workhub/04-workflows.md), [학생 기록](../../docs/workhub/05-students.md)을 참고합니다. 업무·수합·학생 기록은 아직 서버 저장·인증/RLS와 연결하지 않았습니다. 화면 아래 가상 계정 전환은 실제 로그인 기능이 아닙니다. 실제 학생 자료를 입력하지 마세요.

이 진입점의 일반 프로덕션 빌드는 가상 자료 미리보기를 포함하지 않고 준비 화면을 제공합니다. 실제 연결 진입점은 `apps/main`의 `/workhub`입니다. 루트의 `dev`·`build`는 기존 앱을 대상으로 합니다.

## 검증

```sh
npm run check:workhub
npm run build
npm run build:workhub
npm test
```

`test_workhub_database.mjs`는 PGlite의 실제 PostgreSQL 엔진에 기존 001~007 마이그레이션과 신규 SQL을 적용해 RLS·RPC·트랜잭션·회원 보존을 검증합니다. 실제 Supabase/PostgREST·Google OAuth·별도 연결 간 동시 실행 검증을 대신하지 않습니다. 브라우저 연결 시험은 Playwright와 Chrome 설치 후 `node tests/browser/workhub-connection.mjs`로 실행합니다. 이 시험도 주입된 가상 인증 응답을 사용합니다.

전체 가상 업무 브라우저 시험은 `node tests/browser/workhub.mjs`입니다. `PLAYWRIGHT_MODULE`로 설치된 Playwright 경로, `WORKHUB_QA_URL`로 시험할 URL, `WORKHUB_QA_OUTPUT`으로 스크린샷·결과 저장 폴더를 지정할 수 있습니다. 기본 주소는 위 개발 서버입니다.

진단 브라우저 시험은 `node tests/browser/workhub-readiness.mjs`입니다. 합성 응답을 주입한 실제 연결 화면을 시험하며 외부 학교 서버는 호출하지 않습니다.

실제 PostgreSQL 독립 연결 경합 시험은 `npm run test:workhub:postgres`입니다. GitHub Actions의 일회용 PostgreSQL 16 서비스에서 필수 `test` 검사에 포함됩니다. 로컬 실행 시 전용 빈 DB와 명시적 테스트 환경변수가 필요하며, 설정이 없다고 건너뛰어 성공 처리하지 않습니다. [실행 조건과 범위](../../docs/workhub/07-postgres-verification.md)를 먼저 확인해 주세요.

독립 실행 HTML은 `node scripts/export-workhub-preview.mjs [저장할 절대 경로]`로 만듭니다. 생략하면 `dist/workhub-preview.html`에 생성합니다. 번들 안에 합성 자료와 스타일을 포함해 외부 네트워크 없이 열 수 있으며 실제 Supabase 연결은 포함하지 않습니다.

연결 진단만 시연하는 HTML은 `node scripts/export-workhub-readiness-preview.mjs [저장할 절대 경로]`로 만듭니다. 8개 합성 상황을 선택해서 진단 화면을 확인하며 실제 접속 증빙으로 사용하지 않습니다.
