# 업무혁신시스템 로컬 셸

`apps/main`과 연결하지 않은 개발용 미리보기입니다. 실제 학교·교사·학생·DB·인증·외부 API를 사용하지 않습니다.

```sh
npm ci
npm run dev:workhub
```

주소는 `http://127.0.0.1:5176`이며 해당 포트가 사용 중이면 다른 포트로 이동하지 않고 실패합니다. 루트의 기존 `dev`·`build` 명령은 계속 `apps/main`을 대상으로 합니다.

## 확인할 수 있는 흐름

1. 오늘 홈 → 학교 일정 → 원본 보기 → 수정 가능한 일정 편집.
2. 새 일정 등록 → 열람 범위와 관련 대상 미리보기 → 저장 → 같은 원본이 홈에 반영.
3. 화면 아래 개발 시험 도구에서 두 가상 학교·계정 선택, 조회 실패·재시도, 저장 실패·재시도, 빈 목록, 소속 종료, 자료 초기화.
4. 본인 일정의 편집 창 아래 개발 시험 도구에서 다른 교사 수정 발생 → 수정 저장 → 현재 원본 확인 → 내 입력 유지 또는 현재 원본으로 입력 변경.

가상 기준일은 **2026-10-19, 한국 시간**입니다. 오늘 일정은 `시작일 ≤ 기준일 ≤ 종료일`, 다가오는 일정은 `시작일 > 기준일`이며 미래 일정 전체를 보여 줍니다. 관련 대상은 진행 중이면 기준일, 미래면 시작일의 소속을 사용합니다. 현재 소속에 열람 가능한 원본만 홈 추천에 사용합니다. 종료일은 포함합니다.

한 관련 조건 안에서 부서·학년·교과는 모두 일치해야 합니다. 같은 항목의 여러 값과 서로 다른 조건은 하나만 맞으면 포함합니다. 직접 포함은 조건에 추가되고 제외가 항상 우선합니다. 작성자는 본인 원본을 열람하며 홈에서 확인합니다. 학교 전체 열람과 관련 대상 추천은 서로 다른 계산입니다.

## 기술 경계

- `src/main.tsx`는 개발 모드에서만 `preview/PreviewApp`을 동적으로 불러옵니다. 일반 빌드는 **운영 연결 준비 중** 화면만 포함합니다.
- `modules.ts`는 모든 모듈을 `superadmin`·`productionEnabled: false`로 선언합니다. 운영 레지스트리와 라우트는 수정하지 않습니다. 이 선언을 실제 접근 제어로 사용하지 않습니다.
- `contracts.ts`·`domain.ts`는 입력·대상·추천·버전 동작 계약입니다. `preview/memory-adapter.ts`의 소속·역할 검사는 **개발용 시뮬레이션**이며 서버 인증·RLS·보안 검증을 구현하거나 대체하지 않습니다.
- 모든 데이터는 탭 메모리에만 있습니다. 브라우저 저장소를 사용하지 않습니다. 새로고침·초기화로 사라집니다. 초기화 시 대기 중 요청을 취소합니다.
- 학교·계정 전환 시 편집 창을 닫으며 이전 화면의 늦은 응답을 표시하지 않습니다. 동일 입력·버전의 저장 재시도는 같은 요청 키를 사용합니다.
- 일반 교사는 본인 일정만, 가상 일정 담당자는 열람 가능한 공유 일정도 수정합니다. 다른 사람의 개인 일정에는 접근하지 못합니다. 이는 승인 전의 계약 시험용 선택이며 운영 정책 확정을 의미하지 않습니다.
- 대상 관계는 고정된 가상 소속의 부서·학년·교과 배열입니다. 실제 이력 기반 소속, 학교별 정책, 서버 페이지네이션·검색, DB 트랜잭션, 실시간 동기화는 미연결입니다.
- 신규 학교 개설, 실제 사용자 전환, 파일 업로드, 업무·수합·AI·시간표·학생 기록은 구현 범위에 포함하지 않습니다.

## 검증

```sh
npm run check:workhub
npm run build:workhub
npm test -- workhub
npm test
```

`tests/test_workhub.mjs`는 기존 esbuild 도우미로 실제 TypeScript를 실행합니다. 학교 경계·개인 열람·대상 집합·날짜·깨진 입력·등록·충돌·멱등 재시도·권한 재검사·실패·초기화·일반 빌드 제외를 확인합니다. 서버 보안 검증은 별도 운영 연결 단계에서 필요합니다.
